# Rach2 test programs

![List of Rach2 Test Programs](https://raw.githubusercontent.com/rachmiroff/images/refs/heads/main/rach2/tests.png)

The kernel's tests come in three tiers. Freestanding ELF32 programs (this directory) run as guest programs under the kernel: the original syscall tests and the subsystem probes, all but `dnstest` built without a libc (`dnstest` links the ported musl because it shares `utils/resolv.c` with the musl-linked `ping` and `nc`). The musl integration programs (`musl/`) link against the ported musl libc and exercise the kernel through a real C library. The host tests (`host/`) compile pure kernel logic natively and run it under the sanitizers; see [host/Readme.md](host/Readme.md).

## Syscall tests

The original tests, each driving a few syscalls and printing a human-readable pass or fail summary:

* `hello.c`: prints "Hello from ELF!" with the write syscall, then exits.
* `filetest.c`: the file syscalls (open, read, write, close), reading `hello.txt`.
* `forktest.c`: fork, waitpid, and exit; the parent forks a child that exits with status 42, then waits and verifies.
* `shelltest.c`: the fork, exec, waitpid chain; the child exec's `hello` and the parent verifies its exit status.
* `dirtest.c`: chdir and getcwd; "/" and "." succeed, other paths fail.
* `stattest.c`: stat and stat64, for existing and missing files.
* `touchtest.c`: creat and utimensat.
* `rmtest.c`: unlink, with the exact errno for each refusal.
* `mvtest.c`: rename, with the exact errno for each refusal, including the directory source and destination that separate EPERM from EISDIR.
* `lstest.c`: getdents64, parsing the entries of "/".
* `stdintest.c`: the stdin read path: blocking, character echo, and line buffering.
* `dup2test.c`: dup2 for I/O redirection.
* `rebootprobe.c`: `reboot(2)` at every answer that is not a shutdown, so the machine is still running when it finishes. The magics and commands, each asserted on its exact errno: `RB_DISABLE_CAD` returns 0 with the usual second magic and with each of the three alternates, which is the only way to pin that those are accepted, not refused for some other reason, since every command that works stops the machine; `RB_ENABLE_CAD`, `RB_KEXEC`, a zero first magic, a zero second magic and a wrong second magic each return `-EINVAL`; and an unprivileged caller asking for a real power-off gets `-EPERM`. That last case is the one probe in the tree whose misbehaviour destroys the whole run, since they all share one boot, so the child asserts its own precondition first: it requires `setuid` to return 0 and `geteuid` to read the new uid back, and exits with a distinct status having asked for nothing if either fails. Removing the kernel's privilege check does not produce a `FAIL` line; it powers the machine off in the middle of the suite, which is the detection and the reason the precondition is asserted.
* `pingtest.c`: the SC_PING socketcall. Two positive controls (a reply from the gateway, a clean timeout from an unreachable host) and then, in one fork round with a child pinging an address nobody answers, the four claims the sleeping wait rests on: that the parent gets CPU while the child waits (at least two seconds of samples taken while it was alive, which a wait that polled with sti/hlt inside a syscall fails outright), that a second ping is refused with exactly `-EBUSY`, not answered, that the child's call returns exactly `-ETIMEDOUT` within three to eight seconds, and that the slot comes back afterwards. Run by `make ping-test`, which matches `PINGTEST OK`; it wants the SLIRP gateway, which is why it is its own target, not a member of the suite.
* `udptest.c`: UDP sockets: bind, blocking and non-blocking recvfrom, an echo round-trip, and rejection of a bad pointer.
* `tcptest.c`: TCP sockets: connect, a write-and-read echo, a graceful close, and a refused connect.
* `sockettest.c`: the socket lifecycle, so close, dup2, fork sharing, and process-exit cleanup neither leak nor double-free a socket.
* `dnstest.c`: the userspace stub resolver in `utils/resolv.c`: `inet_aton`, a `/hosts` lookup, the DNS message parser against crafted responses (A record, CNAME chain, compression pointers, NXDOMAIN, malformed input), and live resolution through SLIRP's forwarder. It links the ported musl, the one program here that does.

## Subsystem probes

Each `*probe.c` drives one subsystem from user space through direct `int 0x80` calls and prints a final pass or fail line. Most use a `TOKEN OK` or `TOKEN FAIL` form; the exact success line each prints is in parentheses below:

* `vmprobe` (`VMPROBE OK`): the VMA and demand-paging machinery (brk, anonymous mmap, stack growth, lazy zero-fill).
* `cowprobe` (`COWPROBE OK`): copy-on-write fork.
* `dirprobe` (`DIRPROBE OK`): hierarchical KRFFS directories and the `*at` API.
* `unlinkdirprobe` (`UNLINKDIRPROBE OK`): removing a directory's files while listing it, the way `rm -rf` does. The directory cursor used to be a count of children, so each unlink renumbered the survivors and the next read skipped one entry per file already gone; the leftovers then made `rmdir` refuse, and the only thing a user saw was "Directory not empty". `make selfbuild-test` found it, once the kernel source tree had grown enough files that listing it took more than one call, so the buffer here is deliberately small. It also checks that two descriptors on one directory keep their own cursors and that the end of a directory is reported repeatedly, not once.
* `ofdprobe` (`OFDPROBE OK`): refcounted open-file descriptions (the shared seek offset).
* `pipeprobe` (`PIPEPROBE OK`): the anonymous-pipe contract.
* `pollprobe` (`POLLPROBE OK`): I/O multiplexing (poll and select).
* `sigprobe` (`SIGPROBE OK`): signal delivery and the sigreturn frame.
* `credprobe` (`CREDPROBE OK`): the process credential model (V7 with POSIX saved IDs): inheritance, the drop, the saved-id rules, no regain.
* `ownprobe` (`OWNPROBE OK`): file ownership: creation stamping under the umask, the chmod/chown and fchmod/fchown rules, and the kill rule. The last is judged per signal: a uid-1000 child is refused signal 0 and `SIGTERM` to its root parent, permitted `SIGCONT` while it shares that parent's session, and refused it again after `setsid`. A second round parks 1000 in the parent's saved slot and probes it with signal 0, which is the only way to reach the saved-uid arm, since `su` and dropbear both drop all three ids.
* `permprobe` (`PERMPROBE OK`): permission enforcement: the nine-bit access check at open, create, unlink, rename, mkdir, chdir, exec, utimensat (the touch-versus-set split), and access(2), with the root override.
* `waitprobe` (`WAITPROBE OK`): the fd-layer blocking and dispatch substrate.
* `jobprobe` (`JOBPROBE OK`): the session and process-group identity model, including the rule that a process leaves its group when it is reaped and not when it exits, so a terminal can be handed to a group holding one unreaped zombie (which is what a shell does when the first member of a pipeline is a command that has already finished).
* `ttyprobe` (`TTYPROBE OK`): the tty line discipline and termios ioctls.
* `ptyprobe` (`PTYPROBE OK`): the pseudo-terminal pair (`/dev/ptmx` and `/dev/pts/N`).
* `devprobe` (`DEVPROBE OK`): the synthetic `/dev` devices and `/proc` self views.
* `auxvprobe` (`auxvprobe: ALL OK`): the SysV/i386 initial process stack the kernel hands a new program.
* `tlsprobe` (`All TLS checks passed!`): `%gs` thread-local storage surviving syscalls, IRQs, and context switches.
* `errnoprobe` (`All errno checks passed!`): the negative-errno syscall return contract.
* `rngprobe` (`RNGPROBE OK (trusted)` or `RNGPROBE OK (fail-closed)`): trusted entropy and the fail-closed RNG policy.
* `timeprobe` (`TIMEPROBE OK`): time, sleep-with-yield, and the entropy path.
* `miscprobe` (`MISCPROBE OK`): the miscellaneous syscalls busybox needs.
* `loopprobe` (`LOOPPROBE OK`): loopback: a UDP echo and a TCP connect/accept round trip against the machine itself over `127.0.0.1`, with the peer reading back as the canonical address.
* `suidprobe` (`SUIDPROBE OK`): the setuid and setgid bits on exec, driving the staged `suidhelper` at four modes and owners: a 04755 root-owned helper runs a uid-1000 caller with effective and saved uid 0 (gids untouched) and AT_SECURE 1 and can shed and regain root through the saved id; a 04755 helper owned by uid 5 grants euid and suid 5, proving the bit grants the file owner's identity whoever that is; a 02755 helper owned by group 5 moves the effective and saved gid to 5 while the uids stay 1000; a 0755 helper leaves every id at 1000 with AT_SECURE 0; and a 04644 helper (setuid, no execute bit) is refused, so the bit without execute grants nothing. It also asserts stat reports the full 07777 mode.
* `sudoprobe` (`SUDOPROBE OK`): the reference `sudo`, staged setuid root in the test image beside an `/etc/sudoers` listing uid 1000. A permitted real uid reaches root, an unlisted one (1001) is refused, and the target runs with a cleared environment. `sudo` is coursework and ships in no other image; the shipped os-real has `su` alone.
* `modeprobe` (`MODEPROBE OK`): the set-id bits taken away by write (4), truncate, chown (212) and chmod (15), and the grant narrowed to match. It mints and removes every fixture itself, because the probes share one boot and a probe that disarmed `suidprobe`'s staged fixtures would buy a green run by breaking a later probe's premise. As root: the 04755 baseline, a privileged write that keeps the bit (the CAP_FSETID analogue), a chown to 1000:1000 that takes it whoever asks (the pair that separates the two privilege rules), and a chowned 04755 directory that keeps both bits. From a uid-1000 child: `chown(path, -1, -1)` on a root-owned 04755 file returns 0 and leaves the mode alone, which is the gate that stops any uid disarming a setuid program with one call; then, on its own files, a small in-place write clears, a growing write that must relocate the node clears (asserted by a fresh stat after the write, the one case a clear through the stale pointer would fail), `O_TRUNC` clears, `creat` (8) on an existing set-id file clears and leaves it empty, 02755 clears, 02644 survives because setgid without group-execute grants nothing, and a plain 0755 file is the control. The escalation needs a program, so the parent copies the staged `/suidhelper` byte for byte to `/mp_sgid0` through one read/write loop (no manifest entry, no set-id allowlist line), chmods it 02700 and chowns it 1000:0, in that order, so the chown's clear must spare a setgid bit with no group-execute beside it. A uid-1000 child rewrites a byte and stats it back at 02700, execs it with `suidhelper`'s `plain` scenario (which exits 0 only if all three uids and all three gids read 1000 and AT_SECURE is 0), then chmods it 02710, stats it back at 0710 because an owner outside the file's group may not store setgid, and execs it again.

* `searchprobe` (`SEARCHPROBE OK`): search (`x`) charged on every directory a path enters, not just on the target and its immediate parent. A root parent flips the modes of a staged root-owned tree between three uid-1000 children. A denial is 0777 turned into 0666, one bit: read and write stay granted, so only the withheld execute bit can account for a refusal, where the obvious 0755 and 0700 pair would move the read bit along with it and let a kernel that charged read pass unremarked. The baseline child runs while the tree is 0777 throughout and does every read and every mutation the next child will be refused, so a later denial cannot be the leaf's own bits or those of the directory the name lands in; the denied child runs with `/sp_denied` at 0666 and asserts exact errnos one level down and two, across open (5), openat (295), stat64 (195), fstatat64 (300), access (33), faccessat (307), chdir (12), execve (11), creat (8), O_CREAT, unlink (10), mkdir (39), rmdir (40), rename (38) in both directions, chmod (15), fchmodat (306), fchownat (298), utimensat (320) and linkat (303), with a name that does not exist answering `-EACCES` and not `-ENOENT`; the third child runs after the denial moves one level down, so the answer follows the denying directory, not a cached decision. Its mutations run in two rounds. The first aims inside `/sp_denied/shared`, which stays 0777, so only an ancestor above the directory the name lands in can refuse. The second aims directly into `/sp_denied`, which grants write and withholds search, so the refusal can only be the immediate parent's own execute bit; that round is what reaches each syscall's full-path resolve, since the write check walks as far as the parent and a walk never charges the directory it ends on. The parent afterwards asserts that nothing the denied child attempted was actually done, each rename against a source of its own so that an absent destination cannot merely mean an earlier case took the source away. `/sp_denied/../sp_up.txt` and `/` must keep opening (`..` collapses lexically, the root is always searchable), and `access(2)` is asked twice under split real and effective ids, since it charges the prefix by the real ones. Two cases are kept for a neighbouring rule, not for this one: `chdir` into a denied directory names it as its own target, which `chdir`'s execute check refuses whatever the walk charged.

* `stickyprobe` (`STICKYPROBE OK`): the sticky bit, where write permission on a directory stops being enough to take another user's entry out of it. Every denial is paired against the same call in a non-sticky control directory: `/st_plain` holds the same fixtures at the same modes and the same owners as `/st_sticky` and differs from it in exactly one bit, so a lone `-EPERM` cannot be ownership or a missing write bit talking. As uid 1000, four calls are refused in `/st_sticky` and permitted in `/st_plain`: unlink (10) of a root-owned file, rename (38) of one within the directory, rmdir (40) of a root-owned empty subdirectory, and the rename of the caller's own file over a root-owned one, which is the destination end and the half whose omission leaves the attack open while an unlink-side probe goes green. The root-owned victims are 0666, so the caller holds write on every file it is refused, which is the SVR4 relaxation (also permitting the removal when the caller can write the file) refused in the one case that separates it from POSIX. The entry-owner clause is the caller's own file, taken out of the sticky directory by unlink and by rename; the second of those is also what makes the destination case diagnostic, since it shows the source end permitting the very rename the destination end then refuses. The directory-owner clause runs in a minted 01777 directory owned by 1000, where the same caller removes a root-owned entry because it owns the directory, and a third uid (1001) is then refused in both sticky directories after creating and removing a file of its own in each, so its refusal is neither a missing write bit nor the directory being the more permissive one. A 01755 root-owned directory answers `-EACCES` and not `-EPERM`, which pins the order: the directory's write check runs first and the sticky rule never turns an access failure into a permission one. The parent then checks each denial did nothing and each permission was carried out, the two rename victims by mode, not by existence, since a clobbered victim would leave the name in place carrying the source's 0640; its own cleanup, removing from the sticky directory everything both children were refused, is the privileged clause.

The helpers are the programs a probe drives, not probes themselves: they print no success token and are scored only through the status they hand back. `suidhelper.c` is one; `idreport.c` is the other. `idreport` reports the identity, working directory, `argv[0]` and environment an exec gave it as one line of `key=value` items on standard error, and, given an expectation string of the same items, exits non-zero on the first that does not match and 0 when every one does, the environment compared as an exact set so a leaked variable fails exactly as a missing one does. It is the shell of the test image's `probe` account, so `su` reaches it the way a shell is reached, with the expectation after a `-c`; its exit statuses (2 a usage error, 10 to 15 the six ids, 20 the working directory, 21 `argv[0]`, 30 a variable that is not there, 31 an environment holding more than was named) are what says which half of a login broke.

The set-id fixtures `suidprobe` and `sudoprobe` drive are staged by `krffs/manifests/test.manifest`, not minted at runtime: a probe cannot create the very bit it is testing through, since only root may chown a file to root. `searchprobe`'s tree (`/sp_denied` and below, including the program `/sp_denied/prog`) is staged for a different reason: a freestanding probe cannot mint an ELF, and the execve cases need a real program under the denied ancestor. Everything its mutations aim at, and the `/sp_up.txt` its lexical `..` opens, it mints and removes itself, so it hands the image back exactly as staged and rests on no file another probe owns. `modeprobe` stages nothing at all: its parent is root, so it can mint every set-id mode it needs and copy the staged helper into a runnable one, and a probe whose whole subject is the bits coming off a file must not be able to take them off a fixture another probe depends on. `stickyprobe` stages the two directories of its pair (`/st_sticky` at 1777 and `/st_plain` at 0777) and nothing else, for the one reason minting cannot cover: `dir 1777` is how the shipped `/tmp` gets its bit, nothing else in the tree reads that bit back, and the probe asserts both staged modes before it does anything, so a staging tool that dropped 01000 fails there, not quietly shipping an inert `/tmp`. Its entries, and the two further sticky directories the directory-owner and write-check clauses need at other owners and other modes, it mints and removes itself, since chmod and chown can make those directly.

`pwauthmusl` stages an account, not a file tree. The image has a `probe` account at uid 1000 whose shell is `/idreport` and whose home is `/home/probe` (0700 and owned by the account, under a 0755 `/home`), a second committed `/etc/shadow` line for it beside root's, and an `/etc/group` the image has never carried before and the account's gid needs anyway. The home is a real directory and not the image root, because a chdir to the directory the caller is already in would prove nothing about what a login `su` does. The two passwords are different on purpose, root's `rach2` and the account's `probepass`, so offering one to the other account is a wrong password, not a lucky one. The `/su` the probe drives is the shipped binary at the shipped mode, staged from `build/utils/sbin/su` and declared in `tools/check_setid.py`'s allowlist for this image, so the probe exercises what a user runs, not a copy of it.

The milestone-9 through -12 audits added focused regression probes that boot the same way (they do not all follow the `*probe` name):

* `cowregrant` (`COWREGRANT OK`): the copy-on-write re-grant path after fork.
* `usercopyfault` (`USERCOPYFAULT OK`): the user-copy helpers rejecting a bad or window-crossing user pointer.
* `forkleak` (`FORKLEAK OK`): no kernel-stack leak across repeated fork and exit.
* `fdstale` (`FDSTALE OK`): a descriptor open on a regular file names that file from open to close, across an unlink, across a rename onto its name, and across a write that relocates it. Where the probe once asserted `-EBADF` for each, `read`, `lseek`, `_llseek` and `fstat64` through an unlinked descriptor now report the file it opened, and a fresh open of the name answers `-ENOENT`; the rename case runs across two processes, so a holder scan that looked only at the caller could not pass it, and the child must read what it opened whole, not a mixture of two files; a refused rename destroys nothing in either shape, so a rename refused for its directory source leaves the destination it had already resolved readable, through the held descriptor and by name, and one refused with `-EISDIR` for its directory destination leaves that directory named; the orphan is invisible to the scans that enumerate by parent id, so `getdents64` lists no nameless entry and `rmdir` over a held orphan succeeds; a write moves the file past a wall minted behind it and every other descriptor on it follows, whether the holder is the writer's own process or another; and 256 rounds each of unlink-under-a-descriptor, of removal with nothing holding the file, and of write-new-then-rename must not exhaust the image, which is the only free-space assertion a probe can make on a file system with no `statfs`. Directories stay out by decision and the last case says so: `rmdir` still frees the node under an open directory descriptor, and `getdents64` and a relative path through it both answer `-EBADF`.
* `dirgrow` (`DIRGROW OK`): a KRFFS directory growing past its first block, with the parent stamp preserved on relocate.
* `pathcanon` (`PATHCANON OK`): absolute-path canonicalization before the synthetic `/dev` and `/proc` classifier.
* `trapprobe` (`TRAPPROBE OK`): the default handler for the CPU exceptions.
* `orphanprobe` (`ORPHANPROBE OK`): orphan reparenting to `/sbin/init`.
* `procprobe` (`PROCPROBE OK`): the `/proc` snapshot is taken at open, not regenerated on read, proved by killing and reaping the process a still-open `/proc/<pid>/stat` describes; every file it can open comes back complete, asked for something only its own last line carries; `btime` answers the same on a second read; and the idle counters are driven over two intervals of equal length, one sleeping and one running, which must move in opposite directions and together account for every tick the timer delivered. A test that only added them up would pass with idle stuck at zero. It then requires two live sockets to report different inodes and a socket opened into a freed slot to report one that neither had, opens a listening socket and requires its inode to be the same number in `/proc/net/tcp`, in `fstat` and in `/proc/self/fd/N` and its state column to be the `0A` netstat reads as LISTEN, and requires a descriptor open on each network file to name that file through its link and report one identity through `fstat` and `stat`. It fills the connection pool to its last block, half in a child because one process cannot hold that many descriptors, and requires a row back for every one of them. Last it forks a listener owned by uid 1000, connects to it as root over loopback, and requires the accepted connection to belong to the account that listened rather than to whoever was running when the SYN arrived, then closes it and requires the detached row to still report its inode.

The memory-protection probes provoke a deliberate fault. `forkro` forks a child that writes a read-only page, confirms the child is killed by SIGSEGV while the page's protection survived the fork, and prints `FORKRO OK`. `vmro` (a read-only page faulting on write) and `vmfault` (a wild-pointer write) are themselves killed by the fault they trigger, so the kernel surviving a faulting user process is the pass. `winprobe` (run by hand as a standalone boot) reads the kernel-only page-cache window at `PCWIN_BASE` (0xD0000000) from ring 3; the window fault branch is for the supervisor faults the file system raises, not for user code, so the read must segfault the process. Its `winprobe: ERROR still alive` line must never appear; the kernel surviving and the shell returning is the pass.

The disk probes need a real disk, so they are disk-only: boot disk-backed (`rach2.fsdisk`) with a scratch image attached, never the default RAM-module test image. `blockprobe` (`BLOCKPROBE OK`) writes a working set larger than the 4 MiB resident cache (24 files of 256 KiB), fsyncs, and reads it back byte for byte, so a dropped-dirty or mis-mapped page shows up as a mismatch, not a crash. `persistprobe` (`PERSISTPROBE OK (wrote)` then `PERSISTPROBE OK (read back)`) runs twice against the same image: the first boot writes and fsyncs `/persist.txt`, the second reads the marker back, proving fsync pushed the write through the cache to the disk. `stressprobe` (`STRESSPROBE OK n=132 bytes=34603008`) writes and re-reads 33 MiB, past the 32 MiB physical-RAM cap, proving a file system larger than memory round-trips through the cache. `make test-disk`, `make persist-test`, and `make stress-test` build the scratch image and run each under the harness. Each probe also has an AHCI twin that runs the identical token over an `ich9-ahci` SATA HBA selected by `rach2.disk=ahci`: `make test-disk-ahci`, `make persist-test-ahci`, and `make stress-test-ahci` attach the same scratch image as an `if=none` drive plus an `ide-hd` behind the HBA and assert the same `BLOCKPROBE OK` / `PERSISTPROBE OK` / `STRESSPROBE OK` lines. `creddisk` (`CREDDISK OK (wrote)`, `(released)`, `(read back)`) is the credential library's half of that claim and the one place it can be made: both of `cred_rewrite`'s flushes are no-ops on the RAM module every other credential proof runs on. It boots one image three times. The first boot replaces a file under a transaction and releases it, then replaces a second file and leaves through `_exit` still holding the lock, which is a writer cut off where a power failure would cut it off; the second boot requires both replacements, with the modes and owners they inherited and no temporary file beside either, and requires the lock the cut-off writer left to be reported, not broken, with a line naming the removal; the third requires that lock, removed and released by the second boot, to be gone. `make cred-persist-test` runs the three.

`dirtyprobe` (`DIRTYPROBE OK`) is disk-only for a different reason and runs from `make crash-test`, not the suite, so it is staged into `krffs/manifests/disk-test.manifest` and not listed in `tools/runtests.py`. It proves no set-id clear ever reaches the root node, whose spare mode bit is the dirty-mount flag (`KRFFS_MODE_DIRTY` and `KRFFS_MODE_SUID` are the same 0004000). The RAM image never sets that flag and stat reports the root with a fixed `S_IFDIR | 0755`, so neither can see a clear that landed; the probe instead hammers every path that reaches the root node with a mode-adjacent operation (`chown("/", -1, -1)` and `chown("/", 0, 0)`, both 0, though neither reaches the clear at all: the root is already owned 0:0, so the change gate answers first and the guard is never asked. The call that does reach it is `chown("/", -1, 1)`, which moves the group and is put straight back, and that pair is the whole of the guard's proof: without it the phase passes with the guard deleted. Also `chmod("/", 0755)`, 0 and stored nowhere; `open("/", O_WRONLY|O_TRUNC)`, `-EISDIR`; `creat("/")`, `-EINVAL`; and a `write` through a descriptor on `/`, `-EBADF`) and calls `sync` (36) after each attempt. The sync is the proof: the page cache is write-back, so without it a spurious clear would sit in a dirty frame and never reach the platter before QEMU is killed. `crash_test.sh` runs it under `rach2.fsdisk rach2.rescue`, waits for the token, kills QEMU, and requires offline `fsck.krffs` still to report "not cleanly unmounted".

## musl integration tests

`musl/` holds programs linked against the ported musl libc (built by `musl/build.sh`, or `make musl-programs`, and staged into the test image under `/musl`, so `/musl/hello` and `/musl/mallocqsort`). They prove the kernel hosts a real C library end to end, each printing a success line that begins with its token (some append run detail in parentheses): `MALLOC QSORT OK` (`mallocqsort`: malloc, qsort, a 256 KB mmap allocation), `CATFILE OK`, `DEVTEST OK`, `OFDMUSL OK`, `PIPEMUSL OK`, `POLLMUSL OK`, `PTYMUSL OK`, `MTTY OK`, `SIGMUSL OK`, `RNGMUSL OK`, `TIMEMUSL OK`, `COWFORK OK`, `PERMMUSL OK`, `AUTHMUSL OK`, `SUIDMUSL OK` (a setuid-root exec seen through libc: `getresuid`, `getauxval(AT_SECURE)`, and the saved-id dance), `BUDGETMUSL OK`, `SOCKFILLMUSL OK`, `TCPSENDRECV OK`, `READVMUSL OK` (how much of a command line `execve` has, which a link line decides, tested at every boundary, not in the middle: exactly 63 arguments arrive whole and the child asserts the count and the last string itself, 64 is `E2BIG`, the same pair for the environment, exactly the 3072-byte budget shared by both vectors is accepted and one byte more is `E2BIG` WITH THE CALLER STILL RUNNING to say so, since the check that would otherwise catch it runs after the old address space is gone and kills the process instead, and a vector that fills the buffer exactly and is followed by another entry is `E2BIG`, not `EFAULT`), `SPAWNMUSL OK` (`system(3)` and `popen(3)`, which this kernel could not run at all until the vendored musl was patched to fork, not clone: a command's status arrives through the wait encoding, a command's output arrives through the pipe with `pclose` reporting its status, the parent's own stack and heap canaries are intact afterwards, and `clone` itself must still answer ENOSYS with a real stack passed, because a kernel that cannot share an address space must not answer the call that asks for one), `VMAMUSL OK` (how many separate mappings one process may hold: four regions are spoken for before a program runs a line, every large allocation a C library makes takes another, and the compiler has outgrown the table twice, at sixteen entries reading a 1.9 MB archive and at sixty-four linking the machine's own `login`, both times reporting "memory full" with the machine barely touched; the probe now requires more mappings than sixty-four could grant, so a regressed table fails it), and `ISHMUSL OK` (the ISH shell's `-c` form and the status it reports, which is what `su -c` reads: the command's own status, 127 for a name that resolved to nothing, 126 for a redirection that could not be opened, and 128 + N for a command a signal killed), plus `hello` and `ctrlcmusl` (which prints its result inline).

`statushelper` is staged beside them and is deliberately absent from `tools/runtests.py`'s `PROBES`, the way `idreport` and `suidhelper` are absent from the freestanding list: it exits with the status it is told to and kills itself when told to, so listing it would fail the suite. `ishmusl` runs it through the shell.

A program here that must link a source from elsewhere in the tree names it in a `link-deps:` comment, the convention `tools/hosttest.sh` already parses for the host tests, with the path written from the repo root; `musl/build.sh` also puts `utils/` on the include path, so a probe can test the library its program links. A named source that is not there fails the build with its own name, not as a bare "no such file" from the compiler.

`pwauthmusl` (`PWAUTHMUSL OK`) links the credential library (`utils/pwauth.c`) and drives the setuid-root `/su` staged beside it. It is the guest half of the credential proof, and it covers what the host test cannot: a real kernel, a real `/etc`, two processes racing for one transaction, a real terminal, and a real set-id exec. In order, it mints a salt twice and requires two different ones of the declared length and alphabet, which is the positive control the no-entropy run inverts; it replaces a file owned by uid 1000 at mode 0640 and requires the replacement to carry that owner and that mode, to leave no temporary file, and a reader holding a descriptor across the rename to go on reading the file it opened, whole, then does it again with the original at 04640, where the owner must be taken before the mode or the chown clears the set-id bit; it runs the interleave, where two children read and rewrite one file ordered by a pipe so that the second begins its transaction while the first sleeps inside its own, and requires both lines to survive, the second child's acquire to have really waited, and the wait to be announced exactly once (without the lock the second reads the pre-image and its rename destroys the first one's line, which is the lost update the transaction exists to prevent); it writes a lock at the real `/etc/.pwlock` naming a reaped child's pid and requires the acquire to be refused with the file still there and its bytes unchanged, then requires the same of that lock with its modification time pushed back an hour, which is the assertion an age bound fails, and then removes the file by hand and requires the next acquire to succeed; it forks under a held transaction and requires the child to hold nothing, so that neither the child's `exit` nor the signal that kills it drops its parent's lock and its three entry points all decline, and it then clears the lock out from under a live holder and requires neither the publish nor the release to touch the file that took its place (the recorded pid is the only identity available, since `st_ino` here is a hash of the name and two files that carried one name in turn share it); it drives a password prompt on a pseudo-terminal through a stop and a continue, requiring nothing typed to be echoed, a `^Z` to stop the reader with the terminal's modes put back (proved by typing while it is stopped and seeing the echo), the continue to take echo away again and reprint the prompt, and the password read across the whole cycle to be exactly what was typed after it; it sends a suspend character with more bytes behind it in one write, which the discipline does not flush, and requires none of them to become a password byte; it continues a stopped reader that is no longer the foreground group, which is a shell's `bg`, and requires the terminal to be left echoing and the prompt not reprinted into the shell's session; it hands a child a standard error that is a pipe with no reader and requires both a prompt and a writer's diagnostic to survive it, since this kernel raises `SIGPIPE` on that write and the default action would kill the reader with the console silenced and the writer with its lock still in `/etc`; and it runs `su` from a uid-1000 caller with the known password on standard input, requiring the login form to land in the target's home under a leading-dash `argv[0]`, the non-login form run from the same working directory with the same caller environment to do neither, both to reach the target with exactly the five variables `su` builds and none of the caller's, and a wrong password to be refused with the caller's identity unchanged. It waits out the lock's real ten-second retry budget twice and sleeps inside a held transaction once, so it takes tens of seconds where every other probe takes a moment; `make test` widens the per-step window for it. It puts `/etc/passwd`, `/etc/shadow` and `/etc/group` back byte for byte, removes its own fixtures, and asserts before it does that no lock and no temporary file was left anywhere it touched.

`passwdmusl` (`PASSWDMUSL OK`) drives the shipped setuid `/passwd` at the mode a user runs it at, and is the guest half of phase 10. The change is asserted on the file's bytes and metadata, not on an exit status: the account's hash must become a `$6$` with a different salt that `crypt` reproduces from the new password, every other line must be byte-identical (a check through the account alone would pass on a file that lost every other one), the mode and owner must still be 0600 root, and no temporary file and no lock may remain. Then three refusals, each of which must change nothing at all: a wrong old password; an unprivileged caller naming another account, which is the real-uid rule, since the binary is 04755 and a test on the effective uid would authorize everyone; and a database naming one account twice, which musl's parsers would resolve by file order and which this program refuses outright, because the line that authenticates and the line that is rewritten could otherwise be different ones. Then the concurrent case, which is what the lock exists for and what no single-process test can reach: the image has a second account, `probe2` at uid 1001, because a lost update is only visible when two accounts change. The rendezvous is a token and never a sleep: the parent feeds the first writer its old password and waits for the exact `New password:` on its standard error, which it can only have printed after authenticating, so the parent knows, not assumes that the transaction is held before the second writer is started. Both changes must survive, and root's line with them. Every case restores the three databases before it runs, because a case that ran before it changed a password and the refusals would otherwise pass for the wrong reason, not for the rule they name. Which half of the entropy contract runs is `getrandom`'s answer and never a CPUID bit: on a full draw it runs the cases above and exits 0 with `PASSWDMUSL OK`, and on `-EIO` it runs the fail-closed case alone, which requires the refusal to arrive before the new-password prompt is ever printed and every database to be byte-identical, then exits non-zero with `PASSWDMUSL OK (fail-closed)`. The two gates cannot be satisfied by each other's side: the suite scores on the exit status, so a fail-closed boot under `-cpu max` fails it, and `make test-noentropy` matches the token and never reads the status.

`addusermusl` (`ADDUSERMUSL OK`) drives the shipped `/adduser`, and where `passwdmusl` proves one file replaced, this proves four things published in order. Nothing makes the four one change, so what makes an interrupted run safe is that every prefix of the order is a system a reader can still make sense of, and that is proved by injection, not by a reading of the source: the image stages `/adduser-crash`, the same source built with `-DADDUSER_CRASH_POINT`, which takes a leading count and `_exit`s the instant that publication has landed. One round per point asserts what must be present, what must still be byte-identical to the pre-image, and what the refused re-run must name. Round one is the case that reads two shadow lines with the shadow file dropped from the absence check, which is the failing input that check exists for. The crash dies inside the transaction, so every round also leaves the lock a real crash leaves: the probe asserts it is there and clears it the way root would, since the never-break rule would otherwise make the re-run refuse on the lock, not on the residue the round is about. Beside the injection: the end-to-end case, asserted through `getpwnam`, `getgrnam` and `getspnam`, not on bytes alone, because parsing the account back is a different claim from the bytes having landed; the failed password, after which the account exists in all three files with its field still `!`, which is the intended end state of the last prefix and not a residue; the refusals, including a name written by hand into `/etc/group` alone, which a per-file absence check catches and a check on the account as a whole would not; and contention. `passwd` takes its transaction after its prompts, so no live writer here holds the lock across anything a test can synchronize on, and the deterministic half is built on the lock the crash build really leaves: against it `adduser` must report waiting, still be alive under `WNOHANG`, and have published nothing, which is exactly the pair an `adduser` that ignored the lock fails. The live half races two real writers, a password change against a creation, then two creations, which must come out with two different uids. The closing cross-check runs both directions over whatever the run left: every passwd line has a shadow line and a group whose gid it names, and no name appears twice.



The test image stages `/bin/sh` (the ISH shell) and `/bin/echo` for `spawnmusl`'s sake, since musl's `system` and `popen` exec `/bin/sh` literally and this shell has only `cd` and `exit` as builtins.

`saltnoent` (`SALTNOENT OK`) is built by the same sweep and staged at `/musl/saltnoent`, and is deliberately absent from `tools/runtests.py`'s `PROBES`, the way `musl/rngmusl` already sits in the tree outside the list: it must fail where entropy is trusted, and `make test` always boots `-cpu max`. `make test-noentropy` boots the same image on a CPU that exposes neither RDSEED nor RDRAND and runs it there. It asserts the premise first, that `getrandom` really refuses, so a machine that did have the instructions reports a wrong premise, not a mystery; then that `pwauth_mint_salt` returns -1 with every sentinel byte of its buffer untouched and prints its one line exactly once, read back through a pipe put on standard error for the call; then that a writer's whole sequence around the failed mint (take the transaction, read `/etc/shadow`, mint, fail, end) leaves the database byte for byte what it was, with no temporary file and no lock behind it. Without that target nothing in the tree could tell a fail-closed minter from one that quietly fell back to the untrusted stream.

## Build

Requires a cross-compiler (`i686-elf-gcc` or `x86_64-elf-gcc`):

```sh
make        # build all freestanding test programs
make clean  # remove the compiled binaries
```

The musl programs build separately with `musl/build.sh` (after `vendor/musl/build_libc.sh`); the host tests build and run through `make verify-host`.

## Running in Rach2

The probes are staged into the test image (`build/images/test.krffs`), which `make test` builds and boots headless to assert every probe exits 0. To drive them by hand instead:

A probe passes only by exiting 0 itself. The runner reads the status off the line that hands the debug shell back, which has the probe's own outcome: `sys_exit` prints the exit status there and the signal path prints the signal, so a probe killed by a signal fails whatever its children did. It is not scored on a bare `Process exited with status N`, which the kernel prints for every process exit under the debug shell, a forked child's included; an image running `/sbin/init` prints no such line at all, since there the shell answers through `$?`. A run that ends early fails and names the probes it never reached, and `tools/runtests.py --selftest` checks that scoring rule against recorded serial shapes from `make verify-style`, without a boot.

A new freestanding probe is registered in three places, all of them by hand: `tests/Makefile`'s `PROGS`, `tools/runtests.py`'s `PROBES`, and an entry here. A musl probe is registered in two: `tests/musl/build.sh` discovers every `.c` in that directory and builds it, so there is no list to add it to there, but it still needs its `musl/<name>` line in `PROBES` and its entry here. A helper is registered in the places that build and describe it and never in `PROBES`, since nothing runs it on its own. So does a probe that must fail on the boot the suite uses, which is why `musl/saltnoent` is not in the list either; `make test-noentropy` runs it. So does one that needs a boot the suite does not make: `musl/creddisk` wants a disk-backed mount and three boots of one image, so it has a target of its own, `make cred-persist-test`, and a manifest of its own. A probe named `*probe.c` is also picked up by the style gate's hard clang-format and cppcheck lists; one under `tests/musl/`, a helper under `tests/` that is not named `*probe.c`, and any new source under `utils/` are not, and must be added to `tools/check.sh`'s `newcode_ch` and cppcheck list by name in the same commit. The gate's globs are deliberately not widened to those trees, which are legacy and unformatted.

1. Build the test image:
   ```sh
   make test-image
   ```

2. Boot Rach2 with the test image as a module:
   ```sh
   qemu-system-i386 -kernel build/rach2/kernel -initrd build/images/test.krffs -serial stdio
   ```

3. Execute from the Rach2 shell:
   ```
   > exec hello
   Hello from ELF!
   Process exited with status 0

   > exec filetest
   Opening hello.txt... OK
   Reading file... OK
   Content: hello, world
   Closing file... OK
   All file syscalls passed!
   Process exited with status 0

   > exec vmprobe
   VMPROBE OK
   Process exited with status 0
   ```

The network tests target QEMU's SLIRP gateway 10.0.2.2. `udptest` and `tcptest` expect a host echo server reachable at 10.0.2.2:7777 (UDP and TCP respectively). `dnstest` reads `/resolv.conf` and `/hosts` from the image root; its live cases resolve real names through SLIRP's forwarder 10.0.2.3 and need host internet.

`make test-noentropy` boots the same test image on a CPU that exposes neither RDSEED nor RDRAND (`-cpu qemu64`, passed through `tools/harness.py`, which supplies no `-cpu` of its own) and runs `/musl/saltnoent` from the debug shell, passing on its `SALTNOENT OK` token. It is the one run in the tree where the kernel's random pool is untrusted, so it is the only place the fail-closed salt policy can be seen at all.

The disk probes boot disk-only instead of from a RAM module: `tools/harness.py` attaches the scratch image with `--drive` (no `--initrd`) and the kernel mounts KRFFS off the real disk under `rach2.fsdisk`. `make test-disk`, `make persist-test`, `make cred-persist-test`, and `make stress-test` do this; to drive one by hand, build a disk with `tools/mkdisk.sh` and boot it the same way (see the disk make targets for the exact `--drive` and `--append` strings). The AHCI variants (`make test-disk-ahci`/`persist-test-ahci`/`stress-test-ahci`) attach the disk as an `if=none` drive and add the HBA through the harness's repeatable `--qemu-arg` passthrough (`--qemu-arg=-device --qemu-arg=ich9-ahci,id=ahci0 --qemu-arg=-device --qemu-arg=ide-hd,drive=drv0,bus=ahci0.0`), appending `rach2.disk=ahci` so the kernel selects the AHCI backend; the NIC `-device` stays wired. `winprobe` instead boots from the test image and faults on purpose; the harness passes it when the kernel survives.
