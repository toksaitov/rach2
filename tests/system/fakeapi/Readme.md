# The scripted API service

`native/` implements the test service in C11. `make build/tests/cases/machine/agent_server` builds it with static OpenSSL libraries from the GNU layer's pinned source. The preparation may use the compiler, Perl and Make; the service loads no host library or module and runs no command. `agent_relay` is the same compiled program under the name QEMU's restricted guest forward uses. `sntpserver.c`, one directory above, uses the same portable socket and process-lifetime code without TLS.

On Windows the service uses the collection's wide file adapter for asset archives, JSON, credentials, certificates, records and recursive cleanup. OpenSSL receives the corresponding extended native certificate paths. The native selftest unpacks and reads JSON beyond `MAX_PATH`, generates and loads the real certificate and key there, then removes that private tree without following reparse points.

The OpenSSL archive fetch restores MSYS path conversion for the native checksum helper. The submake clears inherited Make flags and runs one job within its parent's reserved recipe job. A forced native rebuild therefore does not force upstream configuration regeneration. The installed Make wrapper, actual Make path and admission limits remain in effect.

The service accepts these commands:

* `agent_server ca DIR NAME...` creates a private authority and an ECDSA server certificate for the DNS names and IP addresses. The certificates expire after two days. The caller owns `DIR` and removes it.
* `agent_server serve SCRIPT RECORD CERTDIR [PORT]` serves HTTP/1.1 over TLS on loopback, using a free port when none is given. It prints its listening port, appends JSON records for requests and WebSocket messages, and prints its verdict on SIGTERM, SIGINT or a Windows console stop. Windowless native services also poll Etude's process-identity-bound stop event into the same handler. It also writes `RECORD.status`. The verdict fails for an unexpected request, a failed exchange or any nonrepeated step left unplayed.
* `agent_server relay PORT`, or `agent_relay PORT`, copies the connection on its standard streams to the service. It joins its copy thread before returning.
* `agent_server render SOURCE DESTINATION ROW` makes the selected row's script, including its repository paths, unordered service calls, screen requests and held final answer.
* `agent_server accept-prepare AGENTJSON GHJSON DIR AGENT` creates the acceptance scripts and authority for both programs' declared hosts.
* `agent_server verify SCRIPT RECORD ROW VERSION` checks each recorded request against its step, the required credentials and user agent, and the row's WebSocket exchanges. Repeated steps are optional and every other step must occur once.
* `agent_server unpack ARCHIVE DIR` reads the immutable source assets with etude's tar reader. `worker-proof ARCHIVE DIR` checks the returned worker board, log and transcripts; the C scenario separately checks the origin's branches and commits with the guest's Git.
* `agent_server remove DIR` removes private fixture files after their processes have ended.

Certificate serial numbers use OpenSSL's integer encoder, which removes leading zero bytes and inserts only the padding the value needs. An all-zero random value becomes one. The native fixture checks six fixed serials through the production certificate generator and OpenSSL's DER reader.

`agents-assets.tar` contains only the tracked source fixtures these cases consume: `agents_rows.sh`, the agent rows, acceptance guest commands and JSON, this directory's JSON and repository fixture, `tools/flow`, the commit-message hook `tools/git-hooks/commit-msg` and the five agent package recipes. Make computes one ordered `git ls-files` list for both prerequisites and tar operands; the archive rule itself is also a prerequisite. A changed fixture or rule therefore rebuilds the archive, including an old archive that contained the whole tests and tools trees.

The row metadata selects its package and API script. A row that names its script with `# script:` returns a result, which the C scenario checks after `verify`. The worker-session row commits the prepared assets into its private repository and runs the real worker loop. It retains all of `tools/flow`, which the loop archives when it updates itself, its actual prompt, the fake GitHub command and the commit-message hook the loop enables. The pre-commit hook stays out, since the guest has no clang-format for it to run. Acceptance cases read their JSON and upload the guest commands and three repository files separately. Codex and Muse API cases read their API scripts and the same repository files. No unrelated host test, case manifest or runner source is transferred to each agent machine.

A script has a `protocol` and a `steps` array. The protocols are `plain` for literal requests and responses, `responses` for streamed OpenAI Responses and WebSocket continuations, `anthropic` for Messages, and `gemini` for generateContent. The checked JSON scripts in this directory and `../agents/` are the protocol fixtures. Requests are matched to the first available ordered step, then to available unordered steps. A repeated step must be unordered. A held step waits for `/fakeapi/release`; `/fakeapi/held` identifies its pending request. Control requests consume no step and have no request number.

The transport accepts request bodies by length or chunks, including `100-continue` and chunk extensions. Responses use a length or chunked server-sent events. WebSocket requests use a checked upgrade digest, masked client frames, fragmented messages, ping and pong, 16-bit and 64-bit lengths, and the close handshake. A reset before the required exchange ends fails the step; a reset after the server starts the closing handshake does not undo it.

Each connection has a thread. POSIX stop handlers remain installed while shutdown closes every owned socket, wakes held replies, joins every thread and writes its verdict and status. Repeated stop delivery from the executor cannot interrupt that publication. The services also watch their parent's lifetime. A scenario that ends unexpectedly therefore cannot leave a service listening outside its owned job. TLS handshake failures consume no script step, which preserves the case that rejects the private authority against the guest's system store before trusting it explicitly.

`native/selftest.c` compiles as `build/tests/system/fakeapi_test`. It checks the production request parser, protocol checks, response framing, ordered and repeated steps, held replies, fragmented WebSockets, reset behavior and all response variants using byte buffers in place of SSL reads and writes. On POSIX the same fixture also delivers separate stop signals before and during verdict output, then checks the complete request record, status bytes and writer failure. The machine fakeapi case supplies the real TLS, hostname validation, guest routing and socket checks, with the GNU guest's curl and `/etude-wsclient`, compiled from `native/wsclient.c` when the GNU root is prepared.

The native WebSocket client retains the exact successful exchange on stdout. A failure identifies its TLS connection, HTTP upgrade, ping, text or close stage. Failed SSL reads and writes report the requested frame part, remaining bytes, actual return value, SSL_get_error, saved errno and OpenSSL error queue. BIO connection failures report their return and retry state separately. Protocol failures report status, frame flags, opcode or length. The server records frame flags, length, mask and at most eight masked and decoded payload bytes in hexadecimal; a mismatched client pong reports the same bounded prefix. Server setup failures identify script loading, TLS certificate/key loading, record opening or socket binding, with errno and the OpenSSL queue. These diagnostics do not accept a failed or incomplete exchange.

Both native frame paths load the four-byte mask into a uint32_t with memcpy and repeat that complete word across four-byte payload groups, then handle the remaining bytes. The copies permit unaligned payloads and the XOR has the same byte meaning on either byte order. The existing protocol fixture builds masked input one byte at a time and compares complete decoded payloads of 5, 8, 9, 63, 64, 65 and 200 bytes, including the extended-length header. Global compiler optimization remains enabled.
