# tests/system/: the behavioral test machinery

This directory contains everything that runs Rach2 to test it: the QEMU runners under `runner/`, the suite scripts under `suites/`, the capture checkers under `checkers/`, the fixture builders under `fixtures/`, and the real-machine acceptance procedure under `accept/`. The suites themselves are Make targets in `suites.mk`, which the root `Makefile` includes with one line so no test rule sits among the product rules. The guest probe sources stay in [`tests/`](../Readme.md) and the native sanitizer tests in [`tests/host/`](../host/Readme.md).

`sh tests/system/ptrace_debug_mutate.sh`, with `ARCH=i686` or `ARCH=x86_64`, builds a 2 MiB image containing only ptracemusl and verifies the staged executable. Its syscall-step fault removes the dispatcher's step stop and must execute the next instruction before trapping. The x86-64 entry rows inject vector 1 before `syscall_entry` changes stacks or GS, since QEMU TCG does not delay the `MOV SS` watchpoint. With that injection, a syscall whose user stack pointer is 1 must return its result; a fault that removes the debug interrupt stack must produce a double fault, and one that uses the saved CS to choose GS must reset the machine, a triple fault, before any handler prints. A further x86-64 fault removes the post of a deferred hit from `sig_pending_now`, and the `sigwait` row must fail; i686 posts the hit from the exception and runs that row only unmodified. Where `/dev/kvm` is usable, on both architectures the `delayed` and `delayed-poll` rows run under KVM, which delays a watched `MOV SS`'s hit into the system-call entry as hardware does; neither may report the early exception. A fault that posts the hit without forcing it must fail `delayed`. The `delayed-poll` row uses an infinite raw `poll` with no descriptors and a valid user stack, and requires a `SIGTRAP` stop with `TRAP_HWBKPT` at the return instruction with result `-EINTR`. Replacing `debug_pending = arch_debug_pending();` with `debug_pending = 0;` in `signal_pending` must fail with `delayed infinite poll did not trap` after the row's ten-second completion bound. Without KVM the script prints that those rows did not run. Every restored source is touched and rebuilt, and its kernel must match the corresponding fixed kernel. A trap stops the guest process group before restoring and rebuilding the original sources. Logs, kernels, source copies and checksums remain under `build/tests/ptrace-debug.*`. The ordinary default suite runs the same ptracemusl rows without injection; either `MOV SS` row reports an exception before the system call with a not-run line.

`sh tests/system/ext2_batch_mutate.sh` builds a small RAM image containing `ext2probe` and boots it beside a 16 MiB ext2 volume, which the probe mounts with `sync`: a mount without it writes back, so a write costs no command before fsync whether or not ext2 batches it. The probe counts sixteen rewrites of one 4 KiB block and two 4 KiB appends through `/proc/disk`, including the final fsync. Rewrites require four commands and two flushes in total; the two appends permit at most ten commands and five flushes. The probe reopens and checks both files, unmounts, and the host checks the volume with `e2fsck` and reads both files with `debugfs`. The mutation makes every write drain its batch and must fail both command-count rows in separate boots. An optional revision argument also builds that revision's ext2 source and requires the same failures. The kernel and the probe are built for the architecture `ARCH` names, i686 when it is unset. Every phase rebuilds the kernel; the restored source is touched and rebuilt, and the restored kernel must match the first. Its trap stops the test process group before restoring source. Sources, kernels, images, counts and logs remain under the printed `build/ext2-batch-proof.*` directory.

`sh tests/system/recovery_key_test.sh` runs the recovery-key Make recipes in an isolated tree with temporary builder and operator keys. It compiles the native KRFFS tools, stages the recovery manifest's key directive into a 1 MiB image, extracts the file and requires both public identities. It also checks the default, preservation of a custom list, unchanged timestamps on repeated composition, and rejection of private, missing, empty and malformed extra files. The style suite runs this row. `--mutate` omits the operator key in a private generator copy, then compiles a private stager that truncates the staged list after the builder's key. Each mutation must fail the image assertion; restored sources are touched and the stager and image rebuilt before each passing restoration. A shell trap restores the private sources after synchronous commands finish. Logs and images remain under the printed `build/recovery-key-test.*` directory. This checks image contents, not an SSH login or a physical stick.

`sh tests/system/dryrun_test.sh` runs a recipe of the vendor stamps' shape over the real `mk/dryrun.mk` in a private tree, with no flags, with `--no-print-directory`, with `-n`, with `--dry-run`, and with `-n` beside `--no-print-directory`, and requires the build to run in the first two and to be skipped in the last three. The style suite runs it. `--mutate` puts the first-word test back in the private copy of the rule and requires the `--no-print-directory` row to skip a build it should have run, then restores the rule, touches it and requires every row again. It reads MAKEFLAGS as this make writes it; the make on another host may write it differently, which is why the rows are the flags and not the string.

`sh tests/system/build_rules_test.sh` reads the build's rules in private trees and builds nothing. The source-list guard must pass a tree whose kernel sources and list agree and name a source missing from either; the root `make clean` must succeed with no cross compiler on the PATH and remove what each sub-make owns, leaving `build/tools`, `build/man` and `build/vendor`. The other rows read the make database, `make -pn`, of a private copy of the root Makefile, `mk/` and the suites' fragment: `os-real-grub-disk` has a rule that makes the GRUB disk and every prerequisite of the disk's rule is a target or a file of the tree (entry 112); the sealed and GRUB disks' rules name mkmbr, fatchains and grubembed, and the rules `mk/images.mk` holds have their names, which they have only when the tools are named before the disk rules and the fragment is included after the names its rules take (entry 114); a tree with a recovery key makes both disks under `-with-key` names and `make no-recovery-key`, run in the private tree over files planted for both architectures, removes both names of both from each; and in a tree with a key `make release` and `RELEASE=1` are refused before anything is built while a development build is not, and `RELEASE=1` is not refused in a tree without one. The style suite runs it. `--mutate` puts nine faults into the private copies, one at a time: the guard's two comparisons emptied, the toolchain check's exemption for clean removed, the GRUB disk's rule renamed, the tool names moved into `mk/images.mk` after the disk rules, the include moved before the names its rules take, the sealed disk's plain name, `ARCH_BUILDS` cut to i686's tree, and the release refusal turned into a message. Each must fail its row, and the restored copy, touched, must pass every row.

## The runner

`tests/run NAME [NAME...]`, `tests/run core` and `tests/run all` are the entry points. The runner is the shell script `tests/run` beside `tests/registry`, and the registry is six fields: the suite's name, the external commands it needs, its tier, the globs of what it writes under `build/images`, the guest memory its machines ask for at once, and the architectures it runs on, both when the field is left out. The make target is the name with `run-` in front, so it is not written down; `tests/run style` checks that every name has a target and every target has a name.

`ARCH` names the architecture a run builds and boots, `i686` when it is unset or `x86_64`, as `mk/arch.mk` does. The runner gives it to every make it starts, and `all` and `core` are the suites the registry lists for it; a suite named on the command line that does not run on it is refused before anything is built. `suites.mk` exports three variables to the recipes: `RACH2_ARCH`, the architecture; `ARCH_BUILD`, its build tree, `build` or `build/x86_64`, from which the suites take the kernel, the programs and the images; and `RACH2_QEMU`, its emulator, `qemu-system-i386` or `qemu-system-x86_64`. The shell suites, the harness and `runtests` boot `RACH2_QEMU`, and `qemu-system-i386` when it is unset, so a suite is written once for both architectures. In the registry the tool `qemu` stands for that emulator. Where a suite's expectations differ by architecture it gives each its own: the GNU rows take the architecture as their second argument and expect its loader, ELF class, triple and `uname -m`, and `tests/run fpu` boots its `rach2.nofxsr` row on i686 alone, since every x86-64 processor has FXSR. The fault scripts that build or boot a guest take `ARCH` from the environment through `mk/arch.sh`, give it to every make they run and to `tests/run`, read the kernel, the programs, the images and the logs from the architecture's build tree, and boot its emulator; `sigcontext_mutate.sh`, whose fault is in i686's signal frame, builds for i686 whatever `ARCH` says. The host tools they use stay under `build/`.

The runner uses these mechanisms:

* Names and tools are checked before anything is built. A run whose last suite needs a missing `mformat` fails in the first second instead of an hour later.
* For a set, `prepare-all` builds the product and the test tools once, before any suite starts. Twenty suites each running Make on the same tree would build the same object twenty times, or race over it. A suite run alone builds through its own target instead, with `make -j run-NAME`, so it builds only what that target names: `tests/run host` after an edit to a utility builds that utility and what its own target names, and not the five images and two ISOs the edit also touches. Either way the components, the builds that turn sources into programs, are built first in a Make of their own, because an image rule that meets a staged program and the component that builds it in one Make reads the program's time before the component has run and keeps the old image.
* The suites then run in a pool, `RACH2_WORKERS` at a time, default twice the processor count divided by the processors each machine has, `RACH2_CPUS`, and at least four, four when the count cannot be read, and within a memory budget, `RACH2_MEMORY_MIB`, default three quarters of the host's memory, against the guest memory each suite declares in the registry. Most of a suite's time is spent waiting for an emulated machine rather than computing, so the useful count is above the core count; the memory budget can hold the number below the worker count.
* Each pooled suite's output is held and printed when that suite ends. Start and progress lines go directly to the run log. The progress line names the suite, its elapsed time and the time since its last output. Every suite has an idleness limit, `RACH2_IDLE_TIMEOUT`, default 300 elapsed seconds: the suite is stopped as hung when for that long it has printed nothing, its machines have printed nothing, and its process group has used next to no processor time, under a tenth of a processor over that span, which the supervisor samples every ten seconds from `ps` with the time of reaped children from `/proc` where it is; a halted machine's timer costs a few percent under either accelerator and is not work, while a process come or gone is. Suite output, QEMU console output and processor time each reset its clock, so a slow machine that writes for minutes without a word is left to finish, and only an idle silent one is stopped. The limit is independent of completion bounds and is never scaled. On idleness the supervisor sends TERM, then KILL after two seconds, reports the last output, and fails the suite. The pool continues unless stop-on-failure was requested.
* A suite that fails has its serial logs kept where no later run writes over them: the files under `build/images` whose names end in `.log`, of the globs the suite owns, that the run wrote, and the console of every machine it booted, which the shim records in the run's scratch directory, are copied to `build/tests/failed/NAME.DATE-TIME.PID`, and the suite's output names that directory. The next run writes over the logs under `build/images` and never into a kept directory; the directories stay until someone removes them.
* Registry order is the order suites are taken in, longest first. The runner passes over one whose memory does not fit beside the running suites and takes the next that does; with the pool empty it takes the first pending suite whatever its memory, so a suite larger than the whole budget runs alone rather than never. A pool finishes when its longest member does, so a long suite started last leaves the machine idle around it.
* Completion bounds use the seconds written in the suite. The runner does not calibrate the emulator, delay a set for a measurement, or narrow the pool. `RACH2_TIMEOUT_FACTOR=F` explicitly multiplies completion bounds for a single suite or a set, including the suites that run serially. It accepts decimals from 1 through 64, the range supported by the consumers, and rounds up to a tenth. The start line records the factor and worker count. Rate assertions, deliberate load intervals and guest deadlines retain their values. The internal `RACH2_DEADLINES` and `RACH2_DEADLINE_FACTOR` variables are set by the runner; inherited values are discarded. `calibrate.sh` remains an optional diagnostic and is never invoked by `tests/run`.
* After locking the tree, the runner installs a shim on `PATH` for each of `qemu-system-i386` and `qemu-system-x86_64` that the host has, so the machines of either architecture, and the x86-64 machines an i686 suite boots for UEFI, are handled alike. The shim chooses the accelerator for every machine a suite boots, so no suite names one: KVM where `/dev/kvm` can be opened, HVF on an x86 Mac that reports it, the emulator otherwise. A host with a `/dev/kvm` its user cannot read and write is refused, since the completion bounds were set under KVM and the emulator misses the longest; `RACH2_QEMU_ACCEL=tcg` asks for the emulator outright. `RACH2_QEMU_ACCEL=kvm|hvf|tcg` names one outright; `tcg` is how a KVM host is measured without it. `RACH2_CPUS`, a whole number from 1 to 64 and 2 when it is unset, is the number of processors the shim gives every machine, as `-smp` ahead of the suite's own arguments, so a suite that names a count of its own keeps it. The start line records the architecture, the accelerator and the processor count. The helper becomes QEMU without changing its PID and starts a child that relays the console. It records both PIDs, groups and process start times. The relay copies QEMU's standard output and standard error to a per-suite console transcript and forwards the bytes to the suite's existing pipe or log. Signalling the suite's QEMU PID still signals the machine, including with KILL; the relay exits when QEMU closes its output. Every current suite uses QEMU's `-serial stdio` route. A registered machine still alive fifteen seconds after TERM fails that suite with its PID, group, start time and command. A zombie or a reused PID does not count as a live machine and is excluded from ledger cleanup. Group and job ledgers and process inspection supply other cleanup targets. An inherited liveness pipe also detects ordinary unregistered workers after changes of group or session and reparenting, under the inspection limits below.

`style` and `host` run alone, before the pool: `style` rebuilds the kernel with its own flags, and both share a scratch directory. Every other suite runs in the pool. Nothing runs alone after it: `usb` waits for the guest's own report of each device, `diskrate` judges counts and prints its times for the record, `install` builds under completion bounds the factor scales, and `imagerace` builds an image of its own, so none of them needs an idle host.

A pooled suite writes only the image files the registry declares for it. The registry's fourth column declares what a suite writes under `build/images`, as globs, and a suite whose files are named after it declares nothing: `NAME-test*`, `NAME.*`, `NAME-*` and `NAME/*` are its own, and a second-card twin's are the plain names with `-e1000` before the extension. The runner refuses a glob two suites declare before anything runs, and after a run lists every file made under `build/images` since the products were prepared: a file no suite of the run owns, or that two own, fails the run by name, `run: images: undeclared:` or `run: images: shared:`. The column is the inventory of what the suites touch, read by a person once and by the runner every time. The runner's check is of names: it cannot see which suite wrote a file, so a suite that wrote a file named for another would pass it; that a suite writes only what it declares is what a person reads the suite for.

A suite waits for a token and asserts on what the kernel counts rather than on the clock. The USB latency rows print the microseconds the kernel stamped and judge counts: no pump of the controller between the wake of a reader beside a user-mode spinner and its dispatch, and at most 4096 bytes of a `getrandom` call completed between the wake of a reader beside it and its dispatch (entry 129 of the shortcomings list). `tools/verify/suitecheck.sh`, run by `tests/run style`, refuses a `sleep` for a number of seconds in a suite, on the host or typed into the guest, a `wait=` harness step, a typed line of more than 240 characters, since the console's line discipline keeps 255 of a line and drops the rest, and an upper bound on a duration in a probe, unless the line, or the command it is in, is marked `interval: REASON` in a comment and `tests/system/intervals` lists the file and the same reason; the list is the inventory of the intervals the suites keep on purpose, a load applied for a period, a holder that must outlive what it holds against, a poll of a server between tries, and a person reads it. A reason listed with no mark left, or a mark with no entry, fails the check.

`tests/run runner` (`selftest.sh`) drives the runner against a registry and a makefile of its own in a temporary directory, with a calibration fixture that fails if invoked and two mock suites that judge by an explicit bound, and boots nothing. It is the only test of the runner itself. It first runs the harness's `--selftest`.

The stop-on-failure row calls `selftest_stop.sh`, also runnable alone with `sh tests/system/selftest_stop.sh`. FIFOs make the failing suite wait until the other active suite starts; that suite can finish normally only if the queued suite starts. Eight checks require the failure status, the runner's stopped and unstarted reports, both active suites' start events, and the absence of the queued start and the running suite's end markers. No elapsed time decides these checks. `sh tests/system/selftest_stop.sh --mutate` compiles a helper that suppresses a child's failure status, then separately removes the runner's stop-on-failure assignment. Each mutation must fail the event checks; each restoration must pass with a freshly compiled helper identical to the first. Its trap stops the runner before restoring and touching the private sources. Logs, events, executed helper copies and checksums remain in the printed `build/selftest-stop.*` directory. The proof replaces only the unused socket preflight and boots no guest.

`drive.sh` is the console driver for a suite that boots QEMU with `-serial stdio < FIFO > LOG`. `drive_feed` holds the FIFO open and transmits the lines spooled by `drive_type`. A new command sets the search cursor before publishing input, so pre-command output cannot answer it and a fast reply is preserved. Consecutive waits consume matches in order, including tokens and a prompt received in one write. `drive_prompt` recognises a prompt at the beginning of a line, with an optional absolute or home directory, even when a daemon writes after it. A command echo paused at a redirection is not a prompt.

All driver waits take elapsed seconds and never scale them. A caller that wants the explicit run factor passes `"$(scaled N)"`; the `_raw` names remain aliases for callers that already computed a remaining budget. `drive_login` passes its elapsed bound unchanged through the exchange. Shell suites retain their assertions; the procfiles suite now waits for Dropbear's token and prompt instead of sleeping and issuing an extra echo.

`tests/run runner` proves scheduling, idleness, console activity, cleanup, locks, input checksums, explicit factors, prompt matching, stale-token rejection and the logs a failing suite keeps in `selftest.sh`. Its machines are shell fixtures and it boots no operating system. It also calls `runutil_group.sh`, which compiles the actual supervisor with a process-group fixture. A pipe orders the parent before the child so an injected EPERM is tested with both correct and wrong membership; separate cases exercise a real session-leader EPERM and successful child setup after a parent error. Each executed command checks its group and returns a nonzero status for the supervisor to relay. `sh tests/system/runutil_group.sh --mutate` additionally compiles the old unconditional failure in a private copy, requires the membership checks to fail, then restores, rebuilds and checks again. It retains its binaries and logs in the directory it prints. `tests/run drive` adds the delayed console exchanges and the harness's `until=` checks in `drivetest.sh`.

`sh tests/system/runutil_owned.sh --mutate` runs the actual runner and freshly compiled helper in private trees. Ten cases cover an unregistered separate group, a double-forked session, a reaped worker, a finishing worker, a same-group child, a group recorded in another ledger, a six-second shutdown, a persistent same-group survivor, unavailable holder inspection, and interruption. The unregistered workers and persistent survivor must fail by suite name and be stopped. Shutdown within the grace must pass; an empty inspection must be reported as inconclusive without failing. Interruption returns 143. An unrelated process stays alive throughout. Five mutations remove the token check, fail recorded groups immediately, shorten the grace to two seconds, fail an unnamed holder, or kill a recorded group that outlives the grace and let the suite pass. Each must fail its affected proof, followed by a rebuilt passing restoration. The restored helper must match the fixed helper. Only socket preflight is substituted; these suites use no sockets or guests. PID files belong to the proof and are never supplied to the runner.

The same script compiles the production machine checker into `fixtures/runutil_machine.c`. A real child whose saved start time differs and an unreaped zombie must be excluded from both verdict and ledger cleanup; a matching live survivor must fail after TERM and the grace. Removing the start-time comparison must fail the proof. It also runs `ssh_flood_test.sh`, which extracts the SSH suite's flood functions and cleanup traps and substitutes only socket-free peers. Normal completion and TERM must reap all eighty children and remove their FIFOs. Omitting the sleep children from ownership must fail, followed by passing restoration. The runner suite invokes these fixed checks. Logs and binaries remain in the printed directories. With `--mutate` it also runs `rehearse_group_mutate.sh`, the proof of the rehearsal's group size below, so that one command runs the proofs of entries 90 to 93 of the shortcomings list.

### Host interfaces

`runner/runutil.c` is compiled with the host `cc` into each run's private temporary directory before any product build. It uses POSIX clocks, `nanosleep`, process groups, pipes, signals, `stat` and record locks. It supplies elapsed time and fractional sleeps to the runner and its selftest, so neither needs Perl, `pgrep`, `lsof`, platform-specific `stat` or `find` options, cryptographic checksum utilities, or `date +%s`. `ps -A -o pid= -o ppid= -o pgid=` supplies descendants on macOS and Linux; recorded groups and machines remain available for cleanup if the listing fails. For detached pipe holders, cleanup reads native pipe identities through libproc on macOS and `/proc/PID/fd` on Linux. No privilege, service or extra command is required. An unavailable or empty holder listing is reported as inconclusive and does not change the suite status. An unreadable group ledger likewise prevents an outside-group verdict. The same helper, built at `build/tests/system/runutil`, is the suites' one wait: `runutil until FILE PATTERN SECS [COUNT]` returns 0 as soon as COUNT lines of FILE (one, unsaid) match the basic regular expression PATTERN and 1 when SECS, a completion bound under the set's factor, pass first; `runutil gone PID SECS` returns 0 as soon as the process is gone, or has ended and waits to be reaped, which a child of the caller's does until the caller waits for it, and 1 at the bound. Both look every fifth of a second, which is the runner's interval and not a suite's.

The `suite` supervisor creates a pipe before fork. Its child closes the reader and inherits the writer through exec; the supervisor closes its writer. The reader has `FD_CLOEXEC`, so inspection commands cannot inherit it. The writer has no environment variable or documented descriptor number. After reaping the direct child, EOF permits its status immediately. An open token triggers inspection of current holders and every recorded group in this run. A holder outside those groups fails immediately and is reported with its PID and group before cleanup. Recorded groups containing holders receive TERM and fifteen seconds to stop; only an identified survivor then fails. The timer starts after TERM. If no holder can be identified, the check reports that limit and does not fail the suite. Cleanup rechecks pipe identities before signalling holders, escalates to KILL, and reports completion before the verdict. On silence or interruption, the existing two-second escalation applies; the outer runner allows five seconds before killing a supervisor. The ordinary `watch` command adds no liveness descriptor to its command.

The token proves liveness only while descendants retain the writer. A descendant that deliberately closes it, or execs a program that closes inherited descriptors, escapes this check. An exited worker's status is still its parent's responsibility; the pipe cannot recover an uncollected exit status.

Both the supervisor and its child attempt to put the child in its own process group. The parent's attempt can lose to the child's exec. Before exec, a failed child call is accepted only if `getpgrp()` already equals `getpid()`. Otherwise the helper reports the PID, actual group and saved error, and exits 2 without running the command.

The shell tools are POSIX except GNU Make, already required by the build, and `mktemp -d TEMPLATE`, supported by both BSD mktemp on macOS and GNU mktemp on Linux. CPU discovery tries macOS `sysctl`, then Linux `nproc`, then takes four processors. The calendar timestamp uses POSIX `date` formatting. A driver invoked directly without `tests/run` falls back to the epoch format of BSD or GNU `date`; under the runner its deadlines use the native monotonic clock. The optional `calibrate.sh` diagnostic retains its own BSD/GNU date calls and is outside the runner's execution path.

## QEMU runners

* `runner/harness.c` drains pre-command output and starts a new search cursor before each send, preserving fast replies and consecutive matches. After the machine process exits, it drains the serial pipe once before its last search, so output written just before exit can still match; reaping the process reads nothing from the pipe. It starts the emulator `RACH2_QEMU` names, `qemu-system-i386` when it is unset, headless, accepts optional initrd, disk, network, device, and extra QEMU arguments, and executes ordered serial steps. A step's pattern is a regular expression without groups, braces or alternation, so a literal parenthesis is written `\(`; every pattern is compiled before the machine starts, and one the matcher refuses ends the run with status 2 and no machine. Step forms include `expect=`, `seen=`, `send=`, `sendraw=`, `sendfile=`, `until=`, `barrier=`, `tcp=`, `udp=`, `exec=`, and `probe=`; there is no step that sleeps for a number of seconds. `seen=REGEX` waits until the pattern has appeared since the last send, wherever it lies, so two `seen=` steps are satisfied in either order where two `expect=` steps are satisfied only in theirs; the usb suite waits for a keyboard's device line and the shell's prompt that way, since the scan of a hub and the shell's start race. `probe=NAME` expands to an internal `boot=` wait for the shell's prompt, bounded by the run's `--timeout`, followed by `execq=NAME`, bounded by `--steptmo` and the remaining run time. A boot under load can take longer than one command. The command types `exec NAME`, typing it again when the shell answers with nothing for three seconds or with `Unknown command`, and ends when the machine has left or, under `--ok`, when the token has arrived. Explicit `expect=` steps retain the `--steptmo` cap. The harness selftest (`--selftest`) checks that a delayed prompt after the step cap is accepted by the probe expansion, rejected by `expect=`, and rejected when the run timeout expires, and that a prompt written by a child that exits before the parent reads is matched. It also checks that a write to a machine that has stopped reading its serial line ends at the run's deadline: the input pipe is non-blocking, and `send=`, `sendraw=` and `sendfile=` all write through one loop that reads the machine's output while it waits and gives up at the deadline. Each `send=`, `sendraw=` or `sendfile=` step fails unless all of its bytes reach the guest's input pipe, so a guest that printed the `--ok` token and then stopped reading does not pass. The selftest also checks that output the machine wrote before a timeout is read after it, where `pump`, which stops at the deadline, reads nothing, and that a `sendfile=` step whose file opens but cannot be read, as a directory cannot, fails. `tests/run runner` runs it. `sh tests/system/harness_input_mutate.sh` leaves the input pipe blocking in a private copy and requires that check to fail, then makes `drain_rest` read nothing and requires the late-output check to fail, then makes `send_file` take a read error for the end of its file and requires the `sendfile=` check to fail, and passes the restored source after each. `until=SECS` is the wait after `send=exec /probe` whose only purpose is the run's `--ok` token: it ends half a second after an unconsumed token from the current command is found, or at SECS, never past `--timeout`. `tcp=PORT` connects to a port a `hostfwd` forwards into the guest and reads the first bytes the guest's server sends, an SSH banner, connecting again until a deadline scaled as the others are when the guest resets or has not answered; a port that never answers fails the step, since QEMU's user network accepts the host side of a connection before it knows whether anything is there. `--bios` gives the emulator no kernel, so its firmware boots whatever the drives and devices hold in the order their `bootindex` says, which is how a machine boots from a stick image. `sendraw=` writes its text with no newline after it, and reads `\xNN` and the usual escapes, which is how a guest terminal in raw mode is given one byte. `key=`, `mouse=`, `usb=add:`, `usb=del:`, `drive=add:`, `drive=del:` and `nmi` go to QEMU's own command channel on a unix socket beside the serial line, because a key pressed, a mouse moved, a device plugged in or a non-maskable interrupt raised on every processor comes from the emulated hardware rather than from anything the guest can be asked to do. A stick plugged in after the boot is two steps: `drive=add:` makes the medium and `usb=add:` the device over it, naming the drive; pulling the device leaves the medium, so a replug is `usb=add:` alone. The socket is opened only for a run whose steps need it, so every other suite's command line is unchanged. Each such command waits for the monitor's prompt before the run goes on: a second command written while the first is still being read is the one that is lost, and the key it was carrying never arrives. It enforces a run deadline and per-step deadlines. With a harness kernel it can decode the guest process status through QEMU's `isa-debug-exit` device; `--ok` instead requires a serial token and a machine that did not stop on its own with an even exit status (a stop through `isa-debug-exit` is odd), and `--never` fails the run if a text ever appears, which is how a probe that must be killed is checked.
* `runner/runtests.c` implements the shared boot of the `default` suite, which is in the core tier. It runs the ordered probe list and scores each probe from the kernel line that returns its transient init process to the debug shell. Every probe the shared boot can set up runs here; the ones that need typed input, a host peer, a disk, or a deliberate fault have a suite of their own, most of them through the harness, which decodes an exit status the same way. On a boot of an architecture other than i686, which `RACH2_ARCH` names, each probe of its `I686_ONLY` list, `tlsprobe`, is reported as `i686 only, not run` and is no failure, since `tests/Makefile` builds it for i686 alone. `--selftest` checks the scorer without QEMU. The boot's transcript is kept at `default-test.log` under the images directory, so a probe that fails names the record it failed on.
* `runner/hostpeer.c` is the host end of a connection a guest test needs. `hold` keeps a TCP connection open while the machine reads its own `/proc/net/tcp`; `echo` serves TCP and UDP on a port and sends back what arrives, which is what makes the socket probes prove a round trip rather than QEMU's willingness to accept.
* `runner/ptydrive.c` runs a command on a pseudo-terminal of a known size and answers one password prompt from the environment. It stops on a second prompt, reports prompt and answer counts, removes the credential variable from the child's environment and filters the password out of terminal output before forwarding it. The SSH suites need a client that reads a password from a terminal.
* `runner/deadline.c` runs one program with a time limit and kills its whole process group. The host suite gives each native test 60 seconds through it, or what the test's own `host-seconds:` line asks for.
* `runner/screentext.c` prints the text a framebuffer console shows from QEMU's screen dump, a binary PPM: it finds the console's cells as the kernel's `fbcon.c` lays them out, the font at the largest whole scale at which the screen still holds 80 columns and 24 rows, as many cells as fit at it within 240 by 64, centred, and matches each cell against the kernel's own font, `rach2/sys/display/vga_font.c`, which it is compiled with, the cursor's underline rows left out. A cell of one colour is a space, one no glyph matches a question mark. With `--colors` it prints how many colours the dump has, which tells a picture from the console's sixteen.

## Capture checkers and fixtures

* `checkers/wavcheck.c` reads the recording QEMU's `wav` audio backend writes and says whether the machine played the scale it was asked for: each named frequency the loudest in its turn, in the order named. The notes are not equal parts of the recording, so it sweeps rather than dividing. It is the only test tool that links the maths library.
* `checkers/pcapcheck.c` reads Ethernet pcap files produced by QEMU, one subcommand per question. `bcast` checks a broadcast UDP datagram, a packet source address, an ARP ownership reply, or use of a gateway for an off-subnet destination. `netconsole` validates and reassembles Rach2 netconsole frames, including their broadcast address, boot id, sequence, payload length, checksum, and required log text. `rawwire` checks the hop limits and caller-supplied ICMP checksum emitted by the raw-socket probe.
* `fixtures/mkfixture.c` builds both disk fixtures. `boot` rewrites a small MBR disk into the `/dev/bootpart` fixture and fills its FAT-typed partition with the probe's byte pattern; `wide` creates a sparse 260 GiB disk with known sectors at 5 GiB and 258 GiB for 64-bit disk-offset tests.

Then the Doom port is started in the background: after ten seconds the game is still running, the disk commands it cost are recorded, and its zone line reports at least 10 MiB, which is the zone sized from the machine's free memory through a heap that grows with brk where the fixed heap held 6. Last, with that game killed, `doom -playdemo demo1` plays the first demo to its end, where the engine quits as the menu's Quit does, and must exit with status 0; then `doom -record /tmp/rec -maxdemo 1` records into a buffer of 1 KiB, which fills in seconds and is written through the port's `fopen` before the engine's error ends the game, and `rec.lmp` must have mode 644, the 0666 that `fopen` passes to `open` less the shell's umask.
* `suites/exfat.sh` (`tests/run exfat`) is six boots on a disk whose second partition is an exFAT volume `mkexfatfixture --empty` built: a program writes a tree and unmounts it, the host's reader walks the volume and reads its bytes (`--check`, `--list`, `--read`, since mtools cannot read exFAT) and the external checker judges it where the host has one, the next boot reads every byte back, a boot killed inside a write sequence leaves the dirty bit set and the next mount checks and repairs the volume, BusyBox copies and moves and removes through the shell, and two writers and a sync run under the lag device.
* `suites/mount.sh` (`tests/run mount`) is nine boots on a disk whose second partition is a FAT32 volume written by mtools: the partition nodes and a read sleeping through the lag device, a device that never answers in time, the root beside a lagged partition, a write copied before the device sleeps, `mountprobe` with an awk over the unmount records, the mounted half of `lagprobe`, the boot partition refusing the raw writer while mounted, and BusyBox on os-real mounting, listing, reading and unmounting the volume with the listing compared against `mdir`.

The remaining suites run through `runner/harness.c` and `runner/runtests.c` directly from their Make recipes, with no script of their own: `default` and the disk, network, persistence and stress families, and three that exist to run probes the shared boot cannot. `tests/run audio` records the five-note scale through HDA and SB16 with QEMU's WAV backend and checks each recording with `wavcheck`. The HDA row reads `/proc/interrupts` before and after playback and requires the controller's message count to increase. The SB16 row uses instruction-counted time and a 500-microsecond audio service interval to exercise its 160-byte DMA halves without host scheduling delays. `tests/run fault` runs the three probes that must be killed rather than served, and ends by running a program that prints a token, which a kernel that took a fault with it could not do. `tests/run console` types at the console for the two probes that block until something is typed, and asserts the text they read back, not only the count. `tests/run fpu` boots `fpuprobe` with XSAVE, under `rach2.noxsave`, on QEMU's `qemu64` processor, which has no XSAVE, and on i686 under `rach2.nofxsr`, for the floating-point state saved at every switch, copied at `fork`, reset at `execve` and carried on the signal frame; the last three boots run `xsaveprobe` too, which must find OSXSAVE clear and `NT_X86_XSTATE` refused. `suites/memory.sh` (`tests/run memory`) boots the test image at 64 MiB, 512 MiB, 2 GiB, 3 GiB and 4 GiB and holds the kernel's four memory numbers to the map it printed and to the size given; then `memprobe` maps 24 MiB at 64 MiB and 1 GiB at 4 GiB, more than the old window held, patterns it, forks over it, execs and frees it; then, under `rach2.framefail` at both sizes, `memprobe fail` makes a frame allocation fail at each step of `fork` and `execve`; and under `rach2.stackoverrun=fork` and `rach2.stackoverrun=boot` the boot descends a kernel stack of each kind until it runs out, and must stop before the debug shell with a record, the double fault's or the page fault's, naming the thread that descended it, and the panic `a kernel stack ran out`. `suites/bigmem.sh` (`tests/run bigmem`), registered for x86-64 alone, boots the test image with 8 GiB, of which QEMU's PC puts 3 GiB below 4 GiB and the other 5 GiB above it: the report must count all of it usable and none unreachable, `/proc/meminfo`'s `MemTotal`, which `memprobe total` prints, must be the managed count, and `memprobe 5120` maps 5 GiB, more than lies below 4 GiB, and patterns, forks over, execs and frees it; then it boots with 72 GiB on a processor without 1 GiB pages, whose direct map stops at 64 GiB, and the report must count the 63 GiB below it, less QEMU's holes, usable and the 9 GiB past it unreachable. `tests/run pools` boots `poolprobe`: forty-eight pipes, forty ptys and forty-eight sockets live at once across eight children, three times the sixteen each pool used to hold, and a thousand of each made and closed with the heap's `HeapUsed` unchanged.

`sh tests/system/stackoverrun_mutate.sh` proves the memory suite's two stack-overrun rows, which `tests/system/stackoverrun_row.sh` holds for the suite and the proof alike, with private kernels built from a copy of `rach2/` and `mk/`, so the tree is not changed. The copy as it stands must pass both rows. Three faults are then compiled in turn: `guard-mapped` maps the guard page `kalloc_guarded` leaves below a stack and must fail the fork row; `boot-guard-mapped` leaves the page below the boot stack mapped and must fail the boot row; `interrupt-gate` gives vector 8 an interrupt gate that runs on the stack in use, where the double fault faults a third time and QEMU, under `-no-reboot`, ends, and must fail both. A failed row must say `the overrun was not reported`, which it says only after the descent's announcement, the row a fault leaves alone must pass, and a fault that does not change the kernel stops the proof. Each restored copy must build the first kernel byte for byte and pass both rows; the kernel and the changed object are removed before each build, since a make that keeps whole seconds could take them for current. A mapped guard leaves a row no address to name the thread by but a mapped one, where nothing faults, so no layout of the heap lets a faulted row pass, and the thread's record lies above its stack, out of the descent's way. It boots a copy of the architecture's `test.krffs`, which `tests/run memory` builds, and keeps its kernels, consoles and logs under `build/stackoverrun-proof.*`.

`tests/run noentropy` boots on `-cpu qemu64`, which exposes neither RDSEED nor RDRAND. On the test image `musl/saltnoent` requires the salt minter to refuse and leave the account files as they were, `musl/passwdmusl` takes its fail-closed side, and `rngprobe` takes its fail-closed branch: `getrandom`, `/dev/urandom` and `/dev/random` answer `EIO` while `GRND_INSECURE` still returns bytes. `sh tests/system/noentropy_mutate.sh` proves the two new steps with three compiled kernel faults in the main tree. `urandom` lets the random devices answer while the generator is untrusted: the probe's step must fail on `/dev/urandom` and `dropbearkey` must make a key, which fails its step. `random` gives `/dev/random` the operations of `/dev/zero`: the probe's step must fail on it. `insecure` refuses `GRND_INSECURE` there: the probe's step must fail on it. `sh tests/system/probe_faults.sh` proves rows of the default suite against the faults in `tests/system/probe_faults.txt`. It holds the run lock as `tests/run` does, so no suite builds or boots the tree while a fault is in it. At the end the kernel and the programs under `build/tests`, `build/tests/musl` and `build/utils` must be the first build's, byte for byte, so the full set run afterwards shows each restored row passing. ## Real-machine acceptance

Every acceptance invocation fetches `/dev/bootlog` from the running machine into `build/images/metal-bootlog.txt`. A missing or empty log fails acceptance. An ext2 check that reports a fault fails even if another check reports clean. `RACH2_ACCEPT_BOOTLOG` and `RACH2_ACCEPT_DD` are rejected: neither a host log nor a guest reader can replace the evidence. After the MBR proof the metal suite independently fetches the live log into `build/images/rach2-metal.krffs.metal.work.final-bootlog` and requires the initial boot, USB and APIC records to remain after the traffic.

The MBR row invokes `/bin/busybox dd`, discards its stdout and requires a successful read and exactly 512 saved bytes before hashing the file. The metal suite first compares the production script's digest with the host's sector, then changes the read count to zero in a private copy of the script and requires failure with no digest. It restores that copy before requiring another pass and the same sector hash. The exit handler also restores the private script. The copy and its original remain under `build/tests/metal-accept.XXXXXX/`; the production script and guest programs are unchanged by the mutation.

The FAT/exFAT stick row copies a unique payload from the host, compares the mounted file, unmounts, mounts again, compares the complete file and unmounts again. `RACH2_ACCEPT_FAT_IMAGE` supplies an independent FAT image to mtools, including an optional `@@BYTE_OFFSET` suffix. When supplied, the row requires `mcopy` to read the file from that image and `cmp` to match the host payload while the guest volume is unmounted. The file is deleted only after these checks. Without an image, acceptance reports that no offline byte check ran. The aggregate flush count covers writes and unmounts; it does not identify an unmount flush. An interrupted or failed row may leave its witness on the volume. Cleanup never removes a temporary directory while its unmount is failing.

The metal rehearsal supplies its 48 MiB FAT32 partition at offset 1048576 in the QEMU backing image. Before the successful row, a private acceptance copy holds the witness open during the first unmount. The row must report failed unmount, suppress remount and host-byte success, and return nonzero even though the flush count increased. The production script then runs through the su transport and must pass both byte comparisons. These checks cover guest unmount and image bytes, not a physical device's power-loss behavior.

`sh tests/system/metal_fat_mutate.sh` runs `tests/run metal` with the fixed kernel, two separately compiled faults and a restored kernel after each fault. Both faults change the witness on disk during cache invalidation after cached readback has passed. One drops the buffer and must fail remount readback. The other retains its original cached bytes, allowing remount readback to pass, and must fail the independent mtools comparison. The exit trap stops the test processes before restoring and touching the source and rebuilding both kernels. Restored kernels must match the originals. Complete logs, kernel copies and checksums remain under the printed `build/metal-fat-proof.*` directory.

Required remote commands preserve their status and discard their stdout on failure. A private failure record survives shell substitutions and conditional pipelines and prevents PASS. The root type comes from a successfully read mount table; a failed command-line read cannot skip the installed-root checks. Building, staging and transferring the temporary image are required when the kernel lists KRFFS. An unavailable boot-slot report is expected only on a RAM boot, and probing an unrecognised partition may reject its file-system type; an SSH failure during either probe still fails acceptance.

`sh tests/system/accept/transport_test.sh` runs the complete acceptance script against private SSH and su status fixtures. Its 34 checks include failed command-line and uname reads, digest-shaped output with a failed status, image preparation and transfer failures, live ext2 fault records, and rejected evidence overrides. The disk fixture lists disk10's FAT volume before disk1's with the same label and accepts a serial belonging to disk1. Four FAT cases per transport cover success, failed first unmount, failed remount comparison and same-length host-byte corruption; the SSH and mcopy fixtures model these outcomes. The write changes a private file representing the selected disk; the test requires the expected disk1 bytes and an unchanged disk10 file. Its su fixture models the helper's status and output; the QEMU row exercises the real helper and file systems. `--mutate` separately removes the persistent failure record and restores the old disk prefix match. The first must permit a false PASS and the second must write the simulated disk10, both detected by the checks. Each restored copy must pass. The script prints the directory containing all logs.

`sh tests/system/accept/installed_test.sh` runs five installed-root rows, also called by `tests/run metal` after its RAM-root checks. `make metal-installed-tools` builds their prerequisites alone. The fixture is a 35 MiB GRUB disk with an MBR, real candidate and fallback slots and an 8 MiB ext2 root, which its boot line names `rach2.root=MBRID=1acef00d,3`, and the same root on a GRUB disk with a GUID table, named `rach2.root=GPTID=GUID,3` as the installer names it there. Each boot executes the current command-line, disk and ext2-root sections extracted from `metal_accept.sh`, using local guest commands against live `/proc` data, device nodes and `bootctl`. The writable partition-3 candidate passes on both disks, so the script takes a root named by either identity for an installed one; moving the root to partition 4, making the root read-only with ext2's `dir_index` feature, or selecting the fallback slot must produce the corresponding rejection. Every row requires the MBR's hash read through the whole-disk node every boot publishes, without `rach2.diskdiag`, and still checks the root. The guest shell is reached through `rach2.rescue` and a serial console with no host network connection. These rows prove the extracted comparisons and their real guest inputs; they do not run SSH, the boot-log checks or the complete acceptance procedure. Those remain the existing rows' responsibility. Logs and staged-byte comparisons are retained under `build/images/metal-installed`.

`sh tests/system/accept/installed_mutate.sh` first requires all five rows to pass. It then stages separate mutations accepting partition 4, accepting a read-only mount, failing the MBR's read and no longer taking a `GPTID=` root for an installed one, and compiles a `bootctl` that reports a fallback boot as candidate. Each must fail its selected row. The script stops its process group before restoring sources in its exit trap, touches restored sources, rebuilds `bootctl`, restages the guest files and requires the restored row to pass. The restored binary must equal the first, and each image's extracted `bootctl` and acceptance sections must equal their build inputs. Logs and artifacts remain in the printed `build/metal-installed-proof.*` directory.

`sh tests/system/accept/password_test.sh` compiles the actual PTY driver and supervisor privately and runs the real su helper against a native dummy SSH peer on a real pseudo-terminal. Seven cases check quoting and nonzero status, echo enabled during authentication, a password split across transfers with an intervening carriage return, a second prompt after authentication, two prompts together, a prompt followed by a long output block, and a partial password at EOF. Cleanup copies the helper's actual `raw` and `text` files for inspection before deleting them; the returned output and diagnostics are also checked. The dummy peer records a second answer if it receives one. Fixed and restored runs must expose neither half of the dummy secret in any of those files. The peer also checks that it did not inherit the password variable. `--mutate` separately restores repeated answers, removes filtering and replaces the prompt count with a boolean, requiring a specific failure for each. Every phase compiles the selected source; each restored binary must equal the first. Cleanup stops an active helper before restoring the private source. All artifacts and logs remain in the printed directory. `tests/run metal` runs both sets of fixed checks before QEMU.

For an installed system whose owner uses an ordinary account's key and `su`, set `RACH2_ACCEPT_SU=1`, `RACH2_ACCEPT_USER` and `RACH2_ACCEPT_KEY`. The owner supplies root's password in `RACH2_ACCEPT_PASSWORD` for that command and clears it afterwards. `accept/su_command.sh` answers the terminal prompt through `ptydrive`, passes quoted text and the command's exit status, and removes its private transcript. The driver accepts a nonempty password without control bytes, sends it once and fails on another prompt. `PROMPTED=N` counts prompts seen and `ANSWERED=N` counts complete answers sent; the helper requires exactly one record of each, both equal to 1. The password is redacted before any terminal bytes reach `raw`, `text` or returned output, including a match split across reads and a trailing partial prefix. Carriage returns are removed before filtering. Command output uses a pipe so programs retain their ordinary SSH output format. The password is never a command argument and the SSH child does not inherit its variable. Binary transfers use a private directory owned by the SSH account: root moves an upload into place, and moves a download into that directory and back after reading it. Both directories are on `/tmp`'s file system, so neither direction needs a second image's storage or hard links. Binary bytes do not pass through a terminal. The script requires uid 0 before its rows. `tests/run metal` rehearses this path, including a quoted command with a nonzero result, a binary round trip and an unnamed stick whose complete image must remain unchanged. It saves the acceptance's complete output in `build/images/rach2-metal.krffs.metal.accept.log`, checks that log and the exit status, and prints the log on a failed verdict.

`accept/metal_accept.sh HOST [PORT] [STICK-SERIAL]` is the scripted half of real-machine acceptance. It reads identity, network, entropy, disk, and device information over root SSH and compares the disk facts for which milestone 24 recorded a baseline. Disk presence, model, size and use come from the registry's `disk` and `identity` records, independently of the optional boot diagnostic. An unpublished whole-disk node skips the MBR read; a published node must supply one complete sector before its hash is reported. The rehearsal compares that hash with the host's, forces an empty read to fail acceptance, and checks acceptance again after restoring the reader. The installed ext2 root must be writable on partition 3. It writes, under temporary names, and removes before it ends: a file on the root and a 1 MiB image under `/tmp` attached to a loop device and written through. Stick rows require the serial the owner approved, as `/proc/disk` reports it; an absent or duplicate serial fails, a recovery ISO in the stick's table disqualifies it, and no serial means no stick is written. The FAT file is removed; `accept.txt` is left on a stick's KRFFS volume for the host to read back as proof. When the script is stopped, its trap unmounts and detaches the image, removes the directory, and removes the known-hosts file last. Physical actions and the final disk write remain manual procedures under `dev-log/24-metal/` and `dev-log/25-sealed/`. Acceptance is not a suite: it is never part of `tests/run all` and remains governed by the hardware rules in `AGENTS.md`.
