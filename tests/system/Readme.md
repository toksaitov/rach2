# tests/system/: the behavioral test machinery

This directory contains everything that runs Rach2 to test it: the QEMU runners under `runner/`, the suite scripts under `suites/`, the capture checkers under `checkers/`, the fixture builders under `fixtures/`, and the real-machine acceptance procedure under `accept/`. The suites themselves are Make targets in `suites.mk`, which the root `Makefile` includes with one line so no test rule sits among the product rules. The guest probe sources stay in [`tests/`](../Readme.md) and the native sanitizer tests in [`tests/host/`](../host/Readme.md).

## The runner

`tests/run NAME [NAME...]`, `tests/run core` and `tests/run all` are the entry points. The runner is the shell script `tests/run` beside `tests/registry`, and the registry is three fields: the suite's name, the external commands it needs, and its tier. The make target is the name with `run-` in front, so it is not written down; `tests/run style` checks that every name has a target and every target has a name.

The runner uses these mechanisms:

* Names and tools are checked before anything is built. A run whose last suite needs a missing `mformat` fails in the first second instead of an hour later.
* For a set, `prepare-all` builds the product and the test tools once, before any suite starts. Twenty suites each running Make on the same tree would build the same object twenty times, or race over it. A suite run alone builds through its own target instead, with `make -j run-NAME`, so it builds only what that target names: `tests/run host` after an edit to a utility takes 97 s instead of 129 s, since the five images and the two ISOs the edit touches are not its business. Either way the components, the builds that turn sources into programs, are built first in a Make of their own, because an image rule that meets a staged program and the component that builds it in one Make reads the program's time before the component has run and keeps the old image.
* The suites then run in a pool, `RACH2_WORKERS` at a time, default twice the processor count and at least four, eight when the count cannot be read. Most of a suite's time is spent waiting for an emulated machine rather than computing, so the useful count is above the core count; on a ten-core machine the full run takes 1286s at four workers, 587 at twelve, and stops improving at twenty.
* Each pooled suite's output is held and printed when that suite ends. Start and progress lines go directly to the run log. The progress line names the suite, its elapsed time and the time since its last output. Every suite has an idleness limit, `RACH2_IDLE_TIMEOUT`, default 300 elapsed seconds: the suite is stopped as hung when for that long it has printed nothing, its machines have printed nothing, and its process group has used next to no processor time, under a tenth of a processor over that span, which the supervisor samples every ten seconds from `ps` with the time of reaped children from `/proc` where it is; a halted machine's timer costs a few percent under either accelerator and is not work, while a process come or gone is. Suite output, QEMU console output and processor time each reset its clock, so a slow machine that writes for minutes without a word is left to finish, and only an idle silent one is stopped. The limit is independent of completion bounds and is never scaled. On idleness the supervisor sends TERM, then KILL after two seconds, reports the last output, and fails the suite. The pool continues unless stop-on-failure was requested.
* Registry order is the schedule order, longest suite first. A pool finishes when its longest member does, so a long suite started last leaves the machine idle around it.
* Completion bounds use the seconds written in the suite. The runner does not calibrate the emulator, delay a set for a measurement, or narrow the pool. `RACH2_TIMEOUT_FACTOR=F` explicitly multiplies completion bounds for a single suite or a set, including the suites that run serially. It accepts decimals from 1 through 64, the range supported by the consumers, and rounds up to a tenth. The start line records the factor and worker count. Rate assertions, deliberate load intervals and guest deadlines retain their values. The internal `RACH2_DEADLINES` and `RACH2_DEADLINE_FACTOR` variables are set by the runner; inherited values are discarded. `calibrate.sh` remains an optional diagnostic and is never invoked by `tests/run`.
* After locking the tree, the runner installs a `qemu-system-i386` shim on `PATH`. The shim chooses the accelerator for every machine a suite boots, so no suite names one: KVM where `/dev/kvm` can be opened, HVF on an x86 Mac that reports it, the emulator otherwise. `RACH2_QEMU_ACCEL=kvm|hvf|tcg` names one outright; `tcg` is how a KVM host is measured without it. The start line records the choice. The helper becomes QEMU without changing its PID and starts a child that relays the console. It records both PIDs, groups and process start times. The relay copies QEMU's standard output and standard error to a per-suite console transcript and forwards the bytes to the suite's existing pipe or log. Signalling the suite's QEMU PID still signals the machine, including with KILL; the relay exits when QEMU closes its output. Every current suite uses QEMU's `-serial stdio` route. A registered machine still alive fifteen seconds after TERM fails that suite with its PID, group, start time and command. A zombie or a reused PID does not count as a live machine and is excluded from ledger cleanup. Group and job ledgers and process inspection supply other cleanup targets. An inherited liveness pipe also detects ordinary unregistered workers after changes of group or session and reparenting, under the inspection limits below.

`style` and `host` run alone, before the pool: `style` rebuilds the kernel with its own flags, and both share a scratch directory. Every other suite runs in the pool. Nothing runs alone after it: `usb` waits for the guest's own report of each device, `diskrate` judges counts and prints its times for the record, `install` builds under completion bounds the factor scales, and `imagerace` builds an image of its own, so none of them needs an idle host.

Pooled suites share nothing. The registry's fourth column declares what a suite writes under `build/images`, as globs, and a suite whose files are named after it declares nothing: `NAME-test*`, `NAME.*`, `NAME-*` and `NAME/*` are its own, and a second-card twin's are the plain names with `-e1000` before the extension. The runner refuses a glob two suites declare before anything runs, and after a run lists every file made under `build/images` since the products were prepared: a file no suite of the run owns, or that two own, fails the run by name, `run: images: undeclared:` or `run: images: shared:`. The column is the inventory of what the suites touch, read by a person once and by the runner every time.

A suite waits for a token and asserts on what the kernel counts, never on the clock. `tools/verify/suitecheck.sh`, run by `tests/run style`, refuses a `sleep` for a number of seconds in a suite, on the host or typed into the guest, a `wait=` harness step, and an upper bound on a duration in a probe, unless the line, or the command it is in, is marked `interval: REASON` in a comment and `tests/system/intervals` lists the file and the same reason; the list is the inventory of the intervals the suites keep on purpose, a load applied for a period, a holder that must outlive what it holds against, a poll of a server between tries, and a person reads it. A reason listed with no mark left, or a mark with no entry, fails the check.

`tests/run runner` (`selftest.sh`) drives the runner against a registry and a makefile of its own in a temporary directory, with a calibration fixture that fails if invoked and two mock suites that judge by an explicit bound, and boots nothing. It is the only test of the runner itself.

`drive.sh` is the console driver for a suite that boots QEMU with `-serial stdio < FIFO > LOG`. `drive_feed` holds the FIFO open and transmits the lines spooled by `drive_type`. A new command sets the search cursor before publishing input, so pre-command output cannot answer it and a fast reply is preserved. Consecutive waits consume matches in order, including tokens and a prompt received in one write. `drive_prompt` recognises a prompt at the beginning of a line, with an optional absolute or home directory, even when a daemon writes after it. A command echo paused at a redirection is not a prompt.

All driver waits take elapsed seconds and never scale them. A caller that wants the explicit run factor passes `"$(scaled N)"`; the `_raw` names remain aliases for callers that already computed a remaining budget. `drive_login` passes its elapsed bound unchanged through the exchange. Shell suites retain their assertions; the procfiles suite now waits for Dropbear's token and prompt instead of sleeping and issuing an extra echo.

`tests/run runner` proves scheduling, idleness, console activity, cleanup, locks, input checksums, explicit factors, prompt matching and stale-token rejection in `selftest.sh`. Its machines are shell fixtures and it boots no operating system. It also calls `runutil_group.sh`, which compiles the actual supervisor with a process-group fixture. A pipe orders the parent before the child so an injected EPERM is tested with both correct and wrong membership; separate cases exercise a real session-leader EPERM and successful child setup after a parent error. Each executed command checks its group and returns a nonzero status for the supervisor to relay. `sh tests/system/runutil_group.sh --mutate` additionally compiles the old unconditional failure in a private copy, requires the membership checks to fail, then restores, rebuilds and checks again. It retains its binaries and logs in the directory it prints. `tests/run drive` adds the delayed console exchanges and the harness's `until=` checks in `drivetest.sh`.

`sh tests/system/runutil_owned.sh --mutate` runs the actual runner and freshly compiled helper in private trees. Ten cases cover an unregistered separate group, a double-forked session, a reaped worker, a finishing worker, a same-group child, a group recorded in another ledger, a six-second shutdown, a persistent same-group survivor, unavailable holder inspection, and interruption. The unregistered workers and persistent survivor must fail by suite name and be stopped. Shutdown within the grace must pass; an empty inspection must be reported as inconclusive without failing. Interruption returns 143. An unrelated process stays alive throughout. Four mutations remove the token check, fail recorded groups immediately, shorten the grace to two seconds, or fail an unnamed holder. Each must fail its affected proof, followed by a rebuilt passing restoration. The restored helper must match the fixed helper. Only socket preflight is substituted; these suites use no sockets or guests. PID files belong to the proof and are never supplied to the runner.

The same script compiles the production machine checker into `fixtures/runutil_machine.c`. A real child whose saved start time differs and an unreaped zombie must be excluded from both verdict and ledger cleanup; a matching live survivor must fail after TERM and the grace. Removing the start-time comparison must fail the proof. It also runs `ssh_flood_test.sh`, which extracts the SSH suite's flood functions and cleanup traps and substitutes only socket-free peers. Normal completion and TERM must reap all eighty children and remove their FIFOs. Omitting the sleep children from ownership must fail, followed by passing restoration. The runner suite invokes these fixed checks. Logs and binaries remain in the printed directories.

### Host interfaces

`runner/runutil.c` is compiled with the host `cc` into each run's private temporary directory before any product build. It uses POSIX clocks, `nanosleep`, process groups, pipes, signals, `stat` and record locks. It supplies elapsed time and fractional sleeps to the runner and its selftest, so neither needs Perl, `pgrep`, `lsof`, platform-specific `stat` or `find` options, cryptographic checksum utilities, or `date +%s`. `ps -A -o pid= -o ppid= -o pgid=` supplies descendants on macOS and Linux; recorded groups and machines remain available for cleanup if the listing fails. For detached pipe holders, cleanup reads native pipe identities through libproc on macOS and `/proc/PID/fd` on Linux. No privilege, service or extra command is required. An unavailable or empty holder listing is reported as inconclusive and does not change the suite status. An unreadable group ledger likewise prevents an outside-group verdict. The same helper, built at `build/tests/system/runutil`, is the suites' one wait: `runutil until FILE PATTERN SECS [COUNT]` returns 0 as soon as COUNT lines of FILE (one, unsaid) match the basic regular expression PATTERN and 1 when SECS, a completion bound under the set's factor, pass first; `runutil gone PID SECS` returns 0 as soon as the process is gone and 1 at the bound. Both look every fifth of a second, which is the runner's interval and not a suite's.

The `suite` supervisor creates a pipe before fork. Its child closes the reader and inherits the writer through exec; the supervisor closes its writer. The reader has `FD_CLOEXEC`, so inspection commands cannot inherit it. The writer has no environment variable or documented descriptor number. After reaping the direct child, EOF permits its status immediately. An open token triggers inspection of current holders and every recorded group in this run. A holder outside those groups fails immediately and is reported with its PID and group before cleanup. Recorded groups containing holders receive TERM and fifteen seconds to stop; only an identified survivor then fails. The timer starts after TERM. If no holder can be identified, the check reports that limit and does not fail the suite. Cleanup rechecks pipe identities before signalling holders, escalates to KILL, and reports completion before the verdict. On silence or interruption, the existing two-second escalation applies; the outer runner allows five seconds before killing a supervisor. The ordinary `watch` command adds no liveness descriptor to its command.

The token proves liveness only while descendants retain the writer. A descendant that deliberately closes it, or execs a program that closes inherited descriptors, escapes this check. An exited worker's status is still its parent's responsibility; the pipe cannot recover an uncollected exit status.

Both the supervisor and its child attempt to put the child in its own process group. The parent's attempt can lose to the child's exec. Before exec, a failed child call is accepted only if `getpgrp()` already equals `getpid()`. Otherwise the helper reports the PID, actual group and saved error, and exits 2 without running the command.

The shell tools are POSIX except GNU Make, already required by the build, and `mktemp -d TEMPLATE`, supported by both BSD mktemp on macOS and GNU mktemp on Linux. CPU discovery tries macOS `sysctl`, then Linux `nproc`, then uses eight workers. The calendar timestamp uses POSIX `date` formatting. A driver invoked directly without `tests/run` falls back to the epoch format of BSD or GNU `date`; under the runner its deadlines use the native monotonic clock. The optional `calibrate.sh` diagnostic retains its own BSD/GNU date calls and is outside the runner's execution path.

## QEMU runners

* `runner/harness.c` drains pre-command output and starts a new search cursor before each send, preserving fast replies and consecutive matches. It starts `qemu-system-i386` headless, accepts optional initrd, disk, network, device, and extra QEMU arguments, and executes ordered serial steps. Step forms include `expect=`, `send=`, `sendraw=`, `sendfile=`, `until=`, `tcp=`, `udp=`, `exec=`, and `probe=`; there is no step that sleeps for a number of seconds. `until=SECS` is the wait after `send=exec /probe` whose only purpose is the run's `--ok` token: it ends half a second after an unconsumed token from the current command is found, or at SECS, never past `--timeout`. `tcp=PORT` connects to a port a `hostfwd` forwards into the guest and reads the first bytes the guest's server sends, an SSH banner, knocking again under a window scaled as a deadline is when the guest resets or has not answered; a port that never answers fails the step, since QEMU's user network accepts the host side of a connection before it knows whether anything is there. `--bios` gives the emulator no kernel, so its firmware boots whatever the drives and devices hold in the order their `bootindex` says, which is how a machine boots from a stick image. `sendraw=` writes its text with no newline after it, and reads `\xNN` and the usual escapes, which is how a guest terminal in raw mode is given one byte. `key=`, `mouse=`, `usb=add:`, `usb=del:`, `drive=add:` and `drive=del:` go to QEMU's own command channel on a unix socket beside the serial line, because a key pressed, a mouse moved or a device plugged in comes from the emulated hardware rather than from anything the guest can be asked to do. A stick plugged in after the boot is two steps: `drive=add:` makes the medium and `usb=add:` the device over it, naming the drive; pulling the device leaves the medium, so a replug is `usb=add:` alone. The socket is opened only for a run whose steps need it, so every other suite's command line is unchanged. Each such command waits for the monitor's prompt before the run goes on: a second command written while the first is still being read is the one that is lost, and the key it was carrying never arrives. It enforces a run deadline and per-step deadlines. With a harness kernel it can decode the guest process status through QEMU's `isa-debug-exit` device; `--ok` instead requires a serial token and a machine that did not stop on its own with an even exit status (a stop through `isa-debug-exit` is odd), and `--never` fails the run if a text ever appears, which is how a probe that must be killed is checked.
* `runner/runtests.c` implements the shared boot of the `default` suite, which is the first entry in the core tier. It runs the ordered probe list and scores each probe from the kernel line that returns its transient init process to the debug shell. Every probe the shared boot can set up runs here; the ones that need typed input, a host peer, a disk, or a deliberate fault have a suite of their own, most of them through the harness, which decodes an exit status the same way. `--selftest` checks the scorer without QEMU. The boot's transcript is kept at `build/images/test.krffs.default.log`, so a probe that fails names the record it failed on.
* `runner/hostpeer.c` is the host end of a connection a guest test needs. `hold` keeps a TCP connection open while the machine reads its own `/proc/net/tcp`; `echo` serves TCP and UDP on a port and sends back what arrives, which is what makes the socket probes prove a round trip rather than QEMU's willingness to accept.
* `runner/ptydrive.c` runs a command on a pseudo-terminal of a known size and answers one password prompt from the environment. It stops on a second prompt, reports prompt and answer counts, removes the credential variable from the child's environment and filters the password out of terminal output before forwarding it. The SSH suites need a client that reads a password from a terminal.
* `runner/deadline.c` runs one program with a time limit and kills its whole process group. The host suite gives each native test 60 seconds through it.

## Capture checkers and fixtures

* `checkers/wavcheck.c` reads the recording QEMU's `wav` audio backend writes and says whether the machine played the scale it was asked for: each named frequency the loudest in its turn, in the order named. The notes are not equal parts of the recording, so it sweeps rather than dividing. It is the only test tool that links the maths library.
* `checkers/pcapcheck.c` reads Ethernet pcap files produced by QEMU, one subcommand per question. `bcast` checks a broadcast UDP datagram, a packet source address, an ARP ownership reply, or use of a gateway for an off-subnet destination. `netconsole` validates and reassembles Rach2 netconsole frames, including their broadcast address, boot id, sequence, payload length, checksum, and required log text. `rawwire` checks the hop limits and caller-supplied ICMP checksum emitted by the raw-socket probe.
* `fixtures/mkfixture.c` builds both disk fixtures. `boot` rewrites a small MBR disk into the `/dev/bootpart` fixture and fills its FAT-typed partition with the probe's byte pattern; `wide` creates a sparse 260 GiB disk with known sectors at 5 GiB and 258 GiB for 64-bit disk-offset tests.

## Suites

The two verification suites come first. `suites/host.sh` (`tests/run host`) discovers every `tests/host/*_hosttest.c`, compiles it with the host C compiler and AddressSanitizer plus UndefinedBehaviorSanitizer, and runs it; a test lists separately compiled sources in repeatable `host-deps:` comments, and the project `deadline` tool limits each test to 60 seconds. The style suite lives under [`tools/verify/`](../../tools/Readme.md) because it checks the tree, not the running system.

`sh tests/system/machine_measure_test.sh --mutate` runs the production inbound and load drivers against private command fixtures, with no network connection. Five cases require the default known-hosts file to disappear after success, failure and interruption, while supplied files and measurement logs survive. Three load cases record starts and finishes and separate a late success, a finish exactly at the deadline and a failed final build. Removing scratch cleanup or counting successes by their start time must fail the corresponding assertion; restored scripts must pass all eight cases. The script prints and retains its private logs. `tests/run host` runs its eight fixed cases before the native C tests.

The install rehearsal uses a 64 MiB ext2 root with 4096-byte blocks and 16384 blocks per group. Its complete first group is required by `growset`; the default 32768-block group would exceed the whole seed. The fixture builder reads back the requested group size. Rehearsal setup must compute the save set successfully before preparing or writing any target. The on-machine range calculator's geometry restrictions remain unchanged.

The behavioral suites receive built artifacts and credentials from their Make targets. They use disposable copies or dedicated fixtures, and each script that starts QEMU installs cleanup for it.

`RACH2_GROW_SMALL=1 tests/run grow` rehearses the measured recovery grow on a 64 MiB disk with an 8 MiB ext2 volume. Groups of 4 MiB make the small grow allocate new groups and backup metadata. It requires before and after times and command and flush counts for the table rewrite, the read-only check, the repairing check and the resize, verifies the writes against `growset`, checks the grown volume, then restores the saved ranges and compares the whole disk with its original. The ordinary grow suite also runs its file, interruption and memory rows.

The measured-grow row temporarily renames the real ext2 tools in its RAM root and installs small shell wrappers. Each wrapper reads `/proc/disk` before and after the real tool. `checkers/grow_measure.awk` requires growroot's six tool-edge samples to match those independent counters, checks the outer snapshots, and requires command work in each of the four phases. Clock differences may be zero within one tick and are labelled as guest tick time. The wrappers add no boot and are removed before the final read-only check. `sh tests/system/grow_measure_test.sh` checks a valid sub-tick reading, all-zero counters, wrong phase attribution, missing and duplicate witnesses, and wrong phase order. Both modes run those six native parser checks and the three native helper proofs first. `sh tests/system/machine_grow_check.sh --mutate` compiles the current range calculator and extracts the production validation functions. It accepts 8 MiB and 1 GiB seeds at the small and Samsung geometries, rejects a shifted final range with the same byte total, and rejects a corrupted last boot byte after the corrupted copy passes its own checksum. Removing each comparison must fail the corresponding assertion; the restored functions must pass again. The complete-extent reads use a fresh native build of the real reflash verifier.

`sh tests/system/machine_grow_boot.sh --mutate` builds growboot, the real bootctl parser and editor with a private command-line file, the reflash verifier and the independent FAT fixture. It runs the helper's boot functions with recorded writes to a private disk file. A correct recovery environment, including different valid comments, causes no write. A zeroed header must be rejected by bootctl; a repair stopped after its first sector must fail, its retry must restore exactly the environment, and another retry must write nothing. Removing repair and forcing an unchanged part to be rewritten each fail an assertion; every restoration reruns the checks. The preparation cannot overwrite its input and the original boot backup must remain unchanged. These proofs test the shell decisions and real FAT code; QEMU tests the device interface and boot.

`sh tests/system/machine_grow_space_test.sh --mutate` extracts the current work-directory, logging, range-check and measurement functions. Ten native cases check a verified store and a missing mount, producer failure, actual output-write failure with an independent console, supported and unsupported seed geometry, and successful, failed and oversized measurement output. Three private mutations restore RAM work placement, ignore the log writer's failure or mislabel the calculator's output failure. Each must fail before a restored run passes. The file-size-limit rows use real failed writes, not a simulated successful logger.

`sh tests/system/machine_grow_full_test.sh` generates the Samsung geometry and replays all 5932200 sectors in 1856 ranges through the production range reader and logging functions and a freshly compiled native `reflash`. It restores 3037286400 patterned bytes into a sparse ordinary file, verifies every byte and the adjacent gaps, and requires all 1856 completion records. It removes the large data fixtures on success and keeps its logs. This is a native full-transfer proof; the guest RAM-file-system limit is exercised separately.

`sh tests/system/machine_grow_space.sh --mutate` uses the prepared grow artifacts without rebuilding them. Its guest boots the shipped 4 MiB recovery root and fills the remaining RAM scratch until the file system refuses allocation. Save, host backup verification, grow and restore then run in one boot, retaining all work directories and capturing the guest's output. The store is unmounted while the host extracts and checks the backup, but the guest is not rebooted. A second case fills the real exFAT store after the first restored range, with the range log and redirected diagnostic file at allocation boundaries. Failure must return nonzero and name the log on the independent console; freeing space and retrying must restore every original byte. Both successful cases boot the restored target without USB and read its owner file. The mutations move work or command logs back into full RAM and must fail before any target write; each is followed by a complete restored pass. Private scripts, console logs and disk images remain in the printed directory. No physical disk is opened. These boots exceed two minutes and run only in small mode or through this explicit command. Ordinary `tests/run grow` includes only the fast native space checks.

Both modes then run `grow_machine.sh`, the small form of the notebook's procedure. Its ordinary three boots use a recovery USB image and two IDE disks. The target has the notebook's boot and recovery offsets and a 64 MiB ext2 root with known original bytes. Recovery saves the ranges and boot partition to exFAT; an unacknowledged grow must leave the target unchanged. The host extracts and verifies the backup before returning its manifest. The next boot grows an 8 MiB seed and erases the MBR. The last restores through USB. Written extents must lie in the saved ranges or boot partition, and the restored disk must equal its original except for the deliberately saved recovery environment.

Only `RACH2_GROW_SMALL=1` adds the rejection and interruption matrix. Bad ranges and a same-length corrupted boot copy must be rejected by the complete guest helper without any target change. Private helper copies pause during save after two ranges, during grow after the first MiB of seed, during restore after the first root range, and during boot repair after one of the environment's two sectors. Each pause flushes the completed transfers and the harness stops the VM while the operation remains unfinished. The repair case first destroys the environment header and requires bootctl's header rejection. Every retry starts with a fresh RAM root, remounts exFAT and extracts `grow-tools.tar` again. Interrupted save leaves the target unchanged and its new backup must equal the host's verified copy. The other retries restore and compare every original byte. Each case then boots recovery from the target with no USB stick attached and reads the original owner file through a read-only ext2 mount. The fixture root contains owner data, not an installed userland; this proves the SSD recovery boot, not a candidate-system login. The matrix models interruption between completed transfers, including a partial environment repair, not arbitrary sub-sector controller failure. It adds fourteen boots to the three-boot helper and exceeds two minutes; it is excluded from the ordinary full tier. Small mode then runs the native full-transfer proof and the fixed and full-log space cases described above, including their target-only boots. Logs, disk snapshots, backup copies and private fault scripts remain in the printed directory.

`sh tests/system/usbdisk_mutate.sh`, after `tests/run usbdisk`, proves the FAT32 and exFAT pull rows against a missing VFS removal check. `--nested` instead removes the recovery lookup for child mounts below a removed parent. Each invocation builds a private kernel and a fresh probe from a private copy of the current source. A private copy of `krffs/manifests/usbdisk-proof.manifest` substitutes that compiled probe's host path. Its stable basename selects the `usbdisk-proof` allowlist entry, which permits no set-id files, forbids init and requires `/usbdiskprobe` at mode 0755 owned by root. Both manifest and image checks must pass, and extracting the probe from the image must reproduce its compiled bytes. Both nested pull rows pass, must fail with the selected fault and pass after restoration; the restored kernel must equal the fixed one. The nested mutant must fail the child's busy-unmount assertion with the ancestor missing. Ordinary `hold` modes remain available for the hub fixtures that have only one partition.

Each command runs under the runner's supervisor. Interruption stops and waits for the command and recorder, removes the FIFO, then restores the source. All output, kernels and disk copies remain in the printed directory. `--resume DIRECTORY` resumes the selected mutation after checking both fixed passes, current source equality and saved artifact hashes. `--restore DIRECTORY` also requires both expected mutant failures and runs only the restored phase. A changed probe or VFS source requires a new proof directory. `sh tests/system/usbdisk_script_test.sh --mutate` proves that changing an assertion changes the extracted probe, and interrupts the command helper in mutant and restoration phases before resuming through a new FIFO. Image construction runs in a fresh `sh -eu` so a conditional caller cannot disable the builder's failure checks. A compiler failure must stop even with earlier artifacts present. Reusing the earlier probe, using an unlisted manifest, reverting to a conditional function call and retaining the FIFO each fail their expected checks; restored functions pass again. This native test checks command continuation, not resumption of a QEMU boot. The `usbdisk` suite runs its fixed cases and the thirteen native unmount checks before its existing boots.

* `suites/account.sh` (`tests/run account`) checks account creation, authentication, password changes, and database consistency in both os-real and os-simple. The os-real profile also checks deletion across reboots.
* `suites/tcc.sh` (`tests/run tcc`) compiles and runs programs as the unprivileged account, compares a machine-built `cat` with the staged one, and checks the unsupported TinyCC output forms.
* `suites/make.sh` (`tests/run make`) checks incremental pdpmake behavior, dependency rebuilding, `.PHONY`, compiler overrides, and timestamps across a reboot.
* `suites/selfbuild.sh` (`tests/run selfbuild`) builds the kernel twice in clean guest workspaces, requires equal hashes, builds utilities and ISH, extracts and checks the exact kernel, and boots it through the probe suite. It also boots that kernel through GRUB, on a disk assembled natively from the pinned GRUB artifacts. `tests/run selfbuild-ext2` runs the same suite with `SELFBUILD_ROOT=ext2` on a disk whose partition is the os-real system as an ext2 volume, booted with `rach2.root=ext2`: the free space and the built kernel are read by `debugfs`, and `e2fsck -fn` must find the volume consistent after the synced stop.
* `suites/ssh.sh` (`tests/run ssh`) checks root key login, unprivileged password login, pty and terminal-size propagation, and rejected authentication attempts. The pty driver `runner/ptydrive.c` answers one password prompt on a sized terminal. The connection flood tracks both sleep and netcat as direct children connected by FIFOs; normal completion, failure and interruption kill and reap both, without relying on runner cleanup.
* `suites/procfiles.sh` (`tests/run procfiles`) checks `/proc/mounts` on RAM, page-cache, and disk roots, then checks the `/proc` data used by `ps`, `df`, `free`, `uptime`, `dmesg`, `route`, `arp`, and `netstat`. ## Real-machine acceptance

Every acceptance invocation fetches `/dev/bootlog` from the running machine into `build/images/metal-bootlog.txt`. A missing or empty log fails acceptance. An ext2 check that reports a fault fails even if another check reports clean. `RACH2_ACCEPT_BOOTLOG` and `RACH2_ACCEPT_DD` are rejected: neither a host log nor a guest reader can replace the evidence. After the MBR proof the metal suite independently fetches the live log into `build/images/rach2-metal.krffs.metal.work.final-bootlog` and requires the initial boot, USB and APIC records to remain after the traffic.

The MBR row invokes `/bin/busybox dd`, discards its stdout and requires a successful read and exactly 512 saved bytes before hashing the file. The metal suite first compares the production script's digest with the host's sector, then changes the read count to zero in a private copy of the script and requires failure with no digest. It restores that copy before requiring another pass and the same sector hash. The exit handler also restores the private script. The copy and its original remain under `build/tests/metal-accept.XXXXXX/`; the production script and guest programs are unchanged by the mutation.

Required remote commands preserve their status and discard their stdout on failure. A private failure record survives shell substitutions and conditional pipelines and prevents PASS. The root type comes from a successfully read mount table; a failed command-line read cannot skip the installed-root checks. Building, staging and transferring the temporary image are required when the kernel lists KRFFS. An unavailable boot-slot report is expected only on a RAM boot, and probing an unrecognised partition may reject its file-system type; an SSH failure during either probe still fails acceptance.

`sh tests/system/accept/transport_test.sh` runs the complete acceptance script against private SSH and su status fixtures. Its 26 checks include failed command-line and uname reads, digest-shaped output with a failed status, image preparation and transfer failures, live ext2 fault records, and rejected evidence overrides. The disk fixture lists disk10's FAT volume before disk1's with the same label and accepts a serial belonging to disk1. The write changes a private file representing the selected disk; the test requires the expected disk1 bytes and an unchanged disk10 file. Its su fixture models the helper's status and output; the QEMU row exercises the real helper and file systems. `--mutate` separately removes the persistent failure record and restores the old disk prefix match. The first must permit a false PASS and the second must write the simulated disk10, both detected by the checks. Each restored copy must pass. The script prints the directory containing all logs.

`sh tests/system/accept/password_test.sh` compiles the actual PTY driver and supervisor privately and runs the real su helper against a native dummy SSH peer on a real pseudo-terminal. Seven cases check quoting and nonzero status, echo enabled during authentication, a password split across transfers with an intervening carriage return, a second prompt after authentication, two prompts together, a prompt followed by a long output block, and a partial password at EOF. Cleanup copies the helper's actual `raw` and `text` files for inspection before deleting them; the returned output and diagnostics are also checked. The dummy peer records a second answer if it receives one. Fixed and restored runs must expose neither half of the dummy secret in any of those files. The peer also checks that it did not inherit the password variable. `--mutate` separately restores repeated answers, removes filtering and replaces the prompt count with a boolean, requiring a specific failure for each. Every phase compiles the selected source; each restored binary must equal the first. Cleanup stops an active helper before restoring the private source. All artifacts and logs remain in the printed directory. `tests/run metal` runs both sets of fixed checks before QEMU.

For an installed system whose owner uses an ordinary account's key and `su`, set `RACH2_ACCEPT_SU=1`, `RACH2_ACCEPT_USER` and `RACH2_ACCEPT_KEY`. The owner supplies root's password in `RACH2_ACCEPT_PASSWORD` for that command and clears it afterwards. `accept/su_command.sh` answers the terminal prompt through `ptydrive`, passes quoted text and the command's exit status, and removes its private transcript. The driver accepts a nonempty password without control bytes, sends it once and fails on another prompt. `PROMPTED=N` counts prompts seen and `ANSWERED=N` counts complete answers sent; the helper requires exactly one record of each, both equal to 1. The password is redacted before any terminal bytes reach `raw`, `text` or returned output, including a match split across reads and a trailing partial prefix. Carriage returns are removed before filtering. Command output uses a pipe so programs retain their ordinary SSH output format. The password is never a command argument and the SSH child does not inherit its variable. Binary transfers use a private directory owned by the SSH account: root moves an upload into place, and moves a download into that directory and back after reading it. Both directories are on `/tmp`'s file system, so neither direction needs a second image's storage or hard links. Binary bytes do not pass through a terminal. The script requires uid 0 before its rows. `tests/run metal` rehearses this path, including a quoted command with a nonzero result, a binary round trip and an unnamed stick whose complete image must remain unchanged. It saves the acceptance's complete output in `build/images/rach2-metal.krffs.metal.accept.log`, checks that log and the exit status, and prints the log on a failed verdict.

`accept/metal_accept.sh HOST [PORT] [STICK-SERIAL]` is the scripted half of real-machine acceptance. It reads identity, network, entropy, disk, and device information over root SSH and compares the disk facts for which milestone 24 recorded a baseline. Disk presence, model, size and use come from the registry's `disk` and `identity` records, independently of the optional boot diagnostic. An unpublished whole-disk node skips the MBR read; a published node must supply one complete sector before its hash is reported. The rehearsal compares that hash with the host's, forces an empty read to fail acceptance, and checks acceptance again after restoring the reader. The installed ext2 root must be writable on partition 3. It writes, under temporary names, and removes before it ends: a file on the root and a 1 MiB image under `/tmp` attached to a loop device and written through. Stick rows require the serial the owner approved, as `/proc/disk` reports it; an absent or duplicate serial fails, a recovery ISO in the stick's table disqualifies it, and no serial means no stick is written. The FAT file is removed; `accept.txt` is left on a stick's KRFFS volume for the host to read back as proof. When the script is stopped, its trap unmounts and detaches the image, removes the directory, and removes the known-hosts file last. Physical actions and the final disk write remain manual procedures under `dev-log/24-metal/` and `dev-log/25-sealed/`. Acceptance is not a suite: it is never part of `tests/run all` and remains governed by the hardware rules in `CLAUDE.md`.
