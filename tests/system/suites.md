# The suites

One line per suite, in the order the pool starts them, from `tests/run inventory`: the tier, the external commands the suite needs, `qemu` being the emulator of the architecture `ARCH` names, the most guest memory its machines ask for at once, the architectures it runs on when it does not run on both, and what it proves, which is the sentence in `tests/system/suites.mk` that names it. `tests/run style` compares this file with that output.

* `gnu` (full tier; needs qemu, ssh, scp, sftp, python3; 2048 MiB): the GNU system on its ext2 root, a boot for each case of tests/cases/machine.gnu.json: logins by key and by password over OpenSSH, each port, GCC, GNU make, GDB, the SpiderMonkey shell and chromium-headless-shell doing its main job, and tmux at the console.
* `agents` (full tier; needs qemu; 4096 MiB; x86_64 only): the pinned GNU agent packages and their headless and interactive sessions, each row driven by C on a private GNU disk against its fake API service, as the cases of tests/cases/machine.agents.json.
* `agentsaccept` (full tier; needs qemu, ssh, python3, openssl, tmux; 4096 MiB; x86_64 only): each agent's work, cancellation, resized terminal, reconnected SSH client and reopened conversation, then a reboot and the unchanged credentials, versions and authenticated requests, as the cases of tests/cases/machine.agentsaccept.json.
* `installer-rehearse` (full tier; needs qemu, qemu-img, xorriso, shasum; 512 MiB): the rehearsal of the Lenovo's install sitting, in its small form with the test stick and on x86-64 at the machine's own size with the product's stick, as the cases of tests/cases/machine.installer-rehearse.json.
* `install` (full tier; needs qemu, mformat, mmd, mcopy, mke2fs, debugfs, e2fsck; 128 MiB): the machine installs its own kernel.
* `selfbuild` (full tier; needs qemu, mformat, mmd, mcopy; 128 MiB): the machine builds its own kernel, utilities and shell with the staged TinyCC and pdpmake, and what it built runs.
* `installer-repair` (full tier; needs qemu, qemu-system-x86_64, qemu-img, xorriso, shasum, ssh, ssh-keygen, mcopy, mmd, mdeltree, mtype, minfo, debugfs; 128 MiB): the machine that will not boot, restored, updated or converted from the stick, each update also stopped part way and run again, as the cases of tests/cases/machine.installer-repair.json.
* `installer` (full tier; needs qemu, xorriso, shasum, ssh, ssh-keygen, mformat, mcopy, mtype, mdel; 512 MiB): the install stick and the installer on the machines it boots, as the cases of tests/cases/machine.installer.json.
* `menu` (full tier; needs qemu, mformat, mmd, mcopy, mke2fs, debugfs, e2fsck; 128 MiB): the boot menu that can be rewritten, and the stub that cannot.
* `uefi` (full tier; needs qemu, qemu-system-x86_64, xorriso, ssh, mformat, mmd, mcopy, mdel; 512 MiB): the machine booted by UEFI firmware, OVMF, from its installed disk, from that disk's recovery entry, from the same disk with its boot partition's menu deleted, from the install stick's image as a USB device and from the recovery ISO as a CD, each answering SSH, installed from the stick onto a 4 TiB NVMe disk whose root grows past 2 TiB, and booted by SeaBIOS after recovery writes a damaged primary GUID table again.
* `selfbuild-ext2` (full tier; needs qemu, mformat, mmd, mcopy, mke2fs, debugfs, e2fsck; 128 MiB): the machine builds its own kernel on an ext2 root, and the kernel it built runs.
* `sealed` (full tier; needs qemu, ssh, mformat, mmd, mcopy, debugfs, e2fsck, gzip; 128 MiB): the disk that goes into the laptop, operated the way it will be operated once it is in there.
* `fakeapi` (full tier; needs qemu; 1024 MiB; x86_64 only): curl's TLS, JSON and server-sent events, a WebSocket exchange and an unexpected request that fails the API server's verdict, on a restricted GNU machine, as tests/cases/machine.fakeapi.json.
* `dhcp` (full tier; needs qemu; 128 MiB): the machine taking an address it was not told, with both of its clients: BusyBox's `udhcpc`, which `ifup` runs, and os-simple's own `dhcpc`, which its `netup` runs.
* `netif` (full tier; needs qemu; 128 MiB): the interface ioctls, which is how a program sets this machine's address, and machines with two cards.
* `mount` (core tier; needs qemu, mformat, mcopy, mdel, mdir; 128 MiB): the partition nodes, the block path through a device that sleeps or never answers, mount(2) and the claims it makes, and the FAT driver mounted from BusyBox's shell.
* `fdlock` (full tier; needs qemu; 128 MiB): pending KRFFS relocation, orphan truncation, and concurrent raw offsets.
* `grow` (full tier; needs qemu, mke2fs, e2fsck, qemu-img, xorriso; 512 MiB): a 1 GiB ext2 root grown by `growroot` on the recovery system to a partition the size of the installed machine's disk, its writes checked against the grow set, a grow stopped in resize2fs and finished, one whose entry is already at the end, and the memory it needs; the machine's save, grow and restore on a small root, on an MBR and on a GUID table, each also cut at a completed transfer and run again, and with the recovery system's RAM root full; and on the host, the grow script's checks, its restore at the Samsung's size and its measures' checker.
* `drill` (full tier; needs qemu, ssh, gzip, mformat, mmd, mcopy, mke2fs, debugfs, e2fsck; 128 MiB): the recovery drill, boots of one disk that carries the same three partitions the sealed disk has.
* `account` (full tier; needs qemu; 128 MiB): accounts created, authenticated, changed and deleted on both images, since both have account tools and they are different code.
* `large` (full tier; needs qemu, mke2fs, e2fsck, mformat, either hdiutil and newfs_exfat or mkfs.exfat and fsck.exfat; 128 MiB): a file of 256 MiB on ext2 and on exFAT, written, read back after a remount, sought, sized, truncated, appended and shared between two descriptors, a mebibyte written astride the 4 GiB line of a sparse ext2 file, and a write past each format's limit refused by name.
* `usb` (core tier; needs qemu; 128 MiB): the USB stack, from a port to a keystroke, the cases of tests/cases/machine.usb.json, each a boot of its own.
* `raw` (full tier; needs qemu; 128 MiB): the raw ICMP socket, which is what `ping` and `traceroute` are.
* `krffsmount` (full tier; needs qemu, python3; 128 MiB): a KRFFS volume mounted by mount(2) from a program, read, written, read back after a reboot, left by a machine killed while writing and repaired by the next mount, written by two processes at once, refused when it is malformed, taken read-only by a write the device fails, mounted three at a time, and left by a stick pulled from under it.
* `diskrate` (full tier; needs qemu, mformat; 512 MiB): the storage paths timed in the machine and held under bounds: the raw device, a file on exFAT and on FAT32 written and read, two hundred small files, and a raw read piped into a hash.
* `usbdisk` (core tier; needs qemu, xorriso, mformat, mcopy, mtype; 128 MiB): a flash drive as a disk, the cases of tests/cases/machine.usbdisk.json: sticks with an MBR, a GUID table and no table; the nodes, the mounts, a write, the pull from under a mount and the replug, ten plugs and pulls of a stick nobody opened, BusyBox mounting by label, a boot from the stick image, three sticks at once, a stick past two terabytes and two logical units.
* `stress-ahci` (full tier; needs qemu; 128 MiB): the stress suite's on-disk KRFFS larger than the page cache, on an AHCI controller.
* `default` (core tier; needs qemu; 128 MiB): every guest probe, each in a boot of its own on the test image.
* `stress` (full tier; needs qemu; 128 MiB): an on-disk KRFFS larger than the page cache.
* `procfiles` (full tier; needs qemu; 128 MiB): the machine's own /proc files, on the boots that differ and through the programs that read them.
* `bigmem` (full tier; needs qemu; 8320 MiB; x86_64 only): all of an x86-64 machine's eight gigabytes is counted, and a program's pages fill memory past what lies below 4 GiB and read back as written; without 1 GiB pages, 72 GiB is counted to the direct map's 64 GiB.
* `memory` (core tier; needs qemu; 4096 MiB): the kernel's account of physical memory at three sizes, memprobe at the two ends of the range and frame allocations failed at the low one, the string routines swept, a machine of 8 MiB refused and kernel stacks run out.
* `parts` (core tier; needs qemu, mformat, mtype; 128 MiB): four tables on four AHCI disks (an MBR with logical partitions, a GPT, a GPT read from its backup, a blank disk), the nodes as the tables number them, the table read again, a 5 TiB disk's numbers past 32 bits in /sys/block and /proc/partitions, and the root chosen by identity: found when the disks are swapped, refused when two disks have it.
* `bootpart` (full tier; needs qemu; 128 MiB): /proc/cmdline and the level-one disk devices.
* `loopdev` (full tier; needs qemu, mformat, mcopy, mtype, mke2fs; 128 MiB): a file system in a file, through a loop device: a FAT32 and a KRFFS image on a FAT32 volume, each mounted, written and read back, and everything an attachment refuses.
* `tcc` (full tier; needs qemu; 128 MiB): the machine compiling a program on itself.
* `make` (full tier; needs qemu; 128 MiB): the machine building a program on itself, and the claim a compiler alone cannot make: that a second build does nothing, that touching one source rebuilds one object, and that the answer survives a reboot.
* `smp` (full tier; needs qemu; 640 MiB): the kernel on one processor, on four and on two of four, each finding its processors and passing a stress of fork, exec, pipes, futexes and munmap across them and sleeps on the last, the debug shell's preemption test and its ring-3 payload on two, an NMI on two that must stop the machine as a fault of the machine, and a parallel build on the installed system that runs on every one of four.
* `clock` (full tier; needs qemu; 384 MiB; x86_64 only): the guest's monotonic and real clocks keeping the host's time within 250 ms, including reference uncertainty, across thirty stops of the machine's QEMU, once under the site's accelerator (see tests/cases/machine.clock.json).
* `host` (full tier; needs qemu; 384 MiB): the host tests, kernel code compiled and run natively under the sanitizers, etude's QEMU launcher booting the kernel, and the fuzz corpora replayed through their harnesses.
* `noentropy` (full tier; needs qemu; 128 MiB): the entropy policy's fail-closed half, which no other suite can reach, on a processor without RDRAND and RDSEED.
* `shutdown` (full tier; needs qemu; 128 MiB): userland stopping the machine, on a disk fixture, with every claim of a stop asserted on QEMU's event, and every claim of a halt on the processors halted in QEMU's monitor, rather than on a token, every disk checked by offline fsck afterwards, and init killed on four processors leaving all four halted with interrupts off and the disk dirty.
* `fatwrite` (core tier; needs qemu, mformat, mcopy, mdir; 128 MiB): FAT32 written from a program, read back after a reboot, judged by the host's walk, mtools and fsck.fat where the host has it, taken through a crash and its repair, written from BusyBox, and written by two processes under the lag.
* `ssh` (core tier; needs qemu, ssh; 128 MiB): logins over SSH with nobody at the keyboard, the case of tests/cases/machine.ssh.json.
* `exfat` (core tier; needs qemu; 128 MiB): exFAT written from a program, read back after a reboot, judged by the host's reader and the external checker where the host has one, taken through a crash and its repair, written from BusyBox and by two processes under the lag, and unmounted after a failed write with its dirty bit still set.
* `ext2` (core tier; needs qemu, mke2fs, debugfs, e2fsck, mtype; 128 MiB): the ext2 driver booted: the probes as init on an ext2 root, ext2probe's link and cost rows on a fixture volume the host's mke2fs wrote, and os-real on its ext2 root, written, killed, checked, damaged and repaired by recovery's e2fsck.
* `cred-persist` (full tier; needs qemu; 128 MiB): the credential replacement's durability across a reboot.
* `addressed` (full tier; needs qemu; 128 MiB): the address named on the boot line, and the proof that it is the one in force.
* `ping` (full tier; needs qemu; 128 MiB): the ICMP path against the SLIRP gateway, which is why it is a case of its own rather than a probe in the default suite.
* `packet` (full tier; needs qemu; 128 MiB): the packet socket, which is how a DHCP client sees a reply that arrives before this machine owns an address.
* `load` (full tier; needs qemu, mformat; 128 MiB): the machine under load while six lines are typed at its console: every line read, no request quarantined by its deadline, and the longest delays it saw, from `/proc/stat`, printed.
* `authority` (core tier; needs qemu; 128 MiB): which kernel may write the whole disk.
* `queue` (core tier; needs qemu, mformat; 128 MiB): real AHCI reads, interrupts and fallback root faults beside raw reads; controlled host models test deadlines.
* `subset` (core tier; needs qemu; 128 MiB): each optional device probe left out, and proved left out.
* `bus` (full tier; needs qemu, mformat, mtype; 128 MiB): four IDE drives on both channels, an AHCI and an IDE disk together with the root on each in turn, and a disk past 128 GiB.
* `exitline` (full tier; needs qemu; 128 MiB): the plain process-exit line is printed under the debug shell and nowhere else.
* `etudeguest` (full tier; needs qemu; 128 MiB): etude-guest on the test image's serial console, as the debug shell's designated init, without the debug-exit port.
* `etudeexec` (full tier; needs qemu; 512 MiB): Rach2 builds etude by its TinyCC recipe, and the POSIX executor, built the same way, passes its test there.
* `login` (core tier; needs qemu; 128 MiB): prove the console cannot fall back to an unauthenticated shell.
* `man` (core tier; needs qemu; 128 MiB): the manual pages on the machine.
* `metal` (core tier; needs qemu, ssh, mformat, mcopy, mmd, mke2fs, debugfs, e2fsck, python3; 128 MiB): unattended SSH on the metal image, the acceptance script rehearsed on it, and the script's installed-root rows, the cases of tests/cases/machine.metal.json.
* `bootline` (full tier; needs qemu, mke2fs; 128 MiB): the boot line that contradicts itself.
* `servicelog` (full tier; needs qemu, mke2fs; 128 MiB): the log init's services write to is bounded within a boot, and a log a boot left full is removed at the next.
* `persist` (core tier; needs qemu; 128 MiB): fsync durability across a power cut.
* `style` (full tier; needs cppcheck, shellcheck, clang, clang-format, python3; no machine): the source checks over the tree, booting nothing.
* `dgram` (core tier; needs qemu; 128 MiB): a connected datagram socket and the permission to broadcast, which is how a DHCP client renews a lease and how it asks for one.
* `diskdiag` (full tier; needs qemu, ssh; 128 MiB): a disk read without being mounted and without being written.
* `e1000` (core tier; needs qemu; 128 MiB): the network path on the other emulated card, and the probe order that decides which card a machine with more than one of them gets, the cases of tests/cases/machine.e1000.json, each a boot of its own.
* `grub` (core tier; needs qemu, mformat, mmd, mcopy, mke2fs, debugfs, e2fsck; 128 MiB): the machine replacing its own boot loader.
* `disk-q35` (full tier; needs qemu; 128 MiB): blockprobe's page-cache integrity check on the q35 machine, whose AHCI controller is built in at 0:31.2, function 2 of the multi-function device 31.
* `doom` (full tier; needs qemu; 128 MiB): the Doom port on a disk root, refused without its WAD, drawing with a zone sized from the machine's free memory, playing a demo to its end and recording one through fopen.
* `diskpolicy` (full tier; needs qemu; 128 MiB): the read-only kernel does not write the disk, shown on the bytes rather than on a return value.
* `console` (core tier; needs qemu; 128 MiB): the two probes that read from the console, which the shared probe boot cannot run because they block until something is typed.
* `fpu` (core tier; needs qemu; 128 MiB): the floating-point state of a process is its own, by each path the kernel saves it with: XSAVE under QEMU's `max`, FXSAVE under `rach2.noxsave`, where `xsaveprobe` must find OSXSAVE clear and no NT_X86_XSTATE, and on `qemu64`, and the x87 state alone by `fnsave` under `rach2.nofxsr`, which only the i686 kernel takes, since every x86-64 processor has FXSR.
* `socket` (core tier; needs qemu; 128 MiB): the guest opening connections of its own, checked by a host that answers (see tests/cases/machine.socket.json).
* `bootorder` (full tier; needs qemu, mformat, mmd, mcopy, mke2fs, debugfs, e2fsck; 128 MiB): the GRUB disk on the second AHCI port behind a disk holding nothing, booted by the firmware, its root found as disk 1.
* `reset` (core tier; needs qemu; 128 MiB): each reset mechanism on its own.
* `netconsole-e1000` (full tier; needs qemu; 128 MiB): the netconsole suite's power-off on the e1000 card, whose stop sends the frames it was given before it silences the card, the case of tests/cases/machine.netconsole-e1000.json.
* `audio` (core tier; needs qemu; 128 MiB): what the machine actually played.
* `netconsole` (core tier; needs qemu; 128 MiB): the kernel log on the wire, the cases of tests/cases/machine.netconsole.json.
* `crash` (core tier; needs qemu; 128 MiB): the dirty-mount flag, a spare mode bit of the root node, untouched by dirtyprobe's clears of the set-id bits and still set after the unclean stop that follows.
* `pools` (core tier; needs qemu; 128 MiB): many pipes, ptys, sockets and processes live at once, and the kernel heap back where it started after a thousand each of pipes, ptys and sockets (see tests/poolprobe.c).
* `diskfull` (core tier; needs qemu; 128 MiB): a file system with no room left.
* `fault` (core tier; needs qemu; 128 MiB): the two probes whose whole claim is that the kernel killed them.
* `imagerace` (full tier; needs nothing beyond the build; no machine): two builds of one image at the same moment, as a parallel run of the suites can make them, and builds stopped at each step of publishing one, none of which may leave an image mixed with another build's files or out of date.
* `krffscheck` (full tier; needs python3; no machine): what the offline checker says about images broken on purpose.
* `codexapi` (full tier; needs qemu; 4096 MiB; x86_64 only): OpenAI's Responses protocol in the C fake API service, proved against the pinned upstream Codex in a fresh home on an isolated GNU Rach2 machine: two turns over a WebSocket, a refused second WebSocket and three turns over HTTPS, with the file, commit, credentials and clean repository checked, and an incorrect tool result refused.
* `museapi` (full tier; needs qemu; 4096 MiB; x86_64 only): Meta's Model API in the C fake API service, proved against the pinned upstream Muse on an isolated GNU Rach2 machine: the model catalog and five HTTPS turns, with the file, commit, credentials and clean repository checked, and an incorrect tool result refused while Muse still runs, before its cancellation and confirmed cleanup.
* `conload` (core tier; needs qemu, mformat; 128 MiB): every line typed at the console under load arrives, numbered and checksummed, with the reader parked, as type-ahead, after an interrupt character to a foreground child, and across an exec.
* `textbusy` (full tier; needs qemu; 128 MiB; x86_64 only): executable files exclude writers until the last image ends, and bind mounts retain removed KRFFS boot-root files until last close.
