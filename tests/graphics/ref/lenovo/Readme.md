# Linux's graphics references on the Lenovo

Debian's results on the Lenovo's Intel HD 4400, the reference that Rach2's results on the same machine are compared with. They come from step 9 of the second discovery run, on 2026-11-08, under Debian 13.7 on the Lenovo's p5: kernel 6.12.115+deb13.1, Mesa 25.0.7-2+deb13u1, with the IOMMU's DMA translation on. The files are the tools' own output, unedited; text is named `.out`, since it keeps the tools' own characters.

## Results

* `igt/`: IGT's `kms-hsw` run, `results.json.gz` with `failures.out`, `metadata.out` and `uname.out`.
* `deqp/`: dEQP's GLES 2, GLES 3, GLES 3.1 and Vulkan runs, each with `results.csv.gz`, one row a case, and `summary.out`; `vk-500/` is a sample of 500 Vulkan cases, and `run.log` is the runner's log.
* `piglit/`: piglit's `quick` profile, `results.json.bz2`, `summary.out` and `failures.out`, with the reruns of the failed cases in `rerun/` and `rerun-egl/` and their lists.
* `glmark2/`: glmark2 on DRM and on Wayland, with GL and GLES 2, each a `.log` and a `.samples` file.
* `webgl/`: the WebGL conformance suite in Firefox and in Chromium, the two summaries, and each browser's `progress`, `samples`, `run.log` and `finish.json`.
* `hasvk/`: step 9's `chromium-blocklist.json` and `chromium-pic-blocklist.json`, and step 10's `host-cube.txt`, copied without changes from the second discovery run. Chromium 156.0.8078.79 ran with `--ignore-gpu-blocklist` under Weston's DRM backend and kiosk shell on the panel at 1366x768: the adapter was Intel gen-7, the compute and render readbacks passed, and 480 picture frames took 8.0098 s. The native vkcube runs used hasvk alone under the same Weston, with 300 then 900 FIFO frames twice: 5.053 and 15.041 s, then 5.045 and 15.035 s. The differences give 60.07 and 60.06 FPS. The final two rows are IMMEDIATE, which the presenting step does not compare. The scripts and settings are in the graphics research's `run2/step9.md` and `run2/step10.md`. `browser/hasvk.html` uses the picture's same shader, canvas, clear colour and readback points, and ends at 480 frames; the reference ended after eight seconds, which gave those 480 frames. The PNG's centre and corner were also read from the original `chromium-pic-blocklist-screen.png`: RGB 95,80,80 and 25,25,76, the same as its canvas readbacks.
* `forward/`: `vkcube.frames`, the CRC-32 of vkcube's frames 300 and 345 that a Debian guest drew through Venus on hasvk, under Debian 13.7 on p5 in Rach2's place with QEMU 10.0.13 and virglrenderer 1.1.0-2, the same in two runs on 2026-11-11, with the IOMMU's translation off; [bed/forward](../../../../bed/forward/Readme.md)'s `venus` scene on the Lenovo is judged by it.

The Lenovo's GPU cases ([tests/native/gpu.cases](../../../native/gpu.cases)) judge against these and against what is made from them, which the graphics tests' Readme describes ([the Lenovo's conformance](../../Readme.md#the-lenovos-conformance)):

* `expect/`: the per-case expectations. `igt-kms.rows` and `piglit-quick.rows.gz`, `NAME RESULT` a line, are made from `igt/` and `piglit/` by `lenovo-expect.py`; `igt-gem.rows`, `glmark2-gl.validations`, `glmark2-es2.validations`, `webgl-chromium.pages` and `webgl-firefox.pages` are the runners' own output from a Debian boot of 2026-11-12, Debian 13.7 on p5 with the IOMMU's translation on (`intel_iommu=on`), as the release boots Rach2; `webgl-chromium.pages` gives the 362 `deqp/` pages that boot ran before `runners/webgl-lenovo.omit` left them out the line an omitted page has, and the measured file is kept with the development log's record of that boot. The probe's lines of `gate` come from that day's second Debian boot, with translation off.
* `gate`: the speed gate's settings, the most a measure may lose against Linux with translation off and Linux's value of each measure.
* `exclusions`: the differences from Linux that the owner has approved, `NAME REASON` a line.

In piglit's expectations, `skip-or-pass` marks 1,035 setup skips in step 9's original run. Of these, 1,033 compiler tests were skipped before execution because piglit checked `GL_EXT_gpu_shader4` in the core profile; this extension is available in the compatibility profile that their GLSL versions use. The other two, `egl_ext_client_extensions@conformance test 3` and `egl_ext_surface_compression@create`, could not open their default or Wayland display. The current runner disables fast skips and sets `EGL_PLATFORM=surfaceless`. Both roots use Mesa 25.0.7-2+deb13u1; this is no Mesa upgrade or new extension in Rach2. These rows require skip or pass, rejecting a failure, crash or missing result; every other skip still requires skip. The original JSON stays unchanged.

IGT's expectations use `skip-or-pass` for 26 rows whose original output names `igt_require_sw_sync`, `kernel_has_sw_sync()` and the absent device's `ENOENT`. Debian's kernel had no sw_sync device in that boot; Rach2 provides one. The rows cover the fence-parameter, interruptible, fenced plane-transition and busy tests, their dynamic results included. A failure, crash or missing result still fails, and other capability skips remain strict. The original JSON stays unchanged.

Another 30 IGT rows use `skip-or-pass` because the original run found no second connected output: 28 cursor tests whose `find_connected_pipe` reports `No second valid output found`, `kms_display_modes@extended-mode-basic`, which reports `Minimum 2 outputs are required`, and `kms_feature_discovery@display-2x`, which reports `Test requirement: output_count >= 2`. The native run with an HDMI display connected can execute them. Their failures still fail, as do missing results; the single-output rows keep their original requirements. The bandwidth test's forced HDMI output already ran in the original reference, so its required passes are unchanged. With the HDMI display connected, IGT also gives the last pipe of a dynamic subtest, `pipe-c-edp-1` in the reference, to `HDMI-A-1`; `judge.py` judges such a row by its pipe ([the graphics tests' Readme](../../Readme.md#display-and-gl-runners)), and the expectations do not change.

The owner deferred DRM leases (#5231), the msr device and i915 runtime PM (#5235), and vgem (#5236) to a later milestone. The expectations mark 121 required passes as `xfail`, each preceded by a `# deferred:` comment naming its issue: 66 `kms_lease` rows, 28 `kms_pm_rpm` rows, six runtime-PM `kms_vblank` rows, two `kms_prime@basic-crc-vgem` rows, `gem_busy@close-race` and 18 `gem_wait` rows under `await`, `write-busy` and `write-wait`. The hybrid PRIME rows and the other runtime-PM rows already accepted skips or failures and keep their original results. The judge accepts any recorded result for a deferred row, including a pass, and permits an absent dynamic row when its deferred parent records skip or fail; a missing parent still fails. Linux's original JSON stays unchanged; `lenovo-expect.py` retains the KMS deferrals when it regenerates the expectations. Under the owner's release deadline, `kms_pipe_crc_basic@compare-crc-sanitycheck-xr24` on pipes A and B, whose first CRC does not come after `kms_panel_fitting`'s fastsets, is also `xfail` (#5249), with its parent. So is `gem_readwrite@read-write`, whose `expected` array is left unset outside bytes 1024 to 2047 and holds the C library's start-up frames on the Lenovo (#5254). In `gate`, Firefox's WebGL2 fill, which measured 66% to 96% of Linux's from run to run, carries `xfail`, which `judge.py gate` reports and does not judge (#5255). Restore Linux's required passes as each deferred feature is implemented.

## Updating

The run's report, with the scripts and how each suite was built, is in the development log's graphics research. A new run replaces a suite's directory whole, and its commit message says what was run and where; `python3 -I tests/graphics/lenovo-expect.py` then makes `expect/igt-kms.rows`, `expect/piglit-quick.rows.gz` and `tests/graphics/igt-lenovo-kms.list` again. The files of the Debian boot are made again by the same commands in a new Debian boot, as the development log's record of the conformance step gives them, each file replaced whole.
