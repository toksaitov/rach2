# Host tests

The host tests compile kernel and user sources as ordinary programs for the build machine and run them under AddressSanitizer and UndefinedBehaviorSanitizer. A test drives the real code against models of what surrounds it (a device's registers, a disk, a scheduler, a peer on the network), so a bounds fault, an overflow or a wrong branch shows in a few seconds on the host rather than as a fault inside QEMU. What needs the machine itself, a system call through the trap path, a privilege change, a real device or a whole subsystem at once, is tested by the guest suites of [`tests/system/`](../system/Readme.md). This directory has the `*_hosttest.c` programs, the headers, models and fixture builders they share, and the scripts that check kernel functions no host test can compile whole.

## Running

`itco_hosttest.c` drives the production TCO register and file operations against a register model. It checks the reserved bits, start and halt write order, both expiry stages and reload, magic and ordinary close, the Linux ioctls, invalid arguments and user pointers, absent registers, a locked NO_REBOOT refusing the device, and refused timer and halt writes. Other rows run the kernel's feed of a timer it starts at boot, `rach2.itco.arm`, on a tick of 5 a second: no reset in a minute of feeds every half heartbeat, a reset two expiries after the tick stops, as after a panic, the feed ended by an open and by `watchdog.open_timeout`, and none with `watchdog.handle_boot_enabled` off; with watchdogd, the tick leaving each feed to `itco_feed_work`, a reset two expiries after the thread stops though the tick goes on, as after a hang with interrupts on, and no feed left due across an open; `iTCO_wdt.nowayout` refusing DISABLECARD with `EBUSY` and leaving a magic close running; a heartbeat out of range taking 30 s; and a timer that firmware left counting kept running and fed, with NO_REBOOT clear and with it set, which the probe clears. Hardware time is advanced in ticks, without a host clock.

`etude prepare collection host` builds the programs and immutable input inventory of [`tests/cases/host.host.json`](../cases/host.host.json). `etude run host` executes that prepared suite through the native C driver [`tests/cases/host/host.c`](../cases/host/host.c). The collection holds the tree while its checks run. No compiler, interpreter or Linux tooling machine runs on the execution host. [The driver's Readme](../cases/host/Readme.md) defines preparation, execution and unsupported adapters.

The cases keep their assertion identifiers:

1. `tests`: the host tests outside etude, with the vendored sources of each selected architecture.
2. `etude`: the shared checks of Etude's complete inventory, once per collection.
3. `etude_quiet`: the platform, remote and repetition checks of that same inventory, with no other collection case running beside them.
4. `boots`: tests with `host-arch:`, over each selected architecture's kernel and images.
5. `checkers`: the five checker selftests under the sanitizers.
6. `fuzz`: each prepared fuzz harness replaying its complete committed corpus. An empty corpus fails preparation.
7. `scripts_native`, `scripts_images`, `scripts_build`, `scripts` and `scripts_tools`: disjoint partitions of all 46 behavioral assertions of `host.list`, preserving each assertion and its position relative to the other rows of its partition. A row awaiting an adapter fails explicitly; it is never a preparation-time pass.

The build-only inventory builder reads source metadata, compiles the checks and hashes compiler dependencies, including locally included `.c` files. Its `--print-commands` option prints commands without compiling or executing. `tools/dev/gen_compile_commands.sh` and `tools/verify/coverage.sh` read the commands it prints.

The `icmp_hosttest.c` model sends pings with timer interrupts still pending at each attempt. It checks the deadline before and at its expiry, a count past 2^32 ticks, release of the deadline, and a reply, carrying the call's own echo identifier, received before the timer handler catches up. Its fragmentation-needed rows quote a TCP segment: a sequence past what was sent, one acknowledged, another connection's and a quote too short for the sequence leave the path MTU as it was, and only a sequence in flight lowers it and reaches TCP.

The `genetlink_hosttest.c` model registers a family against the real generic dispatcher and netlink queue, resolves it through `nlctrl`, checks its operation and group nests, reads a dump in three datagrams, joins and leaves groups including group 40, and fills one reader's queue while another keeps receiving. It also checks privilege refusal, capped and extended errors, malformed and unaligned attributes, the dormant/up link policy and route notifications, and a link's counts past 2^32, whole in `IFLA_STATS64` and cut to 32 bits in `IFLA_STATS`. The model supplies one Ethernet card and empty address, route and socket tables.

`kvm_irq_hosttest.c` checks the full interrupt controller through port and MMIO exits, GSI and state ioctls, and the real eventfd callbacks. Its full-controller rows cover allocation rollback, PIC priority and cascade, level EOI, RTC acknowledgement after state restore, irqfd resampling with independent line sources, PIT latches and reinjection, HPET handoff, halted wakeups and routing replacement. `--irqchip-only` runs these rows alone.

`synthfs_hosttest.c --thp-only` and `procfs_hosttest.c --thp-only` run their transparent-hugepage rows alone, and `sched_hosttest.c --affinity-only` its remote affinity rows; each set also runs with its program's other rows.

## Results

`drm_vblank_hosttest.c` and `drm_vblank64_hosttest.c` also queue two planes with independent engine fences. They check that only the current plane enables signalling and reaches the driver's wait hook, both in the worker and outside the signaller's modeled interrupt locks; a second engine that finishes first is left unlistened until its completion is read; a pending second fence gets a full timeout of its own, including when the worker resumes late after a timely first completion; completion during callback setup leaves no wait; and a timeout prevents later listening or boosting, whether the first fence signals before or after the worker runs.

`vdso32_hosttest.c` checks the fast i386 entry with a modeled user copy that requires the big lock. Both sysenter and syscall32 must hold it once through the copy and dispatch, and release it once on success or EFAULT. `vm_hosttest.c` checks a fallback mapping across the mmap base and the 256-page gap below a growing stack.

`drm_prime_hosttest.c` and `drm_prime64_hosttest.c` check PRIME on both kernel ABIs over the real GEM, dma-buf, fence and udmabuf code. They model frames, sealed memfds, descriptor tables and mappings. The cases cover descriptor modes, self-import and repeated import identity, cross-device and udmabuf pages, shared reservations, reexport after handle close, exporter exit, mappings retained after every descriptor closes, allocation failures and all reference counts returned to their baseline. They also include vgem: its fences on a buffer another device imports, held until signalled, Linux's refusals, the timeout, which a model of the commit worker's queue runs, and the close of a file with fences pending.

`rc_hosttest.c` checks the wireless rate controller with recorded retry completions and modeled clean, lossy and recovered links. It also checks per-series ACK attribution, capability intersections and reset on a peer change, without files or child processes.

The driver prints one result, assertion and progress record per completed check, and the assertion `listed` for agreement between the manifest, source tree and prepared inventory. A source check missing from the manifest is not executed and fails `listed`; a declared check missing from the inventory fails its assertion and `listed`.

A check passes only after exit status zero, confirmed process cleanup and unchanged binary and input hashes. Every sanitizer is fatal. Each check has private scratch under the driver's `rach2-host.XXXXXX` directory in `TMPDIR`; complete output goes to its `NAME.log`. Failed evidence is kept and its directory printed. Successful runs remove their scratch. A stopped driver cancels and reaps its children before removing scratch; unconfirmed cleanup retains it. The case has no time limit of its own. Each completed check writes `progress checks N` for etude's watchdog.

## Design

### The compile

Each test is one compile and one program:

    cc -std=c99 -D_DEFAULT_SOURCE -D_FORTIFY_SOURCE=0 -DRACH2_HOSTTEST \
       -fsanitize=address,undefined -fno-sanitize-recover=all -g -O1 \
       -Wno-empty-body -ffreestanding INCLUDES CFLAGS -o OUT TEST DEPS

`CC` in the environment replaces `cc`. Every group has `-I` paths for `utils`, `krffs` and `tests/host/compat`, in that order. The `tests` group also has `-iquote` paths for `rach2/sys`, `rach2/sys/arch/x86`, `rach2/sys/arch/i686`, `rach2/sys/lib` and `rach2/sys/proc`, before those shared paths. These kernel directories apply only to quoted includes, so a system header such as `<pthread.h>` reads the host's `<sched.h>`. When the source list includes libtsm's `tsm-unicode.c`, `mk/host-check.mk` puts that library's `external/wcwidth` directory first on the quoted include path, so the kernel's `rach2/sys/wcwidth.h` cannot replace libtsm's header. A source list that includes `term/pty.c` also gets `-D_GNU_SOURCE` on the compiler command line: a forced header can include the host's `features.h` before the source's `_XOPEN_SOURCE` definition. The `etude` and `boots` groups have no kernel include path. The command printer uses the same group flags as native preparation. `-ffreestanding` keeps the compiler from turning the loops of `k_memset`, `k_memcpy` and `k_memmove` into calls to the routines they implement, which `rach2/sys/lib/kstring.c` defines as wrappers around them. `-D_DEFAULT_SOURCE` restores the POSIX declarations glibc hides under a strict `-std`, and `-D_FORTIFY_SOURCE=0` turns off the checked string calls that Ubuntu's compiler adds by default and that make `snprintf` a macro on macOS. `RACH2_HOSTTEST` lets a kernel source leave out what a host build cannot compile, and gives it i686's `cpu.h`; a test that also defines `RACH2_HOST_X86_64` on its `host-cflags:` line gets x86-64's.

A test reaches the code under test in one of two ways. It names separately compiled sources on `host-deps:` lines, or it includes a `.c` file whole, which reaches the file's `static` functions and needs no `host-deps:` line for that file. Most tests do both.

`libtsm_width_hosttest.c` compiles the patched libtsm sources, its replacement hash table and its wcwidth. It checks CJK and emoji at the right margin, exact fit, scrolling and scrollback, a scroll region, disabled autowrap and a one-column screen; decomposed accents on narrow and wide bases, pending wrap, attributes, redraw ages and the ten-code-point symbol limit; byte-at-a-time UTF-8 input through the VTE and alternate-screen isolation. Allocation faults cover symbol creation, hash insertion and index growth, with the base retained and a successful retry on the same table. It makes no files and starts no processes.

`fbdev_hosttest.c` also checks nested screen owners, event reads and polling, separate opens and inherited handles, a dead suspended owner and a dead bottom owner, allocation failure, and mode and keyboard restoration at each return. Its keyboard model is checked against the real save and restore operations by `kd_hosttest.c`. `vga_gfx_hosttest.c` requires the console to be redrawn with interrupts masked when graphics ends.

`term_unicode_hosttest.c` checks the actual terminal screen layer with the CJK and rocket from the recorded agent output and explicit accent, Cyrillic, variation-selector, emoji-modifier, flag and ZWJ vectors. Every UTF-8 split point preserves each vector's cells and following sentinel. A byte-at-a-time replay observes the recording's check mark, rocket and CJK with their two-cell widths; its final screen, colors and cursor agree with a whole-input replay. The fixture is declared with `host-inputs:` so preparation fingerprints the recording as well as the compiled sources. These checks have no accepted-failure list. [`term/Readme.md`](../../term/Readme.md#esctest2-and-the-unicode-tests) states the limits they preserve.

### The header lines

A test's opening comment may have five kinds of line, which the preparation tool reads:

* `host-deps: PATH ...`: sources, by path from the repository root, compiled and linked with the test. The line repeats, one list per line. A list wrapped onto a following comment line without its own `host-deps:` prefix fails the test, since the rest of the list would be lost, and so does a named file that does not exist.
* `host-cflags: FLAGS`: more compiler flags, also repeatable: the include paths and warnings of a source outside the kernel tree, or a `-D` the test needs. 112 tests have one.
* `host-first: REASON`: the test starts before the tests of its case without the line, for the reason given, so that a test that runs for minutes does not run alone at the end. The interruption matrices of `ext2_hosttest.c`, `fat32_hosttest.c` and `exfat_hosttest.c`, which run external checkers on copies of the volumes, have one, and so do eight of etude's tests.
* `host-alone: REASON`: the test runs when no other check runs, after the others, for its declared platform isolation or a window of a fraction of a second that a busy machine could miss. `etude_platform_hosttest.c`, `etude_qemu_hosttest.c`, `etude_remote_hosttest.c`, `etude_repeat_hosttest.c` and `etude_watchdog_hosttest.c` have one.
* `host-arch: REASON`: the test boots the kernel of the architecture `ARCH` names, for the reason given, and so is the `boots` case's, which runs once for each architecture. `etude_qemu_hosttest.c`, `etude_watchdog_hosttest.c`, `etude_scenario_hosttest.c` and `etude_legacyset_hosttest.c` have one.

A path of a check's metadata in a vendored port's extracted tree, `vendor/NAME/NAME-VERSION/` as i686 has it, such as `vendor/musl/musl-1.2.5/`, is read for a run with `ARCH=x86_64` from `build/x86_64/vendor-work/` instead, where an x86-64 build extracts the same sources, so a tree that has built only x86-64 runs the test. Another path under `vendor/`, such as a GNU recipe in `vendor/gnu/ports/`, is the repository's file on both architectures.

`tools/verify/coverage.sh` reads the same lines to measure which lines of the named sources a test runs.

`etude_platform_hosttest.c --collection-only` checks the native collection adapter without booting a machine. The real C entry stages local operands, preserves mtools offsets and names, returns failed partial output and the original status, translates debugfs requests, selects native goals and builds an isolated style job. Its preparation row uses real Git and tar with small source and product files; it checks the source index, history bundle, supplied WAD and recovery key, retained workspace and ordinary Make commands. On both architectures a native Make consumes returned musl inputs without rebuilding guest products; an archive missing an input fails even when an older copy remains in the tree. The preparation job must ask for the tooling machine's network, so that a fresh workspace can download the pinned GNU sources; a tool command or a style job that asks for one fails its row. Only the tooling transport is substituted by the fixture. The prepared image-helper controller retains its separate real image and bulk-transfer assertions.

`etude_platform_hosttest.c --retention-only` checks native retention and selected-site reference commands in temporary owned directories. It covers unchanged old bundles, active and unknown evidence, failed or incomplete histories, changed and missing proof closure, accepted baselines, open issues, stale snapshots, logical byte limits, reader use, fractional timestamps, native Windows sequence receipts, concurrent allocation, site mismatch and create-once forecast outputs. The same compiled fixture supplies the read-only GitHub response and estimator roles. No real evidence root or GitHub state is changed.

`etude_scenario_hosttest --real-forward-only` runs only the existing real command-forwarding row, including its exchange, relay closure, restricted-network assertions and cleanup checks. It uses the prepared kernel and images for `ARCH` and the QEMU programs on `PATH`.

### Fixture builders

[`mkfatfixture.c`](mkfatfixture.c) writes FAT32 volumes from the specification, valid ones and ones with each fault a reader must refuse, and with `--check IMAGE` walks a volume and names every fault it finds. [`mkexfatfixture.c`](mkexfatfixture.c) is its pair for exFAT: a builder of the volumes the exFAT tests and the images use, and a checker that walks a volume as `fsck_exfat` does, with `--list`, `--dump` and `--read PATH`. ### Fixtures for extracted functions

Some kernel functions are in files no host test can compile whole. The files in `fixtures/` are test programs over such a function: a rule of [`mk/host-fixtures.mk`](../../mk/host-fixtures.mk) extracts it unchanged from its source into an `.inc` file with [`extract.c`](fixtures/extract.c), which the rules compile first, and compiles the fixture over it. `kstack.c` checks that a new kernel stack is cleared and has a guard page; `endothers.c` that an init under the debug shell waits for the other processes to end; `chown_plan.c` the set-id rules of a chown on a mounted file system; `krffs_open.c` and `krffs_root_lock.c`, with the thread glue of `krffs_open_threads.c`, an open during the flush that publishes a moved KRFFS node, and the KRFFS root's data operations under the mount's lock; and `krffs_stat.c` the inode number the KRFFS root gives to the stat calls. `etude_guest_hosttest --backpressure-only` fills the serial frame queue, witnesses the native child exit, and withholds acknowledgements past the original pipe-drain allowance. It then requires every final byte, both full stream digests and confirmed cleanup. Two further rows cancel or expire an exited attempt with the queue still full and require stopped, unconfirmed records without another acknowledgement. On Linux a fourth row reads the console through a pipe of one page at a frame every 40 ms, so that sending what the child left after its exit takes longer than the allowance, and requires every byte and confirmed cleanup. The ordinary entry includes these rows.

`etude_guest_hosttest --detached-only` runs its three unreported-daemon cleanup paths on Rach2 or Linux: normal exit, cancellation and responder loss. Its ordinary entry still runs every protocol check. A failed check retains and names its private evidence directory. macOS refuses this focused entry because its guest adapter has no child subreaper.

`etude_platform_hosttest.c --evidence-only` checks native evidence staging, restoration, routine proof packing and installed-reader verification. It retains original locators across transport, including foreign native paths, follows late history and load proofs, excludes executable artifact objects and refuses changed, ambiguous, missing, duplicated or escaping members. Restoration verifies every member before creating any destination file. All files are private fixture data.

## Adding tests

Name the file `NAME_hosttest.c` and put the sources it links on `host-deps:` lines in its opening comment:

```c
/**
 * Host test for foo.
 *
 * host-deps: rach2/sys/lib/foo.c rach2/sys/lib/bar.c
 */

#include "foo.h"

int main(void)
{
    return check_foo() ? 0 : 1;
}
```

Repeat the `host-deps:` prefix rather than wrap a long list. A test may use the host's C library, but one that includes kernel sources whole must avoid host headers that define the kernel's types again; the compat files above declare what they need for that reason. Return 0 only when every check passed, and a status from 1 to 255 otherwise: the exit status keeps the low eight bits of what `main` returns, so a count of 256 failures returned whole reads as a pass. Keep the files a test writes in the directory `compat/fixdir_host.c` gives it. Add the test's assertion, `NAME`, to its case in [`tests/cases/host.host.json`](../cases/host.host.json): `tests`, or `etude` for an `etude_` test, or `boots` for one with a `host-arch:` line.

## Limits

* The models are written from the datasheets and the code under test, not from hardware: a device that behaves differently from its model passes here and fails in the guest suites or on the machine.
* No test enters the kernel through a system call or changes privilege. Where a test needs a second thread, it switches at fixed points, by `park_host.c` or by host threads, so an interleaving it does not name is not tested.
* The suite builds with the host's compiler and C library, not the cross compiler, so a fault that only `i686-elf-gcc` or the x86-64 build produces is not seen here.
