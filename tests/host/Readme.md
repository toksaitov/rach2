# Host seam tests (the dual-target seam)

These tests run pure kernel/util logic natively on the host, under AddressSanitizer + UndefinedBehaviorSanitizer, in milliseconds.

A dual-target seam compiles syscall-free logic (string and memory routines, parsers, the VMA tree, path resolution, allocators, scheduler policy) two ways from the same `.c` file: freestanding into the kernel, where only QEMU can run it, and hosted into a native test binary, where a debugger and the sanitizers can. A bounds bug then shows up here, instantly and with a precise diagnosis, instead of as a triple fault in the guest.

Linux unit-tests self-contained pieces the same way (`tools/testing`), and libraries keep their core logic host-verifiable.

## Running

```
make verify-host          # from the repo root
```

`tools/hosttest.sh` compiles every `tests/host/*_hosttest.c` with `-fsanitize=address,undefined -fno-sanitize-recover=all` and runs it. A test passes when it exits 0 (it returns its failed-check count as the status, capped so it never wraps to a false 0, and prints nothing); the sanitizers abort on any out-of-bounds access, overflow, or other undefined behavior in the linked kernel code.

## Writing a seam test

Name the file `*_hosttest.c` in this directory and declare the kernel sources it links with a `host-deps:` comment:

```c
/**
 * One line on what this seam exercises.
 *
 * host-deps: rach2/sys/lib/foo.c rach2/sys/lib/bar.c
 */
#include "foo.h"          /* kernel prototypes; use kernel types, not host libc */
static int fails;
#define CHECK(c) do { if (!(c)) { fails++; } } while (0)
int main(void) { /* ... CHECK(...) ... */ return fails; }
```

The `host-deps:` line is a build contract: `tools/hosttest.sh` reads the paths after it and hands them to the compiler, so the list names every kernel source the seam links separately. A test that pulls its source in with a direct `#include` (to reach the file's `static` routines) leaves the line empty.

Keep the test free of host `<stdio.h>`/`<string.h>` so kernel and host type definitions never collide; assert via the return code; let the sanitizers do the rest.

## The compat headers

`compat/` holds stand-ins for the three musl headers a `utils/` source includes that a native host need not have: `<crypt.h>`, `<shadow.h>` and `<sys/random.h>`. They exist because a seam test may compile a guest source, and a guest source is written against the ported musl; Darwin, for one, declares `crypt` in `<unistd.h>` and ships neither of the other two. `hosttest.sh` puts the directory on the include path, so on a host that does have those headers these declarations are the ones used; they are musl's, so the seam is the same either way. Nothing the guest builds ever sees them, and the symbols themselves are the test's to define.

Current tests:

* `kstring_hosttest.c`: the string and memory routines (`sys/lib/kstring.c`, with `sys/lib/kctypes.c`).
* `krandom_hosttest.c`: the ChaCha20 keystream CSPRNG (`sys/lib/krandom.c`).
* `vm_hosttest.c`: the VMA interval tree, its overlap search and split logic (`sys/mm/vm.c`).
* `frame_hosttest.c`: the physical-frame pool sizing from the multiboot memory map (`sys/mm/frame.c`).
* `synthfs_hosttest.c`: the synthetic `/dev` and `/proc` path classifier (`sys/fs/synthfs.c`).
* `poll_select_hosttest.c`: the `fd_set` and `pollfd` translation and the readable/writable/except projection (`sys/io/poll_select.c`).
* `pipe_ring_hosttest.c`: the pipe ring-buffer arithmetic (`sys/ipc/pipe_ring.c`).
* `n_tty_hosttest.c`: the N_TTY line discipline's input editing and echo (`sys/tty/n_tty.c`).
* `tls_hosttest.c`: the `set_thread_area` user_desc validation (`sys/proc/tls.c`).
* `rtc_hosttest.c`: the CMOS clock (`sys/rtc.c`): the BCD and binary decodings, the PM bit, the status-register cases a decode must refuse, the day count from the epoch across leap years, and the anchor arithmetic that turns a boot-time read plus a tick count into a real time. The kernel side of the clock is here rather than in the guest because the error a wrong anchor makes is under a second, and no tolerance a booted probe could hold would see it.
* `wait_queue_hosttest.c`: the wait-queue enqueue and wake logic (`sys/proc/wait_queue.c`, included directly under a build flag so its static routines are reachable, hence the empty `host-deps:`).
* `uimage_hosttest.c`: the initial-process stack and auxv builder (`sys/proc/uimage.c`, with `sys/lib/kstring.c` and `sys/lib/kctypes.c`).
* `pwauthatexit_hosttest.c`: what a writer does when it cannot register its release (`utils/pwauth.c`, with the vendored musl SHA-512 crypt). A program of its own because the `atexit` it needs to fail cannot be scoped: the stand-in replaces the real one for the whole process, and every case in `pwauth_hosttest` needs a release that is registered. It accepts the first registration and refuses the second, which is the partial failure that leaves one function installed with no transaction behind it: the acquire must be refused, no lock may be left at the name, the library must be seen to have attempted the second registration at all, and the accepted function, called by hand where the walk would have reached it, must put no signal disposition back, since the one it saved is a zeroed `struct sigaction` that would impose the default on the rest of `exit`.
* `pwauth_hosttest.c`: the credential library (`utils/pwauth.c`, with the vendored musl SHA-512 crypt), the one seam here that is a util rather than a kernel source. It covers what is pure or can be made pure: the password comparison against the published SHA-crypt vectors and the deny cases that must refuse alike (a missing entry, an empty field, a locked `!`, a `*`, a field that is not a `crypt(3)` setting), the salt mapping over every byte value, the replacement idiom in a temporary directory (a plain replace, mode inheritance, a stale temporary removed, an uncreatable one leaving the target untouched, a missing target refused, a rename that cannot happen because a directory stands at the destination, and a call with no transaction held refused with the target untouched), the three flushes told apart by a stand-in `fsync` that fails on the call the case names (the one before the rename is a refusal that changed nothing, the one after it a replacement that is already live and must not be reported as unchanged, and the release's own is a lock gone from the running system whose removal may not have reached the disk, which is likewise not a clean finish), what a `fork` under a held transaction does, which is nothing (a child that exits and a child a signal kills both leave the lock where it is, and its `cred_txn_end`, `cred_rewrite` and acquire all decline), what a release and a publish do about a lock that is no longer this transaction's (nothing, since a name is not proof of a file), what an acquire does when it cannot write the holder pid (fails and removes the lock, rather than holding one every later writer is told to clear), and the lock protocol through the `_at` forms, whose lock path and retry budget are parameters so the test neither touches `/etc` nor waits ten seconds to watch an acquire refuse. Every lock case asserts the refusal and that the file is still there afterwards with its bytes unchanged, since the rule is that a lock is reported and never broken: a live pid, a reaped child's pid, a live pid whose modification time was pushed back an hour, an empty lock and one that does not parse are all refused, and each refusal names the removal, the live one conditionally, since a pid does not identify a process across a reboot, a second transaction in one process is refused without touching the file, and the control that makes those mean something is removing the file by hand and watching the next acquire succeed. The wait is timed, too, so a budget that never waited would not pass. Thirteen more cases are deaths and states no arrangement of the file system produces, so each is forced rather than waited for: a prompt, and then a writer, whose standard error is a pipe with no reader, both of which must return rather than be killed by `SIGPIPE`, with the writer's lock gone afterwards, since a death there runs no `atexit`; a release from a child that has filled its descriptor table, which must still remove the lock, beside a release over a lock that cannot be read at all (a symbolic link resolving to itself), which must return -1 and say so; the temporary file's name, read out of the directory by the stand-in `fsync` at the one moment it exists, which must carry the writer's pid, with a directory standing at the shared `<path>.tmp` to show that name is never used and a replacement refused for a lost lock required to leave even its own leftover temporary byte for byte; and a `SIGCONT` inside the prompt's teardown, over a pseudo-terminal, forced by giving the reader a pipe the test fills so the newline in the middle of the teardown blocks inside the window, after which the reader reads `ECHO` off its own terminal and reports it as an exit status; the disposition a writer's child carries across an `exec`, which the program answers by running itself, and which must be the default rather than the `SIG_IGN` an exec would have preserved; the death-signal mask, read from inside each stretch the library blocks it across by the three seams that reach them (`snprintf` for the lock path and the temporary's name, `fsync` for the release, `getpid` for the release registered with `atexit`), with the caller's mask required back afterwards on the paths that fail as well as the ones that succeed, since an early return is where a restore is forgotten; and what that registered release leaves behind, which no case inside the process can watch because it runs after the last of them, so a child execs this program, which registers its own reporter before taking a transaction and therefore runs it last, and then exits holding a transaction it never ends, so the same case proves the lock is dropped at all. Three cases watch the release registered with `atexit`, and each needs a fresh image, because that release runs after the last case in this process and a reporter can only see what it left by being registered before it and therefore running after it. One exits still holding a transaction, so the release must drop the lock, keep the deaths blocked for its own length and give the caller's mask back; one ends its transaction and then installs a disposition of its own, which the release must not reach back and overwrite; and one forks under a held transaction and lets the child leave through `exit` while the middle image leaves through `_exit`, so the heir must drop the descriptor and the five dispositions it inherited and must not touch the lock, which is its parent's. A fourth case, in the same fresh-image shape, asks what a program's own `atexit` function sees if it runs after the library's: an acquire attempted there can never be released, so it must be refused. Three more cases are about signals rather than locks: one holds a transaction and takes `SIGUSR1`, `SIGUSR2`, `SIGALRM`, `SIGABRT` and `SIGSYS` in turn, each of which must leave through `exit` with the lock gone rather than take the default action; one sets every signal to a known disposition in a child, takes a transaction, and reports any signal whose disposition does not then match what the library means, in both directions, skipping the ones this host does not have; and one delivers a death from inside the restore that another death started, through a `tcsetattr` seam that raises on the restore's own call, since that window is two instructions wide and cannot be entered from outside. That last one counts how many restores reached the terminal, which is the whole difference between clearing the echo-off flag before the call and after it. Two habits make those mask cases mean something. The baseline they compare against is the mask the process started with, captured once in `main`: read on arrival instead, a leak from an earlier case would become the thing every later comparison measures against and all of them would pass, and assumed empty instead, the test would blame the library whenever a harness ran it with a signal already blocked. A discrepancy on arrival is therefore an earlier case's doing, and is reported as that and repaired before the case goes on. The comparison is also of the whole mask rather than of the four, since a library that put three back and kept the fourth would satisfy any test of "are the deaths blocked". Owner inheritance and the reader across a rename are asserted in the guest instead, by `tests/musl/pwauthmusl.c`, where root and uid 1000 differ and the file system is the one that makes the promise.
