# Host tests

The host tests compile kernel and user sources as ordinary programs for the build machine and run them under AddressSanitizer and UndefinedBehaviorSanitizer. A test drives the real code against models of what surrounds it (a device's registers, a disk, a scheduler, a peer on the network), so a bounds fault, an overflow or a wrong branch shows in a few seconds on the host rather than as a fault inside QEMU. What needs the machine itself, a system call through the trap path, a privilege change, a real device or a whole subsystem at once, is tested by the guest suites of [`tests/system/`](../system/Readme.md). This directory has the 148 `*_hosttest.c` programs, the headers, models and fixture builders they share, and the mutation scripts that prove them.

## Running

`tests/run host` runs the suite. Its make target, `run-host` in [`tests/system/suites.mk`](../system/suites.mk), first builds musl's installed library (`check-libc`), the extracted e2fsprogs tree, the `deadline` tool and the KRFFS stager, then runs [`tests/system/machine_measure_test.sh`](../system/machine_measure_test.sh), the check of the machine measurement drivers in `tools/dev/` against command fixtures, and then [`tests/system/suites/host.sh`](../system/suites/host.sh), which does four things in order:

1. Compiles and runs each `tests/host/*_hosttest.c`.
2. Compiles six checkers again under the sanitizers and runs their self-tests: `tools/inspect/elfcheck.c`, `cfgcheck.c` and `setidcheck.c`, `tools/verify/prosecheck.c`, and `tests/system/runner/runtests.c` and `harness.c`, each with `-Wall -Wextra -Werror` and `--selftest`.
3. Runs fifteen scripted checks: the `--check` mode of `krffs_open_mutate.sh`, `krffs_root_lock_mutate.sh`, `kstack_mutate.sh`, `endothers_mutate.sh`, `chown_mutate.sh`, `pagecache_mutate.sh` and `krffs_tools_mutate.sh` in this directory; `tests/system/run_scripts_test.sh`, `commit_msg_test.sh`, `ci_test.sh`, `board_test.sh`, `install_accounts_test.sh` and `mkext2_overlay_test.sh`; and `vendor/tcc/check_asm.sh` and `check_ldscript.sh`.
4. Builds the fuzz harnesses of [`tests/fuzz/`](../fuzz/Readme.md) as replay programs with `tests/fuzz/build.sh replay` and runs each over its committed corpus, `tests/fuzz/corpus/NAME/`. A harness that did not build, or whose corpus is empty, fails.

The suite has no option to run one test. To run one by hand, print the compile commands, compile the one wanted, and run the binary:

    HOST_PRINT_COMMANDS=1 sh tests/system/suites/host.sh | grep '/fat32_hosttest ' | sh
    build/tests/host-suite/fat32_hosttest

With `HOST_PRINT_COMMANDS` set, `host.sh` prints the command of each test and checker and compiles nothing; `tools/verify/coverage.sh` and `tools/dev/gen_compile_commands.sh` read the same output.

## Results

`host.sh` prints a line for each program:

    PASS: fat32_hosttest
    FAIL (compile; see build/tests/host-suite/NAME.clog): NAME
    FAIL (run; see build/tests/host-suite/NAME.rlog): NAME
    FAIL (hung; killed after 60s; see build/tests/host-suite/NAME.rlog): NAME
    FAIL: NAME: missing host-deps: rach2/sys/fs/gone.c

A test passes when it exits with status 0. A nonzero exit, a sanitizer report (every sanitizer is fatal, by `-fno-sanitize-recover=all`), a compile failure, or a run past its time limit fails it. The time limit is 60 seconds, or the one a `host-seconds:` line gives; `deadline` kills the test's whole process group and exits 124, which is the "hung" line. When `build/tests/system/deadline` is not built, `host.sh` says so on stderr and runs the tests without a limit. A missing source under `vendor/musl/` adds a line saying the musl tarball is not extracted, with the repair: remove `vendor/musl/.stamp` and run `make`.

A self-test prints `PASS: NAME selftest under the sanitizers`, a scripted check `hosttest: result: pass: WHAT` or `hosttest: result: fail: WHAT` with its log on the terminal, and a fuzz harness `PASS: NAME corpus replayed (N inputs)`. The compile and run logs are in `build/tests/host-suite/`, which belongs to the tree being tested, so runs in two clones write no file in common. The suite exits 1 when anything failed, and also when it found no test at all. A test that writes fixtures keeps its fixture directory when it fails and prints the directory's path.

## Design

### The compile

Each test is one compile and one program:

    cc -std=c99 -D_DEFAULT_SOURCE -D_FORTIFY_SOURCE=0 -DRACH2_HOSTTEST \
       -fsanitize=address,undefined -fno-sanitize-recover=all -g -O1 \
       -Wno-empty-body -ffreestanding INCLUDES CFLAGS -o OUT TEST DEPS

`CC` in the environment replaces `cc`. The include path is `rach2/sys`, `rach2/sys/arch/x86`, `rach2/sys/arch/i686`, `rach2/sys/lib`, `rach2/sys/proc`, `utils`, `krffs` and `tests/host/compat`, in that order. `-ffreestanding` keeps the compiler from turning the loops of `k_memset`, `k_memcpy` and `k_memmove` into calls to the routines they implement, which `rach2/sys/lib/kstring.c` defines as wrappers around them. `-D_DEFAULT_SOURCE` restores the POSIX declarations glibc hides under a strict `-std`, and `-D_FORTIFY_SOURCE=0` turns off the checked string calls that Ubuntu's compiler adds by default and that make `snprintf` a macro on macOS. `RACH2_HOSTTEST` lets a kernel source leave out what a host build cannot compile, and gives it i686's `cpu.h`; a test that also defines `RACH2_HOST_X86_64` on its `host-cflags:` line gets x86-64's.

A test reaches the code under test in one of two ways. It names separately compiled sources on `host-deps:` lines, or it includes a `.c` file whole, which reaches the file's `static` functions and needs no `host-deps:` line for that file. Most tests do both.

### The header lines

A test's opening comment may have three kinds of line, which `host.sh` reads with `grep`:

* `host-deps: PATH ...`: sources, by path from the repository root, compiled and linked with the test. The line repeats, one list per line. A list wrapped onto a following comment line without its own `host-deps:` prefix stops the suite, since the rest of the list would be lost; a named file that does not exist fails the test.
* `host-cflags: FLAGS`: more compiler flags, also repeatable: the include paths and warnings of a source outside the kernel tree, or a `-D` the test needs. 33 tests have one.
* `host-seconds: N`: the time limit, in place of 60 seconds. `fat32_hosttest.c` declares 300 and `exfat_hosttest.c` 450.

`tools/verify/coverage.sh` reads the same lines to measure which lines of the named sources a test runs, and several mutation scripts read them to compile a test the way the suite does.

### Shared code

* `compat/crypt.h`, `compat/shadow.h` and `compat/sys/random.h` declare the three musl interfaces `utils/pwauth.c` uses, for hosts that lack the headers (macOS has no `crypt.h` and no `getrandom`). They are musl's declarations, and the tests define the symbols.
* `compat/netutil/` has the `net/if.h`, `net/route.h` and `netpacket/packet.h` structures the network utilities use, for the tests that compile those utilities.
* `compat/e2fsprogs/` configures e2fsprogs' `unix_io.c` for the two alignment tests and gives them an in-memory sector device.
* `compat/kheap_host.c` is the kernel heap over the C library's allocator, with an optional cap on the largest allocation and on the page allocations it grants before it fails; `compat/paging_host.c` gives a buffer's own address as its physical address; `compat/spinlock_host.c` is a one-processor spinlock that stops the test when a held lock is taken again; `compat/pressure_host.c` answers the buffer cache's memory target.
* `compat/devmodel.c` is a disk with pending and durable writes, for the FAT tests. Reads see every write; `block_flush` makes the pending writes durable, or fails on the Nth call; a stop after the Nth write refuses every later write; and a snapshot at the stop is the medium with none, the newest one to six, or all of the writes since the last barrier, each a state a drive that reorders its cache can leave. `compat/blockmax_host.c` answers the same two block-layer calls for tests that need no model. `devmodel.h` states the model and what lies outside it.
* `compat/park_host.c` runs a second thread's call inside a sleep of the first without threads: `park_run` starts the call on a stack of its own, a model wait calls `park` to switch back, and `park_resume` continues the call where it waited. It uses the C library's ucontext calls.
* `compat/fixdir_host.c` gives a test that writes files a directory of its own. It is the directory `FIXDIR` names when the test is compiled with it, as a mutation script does; otherwise a new one under `$TMPDIR`, when that is an absolute path of at most 100 characters drawn from letters, digits and `/ . _ + -`, or else under `/tmp`. `fix_path` names a file in it and `fix_format` formats a command or path, ending the test when the text does not fit. The directory is removed at exit only when the test called `fix_passed` and LeakSanitizer found no leak. `bootctl`, `exfat`, `exfatcheck`, `ext2`, `fat32`, `fatcheck`, `krffs_fuse` and `netcfg` use it, and `fixdir_hosttest.c` tests it.
* `ns_first.h` answers the namespace calls of `proc/ns.c` as they answer for a process in the first namespaces. `acpi_qemu_tables.h`, `exfat_upcase.inc`, `krffs_hash_vectors.h`, `ext2_batch_cases.h` and `ext2_batch_lifecycle.h` are data and rows included by one or two tests; each begins with a comment saying where it comes from.
* `fuse/fuse.h` declares the FUSE types and calls the KRFFS mount tool uses, so `krffs_fuse_hosttest.c` needs no FUSE installed.

### Fixture builders

[`mkfatfixture.c`](mkfatfixture.c) writes FAT32 volumes from the specification, valid ones and ones with each fault a reader must refuse, and with `--check IMAGE` walks a volume and names every fault it finds. [`mkexfatfixture.c`](mkexfatfixture.c) is its pair for exFAT: a builder of the volumes the exFAT tests and the images use, and a checker that walks a volume as `fsck_exfat` does, with `--list`, `--dump` and `--read PATH`. Both are written apart from the kernel's drivers, so that the drivers are checked against a second implementation of each format; the options are listed at the head of each source. The tests that use them compile their own copies into their fixture directories; the build compiles both into `build/tests/host/` for the image rules and the guest suites. `host.sh` does not run them as tests; `fatcheck_hosttest.c` and `exfatcheck_hosttest.c` test their checkers.

`mkexfat_external.sh DIR` formats and fills an exFAT volume with the host's own tools (`hdiutil` and `newfs_exfat` on macOS) for `exfat_hosttest.c`'s rows over a volume another implementation wrote; it exits 3 where those tools are missing, and the test reports the rows as skipped.

### Fixtures for extracted functions

Some kernel functions are in files no host test can compile whole. The files in `fixtures/` are test programs over such a function: the script beside them extracts it unchanged from a copy of its source into an `.inc` file, compiles the fixture over it, and runs it. `kstack.c` (with `kstack_mutate.sh`) checks that a new kernel stack is cleared and has a guard page; `endothers.c` (`endothers_mutate.sh`) that an init under the debug shell waits for the other processes to end; `chown_plan.c` (`chown_mutate.sh`) the set-id rules of a chown on a mounted file system; `krffs_open.c` and `krffs_root_lock.c` (`krffs_open_mutate.sh`, `krffs_root_lock_mutate.sh`), with the thread glue of `krffs_open_threads.c`, an open during the flush that publishes a moved KRFFS node, and the KRFFS root's data operations under the mount's lock. Each script's `--check` mode runs the fixture alone, which is how the suite runs it.

### Mutation scripts

Each of the 68 `*_mutate.sh` files proves one or more host tests: it copies the sources into a private directory, compiles each fault into the copy, requires the test to fail at the check named for that fault, and then restores the copy, rebuilds and requires a pass. A trap restores the source when the script is stopped, and the logs, sources and binaries stay in the directory under `build/` the script prints. Every script takes `--texts`, which checks that each fault's text occurs in its source and runs nothing; `tools/verify/faulttexts.sh` runs that mode for all of them. Eighteen also take `--check`, which runs the unmodified test alone. The test entries below name the script that proves each test. `ata_rate_test.sh` compiles and runs `ata_hosttest.c` alone for the `diskrate` suite, and with `--mutate` proves its two write-count checks. The [testing skill](../../.agents/skills/testing/SKILL.md) says when a mutation proof is required and how to run one on the testing host.

## Adding tests

Name the file `NAME_hosttest.c` and put the sources it links on `host-deps:` lines in its opening comment:

```c
/**
 * Host test for foo.
 *
 * host-deps: rach2/sys/lib/foo.c rach2/sys/lib/bar.c
 */

#include "foo.h"

int main(void)
{
    return check_foo() ? 0 : 1;
}
```

Repeat the `host-deps:` prefix rather than wrap a long list. A test may use the host's C library, but one that includes kernel sources whole must avoid host headers that define the kernel's types again; the compat files above declare what they need for that reason. Return 0 only when every check passed, and a status from 1 to 255 otherwise: the exit status keeps the low eight bits of what `main` returns, so a count of 256 failures returned whole reads as a pass. Keep the files a test writes in the directory `compat/fixdir_host.c` gives it. A new test is trusted only after a mutation has made it fail; add the script beside it.

## Limits

* The models are written from the datasheets and the code under test, not from hardware: a device that behaves differently from its model passes here and fails in the guest suites or on the machine.
* No test enters the kernel through a system call or changes privilege. Where a test needs a second thread, it switches at fixed points, by `park_host.c` or by host threads, so an interleaving it does not name is not tested.
* The suite builds with the host's compiler and C library, not the cross compiler, so a fault that only `i686-elf-gcc` or the x86-64 build produces is not seen here.

## Tests

Each entry names a test, the code it compiles, and its cases. The reasoning of a case is in the test's source.

### Kernel libraries, memory and processes

* `kstring_hosttest.c` runs the string and memory routines of `rach2/sys/lib/kstring.c` with `rach2/sys/lib/kctypes.c`. Rows check `k_strlen`, `k_memset`, `k_memcpy`, `k_strncpy`, `k_strreverse` on strings of zero to five characters, `k_toupper`, `k_tolower`, `k_strtoupper`, and `k_memmove` over ranges that overlap in either direction and between two separate objects. A sweep runs the copy, the fill and both directions of the move for every length from 0 to 67 at four source and four destination offsets, and checks the bytes copied and the bytes beside them.
* `kstd_hosttest.c` runs `k_itoa` of `rach2/sys/lib/kstd.c`, the integer formatter behind kernel and utility numbers, with `kstring.c` and `kctypes.c`. Rows check signed decimal to both limits of `int`, the most negative value included; hexadecimal, octal and binary, which print the bit pattern unsigned, and a radix of 36; the returned count, which includes the sign and the terminating NUL; a buffer too small and a radix out of range, each answered with 0; and the plus `force_sign` writes before a positive decimal and not before zero or a negative one. `kstd_mutate.sh` proves it.
* `kfmt_hosttest.c` runs `k_vprintf` of `rach2/sys/lib/kfmt.c`, the formatter of every kernel message, into a buffer and compares each row's whole output. Rows check the conversions `%d`, `%u`, `%lu`, `%x`, `%X`, `%o`, `%b`, `%s` with a null pointer, `%c` and `%%`; unsigned values past the largest `int`; the `0` flag and the width, and a value wider than its width; a PCI address message of five fields; a width before another argument; a format that ends on its percent; and an unknown conversion, which prints its letter.
* `klog_hosttest.c` includes the kernel log, `rach2/sys/klog.c`, with recorders for the screen, the serial port and netconsole, and counts the interrupt brackets it takes. Rows check a record's priority, uptime, subsystem and single newline; truncation and its mark; the clamped levels and the levels each destination takes; the order of the destinations, with a serial port that never drains; the eviction of whole records when the ring wraps; console output, which reaches the screen and the port but not the ring or the wire; records raised during the delivery of another, one at a time and in a burst past the queue of eight, which is counted; and a record raised during a program's console write or a line of the debug shell, which follows the line. `klog_mutate.sh` proves it.
* `krandom_hosttest.c` runs the ChaCha20 generator of `rach2/sys/lib/krandom.c`. Rows check that a seed gives the same stream twice and another seed a different one, that the all-zero seed does not give zeros, that `krandom_bytes` fills a 37-byte buffer within its bounds, and that 4096 bits of one fixed seed's stream have a count of set bits within 205 of 2048.
* `latency_hosttest.c` includes `rach2/sys/latency.c`, the kernel's record of its longest delays, with a clock the test sets. Rows check that a delay is the difference of its two readings and only a longer one replaces the maximum; that a pair whose later reading is the smaller is dropped, not kept as a delay of nearly 2^32 microseconds; that the gap between timer ticks follows the same rule and measures the next gap from the stepped reading; and that a kind out of range reads zero and a note for one changes nothing.
* `mbinfo_hosttest.c` runs `rach2/sys/arch/x86/mbinfo.c`, the reader of the boot loader's information, over multiboot2 tag lists the test writes and a Multiboot structure whose pointers a model of physical memory answers. Rows check the boot record: the command line, the loader's name and the memory above 1 MiB; multiboot2 memory maps and the entry sizes refused; an EFI map of 48-byte descriptors, with each kind of memory classed, which takes the place of a multiboot2 map and is cut and counted past 256 entries; the EFI system tables; each kind of framebuffer and its palette; the two RSDP revisions; ten modules, of which eight are kept; and lists cut short, read up to the fault. The Multiboot rows check the same fields. A last row passes the record's command line to `kcmdline_capture` of `rach2/sys/cmdline.c`, which keeps a line of 510 bytes whole and cuts one the record cut at 511 after its last whole token.
* `modlayout_hosttest.c` includes `rach2/sys/mm/modlayout.c`, the check that the boot modules leave the kernel image and each other alone before the kernel reserves their memory. Rows accept modules back to back, out of order, ending at the limit or starting at the kernel's end, and none at all; and refuse an empty, backwards or wrapping range, a module past the limit or over the kernel image, and two that overlap in any way, with the later module's index. Further rows check the panic text of `modlayout_describe`, at the width of the host's addresses and cut to a short buffer or to none, and the reason given for each code.
* `tables_hosttest.c` includes `rach2/sys/arch/i686/gdt.c`, `tss.c` and `idt.c` with the assembly they call stubbed, and reads the tables they build for processor 0. Rows check the double fault's task: vector 8 is a present task gate of DPL 0 whose GDT entry is an available 32-bit TSS over `double_fault_tss`, and that TSS starts `isr_double_fault` with interrupts off in the kernel's segments, on a stack of its own, with the page directory it is given. Other rows check that every other exception gate is an interrupt gate to its own stub, that the kernel's TSS keeps its ring 0 stack, and that GDT entry 8 is the processor's data segment, whose first word is its index.
* `frame_hosttest.c` runs `rach2/sys/mm/frame.c`, which builds the map of physical memory, over memory maps in the boot record's form, and checks the usable, unreachable, reserved and managed bytes and which frames are usable. With i686's reach of 4 GiB the maps are QEMU's from 64 MiB to 4 GiB; the Lenovo G50-70's as its boot printed it, with NVS and ACPI ranges and most of its memory above 4 GiB; and synthetic maps with holes, overlaps, a wrapping length, a cut entry, no entries or too many ranges. With x86-64's reach of 64 TiB they are QEMU's at 6 and 8 GiB, the Lenovo's, a range past 64 TiB, and a UEFI-shaped map of 256 entries. Further rows check `FRAME_MAP_RANGES` and where `frame_map_place` puts the frame table. `frame_mutate.sh` proves it.
* `paging_hosttest.c` includes `rach2/sys/mm/paging.c` and `rach2/sys/arch/i686/mmu.c` with the processor primitives and page directory of the test's own and a heap that counts the page tables it gives; its `host-cflags:` lines make `uintptr_t` and `size_t` 32 bits wide, as on an i686. Rows check that `map_mmio` maps a register page uncached and refuses a range past the top of the address space, and that `premap_kernel_window` gives a window its tables, at address 0 and ending at the top, and refuses one past the top. Other rows check the 1024 slots of `kmap_temp`: a released slot stays mapped until a sweep, made only when no slot is free, which a held slot survives. Two rows fault in and above a kernel stack's guard page, in a forked child, and check the panic. `paging_mutate.sh` proves it.
* `kheap_hosttest.c` includes the kernel heap, `rach2/sys/mm/kheap.c`, over 260 MiB of host memory, with the frames a counter and the page tables a map of the mapped pages. Most rows give the heap 8192 pages with a reserve of 4096 and check that single pages stop at the reserve; that a scattered region still gives sixteen runs of 256 pages from the reserve and no more; that a large `kmalloc` takes a reserve run, and its free or a shortage of frames gives the run back; the guarded runs of kernel stacks; and the cache's pages, taken from the other end. Other rows check `kheap_size_for`, an eighth of memory on x86-64 between a floor of 256 MiB and a cap of 512 GiB, and a heap given the whole region. `kheap_mutate.sh` proves it.
* `mm_hosttest.c` includes `rach2/sys/mm/mm.c` over a model of the paging layer that counts what it frees, and checks an address space's two counts: users, whose last put frees the pages, the directory and the regions, and holds, such as a `/proc/PID/mem` descriptor's, which keep only the record. Rows check that a holder takes a user's count only while a user remains; that a thread's end switches to the kernel's directory only as the last user; and, over a model of the file system's part, the program's file: shared by a fork's copy, released by the last end under the release's lock once the space is off the holder count's list, and not kept when the heap has no room.
* `vm_hosttest.c` runs `rach2/sys/mm/vm.c`, the regions of an address space. Rows check `vm_insert` and its refusal of empty, unaligned and overlapping ranges; `vm_find` and `vm_overlaps`; the four cases of `vm_remove`; stack growth down to a limit, short of another region and within an address-space limit; an array grown past its first size and copied; the merge of neighbours; `vm_protect`'s splits and merges and its refusal of a gap and of write on a region marked never writable; `vm_find_free` and `vm_covered`; and regions that map a file, with the file page each piece starts at through splits and trims, a merge only where the pages continue, a reference per region, and a release left for `vm_file_reap`.
* `wait_queue_hosttest.c` includes `rach2/sys/proc/wait_queue.c` with a stand-in process record, which reaches its static `enqueue` and `dequeue`. Rows check that both are idempotent; that `wq_wake_all` makes each of up to 64 blocked waiters ready, leaves a running one alone and empties the queue; and that a wake is counted under each kind of change it is given, data, room or hangup, and summed by `wq_wakes`, while any wake wakes every waiter. One row runs `wq_wait_event` with a model `schedule` that clears the deadline as `signal_post` does, and checks that a wait whose condition is still false arms the deadline again before it blocks again. `deadline_mutate.sh` proves it.
* `sched_hosttest.c` includes `rach2/sys/proc/sched.c` and `rach2/sys/proc/wait_queue.c` over seven process records, with the interrupt flag, the floating-point save and restore and the stack switch replaced by stand-ins that check interrupts are off. Rows check plain rotation; a woken sleeper that runs before the next ready process, once; five spinning processes that each run within fourteen dispatches while two others are woken at every one; wake marks, the states selection passes over, a removed cursor and preemption deferred to the end of a system call; and a processor's tick, which counts the global ticks it has not counted and charges a tick in ring 3 as user time. `sched_mutate.sh` proves it.
* `smp_hosttest.c` includes `rach2/sys/proc/smp.c` and runs as processor 0, with three other processors as records of `cpu_table` and an interprocessor interrupt of the test's own that counts what each processor is sent and answers at once. Rows check that a TLB shootdown interrupts a processor running a thread of the directory, marks it stale on an idle processor that kept it loaded, and leaves one in another directory alone; that the idle processor gives the directory up before it is freed; that a stop waits a second only for a processor that does not answer; and that the boot counts no processor that did not come, nor one that comes late. `smp_mutate.sh` proves it.
* `process_timer_hosttest.c` includes `rach2/sys/proc/process.c` with every export but `proc_wake_sleepers` and `proc_alarm_at` made private, and a model `signal_post` that counts each `SIGALRM` and wakes no one. Over a blocked process ahead of a running one, each with a timer, rows check that a due timer posts `SIGALRM` to either and is armed again for its interval or left disarmed, and one not yet due posts nothing; that a sleeper wakes at its deadline tick and not before, while a blocked process with no deadline and a running process are left alone; and that timers and sleepers are served across the wrap of the tick count, where `proc_alarm_at` moves a tick of 0 to 1. `deadline_mutate.sh` proves it.
* `futex_hosttest.c` includes `rach2/sys/proc/futex.c` over user memory modelled as a byte array, with a write fault that stands for a sleep in which another thread runs or ticks pass. Rows check that `get_robust_list` reports the head of a thread that ends during the copy out, which AddressSanitizer judges by the freed record; that a thread's end releases a robust futex with `FUTEX_WAITERS` and `FUTEX_OWNER_DIED` and wakes the waiter, reading the word again when another processor changed it; what the end does with a futex it was taking or giving back; that the `CLONE_CHILD_CLEARTID` word is cleared only when another thread shares the address space; that a wait's deadline counts the ticks a fault took; and which interrupted waits `futex_restartable` restarts.
* `exit_hosttest.c` includes `rach2/sys/proc/exit.c` and `rach2/sys/proc/wait_queue.c` and runs `proc_exit_cleanup` with close and directory callbacks that wait on the real queue, and a scheduler stand-in that releases the contended lock only once the dying process is blocked on it. Five cases, with and without files, a directory and a parent, check the order of the end: the futexes; the address space, once, leaving the processor in the kernel's directory; the files; the directories; a `vfork` parent let go once; the children adopted; and only then the zombie and `SIGCHLD`, with the wait status kept and no waiter left. `exit_mutate.sh` proves it.
* `elf_hosttest.c` includes the ELF loader, `rach2/sys/proc/elf.c`, with the page and mapping calls stubbed, and loads images built in a buffer through a read callback. Rows check that every card becomes an interface, numbered from one and named from `eth0` in the table's order; that an absent card is passed over; that a card that will not start is stopped and its reason kept while the walk goes on; a machine with no supported card; a card refused by `rach2.nicfail`; calls with no interface bound; the link report; and `IFF_RUNNING` following the link. `netconfig_mutate.sh` proves it.
* `rtl8139_hosttest.c` includes `rach2/sys/network/driver/rtl8139.c` over a model of its registers that supplies one complete frame and an overflow status for each interrupt; PCI discovery and DMA are not modelled. Through 1024 interrupts of alternating receive-ring and FIFO overflows, every overflow must be counted, every frame delivered intact and released, and only the first overflow logged. A later receive error must still warn, and a transmit must start under the saved interrupt flag and restore it. `rtl8139_mutate.sh` proves it.
* `rtl8168_hosttest.c` includes the RTL8168GU driver, `rach2/sys/network/driver/rtl8168.c`, over a model chip that answers every register the driver touches and records every write, and compares that record with the order and values of the reference driver. Rows cover the bring-up; a different 8168 and an all-ones window refused, and an absent card reported absent; every handshake that never completes; transmit, with padding and a full ring; receive, with error frames, fragments and short frames dropped; ring wrap; the card's messages and interrupt storms; link changes; and the card's own counters.
* `e1000_hosttest.c` includes the Intel 82540EM driver, `rach2/sys/network/driver/e1000.c`, over a model card that moves descriptors as the manual says and records every write in order. Rows check the bring-up order and values; the station address from the register pair, or else the EEPROM; refusals of a reset or EEPROM that never answers, an all-zero or group address, an unmappable window and an interrupt line past 15; an absent card costing no register access; each of the four receive checks failing alone; ring wrap; transmit padding, an over-length frame and a bounded stall; the stop sequence; and the link's speed and duplex.
* `packet_hosttest.c` includes `rach2/sys/network/ethernet/ethernet.c` and `rach2/sys/network/ip/ip.c` with the layers around them replaced by recorders, each frame at the end of its own allocation so that a read past it is a sanitizer report. Receive rows drop a short Ethernet header, a version other than 4, bad header and total lengths, a bad checksum, a fragment and a datagram for another host, and pass each protocol to its parser, the raw layer and the packet sockets. Send rows run `ip_tx`: the MTU on every path, a link that is down, a datagram held on an ARP miss, a driver's refusal, the 64-slot loopback ring overfilled and drained in order, and broadcasts from two cards. `ip_mutate.sh` and `network_mutate.sh` prove it.
* `arp_hosttest.c` includes the address cache, `rach2/sys/network/arp/arp.c`, with the Ethernet layer replaced by a recorder, and feeds it packets one at a time. Rows check that no address a neighbour cannot have is cached; that a request for this machine is answered with its hardware address; that a learned mapping releases the datagrams held for it and a refused one does not; that a seventeenth neighbour replaces the entry longest unused, across a counter wrap too; permanent mappings; malformed layouts; a second interface; and the network lock's balance. `network_mutate.sh` proves it.
* `netconf_hosttest.c` runs `rach2/sys/network/netconf.c` and the command-line capture of `rach2/sys/cmdline.c`, with ARP and TCP replaced by counters. `netconf_parse_cidr` and `netconf_gateway_ok` refuse octal-looking, out-of-range and trailing text, a subnet's own network and broadcast addresses, loopback, multicast, and a gateway off the subnet. `netconf_apply` keeps the defaults for an empty line, gives an address without a gateway no gateway, refuses duplicates, and takes `rach2.ip=none`; `rach2.ifaddr=` configures interfaces by MAC and skips bad tokens. `netconf_set_address`, `netconf_set_netmask` and `netconf_set_gateway` change an interface live: a classful mask until the real one comes, the ARP cache forgotten, TCP told under the network lock, the second interface kept apart from the first. `netconfig_mutate.sh` proves it.
* `netconsole_hosttest.c` includes `rach2/sys/network/netconsole.c` with the Ethernet layer replaced by a recorder. Rows check that nothing is sent before the console is enabled or while the link is down, and that what was held goes out after; the frame's fields and checksum; a frame for each line and for each full payload; overflow counted rather than written past the ring; a full ring drained in the fewest frames; a card that refuses frames; and a driver that prints from inside the transmit, whose message is held rather than sent from within it.
* `rcvwnd_hosttest.c` runs `rcvwnd_update` from `rach2/sys/network/tcp/rcvwnd.c`, the receiver's choice of when to announce a larger window. Rows check that a drained ring announces its window; that growth below one segment or half the ring, whichever is smaller, stays quiet (RFC 1122, section 4.2.3.3), at ring sizes where each half of the rule decides; that a window is not announced twice; that a ring of 65536 bytes or more is clamped to 65535 unless the window is scaled; and that a zero ring, an overfull one and a zero segment size neither wrap nor divide by zero.
* `tcp_hosttest.c` includes `rach2/sys/network/tcp/tcp.c` and links `rcvwnd.c`, with IP replaced by a recorder of every segment `ip_tx` would send, the socket layer by a recorder of callbacks, and the clock by a variable. Rows cover the control-block pool (forty blocks, one freed from the middle), a closed port, the handshake, duplicate, overlapping and out-of-order data around a hole, zero windows, a FIN and a half close, the argument checks of `tcp_send`, the peer's MSS, path MTU reports, window scaling, selective acknowledgements, ephemeral ports, a driver's transient and permanent refusals, retransmission timeouts and slow start, fast retransmit and recovery, the zero-window probe, round-trip samples, and a SYN sent again with growing waits until the open fails. `tcp_mutate.sh` proves it.
* `tcp_reset_hosttest.c` includes `rach2/sys/network/tcp/tcp.c` with recorders like those of `tcp_hosttest.c` and sends it the segments a host off the path can forge. An established connection takes a reset only at the next expected sequence number, acknowledges one elsewhere in the window, and drops one outside it (RFC 5961, section 3.2); an opening connection takes only a reset whose ACK acknowledges its SYN. A handshake completed after its listener closed is answered with a reset and never accepted. An initial sequence number is the clock, 2500 a tick, plus SipHash-2-4 of the addresses and ports under a key drawn once after `tcp_init` (RFC 6528). `tcp_reset_mutate.sh` proves it.
* `socket_wake_hosttest.c` includes `rach2/sys/network/socket/socket.c` over protocol layers no row calls, and records each wake and the kinds of change it names. A UDP datagram and TCP data wake a socket for data alone, and data a full receive ring takes none of wakes nothing; freed send-ring space wakes it for room alone; a FIN, a connection that completes or ends, and a connection queued on a listener wake it for every kind. An edge-triggered epoll registration for one kind is thus not told of the other.
* `raw_hosttest.c` includes `rach2/sys/network/socket/raw.c` and registers a socket for ICMP. A datagram of another protocol is not queued and wakes nothing; an ICMP datagram is queued whole, keeps its source address, and wakes the socket for data alone, so that an edge-triggered registration for output, which a raw socket always has, is not told of it.
* `netif_hosttest.c` includes the socket calls of `rach2/sys/syscall_net.c` and `rach2/sys/network/socket/packet.c` over a model of two interfaces, with user memory a small arena addressed by offset. Rows check `SO_BINDTODEVICE`; the local addresses of packet and TCP sockets; a frame that wakes a bound packet socket for data alone; accept refused on datagram, non-listening and raw sockets before any wait; the creation flags of `socket` and `accept4`; an accept the heap has no room for, which returns `ENOMEM` and keeps the connection queued; a `recvfrom` with an address and no length pointer, which returns `EFAULT`; and another thread's close of the descriptor accept reserves while it copies the peer's address. `netif_mutate.sh` proves it.
* `dhcpmsg_hosttest.c` runs the message half of the DHCP client, `utils/dhcpmsg.c` with `utils/ipcheck.c`, on messages copied to heap blocks of their exact length and built with the test's own checksum code. Rows check the discover and request of `dhcp_build` (padding to 300 BOOTP octets, lengths, checksums, a zero UDP checksum sent as all ones); the refusal by `dhcp_frame_ok` of short, malformed and fragmented frames; `dhcp_parse` on a good reply, on replies to another transaction or hardware address, and on truncated or hostile options; `dhcp_lease_usable`; `dhcp_sane_lease`; and the renewal and rebinding times of `dhcp_boundaries`.
* `dhcpc_hosttest.c` includes the DHCP client, `utils/dhcpc.c`, and links `dhcpmsg.c` and `ipcheck.c`; its files go to a private directory under `/tmp`, its ioctls and standard descriptors to models, and its waits to a modelled clock. Rows check failed address removals, at expiry too; a first lease applied when cleanup fails, when its claim cannot be recorded, and when the interface already had the address; the classful mask of a lease without one; overlapping resolver writers; unreadable and absent claims; a reply wait that lasts to its deadline; a rebinding request sent again at half of what is left; standard descriptors that cannot be redirected; and the claim of an adopted address. `netutil_mutate.sh` proves it.
* `netcfg_hosttest.c` runs the `/etc/network/interfaces` reader, `utils/netcfg.c` with `utils/ipcheck.c`, over files written in its fixture directory. Rows read DHCP and static stanzas, several interfaces, one named twice, the selection with and without `-a`, and inet6 stanzas stepped over; refuse an unknown method, a value that is not an address, an overlong line, too many interfaces and a missing file; check names against their field; and check the refusals of `netcfg_check_static`: a missing address or netmask, a netmask that is not a run of ones or leaves no host, the subnet's own addresses, and a gateway off the subnet, on this machine, multicast, loopback or on network zero.
* `netcfg_io_hosttest.c` includes `utils/netcfg.c` with `fopen`, `fgets`, `ferror` and `fseek` replaced by a stream model over two complete stanzas. After an ordinary two-pass read, a read error after the first stanza in either pass and a failed seek between the passes must each make `netcfg_read` refuse the whole file. `netutil_mutate.sh` proves it.
* `netup_hosttest.c` includes `utils/netup.c` and links `netcfg.c` and `ipcheck.c`, with `fopen`, `ferror`, `kill`, `socket`, `fork` and `waitpid` modelled, so no client is started. `dhcp_holder` must take an absent claim or a dead holder as free and an unreadable, unread, empty or live claim as busy, and `apply_static` must open no socket while the claim is unreadable. `run_dhcp` must report a client that reached the background as success, and one that exited or was killed first by its status or its signal. `netutil_mutate.sh` proves it.
* `resolv_hosttest.c` includes the stub resolver, `utils/resolv.c`, with its socket calls and clock replaced by a model of one connected UDP socket that discards datagrams from any other peer. `dns_query` must send on one IPv4 socket connected to the nameserver's DNS port, take the nameserver's answer, and close the socket once, so that an answer or NXDOMAIN from a foreign address or port cannot decide the name; a failed connect fails the query without sending. The kernel's UDP delivery is left to the guest probes. `userland_mutate.sh` proves it.
* `ncport_hosttest.c` includes `utils/nc.c` and calls its `parse_port` directly. Ports 1, 80 and 65535 are taken; 0, 65536, 65616 (which a cut to 16 bits would make 80), a trailing character, an empty operand, a sign and a leading space are refused, and a twenty-digit operand, run last, is refused without overflow. `netutil_mutate.sh` proves it.
* `ncwrite_hosttest.c` runs the `main` of `utils/nc.c` with `read`, `write`, `socket`, `connect` and `close` modelled: 1024 bytes of input and 1024 of reply, through writes of at most seven bytes. Both outputs must receive every byte, also when one write is interrupted with `EINTR`; a write that returns zero or fails with `EIO` on either output must stop the transfer with status 1. `account_mutate.sh` proves it.
* `httpd_hosttest.c` runs the `main` of the status server, `utils/httpd.c`, over modelled calls: `accept` gives one connection, `recv` one request, `send` keeps the page, and `getsockname` answers with the address and port a row chooses. The page must name the client and the address and port the connection reached, or 0.0.0.0 and the bound port when `getsockname` fails. Port operands of 0, 65536, `80x`, an empty one and twenty digits are refused with the usage line and status 2. `netutil_mutate.sh` proves it.

### Boot, disk tools, accounts and the shell

* `bootctl_hosttest.c` runs `utils/bootslot.c`, the library `bootctl` drives, over FAT32 images that `mkfatfixture.c`, written apart from it, builds in the test's fixture directory, through a write callback that can drop a sector while reporting success, stop after a chosen write, or tear a sector. Rows check that a well-formed image opens and a kernel installs with the fallback saved and a one-boot trial armed; the commit, the cancel and the copy into the fallback; each malformed volume refused with its own diagnostic; kernel validation; the menu slot written whole and read back; volumes of 4 KiB clusters; unknown variables kept by the environment writers; and a dropped, cut or torn write, which fails the install with the fallback still saved and the trial not armed.
* `bootslot_hosttest.c` includes `utils/bootslot.c` over a sector model that begins after FAT discovery. Rows check that `bootslot_validate_kernel` takes an x86-64 kernel with the a.out kludge and refuses one without, and refuses a multiboot2 header that is absent, has an unknown tag or one past its end, has an address tag but no entry tag, or loads or enters outside the file, the load or the first 8192 bytes; and the disk policy an image declares, of which only read-write is taken. Other rows check a chain's cluster count past 4 GiB, an install refused before any write when the fallback is unverified, and a fallback copy whose payload write is dropped, whose read fails, or whose final header write is dropped or torn. `bootslot_mutate.sh` proves it.
* `bootverb_hosttest.c` runs `bootverb_parse` and `bootverb_known` of `utils/bootverb.c`, the command line of `bootctl`. Rows check each of the seven verbs, `status`, `commit`, `cancel`, `kernel`, `config`, `trial` and `env`, with the operands it takes and the operand it returns, `env` with a key alone or a key and a value; and refuse a missing or surplus operand, the old spellings `--commit` and `--where` and a bare kernel path, an empty word, a prefix, a suffix and capitals. Other rows check that a refusal clears the returned operand and that every verb the parser takes is one `bootverb_known` knows.
* `grubslot_hosttest.c` runs `utils/grubslot.c`, which lays a boot loader window out as an entry sector and two tails of the GRUB core and installs a new core into the tail not in use. Rows check the layout of the post-MBR gap, LBA 1 through 2047, with tails of 1023 sectors at LBA 2 and 1025, and of a BIOS boot partition at LBA 34 through 2047, with tails of 1006 at 35 and 1041; windows refused over sector 0, too small or past 32 bits; which tail an entry sector points to; the blocklist patch, where a core of 1007 sectors fits the partition's tail and one of 1008 does not; installs that leave the old tail and sector 0 alone; and core images refused, with nothing written. `grubwindow_mutate.sh` proves it.
* `grubembed_hosttest.c` includes `tools/image/grubembed.c` and calls `bios_boot_partition`, its finder of the BIOS boot partition the GRUB core is written over, on GUID tables the test builds with their checksums in a temporary file. Rows take a partition over sectors 34 to 2047, as this project's disks have it, and refuse one that starts at sector 2, over its own entry array, one that starts before the first usable sector, and one that ends past the last.
* `gptdisk_hosttest.c` includes `utils/gptdisk.c` with its `write` counted, over an image file of 2048 sectors whose GUID table the test builds byte by byte, made 4096 sectors long as an image written to a larger disk is. Rows check the table read from its primary, rewritten with its backup at the disk's end and the protective MBR's boot code kept, read from that backup alone and grown into the space; a partition under the backup refused; and the disk GUID's text form both ways. A rewrite stopped after each of its writes, from either copy, must leave a copy that reads, and a primary of 136-byte entries, which the kernel refuses, leaves the table to be read from its backup.
* `diskctl_hosttest.c` includes `utils/diskctl.c`, with `utils/gptdisk.c`, and runs `diskctl esp` on an image file whose MBR entry 1 has type 0x0C, with the kernel's table reread answered by the test. While the reread is refused with `EBUSY` the command writes type 0xEF and fails; run again with the type already on the disk it must have the table read again and succeed, as must a third run; and an entry of another type is refused, unread and unchanged.
* `growroot_hosttest.c` includes `utils/growroot.c`, with `utils/gptdisk.c`, and answers its device calls from memory and its `/proc` files from temporary streams. Rows check that a valid MBR is written once from the sector the writer checked, with only the root's length and ending CHS bytes changed, and that a failed or short read, a changed disk or partition field, or a partition in the space to grow into stops it before any write. Three rows check that `gpt_limit` bounds a GUID table's root by the entry after it, or by the backup array when there is none, and stops at an entry that overlaps the growth. A run with `--measure` forks a child for each tool and checks the eight measurement lines against counters the children change. `growroot_mutate.sh` proves it.
* `sectorcopy_hosttest.c` runs `utils/sectorcopy.c`, the copy library of `reflash`, against a model stream and device. Rows check `sectorcopy_parse_u64` on decimal numbers up to the largest 64-bit value, refusing one past it, a sign, hexadecimal, white space and trailing text; `sectorcopy_bounds` at the ends of 64 bits and for an offset or length inside a sector; copies from a stream that hands out a byte at a time, ends early, has more than it declared, or fails, including on the read that shows it ended, each written to the device in whole sectors; an image of 2 MiB and 32 KiB written in exactly three writes of 1 MiB, 1 MiB and 32 KiB; and the progress lines, one at each step and one at the end.
* `sha256_hosttest.c` runs `utils/sha256.c`, the digest `reflash --verify` prints. Rows compare its digests of the empty message, the two vectors of FIPS 180-4, messages of 55, 56 and 64 bytes, where the padding adds one block or two, and a million `a` characters fed a thousand bytes at a time and again one byte at a time, with digests written in the test.
* `mkhash_hosttest.c` links musl's SHA-512 crypt, `vendor/musl/musl-1.2.5/src/crypt/crypt_sha512.c`, as the `krffs/mkhash.krffs.c` tool does, and checks `__crypt_sha512` against the two vectors of the SHA-crypt specification, one with `rounds=10000`, and one of the project's own, and that a setting that is not SHA-512 gives no hash.
* `pwauth_hosttest.c` runs the credential library `utils/pwauth.c` with musl's SHA-512 crypt, supplying `crypt`, `getspnam`, `getrandom` and an `fsync` that fails on a chosen call, and interposing `snprintf` and `getpid` to read the signal mask where the library blocks signals. * `pwauthfault_hosttest.c` includes `utils/pwauth.c` with system-call stand-ins that fail on demand.
