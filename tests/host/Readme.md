# Host tests

`tests/run host` compiles project code as native C programs and runs it under AddressSanitizer and UndefinedBehaviorSanitizer. The suite tests pure kernel logic, utility libraries, parsers, and hardware models without booting Rach2. Guest probes and QEMU tests remain responsible for system calls, privilege changes, devices, and complete subsystem behavior.

## Runner

[`tests/system/suites/host.sh`](../../tests/system/suites/host.sh) discovers every `tests/host/*_hosttest.c` file. It uses `${CC:-cc}` with C99, `-g -O1`, `-fsanitize=address,undefined`, and `-fno-sanitize-recover=all`. The include path contains the kernel, utility, KRFFS, and compatibility-header directories.

Each test declares separately compiled project sources in one or more `host-deps:` comment lines. A test whose rows take longer than the suite's sixty-second deadline declares its own in seconds on a `host-seconds:` line; the FAT32 test declares a hundred and fifty, and the exFAT test, whose matrix runs twelve sequences beside its cost rows, four hundred and fifty. The runner rejects a dependency line that was wrapped without repeating the prefix, checks that every named file exists, and passes those files to the compiler. A test that includes a project `.c` file directly to reach its `static` functions leaves `host-deps:` empty.

Tests that need additional compiler flags declare them on repeatable `host-cflags:` comment lines. The e2fsprogs alignment tests use these for their host configuration and the port's headers. They require the extracted e2fsprogs source and its generated headers; they do not build the port.

`krffs_fuse_hosttest.c` selects `fuse/fuse.h` through its `host-cflags:` include path. The header declares only the FUSE types and calls used by KRFFS; the test supplies dispatch and request identity. No FUSE headers, library or service need be installed. The test compiles the real mount entry point, allocator and callbacks, checks valid and malformed node rings, and covers writes past EOF, retained allocation slack, ownership sentinels and timestamp requests. `sh tests/host/krffs_fuse_mutate.sh` runs this test alone under ASan and UBSan, bypasses ring validation in a private source copy and requires rejection assertions to fail, then restores, touches, rebuilds and runs the source again. Its trap stops the test before restoring source. A fallback header with `#error` ensures the build selects the test stub. Logs, sources, binaries and checksums remain under `build/tests/krffs-fuse-proof.*`.

The runner stores binaries and logs under `/tmp/rach2_verify`. `exfat_hosttest.c` and `fat32_hosttest.c` build their fixtures there unless they are compiled with `FIXDIR` set to another directory, which `exfat_scan_mutate.sh` and `fat_barriers_mutate.sh` do, each with a directory of its own, so that two of them can run the same test at once. After the C tests it replays every committed fuzz corpus under [`tests/fuzz/corpus/`](../fuzz/Readme.md) through its harness, built with the same sanitizers and a standalone main. The project `deadline` tool (built by `make`) runs each binary in the foreground with a 60-second limit, or the one its `host-seconds:` line asks for, and kills the whole process group of one that hangs. Exit status 0 passes; a nonzero exit, sanitizer report, compile failure, or timeout fails. Tests may print diagnostics.

The host suite first runs the nineteen fixed cases of `tests/system/machine_measure_test.sh`: the check of a machine's booted slot and kernel, the drivers stopping on a refused machine, inbound cleanup, the load window and the pause between load sessions; its `--mutate` mode is run separately. The build prerequisites include `check-libc`. This ensures that musl's installed library and extracted SHA-512 crypt source exist before the password tests compile.

## Adding a test

Name the file `*_hosttest.c` and put repository-root paths on repeatable `host-deps:` lines:

```c
/**
 * Host test for foo.
 *
 * host-deps: rach2/sys/lib/foo.c rach2/sys/lib/bar.c
 */

#include "foo.h"

int main(void)
{
    return check_foo() ? 0 : 1;
}
```

Do not wrap a dependency onto an unmarked continuation line. Native tests may use host libc. A test that directly includes kernel source must avoid host headers that conflict with the kernel's type definitions. Return 0 only after every assertion passes, and a status from 1 to 255 otherwise: the status keeps the low eight bits of what `main` returns, so a count of failed checks returned whole reads as a pass at 256, and a test that returns its count clamps it at 255.

## Compatibility headers and fixtures

`compat/crypt.h`, `compat/shadow.h`, and `compat/sys/random.h` reproduce the musl declarations needed by `utils/pwauth.c`. The runner places this directory before the system include directories, so the tests receive the same declarations on hosts that lack those headers or declare the interfaces elsewhere. The test programs provide the corresponding symbols; guest builds never use these headers. `compat/devmodel.c` is a device with pending and durable writes for the FAT tests: reads see every write; `block_flush` is the barrier that makes the pending writes durable, or fails on the Nth call: the older half of the pending writes reach the medium, the rest stay pending, the driver is given the error and the device answers as before; a stop after the Nth write refuses every write and barrier after it; and a snapshot at a stop is the medium with none, each of the newest one to six, or all of the writes pending since the last barrier, each a state a drive that reorders pending writes can leave. The model is atomic per request and settles a failed barrier's older half only; a drive that persists part of a request, or some other subset, is outside it; `compat/blockmax_host.c` answers the same two calls for the tests that need no model.

[`mkfatfixture.c`](mkfatfixture.c) independently writes the FAT32 volumes used by `bootctl_hosttest.c` and `fat32_hosttest.c`, which compile it (the bootctl test on first use, the vfat test on every run). It builds valid and malformed layouts, including one-sector and eight-sector clusters, so `utils/bootslot.c` and the kernel's vfat driver are checked against a separate implementation of the format. Its `--vfs` volume has the shapes the driver must read: a fragmented root chain crossing a 4 KiB boundary, long names (one across that boundary, one with a surrogate pair, one with a bad checksum that must fall back to its lower-cased short name, one over a short name starting in 0x05), a deleted entry, a fragmented file, and a subdirectory whose `..` is the root with two damaged chains beside it; `--dir-loop` links that subdirectory to itself, `--active-second` turns mirroring off with the second FAT active and the first wrong, and `--unmasked` sets the reserved high bits of a chain's entries. The runner does not discover the fixture builder as a test. `mkfatfixture --check IMAGE [OFFSET-SECTORS] [--list]` walks a volume instead of building one, independently of the kernel's driver and of mtools: it validates the boot sector field by field, compares the two FATs where mirroring is on, walks every chain the directory tree reaches with one owner per cluster, and reports each fault under the name it found it by: a loop, a cross-link, a chain outside the data region, a chain shorter or longer than its size, a `..` that is not the parent, a duplicate name, orphan long-name entries, lost clusters, a wrong FSInfo, and a dirty flag in either place. `--list` prints every entry reached. The fixtures for it are `--lost-chain`, `--overlong-chain`, `--bad-dotdot`, `--dup-name`, `--fsinfo` and `--fsinfo-wrong`; `--junk` is the FSInfo volume with every free cluster full of bytes that would read as entries, for the writer's rows; the `--dirty` family carries the dirty flag over a clean volume, a chain two clusters past its size, orphan long-name entries, a mirror one entry behind and a cross-link, for the mount-time check.

[`mkexfatfixture.c`](mkexfatfixture.c) is the pair for exFAT, written from Microsoft's specification: a 16 MiB volume with 4 KiB clusters, both boot regions with their checksums, the bitmap and the recommended up-case table (its compressed bytes in `exfat_upcase.inc`, taken from a `newfs_exfat` volume; checksum e619d30d) chained through the FAT, a label, a GUID entry, and a tree with every shape a reader must take: a contiguous file with `NoFatChain`, a file chained through the FAT over clusters that are not adjacent, a file whose `ValidDataLength` is short of its `DataLength` with junk past it, an empty file, a name of four entries, a set with a vendor extension and a vendor allocation, a set whose file and stream entries straddle a sector, a set that crosses a cluster boundary, and a directory of two levels. `mkexfatfixture IMAGE --offset=SECTORS` builds the volume for a place on a larger medium, with `PartitionOffset` set to that sector, which is how the stick image's second partition is made. `mkexfatfixture --check IMAGE [OFFSET-SECTORS] [--list] [--dump]` walks a volume as `fsck_exfat` does: both boot regions, the system objects through the FAT, every set's checksum and name hash through the up-case table, every chain against the bitmap both ways, and it names every fault; `--dump` prints the boot fields, the system entries and the first file set as hex, which is how `dev-log/38-exfat/notes.md` records volumes other implementations wrote. The builder's checksums are its own, apart from the reader's, so a mutation in either is seen by the other.

## Tests

The runner discovers one native test program per `*_hosttest.c` file.

`hda_hosttest.c` models codec parameters, packed connections and the controller immediate-command interface. It runs the real enumeration, stream setup and proc formatter for twelve PCM rates, inherited and overridden capabilities, two-DAC intersections, long and short lists, ranges, invalid paths and retained reports. Renderer rows check silence and the sample sequence after an empty or partly filled 4096-frame period at 44100 Hz input and 32000 Hz output. `sh tests/host/hda_mutate.sh` runs this test alone under ASan and UBSan, compiles thirteen separate faults and requires named failures, then restores, touches and rebuilds each source. Its trap stops the child before restoring private copies. Logs, sources, binaries and checksums remain in the printed `build/tests/hda-proof.*` directory.

### Kernel foundations and memory

* `board_hosttest.c` checks power-controller profiles, PCI identities, PM bases, decode bits, SCI routing, sleep words, ACPI enable decisions, and the uninitialized board state.

The driver is included whole to reach its state.

* `ahci_hosttest.c` runs the AHCI driver against a model of a controller, reached through the register interface `ahci.c` now has (`struct ahci_io`). Each row drives the bring-up step it is about rather than the whole of `ahci_init`, because a row that ran all of it would pass whenever anything at all refused. The rows: a controller that resets and one whose reset never completes, firmware that answers the handoff and firmware that never does, a port with a disk, a port with nothing on the link, a port whose device is not a disk, a controller with no implemented port, the port engines starting, a command that completes, one that never completes (where the wait must poll and then give up), one that returns a fatal task-file status, and a command the disk policy refuses. * `ata_hosttest.c` runs the ATA driver against a model of a drive, reached through the port interface the driver now has (`struct ata_io`). * `ext2_hosttest.c` runs the ext2 driver over the buffer cache over volumes the host's `mke2fs` made from a tree it stages, with `debugfs` adding what a host tree cannot carry: device nodes in both encodings and a size past the kernel's offset. It checks probe order, stopping a failed card, continued probing of subsequent cards and drivers, retained initialization and boot-line refusal reasons, and calls with no interface bound. `sh tests/host/netconfig_mutate.sh` compiles this test and `netconf_hosttest.c` under ASan and UBSan in a private source tree. ### Boot and host utilities

* `rm_hosttest.c` runs the utility's command entry point on host files and directories. It injects an unlink denial for a symbolic link, both as an operand and as a child of a directory, and requires the link and its target's bytes to remain. It also checks ordinary file, link, and tree removal, dangling links, and missing input. `sh tests/host/rm_mutate.sh` compiles this test alone under ASan and UBSan, removes the directory check in a private source copy and requires target-preservation assertions to fail, then restores, touches, rebuilds and requires success. Its trap stops the test before restoring source. Sources, binaries, checksums and logs remain under `build/tests/rm-proof.*`. This test does not exercise kernel permissions, concurrent path replacement, or guest syscalls.

* `growroot_hosttest.c` includes the real grow program with device calls replaced by memory and proc files by temporary streams. Ten cases check one validated sector written without a reread, unchanged bytes outside the target length and CHS fields, failed and short reads, changed disk and partition fields, and newly occupied grow space. Those table cases stop at a simulated busy ioctl. A further run passes `--measure`, publishes the new partition and forks real children for all three tools. An exec substitute checks their arguments and changes shared counters by distinct amounts for each operation; device writes and table rereads change counters separately. Every printed edge must equal the independently expected clock, command and flush values. `sh tests/host/growroot_mutate.sh` freshly compiles each private phase: the old read order must fail the writer assertions, all-zero readings must fail the counter comparison, and sampling the read-only check before running it must fail attribution. The source is restored, rebuilt and tested after each mutation. The simulated tool operations prove attribution, not real e2fsprogs command counts; the QEMU row checks the real tools separately.

* `e2fsprogs_alignment_hosttest.c` and `e2fsprogs_alignment64_hosttest.c` include the port's `unix_io.c` with host configuration and I/O stubs, selecting `pread`/`pwrite` and `pread64`/`pwrite64` respectively. Both force an even caller address two bytes past a 512-byte boundary. They check whole-buffer transfers and bytes, 64 KiB aligned reads and writes, sector preservation for short and interior writes, and upstream retries, short counts, read zero fill, and errors through seek plus read or write. The cache, channel opening, guest libc, and kernel are outside these tests. `sh tests/host/e2fsprogs_alignment_mutate.sh` compiles and runs both tests with the patch, changes `BUFFER_ALIGNED` back to `IS_ALIGNED`, requires all fourteen misaligned rows in each test to fail, then restores the source and compiles and runs them again. A shell trap stops the test process before restoring the source on interruption. Each phase uses fresh binaries; the script preserves its logs and saved source in the temporary directory it prints.

* `bootslot_hosttest.c` checks load memory bounds and fallback copying over resolved files. It drops a payload write beyond the 8192-byte header prefix, fails a payload read and requires a subsequent install to reject each unverified fallback without writes. It also checks a successful retry, dropped or torn final header writes, and the disk policy a whole image names: the read-write banner is taken, the read-only banner is refused as a machine's kernel, and an image naming neither is refused. `sh tests/host/bootslot_mutate.sh` compiles the fixed source, moves header restoration before payload verification and requires the retry assertions to fail, removes the address bound and requires the overflow assertions to fail, then removes the read-only refusal and requires the policy assertion to fail. Each mutation uses a private source copy; the trap stops the test before restoring and touching that copy, and a fresh build must pass after each restoration. Logs, binaries and checksums remain under `build/tests/bootslot-proof.*`.
* `bootctl_hosttest.c` checks FAT32 discovery, kernel and fallback validation, candidate installation, environment and menu updates, cluster geometry, readback, and interrupted, dropped, or torn writes.
* `bootverb_hosttest.c` checks every `bootctl` verb, operand count, returned operand, rejection of the old spelling, and exact name matching.
* `grubslot_hosttest.c` checks the two GRUB core-image tails, blocklist validation and patching, alternating installation, slot clearing, and readback failure.
* `mkhash_hosttest.c` checks the vendored musl SHA-512 crypt against published vectors and rejects a malformed setting.
* `pwauth_hosttest.c` checks password comparison, salt-byte mapping, credential-file replacement, locking, flush failures, fork and exit cleanup, signal state, and terminal teardown.
`sh tests/host/account_mutate.sh` compiles the four tests below against private utility sources. Each fixed test must pass. * `pwauthfault_hosttest.c` checks complete lock-file validation, mode-read errors, nonterminal input, initial and resumed echo failures, and diagnostics and return values after failed lock and temporary-file removal.
* `accounttools_hosttest.c` checks physical sudoers lines, login name termination at EOF, and closure of descriptors through 1023 before identity changes.
* `initpolicy_hosttest.c` checks exact SSH policy lines, the SSH server's command line with and without root's password, OpenSSH's `sshd` by its absolute path with `-D`, `-e` and `PermitRootLogin` and Dropbear's with or without `-g`, each failed redirection, and preservation of init's console descriptors during network setup. * `sectorcopy_hosttest.c` checks decimal size parsing, 64-bit disk bounds, whole-sector streaming, short and long input, partial I/O, errors, and the 2048-sector write batches, exactly three of 1 MiB, 1 MiB and 32 KiB for a 2 MiB + 32 KiB image.
