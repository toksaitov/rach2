# Host tests

`tests/run host` compiles project code as native C programs and runs it under AddressSanitizer and UndefinedBehaviorSanitizer. The suite tests pure kernel logic, utility libraries, parsers, and hardware models without booting Rach2. Guest probes and QEMU tests remain responsible for system calls, privilege changes, devices, and complete subsystem behavior.

## Runner

[`tests/system/suites/host.sh`](../../tests/system/suites/host.sh) discovers every `tests/host/*_hosttest.c` file. It uses `${CC:-cc}` with C99, `-g -O1`, `-fsanitize=address,undefined`, and `-fno-sanitize-recover=all`. The include path contains the kernel, utility, KRFFS, and compatibility-header directories.

Each test declares separately compiled project sources in one or more `host-deps:` comment lines. A test whose rows take longer than the suite's sixty-second deadline declares its own in seconds on a `host-seconds:` line; the two FAT interruption matrices declare a hundred and fifty. The runner rejects a dependency line that was wrapped without repeating the prefix, checks that every named file exists, and passes those files to the compiler. A test that includes a project `.c` file directly to reach its `static` functions leaves `host-deps:` empty.

Tests that need additional compiler flags declare them on repeatable `host-cflags:` comment lines. The e2fsprogs alignment tests use these for their host configuration and the port's headers. They require the extracted e2fsprogs source and its generated headers; they do not build the port.

The runner stores binaries and logs under `/tmp/rach2_verify`. The project `deadline` tool (built by `make`) runs each binary in the foreground with a 60-second limit and kills the whole process group of one that hangs. Exit status 0 passes; a nonzero exit, sanitizer report, compile failure, or timeout fails. Tests may print diagnostics.

The host suite first runs `check-libc`. This ensures that musl's installed library and extracted SHA-512 crypt source exist before the password tests compile.

## Adding a test

Name the file `*_hosttest.c` and put repository-root paths on repeatable `host-deps:` lines:

```c
/**
 * Host test for foo.
 *
 * host-deps: rach2/sys/lib/foo.c rach2/sys/lib/bar.c
 */

#include "foo.h"

int main(void)
{
    return check_foo() ? 0 : 1;
}
```

Do not wrap a dependency onto an unmarked continuation line. Native tests may use host libc. A test that directly includes kernel source must avoid host headers that conflict with the kernel's type definitions. Return 0 only after every assertion passes.

## Compatibility headers and fixtures

`compat/crypt.h`, `compat/shadow.h`, and `compat/sys/random.h` reproduce the musl declarations needed by `utils/pwauth.c`. The runner places this directory before the system include directories, so the tests receive the same declarations on hosts that lack those headers or declare the interfaces elsewhere. The test programs provide the corresponding symbols; guest builds never use these headers. `compat/devmodel.c` is a device with pending and durable writes for the FAT tests: reads see every write; `block_flush` is the barrier that makes the pending writes durable, or fails the Nth time it is asked with the older half of them on the medium and the rest still pending, the driver told and the device still answering; a stop after the Nth write refuses every write and barrier after it; and a snapshot at a stop is the medium with none, each of the newest one to six, or all of the writes pending since the last barrier, each a state a drive that reorders pending writes can leave. The model is atomic per request and settles a failed barrier's older half only; a drive that persists part of a request, or some other subset, is outside it; `compat/blockmax_host.c` answers the same two calls for the tests that need no model.

[`mkfatfixture.c`](mkfatfixture.c) independently writes the FAT32 volumes used by `bootctl_hosttest.c` and `fat32_hosttest.c`, which compile it (the bootctl test on first use, the vfat test on every run). It builds valid and malformed layouts, including one-sector and eight-sector clusters, so `utils/bootslot.c` and the kernel's vfat driver are checked against a separate implementation of the format. Its `--vfs` volume has the shapes the driver must read: a fragmented root chain crossing a 4 KiB boundary, long names (one across that boundary, one with a surrogate pair, one with a bad checksum that must fall back to its lower-cased short name, one over a short name starting in 0x05), a deleted entry, a fragmented file, and a subdirectory whose `..` is the root with two damaged chains beside it; `--dir-loop` links that subdirectory to itself, `--active-second` turns mirroring off with the second FAT active and the first wrong, and `--unmasked` sets the reserved high bits of a chain's entries. The runner does not discover the fixture builder as a test. `mkfatfixture --check IMAGE [OFFSET-SECTORS] [--list]` walks a volume instead of building one, independently of the kernel's driver and of mtools: it validates the boot sector field by field, compares the two FATs where mirroring is on, walks every chain the directory tree reaches with one owner per cluster, and reports each fault under the name it found it by: a loop, a cross-link, a chain outside the data region, a chain shorter or longer than its size, a `..` that is not the parent, a duplicate name, orphan long-name entries, lost clusters, a wrong FSInfo, and a dirty flag in either place. `--list` prints every entry reached. The fixtures for it are `--lost-chain`, `--overlong-chain`, `--bad-dotdot`, `--dup-name`, `--fsinfo` and `--fsinfo-wrong`; `--junk` is the FSInfo volume with every free cluster full of bytes that would read as entries, for the writer's rows; the `--dirty` family carries the dirty flag over a clean volume, a chain two clusters past its size, orphan long-name entries, a mirror one entry behind and a cross-link, for the mount-time check.

[`mkexfatfixture.c`](mkexfatfixture.c) is the pair for exFAT, written from Microsoft's specification: a 16 MiB volume with 4 KiB clusters, both boot regions with their checksums, the bitmap and the recommended up-case table (its compressed bytes in `exfat_upcase.inc`, taken from a `newfs_exfat` volume; checksum e619d30d) chained through the FAT, a label, a GUID entry, and a tree with every shape a reader must take: a contiguous file with `NoFatChain`, a file chained through the FAT over clusters that are not adjacent, a file whose `ValidDataLength` is short of its `DataLength` with junk past it, an empty file, a name of four entries, a set with a vendor extension and a vendor allocation, a set whose file and stream entries straddle a sector, a set that crosses a cluster boundary, and a directory of two levels. `mkexfatfixture IMAGE --offset=SECTORS` builds the volume for a place on a larger medium, with `PartitionOffset` set to that sector, which is how the stick image's second partition is made. `mkexfatfixture --check IMAGE [OFFSET-SECTORS] [--list] [--dump]` walks a volume as `fsck_exfat` does: both boot regions, the system objects through the FAT, every set's checksum and name hash through the up-case table, every chain against the bitmap both ways, and it names every fault; `--dump` prints the boot fields, the system entries and the first file set as hex, which is how `dev-log/38-exfat/notes.md` records volumes other implementations wrote. The builder's checksums are its own, apart from the reader's, so a mutation in either is seen by the other.

## Tests

* `fat32_hosttest.c` runs the vfat driver over the buffer cache over `mkfatfixture`'s volumes. ### Network

* `arp_hosttest.c` checks ARP cache filtering, replacement and use order, counter wrap, mapping changes, request replies, and network-lock balance.
* `dhcpmsg_hosttest.c` checks DHCP discover and request construction, IPv4 and UDP validation, reply parsing, hostile options, lease validation, and renewal arithmetic.

* `rcvwnd_hosttest.c` checks TCP receive-window update thresholds, silly-window avoidance, 16-bit clamping, and invalid geometry.
* `oplmusic_hosttest.c` runs the Doom port's OPL music player over a MIDI file of two tracks built in memory, the shape Freedoom ships: the tempo on track 0 and the notes on track 1. * `e1000_hosttest.c` runs the Intel 82540EM driver against a register model. ### Boot and host utilities

* `e2fsprogs_alignment_hosttest.c` and `e2fsprogs_alignment64_hosttest.c` include the port's `unix_io.c` with host configuration and I/O stubs, selecting `pread`/`pwrite` and `pread64`/`pwrite64` respectively. Both force an even caller address two bytes past a 512-byte boundary. They check whole-buffer transfers and bytes, 64 KiB aligned reads and writes, sector preservation for short and interior writes, and upstream retries, short counts, read zero fill, and errors through seek plus read or write. The cache, channel opening, guest libc, and kernel are outside these tests. `sh tests/host/e2fsprogs_alignment_mutate.sh` compiles and runs both tests with the patch, changes `BUFFER_ALIGNED` back to `IS_ALIGNED`, requires all fourteen misaligned rows in each test to fail, then restores the source and compiles and runs them again. A shell trap stops the test process before restoring the source on interruption. Each phase uses fresh binaries; the script preserves its logs and saved source in the temporary directory it prints.

* `bootctl_hosttest.c` checks FAT32 discovery, kernel and fallback validation, candidate installation, environment and menu updates, cluster geometry, readback, and interrupted, dropped, or torn writes.
* `bootverb_hosttest.c` checks every `bootctl` verb, operand count, returned operand, rejection of the old spelling, and exact name matching.
* `grubslot_hosttest.c` checks the two GRUB core-image tails, blocklist validation and patching, alternating installation, slot clearing, and readback failure.
* `mkhash_hosttest.c` checks the vendored musl SHA-512 crypt against published vectors and rejects a malformed setting.
* `pwauth_hosttest.c` checks password comparison, salt-byte mapping, credential-file replacement, locking, flush failures, fork and exit cleanup, signal state, and terminal teardown.
* `pwauthatexit_hosttest.c` checks that a transaction fails and leaves no lock when the library cannot register both exit handlers.
* `sectorcopy_hosttest.c` checks decimal size parsing, 64-bit disk bounds, whole-sector streaming, short and long input, partial I/O, errors, and the 2048-sector write batches, exactly three of 1 MiB, 1 MiB and 32 KiB for a 2 MiB + 32 KiB image.
