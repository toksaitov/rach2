# Dropbear SSH for Rach2 (Phase 23 — the capstone)

A static **Dropbear 2022.83** SSH server linked against the ported musl
(`libc/install`). Phase 23, the Part II finale: a real OpenSSH client does

    ssh -i krffs/rach2_demo_ed25519 -p 2222 root@localhost

and lands in an interactive BusyBox `ash` shell over an SSH-driven pty.

## Build

    ./build_dropbear.sh

It verifies the pinned tarball (`dropbear-2022.83.tar.bz2`, sha256 gated),
extracts it, applies the curated `localoptions.h`, and configures against the
ported musl with the `muslgcc` wrapper (shared with busybox), bundled
libtomcrypt/libtommath, and `CROSS_COMPILE=i686-elf-`. It builds `dropbearmulti`
(the `dropbear` server + `dropbearkey`, MULTI=1 dispatching on `argv[1]`),
strips it, and stages it to `tests/dropbearmulti` (installed into the RAM disk as
`/dropbearmulti`). Run `libc/build_libc.sh` and `busybox/build_busybox.sh` first.

- **`--disable-harden` is REQUIRED.** With hardening on, configure adds `-Wl,-pie`
  and the link is a dynamic PIE (interpreter `/usr/lib/libc.so.1`) that Rach2's
  ELF loader cannot relocate or run. With it off the binary is static non-PIE i686.
- `localoptions.h` curates the crypto: curve25519 + ECDH, chacha20-poly1305,
  aes128/256-ctr, hmac-sha256, ed25519, RSA (signkey.c needs
  `DROPBEAR_SIGNKEY_RSA`), pubkey + password auth, MOTD off.
- Disabled: zlib, syslog, utmp/wtmp/lastlog, loginrec, pututline (none exist here).

## Run

From the kernel debug shell, with the RAM disk attached:

    exec dropbearmulti dropbear -F -R -p 22

- **`-cpu max` (the default in `run*.sh`) is mandatory.** Dropbear seeds its
  CSPRNG from the kernel's trusted entropy (Phase 20); the default QEMU i386 CPU
  exposes no RDRAND/RDSEED, so `getrandom`/`/dev/urandom` fail closed and key
  generation cannot run.
- **`-R`** auto-generates the host key on first connection into `/etc/dropbear/`
  (staged as an empty dir by `krffs/stagetree.krffs.c`).
- **`-F`** keeps it in the foreground. **Do NOT pass `-E`** — it is invalid
  without syslog (stderr is already the default log sink).

The test harness boots qemu with `-cpu max -netdev
user,hostfwd=tcp::2222-:22 -device rtl8139,netdev=net0`, starts the server, then
runs a host `ssh` against `localhost:2222`.

## Login provisioning

`krffs/build_test_ramdisk.sh` generates a demo keypair
(`krffs/rach2_demo_ed25519`, git-ignored) if no `authorized_keys` is present and
`krffs/stagetree.krffs.c` stages the public half into `/root/.ssh/authorized_keys`
(0600, under `/root` 0755 and `/root/.ssh` 0700 so dropbear's strict permission
check accepts it). `/etc/passwd` is `root:x:0:0:root:/root:/sh`; `/etc/shells`
lists `/sh` so dropbear's `getusershell()` shell check passes; `/sh` is a flat-root
copy of busybox (invoked as `sh` it runs `ash`).

## Kernel gaps this integration surfaced (and how they were closed)

Letting the real binary be the judge exposed, in order:

- **`copy_sockaddr_to_user` wrote `sin_family` big-endian** so `getpeername`/
  `accept` reported family `0x0200`; dropbear rejected it ("Unrecognized address
  family"). Fixed to host byte order (only `sin_port`/`sin_addr` are network order).
- **`fsync`/`fdatasync` were unimplemented** (`-ENOSYS`); dropbear's host-key write
  (open→write→fsync→rename) treats any fsync error as fatal. KRFFS is RAM, so they
  are validating no-ops.
- **`link` was unimplemented.** Dropbear moves the key with `link(tmp, final)` and
  falls back to a direct write on `EPERM`/`EACCES`. KRFFS has no hard links, so
  `link`/`linkat` return `-EPERM` (the POSIX errno for "filesystem does not support
  hard links") — taking dropbear's fallback.
- **`seteuid`/`setegid`/`setresuid` were unimplemented.** Dropbear drops to the
  user's euid to read `authorized_keys`, then restores root. The single-root
  identity policy: id 0 or `(id_t)-1` succeeds, anything else is `-EPERM` (never a
  silent fake privilege drop). Covers `setre{u,g}id`/`setres{u,g}id`, 16- and 32-bit.
- **`chmod`/`chown` were unimplemented.** Dropbear chmod/chowns the session pty to
  root before exec'ing the shell. `chmod` updates a KRFFS file's perm bits (a
  synthetic /dev,/proc node is a no-op); `chown` accepts only root (0/-1), else
  `-EPERM`. Covers the `f*`/`*at`/`l*` variants.

## Known limits

- Dropbear logs "**Failed to disconnect from controlling tty**" once per pty
  session — `/dev/tty` maps to the console regardless of the caller's real
  controlling terminal, so it still opens after `setsid()`. It is a non-fatal
  warning; the session is fully interactive.
- The host key is regenerated by the first connection after each boot (the RAM
  disk does not persist); subsequent connections reuse it for the boot's lifetime.
- `id` is not compiled into the busybox config, so it reports "applet not found";
  `ls`/`cat`/`ps`/`pwd`/`whoami`/etc. work.
