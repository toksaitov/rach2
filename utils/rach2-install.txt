RACH2-INSTALL(8)

NAME
     rach2-install - install this system onto a disk, or update an installed one

SYNOPSIS
     rach2-install [--source DIR]
     rach2-install --update IMAGE DISK

DESCRIPTION
     rach2-install writes Rach2 onto a disk of the machine it is running on. It
     runs from the recovery system booted off the install stick, which carries
     a whole disk image and a manifest naming that image's name, length and
     SHA-256.

     The stick is found by the manifest on it rather than by a position, so the
     machine may have any number of disks. --source DIR takes the image and its
     manifest from a directory that is already mounted, which is how the tests
     drive it without a stick.

     Every question is asked before anything is written, and the last of them
     is the confirmation, so a person who changes their mind has not left a
     disk half written. Since nothing is at stake until then, no answer ends
     the run: an answer that will not do is met with what is wrong with it and
     the same question again. The questions, in order:

     which disk        A disk is offered when it is fixed, nothing is mounted
                       from it, its sector is 512 bytes, it is not the stick
                       this is running from, and it is at least as large as the
                       image. The offered disks are numbered; the disks passed
                       over are listed after them, each with its reason. The
                       answer is a number from the list or the disk's own node,
                       /dev/diskN.

     root's password   Typed twice, with the terminal's echo off. An empty
                       password and two that differ are each said and asked
                       again.

     the first account The name must begin with a lowercase letter and hold
                       only letters, digits, hyphen and underscore, at most 32
                       characters, and it may not be root. A name that breaks
                       one of those is told which one.

     its password      Twice, as root's.

     its keys          The keys this machine can find are listed first, from
                       the stick and from the recovery system's own root, and
                       the answer is one of their numbers, a path to any other
                       file, or nothing for no keys. A path that is not a file
                       is asked again rather than ending the run. What is given
                       is copied into the account's ~/.ssh/authorized_keys.

     the root's size   Whether to grow the root into the whole disk. The
                       default is yes; no leaves the root the size the image
                       has.

     the confirmation  Everything that was answered is shown together: the
                       disk and what it is, the account, the keys, and whether
                       the root will be grown. The disk's own name must then be
                       typed back. The word stop stops without writing;
                       anything else is said to be wrong and asked again, so a
                       typo does not throw away the answers above it.

     The four files are archived on the recovery partition as well, the
     passwords as the hashes they are, so that an update of a root that no
     longer reads still has the machine's accounts.

     Then, in this order: the image on the stick is read and its SHA-256
     compared with the manifest, so a damaged stick is found before anything is
     destroyed; the image is written to the disk with reflash -p, which says
     how far it has got every sixteen mebibytes; the same range is read back
     and hashed, and what reached the disk must be the image; the kernel is
     asked to read the disk's new table; the accounts, /etc/passwd, /etc/group
     and /etc/shadow, are written whole into the ext2 root the image carries,
     each to a name of its own and renamed into place; the account's home is
     made and its keys placed; /etc/rach2/sshd.conf is written with
     root-password-login yes, which is what makes init start the SSH server
     without dropbear's -g; and the root is grown into the free space after it
     when that was asked for.

     The demonstration accounts and keys the image carries are removed from the
     installed root. The KRFFS root beside it and the recovery partition keep
     theirs, since they are the way back into a machine whose new root will not
     come up.

     --update IMAGE DISK writes a root file system image into the root
     partition of a machine that is already installed, without touching its
     table. The disk must be one this system installed: its first partition
     must be a boot partition bootctl can read and the root it replaces must
     carry /etc/rach2. The account files, the SSH policy, the server's host
     keys and the accounts' own keys, root's included and their absence with
     them, are copied off the root first and written back after the write, so a
     password changed after the install is still the machine's password. A
     root that does not read is updated from the archive on the recovery
     partition instead, and the new root goes into the last ext2 partition
     of the table; where both read and disagree, each file that differs is
     named and the root's copy is kept. The archive is written from what was
     kept before the root is written, marked as an update in progress, and
     written again without the mark after the accounts are back, each time
     whole or not at all; an update that stopped between the two leaves the
     image's accounts on the root and the mark on the archive, and the next
     update takes the archive. The recovery partition is mounted with the
     archive readable by root alone. The image's home directories and the
     keys in them are removed whatever was kept; an account whose home was
     not kept gets an empty one.

     The image is judged before the root it replaces is destroyed: its length
     must be a whole number of sectors and must fit the partition, its first
     bytes must be an ext2 file system, and its SHA-256 must match IMAGE.sha256
     when one is there. The saved boot entry is moved to the fallback before
     the write and the new root is armed for one trial boot after it, so a root
     that does not come up, or a write cut off by a power cut, leaves a machine
     that boots the system it had.

EXIT STATUS
     0 when the disk carries the system and, for an update, when the new root
     is on the disk and armed. Anything else is a failure with the reason on
     standard error; nothing is written after a failure that happened before
     the write.

EXAMPLES
     Boot the install stick, log in at the console as root, and run:

           rach2-install

     Update an installed machine from its own recovery entry, with the new root
     file system on the stick:

           mount -t exfat /dev/disk1p2 /mnt
           rach2-install --update /mnt/rach2-root.ext2 /dev/disk0
