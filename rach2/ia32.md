# The i386 interface of the x86-64 kernel

This file lists what the x86-64 kernel must give an i386 program to run it as Linux's x86-64 kernel does: every system call of the i386 table, every structure whose layout differs between the two ABIs, and every ioctl family Rach2 answers, each with the task of milestone 79 that owns it and the test that proves it. The calls are the rows of Linux 6.12's `arch/x86/entry/syscalls/syscall_32.tbl`, compared with its `syscall_64.tbl`; the conversions inside native handlers and the ioctl handlers were read in Linux 6.18.54's source, the one `vendor/gnu/downloads/` keeps; the sizes were measured by compiling 6.18.54's UAPI headers, or the structures Linux defines inside the kernel, with `gcc -m32` and `gcc -m64`. The plan behind the list is [dev-log/79-ia32/plan.md](../dev-log/79-ia32/plan.md).

## Structures

Each structure below has a different size or different offsets in the two ABIs, so the calls and commands that pass it are translated. Bytes are its size on i386 and on x86-64; for `siginfo` and `sigevent` the sizes agree and the members move. Linux's name is its compat type. Structures that are the same in both, and so need no row, include `user_desc`, `epoll_event` (packed on x86-64), `__old_kernel_stat`, `utsname` and its old forms, `sembuf`, `clone_args`, `statx`, `loop_info64`, the 64-bit `__kernel_timespec` and every structure of the DRM, virtio-gpu, dma-buf, sync-file and udmabuf interfaces that the ioctl list does not name.

## ioctl families

`compat_sys_ioctl` (79-6b) answers the commands every descriptor shares and passes the rest to the family's compat handler. A command whose argument has one layout in both ABIs passes through with its pointer zero-extended; one that differs is translated, or fails with ENOTTY where Linux has no translation. A DRM command whose encoded size is smaller than the kernel's, as with `drm_mode_obj_get_properties`, is taken as Linux's `drm_ioctl` takes it: the kernel copies the bytes the command names and zeroes the rest.

## Calls

Rach2's state of each call is the compat column of [syscalls.md](syscalls.md), which `make syscalls` writes from the compat table, `rach2/sys/arch/x86_64/ia32_systab.c`; this list does not repeat it, so the two cannot disagree. The Kind column says what that table must hold for the call:

* `equal`: the arguments and structures have one layout in both ABIs, and the row points at the x86-64 kernel's own handler, which gets each argument zero-extended from its 32-bit register. Linux's x86-64 table names the same function.
* `translated`: the call needs code of its own on the x86-64 kernel. Linux's entry is a `compat_sys_` function, an i386-only function (`sys_ia32_pread64`, `sys_clock_gettime32`, `sys_setuid16`, `sys_old_mmap`) that Linux's x86-64 kernel builds for its i386 table alone, or the native function, whose code converts a structure when `in_compat_syscall()` is true, as the Note says. Linux runs each through a wrapper named `__ia32_` and the entry's name.
* `absent`: Rach2 has the call on neither kernel. Its compat row stays empty and returns ENOSYS, as the native call does; a task that adds the call to the native tables adds its compat row and changes its line here.
* `none`: Linux has no handler either; the number returns ENOSYS on both kernels. The numbers 222, 223, 251, 285, 387 to 392 and 415 have no row in Linux's table and return ENOSYS too.

A call that Rach2 has on neither kernel today but that a task of the graphics stack adds is listed by its kind, with the adding task in its Note. The calls 76-19 adds are owned here by 79-6a (`process_vm_readv` and `process_vm_writev`) and 79-7b (`rseq` and `get_mempolicy`).

The Owner is the task whose code makes the row behave as Linux's. 79-1a writes every row of `ia32_systab.c`, pointing an `equal` row at the native handler and a `translated` row at its owner's file, which returns ENOSYS until that task; afterwards a row changes only in its owner.

The Test names the tests that make the call from i386 code. A probe of `tests/` or a program of `tests/musl/` is its i686 build, run on the x86-64 kernel under 79-8a's `RACH2_KERNEL=ia32` profile by 79-8c; the default suite's programs come first. A probe named with `(new row)` gets a row for the call from the row's owner, built for i686 alone where the call is i386's alone, as `tests/probe.h` says. `wow64probe`, an x86-64 program that makes its calls through `int $0x80`, is 79-1a's probe, `futexvprobe` and `ldtprobe` are 79-1b's and 79-3's, `mixprobe` and `limitsprobe` 79-8c's and 76-19's, and an `ia32_*_hosttest` the owner's host test of the row's structures against Linux 6.12's i386 layout. For an `absent` or `none` row the test is `syscalls.md`, whose compat column shows the row empty and which `tests/run style` checks. A musl program reaches a row only where musl 1.2.5 makes that call on i386: its uid functions use the `32` calls, `stat` and `fstat` use `statx`, its socket functions the direct calls 359 to 373, its SysV IPC the `ipc` call, and its clocks are read by the vDSO or the `_time64` calls, with the old calls as the fallback on ENOSYS, while its calls that set a time or sleep use the old calls when the value fits in 32 bits and the `_time64` calls otherwise.
