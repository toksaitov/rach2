# The kernel command line

This page lists the words the Rach2 kernel reads from its command line, which the loader passes: QEMU's `-append`, or the `multiboot` and `multiboot2` lines of a GRUB menu. [The kernel's Readme](Readme.md) describes what the boot does with the root and the first program.

The line is a list of words separated by spaces, tabs and the other bytes Linux's `isspace` takes, split as Linux's `next_arg` splits them (`sys/cmdline.c`): a space inside double quotes does not end a word, and the quotes around a word or a value are dropped, so `maxcpus="4"` is `maxcpus=4` and `acpi_osi="Windows 2015"` is one word. The kernel reads no word after a bare `--`, as Linux's `parse_args` stops there. A flag matches a whole word, so `rach2.rescue` does not match `xrach2.rescue`. Names are compared as Linux's `parameq` compares them, with `-` and `_` alike, so `intel-iommu=off` is `intel_iommu=off`. A flag that Linux takes as an early parameter, `noapic`, `nox2apic` and `nointremap`, matches with any value too, so `noapic=1` is `noapic`; one that Linux's `obsolete_checksetup` matches by its first bytes, `nomodeset`, `nowatchdog` and `nosoftlockup`, matches any word that begins with it, so `nomodeset=1` and `nowatchdogs` match too. A `key=value` option is read from its first occurrence, but for `ia32_emulation=` and `maxcpus=`, each of whose occurrences is read in turn, as Linux runs an early parameter once for each; `rach2.ifaddr` may be given once for each interface, and a second `rach2.ip` or `rach2.gateway` makes the network refuse both. The kernel keeps a line of up to 510 bytes. A longer one is cut before the word the limit falls in, so that no word is kept in part, and the words past the cut are not read; the boot logs `boot: command line cut: kept K of N bytes`, where N is the length the boot record has, written `511 or more` when the record cut the loader's line at its own limit (`BOOT_CMDLINE_MAX`, `sys/boot.h`). An installed machine's GRUB line with `rach2.root=PARTUUID=...`, `rach2.ifaddr` and the network options can reach this limit. A word the kernel does not read is ignored, as `rach2.disk=ahci`, which `run.sh` adds with `DISKBUS=ahci`, is.

| Option | Effect |
| --- | --- |
| `rach2.rescue`, `init=rescue` | Start the debug shell in place of `/sbin/init` ([run.Readme.md](run.Readme.md)). |
| `rach2.root=ram` | Mount the first boot module in place: the default. |
| `rach2.fsdisk`, `rach2.root=disk` | Mount the KRFFS partition among the first four entries of the boot disk's table, through the page cache. |
| `rach2.root=ext2` | Mount the first ext2 partition among the first four entries of the boot disk's table, through the buffer cache. |
| `rach2.root=SPEC` | Mount the one partition, on any disk, that `SPEC` matches: `PARTUUID=`, `MBRID=`, `GPTID=`, `UUID=`, `LABEL=` or `/dev/diskNpM`, as [disk(7)](../man/man7/disk.7) defines them. |
| `rach2.rootimage=SPEC:/PATH` | Mount the ext2 partition that `SPEC` matches, by the forms of `rach2.root=SPEC`, attach its file `PATH` to a loop device, writable, and mount the ext2 file system in the file as the root, in place of any `rach2.root=`. The partition stays mounted, entered from the new root as `/data`, and a shutdown writes it out after the root. A boot whose image does not mount restarts after ten seconds, so that the boot loader takes its saved default, unless `rach2.rescue` is given; `bootctl rootimage` writes the option on a one-boot menu entry ([bootctl(8)](../man/man8/bootctl.8)). |
| `rach2.rootfstype=TYPE` | With `rach2.root=SPEC`, mount it as `krffs` or `ext2`; another value is refused. Without it the kernel tries KRFFS, then ext2. |
| `rach2.fswindow` | Mount the boot module through the page cache's window, as a disk root is mounted. |
| `rach2.boot=SPEC` | Name the boot partition, which must be entry 1 of an MBR or a GUID table, by the forms of `rach2.root=SPEC`. Without it the boot disk is the root's, when the root is named by identity, and disk 0 otherwise. |
| `rach2.audio.loopback` | Feed capture from the clipped playback mix before the hardware master volume, for audio loopback checks. |
| `rach2.nodisk`, `rach2.nousb`, `rach2.nonet`, `rach2.noaudio`, `rach2.nomouse` | Skip the probe of the disks, the USB controllers, the network cards, the sound cards or the PS/2 mouse. |
| `rach2.ahcipoll`, `rach2.nvmepoll` | Keep the AHCI or the NVMe disks polled, with no interrupts and no request queue. |
| `rach2.atapio` | Move ATA transfers through the data port and not through the controller's bus master. |
| `rach2.diskdiag` | Probe the disks once the root is mounted, when the boot has not, and log whether one answered; the whole-disk nodes are published either way ([disk(7)](../man/man7/disk.7)). |
| `rach2.fsck` | Read by the recovery image's `init`, not by the kernel: run `e2fsck -p` on every ext2 partition first. The kernel reads it only to keep its records on the screen while that runs. |
| `rach2.console=term` | Read by `init-login` and `init-metal`, not by the kernel: run the console's login inside `term` on the whole framebuffer, and on the kernel console when the screen has none or `term` fails ([init(8)](../man/man8/init.8)). The sealed disk's menu carries it; no test image does, so the machine cases keep their login on COM1. |
| `rach2.ip=A.B.C.D/PREFIX`, `rach2.ip=none`, `rach2.gateway=A.B.C.D`, `rach2.ifaddr=MAC,ADDR/PREFIX[,GATEWAY]` | The interfaces' addresses ([the network Readme](sys/network/Readme.md)). Without them the first interface takes QEMU's user-network defaults. |
| `netconsole=[+][r][src-port]@[src-ip]/[dev],[tgt-port]@<tgt-ip>/[tgt-macaddr]` | Send the log, each record as one UDP datagram, to each target, several separated by `;`, as Linux's netconsole does; of several `netconsole=`, the last ([netconsole(4)](../man/man4/netconsole.4)). |
| `rach2.netconsole` | Broadcast the log in Ethernet frames once a card is up ([netconsole(4)](../man/man4/netconsole.4)). |
| `netpoll.carrier_timeout=SECONDS` | As Linux's module parameter, read once early in every boot, whether or not netconsole starts, by `kstrtouint` with base 0, the last valid occurrence counting, and each refused value and bare key logged as `netconsole: refused:` in the line's order, as Linux's `parse_args` does: the longest netconsole's targets and frames wait at their start for the card's carrier, 4 seconds by default ([netconsole(4)](../man/man4/netconsole.4)). |
| `ramoops.mem_address=`, `ramoops.mem_size=`, `ramoops.record_size=`, `ramoops.console_size=`, `ramoops.ftrace_size=`, `ramoops.pmsg_size=`, `ramoops.mem_type=`, `ramoops.ecc=` | As Linux's module parameters: keep a region of RAM across a warm reset, taken from the allocator at boot, into which a panic writes the end of the log and the console every record; the next boot shows them under `/sys/fs/pstore` ([pstore(5)](../man/man5/pstore.5)). |
| `rach2.itco.arm` | Start the Intel TCO watchdog at boot and feed it from the kernel thread `watchdogd`, which the tick wakes, until a program opens `/dev/watchdog`, so that a kernel stopped by a panic or a hang is reset by the chipset ([watchdog(4)](../man/man4/watchdog.4)). |
| `iTCO_wdt.heartbeat=`, `iTCO_wdt.nowayout=`, `iTCO_wdt.turn_SMI_watchdog_clear_off=`, `watchdog.handle_boot_enabled=`, `watchdog.open_timeout=` | As Linux's module parameters, the last valid occurrence counting, a bare boolean true and each value refused, a bare number among them, logged: the TCO watchdog's timeout at boot, a stop refused once a program started it, the firmware's SMI at the first expiry turned off, and whether and how long the kernel feeds a watchdog running at boot ([watchdog(4)](../man/man4/watchdog.4)). |
| `rach2.loglevel=N` | Show records of level `N`, one digit, and more urgent on the screen, in place of `INFO` and more urgent during the boot and `CRIT` alone once init starts. |
| `consoleblank=N` | Blank the screen and turn its backlights off after `N` seconds without a key or a mouse move, 600 when it is not given and never for 0, as on Linux ([console(4)](../man/man4/console.4)). A value that is not a number of seconds is refused and logged. |
| `rach2.diag` | Print the boot's diagnostic report again before the first program, and wait for a key. |
| `rach2.apicdiag` | Print what the firmware left in the local APIC and the MSI capabilities of the xHCI and HDA controllers. |
| `nox2apic` | As on Linux: run the local APIC in xAPIC mode, never x2APIC mode, and leave `x2apic` out of `/proc/cpuinfo`; ignored where the firmware locked the APIC in x2APIC mode or left it there with an identity of 255 or more ([the PC platform](sys/arch/x86/Readme.md)). |
| `rach2.nomsi`, `noapic`, `maxcpus=N` | Take every interrupt through the 8259 pair; keep the 8259 pair and the 8254's tick where there is an I/O APIC, and remap no interrupt and keep the local APIC from x2APIC mode, as on Linux, but for a firmware's x2APIC mode that is locked or that a hypervisor allows, which is kept; start at most `N` processors, the boot processor counted, the last `maxcpus=` that gives a value setting `N`, and any `maxcpus=0` also being `noapic` as on Linux, each `N` read as Linux's `get_option` reads it, hexadecimal after `0x`, octal after a leading 0, a value with no digit as 0 and an empty one as none ([the PC platform](sys/arch/x86/Readme.md)). |
| `intel_iommu=off`, `nointremap`, `intremap=off`, `intremap=no_x2apic_optout` | As on Linux: give no device to a VT-d domain, leaving interrupt remapping on; or do not remap interrupts ([VT-d](sys/arch/x86/iommu/Readme.md)). Each `intel_iommu=` and `intremap=` may hold a list separated by commas, and every such token is read in the line's order, each item by its prefix, as Linux's `intel_iommu_setup` and `setup_irqremap` read them: of `intel_iommu=`, the last `off` or `on` decides; of `intremap=`, the last `off` or `on`, `nointremap` counting as `off`, so `intremap=off,on` and `nointremap intremap=on` leave remapping on. With translation and remapping both off, the units are read and none is programmed. `intremap=no_x2apic_optout` takes the x2APIC format where the DMAR table opts out of x2APIC mode. |
| `vfio_iommu_type1.allow_unsafe_interrupts` | As Linux's bool module parameter, the bare word true and a value read as `ia32_emulation=` reads one, the last that gives a boolean counting: let a VFIO container take its IOMMU on a host whose interrupts are not remapped, where a device given to a program could raise any interrupt by a message ([VFIO](sys/vfio/Readme.md)). Without it, `VFIO_SET_IOMMU` is `EPERM` there. |
| `ia32_emulation=BOOL` | On the x86-64 kernel, as on Linux 6.7 and later: off (a value that begins with `n`, `f` or `0`, or `off`) runs no i386 program and no i386 call, so that an i386 program's exec fails with `ENOEXEC` and `int $0x80` raises `SIGSEGV`; on (`y`, `t`, `1` or `on`) is the default. Each occurrence is read, as Linux reads it, and the last one with such a value wins. The kernel built with `IA32=0`, which has no i386 ABI, ignores it ([ia32(7)](../man/man7/ia32.7)). |
| `nomodeset`, `bochs.modeset=N`, `virtio_gpu.modeset=N`, `i915.modeset=N` | As on Linux: `nomodeset` keeps the native display drivers off, bochs ([bochs(4)](../man/man4/bochs.4)), virtio-gpu ([virtio-gpu(4)](../man/man4/virtio-gpu.4)) and i915 ([i915(4)](../man/man4/i915.4)), and leaves the screen to the loader's framebuffer ([fbdrm(4)](../man/man4/fbdrm.4)). Each driver's `modeset` is Linux's int module parameter, -1 by default, read by `kstrtoint` with base 0, the last occurrence whose value is an int counting and a bare word or any other value ignored: 0 keeps the driver off, -1 leaves it to `nomodeset`, and any other value binds it under `nomodeset` too. |
| `rach2.i915` | Bind the Intel graphics driver to a Haswell GT2 chip, the HD 4400 among them, and register its DRM device, which serves Mesa's Crocus and VA-API and drives the display. Without it the driver logs the chip and leaves it to the firmware's framebuffer ([i915](sys/drm/i915/Readme.md)). An update with `rach2-install --i915` puts it on the installed root's lines, as the release does on the Lenovo ([rach2-install(8)](../man/man8/rach2-install.8)); test images and the recovery system boot without it. |
| `rach2.i915.disable_display` | With `rach2.i915`, as Linux's `i915.disable_display`: bind the chip without its display, so that the device has no mode setting and the display, the backlight and the firmware's framebuffer, on which the console keeps drawing, stay as the firmware left them; for trials of the GPU that leave the screen alone ([i915](sys/drm/i915/Readme.md)). |
| `rach2.i915.firstlight` | With `rach2.i915`, have the bound chip's render ring write a value to memory once at the bind, before any display code, and log `i915: first light: ok` or the failure by name; every wait is bounded ([i915](sys/drm/i915/Readme.md)). |
| `rach2.vkms`, `vkms.enable_cursor=`, `vkms.enable_overlay=` | Register vkms, Linux's display in software, after the other display drivers; the two parameters, as Linux's module parameters, give it the cursor plane (on by default) and eight overlay planes (off by default) ([vkms(4)](../man/man4/vkms.4), [DRM](sys/drm/Readme.md)). |
| `rach2.vgem` | Register vgem, Linux's buffers and fences with no hardware, which IGT's i915 tests export to the GPU and hold busy, after vkms ([vgem(4)](../man/man4/vgem.4), [DRM](sys/drm/Readme.md)). |
| `rach2.i915fake` | Bind the Intel graphics driver, for tests in QEMU, to each function of QEMU's `edu` device (`-device edu`) with a fake chip behind it that answers as the Lenovo's HD 4400, 8086:0a16 in `/sys`, completes every command at once and injects faults from `/sys/kernel/debug/dri/DEVICE/i915_fake`; it draws nothing ([i915](sys/drm/i915/Readme.md)). |
| `rach2.nofxsr`, `rach2.noxsave` | Save the floating-point state with `fnsave` (i686 only) or with `fxsave`, in place of the richer form the processor has ([the PC platform](sys/arch/x86/Readme.md)). |
| `cpuidle_haltpoll.force` | As on Linux, poll before an idle halt under a hypervisor that does not hint that the guest's processors are its own (KVM_HINTS_REALTIME), where the idle wait otherwise halts at once ([processes](sys/proc/Readme.md)). |
| `rach2.notsc`, `rach2.tscreliable` | Never measure the time-stamp counter, so that the clock keeps its other reference and the vDSO's clock calls make the system call; or measure it where `cpuid` does not report one that runs at one rate, as under QEMU's emulator, before the first tick, and keep the clock and `k_udelay` by it instead of the HPET or the PM timer, whose every read under a hypervisor is an exit ([the PC platform](sys/arch/x86/Readme.md), [vdso(7)](../man/man7/vdso.7)). |
| `panic=N`, `oops=panic` | As on Linux: after a panic's record, keep its report on the screen `N` seconds, counting down, and then reset the machine, or reset at once for a negative `N`, or halt for 0. Without it `N` is 30, the owner's choice over Linux's 0, so that a machine nobody watches comes back by itself. `N` is an integer as `kstrtoint` reads one, and each `panic=` is read in turn, a value that is not one logged and left out. `oops=panic` sets `panic_on_oops`, which a kernel exception does not need here: it panics either way. `/proc/sys/kernel/panic` and `panic_on_oops` read and write both ([proc(5)](../man/man5/proc.5)). |
| `reboot=LIST` | As on Linux: the method a panic's reset and a restart begin with, `a` (the FADT's reset register, the default), `k` (the 8042), `p` (port 0xCF9), `t` (a triple fault), `e` (EFI's `ResetSystem`, where the kernel booted by UEFI firmware of its own word size) or `b` (the BIOS's reset entry at F000:FFF0, reached in real mode), and `w` for a warm reset; a restart with it runs Linux's emergency sequence in place of the default one ([the PC platform](sys/arch/x86/Readme.md)). |
| `rach2.board=NAME`, `rach2.resetskip=N` | Try only the named board's power profile, which the chipset must still match; skip the first `N` reset methods ([the PC platform](sys/arch/x86/Readme.md)). |
| `rach2.noacpica`, `rach2.nosci` | Leave ACPICA out, so that no ACPI method runs and the power off goes through the `\_S5` the kernel's own reader of the tables found; or bring ACPICA up without a handler for the system control interrupt, whose line then stays masked ([ACPI](sys/acpi/Readme.md)). |
| `watchdog_thresh=N`, `nowatchdog`, `nosoftlockup`, `nmi_watchdog=panic\|nopanic\|0\|1`, `softlockup_panic=N`, `softlockup_all_cpu_backtrace=N`, `hardlockup_all_cpu_backtrace=N`, `hung_task_panic=N`, `sysctl.kernel.NAME=N` | As on Linux, the lockup detectors' settings: the hard-lockup threshold in seconds, 0 to 60; neither detector, or no soft one; the hard detector off or on, and whether it panics; whether the others panic or log every processor's stack; and any of the fourteen settings of `/proc/sys/kernel` by its name, `hung_task_timeout_secs` among them. A value out of range is refused and logged ([lockup(7)](../man/man7/lockup.7), [the detectors](sys/watchdog.Readme.md)). |
| `rach2.cycleaccount` | Read the cycle count at each entry from user mode and each return to it, so that a tick held while interrupts were off is charged as system time or idle where it was due, and bkl/calls counts each system call's time; without it a tick is charged to the mode it finds, as Linux's tick accounting does ([the scheduler](sys/proc/Readme.md), [debugfs(5)](../man/man5/debugfs.5)). |
| `rach2.trace=enosys` | Log a system call number the kernel does not have, except when the process that last logged it makes it again; the numbers past the table share one such record. |
| `rach2.usblatency` | Print the times of keystrokes against the drain of USB events, and count the pumps and `getrandom` bytes before a blocked console reader runs. |

These options exist for the suites, which use them to bring about a fault or a boundary on demand:

| Option | Effect |
| --- | --- |
| `rach2.blocklag=N` | Answer disk 0's requests `N` hundredths of a second late, 1 to 1000000, through a wrapper that sleeps. Its partition nodes, and `/dev/bootpart` when the boot partition is on disk 0, are on the wrapper; the root's window and every other disk keep their own devices. |
| `rach2.lagdeadline=T`, `rach2.lagperiods=N` | With `rach2.blocklag`: the wrapper's deadline period in hundredths of a second and the periods a request waits before it fails, each 1 to 1000000, in place of five seconds and one period. |
| `rach2.blockfail=N` | With `rach2.blocklag`: the `N`th write through the wrapper fails with `EIO`, `N` from 1 to 1000000. |
| `rach2.blockdead=P` | With `rach2.blocklag`: MBR partition `P` is built over a second device that takes every request and answers none. |
| `rach2.blockpool=N` | Allow `N` block requests in flight, 1 to 16, in place of 16. |
| `rach2.blockdeadline=S` | Give a block request's deadline period as `S` seconds, 1 to 600. |
| `rach2.framefail` | Enable `/dev/framefail`, which takes a count: the count-th frame allocation inside a system call from then on fails ([bootlog(4)](../man/man4/bootlog.4)). |
| `rach2.framehigh` | Take frames from 4 GiB up first, so that on an x86-64 machine with memory there the heap's pages lie above 4 GiB. |
| `rach2.dma32` | Treat the AHCI and xHCI controllers as able to reach only 32-bit addresses. |
| `rach2.stackoverrun=fork`, `rach2.stackoverrun=boot` | Before the first program, run a kernel stack down until it overflows: one `kstack_alloc` gives, or the boot stack. The kernel panics at the page fault or the double fault that the guard page raises ([the architectures' Readme](sys/arch/Readme.md)). |
| `rach2.strings` | Before the first program, check `k_memcpy`, `k_memset` and `k_memmove` over 68 lengths at four source and four destination offsets, with the bytes around each range required unchanged. |
| `rach2.hubslow=MS` | Wait `MS` milliseconds between two ports of a hub scan. |
| `rach2.msidrop=N` | Silence every USB controller's interrupts at the `N`th, so that the timer's pump alone serves them. |
| `rach2.hcfail=N`, `rach2.nicfail=N` | Refuse the `N`th xHCI controller or network card, counting from 0. |
| `rach2.wsim=N` | Make `N` software Wi-Fi radios, 1 to 4, wsim0 onwards, once the wireless station layer is up; a program carries their frames through `/dev/wsim` ([wsim(4)](../man/man4/wsim.4)). |
| `rach2.ath9k_noani` | Leave the Atheros Wi-Fi card's noise immunity at the levels its tables set, the first thing to try if its rate stays at 1 Mbit/s ([ath9k](sys/network/driver/ath9k/Readme.md)). |
| `rach2.ath9k_noaspm` | Disable PCIe L0s and L1 at both ends of the Atheros Wi-Fi card's link; otherwise keep the firmware settings ([ath9k](sys/network/driver/ath9k/Readme.md)). |
| `rach2.ath9k_noampdu` | Send the Atheros Wi-Fi card's frames one at a time, refusing the BlockAck sessions that would aggregate them ([ath9k](sys/network/driver/ath9k/Readme.md)). |
| `rach2.ath9k_nomsi` | Serve the Atheros Wi-Fi card from the timer tick instead of by message-signalled interrupts ([ath9k](sys/network/driver/ath9k/Readme.md)). |
