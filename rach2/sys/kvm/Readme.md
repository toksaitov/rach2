# `kvm/`: the KVM interface

The `kvm/` directory is the kernel's side of Linux's KVM API, version 12, on the x86-64 kernel alone: `/dev/kvm`, the VM and vCPU descriptors its ioctls make, each vCPU's run page, the state ioctls QEMU calls, the run loop, and the interface a processor's backend, AMD's SVM or Intel's VMX, gives the rest. A program such as QEMU uses it as it uses Linux's, through `linux/kvm.h`. The local APIC is in the kernel, with the split controller's routes, MSIs, irqfds and ioeventfds, and the PIC and IOAPIC stay in the caller. Guest memory is the caller's, through memory slots that follow every change to it, the guest-physical tables EPT and nested paging walk, and a dirty log. A guest whose CPUID names Hyper-V gets Linux's Hyper-V enlightenments: its MSRs, the reference TSC page, SynIC and its timers, and its hypercalls, with the IPI and TLB flush ones that Windows and Linux guests use. Both Intel's VMX (`vmx.c`) and AMD's SVM (`svm.c`) run guests. [kvm(4)](../../../man/man4/kvm.4) is the user's contract.

## Interfaces

* `/dev/kvm`, character device 10:232, mode 0666, registered by `kvm_start` (`kernel.c`) when a backend's `probe` succeeds, VMX tried first; the boot logs `kvm: ready: vmx` or `kvm: ready: svm`. Without either there is no node, as Linux loads no KVM module.
* `/sys/module/kvm/parameters`, and `kvm_intel`'s or `kvm_amd`'s beside it, made by `kvm_start` with the node: the read-only parameters Linux's KVM selftests read, with Rach2's values, which [sysfs(5)](../../../man/man5/sysfs.5) lists. Every selftest skips without `force_emulation_prefix`.
* The ioctls of `/dev/kvm`, of a VM and of a vCPU, numbered and laid out as Linux's (`kvm_abi.h`). An ioctl a level does not have is `ENOTTY` on `/dev/kvm` and a VM, and `EINVAL` on a vCPU, as on Linux. The VM and vCPU descriptors are `anon_inode:kvm-vm` and `anon_inode:kvm-vcpu:N`, read-write and close-on-exec.
* A vCPU's mapping: KVM_GET_VCPU_MMAP_SIZE is two pages, the `struct kvm_run` page and the page port I/O data goes through (`KVM_PIO_PAGE_OFFSET` 1). A shared mapping maps both pages cached, and a fork's child shares it; a private one copies each page at its first touch, as a private mapping of a file does here ([memory](../mm/Readme.md)). Either holds a reference to the VM, so the pages outlive the descriptors.
* KVM_CREATE_DEVICE and the VFIO bridge's attributes, described under [VFIO assignment](#vfio-assignment).
* A VM belongs to the address space that made it: an ioctl of the VM or of its vCPUs from another, a fork's child's, is `EIO`, as Linux's `kvm->mm` check makes it.
* An ioctl of KVM's type, 0xAE, that ends with `EINTR` is never restarted, whether or not a handler runs, since Linux gives KVM_RUN's `EINTR` to the caller as it is (`ioctl_restartable` in `syscall.c`, [signals](../proc/signal.Readme.md)).
* KVM_SET_USER_MEMORY_REGION, KVM_GET_DIRTY_LOG and KVM_CLEAR_DIRTY_LOG on a VM, and KVM_ENABLE_CAP of KVM_CAP_MANUAL_DIRTY_LOG_PROTECT2, with Linux's checks and errors.
* KVM_SET_VAPIC_ADDR accepts address zero on a vCPU with the split controller, which QEMU sends on APIC reset even without KVM_CAP_VAPIC. The optional shared VAPIC page is not offered.
* `/proc/stat` counts live VMs, vCPUs, slots, guest-physical table pages and run-page mapping objects as `kvm_vms`, `kvm_vcpus`, `kvm_slots`, `kvm_tdp_pages` and `kvm_run_mappings`. A fork shares a run-page mapping object. These counts include a VM kept by a mapping after its descriptors close and reach zero only after the last reference goes.
* `/proc/stat` also reports `kvm_exits`, the cumulative count of completed backend entries, including exits handled inside KVM_RUN, read under the big lock. Failed entries whose backend returns an error are excluded.
* Hyper-V's, as Linux's `hyperv.c` has them: KVM_GET_SUPPORTED_HV_CPUID on `/dev/kvm` and on a vCPU, KVM_HYPERV_EVENTFD on a VM, KVM_ENABLE_CAP of KVM_CAP_HYPERV_SYNIC, KVM_CAP_HYPERV_SYNIC2 and KVM_CAP_HYPERV_ENFORCE_CPUID on a vCPU, the routes of type KVM_IRQ_ROUTING_HV_SINT, and the exit KVM_EXIT_HYPERV with its SynIC, hypercall and debugger forms.
* `kvm.h` is the interface of the directory's files to each other: the backend's operations, the VM and vCPU records, and each module's calls, among them `kvm_slot_find`, which the guest-physical tables, VFIO and the transport's buffers call to turn a guest frame into the caller's address, `kvm_tdp_fault`, which a backend calls on a guest-physical fault, and `kvm_tdp_root` with the request KVM_REQ_TLB_FLUSH, by which the backend finds the tables and learns when to drop its translations of them.

## Design

### The records

A VM (`struct kvm_vm`) counts its references in `refs`: its descriptor, each vCPU's descriptor and each mapping of a run page. A vCPU lives as long as its VM, as on Linux, so closing a vCPU's descriptor drops its VM reference and nothing else; the last reference frees each vCPU, the modules' shares, the backend's and the VM, and lets go of the address space it held with `mm_hold`. A vCPU's run pages are two pages of the kernel's own, made at KVM_CREATE_VCPU. The descriptors' objects begin with a `struct anon_obj`, as every anonymous descriptor's does ([io](../io/Readme.md)).

### Capabilities

Each module answers only the capabilities it makes true, so a capability turns on with the task that makes it so. `kvm.c` answers its own, then asks `slots.c`, `irq.c`, `iobus.c` and the backend in turn; the stubs answer 0. KVM_CHECK_EXTENSION on a VM gives the same answers as on `/dev/kvm`, since no capability depends on the VM's type.

### The run loop

KVM_RUN (`vcpu.c`) holds the vCPU for the call, swaps in the signal mask KVM_SET_SIGNAL_MASK gave, and gives the backend the caller's answer to the last exit's read, from the port I/O page or the run page's MMIO data, or the result of a Hyper-V hypercall the caller carried out, before anything else, so the answer is not lost when `immediate_exit` or a signal ends the call. With `immediate_exit` set it then returns `EINTR` at once. Otherwise, before each entry, it answers a triple fault with KVM_EXIT_SHUTDOWN and a signal or a request to leave with KVM_EXIT_INTR and `EINTR`, lets `kvm_hv_prepare` write Hyper-V's TSC page or end the run in its exits, injects a waiting event, and enters: with interrupts off it marks the vCPU in the guest, checks the requests once more, lets go of the big lock and calls the backend's `enter`; it takes the lock back after the exit and turns interrupts on, which lets the host's interrupt that ended the guest run. The backend's `exit` then names the exit. A port or MMIO write the bus takes and an exit the kernel handles enter again, and so does a HLT once an interrupt ends it, when the local APIC is in the kernel (`kvm_lapic_halt`); the rest go to the caller through the run page, a port or MMIO read waiting for its answer. `kvm_vcpu_kick` leaves a request and, when the vCPU is in the guest on another processor, interrupts that processor with `smp_kick`, so the guest exits and the loop sees the request.

### The backend

`struct kvm_backend` (`kvm.h`) is the contract: `probe` at boot; `vm_init`, `vm_free`, `vcpu_init` and `vcpu_free`; `enter`, which runs with interrupts off and without the big lock, takes no lock and does not sleep; `exit`, under the big lock, which fills `v->exit` and the interrupt flags the run page reports, and hands a VMCALL or VMMCALL to `kvm_hv_hypercall` while `kvm_hv_hypercall_enabled` holds; `complete`, `save` and `inject`; `check_extension`; and `tdp`, the format of its guest-physical entries, EPT's or the AMD64 format, so that one walker in `tdp.c` builds both. The flush that KVM_REQ_TLB_FLUSH asks for drops the guest's own translations with the guest-physical ones, since Hyper-V's flush hypercalls rely on it: INVEPT does on VMX, and a flush of the ASID must on SVM.

### VMX

`vmx.c` turns VMX on for each run and off after it: `enter`, with interrupts off, sets CR4.VMXE, locks IA32_FEATURE_CONTROL with VMX on where the firmware left it unlocked, and runs VMXON, VMPTRLD, VMLAUNCH, and at the exit VMCLEAR and VMXOFF. A VMCS so never stays current across the big lock, a vCPU moves between processors with nothing to migrate, and an INIT, a kexec or a panic finds the processor out of VMX operation; the panic hook (`k_panic_hook`) clears a VMCS left current by a fault inside the section before VMXOFF, as Linux's emergency disable does. The cost is a VMXON and a full VMCS load for each entry, which Linux pays once per processor and once per migration. Every VMX instruction and every other touch of the processor, MSRs, control and debug registers, the FPU and the host's handlers, goes through the table `vmx_op`, so the host test runs the same code over a model.

The probe takes the controls from the capability MSRs, the true ones where IA32_VMX_BASIC offers them, and needs EPT of four levels, write-back, with INVEPT, the unrestricted guest, the preemption timer, virtual NMIs, the NMI and interrupt window exits, and the exit and entry controls of EFER, PAT and the debug registers; VPID, RDTSCP, INVPCID and WBINVD exiting are taken where they are. The unrestricted guest runs real mode and unpaged protected mode as they are, so no mode is emulated. EPT's pointer is write-back with accessed and dirty bits where the processor has them; each vCPU has a VPID, or 0 when all 65535 are taken, which drops the guest's translations at every entry. KVM_REQ_TLB_FLUSH and an entry on a processor other than the last are INVEPT of the VM's context and INVVPID of the vCPU's. The preemption timer bounds each run at 2^22 TSC ticks, so a guest that never exits still lets the run loop see a signal or a request.

The guest's STAR, LSTAR, CSTAR, SFMASK, KERNEL_GS_BASE and TSC_AUX go in and out through the entry's and exit's MSR lists, and SYSENTER, PAT, EFER and DEBUGCTL through the VMCS; the MSR bitmap passes the guest's FS, GS and KERNEL_GS_BASE accesses, and every other RDMSR and WRMSR exits to `msr.c`. CR0's CD and NW never reach the processor, whose memory types EPT gives, and CR3 does not exit. The guest's FPU is loaded under its XCR0 for the run, by XRSTOR or, without XSAVE, FXRSTOR, and saved after it. An NMI or a machine check that ends the run is the host's, which `enter` passes to the host's handler once VMX is off; the host's interrupt waits until the run loop turns interrupts on.

Events go in by Linux's order in `kvm_check_and_inject_events`: an exception, an NMI, then an interrupt, the one the last exit found under delivery first; an NMI or interrupt the guest cannot take arms the matching window exit. An exception in real mode carries no error code, a fault but #DB, #BP, #OF, #DF and #MC sets RF in the RFLAGS its delivery saves, as Linux sets it before injecting (`kvm_exception_rf`, for both backends), and NMI blocking is set by the delivery, never before the entry. KVM_SET_GUEST_DEBUG's single step runs the guest under TF, which the caller's RFLAGS do not show, and reports KVM_EXIT_DEBUG with DR6.BS after each instruction, the kernel's own among them; software breakpoints take #BP, hardware ones run in the caller's DR0 to DR3 and DR7, and BLOCKIRQ holds new NMIs and interrupts.

### SVM

`svm.c` requires SVM and nested paging, with at least two ASIDs, and refuses a processor whose firmware set VM_CR.SVMDIS. Each processor enables EFER.SVME and installs its host save area at the first entry. Each vCPU owns its VMCB and a second save page for VMLOAD and VMSAVE, which move FS, GS, TR, LDTR and the system-call MSRs. `svm_run.s` loads the general registers around VMRUN, with GIF clear while guest state is installed, and restores the host before setting GIF. A host interrupt that ends the run waits until the run loop enables interrupts. A machine check reaches the host's handler. The panic hook sets GIF and disables SVM on its processor.

Nested paging uses `tdp.c`'s AMD64 entries. Each processor allocates ASIDs in generations; the first entry and generation rollover flush all translations. A vCPU receives a new ASID after migration. A requested flush uses flush-by-ASID where CPUID offers it, otherwise a new ASID. The I/O and MSR permission maps intercept every port and every MSR except FS_BASE, GS_BASE and KERNEL_GS_BASE, whose state VMLOAD and VMSAVE carry. CR0 is intercepted while CD or NW must be hidden, CR4 keeps the host's MCE bit, and CR8 writes update the local APIC's TPR. The backend decodes the intercepted system instructions when NRIP save or decode assists are absent, as under the TCG profile.

Exceptions, NMIs and interrupts are injected in that order, with an event interrupted during delivery reinjected first. The interrupt shadow blocks external interrupts and NMIs. A pending interrupt arms the virtual interrupt intercept; NMI blocking ends after an intercepted IRET runs, with a single step where needed to reach the next NMI window. An enabled Hyper-V hypercall goes from VMMCALL to `hyperv.c`, with NextRIP's instruction length or 3 bytes without NRIP save. Nested SVM instructions raise #UD, since guest CPUID does not offer SVM. XSETBV goes through the guest's CPUID checks, and WBINVD flushes for a noncoherent assigned device.

Both backends restore and save the guest's full XSAVE image under the host's XCR0. The guest's XCR0 takes effect only for guest execution, so a saved component that the guest has disabled cannot make XRSTOR fault; the saved host mask is per processor.

### The instructions the kernel runs

`emulate.c` carries out what an exit hands over, for either backend, with Linux's results: CPUID from the guest's table, a leaf it lacks read as Linux's `kvm_cpuid` reads one, XSETBV under the guest's CPUID, RDMSR and WRMSR through `msr.c` and the local APIC, with Linux's rules for a guest's own writes (IA32_TSC_ADJUST moves the TSC by its change and is ignored without the CPUID bit, IA32_TSC moves the adjustment, a machine-check bank's STATUS takes only 0, and the P6's and K7's performance counters and event selects read 0 and ignore writes while no PMU is offered), port I/O with INS, OUTS and REP through the run page's port page and the ioeventfd buses, and each MMIO instruction `kvm_decode` decodes, whose memory operand may be RAM on one side, as a MOVS between a device and memory is. It walks the guest's page tables in each paging mode, setting their accessed and dirty bits as the processor does, and queues #PF, #GP or #UD where the processor would. A hardware task switch, which VMX hands over as exit 9 from CALL, IRET, JMP or a task gate, is carried out as Linux's `kvm_task_switch` does it: the 32-bit and 16-bit TSS, the busy bits, NT and the back link, CR3 and the LDT, a virtual-8086 task's segments, CR0.TS and DR7's local enables, the error code an exception through a task gate pushes, and an INT n's check of its gate's DPL. Its faults are the processor's: #TS for a TSS too small and #GP for a gate's DPL or a selector past its table come in the old task with nothing changed, and #TS, #NP, #SS or #GP for the new task's segments come in the new task once TR and the registers are its own. Linux 6.12 drops these faults: its `kvm_task_switch` never injects the exception its emulator returns. A VMCALL or VMMCALL that is not Hyper-V's is one of Linux's KVM hypercalls (`kvm_emul_hypercall`), numbered in RAX with its arguments in RBX, RCX, RDX and RSI and its result in RAX, 32 bits of each outside long mode: KVM_HC_VAPIC_POLL_IRQ and KVM_HC_SCHED_YIELD return 0, KVM_HC_KICK_CPU wakes the halted vCPU whose APIC id RCX names, KVM_HC_SEND_IPI, with the local APIC in the kernel, sends the ICR in RSI to the vCPUs that the bitmap in RBX and RCX names, bit 0 being the APIC id in RDX, and returns how many took it, KVM_HC_CLOCK_PAIRING is -KVM_EOPNOTSUPP, any other number -KVM_ENOSYS, and every call above CPL 0 -KVM_EPERM. An instruction the kernel finishes steps RIP and ends the interrupt shadow, so the vCPU that `sti; hlt` halted takes an interrupt at once; under the guest's TF it queues the single-step #DB, and under the caller's single step it ends the run with KVM_EXIT_DEBUG.

### Memory

A slot (`slots.c`) is a range of the caller's memory at a range of guest-physical frames, numbered below 256, made, moved, flagged and deleted by KVM_SET_USER_MEMORY_REGION with the checks of Linux's `kvm_set_memory_region` in its order: the flags, the alignment, the range within user space, the number, the wrap and size, then the deletion of a slot that does not exist, a change of a slot's address in the caller, size or READONLY flag, a range past the host's physical width (`kvm_tdp_frames`), and an overlap with another slot, `EEXIST`. Two slots may map the same memory of the caller, as QEMU's aliases do. A slot finds its frame by a walk of the table, with the last slot found tried first.

Nothing is pinned, as on Linux, whose KVM holds no page longer than a fault. Each slot registers its range of the caller's address space on the change notice ([memory](../mm/Readme.md)), which the memory manager calls under the big lock before a page there goes or changes: munmap, mremap, brk, mprotect, a fork's write protection, a copy-on-write break, madvise, the truncation of a file or device object, and the end of the address space. The call drops what the tables map of that part of the slot and gets every vCPU out of the guest before it returns (`kvm_tdp_flush`), so no processor reaches a frame the memory manager reuses; the guest's next touch faults and finds the page as the caller has it then. A move, a change of flags and a deletion drop the slot's part of the tables the same way. A killed QEMU so leaves no page pinned or counted: its address space's end drops every slot's mappings, and the VM's end frees the slots and the tables.

The guest-physical tables (`tdp.c`) are four levels in the backend's entry format (`struct kvm_tdp_format`), a frame each, reached through the direct map; `kvm_tdp_root` gives the top one for EPTP or nCR3. A guest-physical fault comes to `kvm_tdp_fault` in the vCPU's thread, which is in the caller's address space: the slot's page is brought in as the caller's own touch would (`vm_prefault_range`), which may sleep, then read again from the caller's page table with nothing that sleeps, and the leaf set from it, so the change notice cannot come between the read and the leaf. The leaf is writable when the slot is not read-only and the caller's page is writable, so a copy-on-write page stays read-only for the guest until a guest write breaks it in the caller. A device's frame, one the frame allocator does not count, such as a BAR mapped from `/dev/mem` or by VFIO, is uncached with the guest's PAT in charge, so the guest may make it write-combining; RAM is write-back with the guest's PAT ignored, as Linux's `vmx_get_mt_mask` gives a VM with no device that does not snoop; while VFIO assigns one that does not (`kvm_tdp_noncoherent`), RAM is write-back with the guest's PAT in charge, so the guest's uncached buffers for that device stay uncached, and the first assignment and the last release each drop every leaf so that the next faults take the new type. A 2 MiB leaf maps 2 MiB of guest frames in one slot that does not log when their caller's addresses are one leaf table whose 512 pages are present and 512 consecutive frames from a 2 MiB boundary, all RAM or all a device's; user memory here is mapped in 4 KiB pages, so that is the case for a device's BAR or a contiguous object, and a change to any of the 512 pages drops the whole leaf. A fault where no slot is, or a write to a read-only slot, answers 1, which the backend turns into an MMIO exit. A page the caller cannot touch is `EFAULT`, which ends KVM_RUN, as Linux's "Bad address".

A zap clears the leaves of a range and takes out a table once it maps nothing, flushes when it cleared a leaf or took out a table, and frees the tables after the flush, since until then a vCPU in the guest may walk them or hold them in its paging-structure caches. A flush sets KVM_REQ_TLB_FLUSH on every vCPU, kicks those in the guest and waits until none is: a vCPU leaves the guest within a moment of its kick, and cannot enter again until it takes the big lock, which the flush holds. The backend drops its translations of the VM before an entry with the request set, and before an entry on a processor other than the vCPU's last.

A slot with KVM_MEM_LOG_DIRTY_PAGES has a log (`dirty.c`), a bit for each page in 64-bit words, as Linux lays it out. A write fault marks the page and maps it writable; a read maps a page whose bit is clear read-only, so its first write faults and is logged. Such a slot has no 2 MiB leaf, and turning the log on or off drops the slot's mappings. KVM_GET_DIRTY_LOG takes the log into a buffer of the kernel's, clears it and takes the write right from the leaves it named, flushes, and copies the buffer out, so a write after the call is logged anew. Under KVM_CAP_MANUAL_DIRTY_LOG_PROTECT2 with MANUAL_PROTECT_ENABLE, which QEMU turns on when offered, GET leaves the log, and KVM_CLEAR_DIRTY_LOG clears the bits the caller names, from a page that is a multiple of 64, and protects those pages; with INITIALLY_SET as well, a log starts with every page set and no page protected. `kvm_dirty_mark` is for the kernel's own writes to guest memory.

### The MMIO decoder

An MMIO exit tells the backend the guest-physical address and, on VMX, whether the access read or wrote, but not the operand: that is in the instruction, which `kvm_decode` (`decode.h`) reads from the guest's bytes at its RIP, in the mode of its code segment. It gives the instruction's length, what it does with memory (`KVM_OP_*`: a load, a store, an arithmetic and logic operation, a unary one, XCHG, MOVS, STOS, PUSH or POP), the memory operand's size, the register or immediate, the widening of MOVZX, MOVSX and MOVSXD, the segment and address as base, index, scale and displacement, the address size, and the REP and LOCK prefixes. The backend reads or writes the register, completes the access through the run page, and steps RIP by the length. Prefixes are read as the processor reads them: the last segment override and the last of 0xF2 and 0xF3 count, REX counts only right before the opcode, REX.W outweighs 0x66, and the 16-bit ModRM forms take SS for an address through BP.

An instruction outside that set, one whose ModRM names a register, a LOCK the processor would refuse with #UD, and one that would pass 15 bytes are refused. The backend then does what Linux's `handle_emulation_failure` does: it injects #UD into a guest above CPL 0, and at CPL 0 reports KVM_EXIT_INTERNAL_ERROR through `kvm_decode_fail`, which lays out the run page as Linux's `prepare_emulation_failure_exit`: suberror KVM_INTERNAL_ERROR_EMULATION, the flag that the instruction's bytes follow, the bytes padded with 0x90, then the exit's reason and qualifications.

### Interrupts

The split controller is Linux's: KVM_ENABLE_CAP of KVM_CAP_SPLIT_IRQCHIP on the VM, before its first vCPU, with the caller's IOAPIC's pin count in `args[0]`, at most 4096, puts each vCPU's local APIC in the kernel and leaves the PIC and IOAPIC to the caller. KVM_CREATE_IRQCHIP, the whole controller in the kernel, is `ENXIO`, or `EEXIST` after the split one. QEMU 10's pc and q35 machines ask for the whole controller by default and stop when it fails, so they run with `-machine kernel-irqchip=split`, or with `off`, which keeps every controller, the local APIC too, in QEMU and injects through KVM_INTERRUPT.

`vlapic.c` keeps each APIC's 1 KiB register page and follows Linux's `lapic.c`: the readable registers, the LVT masks, the ID, LDR and DFR rules, SPIV's software disable masking every LVT entry, and the base MSR's moves between disabled, xAPIC and x2APIC modes, which the guest's CPUID allows. Version 0x14 has six LVT entries and directed EOI when the guest's CPUID offers x2APIC. The page is reached through the backend's MMIO exits at the APIC base; in x2APIC mode, or with the APIC disabled, a read of it gives all ones and a write is dropped, as Linux's LAPIC_MMIO_HOLE quirk does. The x2APIC registers are MSRs 0x800 to 0x8FF, whose reserved bits and read-only registers raise #GP. Delivery to a fixed, physical, flat or cluster destination, a broadcast and a shorthand is Linux's `kvm_apic_match_dest`, and lowest priority goes to one vCPU by Linux's vector hashing. The boot vCPU's LINT0 takes ExtINT at reset, as Linux's LINT0_REENABLED quirk sets it, so KVM_INTERRUPT's vector, the caller's PIC's, reaches the guest before it programs its APIC; a second KVM_INTERRUPT while one waits is `EEXIST`. KVM_GET_LAPIC and KVM_SET_LAPIC give the page in Linux's layout, the x2APIC id in bits 31:24 as without KVM_CAP_X2APIC_API, and the timer's TMCCT, from which KVM_SET_LAPIC restarts the count.

The timer counts at Linux's APIC bus of 1 GHz in host nanoseconds, by TDCR's divisor, one-shot, periodic with Linux's floor of 200 us, or against IA32_TSC_DEADLINE in the guest's TSC when the guest's CPUID offers that mode. `kvm_lapic_prepare` checks it before each entry, and the host's 1 ms tick makes the guest exit, so an expiry reaches the guest within a tick. Before each entry it also takes an INIT, which resets the vCPU's registers and the APIC and leaves an application processor waiting for SIPI, a SIPI, which starts that processor at the vector's page in real mode, and the NMIs other vCPUs sent, of which two wait at most, or one while an NMI is under delivery or blocked, as Linux's `process_nmi` limits them. A HLT stays in the kernel: the halted vCPU, or one waiting for SIPI, sleeps until an interrupt it can take, its timer's tick or a signal, which ends KVM_RUN with KVM_EXIT_INTR and leaves the vCPU halted. KVM_GET_MP_STATE and KVM_SET_MP_STATE give and take that state; SIPI_RECEIVED is taken as a wait for SIPI with one pending.

`irq.c` holds the routes KVM_SET_GSI_ROUTING gives, MSI routes and Hyper-V's SINT routes alone, one for each GSI below 4096, since the IOAPIC's are the caller's. KVM_IRQ_LINE and KVM_IRQ_LINE_STATUS raise a GSI's MSI; KVM_SIGNAL_MSI sends one directly and returns the count of APICs that took it, or `EPERM`, Linux's -1, when none did. An MSI's assert bit is ignored, as Linux's `kvm_set_msi_irq` ignores it. The EOI of a vector an APIC took level-triggered through a route of a GSI below the pin count asks its vCPU to exit with KVM_EXIT_IOAPIC_EOI and the vector, so the caller's IOAPIC can lower its line or raise it again.

An irqfd (KVM_IRQFD) is a hook on an eventfd ([io](../io/Readme.md)) that raises its GSI's MSI at each rise of the counter and takes the counter, as Linux's irqfd does. The hook runs under the eventfd's spinlock, possibly in another process's write, so it delivers from a copy of the route that KVM_SET_GSI_ROUTING refreshes under `irq.c`'s spinlock. A counter above 0 at KVM_IRQFD raises the GSI at once. An eventfd may back one irqfd of a VM (`EBUSY`); KVM_IRQFD_FLAG_RESAMPLE is `EINVAL` with the split controller, as Linux's `kvm_arch_irqfd_allowed` makes it, and QEMU then resamples in its own IOAPIC. The irqfd ends at its deassign, the VM's end, or the eventfd's last close, whose hangup frees it; when the VM's end finds the hook already taken off by a close whose hangup has yet to run, it leaves the record to that hangup.

`iobus.c` keeps the ioeventfds (KVM_IOEVENTFD) on Linux's buses, ports, MMIO addresses and s390's notifications, at most 1000 on each: a guest's write at an ioeventfd's address, of its length, or of any length for length 0, and of its value when it has a data match, signals its eventfd and enters the guest again without an exit. A string OUT signals once for each element. Two ioeventfds that some write would both match are `EEXIST`, as in Linux's `ioeventfd_check_collision`. A write that the bus does not take goes to the caller, and a read is never the bus's.

### VFIO assignment

KVM_CAP_DEVICE_CTRL offers KVM_CREATE_DEVICE for KVM_DEV_TYPE_VFIO, one bridge per VM. Its descriptor holds a VM reference. KVM_SET_DEVICE_ATTR of KVM_DEV_VFIO_FILE adds or removes a VFIO group or device descriptor by its open file description, so aliases cannot add the same file twice. The bridge holds each file until removal or its own last close. KVM_HAS_DEVICE_ATTR reports the ADD and DEL attributes; GET is `EPERM`, since neither has a readable value. Every device ioctl requires the VM's address space, as its VM and vCPU ioctls do.

VFIO does not enforce DMA cache coherence, so the first file added calls `kvm_tdp_noncoherent` to drop the existing translations and make new ones observe the guest PAT; the last removal or close releases the files before restoring the ordinary policy. Attribute changes are serialized across a file release that sleeps. The bridge follows Linux's `virt/kvm/vfio.c`.

### Hyper-V

`hyperv.c` follows Linux's `hyperv.c` and the TLFS. A vCPU has Hyper-V once KVM_SET_CPUID2 gives leaf 0x40000001 the interface "Hv#1"; the leaves the caller takes from KVM_GET_SUPPORTED_HV_CPUID are Linux's ten, with no enlightened VMCS and no direct timers or cluster IPI without the APIC in the kernel. The VM's share, the partition-wide MSRs, and each vCPU's, made at its first need, hang off the records' `hv`. A guest's RDMSR or WRMSR of Hyper-V's range reaches `kvm_hv_msr` through `emulate.c`, #GP without Hyper-V in its CPUID or, under KVM_CAP_HYPERV_ENFORCE_CPUID, for an MSR or hypercall the CPUID does not offer; the caller's KVM_GET_MSRS and KVM_SET_MSRS reach it through `msr.c`, held to neither, and the index list names Linux's 28 MSRs of it. A write of the hypercall MSR, once the guest has written its id, puts VMCALL, or VMMCALL on SVM, and RET in the page it names.

The reference counter counts 100 ns of the kvmclock. The reference TSC page is written before the next entry (`kvm_hv_prepare`) once the guest or the caller changes its MSR or KVM_SET_CLOCK or a TSC write moves the clock, as Linux's `kvm_hv_setup_tsc_page`: its sequence 0 first, then the scale, 2^64 * 10^7 / the TSC's rate, and the offset that make its formula the kvmclock's, then the next sequence; a page in no slot or a rate the scale cannot hold leaves sequence 0, so the guest reads the MSR. While the guest emulates the TSC the page is left as it stands. A write of the crash control with its notice bit and of the reset MSR end the next KVM_RUN in KVM_EXIT_SYSTEM_EVENT, of type CRASH or RESET.

SynIC needs the split controller. KVM_CAP_HYPERV_SYNIC turns it on and clears each page the guest enables; KVM_CAP_HYPERV_SYNIC2 leaves them as they are. A guest's write of SCONTROL, SIEFP or SIMP ends the run in KVM_EXIT_HYPERV_SYNIC for the caller's model of the pages. A SINT is raised in the APIC as a self IPI of its vector, by a KVM_IRQ_ROUTING_HV_SINT route, its GSI's irqfd among them, or by a timer; one with auto-EOI is taken without going in service (`kvm_lapic_ack`), and an EOI of a SINT's vector or a write of EOM retries the message a timer could not leave in a full slot. The four synthetic timers of each vCPU count in the reference counter's time, one-shot at an absolute count or periodic, and auto-enabled by their count; armed in the host's ns, they are looked at in `kvm_lapic_prepare` before each entry, and the halted vCPU's wait ends at the next one's time. An expiry leaves a timer message in its SINT's slot of the message page, or in direct mode raises its vector.

A VMCALL from a guest at CPL 0 in protected mode with hypercalls enabled is decoded from RCX, RDX and R8, or EDX:EAX, EBX:ECX and EDI:ESI outside 64-bit mode, with the fast input in XMM0 to XMM5 from the vCPU's FPU image; its status goes back in RAX, or EDX:EAX. HvNotifyLongSpinWait is answered at once, HvSignalEvent signals the eventfd KVM_HYPERV_EVENTFD gave its connection, and HvCallSendSyntheticClusterIpi and its Ex form raise the vector in each vCPU of their set, simple or sparse. HvFlushVirtualAddressSpace and HvFlushVirtualAddressList, and their Ex forms, flush each named vCPU's TLB whole with KVM_REQ_TLB_FLUSH, which the TLFS allows for any list, and wait until none of them is in the guest with the request still set, so no vCPU runs on with old translations when the call returns. HvPostMessage and HvSignalEvent of a connection the kernel does not know, with SynIC on, the extended hypercalls from 0x8001 and the debugger's go to the caller in KVM_EXIT_HYPERV_HCALL, whose result KVM_RUN puts in RAX before the next entry. The synthetic debugger's MSRs are kept, and a write of its control or pending page goes to the caller in KVM_EXIT_HYPERV_SYNDBG.

### Lock order

1. The big kernel lock, which every ioctl runs under.
2. The vCPU, held for one ioctl (`vcpu_lock`), as Linux's `vcpu->mutex`. A second ioctl of the same vCPU sleeps until the first ends, letting go of the big lock meanwhile; a signal does not end that wait, since the holder is a KVM_RUN its own signal ends or a state ioctl that does not sleep long.
3. Spinlocks of other subsystems, such as an eventfd's, which an irqfd's hook runs under ([io](../io/Readme.md)).
4. `irq.c`'s spinlock, over the routes and the irqfds' copies of them, which the hook takes under the eventfd's.

The run loop lets go of the big lock only inside `enter`, with interrupts off and the vCPU held, so nothing else runs the vCPU meanwhile, and another thread changes it only by `kvm_vcpu_kick`'s requests. Nothing sleeps with interrupts off, and no code takes the big lock while it holds a spinlock. The slots, the tables and the dirty logs change only under the big lock, and the change notice calls a slot under it, so `kvm_tdp_flush` may wait for vCPUs to leave the guest without sleeping.

### State

The registers, special registers, XSAVE image, XCR0, events, debug registers, MP state, CPUID, MSRs, TSC offset and machine-check banks live in the vCPU's record; `dirty` names the parts a set changed, for the backend to load before the next entry, and `save` brings the backend's copy back before a get. The checks follow Linux's: KVM_SET_SREGS refuses EFER, CR0 and CR4 that the processor would and bits the guest's CPUID does not offer; KVM_SET_XSAVE refuses components past the guest's XCR0, a reserved MXCSR bit and a compacted image; KVM_SET_CPUID2 after the first KVM_RUN accepts only the same table; KVM_SET_MSRS stops at the first MSR it refuses and returns the count before it. A new vCPU has the power-on state Linux gives one, at the reset vector with the boot processor's APIC base.

AMD's SYSCFG and NB_CFG MSRs read as zero, and NB_CFG writes are ignored, as Linux's `kvm_get_msr_common` and `kvm_set_msr_common` specify for the guest's northbridge probes. SYSCFG writes remain refused.

## Limits

* At most 64 vCPUs in a VM, with ids below 256; 256 memory slots, in address space 0 alone, with no KVM_SET_USER_MEMORY_REGION2 and no guest_memfd; 256 entries for KVM_SET_CPUID2 and KVM_GET_CPUID2, and fewer than 256 MSRs at once for KVM_GET_MSRS and KVM_SET_MSRS, as Linux's bounds.
* Only the machine type 0. The in-kernel interrupt controller is the split one alone: no in-kernel PIC, IOAPIC or PIT, no routes but MSI and SINT routes, and no irqfd resample. There is no KVM_CAP_X2APIC_API, no coalesced MMIO, no dirty ring, and no SMM, SMI or nested virtualization.
* The MMIO decoder knows the instructions `decode.h` lists, which compilers emit for device registers; Linux's emulator knows nearly all of x86, so an MMIO access through another instruction, such as BT, CMPXCHG, a string compare or an SSE move, is an internal error here and emulated there.
* KVM_GET_SUPPORTED_CPUID offers no paravirtual leaf, no performance counters, no PKU and no AMX.
* The guest-physical tables have 4 KiB and 2 MiB leaves, no 1 GiB ones, and a 2 MiB leaf only where the caller's 512 pages are consecutive frames, since user memory is mapped in 4 KiB pages here; Linux's KVM maps the caller's transparent huge pages as 2 MiB leaves.
* SVM boots the Debian x86-64 guest under TCG on WSL and the Mac and under nested KVM on WSL. The i686 guest's intermittent double fault is being investigated in 81-2b; the corpus still awaits qualification ([results](../../../tests/kvm/Readme.md#results)).
* Hyper-V's enlightened VMCS and direct TLB flush, which serve a nested guest, are not offered, and neither is the paravirtual EOI of the VP assist page, so the guest always writes its EOI. A sparse VP set reaches VP indexes below 64, the most vCPUs a VM has. The reenlightenment MSRs are kept but never notify, since a VM's TSC rate does not change.
* No EPT misconfiguration is expected, since the tables use one memory type for each leaf, and one would be an internal error. A task switch whose TSS or tables are in no slot is the internal error Linux reports too, and a TSS's T bit raises no #DB in the new task, as in Linux.
* Each entry turns VMX on and loads the VMCS anew, where Linux keeps VMX on and the VMCS current on a processor between runs.
