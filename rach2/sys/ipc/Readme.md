# `ipc/`: pipes and AF_UNIX sockets

Rach2 implements anonymous byte pipes through `pipe` and `pipe2`, the pipe behind a FIFO file, and AF_UNIX sockets (`unix.c`). A pipe has a read end, a write end, and a 4096-byte ring. It preserves byte order but has no message boundaries.

## Creation and lifetime

`pipe(int pipefd[2])` writes the read descriptor to `pipefd[0]` and the write descriptor to `pipefd[1]`. `pipe2` accepts only `O_CLOEXEC` and `O_NONBLOCK`; it applies either flag to both new descriptors and rejects any other bit with `EINVAL`. The two slots are reserved and given their ends only after both numbers have been copied to the caller: the copy can sleep, a reserved slot has no type for another thread sharing the table to find, and a copy that fails frees the slots and the pipe.

The two ends start with separate open-file descriptions. `dup`, `dup2`, `dup3`, `F_DUPFD`, `F_DUPFD_CLOEXEC`, and `fork` share the open-file description for the end they copy. Its status flags are shared too, so `O_NONBLOCK` changes made through `fcntl` or `FIONBIO` are visible through duplicates of that end. `FD_CLOEXEC` remains a descriptor flag.

Closing a descriptor releases an end only when the last descriptor sharing its open-file description closes. Closing the last writer wakes readers to drain buffered data and observe EOF. Closing the last reader wakes writers for `SIGPIPE`. The pipe is allocated from the kernel heap when made and freed after both ends close; there is no fixed count of pipes, and a process's descriptor table grows from sixteen entries to 1024.

Each live pipe has a nonzero inode distinct from every other live pipe. Both ends report that inode as a FIFO with permissions 0666 through `fstat`, and `/proc/<pid>/fd/<fd>` renders it as `pipe:[inode]`.

## Reads and writes

A read of an empty pipe waits while a writer remains open. It returns `EAGAIN` instead when the read end is non-blocking, and returns `0` once the last writer has closed. Buffered data is returned before EOF. One call reads at most the bytes available when its first transfer starts, up to the requested count. If another reader drains the ring during a later page resolution, the call returns its partial count without waiting for more data.

A blocking write continues until it has copied the requested count while a reader remains. If the pipe fills, the writer waits for space. A non-blocking write uses the space currently available and returns a short count; it returns `EAGAIN` only when it cannot copy a byte. If the last reader has closed, the kernel posts `SIGPIPE` to the writing thread and returns `EPIPE` when no byte has been written by that call. A reader closure, signal, or user-copy fault after a partial transfer returns the partial count.

Pipe waits are signal-interruptible. A wait interrupted before any transfer ends the call with `EINTR`, and the dispatcher marks such a read or write restartable: the return to user mode restarts it when the signal runs no handler, or its handler has `SA_RESTART`, as Linux does, and otherwise the caller gets `EINTR`. A call that moved bytes before the signal returns their count, which nothing restarts. See the [signal documentation](../proc/signal.Readme.md) for delivery details. Reads wake blocked writers after each transfer frees space, writes wake blocked readers when a transfer makes an empty ring nonempty, and either final close wakes the other end. Each wait queue is a linked list of caller-owned waiter records, with no fixed queue capacity. Wakeup makes all sleepers runnable so they can recheck the condition.

Transfers resolve one user page before selecting a ring span. Resolution can sleep during memory reclaim and allow another process to change the ring or close the peer end. The operation rechecks readiness and closure after such a wait. The subsequent checked copy uses a present page, allocates nothing, and advances the ring counter before any context switch. An unresolved page returns `EFAULT` if no byte has been transferred, or the partial count otherwise.

The 4096-byte `PIPE_BUF_SIZE` is the ring capacity, not an atomic-write limit. A blocking write uses whatever space is free before it waits. Concurrent writers can therefore interleave even when each request is no larger than 4096 bytes. There is no POSIX `PIPE_BUF` atomicity guarantee.

## Descriptor operations

Pipe descriptors use a `struct file_ops` table for `read`, `write`, `poll`, `ioctl`, and final `close`. The generic descriptor layer owns duplication, fork inheritance, close-on-exec, and last-reference release.

The read end reports `POLLIN` when data is buffered or no writer remains, and always reports `POLLHUP` after the last writer closes. The write end reports `POLLOUT` when space exists or no reader remains, and always reports `POLLERR` after the last reader closes. These conditions match the ones that stop `read` and `write` from waiting. A poller waits on its end's queue, which the changes of that end's readiness wake; a FIFO opened for reading and writing is both ends, and its pollers wait on a third queue, which every change of either end wakes while such a description is open.

`FIONREAD` reports the buffered byte count. `FIONBIO` sets or clears `O_NONBLOCK` on that end's open-file description. Other pipe ioctls return `ENOTTY`. `lseek` and `_llseek` return `ESPIPE`.

The ring uses monotonically increasing 32-bit head and tail counters. Occupancy is unsigned `tail - head`; a physical index is the counter masked by `PIPE_BUF_SIZE - 1`. The pure ring operations are in `pipe_ring.c` so the host suite can test the same code as the kernel.

The implementation has no pipe resizing, packet mode, `splice`, `tee`, or `vmsplice`.

## FIFOs

A FIFO file is opened as an end of a pipe (`fifo_attach`), one pipe for each FIFO file, found by the file's mount and inode number, made at the first open and freed when no end is open, as in Linux. An open for reading waits for a writer and an open for writing for a reader; with `O_NONBLOCK` a reader does not wait and a writer with no reader fails with `ENXIO`; `O_RDWR` opens both ends and never waits. Each open has a description of its own, and the pipe counts the descriptions open on each end, so the end of input and `SIGPIPE` come when the last of an end's descriptions closes. `open(2)` reaches `fifo_attach` for a node whose mode has `S_IFIFO`, after the permission its access mode asks for, on any file system that keeps FIFOs: ext2, tmpfs and KRFFS. The description holds the file and its mount as a regular file's does, so the mount is busy while an end is open, and the walk's lock is let go before the open waits for the other end. `fstat` of the descriptor reports the pipe, as for an anonymous one.

## AF_UNIX sockets

An AF_UNIX socket (`unix.c`) is a descriptor of type `FD_TYPE_UNIX` whose `priv` is the socket record. `read`, `write`, `poll`, `ioctl` and the last close go through its `file_ops`, and the socket calls through `syscall_net.c`, which sends every call on such a descriptor to one dispatch here. A stream or sequenced-packet connection is two records that point at each other; a datagram socket may point at the one it is connected to. A message is a record on the receiver's queue with its bytes, the sender's name and credentials, and the descriptors it carries: copies of the sender's descriptor entries, each holding its open file description as a descriptor in a table does, installed in the receiver's table as it takes them. A KRFFS file among them is known by the node its description names, which a relocation of the file moves, as it does not move the copies: that node is the one the holder count finds, and the one a copy is released or installed with. The holder count (`unix_inflight_holds`) finds a descriptor in flight wherever it is: on a queue, on the reap list, or with a receive that has taken it off its queue and has not yet installed or closed it, which puts itself on a transit list for that time, since the installation and the closes can sleep while a close of the file's last descriptor elsewhere asks whether anything still holds it. A call that makes descriptors, `socketpair`, `accept` and a receive of `SCM_RIGHTS`, reserves each slot and gives it its socket or open file only after the number, and for `accept` the peer's name, has been copied to the caller: the copy can sleep, and another thread sharing the table finds nothing in the slot that it could use or close. A receive holds the socket's receive lock from choosing a message to consuming it, so that another receiver, and a connect that drops the queue, wait while its copy to the caller sleeps in a page fault; the lock is let go while the receive waits for data. A record counts the descriptors' side, each socket connected to it and an accept queue, and is freed with the last; the last close ends the connection, drops the queue, and so closes the descriptors in flight on it. Those closes go through a reap list: the outermost call closes the descriptors of each dropped message one at a time, and a close that drops another socket's queue adds to the list and returns, so a chain of sockets, each queued in the one before, is closed in a loop and not in nested calls that would run off the kernel stack. A path name is a socket file made through the file system (`fs_socket_bind`), which the bound socket holds as a working directory holds its own. [unix(7)](../../../man/man7/unix.7) states the behaviour; a socket sent over itself and never received is not reclaimed.

## Verification

`make test` runs two pipe-specific freestanding probes:

* `tests/pipeprobe.c` checks byte order, EOF, the 4096-byte capacity, non-blocking empty and full cases, `SIGPIPE` and `EPIPE`, a 5000-byte transfer that blocks across `fork`, 100 create-close cycles, and agreement between the two ends' `fstat` and `/proc` identities.
* `tests/pollprobe.c` checks `POLLIN` readiness, timeout, `POLLHUP`, `select` translation, and a poller woken by a child writing after a delay.

`tests/run host` runs `tests/host/pipe_ring_hosttest.c` under AddressSanitizer and UndefinedBehaviorSanitizer. It checks empty and full rings, bounded partial operations, byte order, and a transfer across the physical end of the array. `tests/host/pipe_copy_hosttest.c` runs the production pipe and user-copy code with a resolver that executes a competing pipe operation before returning a lazy or COW page. It checks byte order, bounded occupancy, peer closure, page faults, partial transfers, waits and wakeups. `sh tests/host/pipe_copy_mutate.sh` removes each early prefault separately in a private source copy; each compiled mutation must fail, and each restored, touched and rebuilt source must pass. This models the scheduling order without running reclaim, disk I/O or a CPU context switch. `tests/host/wait_queue_hosttest.c` checks linked-list insertion and removal, duplicate insertion, wake-all behavior and sixty-four simultaneous waiters; the guest probes above exercise the actual scheduling path.

`tests/musl/unixmusl.c`, in the default suite, checks AF_UNIX stream, datagram and sequenced-packet pairs, `SCM_RIGHTS` to a child, `SO_PEERCRED` and `SCM_CREDENTIALS`, with the process id an unprivileged thread other than the leader may name, a listener on a path and on an abstract name with the names both ends report, the refusals of a second bind and of a socket file with no listener, datagrams to a name, `EAGAIN` and `poll` on a nonblocking pair, the `EFAULT` of an accept given an address and no length pointer, a listener shut down for reading, which gives up the connection queued before and then refuses an accept and a connect, a connect waiting for room that a larger backlog lets finish, the `EPERM` of a connect to a datagram socket connected to another, a datagram socket that connects elsewhere or disconnects dropping its queue, with `ECONNRESET` for the peer it left, the `EPIPE` of a datagram send waiting for room when the receiver shuts down reading, and a chain of a thousand datagram pairs, each queued in the pair before, closed from its head, and a stream with its peer's queue full that polls writable once shut down for writing.

`tests/musl/fifomusl.c`, in the default suite, makes FIFOs in `/tmp` with `mkfifo` and `mknodat`, and checks `ENXIO` for a nonblocking writer with no reader, the end of input a nonblocking reader with no writer reads, bytes from one open to another, blocking opens that wait for each other across `fork`, and an open for reading and writing that does not wait and, once full, polls writable when a child's open reads a byte.

`tests/musl/pipemusl.c` is built and staged at `/musl/pipemusl` for a manual libc `pipe`, `fork`, read, write, close, and wait round trip. It is not an entry in the default `make test` runner.
