# `ipc/`: pipes, FIFOs, AF_UNIX sockets, System V IPC and POSIX message queues

This directory is the kernel's interprocess communication: anonymous pipes and the pipe behind each FIFO file (`pipe.c`, `pipe_ring.c`), AF_UNIX sockets (`unix.c`), System V shared memory, semaphores and message queues (`sysv.c`), and POSIX message queues with the `mqueue` file system (`mqueue.c`). Each follows Linux's system call interface, so the ported C libraries use it unchanged. The manual pages state what a program sees; this document states how the code provides it.

## Interfaces

* Pipes: `pipe`, `pipe2`, and `open` of a FIFO file; [pipe(2)](../../../man/man2/pipe.2), [open(2)](../../../man/man2/open.2) and [mknod(2)](../../../man/man2/mknod.2).
* AF_UNIX sockets: the socket calls on an `AF_UNIX` socket; [unix(7)](../../../man/man7/unix.7) and [socketcall(2)](../../../man/man2/socketcall.2).
* System V IPC: [ipc(2)](../../../man/man2/ipc.2), [shmget(2)](../../../man/man2/shmget.2), [semget(2)](../../../man/man2/semget.2) and [msgget(2)](../../../man/man2/msgget.2).
* POSIX message queues and the `mqueue` file system: [mq_open(2)](../../../man/man2/mq_open.2).

The pages give the system call numbers. Both architectures register `pipe`, `pipe2`, the direct socket calls, `shmget`, `shmat`, `shmdt`, `shmctl`, `semget`, `semctl`, `msgget`, `msgsnd`, `msgrcv`, `msgctl`, and `mq_open` with its five calls. i686 also registers `ipc`, through which musl reaches every System V object and which alone gives `semop` and the 32-bit `semtimedop`, together with `semtimedop_time64`, `socketcall`, `mq_timedsend_time64` and `mq_timedreceive_time64`. x86-64 has none of those, and registers `semop`, `semtimedop`, and a wrapper in `arch/x86_64/systab.c` that makes `accept` an `accept4` with no flags.

Inside the kernel, `open` calls `fifo_attach`, the KRFFS holder count `unix_inflight_holds`, process exit `sysv_exit`, and the end of a namespace `unix_ns_gone` or `ipc_ns_gone`; procfs reads `unix_snapshot` and `sysv_row_at`, and netlink's socket diagnostics `unix_snapshot`. `unix.c` makes and finds socket files through `fs_socket_bind` and `fs_socket_lookup` in `syscall_fs.c`, and `sysv.c` maps segments through `mmap_shm` and `munmap_shm` in `syscall_proc.c`.

## Design

Pipes and FIFOs run without the kernel's big lock (`proc/smp.h`), each pipe under its own sleeping lock and the list of pipes under a spinlock, as the next section says. The rest of the directory runs under the big lock but a poll, which a context switch passes on, so an object there changes under a call only while that call sleeps, in a wait, a page fault or a file system call, and each path checks again after a sleep what it judged before. The poll of a pipe end and of a unix socket runs without the big lock and the object's own lock (`FILE_OPS_POLL_UNLOCKED`, `fs/file.h`): it names its queue and then reads each word of the object once, as Linux's pipe_poll and unix_poll do after poll_wait, and a change it waits for is made before the wake of that queue. A unix socket's peer, whose fields the poll reads, changes under `unix_peer_lock`, which the poll takes, so the peer it reads is one its socket's reference keeps.

### Pipes

A `struct pipe` (`pipe.h`) comes from the heap and is freed when its last open file description closes; there is no fixed count of pipes. Each end is a descriptor of type `FD_TYPE_PIPE` with `pipe_ops`, whose `priv` is the pipe, and an open file description of its own; `pipe_close` runs when the description's last reference goes, `read_open` and `write_open` count the descriptions open on each end, and `files` counts the descriptions of either end and the FIFO opens not yet finished, as Linux's `pipe->files`, whose last let-go frees the pipe (`pipe_info_put`). `pipe_open` reserves both descriptors, copies their numbers to the caller, and only then gives them their ends, as Linux's `do_pipe2` does, so another thread sharing the table cannot use an end while the copy sleeps.

A new pipe's ring has `PIPE_BUF_SIZE` bytes, 65536, Linux's default capacity, which `fcntl(F_GETPIPE_SZ)` reports, and is allocated at the first write. Each pipe is charged to the real user that made it, and that user's pages are the sizes of its live pipes' rings in pages, allocated or not, as Linux's `user->pipe_bufs` counts them (`pipe_user_pages`), from each pipe's charge, `nr_accounted`. For a caller without privilege, a new pipe has at most `pipe_max_size`, and `PIPE_MIN_PAGES`, 8 KiB, once its user's pages with it would pass `pipe_user_pages_soft`, and none at all past `pipe_user_pages_hard` (`pipe_publish`). The sum and the new pipe's charge, and a resize's check and charge (`pipe_charge`), are each one hold of the list's lock, `pipes_lock`, as Linux's `account_pipe_buffers` adds and reads the user's count in one step, so two pipes of one user cannot both pass a limit only one fits under; a resize that fails gives its charge back. `fcntl(F_SETPIPE_SZ)` gives a pipe a power of two of a page or more in `size` (`pipe_set_size`), copying the bytes it holds into a ring allocated then, as GNU cat asks for 512 KiB before it splices: without it each splice moved 64 KiB, and each took the big lock. A caller without privilege may grow a ring up to `pipe_max_size` while its user's pages stay within both limits. The three are Linux's files under `/proc/sys/fs`, with Linux's values at boot: `pipe-max-size`, 1 MiB, which a write sets rounded as Linux's `round_pipe_size` rounds it (`pipe_round_size`); `pipe-user-pages-soft`, 16384 pages, 64 MiB; and `pipe-user-pages-hard`, 0, no limit. `head` and `tail` are 32-bit counts of the bytes consumed and produced; the occupancy is the unsigned difference `tail - head`, correct across wraparound, and a counter masked by `size - 1` is a slot. Over the ring the pipe keeps Linux's page buffers (`buf_pages`), each the counter value of its first byte, that byte's offset in its page and whether a later write may join it, and a shrink may not go below them, as `pipe_resize_ring` refuses it with EBUSY however few bytes they hold. A write's first `count` mod 4096 bytes join the newest buffer when it takes writes and they fit in its page after its offset and the bytes written to it, and the rest of the write opens a page each. A `writev` to a pipe is one such write of the vector's total (`pipe_writev`), each page it opens filled across the elements, as Linux runs a vector through one `pipe_write`. Its elements are checked first only to lie in user space, as Linux's `access_ok` checks them. A write commits the bytes that join the newest buffer, and each page it opens, whole once the group is full or the write is spent, as Linux's `pipe_write` commits a page (`pipe_put_vec`): the group is copied past the tail, and only then is the tail moved past it. A page the caller cannot read, one below the lowest user address among them, ends the write with the groups before its own, or EFAULT, and none of its own group's bytes can be read, as Linux leaves an unfinished page empty; a write of `PIPE_BUF` bytes or fewer is one group, so no other writer's bytes come between its own. A page group that faults leaves its buffer in the ring with no bytes (`pipe_buf_fault`), as Linux's `pipe_write` moves `pipe->head` past an empty buffer before its copy and leaves it there after a fault: the readers are woken, poll reports `POLLIN`, the buffer takes a slot, and a later write's first `count` mod 4096 bytes join it, until a read with room left reaches it and lets it go (`pipe_buf_skip_empty`), as Linux's `pipe_read` does, then waiting or failing with `EAGAIN` if nothing else is buffered; a splice to a file or a socket and vmsplice let go of such buffers at the front before they wait for bytes, as Linux's `splice_from_pipe_next` eats them. A tee links them into the other pipe and a splice between pipes moves them, each taking a slot there, as Linux's `link_pipe` and `splice_pipe_to_pipe` do, and both wait only while the source holds no buffer at all; a tee that linked only empty buffers returns 0, and a splice that moved only empty buffers waits for more or fails with `EAGAIN`. Into a pipe with no reader both fail with `EPIPE` and SIGPIPE, from an ended empty source too, as Linux's `link_pipe` and `splice_pipe_to_pipe` check the output's readers before the input's end. vmsplice and a splice from a file open a buffer for each page of their source, as Linux links the source's pages, and no later write joins one. A splice between pipes opens one for each buffer of the source it reaches, and a buffer it moves whole keeps taking writes if it did, as Linux's `splice_pipe_to_pipe` moves it with its flags; a part of one, and every buffer tee links, takes none. A buffer leaves once read whole, and an empty one once a read passes it. A `read` or a `readv` of a pipe is one read of its vector (`pipe_readv`), as Linux runs both through one `pipe_read`: the wait, the end of input and `EAGAIN` come first, so a buffer that cannot be written reads 0 from an ended pipe; then each buffer is copied whole, or as much of it as the vector takes, and only then is the head moved past it. A page the caller cannot write ends the read with the buffers before it, or EFAULT, and every byte of its own buffer stays queued, as Linux's `pipe_read` advances a buffer only once `copy_page_to_iter` has copied it. A write, a splice, a tee and vmsplice open a buffer only while fewer buffers than the ring's pages hold bytes, as Linux's `pipe_full` stops them at `max_usage` however few bytes the buffers hold (`pipe_slots_free`), so sixteen one-byte vmsplices fill a pipe of 64 KiB, and a write after them waits, or fails with `EAGAIN` under `O_NONBLOCK`; only a write's bytes that join the newest buffer pass a full ring, and poll reports `POLLOUT` by the same rule. The ring's operations are in `pipe_ring.c`, which has no kernel dependency, so the host test links the same code.

A read waits only before its first byte and takes at most the bytes available then; a write waits whenever the ring is full until its whole count is copied. Each holds the pipe's sleeping lock (`lock`, Linux's `pipe->mutex`, of the kind `pipe` in `/proc/fs/lockwait`) from its start to its return and gives it back only while it waits for bytes or room (`pipe_sleep`), so while it brings a page in no other reader takes the next buffer, no writer grows the one being read, and no other write's bytes come between a write's own. A splice's use of a ring (`pipe_put`, `pipe_splice_room`, `pipe_splice_peek`, `pipe_splice_consume`), `F_SETPIPE_SZ`, `FIONREAD`, a close and a FIFO's open take the lock too, as Linux's `pipe_release` and `fifo_open` take `pipe->mutex`, and a tee takes both pipes' locks, the lower address first and the second at subclass 1, as Linux's `pipe_double_lock`; so the ring, the counts of ends and the opens change only under the lock, and a call that holds it sees them change only while it waits, and judges them again when it wakes. Poll and the wait conditions read them with no lock, as Linux's `pipe_poll` does, since a waiter is on its queue before it reads them and every change wakes the queue after it. A read into a null pointer reaches the pipe, as Linux's `vfs_read` passes it, so an ended pipe returns 0 and an empty nonblocking one `EAGAIN` before the copy faults. A read moves a buffer at a time and a write a group at a time, as above, a page of user memory at a time, each page brought in and copied under the address space's regions' lock (`copy_to_user`, `copy_from_user`), which may sleep with the pipe's lock held, as Linux's copies fault under `pipe->mutex`; another thread's unmap comes before or after a page's copy, and a page it took away ends the transfer with `EFAULT` or the count before it. A splice or vmsplice into a pipe (`pipe_put`) makes one page of its source present (`vm_prefault_range`) and copies a span that crosses neither the ring's end nor that page. The dispatcher records an `EINTR` from a wait for restart, as [the signal document](../proc/signal.Readme.md) describes.

The operations of a pipe end are `FILE_OPS_UNLOCKED` (`fs/file.h`): `read`, `write`, `readv`, `writev`, `ioctl`, `poll`, `fstat` and `close` of an anonymous pipe's end run without the big lock, as Linux's pipes run under `pipe->mutex` alone. A FIFO's description names its file, whose release is the file system's, so its calls but poll still take the big lock (`file_ops_unlocked`), and the pipe's own locks are taken under it; poll runs without it for a FIFO too (`FILE_OPS_POLL_UNLOCKED`). SIGPIPE is the signal state's, which the big lock keeps: a write, a splice or a tee into a pipe with no reader posts it once it has given the pipes' locks back, taking the big lock for the post when it runs without it (`pipe_sigpipe`), since the big lock comes before every pipe's lock in the order ([the process document](../proc/Readme.md#locking)). `pipe2` and the splice calls take the big lock, and the pipe's locks under it. The list of live pipes, the next inode number, and each pipe's `files` and `nr_accounted` are kept under `pipes_lock`, a spinlock taken under a pipe's lock or none, under which nothing else is taken.

A read wakes the write end's queue for room after each transfer, a write wakes the read end's queue for data after each transfer, whether the ring had data or not, and a close wakes the other end for every kind of change (`wq_wake` in `proc/wait_queue.h`), so each change reaches an edge-triggered epoll registration that watches its kind. Readiness reports each condition that ends a read's or a write's wait, as Linux does:

* The read end is readable (`POLLIN`) while data is buffered, and reports `POLLHUP` once no writer is left, whatever events were asked for. An empty pipe with no writer, whose read returns 0, reports `POLLHUP` alone; `select` counts it as readable. A FIFO reader opened with `O_NONBLOCK` and no writer reports no hangup until a writer has opened since that read open. Its description saves `write_opens`, so a new read open starts that wait again while older readers still report hangup.
* The write end is writable (`POLLOUT`) while a byte and a buffer's slot are free (`pipe_slot_room`), as Linux's `pipe_full` judges it, or no reader is left, and reports `POLLERR` once no reader is left, whatever events were asked for.

`splice`, `tee`, `vmsplice` and `sendfile` ([splice(2)](../../../man/man2/splice.2), [the file system layer](../fs/Readme.md#copies-between-descriptors)) use six more operations of a pipe end. `pipe_splice_write` is the write with the wait for room chosen by its caller, `SPLICE_F_NONBLOCK` or the description's `O_NONBLOCK` for splice and `SPLICE_F_NONBLOCK` alone for vmsplice, as Linux's `sys_vmsplice` passes the caller's flags unchanged; it waits only before its first byte, in `pipe_wait_writable`, and returns what fitted once the ring fills, as Linux's `wait_for_space` and `iter_to_pipe` do. `pipe_vmsplice_write` is that write from the caller's memory, which also refuses a page Linux's `get_user_pages` refuses, `[vvar]` among them, and one of a mapping without `PROT_READ` that was not present before the call or is the zero page (`paging_pin_allows`, judged under the regions' lock), with `EFAULT` or the count before it. `pipe_splice_room` waits for room before a copy reads its source, and gives the bytes the free slots take from the source's offset in its page, no more than the bytes free. `pipe_splice_peek` copies buffered bytes into a kernel buffer without taking them and holds the pipe (`spliced`), and `pipe_splice_consume` takes as many as were written and ends the hold. While a splice holds a pipe, its other readers, a `read`, another splice and a `tee`, wait on `splice_wq`, even with `O_NONBLOCK`, as Linux's wait for the pipe's lock, so no byte goes to two readers. `pipe_tee` copies from one ring to another, for `tee`, or moves, for a `splice` between pipes, up to as many of the source's buffers as the destination has free slots, with no sleep between the check of both rings and the copy.

A poller waits on its end's queue; a FIFO opened for reading and writing is both ends, and its pollers wait on `rdwr_wq`, which every change of either end wakes (`pipe_wake`). `FIONREAD` reports the bytes buffered, `ioctl`'s common layer answers `FIONBIO`, and other requests are `ENOTTY`. `lseek` and `_llseek` fail with `ESPIPE`. `fstat` reports `S_IFIFO`, mode 0666, and an inode number that is nonzero and differs from every other live pipe's (`pipe_next_inode`), which `/proc/PID/fd` shows as `pipe:[inode]`.

### FIFOs

`open` of a node of type `S_IFIFO` reaches `fifo_attach` through `open_fifo` in `syscall_fs.c`, after the permission check, with the walk's lock released and the mount kept busy by the description. Each FIFO file has one pipe, made at its first open and freed when no end is open. `fifo_get` finds it, or makes and publishes it, under `pipes_lock`, counting the open in its `files` in the same hold, and drops a pipe it made while the lock was let go for one another open published meanwhile, as Linux's `fifo_open` finds or makes `inode->i_pipe` under `i_lock`; `fifo_find` finds it by the mount and a number unique to the file while an end is open: the inode number on a mounted file system, and on the KRFFS root, which numbers a file by its directory and the hash of its name, the node's address. The mount is the base of a bind (`vfs_mount_base`), and a bind of the root keys a FIFO by its node too, so every name of the file reaches one pipe. A FIFO has no bytes, so its node never moves, and one unlinked while open keeps its node until its last end closes (`fd_node_holders`), so no later FIFO takes its address; the last close frees it whichever mount the end was opened through. A blocking open sleeps on `open_wq` until the other end's count of opens changes.

### AF_UNIX sockets

`socket_dispatch` in `syscall_net.c` sends `socket` and `socketpair` of `AF_UNIX`, and every socket call on a descriptor of type `FD_TYPE_UNIX`, to `unix.c`; `read`, `write`, `poll`, `ioctl` and the last close go through `unix_ops`. `readv` is one receive into the whole vector (`unix_readv`), as Linux's `sock_read_iter` gives it to `unix_recvmsg`, so a datagram or sequenced-packet socket takes one message across the elements. A receive whose copy faults keeps a stream's message queued and consumes a datagram's or a sequenced packet's, closing its descriptors, as Linux's `__unix_dgram_recvmsg` frees the skb it dequeued. A `struct unix_sock` comes from the heap and is on one list, `socks`. Its `refs` counts the descriptors' side, each socket connected to it, and an accept queue it is on; the last close ends the descriptors' side (`unix_release`), and the last reference frees the record.

A stream or sequenced-packet connection is two records that point at each other: `connect` makes a new socket joined to the caller and queues it on the listener, so the caller may send before `accept` takes it. A datagram socket may point at one peer. An abstract name is found among the bound sockets of the same type and network namespace. A path is a socket file that `bind` makes and keeps a reference to, as a working directory does, and that `connect` and a send find by mount and inode number.

A message is a `struct unix_msg` on the receiver's queue: its bytes, the sender's name and credentials, and any descriptors sent with `SCM_RIGHTS`, each a copy of the sender's descriptor entry with a reference to its open file description. A stream send is queued in pieces of at most `UNIX_CHUNK` bytes, 65536, so a reader can drain the first while the rest wait. A queue is charged each message's bytes, its record and its descriptor array, as Linux charges an skb's true size, and is full at `rcvbuf` bytes charged, `UNIX_BUF` (212992) by default, so that messages with descriptors fill it long before their count does; `rq_bytes` keeps the unread bytes alone, which `FIONREAD`, `TIOCOUTQ` and `/proc/net/unix` report. A datagram or sequenced-packet queue is full also at more than `UNIX_DGRAM_QLEN` messages, 512, the `net.unix.max_dgram_qlen` of a Linux system under systemd. A message has at most `UNIX_MAX_FDS` descriptors, 253, and a backlog is at most `UNIX_SOMAXCONN`, 4096.

`socketpair`, `accept` and a receive of `SCM_RIGHTS` give a new slot its socket or file only after its number is copied to the caller (`reserve`, `publish`, `put_rights`). A bind holds the socket's bind lock across the file system's sleeps, so a second bind finds the socket bound. A receive holds the receive lock from choosing a message to consuming it, except while it waits for data, so another receiver, or a datagram `connect` that drops the queue, waits while the receive's copy to the caller sleeps in a page fault. `connect` judges both sockets after its last sleep, and a send judges the connection again after its copy.

A descriptor in flight holds its file as a descriptor in a table does, including a boot-root file opened through a bind mount. `unix_inflight_holds` finds one of a KRFFS file on a receive queue, the reap list, or the transit list, where a receive stays while it installs or closes what it took (`transit_enter`). A write that grows a KRFFS file can move its node, and `vfs_repoint` does not update copies in flight, so a copy takes its node from its description (`flight_sync`). A copy of a file of the KRFFS root leaves its place only once its close holds the root's namespace lock (`flight_drop`, `fd_release_lock`), under which the close counts the file's holders and frees a file that has lost its name.

The last close of a socket drops its queue and closes the descriptors on it, and one may be a socket whose queue has the last descriptor of another, and so on. `msg_free` puts a message with descriptors on the reap list, and the outermost call closes them one at a time while the closes it makes add to the list and return, so a chain of sockets is closed in a loop and not in nested calls that would overflow the kernel stack.

A socket's waiters and pollers share its queue, `wq`. A message or a connection queued wakes it for data. Room made in a socket's queue wakes the sockets connected to it for room and its own queue for no kind, since that room changes none of its own events; an accept wakes the listener's queue for no kind too. A close, a shutdown and an error wake every kind.

### System V IPC

`sysv.c` keeps each kind of object in a table of `SYSV_SLOTS` places, 64, one table for every IPC namespace; each object records its namespace, and a lookup sees only the caller's. An id is the place plus a sequence number times `SYSV_SEQ`, 32768, as Linux builds it, so an id refers to one object and not a later one in the same place. Every object begins with `struct sysv_perm`. The get calls share `sysv_lookup`, Linux's `ipcget`; `sysv_may` is Linux's `ipcperms`; the control calls choose an object by id, or by place for the STAT commands (`sysv_target`). They read and write the 64-bit records, and through `ipc` without `IPC_64` the old ones of 16-bit ids and counts (`sysv_rec`). Under `in_compat_syscall` an i386 program on x86-64 gets the i386 records of Linux's compat calls (`ipc32.h`): the old ones, or the 64-bit ones with each time's high word beside its low, and a message whose type is 32 bits (`msg_type_get`).

A segment's memory is a file on the tmpfs of `memfd_create`, which the segment holds through an open file description. `shmat` maps it shared through `mmap_shm`, and `shmdt` unmaps the regions that map it from its start (`munmap_shm`). A detach searches the next segment only when the unmapper returns `EINVAL` for no attachment there; it returns any other error without changing the detach time or last operator. The count of attachments is computed when asked (`shm_attaches`), from the regions of each address space that map the segment from its start. A segment removed while attached is marked `SHM_DEST` and given the key `IPC_PRIVATE`; with no hook at the end of an address space, `shm_reap` frees it at the next call that reads the table after its last attachment goes, where Linux frees it at the last detach. `SHMMAX` is Linux's `ULONG_MAX` less 16 MiB: `0xFEFFFFFF` on i686, and on x86-64 `0xFFFFFFFFFEFFFFFF`, more than a tmpfs file can have ([tmpfs](../fs/tmpfs.Readme.md)), so there tmpfs refuses a larger segment with `ENOMEM`.

A semaphore set and a message queue are in the heap. `semop` applies its operations all at once or not at all (`sem_try`), undoing what it applied when one must wait, and waits on the set's queue for a change of the set's generation count. `SEM_UNDO` adjustments are records on one list for every process, so `SETVAL` and `SETALL` can clear them, and `sysv_exit` applies a process's when its last thread ends. `msg_pick` finds the message a receive's type asks for. A caller that sleeps on a set or a queue holds a reference, so `IPC_RMID` takes the object out of its table, wakes the sleepers with `EIDRM`, and the last reference frees it. A wait that a signal ends returns `EINTR`, as on Linux: `semop` and `semtimedop` are not restarted, even after a handler with `SA_RESTART` (`syscall_restartable` in `syscall.c`), and `msgsnd` and `msgrcv` end as Linux's `ERESTARTNOHAND`, restarted only when no handler runs, as after a stop and a continue (`msg_sleep`). `ipc_ns_gone` removes a namespace's sets and queues, marks its segments removed for `shm_reap`, and takes the names from its POSIX queues.

### POSIX message queues

`mqueue.c` keeps the named queues on one list, `queues`; a name belongs to the IPC namespace it was made in. A queue lives while its name, a descriptor, a waiter or an open of its file holds a reference. A descriptor is of type `FD_TYPE_ANON` with `mq_ops`, and its `O_NONBLOCK` is the description's, which `mq_getsetattr` changes. Its `fstat` is the stat of the queue's file in the `mqueue` file system, on the first mount of the queue's namespace (`mq_fd_ref`), and its `/proc/PID/fd` link is the queue's name (`mq_fd_name`), which the queue keeps after `mq_unlink` for that link. Messages are kept highest priority first, in arrival order within a priority. `mq_notify_now` posts the registered process's signal when a message reaches an empty queue while no receiver waits, as Linux does. `MQ_MSG_MAX` (10) and `MQ_MSGSIZE_MAX` (8192) are a new queue's default count and size and an unprivileged caller's limits, and `MQ_HARD_MSGMAX` (65536) and `MQ_HARD_MSGSIZEMAX` (16 MiB) a privileged caller's; `MQ_QUEUES` (256) limits an unprivileged caller's queues, counted over every namespace.

The `mqueue` file system (`vfs_mqueue_type`) lists the queues of the IPC namespace that mounted it as the files of one sticky directory: a file has its queue's owner, mode and status line, and no link once the name is gone, and `unlink` of it is `mq_unlink`. The type has no create, write or setattr operation. The kernel mounts one for the first namespace at `/dev/mqueue` at boot (`install_permanent` in `fs/vfs.c`).

## Limits

* A pipe write is not atomic at any size: a blocking write copies what fits and then waits, so concurrent writers can interleave even writes of at most `PIPE_BUF` bytes (4096 in musl's `limits.h`), which POSIX requires to be atomic.
* `pipe2` refuses `O_DIRECT`, Linux's packet mode. `splice` copies bytes where Linux moves pages, and reads no socket.
* Nothing collects descriptors in flight, so a socket sent over itself and never received is not reclaimed. `MSG_OOB` is `EOPNOTSUPP`.
* The 64 places of each System V table are shared by every IPC namespace. `msgrcv` with `MSG_COPY` is `ENOSYS`, and `SHM_LOCK` and `SHM_UNLOCK` do nothing.
* `mq_notify` refuses `SIGEV_THREAD`. An `open` with `O_CREAT` in the `mqueue` file system makes no queue, and a queue's owner and mode do not change through its file.

## Tests

`tests/run host` compiles each `tests/host/*_hosttest.c` under AddressSanitizer and UndefinedBehaviorSanitizer. Six cover this directory: `pipe_ring_hosttest.c` links `pipe_ring.c`; `pipe_copy_hosttest.c` runs `pipe.c` with a page resolver that runs a competing pipe operation before it returns a page; `sysv_detach_hosttest.c` runs the detach search and reaper of `sysv.c` against an unmapper that returns errors or success; `unix_hosttest.c` runs `unix.c` and `pipe.c` with another thread's call inside each sleep; `mqueue_hosttest.c` runs the timed waits of `mqueue.c` across settings of the real-time clock; and `ia32_ipc_hosttest.c` checks the i386 System V IPC and message-queue records of `ipc32.h` against the sizes and member offsets of Linux 6.12's i386 layouts. [The host tests' document](../../../tests/host/Readme.md) lists the rows.

The default suite, `tests/run default`, which `make test` runs, boots the test image and runs the programs built from `tests/pipeprobe.c` and `tests/pollprobe.c` on pipes, and from `tests/musl/`: `fifomusl.c` on FIFOs, `unixmusl.c` on AF_UNIX sockets, `ipcmusl.c` on System V objects through `ipc` and the direct calls and on POSIX queues and `/dev/mqueue`, `epollmusl.c` on the kinds of change pipes and sockets report, and `nsmusl.c` on a new IPC namespace; each file's opening comment lists its rows. `tests/musl/pipemusl.c` is staged at `/musl/pipemusl` for a run by hand and is not in the suite.
