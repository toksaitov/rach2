# `ipc/`: pipes, FIFOs, AF_UNIX sockets, System V IPC and POSIX message queues

This directory is the kernel's interprocess communication: anonymous pipes and the pipe behind each FIFO file (`pipe.c`, `pipe_ring.c`), AF_UNIX sockets (`unix.c`), System V shared memory, semaphores and message queues (`sysv.c`), and POSIX message queues with the `mqueue` file system (`mqueue.c`). Each follows Linux's system call interface, so the ported C libraries use it unchanged. The manual pages state what a program sees; this document states how the code provides it.

## Interfaces

* Pipes: `pipe`, `pipe2`, and `open` of a FIFO file; [pipe(2)](../../../man/man2/pipe.2), [open(2)](../../../man/man2/open.2) and [mknod(2)](../../../man/man2/mknod.2).
* AF_UNIX sockets: the socket calls on an `AF_UNIX` socket; [unix(7)](../../../man/man7/unix.7) and [socketcall(2)](../../../man/man2/socketcall.2).
* System V IPC: [ipc(2)](../../../man/man2/ipc.2), [shmget(2)](../../../man/man2/shmget.2), [semget(2)](../../../man/man2/semget.2) and [msgget(2)](../../../man/man2/msgget.2).
* POSIX message queues and the `mqueue` file system: [mq_open(2)](../../../man/man2/mq_open.2).

The pages give the system call numbers. Both architectures register `pipe`, `pipe2`, the direct socket calls, `shmget`, `shmat`, `shmdt`, `shmctl`, `semget`, `semctl`, `msgget`, `msgsnd`, `msgrcv`, `msgctl`, and `mq_open` with its five calls. i686 also registers `ipc`, through which musl reaches every System V object and which alone gives `semop` and the 32-bit `semtimedop`, together with `semtimedop_time64`, `socketcall`, `mq_timedsend_time64` and `mq_timedreceive_time64`. x86-64 has none of those, and registers `semop`, `semtimedop`, and a wrapper in `arch/x86_64/systab.c` that makes `accept` an `accept4` with no flags.

Inside the kernel, `open` calls `fifo_attach`, the KRFFS holder count `unix_inflight_holds`, process exit `sysv_exit`, and the end of a namespace `unix_ns_gone` or `ipc_ns_gone`; procfs reads `unix_snapshot` and `sysv_row_at`, and netlink's socket diagnostics `unix_snapshot`. `unix.c` makes and finds socket files through `fs_socket_bind` and `fs_socket_lookup` in `syscall_fs.c`, and `sysv.c` maps segments through `mmap_shm` and `munmap_shm` in `syscall_proc.c`.

## Design

The code takes no spinlock. Every entry to the kernel runs under its one big lock (`proc/smp.h`), which a context switch passes on, so an object here changes under a call only while that call sleeps, in a wait, a page fault or a file system call, and each path checks again after a sleep what it judged before.

### Pipes

A `struct pipe` (`pipe.h`) comes from the heap and is freed when both ends are closed; there is no fixed count of pipes. Each end is a descriptor of type `FD_TYPE_PIPE` with `pipe_ops`, whose `priv` is the pipe, and an open file description of its own; `pipe_close` runs when the description's last reference goes, and `read_open` and `write_open` count the descriptions open on each end. `pipe_open` reserves both descriptors, copies their numbers to the caller, and only then gives them their ends, as Linux's `do_pipe2` does, so another thread sharing the table cannot use an end while the copy sleeps.

The ring has `PIPE_BUF_SIZE` bytes, 65536, Linux's default capacity, which `fcntl(F_GETPIPE_SZ)` reports, and is allocated at the first write. `head` and `tail` are 32-bit counts of the bytes consumed and produced; the occupancy is the unsigned difference `tail - head`, correct across wraparound, and a counter masked by `PIPE_BUF_SIZE - 1` is a slot. These operations are in `pipe_ring.c`, which has no kernel dependency, so the host test links the same code.

A read waits only before its first transfer and takes at most the bytes available then; a write waits whenever the ring is full until its whole count is copied. Each transfer first makes one page of the user buffer present (`vm_prefault_range`), which can sleep; it then checks the ring again and copies a span that crosses neither the ring's end nor the page, advancing the counter with no sleep between. The dispatcher records an `EINTR` from a wait for restart, as [the signal document](../proc/signal.Readme.md) describes.

A read wakes the write end's queue for room after each transfer, a write wakes the read end's queue for data after each transfer, whether the ring had data or not, and a close wakes the other end for every kind of change (`wq_wake` in `proc/wait_queue.h`), so each change reaches an edge-triggered epoll registration that watches its kind. Readiness matches the conditions that end a read's or a write's wait:

* The read end is readable (`POLLIN`) while data is buffered or no writer is left, and reports `POLLHUP` once no writer is left, whatever events were asked for.
* The write end is writable (`POLLOUT`) while space is free or no reader is left, and reports `POLLERR` once no reader is left, whatever events were asked for.

A poller waits on its end's queue; a FIFO opened for reading and writing is both ends, and its pollers wait on `rdwr_wq`, which every change of either end wakes (`pipe_wake`). `FIONREAD` reports the bytes buffered, `ioctl`'s common layer answers `FIONBIO`, and other requests are `ENOTTY`. `lseek` and `_llseek` fail with `ESPIPE`. `fstat` reports `S_IFIFO`, mode 0666, and an inode number that is nonzero and differs from every other live pipe's (`pipe_next_inode`), which `/proc/PID/fd` shows as `pipe:[inode]`.

### FIFOs

`open` of a node of type `S_IFIFO` reaches `fifo_attach` through `open_fifo` in `syscall_fs.c`, after the permission check, with the walk's lock released and the mount kept busy by the description. Each FIFO file has one pipe, made at its first open and freed when no end is open. `fifo_find` finds it by the mount and a number unique to the file while an end is open: the inode number on a mounted file system, and on the KRFFS root, which numbers a file by its directory and the hash of its name, the node's address. A FIFO has no bytes, so its node never moves, and one unlinked while open keeps its node until its last end closes (`fd_node_holders`), so no later FIFO takes its address. A blocking open sleeps on `open_wq` until the other end's count of opens changes.

### AF_UNIX sockets

`socket_dispatch` in `syscall_net.c` sends `socket` and `socketpair` of `AF_UNIX`, and every socket call on a descriptor of type `FD_TYPE_UNIX`, to `unix.c`; `read`, `write`, `poll`, `ioctl` and the last close go through `unix_ops`. A `struct unix_sock` comes from the heap and is on one list, `socks`. Its `refs` counts the descriptors' side, each socket connected to it, and an accept queue it is on; the last close ends the descriptors' side (`unix_release`), and the last reference frees the record.

A stream or sequenced-packet connection is two records that point at each other: `connect` makes a new socket joined to the caller and queues it on the listener, so the caller may send before `accept` takes it. A datagram socket may point at one peer. An abstract name is found among the bound sockets of the same type and network namespace. A path is a socket file that `bind` makes and keeps a reference to, as a working directory does, and that `connect` and a send find by mount and inode number.

A message is a `struct unix_msg` on the receiver's queue: its bytes, the sender's name and credentials, and any descriptors sent with `SCM_RIGHTS`, each a copy of the sender's descriptor entry with a reference to its open file description. A stream send is queued in pieces of at most `UNIX_CHUNK` bytes, 65536, so a reader can drain the first while the rest wait. A queue is full at `rcvbuf` bytes, `UNIX_BUF` (212992) by default, and a datagram or sequenced-packet queue also at more than `UNIX_DGRAM_QLEN` messages, 10. A message has at most `UNIX_MAX_FDS` descriptors, 253, and a backlog is at most `UNIX_SOMAXCONN`, 4096.

`socketpair`, `accept` and a receive of `SCM_RIGHTS` give a new slot its socket or file only after its number is copied to the caller (`reserve`, `publish`, `put_rights`). A bind holds the socket's bind lock across the file system's sleeps, so a second bind finds the socket bound. A receive holds the receive lock from choosing a message to consuming it, except while it waits for data, so another receiver, or a datagram `connect` that drops the queue, waits while the receive's copy to the caller sleeps in a page fault. `connect` judges both sockets after its last sleep, and a send judges the connection again after its copy.

A descriptor in flight holds its file as a descriptor in a table does. `unix_inflight_holds` finds one of a KRFFS file on a receive queue, the reap list, or the transit list, where a receive stays while it installs or closes what it took (`transit_enter`). A write that grows a KRFFS file can move its node, and `vfs_repoint` does not update copies in flight, so a copy takes its node from its description (`flight_sync`). A copy of a file of the KRFFS root leaves its place only once its close holds the root's namespace lock (`flight_drop`, `fd_release_lock`), under which the close counts the file's holders and frees a file that has lost its name.

The last close of a socket drops its queue and closes the descriptors on it, and one may be a socket whose queue has the last descriptor of another, and so on. `msg_free` puts a message with descriptors on the reap list, and the outermost call closes them one at a time while the closes it makes add to the list and return, so a chain of sockets is closed in a loop and not in nested calls that would overflow the kernel stack.

A socket's waiters and pollers share its queue, `wq`. A message or a connection queued wakes it for data. Room made in a socket's queue wakes the sockets connected to it for room and its own queue for no kind, since that room changes none of its own events; an accept wakes the listener's queue for no kind too. A close, a shutdown and an error wake every kind.

### System V IPC

`sysv.c` keeps each kind of object in a table of `SYSV_SLOTS` places, 64, one table for every IPC namespace; each object records its namespace, and a lookup sees only the caller's. An id is the place plus a sequence number times `SYSV_SEQ`, 32768, as Linux builds it, so an id refers to one object and not a later one in the same place. Every object begins with `struct sysv_perm`. The get calls share `sysv_lookup`, Linux's `ipcget`; `sysv_may` is Linux's `ipcperms`; the control calls choose an object by id, or by place for the STAT commands (`sysv_target`), and use only the 64-bit layouts.

A segment's memory is a file on the tmpfs of `memfd_create`, which the segment holds through an open file description. `shmat` maps it shared through `mmap_shm`, and `shmdt` unmaps the regions that map it from its start (`munmap_shm`). A detach searches the next segment only when the unmapper returns `EINVAL` for no attachment there; it returns any other error without changing the detach time or last operator. The count of attachments is computed when asked (`shm_attaches`), from the regions of each address space that map the segment from its start. A segment removed while attached is marked `SHM_DEST` and given the key `IPC_PRIVATE`; with no hook at the end of an address space, `shm_reap` frees it at the next call that reads the table after its last attachment goes, where Linux frees it at the last detach. `SHMMAX` is Linux's `ULONG_MAX` less 16 MiB: `0xFEFFFFFF` on i686, and on x86-64 `0xFFFFFFFFFEFFFFFF`, more than a tmpfs file can have ([tmpfs](../fs/tmpfs.Readme.md)), so there tmpfs refuses a larger segment with `ENOMEM`.

A semaphore set and a message queue are in the heap. `semop` applies its operations all at once or not at all (`sem_try`), undoing what it applied when one must wait, and waits on the set's queue for a change of the set's generation count. `SEM_UNDO` adjustments are records on one list for every process, so `SETVAL` and `SETALL` can clear them, and `sysv_exit` applies a process's when its last thread ends. `msg_pick` finds the message a receive's type asks for. A caller that sleeps on a set or a queue holds a reference, so `IPC_RMID` takes the object out of its table, wakes the sleepers with `EIDRM`, and the last reference frees it. A wait that a signal ends returns `EINTR` and is not restarted, even after a handler with `SA_RESTART`, as on Linux (`syscall_restartable` in `syscall.c`). `ipc_ns_gone` removes a namespace's sets and queues, marks its segments removed for `shm_reap`, and takes the names from its POSIX queues.

### POSIX message queues

`mqueue.c` keeps the named queues on one list, `queues`; a name belongs to the IPC namespace it was made in. A queue lives while its name, a descriptor, a waiter or an open of its file holds a reference. A descriptor is of type `FD_TYPE_ANON` with `mq_ops`, and its `O_NONBLOCK` is the description's, which `mq_getsetattr` changes. Its `fstat` is the stat of the queue's file in the `mqueue` file system, on the first mount of the queue's namespace (`mq_fd_ref`), and its `/proc/PID/fd` link is the queue's name (`mq_fd_name`), which the queue keeps after `mq_unlink` for that link. Messages are kept highest priority first, in arrival order within a priority. `mq_notify_now` posts the registered process's signal when a message reaches an empty queue while no receiver waits, as Linux does. `MQ_MSG_MAX` (10) and `MQ_MSGSIZE_MAX` (8192) are a new queue's default count and size and an unprivileged caller's limits, and `MQ_HARD_MSGMAX` (65536) and `MQ_HARD_MSGSIZEMAX` (16 MiB) a privileged caller's; `MQ_QUEUES` (256) limits an unprivileged caller's queues, counted over every namespace.

The `mqueue` file system (`vfs_mqueue_type`) lists the queues of the IPC namespace that mounted it as the files of one sticky directory: a file has its queue's owner, mode and status line, and no link once the name is gone, and `unlink` of it is `mq_unlink`. The type has no create, write or setattr operation. The kernel mounts one for the first namespace at `/dev/mqueue` at boot (`install_permanent` in `fs/vfs.c`).

## Limits

* A pipe write is not atomic at any size: a blocking write copies what fits and then waits, so concurrent writers can interleave even writes of at most `PIPE_BUF` bytes (4096 in musl's `limits.h`), which POSIX requires to be atomic.
* `F_SETPIPE_SZ` is `EINVAL`, and `pipe2` refuses `O_DIRECT`, Linux's packet mode. `splice` and `tee` fail with `EINVAL` ([splice(2)](../../../man/man2/splice.2)), and `vmsplice` is not registered.
* Nothing collects descriptors in flight, so a socket sent over itself and never received is not reclaimed. `MSG_OOB` is `EOPNOTSUPP`.
* The 64 places of each System V table are shared by every IPC namespace. `msgrcv` with `MSG_COPY` is `ENOSYS`, and `SHM_LOCK` and `SHM_UNLOCK` do nothing.
* `mq_notify` refuses `SIGEV_THREAD`. An `open` with `O_CREAT` in the `mqueue` file system makes no queue, and a queue's owner and mode do not change through its file.

## Tests

`tests/run host` compiles each `tests/host/*_hosttest.c` under AddressSanitizer and UndefinedBehaviorSanitizer. Four cover this directory: `pipe_ring_hosttest.c` links `pipe_ring.c`; `pipe_copy_hosttest.c` runs `pipe.c` with a page resolver that runs a competing pipe operation before it returns a page; `sysv_detach_hosttest.c` runs the detach search and reaper of `sysv.c` against an unmapper that returns errors or success; and `unix_hosttest.c` runs `unix.c` and `pipe.c` with another thread's call inside each sleep. `sh tests/host/pipe_copy_mutate.sh` and `sh tests/host/unix_mutate.sh` undo, one at a time in a private copy of the source, each fix those rows check, and each mutation must fail its row. `sh tests/host/sysv_detach_mutate.sh` proves that an unmap failure ends the detach search without changing metadata or reaping segments. [The host tests' document](../../../tests/host/Readme.md) lists the rows.

The default suite, `tests/run default`, which `make test` runs, boots the test image and runs the programs built from `tests/pipeprobe.c` and `tests/pollprobe.c` on pipes, and from `tests/musl/`: `fifomusl.c` on FIFOs, `unixmusl.c` on AF_UNIX sockets, `ipcmusl.c` on System V objects through `ipc` and the direct calls and on POSIX queues and `/dev/mqueue`, `epollmusl.c` on the kinds of change pipes and sockets report, and `nsmusl.c` on a new IPC namespace; each file's opening comment lists its rows. `tests/system/probe_faults.txt` has faults in `pipe.c`, `unix.c`, `sysv.c` and `mqueue.c`, each of which must fail a row of that suite; `sh tests/system/probe_faults.sh NAME` runs one. `tests/musl/pipemusl.c` is staged at `/musl/pipemusl` for a run by hand and is not in the suite.
