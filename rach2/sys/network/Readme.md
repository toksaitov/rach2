# `network/`: the IPv4 and IPv6 network stack

The network stack connects the machine to Ethernet and wireless station interfaces: drivers for three cards, Ethernet, ARP, IPv4 with a routing table, ICMP, UDP and TCP, IPv6 with ICMPv6, UDP and TCP, neighbour discovery, address autoconfiguration and MLD, the sockets programs open on them, packet, raw and netlink sockets, and netconsole, which sends the kernel log to UDP targets and broadcasts it. It exists so that programs written for Linux, Dropbear and the DHCP clients among them, reach QEMU's user network and a real LAN through Linux's socket calls and configuration interfaces. The C is the same on i686 and x86-64; the architectures differ in how a program enters the socket calls and in the layout of the structures it passes. AF_UNIX sockets are in [`ipc/`](../ipc/Readme.md).

## Interfaces

The wireless registry, station Ethernet conversion, control port and radio contracts are described in [`wireless/Readme.md`](wireless/Readme.md). Wireless interfaces use the same IP, ARP and socket paths as the cards. Enumeration positions are separate from stable interface indexes: `netdev_at` enumerates cards and radios, then loopback, while `netdev_by_index` resolves an index. Attaching and removing a radio keeps the other interface records and indexes unchanged. IPv6 discovery and multicast state use bounded private slots, reset when a new interface takes a slot.

### System calls

A program uses Linux's socket calls, each with its page in the manual: [socket(2)](../../../man/man2/socket.2), which lists the families and types, [bind(2)](../../../man/man2/bind.2), [connect(2)](../../../man/man2/connect.2), [listen(2)](../../../man/man2/listen.2), [accept(2)](../../../man/man2/accept.2), [getsockname(2)](../../../man/man2/getsockname.2), [send(2)](../../../man/man2/send.2), [recv(2)](../../../man/man2/recv.2), [setsockopt(2)](../../../man/man2/setsockopt.2) and [shutdown(2)](../../../man/man2/shutdown.2). Both architectures register the direct calls Linux defines for them. i686 also has `socketcall`, call 102, which takes an operation number and an array of arguments ([socketcall(2)](../../../man/man2/socketcall.2)); x86-64 has none. [syscalls(2)](../../../man/man2/syscalls.2) gives the numbers. [ping(2)](../../../man/man2/ping.2), Rach2's private echo request, is `socketcall` operation 0x1000, 0x1001 or 0x1002, for IPv6, on i686 and call 400, `rach2_ping`, on x86-64. Each call reaches `socket_dispatch` in [`../syscall_net.c`](../syscall_net.c), which passes a call on an AF_UNIX socket to `ipc/unix.c`.

### Configuration

* The network-interface requests of [ioctl(2)](../../../man/man2/ioctl.2): addresses, masks, flags, MTUs, routes and ARP entries, and, on an `AF_INET6` socket, IPv6's addresses and routes, as BusyBox's `ifconfig` and `route -A inet6` give them.
* [netlink(7)](../../../man/man7/netlink.7): the requests of `ip` and `ip -6`, glibc's `getifaddrs` and `ss`, the notifications `ip monitor` and the watchers of a network change hear, and the kernel's uevents and udevd's relays on NETLINK_KOBJECT_UEVENT, with SCM_CREDENTIALS under SO_PASSCRED.
* [tap(4)](../../../man/man4/tap.4): `/dev/net/tun`, an Ethernet interface whose wire is a descriptor, as QEMU's `-netdev tap` uses it; [vhost-net(4)](../../../man/man4/vhost-net.4): `/dev/vhost-net`, which moves a guest's virtio frames between its rings and a tap inside the kernel, as QEMU's `vhost=on` uses it; and `/sys/bus/pci/drivers/e1000` and `r8169`, whose `bind` and `unbind` give a card to vfio-pci and take it back ([sysfs(5)](../../../man/man5/sysfs.5)).
* `/proc/net/*` and `/proc/sys/net/ipv6/conf` in [proc(5)](../../../man/man5/proc.5) and `/sys/class/net` in [sysfs(5)](../../../man/man5/sysfs.5); [ipv6(7)](../../../man/man7/ipv6.7) and [icmp6(7)](../../../man/man7/icmp6.7) describe the IPv6 stack as a program sees it.
* The boot line: [cmdline.md](../../cmdline.md) lists `rach2.ip=`, `rach2.gateway=`, `rach2.ifaddr=`, `netconsole=`, `rach2.netconsole`, `rach2.nonet` and `rach2.nicfail=`; [netconsole(4)](../../../man/man4/netconsole.4) gives netconsole's two forms.

With no address option the first interface takes QEMU's user network, SLIRP: 10.0.2.15/24 through 10.0.2.2 (`net.h`). `rach2.ip=A.B.C.D/prefix` replaces it, with no gateway unless `rach2.gateway=A.B.C.D` gives one, and `rach2.ip=none` leaves the interface unconfigured for a DHCP client. `netconf_apply` (`netconf.c`) refuses an option given twice, a gateway with no address or beside `none`, a number above 255 or with a leading zero, trailing text, a prefix outside 1 to 32, a first octet of 0, 127, or 224 and above, the subnet's network or broadcast address, and a gateway that is not another host of the subnet; a refusal logs `net: address refused: REASON` and keeps the SLIRP configuration. `rach2.ifaddr=MAC,A.B.C.D/prefix[,GATEWAY]`, once per card, configures the card with that station address under the same rules, after the probe, whatever order the cards were found in; a token that does not parse, is longer than 79 characters or names no card is logged and skipped.

The same rules judge an Ethernet address without a peer set or added while the machine runs, by `ifconfig`, `ip addr` or netlink (`netconf.c`), and the static stanzas and leases `netup` and `dhcpc` check first (`utils/ipcheck.c`). A /31 and a /32 have no network or broadcast address, as on Linux: every address of theirs is a host (RFC 3021), so either address of a /31 may be the interface's and the other its gateway, and an Ethernet /32 without a peer implies no link route. For a TUN the IPv4 local address and peer are distinct configuration fields, carried as IFA_LOCAL and IFA_ADDRESS over rtnetlink. An address with a peer implies a direct route to the peer's prefix, including a /32 host route, while the interface is up. SIOCGIFDSTADDR and SIOCSIFDSTADDR read and set the first address's destination.

### Inside the kernel

* `init_network` (`net.h`) brings the stack up at boot, after PCI enumeration and interrupts, unless the boot line has `rach2.nonet`, and returns 1 when a card came up; boot then calls `netconsole_setup` for `netconsole=`, which starts the frames too when `rach2.netconsole` is given, or `netconsole_enable` for `rach2.netconsole` alone.
* The boot processor's scheduler tick, 250 Hz on physical machines and in guests, and its service events, which come at the services' own deadlines whether it is busy or idle ([the timer](../arch/x86/Readme.md)), call `netdev_poll`, `netconsole_tick`, `tcp_tick`, `ip_frag_tick`, `ip6_tick`, `netlink_tick` and `ip_loop_drain`, in that order (`kernel.c`). The return to user mode of a thread that put a datagram on the loopback backlog, a thread's end and the idle wait also drain the backlog.
* `kernel_shutdown` calls `netconsole_shutdown` after its last log record and then stops every card; `k_panic` calls `netconsole_panic`, and `klog` gives every record to `netconsole_putc` from a processor that holds the big lock, so that a record written out for a holder that is locked up (`klog_flush_stuck`) reaches netconsole once that holder, back, or the panic writes klog again.
* `poll`, `ioctl` and `procfs` reach the stack through `socket_poll`, `netif_ioctl`, and copies made under the lock such as `tcp_snapshot`.

A driver implements `struct netdev_ops` (`driver/netdev.h`). `init(nd, nth)` brings up its `nth` card as the interface `nd` and returns `NETDEV_UP`, `NETDEV_ABSENT` for no such card, having touched nothing, or `NETDEV_FAILED` with `error` giving the reason. `tx` sends one frame without its frame check sequence and reports whether the card took it. `poll` is null for a card that interrupts. `stop` turns the receiver and transmitter off, masks the card's interrupts and clears PCI bus mastering, and must be safe on a card that never finished starting and safe to call twice. `link` reports the link, or 0 when the card cannot tell, which `IFF_RUNNING` takes as up. The interface asks it at most once in two seconds while the link stays up, and at every look while it is down (`netdev_running`), as Linux reads a card's carrier from the state its driver keeps and not from the card (`netif_carrier_ok`): under KVM a register read is served in QEMU's process and waits for QEMU's main lock, some 300 us while a virtio GPU works. A driver whose card interrupts on a link change makes the interface ask at the next look (`netdev_carrier_changed`), as the e1000's handler does, and so does a change of the interface's administrative state. A driver gives each received frame to `ethernet_rx` with its interface and reports one it refused through `ethernet_note_rx_error` or `ethernet_note_rx_drop`.

## Design

### The interface record and the probe

An interface is `struct netdev`: the driver's operations and record for the card, the name and index, the station address, the first address with its mask and gateway, up to `NETDEV_ADDRS` (7) more addresses with their masks, the counters, whether an administrator has it up, and its MTU. A kernel drives at most `NETDEV_MAX` (4) cards.

A card's MTU is 1500 from the probe, or the largest a virtio device gives with `VIRTIO_NET_F_MTU` when that is less, which is then the most the interface takes, as Linux sets both from it. `SIOCSIFMTU` and netlink's `IFLA_MTU` set it through `netdev_set_mtu` to anything from 68 to 1500, Linux's range for Ethernet without jumbo frames, and refuse any other with `EINVAL`; `lo` takes only its own 65536. `SIOCGIFMTU`, netlink and `/sys/class/net/*/mtu` report it. IPv4 output fragments by it, IPv6 takes it as the link's MTU, a router's advertised MTU only lowering it, TCP offers it less the headers, and `ethernet_tx` and a packet socket refuse an IPv4, IPv6 or ARP payload past it. A DHCP lease's interface MTU, option 26, reaches it through the clients' `SIOCSIFMTU`: BusyBox's `udhcpc` asks for it under `udhcpc_opts -O mtu` in `/etc/network/interfaces` and its script applies it, and os-simple's `dhcpc` asks for it always.

`netdev_probe` (`driver/netdev.c`) asks the drivers in the order of its table, RTL8139, e1000, RTL8168GU, virtio, each for its cards until it answers absent, and names the cards that come up `eth0` upward, with indexes from 1; on a machine with an RTL8139 and an e1000, `eth0` is the RTL8139, and a PC's card comes before a virtio device, so a machine that gives its virtio device to a guest keeps the card as `eth0`. A card that fails is stopped, since its bring-up may have enabled bus mastering, and its reason is logged as `net: absent: REASON` when no card came up. The probe goes on to the next card and driver, and gives a driver up after `NETDEV_MAX` failures. `rach2.nicfail=N` makes the Nth card that came up, from zero, fail.

After the cards comes `lo`, with the next index: 127.0.0.1/8 and ::1/128, Linux's loopback type 772 and MTU 65536, always up. The ioctls, netlink, `/proc/net/dev` and `/sys/class/net` list it, and no route uses it; its counters count the loopback backlog, and an IPv4 address, a route of either family or taking it down is `EOPNOTSUPP`.

### The drivers

`driver/rtl8139.c` drives one RTL8139, QEMU's PCI 10ec:8139, through I/O ports. Receive is an 8192-byte ring with a 2064-byte overhang, so a frame that wraps is contiguous; a ring header with a bad status or a length outside 18 to 1518 bytes resynchronizes the ring, and an overflow is counted as a drop and drained. Transmit takes the four descriptors in turn, each with a 1536-byte buffer.

`driver/e1000.c` drives up to `E1000_MAX` (4) Intel 82540EM, PCI 8086:100e, QEMU's default card, through the memory window, with the I/O window for the reset. Its rings have 32 descriptors each, with 2048-byte receive buffers, in frames below 4 GiB. It receives every multicast frame (`RCTL.MPE`), since IPv6 finds its neighbours by groups whose station addresses the card's filter does not hold. Receive takes a frame only whole in one descriptor with its error byte clear, and a full transmit ring is waited on for ten 100-microsecond intervals before the frame is dropped as a stall. It is the descriptor-ring design with nothing added, to read before the RTL8168.

`driver/rtl8168.c` drives one RTL8168, PCI 10ec:8168, whose `TxConfig` revision is of the GU family, the Lenovo G50-70's chip, which QEMU does not emulate. It is a port of Linux v6.16, commit `038d61fd642278bab63ee8ef722c50d10ab01e8f`, `r8169_main.c` and `r8169_phy_config.c`, for `RTL_GIGA_MAC_VER_42`, without the firmware patch, and each register sequence's comment gives the Linux function it follows. It has 64-descriptor rings and 16383-byte receive buffers. Completions and link changes arrive as message-signalled interrupts where the machine can route them, and a card whose MSI enable fails gives its vector back, with the handler, as its `stop` does after it turns the messages off. The handler masks the card's sources, acknowledges, services the rings at most twice and unmasks, which arms the next message. The tick services the rings too, and alone where messages cannot be routed or after a storm: 16 messages in a row that find a source the acknowledgement does not clear, with the rings empty, leave the sources masked. It advertises 10 and 100 Mbit in both duplexes, 1000 full duplex and pause, and resets the card's tally counters, which a warm restart keeps.

`driver/virtio_net.c` drives up to `VNET_MAX` (4) virtio network devices, QEMU's `virtio-net-pci`, as Linux's `drivers/net/virtio_net.c` does, on the transport, queues and bus of [virtio](../virtio/Readme.md). The device has no registers: a frame is a buffer on a virtqueue behind a 12-byte header, or a 10-byte one on a device the transport drives through its legacy interface (`disable-modern=on`) without mergeable buffers, as Linux's virtnet_probe sizes it, and under a hypervisor a burst of frames costs one notification where an emulated card costs an exit for each register access. The driver asks for `VIRTIO_NET_F_MAC`, `STATUS`, `MTU`, `MRG_RXBUF`, `CTRL_VQ`, `CTRL_RX`, `CTRL_MAC_ADDR`, `MQ` and `SPEED_DUPLEX`, and the core for `VIRTIO_F_EVENT_IDX` and indirect descriptors. It asks for no checksum or segmentation offload: Linux asks for those because its stack can leave a checksum to the device and take a 64 KiB segment, and this stack builds each frame whole with every checksum computed and checks every one it receives, so it could use none of them. The receive queue is kept full of 2048-byte buffers, at most 128, each large enough for the header and a whole frame, so a frame fills one buffer with mergeable buffers or without; a frame that a device still spreads over several is put together by the header's `num_buffers`. A reap delivers every frame the device returned, gives each buffer back, and tells the device of them once at its end, and with the event index the device interrupts once for a burst, which is Linux's NAPI in the shape of this kernel, whose receive path runs in the interrupt. Transmit copies the frame behind a zeroed header into one of at most 64 buffers and notifies as the event index allows; the transmit queue's interrupts are off, and the buffers the device has returned are taken at the next send, as Linux frees its old transmit buffers, with a full pool waited on for ten 100-microsecond intervals before the frame is dropped as a stall. With `VIRTIO_NET_F_MQ` the device has `max_virtqueue_pairs` pairs, each a receive and a transmit queue, with the control queue after the last, and the driver sets up each pair up to `NR_CPUS`, as Linux's virtnet_find_vqs sets up every one; each pair has its own buffers, pool and frame being put together, and the core gives each queue a vector where the interrupt slots allow. One pair for each processor online is filled and used, as Linux's virtnet_probe sets `curr_queue_pairs`, and the device is told their count with `VIRTIO_NET_CTRL_MQ_VQ_PAIRS_SET`, after which it spreads the frames it receives over them; since the boot's probe binds the device before the other processors start, `virtio_net_cpus_started` fills and uses the rest once they have, and sets the count again. A send goes out on the pair of the processor that sends, its number modulo the pairs, as Linux's virtnet_set_affinity gives each processor a transmit queue; a device that refuses the count is sent to on the first pair alone. The control queue sets the receive mode at bring-up, every multicast frame and no promiscuous mode, as the e1000 does, and sets the station address on a device that gave none, which then has a random locally administered one. The link is the configuration's status word, read at bring-up and at each configuration interrupt, which logs `virtio_net: link: virtioN: up` or `down` and announces the carrier; a device without `VIRTIO_NET_F_STATUS` is always up. Each reading and its record are one step under `net_lock`, so an interrupt that arrives in the middle of the bring-up's reading is taken after it and its newer reading stands. The speed and duplex are the configuration's with `VIRTIO_NET_F_SPEED_DUPLEX` and unknown without, when `/sys/class/net/*/speed` reads -1 and `duplex` reads `unknown`, as Linux's. A device with no interrupt at all is reaped from the tick, which also reads its link once in 50 polls, a fifth of a second, so that a cable put in or pulled out is seen there too; the status word is read and not the configuration's generation, which a device need not change until a changed field has been read. The interface's `device` in `/sys/class/net` is a link to the virtio device, `/sys/devices/pci0000:00/0000:BB:DD.F/virtioN`, the parent Linux gives a virtio interface, where a PCI card's is its function; a device without a directory on the virtio bus has its function as the parent, and a link that cannot be made fails the bring-up, as Linux's `device_add` fails `register_netdev`. A write of the function's name to `/sys/bus/pci/drivers/virtio-pci/unbind` stops the device, takes the driver off it, so that vfio-pci may have it, and withdraws the interface, as Linux's virtnet_remove unregisters it (`netdev_withdraw`): it is taken down, its addresses, routes, neighbours and IPv6 state go, a packet socket bound to it reads `ENETDOWN`, and it leaves every list. A card put in after boot through ACPI's PCI hot plug is bound the same way, and one ejected is unbound first ([ACPI](../acpi/Readme.md)). `bind`, or the boot's probe for a device it did not name, brings the device up on a new interface, as Linux's virtnet_probe makes one: `ethN` for the lowest N free (`netdev_name_eth`), a new index, registered with `netdev_register` and down until it is set up. The record of an interface withdrawn keeps no device, so a pointer to it that netconsole or a socket kept reaches nothing the next bind made, and netconsole holds a target whose interface's index no longer names it.

`driver/tap.c` is `/dev/net/tun`, Linux's TUN and TAP device (`drivers/net/tun.c`): interfaces made by `TUNSETIFF` and registered beside the probe's cards with `netdev_register`, as many as the stack takes, each in a record of the heap that is never freed, since the ARP cache keeps a pointer to an interface's name, and that serves the next interface once its own is removed. A TAP is an Ethernet interface; a TUN is an interface of IP datagrams (`l3` in `struct netdev`), Linux's type none with `IFF_POINTOPOINT` and `IFF_NOARP`, which has no station address and on which IPv4 and IPv6 send at once, with neither ARP nor neighbour discovery, duplicate detection or a link-layer option, and whose link-local address has a random identifier from a secret drawn for it, as Linux's `IN6_ADDR_GEN_MODE_RANDOM` (`nd6_random_link_local`). Its driver is given the frame `ethernet_tx` builds, whose header carries only the EtherType, and gives `ethernet_rx` its datagram behind such a header, so the stack's paths stay one and only the counts leave the header out. Each open has a record, Linux's `tun_file`, that every descriptor of the open file description shares, so that a descriptor duplicated before `TUNSETIFF` closes the interface with the others. The interface's `tx` copies the frame into a ring of `TAP_RING` (1024) slots of 1536 bytes, taken when the record first makes an interface and kept once one is registered, which a read empties one frame at a time; Linux's tun queues 1000 (`tx_queue_len`), and with 256 a gateway guest that took 50000 frames a second lost one in two of this stack's acknowledgements. A full ring, or no descriptor, drops the frame, which the caller counts. A read gives a TUN's datagram without the header, and without `IFF_NO_PI` puts Linux's `struct tun_pi` before each frame, its protocol the EtherType and its flags `TUN_PKT_STRIP` for a read that cuts the frame short (`tap_out`). A write, or a `writev` that gathers its vector into one frame (`tap_writev`), gives the frame to `ethernet_rx` under `net_lock`, as a card's interrupt does, after its `struct tun_pi` without `IFF_NO_PI`, and a TUN's datagram as the protocol that header names or, with `IFF_NO_PI`, its IP version gives (`tap_inject`); a `readv` scatters one frame across its vector (`tap_readv`), as Linux's tun_chr_read_iter. `TUNSETIFF` copies the caller's whole `struct ifreq`, 32 bytes for an i386 caller and 40 for an x86-64 one, before its checks, since the copy may sleep and let a call on a duplicate of the descriptor run; from the checks to the open's record nothing sleeps, the ring's allocation among them, so a second call finds the first's interface and answers `EEXIST`, as Linux's. A call refused before it registers an interface keeps no ring; when only its copy of the name back faults, the descriptor keeps the interface it made or took, as Linux's. Making an interface takes `CAP_NET_ADMIN`; attaching one also takes it unless the caller is the owner and in the group that `TUNSETOWNER` and `TUNSETGROUP` gave the interface, of those it has, as Linux's `tun_not_capable`, so an administrator can make a persistent interface for a program that runs without privilege. No virtio header is offered, so `TUNGETFEATURES` leads QEMU to ask for no offload and every frame is whole with its checksums. The carrier is the descriptor; the last close drops the ring and, without `TUNSETPERSIST`, takes the interface down and forgets its addresses, routes, neighbours and IPv6 reassemblies (`ip6_forget_dev`), as the radio layer withdraws its interface, and its record serves the next `TUNSETIFF`. A backend may take the frames in place of the reader (`tap_backend_set`), which is the hook /dev/vhost-net uses.

`driver/vhost_net.c` is `/dev/vhost-net`, Linux's vhost-net (`drivers/vhost/net.c`, `drivers/vhost/vhost.c`): each open is a device with the guest's memory, a receive and a transmit ring, and the tap that `VHOST_NET_SET_BACKEND` gives it, whose backend it becomes. `VHOST_SET_MEM_TABLE` gives each region of QEMU's mapping of the guest's memory a pin that follows QEMU's address space (`PIN_FOLLOW`, [memory](../mm/Readme.md#locked-memory-and-pins)), which holds no page at first, and keeps the pin of a region the old table has whole, since QEMU sends the table again at each change of the guest's memory map; the old table is swapped out under the device's lock and unpinned after it, once no refill of the thread's uses it. Each request but the two that read the features holds the device's mutex, as Linux's `dev->mutex`, since a pin, a release of a held descriptor and `VHOST_RESET_OWNER`'s wait for a refill sleep and let the big lock go: another thread of the owner's that sets a table while a reset waits runs after it, finds no owner and is refused, so no table of the old owner's is left for the next. Guest addresses are translated through the regions and each page reached through `kmap_cpu`, so a ring is read and written in any context. A page the pin does not hold, at its first use or after a change took it, a balloon's discard, a write-back's taking of write access from a shared mapping of a disk file, a copy-on-write or an unmap, is noted on its ring, which then moves nothing: a receive leaves its frame in the tap and a transmit pass leaves its chain on the ring, each with the ring's indices as they were, and the thread brings the page in (`pin_refill`), which may sleep, and kicks the ring to go on, or stops the ring when the page cannot be had, as Linux's copies through QEMU's mappings fault the page in or fail with EFAULT. So the device writes only frames QEMU maps, a writable shared mapping of a disk file is taken as Linux takes it, and nothing counts against `RLIMIT_MEMLOCK`. A ring's 16-bit indices and flags are read and written with one aligned access each, so a guest on another processor never sees half of one. The receive path is the tap's backend call, made with the tap's lock held in whatever context sent the frame, an interrupt handler's among them, without the big lock: it writes a virtio header of no offload with num_buffers 1 and the frame into the next chain the guest offers, puts it on the used ring and signals the ring's call eventfd, which QEMU makes a KVM irqfd, as Linux's `handle_rx` does from its worker; so the device's lock, `vnet`, is over everything that path reads, the regions, the header's length, the tap and the receive ring, and every change of those takes it under the big lock, an unmap's release of a pin among them, which then finds no copy under way. A frame longer than the chain is dropped and the chain left to the guest, as Linux's `vhost_discard_vq_desc`. The receive path sums a chain's room before it copies and checks each descriptor again as it copies, since the guest may change the chain between. The kick, an eventfd the guest's doorbell signals through a KVM ioeventfd, only marks its ring and wakes the kernel thread `vhost-net`, as Linux's `vhost_poll_wakeup` queues work, since its hook runs under the eventfd's lock. The device holds a copy of the tap's descriptor and of each kick's, a reference to its description, as Linux holds their files, so QEMU's close of its own leaves the rings their tap and their kicks; a kick that is replaced is let go only after its replacement is taken, so a refused one leaves the old. The thread, an ordinary one as Linux's worker is, holds the big lock as every kernel thread does: for a kicked transmit ring it gathers each chain, puts it on the used ring, strips the header and gives the frame to `tap_inject`, at most 128 a pass and the pass one batch of TCP's acknowledgements (`tcp_batch_begin`), then signals the call; for a kicked receive ring it drains the frames the tap kept while the ring had no buffer. The device asks the guest for no kicks while a ring has entries and for kicks again only when it finds the ring empty, and for the receive ring keeps them off while the guest has buffers, as Linux's `handle_rx` does, since a kick of it matters only once a frame waits. A bad descriptor stops its ring and signals its error eventfd once. The device counts the frames it moves each way and logs them when it lets the tap go, `vhost-net: detached: tap0: 22 frames to the guest, 21 from it`, which tells a run that QEMU did not fall back to moving them itself. `VHOST_SET_VRING_BUSYLOOP_TIMEOUT` is kept and given back, and the thread does not poll.

A card of the e1000 or the RTL8168 can be given to vfio-pci and taken back (`netdev_release`, `netdev_reclaim`), through `/sys/bus/pci/drivers/e1000` and `r8169`, the names of Linux's drivers of the same cards, which `netdev_sys_start` makes after the probe. Release sets the interface down, puts a table in place of the driver's whose `tx` drops every frame, whose link has no carrier and whose `set_up` refuses to bring it up, stops the card with the driver's `stop` and gives up the function, so that the interface keeps its name, index, IPv4 addresses and the IPv6 addresses it was given; those it learned from routers go, as at any down. Reclaim brings the function to D0 first, since a guest's driver may leave the card in D3hot, as Linux's r8169 does at power-off, and in D3hot its window reads all ones; VFIO's saved state has no power word, and a card with no function-level reset is reset by nobody. It then runs the driver's `init` again, and once more after 100 ms when the first fails, since a card a guest died on may need the first bring-up's reset to start; a card that fails both, or whose function /sys cannot show bound, is stopped and left away. `bind` is `ENODEV` while the function's `driver_override` names another driver, as Linux's match reads the stored text (`vfio_override_allows`). Each driver keeps the window it mapped and its address, so a second bring-up maps nothing new, and unmaps a window at an address the BAR left. The RTL8168's 8168G sequence, and the wait before its second reset, log FIFOs that do not drain and go on, as Linux's `rtl_hw_init_8168g` and `rtl8169_cleanup` do: a card taken back from a guest that died in the middle of a transfer has frames it cannot move with bus mastering off, and the reset after the sequence empties them. Its `stop` reclaims the transmit ring inside `net_lock`, since the handler and the tick reclaim it too, and masks the card's sources a second time once the message vector is freed, since a handler that ran beside the first masking unmasks them as it ends.

`driver/ath9k/` is the driver of Atheros' AR9003 Wi-Fi chips, among them the G50-70's QCA9565, a radio under the wireless station rather than an Ethernet card; [its Readme](driver/ath9k/Readme.md) describes it.

The e1000, RTL8168 and virtio `stop` first waits up to 10 ms for the frames given to the card, so the last log line before shutdown reaches the wire.

### Receive

A driver gives each frame to `ethernet_rx` (`ethernet/ethernet.c`) from its interrupt handler or, for the RTL8168, also from the tick. It drops a frame shorter than 14 bytes and every frame on an interface that is down, counts the rest, offers each ARP, IPv4 and IPv6 frame (`0x86DD`) to the packet sockets, and gives the payload to `arp_rx`, `ip_rx` or `ip6_rx`.

`ip_rx` (`ip/ip.c`) drops a datagram with a bad version, length or header checksum, and skips options. It accepts one for any address of any interface, whichever card it came in on, for a subnet broadcast or 255.255.255.255, and, from the loopback backlog only, for 127/8. It drops one from the wire whose source is this machine's or in 127/8, and gives a broadcast to UDP alone. An accepted datagram is copied to the raw sockets of its protocol, then given to ICMP, UDP or TCP (`ip_deliver`); a unicast UDP datagram for a port no socket has is answered with a port unreachable.

A fragment that passes the same checks goes to `ip_frag_input` (`ip/ipfrag.c`), which keeps it in its datagram's queue, keyed by source, destination, protocol and identification, and gives the datagram whole to `ip_deliver`, its header the first fragment's with the total length set and the fragment fields cleared. A fragment other than the last whose data is not a multiple of 8 bytes, and one that would take the datagram past 65535 bytes, are dropped as header errors. Two fragments that share a byte drop the whole datagram, as Linux drops it, and the queue stays, empty, until its time is out; an exact duplicate is dropped alone. At most `IP_FRAG_QUEUES` (16) datagrams are reassembled at once, each of at most `IP_FRAG_PIECES` (192) fragments, in at most `IP_FRAG_MEM_MAX` (4 MiB, Linux's `ipfrag_high_thresh`) of the heap; a new one takes the place of the one that would time out first. `ip_frag_tick` gives up a reassembly 30 seconds after its first fragment came, as Linux's `ipfrag_time`, and answers it, when the fragment at offset 0 came, with a time exceeded of code 1. `/proc/net/snmp` counts ReasmReqds, ReasmOKs, ReasmFails and ReasmTimeout.

### Transmit and routing

`ip_tx_opts` builds a 20-byte header with the sender's hop limit, refuses a payload over 65515 bytes with `EMSGSIZE`, and sends the datagram:

* To 127/8 or an address an interface has: onto the loopback backlog, whose MTU is `lo`'s, 65536 bytes, so that no datagram needs fragments there.
* To a broadcast address: UDP only, to the all-ones hardware address, by the interface on that subnet, or the first card for 255.255.255.255.
* Otherwise by the route `netdev_route` chooses, to the next hop's hardware address from ARP, or `ENETUNREACH` with no route. On a miss an ARP request goes out and the datagram waits in one of `IP_HOLD_SLOTS` (64) slots, a copy on the heap, for at most three seconds, until the reply sends it, so the first ping or SYN to an uncached host is not lost. A datagram past the MTU waits whole in one slot and is fragmented when it leaves, so that even the 119 fragments of the largest at an MTU of 576 arrive. A datagram that the card's MTU no longer passes when it leaves, since the MTU fell while it waited, as a virtio device bound again with a smaller limit lowers it, leaves in fragments of the MTU as it is then, or, when its sender forbade fragments with `IP_PMTUDISC_DO` or `PROBE`, is dropped and counted in FragFails; IPv6's neighbour queue does the same at the link's MTU, dropping a datagram that was a fragment already, a raw one with its own header or MLD's.

A datagram within its path MTU carries DF, as Linux's path MTU discovery sends it. The path MTU (`ip_path_mtu`, `ip/pmtu.c`) is the interface's MTU, or less for a destination a fragmentation-needed report has lowered: `icmp_rx` gives `ip_pmtu_lower` the MTU of one that quotes a datagram from an address of this machine's, whatever its protocol, but a TCP segment only when its sequence is in flight on its connection (`tcp_in_flight`), since anyone can forge a report. As Linux does, an MTU below 552 (`ip_rt_min_pmtu`) counts as 552, an estimate only falls, and it ages out ten minutes after it last fell (`ip_rt_mtu_expires`); the table holds 16 destinations. A larger datagram leaves in fragments of the most payload the path MTU leaves room for, a multiple of 8 bytes, 1480 at 1500, all with one identification and none with DF, counted in FragOKs and FragCreates (`ip_fragment`), unless its socket set `IP_MTU_DISCOVER` to `IP_PMTUDISC_DO` or `IP_PMTUDISC_PROBE`, when it is `EMSGSIZE` and counted in FragFails. `IP_PMTUDISC_DONT` sends every datagram without DF, and `IP_PMTUDISC_INTERFACE` and `IP_PMTUDISC_OMIT` send every datagram without DF, fragmented by the interface's MTU whatever the path's. TCP's segments fit the path MTU and never fragment.

The routing table (`route.c`) holds the link routes addresses imply, each interface's gateway as its default route, and up to `NETDEV_ROUTES` (32) routes added by `SIOCADDRT` or `RTM_NEWROUTE`. The two route interfaces recognize an implied link route by its exact destination prefix, which comes from the peer when there is one. A TUN's default gateway may lie in any of its link prefixes. A lookup takes, among the routes of interfaces that are up whose prefix covers the destination, the longest prefix, then the lowest metric, then the first found, so an implied route comes before an added one, as on Linux. The source is the connection's or socket's bound address, 127.0.0.1 for 127/8, and otherwise the outgoing interface's address on the next hop's subnet, or its first (`netdev_source`).

A UDP, raw, ICMP or TCP socket bound to a card with `SO_BINDTODEVICE` sends by that card alone (`netdev_route_on`): the lookup takes only its routes, and when none covers the destination, the destination is taken to be on the card's link, as Linux takes it, so that `ping -I wlan0 192.168.0.1` reaches a host on wlan0's network while eth0 holds the default route. A card that is down is `ENETUNREACH`, and an address of this machine's still goes onto the loopback backlog. The source, connect and getsockname follow the same route. An IPv6 datagram of such a socket leaves by the card as if its address had the card's scope. A TCP connection takes the binding its socket has when it connects, or its listener's when it is accepted, and follows a later SO_BINDTODEVICE on its socket (`tcp_bind_device`), a bound connection's segments being matched by their addresses without IPv6 scopes, as Linux matches the binding in place of a scope; its MTU is that of the card's route, its resets and its wait on a refusing card's link follow the same card, and an IPv6 peer whose scope names another card is `EINVAL`. A bound TCP connection or listener takes only the segments that came by its card or off the loopback backlog (`ip_rx_ifindex`), as Linux's lookup compares the binding with the arriving card; a datagram socket's binding does not filter what it receives.

`ethernet_tx` adds the header with the interface's station address, and refuses a payload over 1500 bytes or an IPv4, IPv6 or ARP payload over the interface's MTU, IPv4, IPv6 and ARP on an interface that is down, and every frame for a card whose link is down; each refusal counts as a transmit drop. TCP keeps a refused segment to send again. A UDP or raw sender is told nothing of a refusal (`dgram_sent` in `syscall_net.c`), as on Linux without `IP_RECVERR`: the datagram is lost, as it may be on the way, and a packet socket alone sees `ENOBUFS`.

### Addresses and ARP

An interface answers ARP for each of its addresses, and a datagram to any of them is this machine's. Changing an interface's address (`addr_publish` in `netconf.c`) drops the ARP mappings learned on it, all of them for the first interface, and the datagrams waiting for ARP; clears a gateway it no longer reaches; and removes the added routes whose gateway it no longer reaches. Removing one of several addresses (`netconf_del_address`) keeps the gateway and the added routes, as Linux's `fib_del_ifaddr` does, and removing the last drops them all, as Linux's `fib_disable_ip`. A TCP connection opened from an address that goes is kept, as Linux keeps it (see TCP below).

The ARP cache (`arp/arp.c`) has `ARP_CACHE_SIZE` (16) entries, each with the interface it was learned on, and a lookup matches only on that interface. It learns the sender of every request and reply, unless that address cannot be a host's (a first octet of 0, 127, or 224 and above) or is the receiving subnet's network or broadcast address. A lookup refreshes an entry, and a full cache replaces the learned entry unused longest. No packet or address change touches an entry set by hand as permanent, by `arp -s` or `ip neigh add`; only `arp -d` or `ip neigh del` removes it.

### Loopback

A datagram to this machine never reaches a card. `ip_tx_opts`, or IPv6's transmit for each datagram or fragment it sends, copies it whole into a block of the heap on the loopback backlog, a queue kept in the order sent, as Linux's loopback_xmit hands it to the backlog of `__netif_rx` (net/core/dev.c, `enqueue_to_backlog`), and `ip_loop_drain_from` delivers the backlog through `ip_rx`, or `ip6_loop_rx` for an IPv6 datagram, from the tick, the idle wait, the return to user mode of each thread that put a datagram on it, which marks the thread's work word (`WORK_LOOP`), as Linux's sender raises the softirq its own `local_bh_enable` runs, and a thread's end once its descriptors are closed, since an ending thread reaches no return to user mode. A return that runs without the big lock waits for it before the drain. Delivery waits so that a send's own code never runs the receive path, and TCP, from inside itself, though the boot processor's tick may drain the backlog while a send call is still in progress, once the send has let interrupts in; the drain runs over what a call put on the backlog before the program that made it runs again, unless the drain's budgets, below, end it first; a receive needs no drain of its own. The backlog is Linux's two queues in one list: senders append to the input queue, and a drain, as Linux's `process_backlog`, takes the whole input queue onto the process queue once that is empty and delivers from it, so the datagram being delivered is not on the input queue. A drain delivers in turns of 64, Linux's `dev_rx_weight`, and after each turn ends when `netdev_budget` (300) datagrams are spent or `netdev_budget_usecs` (8000, two ticks) have passed, as Linux's `net_rx_action`, counting the end as a squeeze; its time is a stopwatch (`timer_watch_us`), which reads the reference that keeps the clock, the HPET, the PM timer, KVM's clock or a trusted TSC, and adds each reading's counts to the last, whether or not the processor's cycle counter has a measured rate, as on i686 and under QEMU's emulator. Linux counts this time in jiffies, which its softirq lets the tick advance; the drain holds interrupts off, so no tick counts, and it reads the stopwatch after every delivery instead, one datagram's work apart, far closer than the 4.7 s in which the 24-bit PM timer wraps, so that a turn of any length counts whole, past the counter's wrap and the minute the clock under the tick counts without a tick. What a drain leaves marks the current thread's work, as Linux raises the softirq again, so the thread's next return to user mode, after the interrupts held off meanwhile, drains it, if the idle wait or the tick does not first. Both budgets are written through `/proc/sys/net/core`, the time from two ticks up, as Linux 6.12.115 takes it. The input queue takes a datagram while no more than `netdev_max_backlog` wait on it, 1000 unless written through `/proc/sys/net/core/netdev_max_backlog`, so an echo is answered at a limit of 0, and drops the next as Linux does: the send still succeeds, as loopback_xmit ignores the drop, TCP sends the segment again when it finds it lost, and the drop is counted on the processor in `/proc/net/softnet_stat`'s second column and as `lo`'s receive drop, and logged once. Each processor's line there also counts the datagrams its drains delivered and the drains that ended on either budget; the backlog is the machine's, since the big lock orders its producers and its drain, and the lengths of its two queues are on the boot processor's line. A datagram no memory holds is refused with `ENOBUFS`. The tick also counts in `/proc/stat`, as `loopback_left_idle`, the datagrams it finds on the backlog while every processor is halted in an idle wait: the idle wait of a blocked process (`idle_wait_irq_off`) delivers the backlog before it halts, so each of them waited for the timer with nothing running.

A network namespace other than the first sends on the same ring. Each slot keeps the namespace its datagram was sent in, `ip_ns` while it was put there, and the drain sets `ip_ns` to it around the delivery, so that TCP's lookups, UDP's and the raw sockets match only that namespace's sockets and connections, and a reply goes back into the namespace. A sender sets `ip_ns` from its socket or connection around its call to `ip_tx_opts`, which then reaches only 127/8, while the namespace's `lo` is up with its address; `ip6_tx_opts` reaches nothing. A namespace's own `lo` counts its traffic.

### IPv6

An interface holds up to `NETDEV_ADDRS6` (8) IPv6 addresses, `struct netdev_addr6` (`driver/netdev.h`), each with its prefix length, scope, Linux's `IFA_F_` flags, its maker in Linux's `IFAPROT_` numbers and lifetimes, and is a member of up to `NETDEV_GROUPS6` (16) groups, counted by reference. `netconf_add_address6` (`netconf.c`) joins an address's solicited-node group as it adds it, and a card's address is tentative, neither accepted nor used as a source, until duplicate address detection passes. A card brought up, at boot or by `SIOCSIFFLAGS` or netlink (`netconf_set_up`), joins ff02::1, takes the link-local address fe80::/64 with the modified EUI-64 of its station address, and starts neighbour discovery; `lo` holds ::1. An address whose lifetimes end is deprecated, then removed; the TCP connections opened from it are kept, as an IPv4 address's are.

`ip6_rx` (`ip6/ip6.c`) drops a datagram with a bad version or length, a group as its source, or, from the wire, ::1 at either end or a source of this machine's, and every datagram of an interface with IPv6 disabled. It accepts one for an address an interface holds, a link-local one only on its own interface, for ::1 from the loopback backlog, and for a group the card is a member of. `ip6_walk` then follows the chain of extension headers as RFC 8200, section 4, says. Hop-by-hop options are taken only right after the fixed header, and an option of an unknown type is skipped or answered by the action its top two bits name, a parameter problem of code 2 among them. A routing header with no segment left is skipped, and one with segments left is refused with a parameter problem at its type, since this machine forwards nothing. A next header of no protocol it knows, AH and ESP among them, is answered with a parameter problem at the field that names it. TCP and UDP messages enter the shared transport state machines after the extension headers. An ICMPv6 message is copied to the raw ICMPv6 sockets if its checksum is good, then given to `icmp6_rx` (`ip6/icmp6.c`), which checks the checksum itself, answers an echo request from the address it was sent to, or for a group from the link's own address, gives an echo reply to the kernel's ping, neighbour discovery to `nd6_rx` and MLD to `mld6_rx`. An error this machine sends follows RFC 4443: none about an error, none to a group but a parameter problem of code 2, a quote of at most 1232 bytes, and the IPv4 rate limit.

A fragment goes to `frag6_input` (`ip6/frag6.c`), which keeps it in its datagram's queue, keyed by source, destination, identification and interface, and gives the datagram whole back to `ip6_walk` from the header after the fragment header. A fragment at offset 0 with no more to come is the datagram itself and takes no queue (RFC 6946). A fragment other than the last whose length is not a multiple of 8, one that would take the payload past 65535 bytes, and a first fragment without every header up to the upper layer's (RFC 7112) are refused with a parameter problem. Two fragments that share a byte drop the whole datagram (RFC 5722), and the queue stays, empty, until its time is out, so the fragments still to come are dropped too; an exact duplicate is dropped alone. At most `FRAG6_QUEUES` (16) datagrams are reassembled at once, each of at most `FRAG6_PIECES` (64) fragments, in at most `FRAG6_MEM_MAX` (256 KiB) of the heap; a new one takes the place of the one that would time out first. `frag6_tick`, from `ip6_tick`, gives up a reassembly 60 seconds after its first fragment came and answers it, when the fragment at offset 0 came, with a time exceeded quoting that fragment.

`ip6_tx` builds a 40-byte header with no extension header, but a hop-by-hop header with a router alert for MLD, and sends a datagram past its destination's path MTU in fragments (`frag6_output`), each a multiple of 8 bytes of payload but the last, under an identification drawn at random (RFC 7739). `ip6_route` (`ip6/route6.c`) sends ::1 and an address an interface holds onto the loopback backlog, which IPv4 and IPv6 share and whose drain chooses the layer by the version. A link-local address or a group of link scope leaves by the interface its scope names, or by the one card; a wider group by its scope or the first card; a group goes to its station address, 33:33 and its low 32 bits. Another unicast address is the routing table's (`route6_lookup`): the prefixes of the cards' addresses, made by hand or at link up, at metric 256, and a table of 32 for the on-link prefixes routers advertise, at 256, the routers themselves as default routes, at the card's `ra_defrtr_metric`, 1024 unless written, which expire with the advertisement's lifetimes, and the routes a program adds. The longest prefix wins, then the lowest metric, then a router not known unreachable. A unicast next hop's station address is the neighbour cache's. The source is chosen by RFC 6724's rules 2, 3, 7 and 8 (`ip6_source`), a temporary address first only when `use_tempaddr` is 2. `ip6_path_mtu` (`ip6/pmtu6.c`) is the link's MTU, 1500 bytes or less when a router advertises less, 65536 for `lo`, or less for a destination a Packet Too Big has lowered: `icmp6_rx` gives `ip6_pmtu_lower` the MTU of one that quotes a datagram from ::1 or an address of this machine's, unless it came from the wire about a destination of this machine's own, and for a TCP segment only when its sequence is in flight on its connection. As RFC 8201 says, an MTU below 1280 counts as 1280, an estimate only falls, and it ages out ten minutes after it last fell; the table holds `PMTU6_ENTRIES` (16) destinations. `ip6_tx_whole` sends a datagram a raw socket of `IPPROTO_RAW` built whole, by its destination's route, and refuses one past the path MTU.

Neighbour discovery (`ip6/nd6.c`) follows RFC 4861. A next hop's station address is asked for by a solicitation to its solicited-node group and kept in a cache of 32 entries in the states of RFC 4861, 7.3.2, which netlink reports by Linux's `NUD_` numbers: an answer to a solicitation makes it REACHABLE for the routers' reachable time, 30 seconds by default, drawn between half and one and a half of it, then STALE, and a send to a STALE neighbour waits five seconds for a confirmation before three unicast probes. Up to four datagrams wait for answers in a queue of their own, each a copy on the heap, and one past the path MTU waits whole in one place and is fragmented when the answer comes, so that none of its fragments puts out another; after three solicitations a second apart without one, each is answered with an ICMPv6 address unreachable from this machine, which reaches the sender's socket. A card's tentative address is solicited once from ::, with a nonce that tells a looped solicitation from another node's (RFC 7527), after a random wait of up to a second, and becomes usable a second later unless a node answered or solicited it too; a duplicate is marked `IFA_F_DADFAILED` and kept unused. Once its link-local address is usable a card sends up to three router solicitations four seconds apart, and again when its link comes back. A router advertisement, taken when `accept_ra` is not 0 and `forwarding` is 0, or `accept_ra` is 2, as Linux's `ipv6_accept_ra` takes one, sets the card's hop limit, reachable time, retransmission time and MTU, makes its sender a default route at the card's `ra_defrtr_metric` for its router lifetime, and its prefixes on-link routes and, for an autonomous /64 with `autoconf` on, a SLAAC address. The address's identifier is that of RFC 7217, the first 64 bits of SHA-256 over the prefix, the station address, a counter and `stable_secret`, the interface's or the default one's, raised past a duplicate up to three times; with no secret written it is the modified EUI-64, as on Linux. With `use_tempaddr` above 0 a temporary address of RFC 8981 is made beside it, with a random identifier, lived for at most two days and preferred for at most a day less a random part, and its successor made five seconds before it is deprecated. A later advertisement renews the prefix's addresses by RFC 4862, 5.5.3 (e). Its RDNSS and DNSSL options (RFC 8106), checked for a length the RFC allows, go to netlink as `RTM_NEWNDUSEROPT` (`netlink_nd_useropt`), whatever `accept_ra` says, as on Linux. A card that goes down forgets its neighbours, routers and SLAAC addresses; so does one whose link goes down, which `if_timers` sees on the tick, since the link that comes back may be another network; when it comes back the card detects all its addresses again and solicits routers. Redirects are counted and ignored, and a router solicitation is ignored even with `forwarding` on.

The settings of `net.ipv6.conf.NAME`, for `all`, `default` and each interface, are kept in nd6.c and read and written through `nd6_conf_get`, `nd6_conf_set` and `nd6_secret_set`: `disable_ipv6`, which takes every address of the interface away and stops its IPv6, `accept_ra`, `autoconf`, `forwarding`, which makes the card answer as a router, join ff02::2 and solicit no router, `ra_defrtr_metric`, the metric of the default routes routers give the card, 1024 as on Linux and at least 1, whose write also moves the routes already learned (`route6_ra_metric`), where Linux waits for the next advertisement, so that a value written at start-up need not race the first router, and `use_tempaddr`. Writing `forwarding`, `disable_ipv6` or `use_tempaddr` of `all` writes it of every interface and of `default`, so a line of sysctl.conf(5) for `all` reaches the cards that came up before it was read. Each but `ra_defrtr_metric`, which is unsigned, takes any int, as Linux's `proc_dointvec` does, a boolean being true when it is not 0, and `disable_ipv6` and `forwarding` act only when their truth changes. `procfs.c` gives each as a file of `/proc/sys/net/ipv6/conf/NAME`, `stable_secret` among them, mode 0600, which reads as eight groups of four hexadecimal digits, as Linux's `%pI6` writes an address, and fails with `EIO` while none is written, and always for `all`. A write changes that text from the descriptor's offset as `proc_dostring` changes a string, and what it then begins with becomes the secret: text that is no address fails with `EIO`, and an empty write, or one past the text, makes the secret the text it reads, all zeros while none is written, as Linux's `addrconf_sysctl_stable_secret` does. A card's IPv6 made with `disable_ipv6` 1 then 0 starts again from its link-local address, so its SLAAC addresses are made again with the secret then in force. At start-up `init`, and `netup` where no `init` of BusyBox's runs, write the secret kept in `/var/lib/ipv6-stable-secret` (`utils/ip6secret.c`), making it from 16 random bytes on the first boot, and restart a card that already took a router's prefix. `ip6_tick` calls `nd6_tick`, which runs the timers ten times a second.

MLD (`ip6/mld6.c`) reports each card's groups to the link's routers by RFC 3810, but ff02::1 and the groups of scope 0 and 1: a group joined is reported twice, as a change to exclude no source, the second time within a second, and a group left the same way as a change to include none. A general query is answered with one report of every group at a random time within its maximum response delay, and a query for a group with that group's. A link whose querier sent an MLDv1 query in the last 260 seconds gets MLDv1's reports and dones instead.

### Internet endpoints

`net_addr_t` (`socket/address.h`) holds either family's address and an interface index for a link-scoped IPv6 address. IPv4 is a host-order word and IPv6 is sixteen bytes in wire order; mapped IPv4 addresses are normalized to IPv4 inside the stack. Sockets, TCP control blocks and snapshots, and the UDP and raw receive queues use this type. `address_route.c` checks the route and chooses a usable source before a TCP or UDP connect creates state, so an unreachable IPv6 destination returns `ENETUNREACH` at once and a program can try IPv4.

An IPv6 socket defaults to dual stack. A listener bound to :: accepts both native IPv6 and mapped IPv4 peers; an accepted socket keeps its listener's family. Every address returned through an IPv6 socket is a 28-byte `sockaddr_in6`, including mapped IPv4 peers. A link-scoped endpoint requires a scope id, the socket's `SO_BINDTODEVICE` index, or for a UDP send a sendmsg's `IPV6_PKTINFO` card. `IPV6_V6ONLY`, set before binding, limits the socket to IPv6 and allows a separate IPv4 binding on the same port. A wildcard dual-stack binding overlaps IPv4 bindings; UDP applies its reuse rules to the overlap, and TCP refuses overlapping listeners and cross-family stream binds. Each transport gives both families the same ephemeral ports, Linux's 32768 to 60999 (`NET_PORT_LOW` and `NET_PORT_HIGH` in `net.h`). UDP starts its search at a random port, as Linux's `udp_lib_get_port` does, and passes over the ports a table of bindings by port counts (`udp_ports`). TCP's choice is in the next section.

An IPv6 socket keeps the options of RFC 3493 and RFC 3542 that its UDP and raw datagrams honour ([setsockopt(2)](../../../man/man2/setsockopt.2)): `IPV6_UNICAST_HOPS`, -1 for the hop limit routers advertised for the route's card, else 64; `IPV6_MULTICAST_HOPS`, 1 unless set; `IPV6_MULTICAST_IF`, the card a group with no scope id leaves by after the socket's bound card; `IPV6_MULTICAST_LOOP`, on unless cleared; `IPV6_TCLASS`, written into the header's traffic class; and up to `SOCK_GROUPS6` (8) memberships, each a group on one card, which `IPV6_JOIN_GROUP` adds as one reference of the card's (`netdev_join6`), so that MLD reports it, and `IPV6_LEAVE_GROUP` and the socket's end take back. A receive keeps beside each datagram what the network layer saw of it, `struct net_rxinfo` (`socket/socket.h`): its destination, the card it came in on, its hop limit and its class, and a recvmsg on a socket that asked with `IPV6_RECVPKTINFO`, `IPV6_RECVHOPLIMIT` or `IPV6_RECVTCLASS` answers with the control messages `IPV6_PKTINFO`, `IPV6_HOPLIMIT` and `IPV6_TCLASS`, in that order, cut with `MSG_CTRUNC` at the first that does not fit. A sendmsg's own `IPV6_PKTINFO`, a source of this machine's and a card, `IPV6_HOPLIMIT` and `IPV6_TCLASS` apply to that datagram alone, before the socket's (`struct net_txopt`). A datagram to a group that the card it leaves by is a member of comes back while the loop is on: `ip6_tx_opts` puts a copy on the loopback backlog marked with the card's index (`ip_loop_put_on`), and the drain gives it to `ip6_loop_rx`, which receives it as the card's without taking its own source for a spoof.

### ICMP and UDP

`ip/icmp.c` answers an echo request from the address it was sent to. A report that a datagram was too big lowers its destination's path MTU, one about a TCP segment only when the segment is in flight on its connection, and then also goes to `tcp_path_mtu`; and a port unreachable to `udp_refused`, which gives the UDP socket connected to that peer `ECONNREFUSED`. An error this machine sends quotes as much of the datagram as fits 576 bytes, goes to no source of 0.0.0.0, broadcast or multicast, and, unless it goes to this machine, is limited to one a second after a burst of six.

Echo requests carry an identifier, and every sender of them on this machine holds one of its own, which `icmp_echo_id` hands out: each call of the kernel's ping for as long as it lasts, and each ICMP datagram socket for as long as it lives. An echo reply goes only to the holder of its identifier, so any number of pings run at once, to one host or to many, and none sees another's replies. The kernel's ping ([ping(2)](../../../man/man2/ping.2)), to an IPv4 or IPv6 address, keeps its echo record on the caller's stack, on a list `icmp_rx` and `icmp_ping_reply6` walk, and makes at most four attempts, each with a deadline a second of ticks from the current tick, including ticks whose interrupts are still pending. The timer handler's count ends the wait. The returned round-trip count also includes ticks whose interrupts are pending. [ping(1)](../../../man/man1/ping.1) does not use it: it sends through an ICMP datagram socket, one request an interval.

`udp/udp.c` keeps one list of bindings, a record from the heap for each bound socket; [bind(2)](../../../man/man2/bind.2) gives the rules for sharing a port. IPv6 UDP sends and verifies the mandatory pseudo-header checksum; a missing or bad checksum is dropped. A datagram goes to the socket connected to its sender, else to one bound to its destination address, else to one bound to any. Both families send the pseudo-header checksum, and IPv4 checks one received unless it is 0. A payload may be 65507 bytes over IPv4 and 65527 over IPv6, sent in fragments past one frame.

A UDP, raw or packet socket queues its datagrams whole, each a record from the heap (`struct sock_dgram`), in its `rq` (`socket/socket.h`), within the budget `SO_RCVBUF` sets: 212992 bytes by default, Linux's `rmem_default`, of which each record counts with its datagram, as Linux charges a buffer's true size. A datagram is taken while the queue holds no more than the budget, so an empty queue takes the largest, and one that finds the budget spent is dropped and, for UDP over IPv4, counted in RcvbufErrors. A receive hands the whole datagram, or as much as the buffer takes with `MSG_TRUNC` set in `msg_flags`; with `MSG_TRUNC` in its flags it answers the datagram's whole length. `readv_dgram` (`syscall_fs.c`) copies as much as the caller's buffers take through 1024 bytes of its stack or a block of the heap.

### TCP

IPv4 and IPv6 use the same state machine. IPv6 sums its 40-byte pseudo-header and uses 1220 without a peer MSS option. A SYN offers the link's MTU less the headers, 40 bytes on IPv4 and 60 on IPv6, at most 1460 (`tcp_offer_mss`), whatever a report has lowered the path to, as Linux offers it. Output and retransmission reduce the segment size to the current path MTU, `ip_path_mtu` or `ip6_path_mtu`, less the headers (`tcp_payload_limit`), so a new connection to a destination whose path MTU a report lowered starts at the lower size. The initial sequence number hashes the full IPv6 addresses and their scopes. A connection keeps its addresses when its source address goes, by a change of address, its removal or the end of its lifetimes, as on Linux: each segment it would send is refused for want of a route (`tcp_ip_tx`), counted in OutNoRoutes, and taken for lost, so that the retransmission timer and its backoff run as for any loss. When the address returns, the next retransmission goes out and the connection resumes with nothing lost; when it does not, the connection is given up at its time with `ENETUNREACH`, the soft error a refused send leaves until an acknowledgement clears it, in place of `ETIMEDOUT`, as Linux reports `sk_err_soft`. A listener and an unfinished handshake are kept the same way, and the handshake ends by its own timeout. A listener's unfinished handshakes belong to that listener, so closing one family cannot discard another family's handshakes on the same port.

A control block, `struct tcb` (`tcp/tcp.h`), is allocated from the heap by `listen`, by `connect`, or for an incoming SYN, and freed when the connection is done. A connection's rings are from the heap: the send ring of 64 KiB, and the receive ring, 512 KiB when more than `TCP_BIG_RING_FRAMES` (32768) frames are free as the connection opens, else 64 KiB; a listener has neither. A block in TIME_WAIT gives its send ring back on entering it, and its receive ring then when no socket holds the block or the ring has nothing unread, and otherwise when the socket is closed (`tcp_time_wait_trim`), so a burst of short connections, each of which waits there 60 seconds, holds only the blocks.

The blocks are on one list, the detached blocks in TIME_WAIT last, in the order their TIME_WAIT ends, so that the tick, the search for a listener and the pumps stop where that run begins and the tick frees from its head (`tw_first`, `tcp_tick_time_wait`). The run holds at most Linux's `tcp_max_tw_buckets` for the machine's memory (`tcp_tw_max`); past it a connection skips TIME_WAIT, counted in TCPTimeWaitOverflow, as Linux's `tcp_time_wait` does. Every block but a listener is also in a hash table by local port and remote address and port, keyed by the ISN key, so that an arriving segment and the check of a pair read one bucket (`tcp_find`, `tcp_pair_in_use`).

The ephemeral ports in use are counted in two tables by port: `port_fixed` for listeners, passive connections, connections from a bound port and bound stream sockets (`tcp_port_hold` at `bind`, given back at the socket's last close), and `port_auto` for connections whose port `connect` chose. A bind to port 0 and a listen without a port take a port neither counts, from a keyed hash of a count of the searches, odd ports first, as Linux's `inet_csk_find_open_port` (`tcp_free_port`). A connection takes the first even port, then odd, from the place a keyed hash of its source, peer address and peer port picks in `port_perturb`, that `port_fixed` does not count and that no connection to the same peer has, a block in TIME_WAIT included, and moves the place past it, as Linux's `__inet_hash_connect` (RFC 6056, algorithm 4; `tcp_connect_port`): each destination has the whole range, and a connection to another peer shares a port.

Every SYN this side sends offers that MSS, 1460 at an MTU of 1500, a window scale shift of 4 for the large ring or 1 for the small, and selective acknowledgement. When the peer's SYN lacks window scaling neither side scales, and at most 65535 bytes are offered. The peer's MSS is taken between 48 and 1460 bytes, or 536 when its SYN has none. The window offered is the receive ring's free space, and while the delayed acknowledgement is on, zero when less than half the largest window, the ring or what the scale can offer if less, is free and less than a sixteenth of it or than `rcv_mss` is, Rach2's measures for the low space at which Linux's `__tcp_select_window` also turns to zero, and then raised to the bytes left below the furthest right edge an earlier segment with ACK was built with, one IP refused among them (`rcv_adv`), when that is more, a floor Linux's `tcp_select_window` rounds up to the scale's unit (`tcp_rcv_window`); every scaled window is encoded rounded down to the scale's unit, so that the edge can move back by less than one unit, selected again for every segment with ACK and without SYN before TIME_WAIT, which below half the largest window also ends the quick acknowledgements (`tcp_wnd_field`); a SYN-ACK offers the stored window. In TIME_WAIT, which takes no more data and may have freed its ring, an acknowledgement offers the saved window, selected before TIME_WAIT or on entering it, and reused even when IP refused that segment and kept when the reader drains what is left, as Linux's `tw_rcv_wnd` keeps it. In ESTABLISHED, FIN_WAIT_1 and FIN_WAIT_2, while the socket is open for receiving, a read sends an update once the window has grown by the smaller of one MSS and half the ring (`tcp/rcvwnd.c`, RFC 1122 4.2.3.3), or, while the delayed acknowledgement is on, as Linux's `tcp_cleanup_rbuf` sends it: only while the peer has no more than half the largest window left and when the window as it stands, in whole units of the scale and at least `rcv_mss` and a sixteenth of the largest window, is at least twice what the peer has (`tcp_read_window`).

Acknowledgements follow Linux's delayed acknowledgement (`tcp_delack_hold`). The first data, and data after a quiet time longer than the retransmission timeout, grant up to 16 quick acknowledgements, one for each two `rcv_mss` the window last offered holds, or 2 when it holds fewer than two, as Linux's `tcp_incr_quickack` does (`tcp_delack_quick`), and data the peer sends again or sends past the window, a probe of a closed one among it, grants them and ends ping-pong mode (`tcp_enter_quickack`); while any are left and the connection is not in ping-pong mode each acknowledgement goes at once, and each that follows data or a FIN let past the window check uses one (`ack_quick`, `ack_sched`, `tcp_tcb_tx`), the grant counted from the window the last acknowledgement IP took offered (`rcv_offered`). Otherwise data taken in order in ESTABLISHED, with no FIN and nothing past a hole before or after it, is acknowledged at once only when more than `rcv_mss` is unacknowledged from `rcv_acked`, the acknowledgement IP last took, so that every second full segment is; otherwise the acknowledgement waits for the next segment this side sends, a read that makes it due, or 40 ms after the first segment held (`tcp_delack_expire`). The 40 ms, Linux's `TCP_DELACK_MIN`, is Rach2's fixed cap; Linux adapts its timeout and can wait longer. `rcv_mss` is the largest payload received, at least 536 and at most 1460, or the length less 20 of two shorter segments in a row of one length with their headers that are full by Linux's `tcp_measure_rcv_mss`, at least 556 bytes or 108 without FIN, SYN, URG or PSH, so that options that vary, such as SACK blocks, do not upset it; 20 is Linux's fixed header, since this side offers no option every segment carries (`rcv_last_seg`, `tcp_delack_note`). A read that empties the ring after a segment that ended a write of the peer's, a full one with PSH or a shorter one that does not repeat a full length (`ack_pushed`), sends the held acknowledgement, but in ping-pong mode only after two such segments (`tcp_read_acks`); data sent within 40 ms of data received begins the mode and an acknowledgement held its whole 40 ms ends it, as Linux's `tcp_event_data_sent` and `tcp_delack_timer_handler` do, and `TCP_QUICKACK` sets it, on a socket with no connection for the one `connect` opens (`quickack_off`, `tcp_quickack_set`). A segment past a hole, the one that fills it, data received again, a FIN and data in the closing states are acknowledged at once. A driver that hands the stack a batch of frames brackets one receive pass under the big kernel lock with `tcp_batch_begin` and `tcp_batch_end`, and the batch's in-order data is acknowledged once, at its end, as Linux's GRO hands TCP one segment for a NAPI poll; what is held is acknowledged before a segment that would carry it past 64 KiB (`tcp_batch_flush`), a batch in quick mode is acknowledged once at its end, and a batch that ends outside quick mode with no more than `rcv_mss` unacknowledged holds it to the deadline its first segment set. A frame another path delivers inside the bracket joins the batch. A reset or a give-up drops the held acknowledgement (`tcp_delack_clear`). vhost-net's transmit pass is the one driver that does (`vn_pass`).

The congestion window starts at four segments and the slow-start threshold at 65535 bytes (RFC 5681). The third duplicate acknowledgement in a row resends the missing segment and begins NewReno recovery (RFC 6582), in which each partial acknowledgement resends the next hole. A timeout sets the window to one segment and resends from the oldest unacknowledged byte. The round trip is sampled one segment at a time, never from a resend (RFC 6298, Karn's rule); [connect(2)](../../../man/man2/connect.2) gives the timeout's bounds, resets (RFC 5961) and the initial sequence number (RFC 6528). A report that a segment was too big lowers the segment size to the link's MTU less 40, with 536 as the floor (RFC 1191). A closed peer window over data waiting to be sent, with nothing in flight, is probed with an acknowledgement of no data at `snd_una` less one, as Linux's `tcp_xmit_probe_skb` sends it, at the timeout, doubled after each probe up to 120 seconds, and the connection is given up after `tcp_retries2` probes in a row without an acknowledgement, or once `TCP_USER_TIMEOUT` has passed since the first probe, as Linux's `tcp_probe_timer` gives it up (`tcp_zwp_expire`). A window closed over data in flight is probed by the retransmission timer, which sends up to a segment of the oldest data past the window, as Linux's `__tcp_retransmit_skb` does, and the connection is given up only when no acknowledgement inside the data sent, a duplicate among them, in a segment `tcp_rx_check` lets on, was received for 240 seconds, as Linux's `tcp_rtx_probe0_timed_out` says (`tcp_zwp_rtx_expired`). Data that starts at or past the right edge of the windows offered, counted from the peer's SYN, is dropped and acknowledged (`rcv_adv`). After the handshake and before TIME_WAIT each segment is judged before anything in it is taken, as Linux's `tcp_validate_incoming` and `tcp_ack` judge it (`tcp_rx_check`): one without ACK is dropped; one outside the receive window, which ends before `rcv_wup` or starts past the right edge, is dropped and answered with a duplicate acknowledgement, at most one in 500 ms when it carries neither data nor a FIN (`tcp_dupack`, `TCP_INVALID_RATELIMIT`); a SYN draws a challenge acknowledgement (RFC 5961, section 4); and an acknowledgement below `snd_una` by more than the peer's largest window (`snd_wnd_max`) or the bytes it has acknowledged (`snd_acked`, which counts this side's SYN only on an active open and stops at 2^32 - 1), whichever is less, or one at or past `snd_una` that acknowledges data never sent, drops the segment (RFC 5961, section 5). Only an acknowledgement inside [`snd_una`, `snd_nxt`] on a segment that passes these checks answers the keepalive's and the zero-window probes (`tcp_rx_answers`). A segment with data or a FIN taken whole before is acknowledged and counted in DelayedACKLost from ESTABLISHED to LAST_ACK, but not in CLOSING or LAST_ACK when it acknowledges this side's FIN, which ends the connection first; TIME_WAIT counts none (`tcp_rx_resent`, `tcp_rx_after_fin`). After the peer's FIN, a segment whose data runs past the FIN ends the connection as an accepted reset does and is answered with a reset at its acknowledgement number, counted in TCPAbortOnData, as Linux's `tcp_rcv_state_process` ends it and `tcp_v4_do_rcv` answers it (`tcp_abort_on_data`). Challenge acknowledgements share the 500 ms limit (`tcp_challenge_ack`). The first probe of a window closed over data in flight counts `TCP_USER_TIMEOUT` from the first send of the oldest data, which each connection keeps for its data in flight in runs of one tick, sixteen in the control block and the rest in a heap array that doubles as it fills and is freed when the data is acknowledged (`tcp_sent_note`); new data waits in the send ring while the heap refuses the array a run, so that no byte takes another's stamp (`tcp_sent_room`). It counts so when no retransmission came first, as Linux counts it from the head segment's stamp.

A path that drops large segments silently is found, in mode 1 of `tcp_mtu_probing`, which is off by default as on Linux, since a radio link's stall looks the same, as RFC 4821 and Linux's mode 1 find it (`tcp_blackhole`, `tcp_probe_due`): the third timeout in a row of more than the floor of data, 536 bytes on IPv4 and 1220 on IPv6, on a link that is up, lowers the segment size to 1024 and each later one halves it, and ten minutes on a probe halfway to the largest the peer and the path allow goes ahead of new data and, acknowledged, raises the size to its own, or, lost, lowers the top of the search. Keepalive (`tcp_keepalive`), from `SO_KEEPALIVE`, sends one old byte after `TCP_KEEPIDLE` seconds with no acceptable acknowledgement or in-order data received and nothing in flight, and resets a connection whose `TCP_KEEPCNT` probes went unanswered. A connection is given up after Linux's time for `tcp_retries2` retransmissions, 924.6 seconds, counted, as on Linux, from the first retransmission of the loss, a fast retransmission or a timeout's, until an acknowledgement ends the recovery (`tcp_retx_limit`, `tcp_resend`), or after `TCP_USER_TIMEOUT`. [tcp(7)](../../../man/man7/tcp.7) gives the rules and the settings, and `/proc/net/netstat` counts the data received again, the timeouts, the connections ended by data no program will read, by a close with data unread and by timeouts, challenge acknowledgements and SYNs challenged, the answers the rate limit held back, in a handshake among them, the probes and the probes of a larger size.

Data past a hole is kept in the receive ring in up to `TCP_OOO_RANGES` (8) ranges, and, when both SYNs permitted it, an acknowledgement lists up to 4 of them in a SACK option, the latest first (RFC 2018). A segment the driver refuses stays in the send ring; each tick resends for up to `TCP_TICK_PUMPS` (4) connections in rotation, and a connection whose transmits are all refused for 30 seconds is given up, a wait that does not run while the card reports its link down (`net_addr_link_down`), so that a cable out for a minute ends nothing.

A listener's completed connections wait in a ring of `SOCK_ACCEPT_BACKLOG` (16) slots in its socket, one kept empty ([listen(2)](../../../man/man2/listen.2)). A SYN that finds the ring full, or no memory for a block, is answered with a reset; one that comes while free memory is within the reserve of [memory(7)](../../../man/man7/memory.7) is dropped for the peer to resend. The connection takes the address the SYN was sent to, and a SYN goes to a listener bound to that address before one bound to any. Until the handshake ends, its block judges each segment as Linux's `tcp_check_req` does (`tcp_rx_syn_rcvd`): the peer's SYN sent again is answered with the SYN-ACK, an ACK of another number with a reset at that number, a segment outside the window offered with an acknowledgement, each at most once in 500 ms when it has a SYN or neither data nor a FIN, as Linux's `tcp_oow_rate_limited` limits it, and a SYN at another number with a reset that ends the handshake. The block of a simultaneous open judges each segment as Linux's `tcp_rcv_state_process` does: a SYN, inside the receive window or outside it, draws a challenge acknowledgement but for the peer's SYN-ACK, a segment outside the window a duplicate acknowledgement, and an acknowledgement outside [`snd_una`, `snd_nxt`] a reset; one of `snd_una` ends the handshake with this side's SYN unacknowledged, which holds the send ring's slot before the data and is sent again as the SYN-ACK until it is acknowledged (`syn_unacked`). The ACK that ends a handshake brings its data and FIN, which are taken as in ESTABLISHED (`tcp_rx_established`). The socket's last close detaches the block (`tcp_close`), which finishes the close alone: `TIME_WAIT` lasts 60 seconds, Linux's `TCP_TIMEWAIT_LEN`, a FIN the peer sends again restarting it, a detached block in `FIN_WAIT_2` is freed after ten, and one that still has data or a FIN to deliver is freed when its peer has acknowledged nothing for 30 seconds. A close with received data its reader never read sends a reset at `snd_nxt` in place of the FIN and frees the block, counted in TCPAbortOnClose, as Linux's `__tcp_close` does (`tcp_abort_on_close`). [shutdown(2)](../../../man/man2/shutdown.2) sets the socket's `SOCK_RCV_SHUTDOWN` and `SOCK_SEND_SHUTDOWN`, Linux's `sk_shutdown`, and keeps the block attached (`tcp_shutdown`): `SHUT_WR` sends the FIN after the queued data, `SHUT_RD` makes a read of an empty stream the end of input, after an error the connection recorded, and stops the window updates, and a shutdown in `SYN_SENT` frees the block, sends nothing and records ECONNRESET, as Linux's `tcp_disconnect` does. A shutdown in `SYN_RCVD` takes the flags and sends no FIN, and one of a socket with no block, never connected or disconnected, or of a block `CLOSED` or in `TIME_WAIT` takes them and fails with ENOTCONN, as Linux's `inet_shutdown` judges those states; a socket with no block shut for receiving then reads the end of input, after an error it recorded, and polls `POLLIN` and `POLLRDHUP` beside `POLLHUP` and `POLLOUT`, as Linux's `tcp_recvmsg` and `tcp_poll` judge `TCP_CLOSE`, and the flags stay set if it then connects. A listener shut for receiving stops listening as Linux's `inet_csk_listen_stop` stops it, and a listener's close does the same: each connection still queued is reset (`tcp_forget_queued`), whether or not its data was read, and an `accept` waiting on it fails with EINVAL. A UDP or raw IPv4 or IPv6 socket's shutdown sets the same flags, which end a blocking receive with 0 once the queue is empty and show in poll, as Linux's `datagram_poll`; `SOCK_SEND_SHUTDOWN` fails a UDP or ICMP datagram send with EPIPE and no SIGPIPE, as Linux's `sock_alloc_send_skb`, and a raw send still goes. Before the peer's FIN, once this side's FIN is sent or queued, data or a FIN past `rcv_nxt` that reaches a block the close detached or the socket shut for receiving, which no program will read, ends the connection with a reset, counted in TCPAbortOnData, as Linux ends a socket with `RCV_SHUTDOWN` in `FIN_WAIT_1` and `FIN_WAIT_2` (`tcp_rx_closed_data`); after the peer's FIN the rule of data past that FIN applies. The timers are written in milliseconds in `tcp.h` and kept in ticks. Timeouts and resets are ordinary on a network and are not logged; `/proc/net/snmp` counts them.

### Sockets

A socket, `struct socket` (`socket/socket.h`), is allocated from the heap when it is opened, or for an incoming SYN in interrupt context, which the heap allows since it masks interrupts and never sleeps, and is freed when its last reference goes. A descriptor of type `FD_TYPE_SOCKET` refers to it, and `dup` and `fork` share it. An accepted connection's socket takes its owner from the listener. A socket made in a network namespace other than the first reaches only that namespace's own `lo` ([`../proc/ns.Readme.md`](../proc/ns.Readme.md)).

TCP `recv`, `recvfrom`, `recvmsg`, `read` and `readv` read the stream as one read of the vector, which `recvmsg` and `readv` copy once (`stream_readv`), as Linux's `tcp_recvmsg` reads an `iov_iter`: each buffer is checked at the start only to end in user space, as Linux's `import_ubuf` and `import_iovec` check it, and the wait, the end of input and `EAGAIN` come first, before any page of it is touched; then the bytes are taken one receive buffer at a time until the vector is full or none is queued, and with `MSG_WAITALL` the call waits on until the vector is full, the input ends, an error comes or a signal, returning what it took. The receive ring keeps the end of each receive buffer, as Linux's receive queue keeps its `sk_buff`s, the first `TCP_RECV_SEGS` (32) in the control block and more in a table on the heap that doubles as needed and is given back once they are read: each in-order segment is one, and so are the bytes a filled hole releases at once. A new one joins the last only when the table would take more bytes than the ring, or the heap has no room, as Linux's `tcp_prune_queue` has `tcp_collapse` join buffers once their overhead passes the receive buffer. Linux joins an in-order segment to its queue's last buffer whenever `tcp_try_coalesce` can (`net/ipv4/tcp_input.c`), which depends on how the two `sk_buff`s are laid out and shared, so it may keep fewer bounds than Rach2, and a read whose later destination cannot be written may fail on Linux where Rach2 returns the buffers before it. The destination of each buffer, as much of it as the vector takes, must lie in user space and is brought in for writing, and with no sleep after the last of its pages the buffer is copied and taken; one whose destination cannot be written stays queued whole and ends the call with the bytes taken before it, or `EFAULT`, as Linux leaves an `sk_buff` whose copy fails. A reader holds the socket's receive lock (`recv_lock`) throughout and gives it up only while it waits for data, as Linux's `tcp_recvmsg` holds `lock_sock` and `sk_wait_data` gives it up, so a second reader cannot take a buffer while the first brings in a destination, and the bytes one read returns are adjacent in the stream when the read does not wait after its first bytes; a read with `MSG_WAITALL` that waits for more gives the lock up meanwhile, and another reader may take the bytes between its two parts, as on Linux. A buffer may overlap the list without changing a later destination. A datagram, raw or packet socket's `readv` and `recvmsg` are one receive of one datagram through the copied list (`readv_dgram`), whose buffers are checked only to end in user space: the datagram is copied into as many as it fills, and any copy that fails gives `EFAULT`, the datagram consumed, or kept by `MSG_PEEK`, as Linux's `udp_recvmsg` fails at any element. A vector with no capacity waits for input as `recv` does, or returns `EAGAIN` when nonblocking; when input is ready it returns zero and takes nothing. These cases follow Linux 6.12's `tcp_recvmsg_locked` and `sock_rcvlowat`.

Blocked callers and pollers share the socket's wait queue, and each wake gives its kind for an edge-triggered `epoll`: a datagram on a UDP, raw, packet or netlink socket, and TCP data the receive ring took, are data; an acknowledgement that frees send space is room; a connection that completes or ends, a FIN, and a connection queued on a listener are every kind. Data that comes to a socket watched for output alone is no edge, as in Linux.

### Packet and raw sockets

A packet socket (`socket/packet.c`), `AF_PACKET` with `SOCK_DGRAM`, is how a DHCP client sees an offer, which `ip_rx` drops since it comes before the machine has the address, and what `arping` uses for ARP. It is offered each ARP, IPv4 or IPv6 frame of its protocol before the kernel's handler, which still runs, from every interface when bound to index 0, or from the one it is bound to, which it also sends through. A receive gives the payload and a 20-byte `sockaddr_ll`, whose packet type is judged against the receiving card's station address. A TUN reports an address length of zero. Sending through it puts the datagram on the interface with no hardware destination.

A raw socket (`socket/raw.c`), `AF_INET` with `SOCK_RAW` and `IPPROTO_ICMP`, is what BusyBox's `ping` as root and `traceroute` use. It receives a copy of every accepted ICMP datagram, header included, and sends the caller's ICMP message and checksum unchanged with the socket's hop limit, from the address it is bound to, if any. `AF_INET6` with `SOCK_RAW` and `IPPROTO_ICMPV6`, what `ping -6` uses on Linux, receives every accepted ICMPv6 message whose checksum is good (RFC 3542, 3.1) without the IPv6 header, with the sender and the interface it came in on, but no other check, as on Linux: a reader of neighbour discovery checks the hop limit and source itself, and sends the caller's message with the checksum the kernel computes over the pseudo-header, under the socket's IPv6 options. Its filter, `ICMP6_FILTER` at level `SOL_ICMPV6` (RFC 3542, 3.2), is 256 bits, one for each type, a set bit blocking it: `raw6_rx` judges a message by it before the message takes a place in the queue, and a new socket passes every type. An ICMPv6 message past one datagram leaves in fragments. `AF_INET`'s `IPPROTO_RAW` gives a descriptor for the interface ioctls alone, which BusyBox's DHCP client opens; `AF_INET6`'s, as on Linux, sends the datagram the caller built, header included, and receives nothing. Both kinds are root's. An `AF_INET` one receives the datagram reassembled when it came in fragments, and its send past one frame leaves in fragments under `IP_MTU_DISCOVER`; `IP_RECVTTL` has its receives report each datagram's TTL.

An ICMP datagram socket, Linux's ping socket, `AF_INET` with `SOCK_DGRAM` and `IPPROTO_ICMP` or `AF_INET6` with `SOCK_DGRAM` and `IPPROTO_ICMPV6`, is what [ping(1)](../../../man/man1/ping.1) falls back to when a raw socket is refused, and any account may open one, as on a Linux whose `net.ipv4.ping_group_range` admits every group. It is a raw socket inside, registered with an echo identifier of its own, and `SO_TYPE` reports it as `SOCK_DGRAM`. A send must be an echo request, or it is `EINVAL`; the kernel writes the socket's identifier into it and sums it (`raw_echo_stamp`). `raw_rx` and `raw6_rx` give it only the echo replies that carry its identifier and a good ICMP checksum, the ICMP message alone over either family, as Linux's `icmp_rcv` drops a message with a bad checksum before a ping socket sees it; a raw socket takes the datagram whatever its checksum. As in Linux's `net/ipv4/ping.c`, the identifier is the socket's port: `bind` takes a nonzero one from `sin_port` or `sin6_port`, `EADDRINUSE` when another socket or a kernel ping holds it, and keeps the socket's own for 0 (`raw_echo_bind`); the first bind, send or connect fixes it, after which `getsockname` reports it and a second bind is `EINVAL`, and before which the port reported is 0. `connect` records a peer, to which a send with no address goes, and replies are still taken from any host, since Linux's `ping_lookup` matches the identifier alone; `recv` and `getpeername` work as on a UDP socket.

### Netlink and netconsole

`socket/genetlink.c` dispatches `NETLINK_GENERIC` through the registration and attribute helpers of `socket/genetlink.h`. `nlctrl` resolves a family by name or id and dumps the registry, including its operations and globally numbered groups, in the format libnl reads. Families retain their tables until unregister returns; a dispatch retains the family across a sleeping handler, and unregister prevents new calls, stops a dump at its next callback and waits for the current call to release it. Handlers run without `net_lock`; reply and group delivery take it internally. Dumps run during send, queue one datagram per callback and end with `NLMSG_DONE`; a started dump's `done` handler runs once on success or failure. Single requests receive an error or the requested acknowledgement, with optional capped echo and extended error attributes. [genetlink(7)](../../../man/man7/genetlink.7) defines the wire format and limits, following [Linux's netlink interface](https://docs.kernel.org/userspace-api/netlink/intro.html).

Generic sockets join groups through bind's 32 bits or the membership options, which also take group numbers above 32. Each member receives a copy, and each queue has the same overrun rule as route notifications. Port IDs are distinct within one protocol, so route and generic sockets can share a process's ID. `RTM_SETLINK` also takes `IFLA_LINKMODE` and `IFLA_OPERSTATE`: a userspace-controlled link is dormant until authorized, its carrier reported by `IFF_LOWER_UP` while `IFF_RUNNING` is clear, as [Linux's operstate interface](https://docs.kernel.org/networking/operstates.html) specifies. The route watcher includes that policy and state in its comparison.

`socket/netlink.c` answers the requests of [netlink(7)](../../../man/man7/netlink.7) from the interface records, routing table, ARP cache and socket lists, in datagrams packed as Linux packs a dump: up to `NL_DGRAM_GOOD` (3776) bytes, or once the socket has read with a larger buffer up to that buffer's size and at most `NL_DGRAM_MAX` (32448), and makes changes as the ioctls do. Its notifications come from a comparison of the state they describe: ten times a second (`netlink_tick`), and after each change a request makes, it takes the interfaces' flags, links and MTUs, their IPv4 and IPv6 addresses and the two route tables, and sends what differs from the last time to the groups of Linux's `RTNLGRP_` numbers. One comparison catches every change, those of the timers and the receive path among them, where a call in each place that changes the state would have to be kept beside every such place; the cost is a tenth of a second's delay, and a change undone within it goes unannounced. It runs only while a socket is in one of the groups. Each notification is a datagram of its own, queued under `net_lock`, since the tick and the receive path queue them; a socket with `NL_NOTIFY_QUEUE_MAX` (64 KiB) queued misses the next and its receive fails once with `ENOBUFS`.

A request's family chooses the table. A dump of addresses, routes, neighbours, rules or settings for `AF_INET` answers from IPv4's records, for `AF_INET6` from IPv6's, and for `AF_UNSPEC`, where Linux answers both, from both, IPv4's first. An IPv6 address carries its flags, its maker (`IFA_PROTO`) and its lifetimes left (`IFA_CACHEINFO`); a route its table, metric, gateway, interface and, for one a router gave, the seconds it has left in `RTA_CACHEINFO`; a neighbour its `NUD_` state, `NTF_ROUTER` for a router. `RTM_GETROUTE` for one IPv6 destination answers with `ip6_route`'s choice and `ip6_source`'s source, or a local route by `lo` for ::1 and the machine's own addresses. `RTM_NEWADDR` and `RTM_DELADDR` of `AF_INET6` go to `netconf_add_address6` and `netconf_del_address6`, an address with `IFA_F_NODAD` skipping duplicate address detection and one with no `IFA_CACHEINFO` living for ever; `RTM_NEWROUTE` and `RTM_DELROUTE` to `route6_add` and `route6_del`, at metric 1024 by default; `RTM_NEWNEIGH` and `RTM_DELNEIGH` to `nd6_set` and `nd6_forget`.

A `SOCK_DIAG_BY_FAMILY` dump for `AF_INET` or `AF_INET6` lists that family's TCP, UDP or raw sockets, as `/proc/net/tcp`, `udp` and `raw` and their IPv6 files do, which share `tcp_snapshot` and `socket_snapshot` with it. An `AF_INET6` socket is listed with its family's sockets even when its peer is IPv4, whose address it gives mapped, and a link-local address with its interface in `idiag_if`.

`netconsole.c` is given every log record from the first, before any card is up, and keeps the characters in a 32768-byte ring, 32767 of them usable, room for the Lenovo's boot log before its link is up. Two kinds of sender drain it, each from its own place, and a character leaves the ring once all have sent it, so each sender is sent the log from the boot's first record. When the ring is full, each sender furthest behind that is held, for want of a link, an address or a card that takes the frame, loses its oldest record, so that one that cannot send costs the others nothing, as a console behind Linux's log buffer loses its own oldest records. Before any sender exists, and while a drain runs, a full ring drops the newest records whole instead, a record it fills in on with them, and counts their characters, so that a sender is given only whole records and the boot log is kept. A target is told what it lost as Linux tells a console: a gap in the extended form's `seq`, which numbers the records written since the target began, or `** N printk messages dropped **` in front of the next plain record, in that record's datagram, as Linux's `console_prepend_dropped` puts it in the record's buffer; the record is then cut so that both fit 1000 bytes.

The targets of `netconsole=` are read as Linux's `alloc_param_target` and `netpoll_parse_options` read them (`drivers/net/netconsole.c`, `net/core/netpoll.c` in Linux 6.12): `[+][r][src-port]@[src-ip]/[dev],[tgt-port]@<tgt-ip>/[tgt-macaddr]`, several separated by `;`, with Linux's defaults of ports 6665 and 6666, `eth0` and the broadcast station address, and `dev` a name or a station address. A target that does not parse or names no card is logged and left out, as with Linux's `CONFIG_NETCONSOLE_DYNAMIC`. Each record goes to each target as one UDP datagram, built as `netpoll_send_udp` builds it: IPv4 with TTL 64 and a counting identification, or IPv6 with hop limit 32, and a UDP checksum. A line longer than 1000 characters, Linux's `MAX_PRINT_CHUNK`, would go in pieces; a record is never that long. `+` sends Linux's extended form, `level,seq,usec,flags;text` with the text escaped as `msg_add_ext_text` escapes it and a message past 1000 bytes in `ncfrag=` pieces, as `send_ext_msg_udp` sends it; `r` puts the release and a comma first. A target with no `src-ip` takes the interface's address at each datagram, the first IPv4 one, or the first IPv6 one whose link-local scope matches the target's, as `netpoll_setup` chooses, passing over, as Linux does not, one that is tentative or failed duplicate detection; while there is none its records wait, where Linux refuses the target. A newline starts a target's drain.

After `netconsole_enable`, or `netconsole_setup` with the frames asked for, a newline or 512 waiting characters starts a drain of the frames: up to 512 characters behind a 16-byte header, broadcast with EtherType `0x88b5` through the first interface, laid out as [`netconsole.h`](netconsole.h) describes. The frames work below IP, so they need no address and continue while the interface is down; only a packet socket receives them, which needs root. Each sender begins with a start, as Linux's `netpoll_setup` waits for carrier: until its card's link is up, for at most `netpoll.carrier_timeout=` seconds, 4 by default, Linux's `carrier_timeout`, read as Linux reads that uint parameter, once early in every boot (`netconsole_read_params`), whether or not netconsole starts, by `kstrtouint` with base 0, the last valid occurrence counting, and each value it refuses and each bare `netpoll.carrier_timeout` logged as `netconsole: refused:` in the line's order, as Linux's `parse_args` logs them. When the start finds the link up with records held, whether at its first check, as in QEMU, or later, they and every record written meanwhile wait until the link has been up for two seconds, so that the records go out in order. The settle is Rach2's own: the Lenovo's RTL8168 counted as sent, in its own tally, every frame it sent the moment its link came up, yet none reached the Mac, while those from 0.85 s later did, and Linux 6.12's netpoll, which waits for carrier and no longer, would lose them too. The boot processor's tick tries a drain every 10 ms while a sender is in its start (`netconsole_tick`), so the held records go out when it ends, after which the flush logs `netconsole: settled: held records sent after 2000 ms of link`; `netconsole_shutdown` and a panic end it at once. After the start a sender sends whenever its link is up; while the link is down, or when the card refuses a frame, its characters wait for the next newline. A flag keeps a record raised during a send from starting another, and `netconsole_panic` clears it, since a send the panic stopped never resumes. Both are sent by calling the card's transmit with interrupts off, which reclaims its ring by polling, as Linux's netpoll does, so a panic's record goes out.

### Counters and concurrency

Each interface has seven 64-bit counters, as Linux's `rtnl_link_stats64`, kept by `ethernet.c`: frames and bytes each way, receive errors, receive drops and transmit drops. Each changes with interrupts off; on i686 a 64-bit add takes two instructions, so `/proc/net/dev`, `/sys/class/net/*/statistics` and netlink copy them inside `net_lock`, and none is read half updated. The RTL8168's `counters` adds the card's tallies. `net_mib` (`net.h`) has the counters of RFC 1213 for IP, ICMP, TCP and UDP, `net_mib6` (`ip6/ip6.h`) those of RFC 4293 for IPv6 and ICMPv6, reassembly and fragments among them, and UDP's for datagrams over IPv6, which `net_mib`'s leave out, and the ARP cache and routing table count their lookups and misses. [proc(5)](../../../man/man5/proc.5) gives the files.

Every entry to the kernel takes the big lock ([`../proc/smp.h`](../proc/smp.h)), so the stack runs on one processor at a time. Two contexts meet in it: interrupt handlers, the cards' and the tick, which run with interrupts off and do not nest, and system calls, which run with interrupts on. The shared state, each layer's transmit buffer, the driver rings, the ARP cache, the counters and the lists, has no lock of its own: a system call brackets every use of it with `net_lock` and `net_unlock`, which save the interrupt flag, disable interrupts and nest, as each driver's transmit does. The loopback backlog is drained only with interrupts off, after the sender has left its bracket.

## Limits

* No extension header is sent but the fragment header and MLD's hop-by-hop router alert, and no IPv6 datagram is forwarded, so a routing header with segments left is refused. No redirect is followed, and no router preference or route information option (RFC 4191) is read; RDNSS and DNSSL options are left to a program, as on Linux, which here is [ndwatch(8)](../../../man/man8/ndwatch.8).
* A card's MTU is at most 1500 bytes: there are no jumbo frames, and no IPv6 jumbograms. IPv6 below an MTU of 1280 still sends, in fragments of the interface's size, where Linux turns IPv6 off on the interface.
* No IP options are sent and no datagram is forwarded between interfaces. A program can join no IPv4 multicast group, and has no source filter for an IPv6 one (RFC 3678).
* A UDP datagram goes to one socket, so of two bound to a port that both joined a group, one receives it. A datagram to a group that leaves in fragments does not come back to this machine, and `IPV6_MULTICAST_LOOP` has no copy of it to give.
* TCP segments leave with hop limit 64 and class 0, whatever `IP_TTL`, `IPV6_UNICAST_HOPS` and `IPV6_TCLASS` say. An IPv4 datagram that reaches an IPv6 UDP socket is given its destination, mapped, in `IPV6_PKTINFO` with interface 0, and neither `IPV6_HOPLIMIT` nor `IPV6_TCLASS`, since `udp_rx` is not given the card, the TTL or the type of service. Of the control messages only those three are read or written: no routing header, hop-by-hop or destination options, and no `IPV6_RECVERR`.
* IPv4 UDP checksums are neither sent nor checked.
* TCP sends no timestamps and reads no SACK blocks. A lost probe of a larger segment size is recovered as any loss is, with the congestion window cut.
* ARP entries do not expire, any host on the link can replace a learned one, and there is no proxy ARP.
* The ICMP error limit is the machine's, shared by all peers.
* One RTL8139, up to four e1000, one RTL8168GU and up to four virtio devices, four cards in all. The RTL8139 driver does not wait for a transmit to complete, since QEMU completes it as it starts. The RTL8139 and e1000 need a legacy interrupt line from 0 to 15 and have no polled fallback. On i686 an e1000 or RTL8168 whose memory window is above 4 GiB does not start. No driver has offloads, VLAN tags, Wake-on-LAN or runtime power management, and only the virtio driver has MSI-X.
* The virtio driver does not take `GUEST_ANNOUNCE`, `CTRL_VLAN`, the offloads or receive-side scaling's `VIRTIO_NET_F_RSS`, and the pairs in use change only as processors start: there is no `ethtool -L`. A device whose control queue the core could not number, past 1024 queues, is driven on one pair, with a record.
* An e1000 or RTL8168 that is unbound keeps its interface, down, with its IPv4 and given IPv6 addresses, without a carrier, where Linux removes the interface and makes it again at bind.
* `/dev/vhost-net` has the split ring alone, with no indirect descriptors, event index, mergeable receive buffers, offload, dirty log or IOTLB, one queue pair whose rings take the same tap, and one thread for every device, which does not busy-poll.
* `/dev/net/tun` makes its interfaces among the four interfaces and only in the first network namespace, with no virtio header and so no offload, one queue, and frames written of at most 1514 bytes, a TUN's datagrams of 1500.
* Netlink announces no neighbours, and a change undone within a tenth of a second is not announced. Netconsole's frames use the first interface only; neither form is acknowledged, and a target cannot be changed while the machine runs, which Linux does through configfs.
* A network namespace other than the first has its own `lo` alone, with IPv4 alone; `/proc/net` and `/sys/class/net` do not list it, and netlink announces nothing to its sockets or about its `lo`. An IPv6 socket there names no interface (`socket_iface6`): its joins, `IPV6_MULTICAST_IF`, `IPV6_PKTINFO` card and scope ids are `ENODEV`.

## Tests

`nd6_hosttest.c` gives two cards, `eth0` and `wlan0`, advertisements under `ra_defrtr_metric` 100 and 600 and checks each default route's metric, the cable's chosen, a write that moves a learned route with its time left, a lifetime of 0 that removes it, and the merge with a route already at the new metric.

`tcp_hosttest.c` drives the acknowledgement rules segment by segment on a clock it sets: the quick acknowledgements at the start, after a quiet time counted from the window offered, after an old segment in and before the window and in FIN_WAIT_2, in a connection's first batch, the grant from the window the last acknowledgement offered and its end below half the ring, the grant spent by data in FIN_WAIT_2, the retransmission that fills a whole hole, the second full segment's acknowledgement at once and a lone one's at 40 ms, the idle tick's deadline, data that carries a held one, holes, a FIN, partial and emptying reads after segments with and without PSH, the receive MSS learned from two shorter segments, ping-pong mode, `TCP_QUICKACK` on a connection and on a socket with none, the receive MSS learned across options that vary, the window-update rule on a 64 KiB ring with a segment held a window closed to a probe below a sixteenth of the ring and data that offers the window as it stands, and a batch's single acknowledgement, its 64 KiB cap with equal and mixed segment sizes and a segment that repeats some data on a scaled window, its deadline and a block freed inside it; the other rows turn the delayed acknowledgement off, so that each segment's acknowledgement shows.

`genetlink_hosttest.c` drives the real generic dispatch and netlink queues with a registered family, controller discovery and metadata, a dump read in three datagrams, membership through bind and options including group 40, a slow reader's overrun, capped and extended acknowledgements, invalid attributes and the supplicant's link policy transitions. It runs alone while being written, and with the host tests at the milestone end.

`tests/run host` runs the host tests `tests/host/NAME_hosttest.c` of `arp`, `icmp`, `packet`, `tcp`, `tcp_reset`, `rcvwnd`, `socket_wake`, `raw`, `netif`, `netconf`, `netdev`, `netconsole`, `tap`, `vhost_net`, `rtl8139`, `e1000`, `rtl8168` and `virtio_net`, which compile the stack's files natively under the sanitizers and drive them with crafted frames, segments and calls, the last three against a software model of the chip or the device ([`tests/host/Readme.md`](../../../tests/host/Readme.md)).

The suites boot QEMU on the virtio network device, but for those whose subject is the wire, `ping`, `packet`, `netif`, `dhcp`, `dgram`, `raw`, `netconsole` and `addressed`, and those that boot an installer, a recovery image or firmware as a PC does, `uefi`, `installer`, `installer-repair`, `metal`, `grow`, `drill` and `sealed`, which keep the RTL8139, and those that name the e1000; [`tests/system/suites.md`](../../../tests/system/suites.md) says what each proves, and [`tests/Readme.md`](../../../tests/Readme.md) how to run one.

* Core tier: `default`, whose `loopprobe` runs UDP and TCP over 127.0.0.1, among them TCP `recvmsg` into a vector that overlaps its own list, blocking, nonblocking and peeking, and into empty vectors with input absent, queued or ended, with `sockettest` and the musl probes `sockflagmusl`, `epollmusl`, `netlinkmusl`, `callsmusl`, `nsmusl`, `ip6optmusl`, which judges the IPv6 options, their control messages, raw ICMPv6's filter, a group joined on the card, a link-local send scoped by `IPV6_PKTINFO` and the refusal of joins from another network namespace, and `ndwatchmusl`, which judges raw ICMPv6's checksum check; `socket`, whose `udptest` and `tcptest` reach an echo peer on the host; `virtionet`, whose `vnetprobe` reads a virtio device's link files and lets its driver go and binds it again with a ping at each, on the device in each of its forms; and `dgram`, `netconsole`, `e1000`, `ssh` and `pools`.
* Full tier: `addressed`, `ping`, `netif`, `packet`, `raw`, `frag6`, which judges IPv6 fragments, extension headers and the path MTU over ::1, and `dhcp`, and the e1000 twin `netconsole-e1000`.
