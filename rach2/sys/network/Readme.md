# `network/`: the IPv4 and IPv6 network stack

The network stack connects the machine to Ethernet and wireless station interfaces: drivers for three cards, Ethernet, ARP, IPv4 with a routing table, ICMP, UDP and TCP, IPv6 with ICMPv6, UDP and TCP, neighbour discovery, address autoconfiguration and MLD, the sockets programs open on them, packet, raw and netlink sockets, and netconsole, which broadcasts the kernel log. It exists so that programs written for Linux, Dropbear and the DHCP clients among them, reach QEMU's user network and a real LAN through Linux's socket calls and configuration interfaces. The C is the same on i686 and x86-64; the architectures differ in how a program enters the socket calls and in the layout of the structures it passes. AF_UNIX sockets are in [`ipc/`](../ipc/Readme.md).

## Interfaces

The wireless registry, station Ethernet conversion, control port and radio contracts are described in [`wireless/Readme.md`](wireless/Readme.md). Wireless interfaces use the same IP, ARP and socket paths as the cards. Enumeration positions are separate from stable interface indexes: `netdev_at` enumerates cards and radios, then loopback, while `netdev_by_index` resolves an index. Attaching and removing a radio keeps the other interface records and indexes unchanged. IPv6 discovery and multicast state use bounded private slots, reset when a new interface takes a slot.

### System calls

A program uses Linux's socket calls, each with its page in the manual: [socket(2)](../../../man/man2/socket.2), which lists the families and types, [bind(2)](../../../man/man2/bind.2), [connect(2)](../../../man/man2/connect.2), [listen(2)](../../../man/man2/listen.2), [accept(2)](../../../man/man2/accept.2), [getsockname(2)](../../../man/man2/getsockname.2), [send(2)](../../../man/man2/send.2), [recv(2)](../../../man/man2/recv.2), [setsockopt(2)](../../../man/man2/setsockopt.2) and [shutdown(2)](../../../man/man2/shutdown.2). Both architectures register the direct calls Linux defines for them. i686 also has `socketcall`, call 102, which takes an operation number and an array of arguments ([socketcall(2)](../../../man/man2/socketcall.2)); x86-64 has none. [syscalls(2)](../../../man/man2/syscalls.2) gives the numbers. [ping(2)](../../../man/man2/ping.2), Rach2's private echo request, is `socketcall` operation 0x1000, 0x1001 or 0x1002, for IPv6, on i686 and call 400, `rach2_ping`, on x86-64. Each call reaches `socket_dispatch` in [`../syscall_net.c`](../syscall_net.c), which passes a call on an AF_UNIX socket to `ipc/unix.c`.

### Configuration

* The network-interface requests of [ioctl(2)](../../../man/man2/ioctl.2): addresses, masks, flags, MTUs, routes and ARP entries, and, on an `AF_INET6` socket, IPv6's addresses and routes, as BusyBox's `ifconfig` and `route -A inet6` give them.
* [netlink(7)](../../../man/man7/netlink.7): the requests of `ip` and `ip -6`, glibc's `getifaddrs` and `ss`, and the notifications `ip monitor` and the watchers of a network change hear.
* `/proc/net/*` and `/proc/sys/net/ipv6/conf` in [proc(5)](../../../man/man5/proc.5) and `/sys/class/net` in [sysfs(5)](../../../man/man5/sysfs.5); [ipv6(7)](../../../man/man7/ipv6.7) and [icmp6(7)](../../../man/man7/icmp6.7) describe the IPv6 stack as a program sees it.
* The boot line: [cmdline.md](../../cmdline.md) lists `rach2.ip=`, `rach2.gateway=`, `rach2.ifaddr=`, `rach2.netconsole`, `rach2.nonet` and `rach2.nicfail=`.

With no address option the first interface takes QEMU's user network, SLIRP: 10.0.2.15/24 through 10.0.2.2 (`net.h`). `rach2.ip=A.B.C.D/prefix` replaces it, with no gateway unless `rach2.gateway=A.B.C.D` gives one, and `rach2.ip=none` leaves the interface unconfigured for a DHCP client. `netconf_apply` (`netconf.c`) refuses an option given twice, a gateway with no address or beside `none`, a number above 255 or with a leading zero, trailing text, a prefix outside 1 to 32, a first octet of 0, 127, or 224 and above, the subnet's network or broadcast address, and a gateway that is not another host of the subnet; a refusal logs `net: address refused: REASON` and keeps the SLIRP configuration. `rach2.ifaddr=MAC,A.B.C.D/prefix[,GATEWAY]`, once per card, configures the card with that station address under the same rules, after the probe, whatever order the cards were found in; a token that does not parse, is longer than 79 characters or names no card is logged and skipped.

The same rules judge an address set or added while the machine runs, by `ifconfig`, `ip addr` or netlink (`netconf.c`), and the static stanzas and leases `netup` and `dhcpc` check first (`utils/ipcheck.c`). A /31 and a /32 have no network or broadcast address, as on Linux: every address of theirs is a host (RFC 3021), so either address of a /31 may be the interface's and the other its gateway, and a /32 has no gateway on its subnet and implies no route, leaving the routes to other hosts to be added by hand.

### Inside the kernel

* `init_network` (`net.h`) brings the stack up at boot, after PCI enumeration and interrupts, unless the boot line has `rach2.nonet`, and returns 1 when a card came up; boot then calls `netconsole_enable` for `rach2.netconsole`.
* The boot processor's timer tick, 1000 times a second, calls `netdev_poll`, `tcp_tick`, `ip_frag_tick`, `ip6_tick`, `netlink_tick` and `ip_loop_drain`, in that order (`kernel.c`). A system call's exit and the idle wait also drain the loopback ring.
* `kernel_shutdown` stops every card after its last log record, and `klog` gives every record to `netconsole_putc`.
* `poll`, `ioctl` and `procfs` reach the stack through `socket_poll`, `netif_ioctl`, and copies made under the lock such as `tcp_snapshot`.

A driver implements `struct netdev_ops` (`driver/netdev.h`). `init(nd, nth)` brings up its `nth` card as the interface `nd` and returns `NETDEV_UP`, `NETDEV_ABSENT` for no such card, having touched nothing, or `NETDEV_FAILED` with `error` giving the reason. `tx` sends one frame without its frame check sequence and reports whether the card took it. `poll` is null for a card that interrupts. `stop` turns the receiver and transmitter off, masks the card's interrupts and clears PCI bus mastering, and must be safe on a card that never finished starting and safe to call twice. `link` reports the link, or 0 when the card cannot tell, which `IFF_RUNNING` takes as up. A driver gives each received frame to `ethernet_rx` with its interface and reports one it refused through `ethernet_note_rx_error` or `ethernet_note_rx_drop`.

## Design

### The interface record and the probe

An interface is `struct netdev`: the driver's operations and record for the card, the name and index, the station address, the first address with its mask and gateway, up to `NETDEV_ADDRS` (7) more addresses with their masks, the counters, whether an administrator has it up, and its MTU. A kernel drives at most `NETDEV_MAX` (4) cards.

A card's MTU is 1500 from the probe. `SIOCSIFMTU` and netlink's `IFLA_MTU` set it through `netdev_set_mtu` to anything from 68 to 1500, Linux's range for Ethernet without jumbo frames, and refuse any other with `EINVAL`; `lo` takes only its own 65536. `SIOCGIFMTU`, netlink and `/sys/class/net/*/mtu` report it. IPv4 output fragments by it, IPv6 takes it as the link's MTU, a router's advertised MTU only lowering it, TCP offers it less the headers, and `ethernet_tx` and a packet socket refuse an IPv4, IPv6 or ARP payload past it. A DHCP lease's interface MTU, option 26, reaches it through the clients' `SIOCSIFMTU`: BusyBox's `udhcpc` asks for it under `udhcpc_opts -O mtu` in `/etc/network/interfaces` and its script applies it, and os-simple's `dhcpc` asks for it always.

`netdev_probe` (`driver/netdev.c`) asks the drivers in the order of its table, RTL8139, e1000, RTL8168GU, each for its cards until it answers absent, and names the cards that come up `eth0` upward, with indexes from 1; on a machine with an RTL8139 and an e1000, `eth0` is the RTL8139. A card that fails is stopped, since its bring-up may have enabled bus mastering, and its reason is logged as `net: absent: REASON` when no card came up. The probe goes on to the next card and driver, and gives a driver up after `NETDEV_MAX` failures. `rach2.nicfail=N` makes the Nth card that came up, from zero, fail.

After the cards comes `lo`, with the next index: 127.0.0.1/8 and ::1/128, Linux's loopback type 772 and MTU 65536, always up. The ioctls, netlink, `/proc/net/dev` and `/sys/class/net` list it, and no route uses it; its counters count the loopback ring, and an IPv4 address, a route of either family or taking it down is `EOPNOTSUPP`.

### The drivers

`driver/rtl8139.c` drives one RTL8139, QEMU's PCI 10ec:8139, through I/O ports. Receive is an 8192-byte ring with a 2064-byte overhang, so a frame that wraps is contiguous; a ring header with a bad status or a length outside 18 to 1518 bytes resynchronizes the ring, and an overflow is counted as a drop and drained. Transmit takes the four descriptors in turn, each with a 1536-byte buffer.

`driver/e1000.c` drives up to `E1000_MAX` (4) Intel 82540EM, PCI 8086:100e, QEMU's default card, through the memory window, with the I/O window for the reset. Its rings have 32 descriptors each, with 2048-byte receive buffers, in frames below 4 GiB. It receives every multicast frame (`RCTL.MPE`), since IPv6 finds its neighbours by groups whose station addresses the card's filter does not hold. Receive takes a frame only whole in one descriptor with its error byte clear, and a full transmit ring is waited on for ten 100-microsecond intervals before the frame is dropped as a stall. It is the descriptor-ring design with nothing added, to read before the RTL8168.

`driver/rtl8168.c` drives one RTL8168, PCI 10ec:8168, whose `TxConfig` revision is of the GU family, the Lenovo G50-70's chip, which QEMU does not emulate. It is a port of Linux v6.16, commit `038d61fd642278bab63ee8ef722c50d10ab01e8f`, `r8169_main.c` and `r8169_phy_config.c`, for `RTL_GIGA_MAC_VER_42`, without the firmware patch, and each register sequence's comment gives the Linux function it follows. It has 64-descriptor rings and 16383-byte receive buffers. Completions and link changes arrive as message-signalled interrupts where the machine can route them, and a card whose MSI enable fails gives its vector back, with the handler. The handler masks the card's sources, acknowledges, services the rings at most twice and unmasks, which arms the next message. The tick services the rings too, and alone where messages cannot be routed or after a storm: 16 messages in a row that find a source the acknowledgement does not clear, with the rings empty, leave the sources masked. It advertises 10 and 100 Mbit in both duplexes, 1000 full duplex and pause, and resets the card's tally counters, which a warm restart keeps.

`driver/ath9k/` is the driver of Atheros' AR9003 Wi-Fi chips, among them the G50-70's QCA9565, a radio under the wireless station rather than an Ethernet card; [its Readme](driver/ath9k/Readme.md) describes it.

The e1000 and RTL8168 `stop` first waits up to 10 ms for the frames given to the card, so the last log line before shutdown reaches the wire.

### Receive

A driver gives each frame to `ethernet_rx` (`ethernet/ethernet.c`) from its interrupt handler or, for the RTL8168, also from the tick. It drops a frame shorter than 14 bytes and every frame on an interface that is down, counts the rest, offers each ARP, IPv4 and IPv6 frame (`0x86DD`) to the packet sockets, and gives the payload to `arp_rx`, `ip_rx` or `ip6_rx`.

`ip_rx` (`ip/ip.c`) drops a datagram with a bad version, length or header checksum, and skips options. It accepts one for any address of any interface, whichever card it came in on, for a subnet broadcast or 255.255.255.255, and, from the loopback ring only, for 127/8. It drops one from the wire whose source is this machine's or in 127/8, and gives a broadcast to UDP alone. An accepted datagram is copied to the raw sockets of its protocol, then given to ICMP, UDP or TCP (`ip_deliver`); a unicast UDP datagram for a port no socket has is answered with a port unreachable.

A fragment that passes the same checks goes to `ip_frag_input` (`ip/ipfrag.c`), which keeps it in its datagram's queue, keyed by source, destination, protocol and identification, and gives the datagram whole to `ip_deliver`, its header the first fragment's with the total length set and the fragment fields cleared. A fragment other than the last whose data is not a multiple of 8 bytes, and one that would take the datagram past 65535 bytes, are dropped as header errors. Two fragments that share a byte drop the whole datagram, as Linux drops it, and the queue stays, empty, until its time is out; an exact duplicate is dropped alone. At most `IP_FRAG_QUEUES` (16) datagrams are reassembled at once, each of at most `IP_FRAG_PIECES` (192) fragments, in at most `IP_FRAG_MEM_MAX` (4 MiB, Linux's `ipfrag_high_thresh`) of the heap; a new one takes the place of the one that would time out first. `ip_frag_tick` gives up a reassembly 30 seconds after its first fragment came, as Linux's `ipfrag_time`, and answers it, when the fragment at offset 0 came, with a time exceeded of code 1. `/proc/net/snmp` counts ReasmReqds, ReasmOKs, ReasmFails and ReasmTimeout.

### Transmit and routing

`ip_tx_opts` builds a 20-byte header with the sender's hop limit, refuses a payload over 65515 bytes with `EMSGSIZE`, and sends the datagram:

* To 127/8 or an address an interface has: onto the loopback ring, whose MTU is `lo`'s, 65536 bytes, so that no datagram needs fragments there.
* To a broadcast address: UDP only, to the all-ones hardware address, by the interface on that subnet, or the first card for 255.255.255.255.
* Otherwise by the route `netdev_route` chooses, to the next hop's hardware address from ARP, or `ENETUNREACH` with no route. On a miss an ARP request goes out and the datagram waits in one of `IP_HOLD_SLOTS` (64) slots, a copy on the heap, for at most three seconds, until the reply sends it, so the first ping or SYN to an uncached host is not lost. A datagram past the MTU waits whole in one slot and is fragmented when it leaves, so that even the 119 fragments of the largest at an MTU of 576 arrive.

A datagram within its path MTU carries DF, as Linux's path MTU discovery sends it. The path MTU (`ip_path_mtu`, `ip/pmtu.c`) is the interface's MTU, or less for a destination a fragmentation-needed report has lowered: `icmp_rx` gives `ip_pmtu_lower` the MTU of one that quotes a datagram from an address of this machine's, whatever its protocol, but a TCP segment only when its sequence is in flight on its connection (`tcp_in_flight`), since anyone can forge a report. As Linux does, an MTU below 552 (`ip_rt_min_pmtu`) counts as 552, an estimate only falls, and it ages out ten minutes after it last fell (`ip_rt_mtu_expires`); the table holds 16 destinations. A larger datagram leaves in fragments of the most payload the path MTU leaves room for, a multiple of 8 bytes, 1480 at 1500, all with one identification and none with DF, counted in FragOKs and FragCreates (`ip_fragment`), unless its socket set `IP_MTU_DISCOVER` to `IP_PMTUDISC_DO` or `IP_PMTUDISC_PROBE`, when it is `EMSGSIZE` and counted in FragFails. `IP_PMTUDISC_DONT` sends every datagram without DF, and `IP_PMTUDISC_INTERFACE` and `IP_PMTUDISC_OMIT` send every datagram without DF, fragmented by the interface's MTU whatever the path's. TCP's segments fit the path MTU and never fragment.

The routing table (`route.c`) is the routes the interfaces imply, each address's subnet on the link but a /32's and each gateway as its interface's default route, and up to `NETDEV_ROUTES` (32) added by `SIOCADDRT` or `RTM_NEWROUTE`. A lookup takes, among the routes of interfaces that are up whose prefix covers the destination, the longest prefix, then the lowest metric, then the first found, so an implied route comes before an added one, as on Linux. The source is the connection's or socket's bound address, 127.0.0.1 for 127/8, and otherwise the outgoing interface's address on the next hop's subnet, or its first (`netdev_source`).

A UDP, raw or ICMP datagram socket bound to a card with `SO_BINDTODEVICE` sends by that card alone (`netdev_route_on`): the lookup takes only its routes, and when none covers the destination, the destination is taken to be on the card's link, as Linux takes it, so that `ping -I wlan0 192.168.0.1` reaches a host on wlan0's network while eth0 holds the default route. A card that is down is `ENETUNREACH`, and an address of this machine's still goes onto the loopback ring. The source, connect and getsockname follow the same route. An IPv6 datagram of such a socket leaves by the card as if its address had the card's scope. The binding does not filter what the socket receives, and TCP does not consult it.

`ethernet_tx` adds the header with the interface's station address, and refuses a payload over 1500 bytes or an IPv4, IPv6 or ARP payload over the interface's MTU, IPv4, IPv6 and ARP on an interface that is down, and every frame for a card whose link is down; each refusal counts as a transmit drop. A refusal reaches a UDP or raw sender as `ENOBUFS`, and TCP keeps the segment to send again.

### Addresses and ARP

An interface answers ARP for each of its addresses, and a datagram to any of them is this machine's. Changing an interface's address (`addr_publish` in `netconf.c`) drops the ARP mappings learned on it, all of them for the first interface, and the datagrams waiting for ARP; clears a gateway off the new subnet; and removes the added routes whose gateway it no longer reaches. A TCP connection opened from an address that goes is kept, as Linux keeps it (see TCP below).

The ARP cache (`arp/arp.c`) has `ARP_CACHE_SIZE` (16) entries, each with the interface it was learned on, and a lookup matches only on that interface. It learns the sender of every request and reply, unless that address cannot be a host's (a first octet of 0, 127, or 224 and above) or is the receiving subnet's network or broadcast address. A lookup refreshes an entry, and a full cache replaces the learned entry unused longest. No packet or address change touches an entry set by hand as permanent, by `arp -s` or `ip neigh add`; only `arp -d` or `ip neigh del` removes it.

### Loopback

A datagram to this machine never reaches a card. `ip_tx_opts` copies it onto a ring of `LOOP_RING_SLOTS` (64), each slot a frame's 1500 bytes, with a datagram past that copied to the heap until it is delivered, and `ip_loop_drain_from` delivers the ring through `ip_rx` from the tick, the idle wait, and a system call's exit once 3 or more wait (`LOOP_DRAIN_AT`). Delivery waits so that a send never runs the receive path, and TCP, inside the sender's own call; the threshold leaves a pair to the timer, since a simultaneous open's two SYNs cross only while neither has been delivered. A full ring refuses with `ENOBUFS` and counts the refusal in `/proc/stat`. The tick also counts there, as `loopback_left_idle`, the datagrams it finds on the ring while every processor is halted in an idle wait: the idle wait of a blocked process (`idle_wait_irq_off`) delivers the ring before it halts, so each of them waited for the timer with nothing running.

A network namespace other than the first sends on the same ring. Each slot keeps the namespace its datagram was sent in, `ip_ns` while it was put there, and the drain sets `ip_ns` to it around the delivery, so that TCP's lookups, UDP's and the raw sockets match only that namespace's sockets and connections, and a reply goes back into the namespace. A sender sets `ip_ns` from its socket or connection around its call to `ip_tx_opts`, which then reaches only 127/8, while the namespace's `lo` is up with its address; `ip6_tx_opts` reaches nothing. A namespace's own `lo` counts its traffic.

### IPv6

An interface holds up to `NETDEV_ADDRS6` (8) IPv6 addresses, `struct netdev_addr6` (`driver/netdev.h`), each with its prefix length, scope, Linux's `IFA_F_` flags, its maker in Linux's `IFAPROT_` numbers and lifetimes, and is a member of up to `NETDEV_GROUPS6` (16) groups, counted by reference. `netconf_add_address6` (`netconf.c`) joins an address's solicited-node group as it adds it, and a card's address is tentative, neither accepted nor used as a source, until duplicate address detection passes. A card brought up, at boot or by `SIOCSIFFLAGS` or netlink (`netconf_set_up`), joins ff02::1, takes the link-local address fe80::/64 with the modified EUI-64 of its station address, and starts neighbour discovery; `lo` holds ::1. An address whose lifetimes end is deprecated, then removed; the TCP connections opened from it are kept, as an IPv4 address's are.

`ip6_rx` (`ip6/ip6.c`) drops a datagram with a bad version or length, a group as its source, or, from the wire, ::1 at either end or a source of this machine's, and every datagram of an interface with IPv6 disabled. It accepts one for an address an interface holds, a link-local one only on its own interface, for ::1 from the loopback ring, and for a group the card is a member of. `ip6_walk` then follows the chain of extension headers as RFC 8200, section 4, says. Hop-by-hop options are taken only right after the fixed header, and an option of an unknown type is skipped or answered by the action its top two bits name, a parameter problem of code 2 among them. A routing header with no segment left is skipped, and one with segments left is refused with a parameter problem at its type, since this machine forwards nothing. A next header of no protocol it knows, AH and ESP among them, is answered with a parameter problem at the field that names it. TCP and UDP messages enter the shared transport state machines after the extension headers. An ICMPv6 message is copied to the raw ICMPv6 sockets if its checksum is good, then given to `icmp6_rx` (`ip6/icmp6.c`), which checks the checksum itself, answers an echo request from the address it was sent to, or for a group from the link's own address, gives an echo reply to the kernel's ping, neighbour discovery to `nd6_rx` and MLD to `mld6_rx`. An error this machine sends follows RFC 4443: none about an error, none to a group but a parameter problem of code 2, a quote of at most 1232 bytes, and the IPv4 rate limit.

A fragment goes to `frag6_input` (`ip6/frag6.c`), which keeps it in its datagram's queue, keyed by source, destination, identification and interface, and gives the datagram whole back to `ip6_walk` from the header after the fragment header. A fragment at offset 0 with no more to come is the datagram itself and takes no queue (RFC 6946). A fragment other than the last whose length is not a multiple of 8, one that would take the payload past 65535 bytes, and a first fragment without every header up to the upper layer's (RFC 7112) are refused with a parameter problem. Two fragments that share a byte drop the whole datagram (RFC 5722), and the queue stays, empty, until its time is out, so the fragments still to come are dropped too; an exact duplicate is dropped alone. At most `FRAG6_QUEUES` (16) datagrams are reassembled at once, each of at most `FRAG6_PIECES` (64) fragments, in at most `FRAG6_MEM_MAX` (256 KiB) of the heap; a new one takes the place of the one that would time out first. `frag6_tick`, from `ip6_tick`, gives up a reassembly 60 seconds after its first fragment came and answers it, when the fragment at offset 0 came, with a time exceeded quoting that fragment.

`ip6_tx` builds a 40-byte header with no extension header, but a hop-by-hop header with a router alert for MLD, and sends a datagram past its destination's path MTU in fragments (`frag6_output`), each a multiple of 8 bytes of payload but the last, under an identification drawn at random (RFC 7739). `ip6_route` (`ip6/route6.c`) sends ::1 and an address an interface holds onto the loopback ring, which IPv4 and IPv6 share and whose drain chooses the layer by the version. A link-local address or a group of link scope leaves by the interface its scope names, or by the one card; a wider group by its scope or the first card; a group goes to its station address, 33:33 and its low 32 bits. Another unicast address is the routing table's (`route6_lookup`): the prefixes of the cards' addresses, made by hand or at link up, at metric 256, and a table of 32 for the on-link prefixes routers advertise, at 256, the routers themselves as default routes, at the card's `ra_defrtr_metric`, 1024 unless written, which expire with the advertisement's lifetimes, and the routes a program adds. The longest prefix wins, then the lowest metric, then a router not known unreachable. A unicast next hop's station address is the neighbour cache's. The source is chosen by RFC 6724's rules 2, 3, 7 and 8 (`ip6_source`), a temporary address first only when `use_tempaddr` is 2. `ip6_path_mtu` (`ip6/pmtu6.c`) is the link's MTU, 1500 bytes or less when a router advertises less, 65536 for `lo`, or less for a destination a Packet Too Big has lowered: `icmp6_rx` gives `ip6_pmtu_lower` the MTU of one that quotes a datagram from ::1 or an address of this machine's, unless it came from the wire about a destination of this machine's own, and for a TCP segment only when its sequence is in flight on its connection. As RFC 8201 says, an MTU below 1280 counts as 1280, an estimate only falls, and it ages out ten minutes after it last fell; the table holds `PMTU6_ENTRIES` (16) destinations. `ip6_tx_whole` sends a datagram a raw socket of `IPPROTO_RAW` built whole, by its destination's route, and refuses one past the path MTU.

Neighbour discovery (`ip6/nd6.c`) follows RFC 4861. A next hop's station address is asked for by a solicitation to its solicited-node group and kept in a cache of 32 entries in the states of RFC 4861, 7.3.2, which netlink reports by Linux's `NUD_` numbers: an answer to a solicitation makes it REACHABLE for the routers' reachable time, 30 seconds by default, drawn between half and one and a half of it, then STALE, and a send to a STALE neighbour waits five seconds for a confirmation before three unicast probes. Up to four datagrams wait for answers in a queue of their own, each a copy on the heap, and one past the path MTU waits whole in one place and is fragmented when the answer comes, so that none of its fragments puts out another; after three solicitations a second apart without one, each is answered with an ICMPv6 address unreachable from this machine, which reaches the sender's socket. A card's tentative address is solicited once from ::, with a nonce that tells a looped solicitation from another node's (RFC 7527), after a random wait of up to a second, and becomes usable a second later unless a node answered or solicited it too; a duplicate is marked `IFA_F_DADFAILED` and kept unused. Once its link-local address is usable a card sends up to three router solicitations four seconds apart, and again when its link comes back. A router advertisement, taken when `accept_ra` is 1 and `forwarding` 0, or `accept_ra` is 2, sets the card's hop limit, reachable time, retransmission time and MTU, makes its sender a default route at the card's `ra_defrtr_metric` for its router lifetime, and its prefixes on-link routes and, for an autonomous /64 with `autoconf` on, a SLAAC address. The address's identifier is that of RFC 7217, the first 64 bits of SHA-256 over the prefix, the station address, a counter and `stable_secret`, the interface's or the default one's, raised past a duplicate up to three times; with no secret written it is the modified EUI-64, as on Linux. With `use_tempaddr` above 0 a temporary address of RFC 8981 is made beside it, with a random identifier, lived for at most two days and preferred for at most a day less a random part, and its successor made five seconds before it is deprecated. A later advertisement renews the prefix's addresses by RFC 4862, 5.5.3 (e). Its RDNSS and DNSSL options (RFC 8106), checked for a length the RFC allows, go to netlink as `RTM_NEWNDUSEROPT` (`netlink_nd_useropt`), whatever `accept_ra` says, as on Linux. A card that goes down forgets its neighbours, routers and SLAAC addresses; so does one whose link goes down, which `if_timers` sees on the tick, since the link that comes back may be another network; when it comes back the card detects all its addresses again and solicits routers. Redirects are counted and ignored, and a router solicitation is ignored even with `forwarding` on.

The settings of `net.ipv6.conf.NAME`, for `all`, `default` and each interface, are kept in nd6.c and read and written through `nd6_conf_get`, `nd6_conf_set` and `nd6_secret_set`: `disable_ipv6`, which takes every address of the interface away and stops its IPv6, `accept_ra`, `autoconf`, `forwarding`, which makes the card answer as a router, join ff02::2 and solicit no router, `ra_defrtr_metric`, the metric of the default routes routers give the card, 1024 as on Linux and at least 1, whose write also moves the routes already learned (`route6_ra_metric`), where Linux waits for the next advertisement, so that a value written at start-up need not race the first router, and `use_tempaddr`. Writing `forwarding`, `disable_ipv6` or `use_tempaddr` of `all` writes it of every interface and of `default`, so a line of sysctl.conf(5) for `all` reaches the cards that came up before it was read. `procfs.c` gives each as a file of `/proc/sys/net/ipv6/conf/NAME`, `stable_secret` among them, which reads as an address's text and fails with `EIO` while none is written, and always for `all`. A card's IPv6 made with `disable_ipv6` 1 then 0 starts again from its link-local address, so its SLAAC addresses are made again with the secret then in force. At start-up `init`, and `netup` where no `init` of BusyBox's runs, write the secret kept in `/var/lib/ipv6-stable-secret` (`utils/ip6secret.c`), making it from 16 random bytes on the first boot, and restart a card that already took a router's prefix. `ip6_tick` calls `nd6_tick`, which runs the timers ten times a second.

MLD (`ip6/mld6.c`) reports each card's groups to the link's routers by RFC 3810, but ff02::1 and the groups of scope 0 and 1: a group joined is reported twice, as a change to exclude no source, the second time within a second, and a group left the same way as a change to include none. A general query is answered with one report of every group at a random time within its maximum response delay, and a query for a group with that group's. A link whose querier sent an MLDv1 query in the last 260 seconds gets MLDv1's reports and dones instead.

### Internet endpoints

`net_addr_t` (`socket/address.h`) holds either family's address and an interface index for a link-scoped IPv6 address. IPv4 is a host-order word and IPv6 is sixteen bytes in wire order; mapped IPv4 addresses are normalized to IPv4 inside the stack. Sockets, TCP control blocks and snapshots, and the UDP and raw receive queues use this type. `address_route.c` checks the route and chooses a usable source before a TCP or UDP connect creates state, so an unreachable IPv6 destination returns `ENETUNREACH` at once and a program can try IPv4.

An IPv6 socket defaults to dual stack. A listener bound to :: accepts both native IPv6 and mapped IPv4 peers; an accepted socket keeps its listener's family. Every address returned through an IPv6 socket is a 28-byte `sockaddr_in6`, including mapped IPv4 peers. A link-scoped endpoint requires a scope id, the socket's `SO_BINDTODEVICE` index, or for a UDP send a sendmsg's `IPV6_PKTINFO` card. `IPV6_V6ONLY`, set before binding, limits the socket to IPv6 and allows a separate IPv4 binding on the same port. A wildcard dual-stack binding overlaps IPv4 bindings; UDP applies its existing reuse and owner rules to the overlap, and TCP refuses overlapping listeners and cross-family stream binds. Each transport has one ephemeral port sequence for both families.

An IPv6 socket keeps the options of RFC 3493 and RFC 3542 that its UDP and raw datagrams honour ([setsockopt(2)](../../../man/man2/setsockopt.2)): `IPV6_UNICAST_HOPS`, -1 for the hop limit routers advertised for the route's card, else 64; `IPV6_MULTICAST_HOPS`, 1 unless set; `IPV6_MULTICAST_IF`, the card a group with no scope id leaves by after the socket's bound card; `IPV6_MULTICAST_LOOP`, on unless cleared; `IPV6_TCLASS`, written into the header's traffic class; and up to `SOCK_GROUPS6` (8) memberships, each a group on one card, which `IPV6_JOIN_GROUP` adds as one reference of the card's (`netdev_join6`), so that MLD reports it, and `IPV6_LEAVE_GROUP` and the socket's end take back. A receive keeps beside each datagram what the network layer saw of it, `struct net_rxinfo` (`socket/socket.h`): its destination, the card it came in on, its hop limit and its class, and a recvmsg on a socket that asked with `IPV6_RECVPKTINFO`, `IPV6_RECVHOPLIMIT` or `IPV6_RECVTCLASS` answers with the control messages `IPV6_PKTINFO`, `IPV6_HOPLIMIT` and `IPV6_TCLASS`, in that order, cut with `MSG_CTRUNC` at the first that does not fit. A sendmsg's own `IPV6_PKTINFO`, a source of this machine's and a card, `IPV6_HOPLIMIT` and `IPV6_TCLASS` apply to that datagram alone, before the socket's (`struct net_txopt`). A datagram to a group that the card it leaves by is a member of comes back while the loop is on: `ip6_tx_opts` puts a copy on the loopback ring marked with the card's index (`ip_loop_put_on`), and the drain gives it to `ip6_loop_rx`, which receives it as the card's without taking its own source for a spoof.

### ICMP and UDP

`ip/icmp.c` answers an echo request from the address it was sent to. A report that a datagram was too big lowers its destination's path MTU, one about a TCP segment only when the segment is in flight on its connection, and then also goes to `tcp_path_mtu`; and a port unreachable to `udp_refused`, which gives the UDP socket connected to that peer `ECONNREFUSED`. An error this machine sends quotes as much of the datagram as fits 576 bytes, goes to no source of 0.0.0.0, broadcast or multicast, and, unless it goes to this machine, is limited to one a second after a burst of six.

Echo requests carry an identifier, and every sender of them on this machine holds one of its own, which `icmp_echo_id` hands out: each call of the kernel's ping for as long as it lasts, and each ICMP datagram socket for as long as it lives. An echo reply goes only to the holder of its identifier, so any number of pings run at once, to one host or to many, and none sees another's replies. The kernel's ping ([ping(2)](../../../man/man2/ping.2)), to an IPv4 or IPv6 address, keeps its echo record on the caller's stack, on a list `icmp_rx` and `icmp_ping_reply6` walk, and makes at most four attempts, each with a deadline a second of ticks from the current tick, including ticks whose interrupts are still pending. The timer handler's count ends the wait. The returned round-trip count also includes ticks whose interrupts are pending. [ping(1)](../../../man/man1/ping.1) does not use it: it sends through an ICMP datagram socket, one request an interval.

`udp/udp.c` keeps one list of bindings, a record from the heap for each bound socket, with the effective user ID that bound it; [bind(2)](../../../man/man2/bind.2) gives the rules for sharing a port. IPv6 UDP sends and verifies the mandatory pseudo-header checksum; a missing or bad checksum is dropped. A datagram goes to the socket connected to its sender, else to one bound to its destination address, else to one bound to any. Both families send the pseudo-header checksum, and IPv4 checks one received unless it is 0. A payload may be 65507 bytes over IPv4 and 65527 over IPv6, sent in fragments past one frame.

A UDP, raw or packet socket queues its datagrams whole, each a record from the heap (`struct sock_dgram`), in its `rq` (`socket/socket.h`), within the budget `SO_RCVBUF` sets: 212992 bytes by default, Linux's `rmem_default`, of which each record counts with its datagram, as Linux charges a buffer's true size. A datagram is taken while the queue holds no more than the budget, so an empty queue takes the largest, and one that finds the budget spent is dropped and, for UDP over IPv4, counted in RcvbufErrors. A receive hands the whole datagram, or as much as the buffer takes with `MSG_TRUNC` set in `msg_flags`; with `MSG_TRUNC` in its flags it answers the datagram's whole length. `readv_dgram` (`syscall_fs.c`) copies as much as the caller's buffers take through 1024 bytes of its stack or a block of the heap.

### TCP

IPv4 and IPv6 use the same state machine. IPv6 sums its 40-byte pseudo-header and uses 1220 without a peer MSS option. A SYN offers the link's MTU less the headers, 40 bytes on IPv4 and 60 on IPv6, at most 1460 (`tcp_offer_mss`), whatever a report has lowered the path to, as Linux offers it. Output and retransmission reduce the segment size to the current path MTU, `ip_path_mtu` or `ip6_path_mtu`, less the headers (`tcp_payload_limit`), so a new connection to a destination whose path MTU a report lowered starts at the lower size. The initial sequence number hashes the full IPv6 addresses and their scopes. A connection keeps its addresses when its source address goes, by a change of address, its removal or the end of its lifetimes, as on Linux: each segment it would send is refused for want of a route (`tcp_ip_tx`), counted in OutNoRoutes, and taken for lost, so that the retransmission timer and its backoff run as for any loss. When the address returns, the next retransmission goes out and the connection resumes with nothing lost; when it does not, the connection is given up at its time with `ENETUNREACH`, the soft error a refused send leaves until an acknowledgement clears it, in place of `ETIMEDOUT`, as Linux reports `sk_err_soft`. A listener and an unfinished handshake are kept the same way, and the handshake ends by its own timeout. A listener's unfinished handshakes belong to that listener, so closing one family cannot discard another family's handshakes on the same port.

A control block, `struct tcb` (`tcp/tcp.h`), is allocated from the heap by `listen`, by `connect`, or for an incoming SYN, and freed when the connection is done. Its 64 KiB send ring is in the block; its receive ring is from the heap, 512 KiB when more than `TCP_BIG_RING_FRAMES` (32768) frames are free as the connection opens, else 64 KiB.

Every SYN this side sends offers that MSS, 1460 at an MTU of 1500, a window scale shift of 4 for the large ring or 1 for the small, and selective acknowledgement. When the peer's SYN lacks window scaling neither side scales, and at most 65535 bytes are offered. The peer's MSS is taken between 48 and 1460 bytes, or 536 when its SYN has none. The window offered is the receive ring's free space; after a read an update goes out once the window has grown by the smaller of one MSS and half the ring (`tcp/rcvwnd.c`, RFC 1122 4.2.3.3).

The congestion window starts at four segments and the slow-start threshold at 65535 bytes (RFC 5681). The third duplicate acknowledgement in a row resends the missing segment and begins NewReno recovery (RFC 6582), in which each partial acknowledgement resends the next hole. A timeout sets the window to one segment and resends from the oldest unacknowledged byte. The round trip is sampled one segment at a time, never from a resend (RFC 6298, Karn's rule); [connect(2)](../../../man/man2/connect.2) gives the timeout's bounds, resets (RFC 5961) and the initial sequence number (RFC 6528). A report that a segment was too big lowers the segment size to the link's MTU less 40, with 536 as the floor (RFC 1191). A closed peer window is probed.

A path that drops large segments silently is found as RFC 4821 and Linux's `tcp_mtu_probing` 1 find it (`tcp_blackhole`, `tcp_probe_due`): the third timeout in a row of more than the floor of data, 536 bytes on IPv4 and 1220 on IPv6, on a link that is up, lowers the segment size to 1024 and each later one halves it, and ten minutes on a probe halfway to the largest the peer and the path allow goes ahead of new data and, acknowledged, raises the size to its own, or, lost, lowers the top of the search. Keepalive (`tcp_keepalive`), from `SO_KEEPALIVE`, sends one old byte after `TCP_KEEPIDLE` seconds with nothing received and nothing in flight, and resets a connection whose `TCP_KEEPCNT` probes went unanswered. A connection is given up after Linux's time for `tcp_retries2` retransmissions, 924.6 seconds, counted from the first timeout's segment (`tcp_retx_limit`), or after `TCP_USER_TIMEOUT`. [tcp(7)](../../../man/man7/tcp.7) gives the rules and the settings, and `/proc/net/netstat` counts the timeouts, aborts, probes and probes of a larger size.

Data past a hole is kept in the receive ring in up to `TCP_OOO_RANGES` (8) ranges, and, when both SYNs permitted it, an acknowledgement lists up to 4 of them in a SACK option, the latest first (RFC 2018). A segment the driver refuses stays in the send ring; each tick resends for up to `TCP_TICK_PUMPS` (4) connections in rotation, and a connection whose transmits are all refused for 30 seconds is given up, a wait that does not run while the card reports its link down (`net_addr_link_down`), so that a cable out for a minute ends nothing.

A listener's completed connections wait in a ring of `SOCK_ACCEPT_BACKLOG` (16) slots in its socket, one kept empty ([listen(2)](../../../man/man2/listen.2)). A SYN that finds the ring full, or no memory for a block, is answered with a reset; one that comes while free memory is within the reserve of [memory(7)](../../../man/man7/memory.7) is dropped for the peer to resend. The connection takes the address the SYN was sent to, and a SYN goes to a listener bound to that address before one bound to any. The socket's last close detaches the block (`tcp_close`), which finishes the close alone: `TIME_WAIT` lasts two seconds, a detached block in `FIN_WAIT_2` is freed after ten, and one that still has data or a FIN to deliver is freed when its peer has acknowledged nothing for 30 seconds. The timers are written in milliseconds in `tcp.h` and kept in ticks. Timeouts and resets are ordinary on a network and are not logged; `/proc/net/snmp` counts them.

### Sockets

A socket, `struct socket` (`socket/socket.h`), is allocated from the heap when it is opened, or for an incoming SYN in interrupt context, which the heap allows since it masks interrupts and never sleeps, and is freed when its last reference goes. A descriptor of type `FD_TYPE_SOCKET` refers to it, and `dup` and `fork` share it. An accepted connection's socket takes its owner from the listener. A socket made in a network namespace other than the first reaches only that namespace's own `lo` ([`../proc/ns.Readme.md`](../proc/ns.Readme.md)).

Blocked callers and pollers share the socket's wait queue, and each wake gives its kind for an edge-triggered `epoll`: a datagram on a UDP, raw, packet or netlink socket, and TCP data the receive ring took, are data; an acknowledgement that frees send space is room; a connection that completes or ends, a FIN, and a connection queued on a listener are every kind. Data that comes to a socket watched for output alone is no edge, as in Linux.

### Packet and raw sockets

A packet socket (`socket/packet.c`), `AF_PACKET` with `SOCK_DGRAM`, is how a DHCP client sees an offer, which `ip_rx` drops since it comes before the machine has the address, and what `arping` uses for ARP. It is offered each ARP, IPv4 or IPv6 frame of its protocol before the kernel's handler, which still runs, from every interface when bound to index 0, or from the one it is bound to, which it also sends through. A receive gives the payload and a 20-byte `sockaddr_ll`, whose packet type is judged against the receiving card's station address.

A raw socket (`socket/raw.c`), `AF_INET` with `SOCK_RAW` and `IPPROTO_ICMP`, is what BusyBox's `ping` and `traceroute` use. It receives a copy of every accepted ICMP datagram, header included, and sends the caller's ICMP message and checksum unchanged with the socket's hop limit, from the address it is bound to, if any. `AF_INET6` with `SOCK_RAW` and `IPPROTO_ICMPV6`, what `ping -6` uses on Linux, receives every accepted ICMPv6 message whose checksum is good (RFC 3542, 3.1) without the IPv6 header, with the sender and the interface it came in on, but no other check, as on Linux: a reader of neighbour discovery checks the hop limit and source itself, and sends the caller's message with the checksum the kernel computes over the pseudo-header, under the socket's IPv6 options. Its filter, `ICMP6_FILTER` at level `SOL_ICMPV6` (RFC 3542, 3.2), is 256 bits, one for each type, a set bit blocking it: `raw6_rx` judges a message by it before the message takes a place in the queue, and a new socket passes every type. An ICMPv6 message past one datagram leaves in fragments. `AF_INET`'s `IPPROTO_RAW` gives a descriptor for the interface ioctls alone, which BusyBox's DHCP client opens; `AF_INET6`'s, as on Linux, sends the datagram the caller built, header included, and receives nothing. Both kinds are root's. An `AF_INET` one receives the datagram reassembled when it came in fragments, and its send past one frame leaves in fragments under `IP_MTU_DISCOVER`; `IP_RECVTTL` has its receives report each datagram's TTL.

An ICMP datagram socket, Linux's ping socket, `AF_INET` with `SOCK_DGRAM` and `IPPROTO_ICMP` or `AF_INET6` with `SOCK_DGRAM` and `IPPROTO_ICMPV6`, is what [ping(1)](../../../man/man1/ping.1) uses, and any account may open one, as on a Linux whose `net.ipv4.ping_group_range` admits every group. It is a raw socket inside, registered with an echo identifier of its own, and `SO_TYPE` reports it as `SOCK_DGRAM`. A send must be an echo request, or it is `EINVAL`; the kernel writes the socket's identifier into it and sums it (`raw_echo_stamp`). `raw_rx` and `raw6_rx` give it only the echo replies that carry its identifier and a good ICMP checksum, the ICMP message alone over either family, as Linux's `icmp_rcv` drops a message with a bad checksum before a ping socket sees it; a raw socket takes the datagram whatever its checksum. As in Linux's `net/ipv4/ping.c`, the identifier is the socket's port: `bind` takes a nonzero one from `sin_port` or `sin6_port`, `EADDRINUSE` when another socket or a kernel ping holds it, and keeps the socket's own for 0 (`raw_echo_bind`); the first bind, send or connect fixes it, after which `getsockname` reports it and a second bind is `EINVAL`, and before which the port reported is 0. `connect` records a peer, to which a send with no address goes, and replies are still taken from any host, since Linux's `ping_lookup` matches the identifier alone; `recv` and `getpeername` work as on a UDP socket.

### Netlink and netconsole

`socket/genetlink.c` dispatches `NETLINK_GENERIC` through the registration and attribute helpers of `socket/genetlink.h`. `nlctrl` resolves a family by name or id and dumps the registry, including its operations and globally numbered groups, in the format libnl reads. Families retain their tables until unregister returns; a dispatch retains the family across a sleeping handler, and unregister prevents new calls, stops a dump at its next callback and waits for the current call to release it. Handlers run without `net_lock`; reply and group delivery take it internally. Dumps run during send, queue one datagram per callback and end with `NLMSG_DONE`; a started dump's `done` handler runs once on success or failure. Single requests receive an error or the requested acknowledgement, with optional capped echo and extended error attributes. [genetlink(7)](../../../man/man7/genetlink.7) defines the wire format and limits, following [Linux's netlink interface](https://docs.kernel.org/userspace-api/netlink/intro.html).

Generic sockets join groups through bind's 32 bits or the membership options, which also take group numbers above 32. Each member receives a copy, and each queue has the same overrun rule as route notifications. Port IDs are distinct within one protocol, so route and generic sockets can share a process's ID. `RTM_SETLINK` also takes `IFLA_LINKMODE` and `IFLA_OPERSTATE`: a userspace-controlled link is dormant until authorized, its carrier reported by `IFF_LOWER_UP` while `IFF_RUNNING` is clear, as [Linux's operstate interface](https://docs.kernel.org/networking/operstates.html) specifies. The route watcher includes that policy and state in its comparison.

`socket/netlink.c` answers the requests of [netlink(7)](../../../man/man7/netlink.7) from the interface records, routing table, ARP cache and socket lists, in datagrams packed as Linux packs a dump: up to `NL_DGRAM_GOOD` (3776) bytes, or once the socket has read with a larger buffer up to that buffer's size and at most `NL_DGRAM_MAX` (32448), and makes changes as the ioctls do. Its notifications come from a comparison of the state they describe: ten times a second (`netlink_tick`), and after each change a request makes, it takes the interfaces' flags, links and MTUs, their IPv4 and IPv6 addresses and the two route tables, and sends what differs from the last time to the groups of Linux's `RTNLGRP_` numbers. One comparison catches every change, those of the timers and the receive path among them, where a call in each place that changes the state would have to be kept beside every such place; the cost is a tenth of a second's delay, and a change undone within it goes unannounced. It runs only while a socket is in one of the groups. Each notification is a datagram of its own, queued under `net_lock`, since the tick and the receive path queue them; a socket with `NL_NOTIFY_QUEUE_MAX` (64 KiB) queued misses the next and its receive fails once with `ENOBUFS`.

A request's family chooses the table. A dump of addresses, routes, neighbours, rules or settings for `AF_INET` answers from IPv4's records, for `AF_INET6` from IPv6's, and for `AF_UNSPEC`, where Linux answers both, from both, IPv4's first. An IPv6 address carries its flags, its maker (`IFA_PROTO`) and its lifetimes left (`IFA_CACHEINFO`); a route its table, metric, gateway, interface and, for one a router gave, the seconds it has left in `RTA_CACHEINFO`; a neighbour its `NUD_` state, `NTF_ROUTER` for a router. `RTM_GETROUTE` for one IPv6 destination answers with `ip6_route`'s choice and `ip6_source`'s source, or a local route by `lo` for ::1 and the machine's own addresses. `RTM_NEWADDR` and `RTM_DELADDR` of `AF_INET6` go to `netconf_add_address6` and `netconf_del_address6`, an address with `IFA_F_NODAD` skipping duplicate address detection and one with no `IFA_CACHEINFO` living for ever; `RTM_NEWROUTE` and `RTM_DELROUTE` to `route6_add` and `route6_del`, at metric 1024 by default; `RTM_NEWNEIGH` and `RTM_DELNEIGH` to `nd6_set` and `nd6_forget`.

A `SOCK_DIAG_BY_FAMILY` dump for `AF_INET` or `AF_INET6` lists that family's TCP, UDP or raw sockets, as `/proc/net/tcp`, `udp` and `raw` and their IPv6 files do, which share `tcp_snapshot` and `socket_snapshot` with it. An `AF_INET6` socket is listed with its family's sockets even when its peer is IPv4, whose address it gives mapped, and a link-local address with its interface in `idiag_if`.

`netconsole.c` is given every log record from the first, before any card is up, and keeps the characters in an 8192-byte ring, 8191 of them usable; a full ring drops the newest and counts it. After `netconsole_enable`, a newline or 512 waiting characters starts a drain: frames of up to 512 characters behind a 16-byte header, broadcast with EtherType `0x88b5` through the first interface, laid out as [`netconsole.h`](netconsole.h) describes. While that card's link is down, or when it refuses a frame, the characters wait for the next newline. Netconsole works below IP, so it needs no address and continues while the interface is down. A flag keeps a record raised during a send from starting another.

### Counters and concurrency

Each interface has seven 64-bit counters, as Linux's `rtnl_link_stats64`, kept by `ethernet.c`: frames and bytes each way, receive errors, receive drops and transmit drops. Each changes with interrupts off; on i686 a 64-bit add takes two instructions, so `/proc/net/dev`, `/sys/class/net/*/statistics` and netlink copy them inside `net_lock`, and none is read half updated. The RTL8168's `counters` adds the card's tallies. `net_mib` (`net.h`) has the counters of RFC 1213 for IP, ICMP, TCP and UDP, `net_mib6` (`ip6/ip6.h`) those of RFC 4293 for IPv6 and ICMPv6, reassembly and fragments among them, and UDP's for datagrams over IPv6, which `net_mib`'s leave out, and the ARP cache and routing table count their lookups and misses. [proc(5)](../../../man/man5/proc.5) gives the files.

Every entry to the kernel takes the big lock ([`../proc/smp.h`](../proc/smp.h)), so the stack runs on one processor at a time. Two contexts meet in it: interrupt handlers, the cards' and the tick, which run with interrupts off and do not nest, and system calls, which run with interrupts on. The shared state, each layer's transmit buffer, the driver rings, the ARP cache, the counters and the lists, has no lock of its own: a system call brackets every use of it with `net_lock` and `net_unlock`, which save the interrupt flag, disable interrupts and nest, as each driver's transmit does. The loopback ring is drained only with interrupts off, after the sender has left its bracket.

## Limits

* No extension header is sent but the fragment header and MLD's hop-by-hop router alert, and no IPv6 datagram is forwarded, so a routing header with segments left is refused. No redirect is followed, and no router preference or route information option (RFC 4191) is read; RDNSS and DNSSL options are left to a program, as on Linux, which here is [ndwatch(8)](../../../man/man8/ndwatch.8).
* A card's MTU is at most 1500 bytes: there are no jumbo frames, and no IPv6 jumbograms. IPv6 below an MTU of 1280 still sends, in fragments of the interface's size, where Linux turns IPv6 off on the interface.
* No IP options are sent and no datagram is forwarded between interfaces. A program can join no IPv4 multicast group, and has no source filter for an IPv6 one (RFC 3678).
* A UDP datagram goes to one socket, so of two bound to a port that both joined a group, one receives it. A datagram to a group that leaves in fragments does not come back to this machine, and `IPV6_MULTICAST_LOOP` has no copy of it to give.
* TCP segments leave with hop limit 64 and class 0, whatever `IP_TTL`, `IPV6_UNICAST_HOPS` and `IPV6_TCLASS` say. An IPv4 datagram that reaches an IPv6 UDP socket is given its destination, mapped, in `IPV6_PKTINFO` with interface 0, and neither `IPV6_HOPLIMIT` nor `IPV6_TCLASS`, since `udp_rx` is not given the card, the TTL or the type of service. Of the control messages only those three are read or written: no routing header, hop-by-hop or destination options, and no `IPV6_RECVERR`.
* IPv4 UDP checksums are neither sent nor checked.
* TCP sends no timestamps and reads no SACK blocks. A closed window is probed for as long as it stays closed: neither `tcp_retries2` nor `TCP_USER_TIMEOUT` ends the probing, as they do on Linux. A lost probe of a larger segment size is recovered as any loss is, with the congestion window cut.
* ARP entries do not expire, any host on the link can replace a learned one, and there is no proxy ARP.
* The ICMP error limit is the machine's, shared by all peers.
* One RTL8139, up to four e1000 and one RTL8168GU, four cards in all. The RTL8139 driver does not wait for a transmit to complete, since QEMU completes it as it starts. The RTL8139 and e1000 need a legacy interrupt line from 0 to 15 and have no polled fallback. On i686 an e1000 or RTL8168 whose memory window is above 4 GiB does not start. No driver has offloads, VLAN tags, Wake-on-LAN, MSI-X or runtime power management.
* Netlink announces no neighbours, and a change undone within a tenth of a second is not announced. Netconsole uses the first interface only, unacknowledged.
* A network namespace other than the first has its own `lo` alone, with IPv4 alone; `/proc/net` and `/sys/class/net` do not list it, and netlink announces nothing to its sockets or about its `lo`. An IPv6 socket there names no interface (`socket_iface6`): its joins, `IPV6_MULTICAST_IF`, `IPV6_PKTINFO` card and scope ids are `ENODEV`.

## Tests

`nd6_hosttest.c` gives two cards, `eth0` and `wlan0`, advertisements under `ra_defrtr_metric` 100 and 600 and checks each default route's metric, the cable's chosen, a write that moves a learned route with its time left, a lifetime of 0 that removes it, and the merge with a route already at the new metric.

`genetlink_hosttest.c` drives the real generic dispatch and netlink queues with a registered family, controller discovery and metadata, a dump read in three datagrams, membership through bind and options including group 40, a slow reader's overrun, capped and extended acknowledgements, invalid attributes and the supplicant's link policy transitions. It runs alone while being written, and with the host tests at the milestone end.

`tests/run host` runs the host tests `tests/host/NAME_hosttest.c` of `arp`, `icmp`, `packet`, `tcp`, `tcp_reset`, `rcvwnd`, `socket_wake`, `raw`, `netif`, `netconf`, `netdev`, `netconsole`, `rtl8139`, `e1000` and `rtl8168`, which compile the stack's files natively under the sanitizers and drive them with crafted frames, segments and calls, the last two against a software model of the chip ([`tests/host/Readme.md`](../../../tests/host/Readme.md)).

The suites boot QEMU on the RTL8139 unless they say otherwise; [`tests/system/suites.md`](../../../tests/system/suites.md) says what each proves, and [`tests/Readme.md`](../../../tests/Readme.md) how to run one.

* Core tier: `default`, whose `loopprobe` runs UDP and TCP over 127.0.0.1, with `sockettest` and the musl probes `sockflagmusl`, `epollmusl`, `netlinkmusl`, `callsmusl`, `nsmusl`, `ip6optmusl`, which judges the IPv6 options, their control messages, raw ICMPv6's filter, a group joined on the card, a link-local send scoped by `IPV6_PKTINFO` and the refusal of joins from another network namespace, and `ndwatchmusl`, which judges raw ICMPv6's checksum check; `socket`, whose `udptest` and `tcptest` reach an echo peer on the host; and `dgram`, `netconsole`, `e1000`, `ssh` and `pools`.
* Full tier: `addressed`, `ping`, `netif`, `packet`, `raw`, `frag6`, which judges IPv6 fragments, extension headers and the path MTU over ::1, and `dhcp`, and the e1000 twin `netconsole-e1000`.
