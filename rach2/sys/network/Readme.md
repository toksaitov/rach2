# network/: Ethernet and IPv4

This directory implements the kernel network stack. It supports Ethernet interfaces, IPv4, ARP, ICMP echo, UDP, TCP, packet sockets, raw ICMP sockets, and a broadcast netconsole. User programs reach it through the Linux i386 `socketcall` ABI and the interface ioctls.

## Device selection

`init_network` initializes empty TCP and socket lists before a device can receive a frame. Sockets and TCP control blocks are allocated from the heap when created. `netdev_probe` then asks the RTL8139, the e1000 and the RTL8168GU, in that order, for their cards one after another, and makes an interface of every card that starts.

The order has a reason at each position. The RTL8139 is first because it is what every existing suite boots against. The e1000 is second because it is what QEMU attaches when nobody asks for a card. The RTL8168GU is last because it is the one physical target, and a failure from it is the only diagnostic a machine with no serial port and no network has.

A driver that finds a card and cannot start it supplies the boot diagnostic, and that card is silenced on the way past: a bring-up can fail after it has enabled bus mastering, and a card no interface holds is one nothing else will ever reach. The drivers after it are still asked, so a machine whose second card is broken keeps its first. `rach2.nicfail=N` refuses the Nth card that would otherwise have come up, which is how that is seen to work on a machine whose cards all start.

An interface is `struct netdev`: the driver, that driver's own record for the card, the name and index the rest of the kernel knows it by, the card's station address, that interface's own address, mask and way out, its counters, and whether an administrator has it up. Interfaces are `eth0` upward in the order the probe found them, numbered from one. A driver is given the interface at bring-up and keeps it, so every frame it delivers says which interface it arrived on, and every count is that interface's.

Every driver publishes a `link`, which reports whether the link is up and at what speed and duplex, and a `stop`, which turns the receiver and transmitter off, masks the interrupts, and clears PCI bus mastering, in that order. Clearing PCI bus mastering stops DMA. `kernel_shutdown` calls it after the page cache is flushed and after the goodbye line, so a machine read over netconsole sees that line and nothing `power_stop` prints after it. `stop` must be safe on a device that never finished starting and safe to call twice.

The storage drivers have no equivalent and are not quiesced at shutdown.

`link` returns 1 with its answer filled or 0 when the card cannot report a link at all, and the two are not the same: a card saying the link is down is different from a card that cannot say. Each driver's boot detail line reports what it read.

The RTL8139 driver is for QEMU's PCI device `10ec:8139`. It uses BAR0 I/O ports, an 8 KiB receive ring with a contiguous overhang, four round-robin transmit buffers, and IRQ-driven receive. It accepts frames promiscuously, pads short transmit frames to 60 bytes, drops received frames larger than 1518 bytes, and drops transmit frames larger than 1536 bytes. Its transmit path assumes QEMU completes a descriptor before the four-slot rotation reuses it. It does not wait for ownership as a real RTL8139 driver would. A receive-ring or FIFO overflow logs one warning per boot, increments the interface's receive-drop counter on every reported event and drains the retained frames. That counter counts overflow events, not the number of frames lost within each event. Repeated overflow warnings do not displace the boot inventory.

The e1000 driver is for PCI device `8086:100e`, the Intel 82540EM, which is what QEMU's `e1000` device is and what QEMU attaches when nothing asks for a card. It maps BAR0, reads its station address from `RAL0` and `RAH0` when the valid bit is set and the address is usable, and from EEPROM words 0 through 2 otherwise, and uses 32-entry receive and transmit descriptor rings with 2048-byte receive buffers. `RCTL.SECRC` is set, so a descriptor's length is the frame's length. Receive is interrupt-driven and takes only whole single-descriptor frames whose error byte is clear and whose length lies between 14 bytes and the buffer size; anything else is dropped and counted. Transmit waits at most ten 100 microsecond intervals for a full ring, then drops the frame and counts a stall. Short frames are padded to 60 bytes in software as well as by `TCTL.PSP`. The port omits jumbo frames, every offload, MSI and MSI-X, multiple queues, VLAN handling, interrupt throttling, and runtime power management. The related `e1000e` device is the 82574L and is refused by device id.

The RTL8168 driver accepts PCI device `10ec:8168` only when the `TxConfig` revision matches the RTL8168GU family. It uses MMIO and separate 64-entry receive and transmit descriptor rings. Receive buffers are 16,383 bytes, the programmed receive maximum is 16,384, and the largest transmit frame is 1514 bytes. The card's receive and transmit completions and its link changes arrive as message-signalled interrupts on a vector of the driver's own when the machine can route them; the handler acknowledges the status, services the rings at most twice per message and leaves the rest to the next message or to the 100 Hz timer, which polls the rings on every tick as the fallback and alone on a machine that cannot route messages. A source the acknowledgement does not clear masks the sources for the rest of the boot and is counted as a storm. The port advertises 10 and 100 Mbit in both duplexes, 1000 full duplex, and pause in both directions, so that a switch with a slower port on the far side pauses this port's transmission instead of dropping its frames; each link change the card reports is logged with the speed, duplex and pause resolved. A full transmit ring waits at most ten 100 microsecond intervals before dropping the frame and counting a stall. Receive accepts only complete single-descriptor frames and removes the four-byte frame check sequence.

The RTL8168GU initialization sequence is derived from Linux v6.16 commit `038d61fd642278bab63ee8ef722c50d10ab01e8f`. The port omits MSI-X, jumbo frames, offloads, RSS, VLAN support, Wake-on-LAN, runtime power management, and the upstream firmware patch. The host model checks register access, bounded waits, initialization order, and descriptor ownership. It cannot check PCIe ordering, DMA on the physical device, PHY behavior, or whether the Lenovo board needs the omitted firmware.

## Interface configuration

Each interface has an index from one and an MTU of 1500. With no address options the first uses the QEMU SLIRP configuration `10.0.2.15/24` through `10.0.2.2`, which is what `rach2.ip=` and `rach2.gateway=` change.

`rach2.ifaddr=<mac>,<addr>/<prefix>[,<gateway>]` configures a card by its station address after probing. Each valid token updates the matching interface. Invalid tokens, including oversized values and unknown hardware addresses, are reported and skipped; subsequent tokens are still processed. Configuring the first interface also updates the primary IPv4 address, mask and gateway, the source of a datagram no route reaches. Configuring another interface leaves those primary values unchanged.

A datagram leaves by the route of its destination (`route.c`): of the routes of interfaces that are up and have that destination, the one of the longest prefix, then of the lowest metric, then the first found. The routes are each address's subnet, reached on the link, each interface's gateway as its default route, and the routes programs add, at most 32, by an interface, through a gateway on one of its subnets or on the link; an implied route comes before an added one of the same prefix and metric, as Linux's kernel routes do. A subnet's broadcast address leaves by the interface on that subnet, and the limited broadcast, 255.255.255.255, by the first interface. The source address a datagram carries is a connection's own address when it has one, the address an echo request was sent to for the reply, and else the address of the interface whose subnet has the next hop, or its first (`netdev_source`). An interface holds its first address and up to seven more, each with its mask, and answers ARP for every one; a datagram to any address of any interface is addressed to this machine. An address nothing reaches is refused with a reason. ARP entries name the interface they were learned on and a lookup matches only on the same one, so two cards may have neighbours at the same address on their own subnets. An interface an administrator takes down carries nothing and answers nothing; the others are unaffected.

`/proc/net/dev` has a line per interface, `/proc/net/route` each interface's default route and subnets and then the added routes, `/proc/net/arp` names the interface each mapping was learned on, with the flags 0x6 for one set by hand as permanent, and `/proc/net/stat/rt_cache` and `arp_cache` have Linux's counters of routes and neighbours that iproute2's `lnstat` reads. Every `SIOCGIF*` answers about the interface the caller names, and `SIOCGIFNAME` answers for any index the machine has. A packet socket binds to any of them, or to zero for all: one bound to an interface is offered that interface's frames and no others, sends through it, and is told with each datagram which interface it arrived on. A `sockaddr_ll` that names an interface at `sendto` sends through that one. Whether a frame was addressed to this machine is judged against the station address of the card it arrived on.

The boot line accepts:

```text
rach2.ip=A.B.C.D/prefix rach2.gateway=A.B.C.D
rach2.ip=none
```

An explicit address without `rach2.gateway` has no default route. `rach2.ip=none` leaves IPv4 unconfigured for userland. A gateway beside `none` is invalid. The parser rejects duplicate options, leading zeroes, malformed or out-of-range octets, trailing text, prefixes outside 1 through 30, non-host addresses, and a gateway outside the configured subnet. A refusal preserves the complete SLIRP default tuple.

`SIOCGIFFLAGS` reports `IFF_RUNNING` when the bound card says its link is up. A card that cannot report a link is treated as running while a device is bound, because no hardware link status is available.

Programs configure an interface through `SIOCGIF*`, `SIOCSIF*`, `SIOCADDRT`, and `SIOCDELRT` on a socket descriptor, or through the route socket's requests (Netlink, below). `SIOCDARP` forgets one ARP mapping, for `arp -d`, and `SIOCSARP` stores one by hand, for `arp -s`, permanent with `ATF_PERM`. Every one of them acts on the interface the caller names, and a route with no device named is the first interface's. Getters are available to every user; setters and route changes require effective uid 0. Each interface holds a first address with its mask, the derived broadcast address, interface flags, and at most one default gateway, which the address ioctls act on; `ip addr add` gives it up to seven more (`netconf_add_address`). An address set without a netmask takes its class's mask, 255.0.0.0 when its first byte is below 128, 255.255.0.0 when it is below 192 and 255.255.255.0 otherwise, until a netmask ioctl sets one; a class network or broadcast address is held pending instead, with the interface unconfigured, until a netmask makes it a host. A netmask ioctl that fails with `EINVAL` in either state, for a mask that is not contiguous, is all ones, or makes the address a network or broadcast address, unconfigures the interface, and the address must be set again; one that fails with `EPERM` or `EFAULT` changes nothing. Each interface's pending address is its own. Adding the already implied subnet route succeeds without changing state, and it cannot be removed while its address is in force; any other route goes in the table, with the metric one less than `rt_metric`, as `route` sends it. A socket of any family takes them, an `AF_UNIX` one among them, since glibc's `if_nametoindex` asks one. `SIOCGIFCONF` lists the interfaces that have an address, each an `ifreq` with its name and address, in the caller's buffer, and with no buffer says the bytes they take; an interface the buffer has no room for whole is left out, as on Linux.

Changing any interface's address notifies TCP. Connections whose local address is no longer configured are aborted with `ENETRESET`; connections whose address remains configured are preserved. Listening sockets remain active. A change to the first interface flushes the ARP cache and updates the primary IPv4 globals; a change to another interface removes only that interface's ARP mappings. A gateway no longer on the interface's subnet is cleared. Setting an address to zero also clears the mask. Taking an interface down drops IP and ARP in both directions on it. It does not disable netconsole. A card whose `link` says the link is down is handed no frame of any kind, as Linux hands a card nothing while its carrier is off; each refused frame counts as a transmit drop, and a packet socket's send still succeeds, as it does on Linux.

## Ethernet, ARP, and IPv4

Ethernet accepts IPv4 and ARP. Packet sockets see a matching frame before the kernel protocol handler. The same frame still reaches that handler.

This layer keeps seven 32-bit counters, which wrap, and `/proc/net/dev` reads them: frames and bytes each way, receive errors, receive drops, and transmit drops. A frame is counted as transmitted only after the driver reports that it took it. A driver reports what it refused through `ethernet_note_rx_error` and `ethernet_note_rx_drop` and through its transmit verdict; it does not keep the interface's counters itself. A driver whose card keeps its own tallies fills seven more columns through its `counters` operation, as Linux fills them from a card: frames the card missed for lack of ring room add to the receive drops, alignment errors are the frame column, multicasts received their own, and on the transmit side errors, underruns (fifo), collisions, and transmissions the card aborted (carrier). The RTL8168 driver reads them from the chip's tally block at each read of the file, and zeroes the block when the card comes up, since only a power cycle clears it and after a warm restart it would still have the earlier boot's counts; the other drivers keep none. The compressed columns and the receive fifo are zero.

The ARP cache has sixteen entries, of which those set by hand as permanent are never changed by a packet, replaced when the cache is full, or dropped by an address change; only `arp -d` or `ip neigh del` removes one. It learns a usable sender from requests and replies, including unsolicited packets. It rejects zero, loopback, multicast, reserved, broadcast, and subnet-network addresses. A lookup refreshes an entry's use order. When full, the cache replaces the entry unused for the longest time. Entries do not expire by age. On a transmit miss, the stack sends an ARP request, holds the datagram, and reports success to the sender; when the reply stores the mapping, the held datagram leaves, as Linux's neighbour queue sends it, so the first ping or SYN to a host not yet cached is answered at once and not after a retry. Four datagrams are held, for any hops; a fifth takes the place of the one held longest, and one held for more than three seconds is dropped. A change of an interface's address drops what is held for it.

A failed card is stopped and its error retained. Probing continues with subsequent cards and drivers until the interface limit is reached; each driver is limited to `NETDEV_MAX` failures. Stopping a failed card disables any bus mastering enabled during initialization. `rach2.nicfail=N` refuses the Nth card that would otherwise have started, counting from zero, and retains the boot-line refusal reason. A later failed card replaces that reason with its own.

IPv4 validates the version, header length, total length, and header checksum. Receive skips options according to IHL but drops every fragment. It accepts the local address, the limited broadcast, and the subnet broadcast. Broadcast datagrams reach UDP only. A wire packet whose source is the local address or `127/8` is dropped. Accepted datagrams are copied to matching raw sockets before ICMP, UDP, or TCP handles them.

Transmit creates a 20-byte header, sets DF, and uses the caller's hop limit. The 1500-byte MTU includes that header. Payloads above 1480 bytes return `EMSGSIZE` before routing or queueing, including on loopback. The stack does not fragment. An absent route returns `ENETUNREACH`. UDP broadcast uses the all-ones hardware address and never performs ARP.

`127/8` is this machine's, as it is on Linux, and `lo` holds it: an interface listed after the cards (`netdev_loopback`), with 127.0.0.1/8, Linux's loopback type and an MTU of 65536, always up, which counts the loopback ring's datagrams as its traffic. It is in the listings a program reads, netlink, the interface ioctls, `/proc/net/dev` and `/sys/class/net`, and nowhere in the stack's own: no route names it, `ip route get` answers an address of the machine or of `127/8` with a local route on it, and an address, a route, a neighbour or taking it down is `EOPNOTSUPP`. A datagram to an address in it needs no route and leaves from 127.0.0.1, or from the sender's bound address when that is another of the machine's; one from `127/8` to an address that is not the machine's is `EINVAL`, and one that arrives from the wire addressed to `127/8` is dropped, so a socket bound to 127.0.0.1 is reached from this machine alone. Datagrams to the machine's own addresses, `127/8` and the interfaces' alike, enter a 64-slot ring and are delivered at the exit of the system call that queued them once the ring holds three or more, and otherwise from the next timer tick; neither re-enters TCP in the sender's call frame. One or two are left to the timer because a simultaneous open is a pair of crossing SYNs and is only a pair while neither has been delivered. `/proc/stat` reports `loopback_dropped` and `loopback_peak`. A full loopback ring returns `ENOBUFS`.

## ICMP and UDP

ICMP implements echo request and reply, and takes a destination-unreachable report of fragmentation needed as TCP's path MTU. A UDP datagram addressed to this machine, not broadcast, for a port no socket has is answered with a port unreachable that quotes it, up to a 576-byte datagram, which is what ends a `traceroute` to this machine. Errors leave at most one a second after a burst of six, Linux's rate for each peer, kept here for the machine as a whole; an error to this machine's own address is not limited, as Linux does not limit those it sends over its loopback. A port unreachable that arrives for a datagram a connected UDP socket sent gives that socket `ECONNREFUSED` as its pending error, which `poll` reports as `POLLERR` and the next receive, send or `SO_ERROR` returns once, as Linux does; glibc's resolver connects its socket and moves to the next server on it. The private ping socketcall permits one machine-wide request at a time. It makes four attempts with a one-second limit for each, which lets the first request populate ARP. A process sleeps on a wait queue; the kernel debug shell polls because no process scheduler is running there. The result is the round-trip time in ticks, `ETIMEDOUT`, `EBUSY`, or `EINTR`.

`bind` takes an address and a port. The address is 0 for any, one in `127/8`, an interface's, or for a datagram socket a broadcast address; another is `EADDRNOTAVAIL`. A stream or datagram socket bound to an address is given only what arrives for that address. UDP allocates a binding record from the heap when a socket binds and adds it to the binding list under `net_lock`. It assigns ephemeral ports from 49152 through 65535. A nonzero port below 1024 requires effective uid 0. Two bindings of a port meet when one is to any address or both are to the same one; a port may be bound again at an address that meets an existing binding only when the new socket and every binding it meets enable `SO_REUSEADDR`, and every one was created under the caller's effective uid. A matching connected socket receives before an unconnected socket on the same port, and of the unconnected ones a socket bound to the datagram's address before one bound to any.

Outgoing UDP checksums are zero, which disables the checksum under IPv4. Incoming UDP checksums are not verified. The maximum user payload is 1472 bytes, leaving room for the IPv4 and UDP headers within the 1500-byte MTU. Larger payloads return `EMSGSIZE`. An ordinary UDP socket queues up to eight datagrams of up to 1500 bytes, and drops a datagram that finds the queue full. Empty datagrams are represented separately from an empty slot and therefore return a valid zero-byte read. `connect` records a peer without a handshake, filters receive to that peer, and may be undone with `AF_UNSPEC`.

## TCP

A transmission control block is allocated from the kernel heap when a connection opens, actively or for an incoming SYN on the interrupt side, and freed when the connection is done; a block in `TIME_WAIT` or `FIN_WAIT_2` is freed when its deadline passes, and there is no fixed count of them. `/proc/net/tcp` takes a snapshot at open: it counts blocks under `net_lock`, allocates outside the lock, then copies up to the original count under the lock. Newly allocated blocks may be included; growth can exclude older blocks. Its `retrnsmt` column counts the segments the connection sent again. The send ring is 64 KiB. The receive ring is from the heap, 512 KiB when more than 128 MiB of frames are free as the connection opens and 64 KiB otherwise, and a connection with the large ring offers the window scale option in its SYN (RFC 7323); when the peer's SYN has the option too, both sides' windows are scaled, and otherwise neither is and at most 65,535 bytes are offered. The advertised window is the receive ring's free space clamped to what the field says at the connection's scale; data the receive ring takes wakes its readers for data, and a segment it takes none of, full, wakes nobody. This side offers an MSS of 1460 bytes, and sends segments no larger than the MSS option of the peer's SYN, at most 1460 and at least 48 bytes, or 536 bytes when the SYN has none. The segments have DF set, and a router's ICMP report that one in flight did not fit a link lowers the connection's segment size to that link's MTU less 40, but not below 536, and sends the unacknowledged data again (RFC 1191); a report whose quoted sequence number is not in flight is ignored. A segment the driver refuses stays in the send ring for the next acknowledgement or tick, and a connection whose segments are refused for thirty seconds is given up. The initial congestion window is four of the peer's segments and the initial slow-start threshold is 65,535 bytes.

`tcp_send` accepts bytes only in `ESTABLISHED` or `CLOSE_WAIT`. It saves and masks interrupts before reading the socket's control block or checking its state, and restores the saved state after queueing and transmitting. It returns the count accepted, zero when the ring is full, or -1 for a missing connection, negative length, or invalid state. Unacknowledged bytes remain in the ring for retransmission.

The implementation includes passive, active, and simultaneous open; in-order delivery; retransmission and loss recovery (RFC 5681, RFC 6582); slow start and congestion avoidance; RTT measurement, one sample at a time, ended by the acknowledgement that covers the sampled segment and never taken from a segment sent again (Karn's rule); zero-window probes; and an update when a reader reopens enough receive space. The update threshold is the smaller of one MSS and half the receive ring. TCP negotiates the window scale option and selective acknowledgement (RFC 2018), but not timestamps. Selective acknowledgement is on the receiving side only: every SYN this side sends permits it, its answer to a SYN only when that SYN did, and when both permitted it, an acknowledgement without data, sent while data past a hole is held, names up to four of the held ranges: those of the last four segments kept, the newest first, and then the others in order. A segment past a hole that finds the eight ranges the receiver tracks all taken is not kept, and not named. A peer's SACK blocks are not read: this side's retransmission waits for the cumulative acknowledgement, as without the option.

The initial and minimum retransmission timeout is one second and the maximum is 60 seconds. The timer may expire seven times in a row for one segment; the eighth expiry ends the connection. The third duplicate acknowledgement in a row sends the segment the peer lacks again at once, with the congestion window set to half of what was in flight plus three segments, and each partial acknowledgement after it sends the next hole; a resend the driver refuses is sent by the next acknowledgement or tick before anything else. A timeout sends the unacknowledged data again from the oldest byte, a segment more per acknowledgement from a window of one, until everything sent before the loss is acknowledged; the timeout it doubled is measured again from the first new data acknowledged. `TIME_WAIT` lasts two seconds and `FIN_WAIT_2` has a ten-second backstop.

Only one live listener may hold a port at an address: listeners on 127.0.0.1 and on an interface's address may share one, and one bound to any address shares it with none. A connection is matched by its local address and port and its peer's, and a SYN goes to the listener bound to its address before the one bound to any. A connection is opened from the socket's bound address, or else from 127.0.0.1 to `127/8` and from the address of the interface its route leaves by otherwise. A stream socket bound to port 0, or listening without a bind, is given an ephemeral port from 49152 through 65535 that no control block uses and no other stream socket has bound, as Linux gives one. The `listen` backlog argument is ignored. The fixed circular accept array has 16 entries but leaves one unused to distinguish full from empty, so it queues at most 15 completed connections. `tcp_close` detaches the socket and flushes queued data before FIN where the state permits it; a connection whose FIN went at a shutdown finishes its close without the socket. `shutdown(SHUT_WR)` is a half close (`tcp_shutdown_send`): the FIN goes after the queued data, a later send is `EPIPE`, and the socket stays attached, so the peer's data and its FIN still reach the reader, and a block that reaches its end while the socket holds it is kept, with the data not yet read, until the socket's close. `SHUT_RDWR` closes as `tcp_close` does. The caller retains ownership of the socket either way.

## Socket interface

A socket is an object allocated from the kernel heap when it is opened, on the list of live sockets, and freed when its last reference closes; an incoming SYN allocates one from the interrupt side, which the heap allows since it masks interrupts and never sleeps. There is no fixed count of them. Sockets are `FD_TYPE_SOCKET` descriptors and retain one object across `dup`, `dup2`, and `fork` until the last reference closes.

Linux i386 syscall 102 implements these subcalls: `socket`, `bind`, `connect`, `listen`, `accept`, `getsockname`, `getpeername`, `socketpair`, `send`, `recv`, `sendto`, `recvfrom`, `shutdown`, `setsockopt`, `getsockopt`, `sendmsg`, `recvmsg`, `accept4`, `recvmmsg` and `sendmmsg`, and the direct calls 359 to 373 and 337 and 345 are the same subcalls with their arguments in registers. Private subcall `0x1000` performs ICMP echo. `socket_dispatch` sends a call on an AF_UNIX socket, and a `socket` or `socketpair` of `AF_UNIX`, to `ipc/unix.c`, which the [ipc documentation](../ipc/Readme.md) and [unix(7)](../../../man/man7/unix.7) describe; `socketpair` of another family is `EOPNOTSUPP`. `sendmmsg` and `recvmmsg` take up to 1024 messages, each sent or received as `sendmsg` or `recvmsg` would, of either family. `socket` takes `SOCK_CLOEXEC` and `SOCK_NONBLOCK` above the type's low four bits and `accept4` takes them in its flags, as Linux does: the new descriptor is close-on-exec, and its open-file description is `O_NONBLOCK`; any other such bit is `EINVAL`. Pointer ranges are checked before the protocol layer receives them. `O_NONBLOCK` and `MSG_DONTWAIT` apply to the supported blocking operations. A receive with `MSG_PEEK` copies what it would take and leaves it queued: a stream's bytes stay in the receive ring and a datagram in its slot, so the next receive takes them; Chromium checks a connection it keeps idle with a peek of one byte, which a receive that took the byte would cut out of the TLS records. `recvmsg` on a datagram socket sets `MSG_TRUNC` in `msg_flags` when the datagram was longer than its buffers, and with `MSG_TRUNC` in its flags answers the datagram's whole length, which iproute2's `ip` asks with `MSG_PEEK` and no buffer before it reads a netlink answer.

The supported families and types are:

* `AF_INET/SOCK_STREAM` for TCP.
* `AF_INET/SOCK_DGRAM` for UDP.
* `AF_INET/SOCK_RAW/IPPROTO_ICMP` for root-only raw ICMP.
* `AF_INET/SOCK_RAW/IPPROTO_RAW` for the root-only, ioctl-only descriptor used by network configuration programs. Data operations on it return `EOPNOTSUPP`.
* `AF_PACKET/SOCK_DGRAM` for root-only IPv4 and ARP packet sockets.

`accept` requires a listening stream socket: other streams and datagrams return `EINVAL`, and raw sockets return `EOPNOTSUPP`. It reserves the new descriptor before it takes the connection off the queue, so a caller with no descriptor free leaves the connection queued, and gives the descriptor its socket only after the peer's address has been copied out; a copy that fails frees the descriptor and closes the connection, as does an address given with no length pointer, which is `EFAULT`. `getsockname` reports a TCP control block's local address when one exists, including the address used by an accepted connection and a listener's bound address; another IPv4 socket reports the address it bound, 0.0.0.0 for any, except that a connected datagram socket bound to any address reports the one its datagrams leave from, as Linux does. A packet socket reports its bound interface's index and MAC. An unbound packet socket or one bound to every interface reports index zero with no hardware address.

`connect` succeeds when the handshake completes, including when the peer's FIN arrives before the caller resumes and the connection is already in `CLOSE_WAIT`. A read then returns any queued data followed by EOF. A nonblocking connect uses the same completion check before deciding whether to return `EINPROGRESS`.

A socket's waiters and pollers share its wait queue, and each wake names its kind of change for an edge-triggered epoll registration: a datagram or a frame queued for a UDP, raw or packet socket, and data for a TCP connection, are data; an acknowledgement that frees send-ring space is room; a connection that completes or ends, a FIN, a shutdown and a connection queued on a listener are every kind. So data that comes to a socket watched for output alone is no edge, as in Linux.

`recvmsg` supports datagram sockets, including packet sockets, and supplies no ancillary data. `PACKET_AUXDATA` and `IP_HDRINCL` return `ENOPROTOOPT`. `shutdown` applies only to a connected TCP socket. `SHUT_RD` is a no-op; a direction that includes write starts the normal TCP close.

The effective options are `SO_BROADCAST`, `SO_REUSEADDR`, `IP_TTL`, `SO_ERROR`, and `SO_TYPE`. `SO_KEEPALIVE` and `TCP_NODELAY` report off and have no effect. Most other unknown options are accepted and ignored. `SO_ERROR` returns and clears the pending TCP error. `SO_BINDTODEVICE` stores any registered interface's index and reads back its name; an empty name clears it. The setting does not restrict socket traffic. Packet sockets select an interface through `bind` with a `sockaddr_ll`.

## Packet and raw sockets

A packet socket binds to interface index zero, for every interface, or to any index the machine has, and to IPv4 or ARP. Each binding and its queue are allocated together from the heap, without a fixed count of bindings. Each has an eight-entry queue of payloads up to 1500 bytes. A full queue drops the newest frame. Receive omits the Ethernet header and reports the sender, protocol, interface, hardware type, and packet type in a 20-byte `sockaddr_ll`. Send accepts a nonempty payload of at most 1500 bytes plus a destination MAC address and supplies the Ethernet header.

Each raw ICMP registration and its queue are allocated together from the heap, without a fixed count of registrations. Each has an eight-entry queue of whole IPv4 datagrams up to 1500 bytes. Every matching socket receives a copy; a full queue drops the newest datagram. A raw send preserves the caller's ICMP bytes and checksum, adds the IPv4 header, and applies the socket's `IP_TTL`. The largest ICMP message is 1480 bytes, leaving room for the 20-byte IPv4 header within the 1500-byte MTU. A larger message returns `EMSGSIZE` before transmission, including on loopback.

## Netlink

`socket/netlink.c` has the `AF_NETLINK` sockets of `NETLINK_ROUTE`, through which a program asks what interfaces, addresses and routes the machine has: BusyBox's `ip` and glibc's `getifaddrs` ask nothing else, and Chromium watches the addresses through one. A request is a netlink message sent to the kernel; its answer is built in a page from the heap and queued on the socket as datagrams of at most 4096 bytes, each read whole or cut as a datagram socket's. `RTM_GETLINK`, `RTM_GETADDR` and `RTM_GETROUTE` with `NLM_F_DUMP` answer with a message for each interface, each IPv4 address, the first ones before the others, and each route of the table, from the records the interface ioctls read and write, each with `NLM_F_MULTI`, then `NLMSG_DONE`; `RTM_GETLINK` of one index answers its interface or `ENODEV`. A privileged caller's `RTM_NEWLINK`, `RTM_SETLINK`, `RTM_NEWADDR`, `RTM_DELADDR`, `RTM_NEWROUTE`, `RTM_DELROUTE`, `RTM_NEWNEIGH` and `RTM_DELNEIGH`, which `ip link set`, `ip addr`, `ip route` and `ip neigh` send, change an interface's flag, its addresses, its default gateway, the route table and the ARP cache through the operations the ioctls use, with Linux's `EEXIST`, `ESRCH` and `ENOENT` for a change already made or nothing to undo, and are acknowledged when `NLM_F_ACK` asks; what an interface here cannot hold, another MTU or a name, is `EOPNOTSUPP`, as is a type the kernel does not know. The messages of a send end at one shorter than a header or longer than the bytes left, and the rest is ignored, as Linux ignores it: `ip` sends its route dump request in a buffer longer than the request. A socket is bound to a port id at its first send or `getsockname` if the program does not bind it: the process ID for its first and a number above 2^31 for the rest. The kernel sends no notifications, so a socket bound to multicast groups hears nothing. A socket of `NETLINK_KOBJECT_UEVENT`, which udev's monitors open, is made and bound like the other and hears nothing, since the kernel sends no uevents. `netlink(7)` has the contract.

## Netconsole

Netconsole is the last destination of the kernel log (see [the kernel Readme](../../Readme.md)), so it is offered every record from the first one, before there is a device to send through. Records collect until `netconsole_enable`, which `rach2.netconsole` asks for once a network device is up, and it then drains them. While the card's link is down, as a real card's is for the seconds its PHY takes to negotiate, they stay in the ring, and the first line after the link comes up drains them. The ring is 8192 bytes with 8191 usable slots; new characters are dropped when it is full. After enable, a newline or 512 buffered bytes starts a transmission. The debug shell's own output is not a record and never reaches the wire.

Each broadcast Ethernet frame uses EtherType `0x88b5`. Its payload starts with a 16-byte big-endian header containing `RCH2`, a nonzero per-boot id, a sequence number, the payload length, and a one's-complement checksum. Frames have no acknowledgement or retry. Fixed buffers, the network interrupt lock, and a recursion guard permit calls from interrupt and error paths.

## Counters

`net_mib` in `net.h` keeps the MIB counters of RFC 1213 that Linux reports in `/proc/net/snmp` and `nstat` reads, for the layers this stack has: IP's datagrams in and out and the reasons it dropped some, ICMP's messages and echoes each way, TCP's opens, failed handshakes, reset connections, segments in, out and retransmitted, malformed segments and resets sent, and UDP's datagrams each way, those for a port no socket has and the malformed ones. Each is a 32-bit count from boot that wraps, as Linux's do on i386. The layers update them on paths the concurrency rule below already serializes, so they need no lock. TCP counts a segment sent only when IP took it, in `tcp_ip_tx`, and a connection ended by a reset or a timeout in `tcp_count_end`, as a failed attempt from a SYN state and as a reset from ESTABLISHED or CLOSE_WAIT; a connection a close aborts is not counted.

## Concurrency

Protocol transmit buffers, driver descriptors, ARP state, and the socket and TCP lists are shared. IRQ handlers already run with interrupts disabled. Syscall paths use `net_lock` to save the interrupt flag and disable interrupts across shared-state operations. All three transmit paths also protect their descriptor handoff. The timer runs `netdev_poll`, `tcp_tick`, and `ip_loop_drain` in that order at 100 Hz.

## Verification

The default suite runs its whole probe list over the emulated card and SLIRP. It includes `loopprobe`, which covers UDP and TCP against the local address without touching the wire, and `sockettest` and `dnstest`, which reach SLIRP's own services. `tests/run pools` separately opens forty-eight sockets at once, then makes and closes a thousand sockets and requires the heap's bytes in use to remain unchanged and its page count to remain within two of the starting count. A probe that needs a peer on the host has a suite of its own.

The specialized network targets are:

* `tests/run addressed` boots with an address on the command line, runs `pingtest`, and requires the capture to show that address as the source of the machine's packets and of its ARP requests.
* `tests/run ping` checks replies, timeout, serialization, process progress, and slot release.
* `tests/run netif` checks interface queries, runtime reconfiguration, interface-down behavior, connection reset, and listener survival.
* `tests/run dgram` checks connected UDP, broadcast permission, shared binds, service-port permission, and socket options.
* `tests/run packet` checks packet-socket validation and live IPv4 and ARP exchange.
* `tests/run raw` checks raw ICMP fan-out, queue limits, routing errors, hop limits, caller checksums, and `traceroute`.
* `tests/run dhcp` checks the BusyBox and in-house DHCP clients, renewal, fixed configuration, routing, and unattended startup.
* `tests/run netconsole` validates captured frame headers, sequence numbers, checksums, and early buffered output.

`tests/run host` drives ARP replacement, address parsing and transitions, netconsole buffering and recursion, the receive parsers against malformed frames under AddressSanitizer, the TCP state machine segment by segment, and the RTL8168GU software model. `socket_wake_hosttest.c` checks the kind of change each wake from the receive side names: data for a datagram and for TCP data, and no wake for TCP data a full receive ring takes none of, room for freed send-ring space, and every kind for a FIN, a connection's completion or end, and a queued connection. `raw_hosttest.c` and `netif_hosttest.c` check that a datagram queued for a raw socket, and a frame for a packet socket, wake the socket's queue for data alone, and `tests/musl/epollmusl.c` that a datagram, and a TCP segment over the loopback, are no edge for a socket watched for output. `pingtest`, `udptest` and `tcptest` are excluded from the default runner because each needs a peer: `ping` answers the first and `socket` starts a host peer for the other two.
