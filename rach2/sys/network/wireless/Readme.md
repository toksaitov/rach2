# The wireless station interfaces

The wireless interfaces divide a Wi-Fi station into a radio driver, a worker, scanning and the BSS table, the station's management state machine, the data path and keys, and an nl80211 server. The headers define the calls and ownership between these parts. `elems.c` parses management-frame information elements and builds the elements a station sends. The radio operations serve both a software medium and a physical radio; neither exposes its private records to the station layer.

## Interfaces

### Frames and elements

`ieee80211.h` defines the station's management, control and data formats, frame-control bits, elements, authentication status and disconnect reason codes, and cipher and AKM selectors. Wire structures use byte arrays for integers, with little-endian byte order unless the field says otherwise. A suite selector is a host integer whose four wire bytes are big endian. A frame begins at frame control and excludes the FCS. `IEEE80211_MAX_FRAME_LEN` bounds the buffer, including encryption headers and tags.

`ieee80211_parse_elems` returns pointers into its input, each at an element's id byte, followed by its length and payload. The caller keeps that buffer unchanged while using the table. A truncated header or payload, an invalid known length, or a repeated singleton returns `-EINVAL` and clears the whole table. An empty SSID is valid. Unknown elements are retained without interpreting their payload. Vendor elements may repeat: WPA, WMM information and WMM parameters have separate references and each may appear once. Extension elements may repeat with distinct extension ids; the ordinary table retains the first. The parser checks framing and known element lengths; RSN suites and counts, country triplets and HT capability contents are checked by their consumers.

`ieee80211_put_elem` appends one bounded element. `ieee80211_build_sta_elems` writes a station's SSID and rates, splitting rates after eight, and optionally RSN, HT capabilities, extended capabilities, WMM information and RSNX. The optional inputs are element payloads without their id and length. A zero SSID length emits a wildcard SSID; zero optional lengths omit those elements. The builder validates all inputs and the complete size before writing, so a failure changes neither the buffer nor its output length. Buffers must not overlap. A WPA vendor element can be appended with `ieee80211_put_elem`.

### Radio and station

`radio.h` follows the division of Linux mac80211's `ieee80211_ops`, with Rach2's own records and calls. A driver supplies immutable band capabilities, its address, hardware ciphers and operations in a driver-owned `wlan_radio`. The registry assigns its `phyN` number and the station record. Registration takes no ownership of the driver's storage; unregister stops the device and drains callbacks before returning it.

Start, stop, channel/filter configuration and transmit are required. Hardware scanning, key slots, station notifications, BlockAck, TSF and `tx_idle`, which says whether the radio has finished its frames, are optional. An unsupported key operation selects software encryption; another error fails the operation. Channels are in MHz, legacy rates in 100 kbit/s, and signal in dBm at the driver boundary. The BSS table and counters use mBm for nl80211. HT MCS indexes are distinguished from legacy rate indexes by `WLAN_RATE_MCS`. The first unused rate-series slot has index -1 and count zero. Access categories use mac80211's voice, video, best-effort, background order.

A transmit operation copies its frame and metadata before returning success and later reports exactly one status with its cookie. A refused transmit produces no status; `-ENOBUFS` says the ring is full, and is returned only while it holds frames whose statuses will come, since the station waits for one before it tries again. A status says which rates were tried and whether the frame was acknowledged, filtered or failed. Completion delivery must have room independent of receive traffic. Stop quiesces DMA and interrupt callbacks and completes accepted transmissions before returning. Receive copies a frame and its status to work-owned storage; the driver can reuse its buffer on return. A full receive queue returns `-ENOBUFS`. A decrypted receive with its IV stripped must supply the PN and key index, so that stripping cannot bypass replay checks.

`wireless.h` defines BSS snapshots, scan requests, keys, counters, work records and station events. BSS records own their element bytes. The station states are none, authenticating, authenticated, associating, associated and authorized. Association gives carrier; authorization opens the control port to ordinary data. EAPOL must pass before authorization. The management and data implementations have their private declarations in their own headers.

### Execution and ownership

One wireless worker serializes station transitions, scans, BSS changes, keys and events. Driver operations and nl80211 handlers run in process context under the kernel lock without `net_lock`; operations documented as sleeping may release the kernel lock through the scheduler. Code takes `net_lock` only around a network-stack operation and never waits for the worker while holding it. Interrupt entry points only copy and enqueue receive frames, completion records, scan completion or rfkill changes. They never run management or encryption code in the interrupt handler.

A work record remains live until its callback returns or cancellation finishes. Queuing an already pending or running record returns `-EBUSY`. A callback uses another work record for a later operation. Cancellation may sleep and cannot be called by the callback being cancelled. Event delivery borrows its frame only for the call; nl80211 must copy what it queues. Registry and key calls state their context and errors in the headers.

### Encryption and keys

`wcrypto.h` defines allocation-free AES-128, CMAC, CCMP-128, BIP-CMAC-128, Michael, TKIP key mixing and RC4. AES uses no secret-indexed lookup table. Keys and schedules belong to the caller, which erases them at removal. CCMP and BIP operate on a bounded complete MPDU in place. A failure leaves the frame, length and result counters unchanged. BIP signs a group-addressed management frame without setting the Protected bit; its body remains plaintext. The headers give exact expansion sizes and buffer-overlap rules.

PN and IPN are host-order 48-bit counters. The caller assigns a fresh transmit value before encryption and never wraps it or reuses it after a reset. Receive checks replay per TID and commits the counter only after successful authentication. Installing identical key bytes again preserves counters. TKIP key bytes are the temporal key followed by the local transmit and local receive Michael keys. Slots 0 to 3 hold group data keys, 4 and 5 integrity keys; pairwise keys also name their peer. A group rekey does not remove the pairwise key. The radio's hardware slot is separate from the over-the-air key index.

### Data path

`data.h` is the data path's interface. The registry attaches one `struct wlan_data` to each station with `wlan_data_attach`, which installs `tx_ethernet`, and frees it with `wlan_data_detach` after the radio stopped. Everything else runs on the wireless worker.

The data path owns the radio's interrupt entry points `wlan_radio_rx` and `wlan_radio_tx_status`. They copy into a queue of 144 received frames, what one service of ath9k's two FIFOs can hand up, and one of 256 completions, one for each frame ath9k's four rings of 64 can hold, under a spinlock, and queue the drain; a full receive queue returns `-ENOBUFS`. A report of tries alone (`WLAN_TX_NO_FRAME`), which ath9k sends for an aggregate whose frames all stay for another try, has a queue of 16 of its own, so that it never takes a frame's place; one that finds that queue full is merged into a queued report of the same rate series, as one report of the MPDUs of both whose counts are their mean weighted by MPDUs, exact when the counts agree. A completion that finds no room is counted in `tx_status_lost`, which `/proc/stat` shows as `wlan_tx_status_lost`. A frame the radio has acknowledged is the AP's to forget, so a radio asks `wlan_radio_rx_full` before it reads a frame and leaves the frame in its own buffers while the queue is full; `rx_held` counts that, and `rx_wait_most` the longest time in ticks that frames waited for the worker, which runs under the big lock. `/proc/stat` shows them as `wlan_rx_held` and `wlan_rx_wait_most`. The drain takes completions first, then each frame, and after every eight frames sends what is queued, since a stream of received frames could otherwise hold back what they made TCP answer. One call takes at most 32 frames and completions; when more wait it queues its other work record at the current tick, moving it there if an interrupt queued it earlier, so that a timer already due, such as a scan's return, a reordering release or a renewal's rescue, runs before the rest of a steady stream. A pairwise key's install takes every completion and the frames queued when it is called. A data frame or a BlockAckReq goes to `wlan_data_rx`. A management frame goes to `wlan_data_rx_mgmt`, which checks and removes CCMP or BIP and says whether the frame came protected, and then to the `rx_mgmt` hook, which is `wlan_mlme_rx`; what the hook leaves goes by default to the BSS table (beacons and probe responses), to `wlan_data_rx_action` (Block Ack), or to `wlan_event` as `WLAN_EVENT_FRAME` (other actions). Whether an unprotected robust frame is acceptable is the MLME's policy. A completion whose cookie has `WLAN_DATA_COOKIE` set is counted and passed to rate selection, and every completion then goes to the `tx_status` hook.

The adapter's `tx_ethernet` copies a frame into a transmit queue of 24, whose last two slots take only EAPOL, the four before them no bare TCP acknowledgement and the four before those no TCP data, and queues the transmit drain, which checks the control port again and sends each frame through `wlan_data_tx`. A radio that refuses a frame with `-ENOBUFS`, its ring for the frame's access category being full, leaves the frame at the head of the queue, and the queue is held: frames queued meanwhile wait without queuing the drain, and the drain of completions queues it once it has taken a completion, since each frees a slot. This is Linux's `ieee80211_stop_queue` and the wake from the driver's completions, kept in the data path because a network interface has no queue to stop. Any other refusal, a closed control port or a lost connection drops the frame and counts it in the interface's `tx_dropped`. The queue refuses first what its sender sends again. A segment of more than one byte of TCP data, read from the frame's IP and TCP headers, stops at 14 waiting frames, since TCP keeps it and sends it again at once. A bare TCP acknowledgement stops at 18, since TCP sends a fresh one on its next tick. Any other frame refused is lost or waits for a timeout: a ping, a DNS or DHCP request, ARP, a SYN, a FIN, a reset, and a keepalive or zero-window probe, one byte long, whose sender ignores the refusal. So those keep the slots above behind a bulk transfer each way, as Linux's per-flow queues do. Other frames stop at 22, so that wpa_supplicant's reply to a group rekey finds room behind them all, as Linux's voice queue gives it room; a reply that cannot be sent makes wpa_supplicant deauthenticate. `tx_refused_tcp`, `tx_refused_ack` and `tx_refused_other` count what a full queue refused, and `/proc/stat` shows them as `wlan_refused_tcp`, `wlan_refused_ack` and `wlan_refused_other`. A refused frame makes `wireless_tx` answer `NETDEV_TX_DROPPED`, as the RTL8168 does when its ring stays full: `ethernet_tx` counts a transmit drop, an IP sender sees `ENOBUFS`, for which TCP keeps its segment to send again, and a packet socket's send fails with `ENETDOWN`. A disconnect, which `wlan_stop` makes before it stops the radio, empties the queue and ends the hold. While the AP's channel switch of mode 1 is under way, `wlan_data_stop_tx` stops the drain, which leaves frames queued, as mac80211 stops its queues for `IEEE80211_QUEUE_STOP_REASON_CSA`; the switch's end, or a disconnect, sends them again.

`wlan_data_mlme_tx` has the signature of the MLME's `tx` operation. It sends a management frame with the non-QoS sequence number and the lowest basic rate, protected on request: CCMP under the pairwise key when individually addressed, BIP under the default integrity key when group addressed. `wlan_set_state` tells the data path of each committed state through `wlan_data_state`: reaching association, or moving it to another BSS, connects the data path, with QoS when the BSS sends WMM parameters and privacy when its capability says so; leaving association disconnects it and removes every key. The softMAC station then gives a connected data path the management protection the association negotiated, which the registry does not know, so that its BlockAck action frames go protected when the AP requires it.

`wlan_install_key`, `wlan_remove_key` and `wlan_default_key` of `wireless.h` are the data path's. A pairwise key takes index 0 or 1 and the AP's address; CCMP and TKIP group keys take 0 to 3 and BIP keys 4 and 5. The receive counters given at installation are the RSC; the same key bytes installed again keep the counters. Before a pairwise key is installed, `wlan_install_key` takes the frames the radio has queued and empties the reordering buffers, so that what the old key opened is judged under the old key's counters. It also sends what was queued, message 4 of a renewal among it, so that the AP can read it; while a full ring or a channel switch of mode 1 keeps those frames, it changes nothing and returns `-EINPROGRESS`, for nl80211 to call again every 10 ms, and what is queued after the key waits for the key. After 4 s (`WLAN_DATA_REKEY_WAIT`) on a dead link the key goes in with the data still queued. EAPOL still queued was written for the key in place, so then the install fails with `-ETIMEDOUT`, the old key stays, and wpa_supplicant deauthenticates and joins again. A frame still in the radio's ring when the key changes comes up with the old key's slot in `hw_key`, and `wlan_data_rx` drops it and counts it in `rx_dropped`: under the new key it would set the counter to the old key's number, and every frame after it would be a replay until the AP's new count passed that number, about as many frames as the old key carried. The most recently installed pairwise key transmits. Each pairwise installation logs the transmit number the old key reached, and the connection's decrypt errors, duplicates and replays so far. On a connection with privacy, `wlan_data_tx` sends a data frame other than EAPOL only under a pairwise key and refuses it with `-ENOKEY` while there is none, so that removing the key sends nothing in clear, queued frames included.

### Generic netlink

[`../socket/genetlink.h`](../socket/genetlink.h) defines the generic-netlink registry used by nl80211. A registered family supplies its name, version, private header size, largest attribute id, policy, commands and multicast groups. Family and group ids are assigned at registration. Command handlers have separate request and dump entry points. `GENL_ADMIN_PERM` asks the dispatcher to check `net_admin` before calling either entry point. Registration and unregister are process-context operations; unregister ends active dumps before returning the family storage.

The dispatcher validates message and private-header bounds before handing a request to a handler. `nla_parse` validates attributes against a policy and produces borrowed pointers; getters require that validation. Native-endian scalar values need no aligned access. Unknown ids above `maxattr` are skipped; a repeated id takes its last value, as Linux takes it, and malformed bounds fail. Strings include their final NUL, flags have no payload, and nested policies are checked with `nla_parse_nested`. Message append errors are sticky. A nest's offset remains valid if its backing buffer moves; nests finish or cancel in reverse order.

A request handler emits replies through `genl_reply`; dispatch owns ACK and error messages. A dump keeps a stable copy of its request and a six-word cursor, appends only complete messages, and advances its cursor only for a message that fits. Its return distinguishes more output, completion and error; dispatch emits `NLMSG_DONE`. The optional cleanup runs once, including when the socket closes. Multicast group ids are global and may exceed 32. A delivery overrun is recorded for each affected socket as `ENOBUFS`.

`genl_unicast` sends a family's message to one port, the way nl80211 delivers a registered frame; it returns `-ECONNREFUSED` when no generic socket has that port and `-ENOBUFS`, recorded on the socket, when its queue is full. A family's optional `release` call runs when a generic socket closes, with the socket's port, so that the family can drop what it keeps for that socket.

### nl80211

[`nl80211.h`](nl80211.h) declares how a station becomes reachable through nl80211, and `struct nl80211_ops`, the calls nl80211 makes into it, in the shape of Linux's `cfg80211_ops`: scan, authentication, association, leaving, the port, the keys, management frames, the station's state, and an optional `connect` and `disconnect` for a station that joins by itself. `nl80211_attach` gives nl80211 a station's radio, its band after the regulatory rules, its interface, its BSS table and its operations; `nl80211_init`, which the registry's `wlan_init` makes at boot and the first attachment makes if it has not run, registers the family and installs nl80211's event consumer with `wlan_set_event_handler`, through which the registry's `wlan_event` passes each event on. `nl80211_detach` ends with `-ENODEV` the requests still waiting for the worker and those that have run but whose handler has not yet woken, and from its start refuses with `-ENODEV` every new request and every queued one the worker comes to, so that a key's retry never reaches a freed station. Every call of `nl80211_ops` but `status` runs on the worker, may sleep and borrows its arguments; `status` must not sleep. A join with the access point just left waits 150 ms from the frame of leaving, on the worker's queue: a TP-Link access point loses a join sent 5 ms after the deauthentication, and the station would then wait out its timeouts, about 11 s. What follows a call, such as the access point's answer, comes back as an event. [nl80211(7)](../../../../man/man7/nl80211.7) gives the commands, attributes and events user space sees.

[`sta.h`](sta.h) declares the softMAC station, the implementation of `nl80211_ops` for a radio of `radio.h`. The registry calls `wlan_sta_attach` at registration, once the data path is attached, and `wlan_sta_detach` first at unregistration, before the radio stops.

### Software-medium datagrams

The `/dev/wsim` endpoint and both relay programs use version 1 of this format. The constants and offsets are in `relay.h`, which `wireless.h` includes. A UDP datagram is exactly one 40-byte header followed by `frame_len` bytes. All multi-byte integers are big endian, including cookie and TSF. Signed signal is a 16-bit two's-complement dBm value. No C structure, pointer, padding or host-endian integer is sent directly.

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 4 | Magic `0x5753494d`, ASCII `WSIM` |
| 4 | 1 | Version, 1 |
| 5 | 1 | Type: 1 frame, 2 transmit status |
| 6 | 2 | Header length, 40 |
| 8 | 2 | Endpoint-local radio number |
| 10 | 2 | Flags |
| 12 | 2 | Frequency, MHz |
| 14 | 2 | Rate, 100 kbit/s, or MCS index with the MCS flag |
| 16 | 2 | Signal, signed dBm; 0 if unavailable |
| 18 | 2 | Frame length, 0 to `IEEE80211_MAX_FRAME_LEN` |
| 20 | 8 | Transmit cookie; 0 for an unsolicited receive |
| 28 | 8 | Receive TSF in microseconds, 0 if unavailable |
| 36 | 1 | Actual transmit attempts, 0 if unavailable |
| 37 | 3 | Reserved, zero |

Flags are TX `0x0001`, ACKED `0x0002`, NO_ACK `0x0004`, FAILED `0x0008`, MCS `0x0010`, SHORT_GI `0x0020` and SHORT_PREAMBLE `0x0040`. A frame from a transmitting radio has TX set and a nonzero outstanding cookie. The peer medium routes its bytes to receiving radios tuned to the frequency, clearing TX, cookie and attempts in receive records and filling the destination endpoint's radio number and receive metadata. A relay maps its peer's radio numbers to local radios explicitly; the number is never a kernel pointer or interface index. Encrypted frames stay encrypted across the medium. Payload includes the MAC header, encryption header and tag, and excludes FCS and radiotap.

A transmit-status datagram has no payload, frame length zero, TX set, and the originating radio number and cookie. ACKED means an acknowledged transmission; NO_ACK means no acknowledgement was requested; FAILED means it failed. Exactly one of these three outcomes is set. An acknowledged group-addressed or NO_ACK frame is invalid. The medium reports a status once per accepted transmit, including failure when no suitable receiver exists. The sender correlates it with an outstanding radio/cookie pair, rejects unknown or repeated completions and completes that transmission once. Rate and attempts describe the last attempted series; the driver keeps the original series with the cookie. A disconnected relay fails its outstanding transmissions during stop.

A receiver refuses a wrong magic, version, type or header length, nonzero reserved bytes, unknown flags, an impossible length, a truncated or trailing payload, or a status with an invalid outcome. A frame has at least a ten-byte control header and no ACKED or FAILED flag. A receive record has no TX or NO_ACK flag, no cookie and no attempts. Frequency and rate must belong to the selected radio; MCS requires HT support. Status metadata cannot be used to select a different radio or transmission. A relay sends to a configured peer address and port and takes datagrams from that address, whatever their source port, which a NAT may change. The relay's transport card is separate from the cable interface whose link the roaming checks change.

## Design

### Drivers

A driver plugs in at one of two levels. A softMAC chip, whose host runs the MLME, as `wsim` and [`driver/ath9k/`](../driver/ath9k/Readme.md) do, fills a `wlan_radio` with its `wlan_radio_ops` and registers it; registration attaches the softMAC station of `sta.c`, which gives `nl80211_attach` its `nl80211_ops`. A fullMAC chip, which runs its own MLME, would give `nl80211_attach` `nl80211_ops` of its own in place of `sta.c`'s, with `connect` and `disconnect` since it joins by itself; no driver does yet, and registration attaches `sta.c` to every radio. Above either level lie the parts a driver reuses rather than writes: the BSS table, the key records, the software ciphers of `crypto/`, rate control through `wlan_rate_ops`, the radio's rfkill switch and the regulatory rules. A new chip supplies only its hardware's calls.

### Registry and regulatory rules

`radio.h` is the driver boundary. The registry, Ethernet adaptation and world regulatory rules implement it above the radio. A driver advertises its capabilities once; regulatory rules narrow the channel set rather than expanding it.

`wiphy.h` defines the registry-owned station record. `wlan_register_radio` validates a borrowed radio and attaches an initially down `wlanN` interface. Radio numbers increase through 999 and are not reused; four physical and radio interfaces together fit the network table. A registration failure leaves no interface or radio attachment. Registration starts the shared worker, attaches the embedded scan and BSS table and attaches the data path; unregister detaches the scan, then the data path, and destroys the table after holders have drained. `wlan_stop` disconnects the data path, which removes its keys. `wlan_radio_scan_done` routes a hardware completion to that embedded scan. `wlan_event` dispatches to the consumer installed by nl80211 with `wlan_set_event_handler`; until the server attaches, events have no consumer. `wlan_start` and `wlan_stop` run in process context without `net_lock`. The interface's `set_up`, which `netconf_set_up` calls for `SIOCSIFFLAGS` and `RTM_NEWLINK`, starts the radio as `wlanN` comes up, and refuses with `-ERFKILL` while the radio's switch is blocked, as Linux does; the rfkill section has the rest. On the way down it carries the rest to the worker and waits: a scan is aborted, the station deauthenticates, sending the frame and reporting it to nl80211, and the radio stops; a frame the radio has not sent by then is lost, as its stop fails what it holds. Each request to come up or go down is linked on its radio while it sleeps, in the driver's start or waiting for the worker; unregister marks every such request gone and waits until the worker has run each way down and each start has returned, and a caller that wakes to find its request gone answers `-ENODEV`, which `netconf_set_up` returns without touching the freed interface. Until an interface is up, nl80211's scan, authentication, association and frame transmission answer `-ENETDOWN`, as cfg80211's do. `wlan_set_state` asks the optional driver state callback before committing the state and borrowed BSS; a refusal keeps the old state, except that a move to none always commits, since a station that has left cannot stay associated. The management layer holds that BSS while using it, and the BSS's channel becomes the station's `frequency`, on which the MLME's frames go out before the data path connects. Associated and authorized states have carrier. Only the authorized state passes ordinary data.

The data worker installs `tx_ethernet`, which copies an Ethernet frame into its queue and returns without sleeping. The network adapter gates every frame, including a direct packet-socket send, before that callback. A missing callback refuses the frame. The data worker must check the port again before transmitting a queued frame, since association and authorization can change while it waits. On receive it calls `wlan_rx_ethernet` after decryption and replay checks; this applies the same gate before any packet socket or IP handler sees the frame. EAPOL, EtherType `0x888e`, passes while associated with a closed control port. Stopping or blocking the radio prevents EAPOL too. `quiesce` is installed by the worker and cancels and drains this station's work during unregister, after the driver stops and reports its pending completions. Unregister clears routes, addresses and permanent as well as learned neighbours before freeing the station.

`wlan_encap` converts Ethernet II into a station's ToDS frame with the AP, station and destination addresses and an LLC/SNAP header. IPX and AARP use the bridge-tunnel OUI `00:00:f8`; other protocols use RFC 1042's `00:00:00`. `wlan_decap` accepts FromDS three-address data, including QoS and its optional HT control, after decryption and reassembly. It refuses null frames, four addresses, A-MSDU, wrong BSSIDs and remaining protection or fragmentation. RFC 1042 IPX and AARP remain LLC payloads in an 802.3 Ethernet frame; bridge-tunnel versions become Ethernet II. An 802.3 frame retains its LLC payload in both directions; encapsulation checks its length field and omits any Ethernet padding. Both helpers preserve outputs on an error and borrow non-overlapping buffers. The data layer supplies sequence numbers, encryption, duplicate and replay checks, aggregation and rate selection.

`reg.c` intersects each advertised channel with the world domain: channels 1 to 11 permit active use, 12 and 13 are passive, and 14 is disabled. An EEPROM country of US or CA also disables 12 and 13. Unknown country codes keep the world rules; the radio's advertised flags and power can restrict them further. No rule clears a restriction or raises power. The power ceiling is 20 dBm. `wlan_channel` returns no disabled channel and excludes passive channels for active use.

The registry publishes `/sys/class/ieee80211/phyN`, its `index`, `name`, `macaddress` and `uevent` attributes, the interface's `phy80211` link, and `device/driver` with the registered driver name. `/proc/net/wireless` reports link quality, signed dBm signal and noise, decrypt, fragment, retry and discard counters and missed beacons. Wireless extensions are absent: `SIOCGIWNAME` returns `EOPNOTSUPP`.

### Worker, scan and BSS table

`work.h` declares the worker, the scan and the BSS table; the registry embeds a `struct wlan_scan` and a `struct wlan_bss_table` in its station record.

`work.c` is the worker: one kernel thread, `kwlan`, which `wlan_work_start` makes before the first radio starts. A radio registered at boot, before the first program, only asks for the thread, and `platform_threads_start` makes it once init has pid 1, which BusyBox's `reboot` and `poweroff` signal; its work waits in the queue until then. A thread that cannot be made, for want of a stack or a process record, is tried again by whoever would sleep on its work: each nl80211 request, which answers `-ENOMEM` when it still cannot be made, and the interface, which then stays down, or on the way down stops the radio itself. The queue is a list in order of due tick, with work of equal ticks in the order queued. Work queued for tick zero is due at the tick it was queued, behind any work already due, so that the receive and status drains, which queue themselves at once while frames come, never hold back a timer that has come due. The thread sleeps in an idle wait whose deadline is the earliest due tick, and wakes when that tick comes or when new work changes the earliest one; it then runs every callback due, under the big lock, reading the tick again before each, so that work those callbacks queue at once runs in the same pass. `wlan_queue_work` takes a spinlock with interrupts off, so an interrupt handler can queue. The queue compares the running record by pointer only, so its owner may reuse it once the callback returns; `wlan_cancel_work` waits for a running callback outside the worker, and never on it. With scheduling off, as when the shutdown stops the cards, it does not wait: the timer may have switched the worker away inside a callback, which then never runs again.

`scan.c` scans. `wlan_scan_start` checks and copies the request and queues its start; the worker then tries the radio's `scan_start`, and on `-EOPNOTSUPP` scans in software. A software scan visits the requested channels, or every channel the band allows, skipping disabled ones and repeats. On each it tunes the radio with the home filters and `WLAN_FILTER_OTHER_BSS`. Where the channel is active and the request names SSIDs, it sends a probe request for each SSID and stays 30 ms; otherwise it listens for 110 ms, as Linux's mac80211 does. A probe request goes at the lowest rate with no acknowledgement asked for. It carries the SSID, the rates split after eight, the DS Parameter Set, HT Capabilities when the band has HT, and then the request's elements. Its cookie has `WLAN_SCAN_COOKIE` set, so that the transmit status can be told from the data path's and dropped. Each step queues the next on the other of two work records, since a callback cannot queue its own. The scan reports `SCAN_STARTED` when it begins, and `SCAN_DONE` or `SCAN_ABORTED` last, after the software scan has returned to the home channel the MLME set and stale entries have left the table. A radio that refuses its own scan with another error ends the scan as aborted. An abort cancels the radio's scan through `scan_cancel`, or cancels the pending dwell and finishes at once.

An associated station's software scan goes away in trips, as mac80211's does. The station's `ask` call, `sta_scan_ask`, is the scan's one way to the data path and the MLME. The scan does not start while the MLME is authenticating, associating, polling, renewing a key or following a channel switch, and tries again every 200 ms; refused five times, the last 0.8 s after the first, it ends in `SCAN_ABORTED`. It stops the transmit queue, waits up to 100 ms for the driver's frames to end through the radio's `tx_idle`, which also holds back block ack requests, tells the AP with a null frame that has power management set, and tunes away only once the radio has finished that frame and the AP has acknowledged it. The data path sends a null frame that the radio refuses or the AP does not acknowledge once more. If both attempts fail the station stays home as after a radio that does not finish, and the scan tries again. A frame still unfinished 100 ms after it was sent ends the scan as aborted, with the radio never tuned, since a retune would destroy the frame. mac80211 reads no status of these frames and tunes when its flush ends; here the frame survives and the AP is known to be told, at the cost of no scan on a link too weak to carry the frame. A trip ends before it would pass 125 ms, or after one channel when frames wait. The home channel, reached from home, is scanned there without a trip: the queue runs, the AP is not told and the radio's filter alone changes, which a radio does without destroying what it holds, as mac80211 does for a scan of its operating channel alone; mac80211 visits it in a trip within a longer scan. Reached during a trip, it is one more channel of the trip. The radio then goes home, a null frame with power management clear tells the AP, once more if it fails, the queue starts again whatever became of it, and the station stays home 200 ms. While away from home the MLME's monitor counts no silence and starts no rejoin; on the way back it restarts its clocks. An MLME that leaves the AP sends the scan home first. A return that fails to tune ends the scan as aborted. The periodic calibration skips its turn while the filter has `WLAN_FILTER_OTHER_BSS`, and a retune starts the recovery checks' receive window again. The scan takes its event call at attach, `wlan_event` in the kernel, so that `scan.c` links before nl80211 does.

`bss.c` keeps up to `WLAN_MAX_BSS` entries, keyed by BSSID and channel, each allocated when first heard. A beacon or probe response gives an entry its SSID, signal in mBm, TSF, beacon interval, capability and elements. Its channel is the DS Parameter Set's when present, since a 2.4 GHz receiver hears neighbouring channels, and a frame from a channel the regulatory rules disable is dropped. A beacon with a hidden SSID keeps the SSID and elements a probe response gave the entry, as cfg80211 does for hidden networks. The MLME holds the current BSS, which then neither ages out nor is evicted. When the station follows its AP to a new channel, the MLME gives the held entry the new frequency and `wlan_bss_moved` removes any other entry of that BSSID there that nobody holds, so that the AP's beacons on the new channel update the held one. An entry nobody holds leaves the table 30 s after it was last heard, at the end of each scan and before each dump; when the table is full, the oldest such entry makes room. `generation` changes whenever an entry comes or goes, for nl80211's dumps.

### Management state machine

`mlme.c` and `mlme.h` hold the station's MLME, after the design of Linux's `net/mac80211/mlme.c`; no code is taken from it. The interface embeds a `struct wlan_mlme` and gives it eight calls: `tx` sends a management frame through the data path, `state` commits each station state through `wlan_set_state`, which asks the radio, and then gives the data path the negotiated management protection, so that carrier follows association and the control port follows authorization, `event` is `wlan_event`, as the scan's event call is, `poll` and `heard`, which an interface that learns of no ACK leaves NULL, serve the connection monitor below, `hold` and `moved` carry the AP's channel switch to the data path and the registry, and `beacon_loss`, which may be NULL, is told of each beacon loss with the age of the AP's last beacon, for a log line that is temporary. The MLME takes its channels, rates and HT from the interface's band, after the regulatory rules. From authentication until the station leaves, the MLME holds the BSS with `wlan_bss_hold` and makes its channel the scan's home. nl80211's AUTHENTICATE, ASSOCIATE, DEAUTHENTICATE, DISASSOCIATE and SET_STATION's authorized flag map to the `wlan_mlme_*` calls of the same names, all on the wireless worker.

Open System is built here and tried three times, 200 ms apart. SAE runs in user space: each AUTHENTICATE carries a commit or confirm with its transaction and status as AUTH_DATA, and each SAE frame of the AP's goes up with whatever status it has. An anti-clogging request (76), a hash-to-element commit (126) or a commit waits two seconds for user space's answer; the AP's confirm after ours authenticates; any other status ends the attempt. An AUTHENTICATE or ASSOCIATE event without a frame means the request timed out. An authentication to a new AP while associated ends the old association as mac80211 does: reported as a local deauthentication, its frame not sent.

The association request has the capabilities, the listen interval and, when nl80211 names a previous AP, its address, which makes it a reassociation. Its elements are the SSID, the rates both ends know, the supplicant's RSN, HT capabilities for a 20 MHz channel when the AP has HT and the cipher allows it, the supplicant's extended capabilities, WMM information when the AP has WMM, the supplicant's RSNX and then its other elements. The response's AID, capabilities, rates, HT and WMM go into the station's state. A temporary refusal (30) with a comeback time is asked again after it, up to ten seconds.

Associated, the station watches the AP, as mac80211's beacon and connection monitors do. Seventeen beacon intervals without a beacon or probe response, 1740 ms at 100 TU and longer than mac80211 waits, so that a short silence of the AP does not end the connection, are a beacon loss, which the station dump and `/proc/net/wireless` count from the association on. Where the interface reports ACKs, as the softMAC station does with its `poll` and `heard` operations, a beacon loss or 30 seconds in which the data path heard no unicast frame from the AP and no ACK of one of its own makes the station poll the AP with a null data frame at the lowest basic rate, as mac80211 does on a radio with `REPORTS_TX_ACK_STATUS` such as ath9k: the ACK, a beacon or a probe response ends the poll, and a null frame not acknowledged, or one whose status has not come, goes again 500 ms after the last, where mac80211 asks again at once, so that the tries span a silence of the medium of up to 2.7 s from the last beacon. A beacon loss on an interface without ACKs starts unicast probe requests instead, 500 ms apart, which only a beacon or probe response answers. After three null frames or three probe requests unanswered the station leaves, reported as a local deauthentication of reason 4 with no frame sent. Under 802.11w, from association on, an unprotected robust frame is dropped, and the AP's unprotected deauthentication or disassociation is reported as `UNPROT_DEAUTHENTICATE` or `UNPROT_DISASSOCIATE` so that user space can ask the AP with an SA Query. The station answers the AP's protected SA Query request itself; other action frames, the answers to user space's SA Queries among them, go on to nl80211's registrations.

A renewal of the pairwise key has a limit here. An AP that gives a renewal up, as one does some 4 seconds after its first message when the reply is late, forgets the station without a word: its radio goes on ACKing, null frames included, its beacons go on, and nothing in wpa_supplicant times the handshake out. So when the AP's message 1 reaches a connection that has a pairwise key and no pairwise key goes in for 10 seconds (`WLAN_MLME_KEY_WAIT`), the station deauthenticates with reason 15 and wpa_supplicant joins again. mac80211 has no such limit.

The key going in ends nothing, since it says only that the radio has it. A unicast frame from the AP opened under the new key, data or a protected management frame, shows that the AP has the key, so that message 4 is owed no more, and never a beacon or an ACK, which the same forgetful AP goes on giving. It does not end the renewal: the AP's radio ACKs before its replay check, and its own frames need nothing from us, so that an AP can ACK all we send, pass none of it on and go on sending. Two things start the same 10 seconds after the key is in, ending in the same leave. Message 4 under the old key came back without an ACK, or with no status at all: the AP may never have had it, and its repeats of message 3 cannot be read here. A later message 4, sent after the AP repeats message 3, takes its place, so one acknowledged clears the failure. Or the AP ACKed unicast data under the new key: the wait starts at the first such ACK. Null frames, which carry no key, do not count, and neither do frames to a group address, such as mDNS, MLD or SSDP, which the AP ACKs as it takes them to relay. A link that has neither, message 4 ACKed and no data ACKed, owes nothing for as long as it stays idle, and the renewal stays recorded until the first data ACKed under the key, however long after, or the next renewal's message 1. Once that wait starts the station asks a question only a working link can answer: an ARP request for the gateway of the interface's default route, the card's own or the lowest added one, read afresh each time, sent again each 2 seconds (`WLAN_MLME_ASK_WAIT`), since one lost frame must not end a connection. The monitor looks at each beacon loss time, 17 beacon intervals, so the first goes within about 2 seconds. An ARP reply under the new key ends the renewal and counts in `wlan_rescue_saved`; with none when the 10 seconds and the last question's 2 are over the station leaves. An interface with no default route has nobody to ask, and its renewal ends there with no leave. A failed message 4 and a missing key have no question and leave at the 10 seconds. `wlan_rescue_key`, `wlan_rescue_message4` and `wlan_rescue_silent` in `/proc/stat` count the leaves by cause, and an association keeps them and `wlan_rescue_saved`.

Associated, the station follows its AP's channel switch, as mac80211's `ieee80211_sta_process_chanswitch` and `ieee80211_chswitch_work` do. A Channel Switch Announcement (element 37: mode, channel, count) or an Extended one (element 60: mode, operating class, channel, count), in a beacon or probe response of the AP, in spectrum management's channel switch action frame or as the public Extended Channel Switch Announcement action, names the new channel and the beacons left; the 2.4 GHz band needs no operating class. The switch is due count beacon intervals after the announcement, and at once for a count of 0 or 1; each later announcement sets the time again. Mode 1 asks the station to send nothing until then, so `hold` stops the data path's transmit. Until the switch the AP is neither probed nor polled, and the station does not leave it. An AP may also move unannounced, as one on automatic channel selection does. Its beacons are then still heard from the next channel, though its ACKs too seldom for the link to work or to fail, and mac80211's station, which does not read the element, leaves such an AP only by a failed poll, beacon loss or the AP's deauthentication. A beacon is not protected, so here a change of its DS Parameter Set, away from the station's channel, is a hint. On an interface with polls the station polls the AP at once, and beacons do not answer those polls: an ACK asks again 5 s later while the beacons still name that channel, a beacon of the station's own channel ends the matter, and three polls unanswered move the station. Moved, it needs a protected frame from the AP within 10 s, one opened under a key, or with no key in place anything the monitor hears. The data path dates a protected frame by its reception, not its delivery, and counts it only when the radio heard it on the connection's channel, so that a frame the reordering buffer held across the move, or one the radio took on the old channel and handed on after it, proves nothing. Without one it goes back, at once if the AP answers no poll there, and may ask again after 5 s; an AP silent on both channels ends in the usual leave. An AP whose element was wrong from the start is left alone. At the switch the MLME tunes the radio to the new channel through `config`, or, while a software scan runs, leaves the scan to return there, makes it the BSS's channel and the scan's home, and keeps the association, the keys and the BSS; `moved` gives the interface the new channel, the transmit hold ends, and beacon loss is counted again from the switch, so an AP not heard on the new channel is left as above. A beacon without the element calls off a switch under way, as does an announcement of the station's own channel, and a channel the band lacks is ignored, so that an AP that leaves for it is lost by beacon loss.

### Data, keys, aggregation and rates

The data path follows Linux's `net/mac80211/tx.c`, `rx.c`, `wpa.c`, `key.c`, `agg-rx.c` and `agg-tx.c` in design; no code is taken from them.

`tx.c` takes the station frame `wlan_encap` makes. With QoS it inserts QoS Control with the TID of the frame's 802.1D priority, which `wlan_data_priority` reads from the DSCP of IPv4 and IPv6 and sets to 7 for EAPOL, and puts the frame in that TID's access category, as 802.11-2020 Table 10-1 maps them. Each TID has its own sequence numbers; non-QoS data and management frames share one counter. A frame that does not go out, refused by the radio or by its cipher, gives its number back, so that a BlockAck window has no hole for it. Under a pairwise key the frame takes the key's next PN, which never wraps: `-EOVERFLOW` refuses once it is spent. In software CCMP encrypts the MPDU and TKIP appends the Michael MIC, inserts the IV and encrypts with RC4 over the body and its ICV. A key in the radio's slot gets the CCMP header, or TKIP's IV and Michael MIC, written here and room for the radio's MIC or ICV, with `WLAN_TX_HW_KEY` and the slot; since the PN is the data path's, a radio's reset cannot make one used twice. Management frames are protected in software only.

`rx.c` checks a frame in this order. It must come FromDS from the BSSID to this station or a group, and a group frame from this station is dropped. A QoS frame of a TID under BlockAck goes through the reordering buffer first. A retry whose sequence control equals the last of its TID is a duplicate; group frames are not checked. A protected frame is decrypted under the key its key id names, or taken as the radio decrypted it, with the PN from the status when the IV was stripped; a PN not above the TID's counter is a replay. CCMP commits the counter at once; TKIP only after its Michael check, as `ieee80211_rx_h_michael_mic_verify` does. A protected network takes no data in clear but a whole EAPOL frame. Fragments of one MSDU must come in order, under one key and, for CCMP, with consecutive PNs, within two seconds; group fragments are refused, and installing or removing a key drops what reassembly holds. A wrong Michael MIC is reported as `WLAN_EVENT_MIC_FAILURE` with the key's index and whether it was pairwise, for wpa_supplicant's countermeasures. An A-MSDU is split into three-address frames, one per subframe, and dropped whole when its first DA is an LLC/SNAP header, a plain MSDU whose A-MSDU bit was set to inject frames. Robust management frames keep a replay counter of their own beside the per-TID ones; BIP checks the IPN against the integrity key's.

`key.c` keeps the keys in software, with their AES schedules, and offers each to the radio's `set_key` when the radio names the cipher in `hw_ciphers`. `-EOPNOTSUPP` leaves a key in software; any other error fails the installation and keeps the old key. `wlan_install_key` keeps old-key frames few, since each can cross the AP's change of key: the first call ends the BlockAck sessions, so that no retry follows, it sends the queue only as far as its last EAPOL frame, and data behind that waits for the new key, whatever else holds the key up. A pairwise key replaced in the radio leaves its slot before the new one goes in, as `ieee80211_key_replace` has it, so that the cache holds one entry for the AP, and the new key takes another slot, which marks a frame the old key opened; a failed install leaves the old key in software. The other way round, a frame of the old key that crosses the AP's change of key can raise the AP's counter for the new key, which then takes nothing of ours until the next key, though its radio ACKs all of it, so a CCMP pairwise key goes on from the old one's send count. An AP may encrypt what it had queued with the new key under the old key's count, which would set the new key's counter ahead of the AP's and make every frame a replay, so for 2 s after a replacement `rx.c` drops a pairwise frame whose number lies within 256 of the old key's count and more than a BlockAck window past the highest number the new key has seen on any TID, since the sender's count is shared across TIDs. `wlan_data_restore_keys` puts every key back into a radio that restarted and lost its slots. Removal erases a key's bytes.

`agg_rx.c` answers an ADDBA request for TIDs 0 to 7 with immediate BlockAck, a window of the AP's size up to 64 and the AP's timeout echoed, protected when the request was; delayed BlockAck, a TID of 8 or more, or a station without QoS is declined with status 37. A request repeated with the same token keeps the session and its window and is answered again, or declined if its timeout changed, as `__ieee80211_start_rx_ba_session` does. No session starts in either direction from the moment a replaced pairwise key ends them until the new key is in, so an ADDBA request meanwhile is declined and none is sent, as `WLAN_STA_BLOCK_BA` has it. A session given a timeout ends with a DELBA of reason 39 once that many TU pass with no frame of it, as mac80211's session timer does. The radio learns the session through `ampdu_action`. The buffer holds MPDUs by sequence number modulo 64 and hands them on in order: a frame before the window is a duplicate, which neither moves the window nor puts off the session's timeout, one past it moves the window and hands on what it passes, and a BlockAckReq moves the window to its starting number. A frame that waited 100 ms past a hole goes on with the frames before it, as mac80211's `HT_RX_REORDER_BUF_TIMEOUT` does. An AP that numbers its frames from the start again without a DELBA would have every frame dropped as a duplicate until its numbers reached the window, which with a session of no timeout is up to 2047 frames. A retry lies at most a window before the window's start, so once a window's worth of frames further back come with none taken between, or one comes 2 seconds after the last frame taken, the session ends with a DELBA of reason 1 and the last of them goes on outside it, as mac80211 ends a session its driver gives up on. The count alone would take 13 seconds at 5 frames a second, and minutes on a quiet link; the AP's idle timeout, where it gives one, ends the session too. mac80211 has no such rule and drops those frames. A frame more than a window ahead moves the window, in mac80211's `ieee80211_sta_manage_reorder_buf` as here, before any key has opened the frame, so a frame of another counter, as an EAPOL frame numbered apart from the data may be, would make the AP's next frames duplicates. Until a frame lands inside the new window the move is unproved, and a frame of the window it left, which a conforming AP no longer sends once its own window has passed, ends the session at once in the same way. Numbers that begin again from 0 with the window above 2048 move it and lose nothing; only a gap between a window and 2048 makes frames fall behind, for the rules above. A pairwise key in the radio that is replaced ends every session each way with a DELBA first, as `ieee80211_pairwise_rekey` does: `wlan_ba_rekey`, reason 36 for a session the AP began and 37 for one of ours, which the next data frame asks for again. A DELBA that finds the radio's queue full holds the key back and is tried again every 10 ms for at most a second. The worker refuses to queue a record from its own callback, so the timeout and both drains have two work records each.

`agg_rx.c` also originates the station's transmit sessions, as mac80211's `agg-tx.c` does for a radio that aggregates. After a QoS data frame goes out, `wlan_ba_tx_check` asks the AP for its TID's session with an ADDBA request: immediate BlockAck of 64 frames, no timeout, from the TID's next sequence number, protected under 802.11w. It asks only when the radio has `ampdu_action` and HT, the AP sends HT Capabilities, the frame was not EAPOL and its TID not of the voice category, and a protected network has its pairwise key, so that the handshake is not delayed. One request per TID waits at a time, and the frames of its TID wait with it at the head of the transmit queue, as mac80211 keeps them in `tid_tx->pending`, so that the first frame of the session has the number the AP's window starts from; a request unanswered for a second or declined waits 15 seconds before the next, as mac80211's `ADDBA_RESP_INTERVAL` and `HT_AGG_RETRIES_PERIOD` have it. A response of success with its token starts the session in the radio with `WLAN_AMPDU_TX_START`, from the request's number with the AP's window; a radio that refuses is sent a DELBA, and one that answers `-EOPNOTSUPP` is asked no more until the next connection. The AP's DELBA as recipient, or a disconnection, stops the session with `WLAN_AMPDU_TX_STOP`. The radio forms the aggregates, reads the BlockAck and sends any BlockAckReq.

The station records the rate of the last data frame acknowledged, from the series that ended it, and of the last frame received from the BSS, which nl80211's station dump reports as the transmit and receive bit rates; EAPOL, null and management frames do not change the first. Its `rx drop misc` counts the frames dropped, replays and duplicates, as Linux's `rx_stats.dropped` counts duplicates. The station dump's packet, byte, retry and failure counts start at each association, as Linux's station entry does, and count every frame the data path sends, management and null frames among them, so that the failures are a part of the frames sent. `wlan_data_tx_null` sends the monitor's null frame, a QoS Null of TID 7 on a QoS connection, as mac80211's `ieee80211_send_nullfunc` builds it: ToDS, unprotected, power management clear, on the voice queue and outside every BlockAck session. The data path keeps in `heard` the tick of the last unicast data frame from the AP and of the last ACK of a frame of its own. `rate.c` gives a frame the radio's `rate_ops` when it has them, and otherwise the basic table: the BSS's basic rates, fastest first, two attempts each, the last and slowest four. EAPOL, null and management frames take the slowest basic rate alone with ten attempts, as mac80211's `rate_control_send_low` gives them ath9k's `max_rate_tries`. Completions go to `rate_ops` with the attempts made.

`rc_minstrel.c` implements rate control for radios that report actual attempts in each retry series. The driver embeds one `struct wlan_minstrel` from `rc_minstrel.h` and calls `wlan_minstrel_init` before registration to install the callbacks and `rate_priv`. The storage belongs to the driver through unregister; it may reset it on the worker after draining old transmissions. Selection intersects the BSS's legacy rates and MCS bitmap with the radio's. HT also requires the registered station's negotiated HT flag, so a TKIP association cannot use it. A new BSSID, channel or supported rate set clears the estimates. An absent or malformed peer leaves the series empty. Management and group frames use the lowest basic rate.

The policy follows the [published Minstrel design](https://wireless.docs.kernel.org/en/latest/en/developers/documentation/mac80211/ratecontrol/minstrel.html): success probability divided by airtime, a retry chain of best throughput, next throughput, best probability and lowest basic rate, and one probe per ten data selections. A faster probe precedes the best rate; a slower probe follows it. Duplicate rates are omitted. Probes get one attempt, ordinary series at most two, with a 26 ms airtime budget for the complete frame and ACK; a single slow MPDU may exceed it. Rates cover legacy DSSS/OFDM and HT20 MCS 0 through 7 with long GI. Short GI, HT40 and multiple streams are outside this policy. Each 32 completed packets update a per-rate EWMA with three parts old estimate and one part current success ratio; an untried rate keeps its estimate. Every reported attempt counts, once for each MPDU a status's `ampdu_len` says it carried, and only the last attempted series earns a success, for each MPDU of `ampdu_ack_len` or, in a status of one frame, for its ACK. A radio that keeps a push's frames to send again reports the push with `WLAN_TX_NO_FRAME`, which rate control alone reads. Filtered and invalid completions change no estimates. The implementation uses fixed storage and 32-bit arithmetic, without Linux code.

### Cryptography

The primitives have no device, station or allocator state. The data and key layers own counters and replay policy; cryptographic success alone does not authorize delivery.

`crypto/aes.c` holds the cipher and CMAC. Its S-box is a Boolean circuit over bitsliced words, so the time taken does not depend on the key or the data. `struct wlan_aes128` keeps the schedule compressed to 44 words, and each pass expands it to 88 on the stack and erases it after. A pass carries two blocks, so CCM pairs each CBC-MAC block with the next counter block, which halves the passes. `crypto/wcrypto_int.h` declares what the cipher files and the host test share: the paired pass, CMAC in pieces, Michael over a plain message, a comparison in constant time and an erase the compiler keeps.

`crypto/ccmp.c` masks the MAC header as 802.11-2020 12.5.3.3.3 says: Retry, Power Management and More Data cleared, the subtype bits 4 to 6 of a data frame cleared, Protected set, and in a QoS data frame Order cleared and only the TID kept of QoS Control. The HT Control field is outside the AAD. The nonce's Management bit marks a robust management frame. Decryption authenticates in a pass that writes nothing and then decrypts in place over the CCMP header, so a forged frame comes back unchanged.

`crypto/bip.c` computes the MIC over the masked frame control, the three addresses and every byte after the 24-byte header, the MMIE's MIC field taken as zero, as Linux and hostap do. Sign and check refuse a frame that is not a group-addressed management frame, or that has Protected set.

`crypto/tkip.c` gives Michael, both phases of key mixing and RC4. TKIP's S-box and RC4 index tables by key bytes by design, so their timing is not constant. The caller builds the TKIP header from the phase 2 key's first three bytes and the IV32, and computes the ICV, a CRC-32 of the MSDU and its MIC.

### nl80211

The server translates generic-netlink attributes into station operations and station events into multicast messages. It advertises only operations and capabilities implemented below it.

A handler parses and checks its request in the sending process, then carries it to the worker on a work record of its own and sleeps until the call below has run, since only the worker may change a station. The reads, the interface, station and survey answers and the scan dump, need no trip: they run under the kernel lock without sleeping and take a snapshot through `status`, and the scan dump first removes the entries too old to keep, as the table's other callers do. Each attached station has a list of its requests, each kept there until its handler is back, which `nl80211_detach` ends. The detachment marks the station before its first wait, so that a handler that wakes during one cannot link a retry, perhaps at the address of a request already ended, and leave its work queued for a freed station.

The radios' interfaces are the first network namespace's. From another, which has only its own `lo`, every lookup by interface, wireless device or wiphy fails with `-ENODEV` and the dumps list nothing (`net_ns_seen`), as the routing socket shows such a namespace none of the machine's interfaces, so that an administrator of a namespace of its own cannot reach the machine's station. The multicast groups reach only the first namespace's sockets.

`GET_WIPHY` sends a wiphy in four parts when the request asks for a split dump, as wpa_supplicant does: the basic attributes, the band, the supported commands, and the frame types. Without the flag it sends the four in one message. The policy table is filled at the first attachment, since C89 has no designated initializers.

`CONNECT` is built from scanning, authentication and association, as cfg80211's `sme.c` builds it for a driver without its own: a connection record on the station's work record scans for the SSID when the table lacks a match, chooses the strongest BSS, authenticates by Open System and associates, each step queued when the last one's event comes. A failure, or a scan that finds nothing, ends with a `CONNECT` event that says why. `DISCONNECT` during the steps ends the record without an event.

`REGISTER_FRAME` keeps a list of action-frame matches on each station, each with the port that registered it. A received action frame goes by `genl_unicast` to the first match, and a port that has closed loses its registration then; the family's `release` call drops a socket's registrations as it closes. `FRAME` gives each frame a cookie with `NL80211_COOKIE` set, and `NL80211_COOKIE_NOACK` when no acknowledgement was asked for, so that a transmit status is reported only for nl80211's own frames that asked for one.

`CONNECT` and `DISCONNECT` go to the station's own `connect` and `disconnect` when it has them, as cfg80211 hands them to a fullMAC driver; the station then reports the outcome as an `ASSOCIATE` event, which nl80211 turns into the `CONNECT` event as it does after its own steps.

`GET_REG` reports the world domain, `00`, as two rules: 2402 to 2472 MHz at 40 MHz, and 2457 to 2482 MHz at 20 MHz with no initiation of radiation, both at 20 dBm.

### Station

`sta.c` embeds the MLME in the station record's `mlme_priv` and carries out nl80211's calls with the MLME, the scan, the BSS table and the data path's keys, as mac80211's `cfg.c` does. It installs two hooks of the data path: received management frames go to the MLME first, and transmit completions come back to it. A frame sent for `FRAME` takes the data path's own cookie, so `sta.c` keeps the last four such frames, each with nl80211's cookie and a copy of its bytes, and reports a completion under nl80211's cookie with the frame; a fifth frame takes the oldest entry, whose status is then lost. A robust action frame goes protected once management-frame protection is in use. The MLME's events pass through `sta.c`, which notes the time of an association and, when the association asked for no control port, opens the port on its own work record, since an event may not call back into the MLME. It logs each leave as `wlan: wlanN: left: BSSID: WHY: reason N`, where WHY is `deauthenticated by the AP` or `disassociated by the AP` for the AP's frame, `asked` for a leave nl80211 or the interface asked for, and `no answer from the AP` for the MLME's own, when the AP answered none of the connection monitor's polls or probes. It reads each beacon and probe response of the associated AP before the MLME does and logs, once each, a channel switch the AP announces (`wlan: wlanN: channel switch: BSSID: from C to C in N beacons, mode M`) and a DS Parameter Set that names a channel other than the station's (`wlan: wlanN: beacon: BSSID: on channel C, not C`), as a 2.4 GHz receiver hears an AP that has moved to a neighbouring channel. It logs each beacon loss as `wlan: wlanN: beacon loss: BSSID: beacon A ms ago, heard H ms ago, signal S dBm, retries R, failed F, losses L`: the age of the AP's last beacon, which an answered poll does not reset as it resets the connection monitor, the time since the data path last heard a unicast frame or an ACK from the AP, or since the association when it heard none, the last frame's signal, and the transmit retries, failures and beacon losses since the association. The line is temporary, to show why the AP goes silent, and #2407 removes it. The MLME's `hold` stops and starts the data path's transmit, and its `moved` removes the BSS table's other entries of the AP on the new channel, gives the registry and the data path the new frequency, logs `wlan: wlanN: switched: BSSID: to channel C`, and reports the switch to nl80211, which sends `CH_SWITCH_NOTIFY` with the frequency and the channel's width, as `cfg80211_ch_switch_notify` does; wpa_supplicant then logs `CTRL-EVENT-CHANNEL-SWITCH` and moves its record of the association. The station has no `connect` of its own, so nl80211 builds CONNECT from authentication and association.

### Software radio

`wsim.c` is a radio of `radio.h` with no hardware behind it, as Linux's `mac80211_hwsim` is for mac80211, and `wsim.h` its interface; [wsim(4)](../../../../man/man4/wsim.4) is the device's contract and [wsimrelay(8)](../../../../man/man8/wsimrelay.8) the relay's. It offers start, stop, configuration, transmit and the TSF, and leaves the key, scan, station and BlockAck operations empty, so that the station layer encrypts in software, scans in software and reorders in software, as it would above a chip without those features. Its band is channels 1 to 14 before the regulatory rules, the twelve legacy rates and HT MCS 0 to 7 at 20 MHz. Radio N has the address 02:77:73:00:00:N.

The station layer's calls reach wsim through `struct wsim_station`, which `wsim_attach` takes once the registry can take radios, so that `wsim.c` links before the registry and the data path do; until then `/dev/wsim` refuses opens. The registry's `wlan_init` registers nl80211's family and passes its own calls to `wsim_attach`; the kernel makes it once the network stack is set up, unless `rach2.nonet` is given. `wsim_attach` makes the radios `rach2.wsim=N` asks for. Each open of `/dev/wsim` adopts the lowest such radio no descriptor carries, or registers a new one that its last close unregisters; `devfs.c` calls `wsim_open` and binds the descriptor's operations to the rest. A radio is held while it registers, so that no other open takes it while registration sleeps. Every field of a radio is under the kernel lock; nothing in wsim runs from an interrupt.

A transmit copies the frame into a record of the relay format, queues it for the descriptor's reader and keeps the frame's rate series and the station's cookie under a cookie of wsim's own, nonzero and unique among the radio's frames. A group-addressed frame goes with NO_ACK. The queue and the table of frames awaiting status hold 64 each; a transmit beyond either fails with `-ENOBUFS`, before anything is accepted. A read takes the record off the queue before copying it out, since the copy may sleep while a stop empties the queue; a record lost to a bad buffer completes as failed at once. A status completes its frame with the series cut where the attempts end, or the whole series for a failure whose attempts are unknown. Stop and the descriptor's close fail every frame queued or awaiting status, so that each accepted frame has exactly one status. A frame written is received only by a running radio on its channel whose filters pass it; wsim passes the frames of other BSSs and leaves them to the station layer.

`utils/wsimmedium.c` is the relay's medium, separate from its `main` so that the host test drives it: it checks every record against the format, renumbers a sent frame for the peer, makes a peer's frame a receive record with the relay's signal, answers it with ACKED only when the radio received a frame addressed to it, and fails a sent frame whose status has not come within the timeout. `wsimrelay.c` binds it to the device and a UDP socket in one `poll` loop, and takes datagrams from the peer's address whatever their source port, since a forward of QEMU's user network sends from a port of its own.

### rfkill

`rach2/sys/rfkill.h` is the core every radio switch registers with, wireless or not. A switch has a name, a type, the radio it belongs to, a soft block and a hard block. Its index, the N of `rfkillN`, is never given again, as in Linux. `rfkill_register` announces it to each open of `/dev/rfkill` with an `ADD` event, and `rfkill_unregister` with `DEL`. The owner's `set_block` takes each change of the soft block, from a write to `/dev/rfkill` or to `soft` or `state` under `/sys/class/rfkill/rfkillN`, before the state changes and a `CHANGE` event goes out; a refusal changes nothing. `rfkill_set_hw_state` records the hard block a driver reports from any context and calls nothing. A soft block that `CHANGE_ALL` set for a type is the block a switch of that type starts with.

An open of `/dev/rfkill` keeps its own ring of 32 events and drops the oldest when full, since every event carries the switch's whole state. It is queued an `ADD` for each switch at the open, in the order of their indexes, so that a reader such as BusyBox's `rfkill list` or wpa_supplicant's `rfkill_init` reads them under `O_NONBLOCK` until `EAGAIN`. A read takes one event, 8 bytes, or 9 after `RFKILL_IOCTL_MAX_SIZE`, cut to the count. A write takes at most that size, and returns what it took. One spinlock, taken with interrupts off, guards the switches and the queues; a reader is woken only when it was queued an event.

The registry registers a `wlan` switch named `phyN` with each radio, before its interface, so that a radio that starts while a type block is set starts blocked. `/sys/class/rfkill/rfkillN/device` leads to `/sys/class/ieee80211/phyN`, the directory `phy80211` leads to, which is how wpa_supplicant finds its interface's switch. The switch's `set_block` and the driver's `wlan_radio_rfkill`, which may be called from an interrupt handler, record the block they ask for and queue `wlan_rfkill_apply` on the worker. It queues the first of the station's two work records, or the second when the first is pending or running, so that a report a running callback has already passed is not lost. On the worker, a block does what Linux's `cfg80211_rfkill_set_block` does: it aborts a scan, which reports its abort, has the station leave its network without a frame, which nl80211 reports as a local deauthentication, calls `wlan_stop` and closes the interface with `netconf_set_up`. wpa_supplicant's nl80211 driver sees `IFF_UP` fall over rtnetlink, reports the interface disabled and stops scanning; at the release's `CHANGE` event it brings the interface up itself and joins again. The close cannot wait for the worker, which is running it, so the interface's way down stops a radio whose block is applied by itself, as the block has already left the network. While the switch's soft or hard block is set, bringing the interface up fails with `-ERFKILL`, also when the block comes while the driver's start sleeps, which then stops the radio again. The switch's owner records a release before `CHANGE` goes out, so wpa_supplicant may bring the interface up before the worker has applied the release; the refusal judges by the blocks asked for, not the one applied, and `wlan_start`, refused with `-ERFKILL` by the block still applied, has the worker start the radio as it clears that block. A release that comes while the block's stop sleeps finds the interface still up, so wpa_supplicant's up does nothing; the worker then leaves the interface up and starts the radio itself. Otherwise the release starts nothing. The callback loops until the block applied is the one asked for, with the interface down while blocked, since either may change while the driver's stop or start sleeps. Unregister withdraws the switch and cancels both records before it stops the radio.

## Limits

* Two machines on one medium both number their first software radio wsim0 and give it the same address, so the radios of two Rach2 machines collide; a Rach2 machine shares a medium with the Linux guest's radios, whose addresses differ.
* The software medium has no distance, loss or interference: a radio on the channel hears every frame at the relay's signal, and a frame fails only when nobody acknowledges it.
* A software scan does not wait after tuning before its first probe, as mac80211's `IEEE80211_PROBE_DELAY` does.
* A wake frame that fails twice is not sent again; the AP buffers until the next data frame, whose power management bit is clear too.
* A management frame sent from outside the scan during a trip goes out off channel; only leaving the AP sends the scan home first.
* A passive channel stays passive for the whole scan: a beacon heard there does not let the scan probe it, as Linux's beacon hints do.
* nl80211 has no connection-quality monitor: `SET_CQM` is `EOPNOTSUPP`, and wpa_supplicant's background scan polls `GET_STATION` instead.
* `GET_REG` reports the world domain only, whatever country the registry has applied.
* `FRAME` has no off-channel wait, `REMAIN_ON_CHANNEL` is `EOPNOTSUPP`, and only action frames can be registered or sent.
* WEP, Shared Key, FT and FILS are refused, as are extended key IDs and power save; SAE runs only through `AUTHENTICATE`, not `CONNECT`.
* The host test replays the requests wpa_supplicant 2.12 and iw 6.17 send, from their sources. Comparing it with the trace of those programs running on Linux, and adding or listing here the commands the trace has and nl80211 lacks, waits for that trace.
* The station transmits A-MPDUs only through a radio that forms them, and sends no A-MSDU; it advertises no A-MSDU in its ADDBA response, and splits an A-MSDU an AP sends anyway.
* Management frames are protected in software even when the radio holds the key, and a radio holding a TKIP key gets the Michael MIC from software.
* Transmit takes no fragmentation threshold: every MSDU goes whole.
