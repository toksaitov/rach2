# Memory

`rach2/sys/mm/` is the kernel's memory manager. It counts the physical memory the loader's map offers and gives it out a frame at a time; it lays out the kernel's half of the address space, with a heap that allocates and frees objects of any size; it gives each process an address space of page tables and regions, backs a page when it is first touched, and shares a parent's pages with a forked child until one of them writes; it copies data between the kernel and user memory without faulting on a bad pointer; and it keeps pages of files and of a KRFFS disk root in free frames, which it gives back when memory runs short. Pages are 4 KiB. Each architecture's `mmu.c` builds and walks its own page tables, and the code here decides what goes in an entry. There is no swap.

## Design

A mapping without a usable hint first searches down from the mmap base, then searches the whole permitted range upwards, including a gap that crosses that base. Mappings leave 256 pages below the stack's growth limit. Stack growth also refuses a page within 256 pages of the preceding accessible non-stack region, so an explicit fixed mapping cannot remove that protection.

The top-down gap search remembers an upper bound above which no gap fitted its last requested length and bounds. A later search with the same bounds and at least that length starts there. Adding or splitting coverage cannot enlarge a gap; removing coverage clears the bound. Smaller requests and changed bounds start from the top again. `vm_gap_steps` in `/proc/stat` counts candidate gaps examined since boot, modulo 2^32; each search adds its count in one atomic step, since searches in different address spaces run at once.

A file named alone is in `sys/mm/`; other paths start at `rach2/`.

### The boot

`kernel_main` (`kernel.c`) sets memory up in this order.

1. `modlayout_check` refuses a module that is empty, ends past 4 GiB, starts below the end of the kernel image or overlaps another, with the module's number and range in the panic. A module that ends within the first 64 MiB moves the boot allocator's break past it, and `init_mm` (`heap.c`) moves the break to `_end`, the end of the image, if it is lower.
2. `frame_map_build` (`frame.c`) reads the loader's memory map, in 64-bit arithmetic, into a sorted list of disjoint ranges: those the map calls available, less every range of another type that overlaps them, with what lies at or above the reach counted apart as unreachable. Without a usable map it takes `mem_upper` as one range from 1 MiB. The list has room for `FRAME_MAP_RANGES`, 265: the boot record's 256 entries give at most 256 ranges, and each later reservation, one of at most eight modules or the frame table, splits at most one more. The kernel then reserves the range from 0 to `_end` and each module.
3. `init_paging` (`paging.c`) makes the frame table, a 32-bit word for each frame below the top of the map, which the architecture places (`mmu_frame_table`). On i686 it is carved at the break, where the kernel reaches it before paging is on, the break first raised past any range of the window the map does not offer (`mem_reserve_usable`), such as the NVS ranges OVMF puts at 8 MiB. On x86-64 the boot first builds and loads the direct map, then puts the table at the top of the highest usable range above 64 MiB that has room, so the DMA pool keeps its room, and at the break, raised the same way, when no range has. A table on memory the map does not offer refuses the machine with `memory: refused: the frame table needs memory past what the map offers after the kernel's reservations`.
4. `mmu_init` builds the kernel's directory, `mmu_start` turns translation on, and `kheap_init` starts the heap.
5. `guard_boot_stack` (`kernel.c`) unmaps the image's page below the boot stack, and `map_modules` maps each module into the module region from wherever the loader put it.
6. The kernel prints `memory: usable N KiB, unreachable N KiB, reserved N KiB, managed N KiB`. Usable and unreachable are the available bytes below the reach and at or above it, reserved is what the boot took of the usable bytes, and managed is the count of free frames in the table above the break. A machine with less than `FRAME_MIN_MANAGED_KIB`, 1024 KiB, managed is refused with `memory: refused: N KiB managed after the kernel's reservations, at least 1024 KiB needed`, and stops.
7. `init_pagecache` makes the page-cache window's page tables before the first process copies the kernel's directory.

`mem_reserve` (`heap.c`) is the boot allocator: it moves the break up, never frees, and returns 0 for a reservation that would pass `HARD_MEMORY_LIMIT`. Once the frame table exists it passes over frames in use and marks the frames it takes.

### The frame allocator

The frame table (`_frames` in `paging.c`) has, for each frame, 0 when it is free, a reference count below `FRAME_REF_MAX` when it is in use, and `FRAME_ABSENT` for a frame the map does not offer. Every writer keeps the free counts, so `frame_free_count` reads one word. A bitmap reserved beside the table marks anonymous frames, independently of the page-table dirty bit. A private copy, a private write and an anonymous allocation set the mark before mapping the frame. Fork shares it with the frame, or copies it when a pinned page needs a new frame; allocation clears it before reuse. The frame lock protects changes to the bitmap.

The frames below `HARD_MEMORY_LIMIT` are the DMA pool. They lie below 4 GiB on both architectures, so a device takes the physical address of one in a 32-bit register. `alloc_kernel_frame` takes the highest free frame of the pool and returns the frame's kernel address; the page cache, `sys/block/request.c`, `ahci.c` and `nvme.c`, `sys/usb/core.c`, `hub.c` and `xhci.c`, and `sys/network/driver/e1000.c` take frames from it.

`alloc_frame`, for the heap's pages, x86-64's page tables and the stack pages exec writes the arguments into (`sys/proc/uimage.c`), and `alloc_user_frame`, for user pages, scan above the pool first, then the pool from its bottom up while more than 64 of its frames (`WINDOW_KEEP`) are free, so that `alloc_kernel_frame` finds frames at its top. A hint for each part says that no frame below it is free, so a scan does not start from the bottom each time, and an index reserved beside the table, a count of free frames for each group of 64 with a bit set for each group whose count is not 0, lets every scan, `alloc_kernel_frame`'s among them, pass 32 groups with no free frame in one word instead of reading each used frame (`frame_next_free`, `frame_prev_free`), as Linux takes a page from a free list. Under `rach2.framehigh`, on a machine with memory above 4 GiB, the scan starts at 4 GiB.

`alloc_frames` takes a run of consecutive free frames, as Linux's `alloc_pages` of an order above 0, for a structure the processor reads by its physical address across pages. It searches the same parts in the same order, with the same refusals, and takes the lowest run: each candidate is the next free frame the index gives, and a used frame inside the run restarts the search past it. The run so depends only on which frames are free, never on the order they were freed in. Each frame of it is given back on its own.

On i686 nothing above the pool is reached by its physical address. A user frame is zeroed, copied and filled through one of the 1024 temporary mappings (`kmap_temp`, `paging_zero_frame`, `paging_copy_frame`), and a caller may sleep while it has one. The slots are split into a pool for each processor, up to 32 pools of whole words of the slot maps, each under its own lock, as Linux gives each processor its own `kmap_local` slots (`mm/highmem.c:476-480`), so that two processors never take one slot; `smp_start` makes the split once it knows how many processors there are (`paging_temp_split`). A processor takes from its own pool, and borrows another's free slot only when its own has none, so one processor may still hold all 1024. A released slot, on whatever processor, goes back to its pool and stays mapped until the pool has none free; then every released slot of the pool is unmapped at once and every processor drops its translations, once for all the pool's releases, as Linux's `kmap` does with its pool. The sweep returns only once every processor has dropped its translations (`smp_kernel_flush`), so no processor has one of a slot mapped after it, and a holder that sleeps and wakes on another processor reads its slot through the new entry. On x86-64 `kmap_temp` returns the frame's address in the direct map.

`alloc_frame` and `alloc_user_frame` ask `mem_may_take` (`pressure.c`) first. It refuses a frame to a process that is not privileged (`proc_privileged`, `sys/proc/process.h`) once the free count is at or below the reserve, a thirty-second of managed memory, which is kept for root's login and for the writes reclaim starts. An interrupt handler, the kernel outside any process and a process that is reclaiming take from the reserve. A refused user frame, or one that cannot be had at all, is logged with the process's pid and sets `frame_refused` in its record, which the fault handler reads; a fault that cannot have a page table for its page sets it too (`table_refused`), so that the process ends as out of memory, as Linux answers VM_FAULT_OOM, and not with SIGSEGV. Under `rach2.framefail`, a count written to `/dev/framefail` makes the count-th frame allocation inside a system call fail.

### Page tables

The shared code reaches the tables through `mmu_user_table`, a directory's leaf table for a user address, which it makes on request; `mmu_user_skip`, the next user address whose leaf table a directory may have; and `mmu_kernel_table` (`paging.h`). On i686 a directory has two levels of 1024 entries, and on x86-64 four levels of 512; [the architectures' Readme](../arch/Readme.md) describes each architecture's tables and the kernel's directory. `clone_page_directory` copies the kernel's entries into a process's directory, so every table of the kernel's layout on i686, and every PML4 entry of it on x86-64, must exist before the first process starts; a kernel mapping made later is then seen by every process. On i686 the boot makes the 256 tables of the gigabyte from `0xC0000000`. On x86-64 it makes the eight PML4 entries, 4 TiB, of the heap, the MMIO region, the modules and the page-cache window, and the tables of the MMIO and module regions, and `premap_kernel_window` makes those of the heap's part and of the window. The x86-64 direct map reaches from 0 to the top of usable memory, at least 4 GiB, in 1 GiB pages where the processor has them and otherwise in 2 MiB pages, whose directories are carved below 64 MiB.

Before the heap exists the boot carves tables at the break; on x86-64 one that would fall past the memory the map offers refuses the machine with `memory: refused: the kernel's page tables need memory past what the map offers after the kernel's reservations`. After `mmu_heap_ready` a table is a heap page on i686, whose physical address the kernel's directory gives (`paging_virt_to_phys`), and a frame from `alloc_frame` on x86-64.

An entry has the processor's bits and two marks of the kernel's own in bits the processor ignores: `PTE_COW`, bit 9, a page shared copy-on-write, and `PTE_NONE`, bit 10, a resident page of a region with no access, which keeps its frame with the present and user bits clear, so that every access to it faults, the kernel's too, as Linux's PROT_NONE entry is `_PAGE_PROTNONE` without `_PAGE_PRESENT`. `PTE_MAPPED` (`paging.h`) is whether an entry holds a page, present or PROT_NONE, as Linux's `pte_present` reads both bits: the walkers that keep, move, count or free a frame (the fault resolver, fork, `mremap`, `munmap`, `mprotect`, teardown, `mincore`, the resident counts and the core file) ask it, and only what the processor reaches asks the present bit. `PTE_NOEXEC` is the no-execute bit, 0 on i686, which has none. Copy-on-write and the page cache's dirty marks depend on `CR0.WP`, which makes a write from ring 0 to a read-only page fault.

The walks over a user range step from one leaf table's span to the next and pass an absent upper level in one step (`user_span`), so a region of terabytes with few pages costs few steps.

`paging_flush_range` drops the translations of a range of user pages. It flushes this processor's when the directory is loaded and has every other processor that translates through the directory flush them, with one request to each, waiting for each (`smp_tlb_shootdown`, `sys/proc/smp.c`), so the caller may free the frames next. Past 33 pages, Linux's `tlb_single_page_flush_ceiling`, every user translation is dropped instead. A processor whose running thread has no address space is not interrupted: the directory is marked stale there, and the next switch to one of its threads loads it again. `paging_flush_dir` drops one page's translation the same way, and for a kernel address has every other processor drop all its translations before it next takes the big lock.

A page mapped where no page was present needs no flush, since x86 caches no translation of an entry that is not present, so a fault that brings a page in costs no shootdown (`map_user_frame`, `alloc_user_page`), as in Linux. A walk that changes many entries flushes once at its end, for the span of pages it changed: `paging_protect_range` for `mprotect`, `paging_move_range` for `mremap`, and `paging_fork_copy` for the parent's pages a fork makes copy-on-write, where a write another thread makes before the flush lands in the frame both share, as if it came before the fork. `unmap_user_range` cannot free a frame before its flush, so it walks twice: the first walk marks each entry that holds a page, present or PROT_NONE, as one going (`PTE_GOING`: the frame with `PTE_NONE` and the user bit, without the present bit), the one flush follows, and the second walk clears those entries and drops their frames. No other code makes an entry marked so, the big lock is held throughout, and no processor writes an entry that is not present. `free_user_pages` runs once no other processor translates through the directory, and flushes once at its end. `/proc/stat` counts the shootdowns that interrupted a processor as `tlb_shootdowns`.

### The MMIO region

`mmio_map` maps a range of physical addresses into the MMIO region with the cache bits it is given, `PTE_WC` for a framebuffer, and returns the address the driver uses; `mmio_unmap` frees the window, whose addresses a later map may take. `map_mmio` maps uncached and `map_mmio_typed` with other bits, each for the life of the kernel. A bit for each of the region's pages says it is taken, and a map takes the first free run long enough; one lock covers the bits and the region's entries, so two processors never take one run. The region's tables exist from the boot and every directory shares them, so a window is seen by every process at once; each change drops every processor's kernel translations.

On x86-64 a window of 2 MiB or more is placed at an address congruent with its physical address modulo 2 MiB, so that each 2 MiB of it that is aligned at both ends is one large page (`mmu_kernel_large`, which saves the directory entry of the span's table and puts it back at the unmap); the ends of a window not aligned to 2 MiB are 4 KiB pages. When no congruent run is free the window takes any run, in 4 KiB pages. i686 maps the region in 4 KiB pages alone: it does not enable PSE, and a large page would change a directory entry that each process's directory holds a copy of. `mmio_page_size` gives the size of the page at an address of the region, and `mmio_usage` the bytes taken and the longest free run.

`pci_bar_map` ([pci.h](../pci.h)) maps a window of a BAR, at an offset and of a size within the BAR, and `pci_bar_unmap` frees it; `pci_bar_size64` reads a BAR's size with the device's memory decoding off. A BAR larger than the region is reached through windows, as a driver needs them. Under QEMU the boot leaves 196 KiB of the region taken and 127.8 MiB free in one run on both architectures, so the largest framebuffer one window maps is 127.8 MiB; std-vga's 16 MiB BAR at `0xFD000000` maps whole, in 4096 pages of 4 KiB on i686 and in eight pages of 2 MiB on x86-64, as the debug shell's `mmio` command shows. On i686 a window ends below 4 GiB, where its page table entries reach.

### The kernel heap

`kheap.c` is the heap. `kheap_size_for` gives it an eighth of managed memory, rounded down to 4 MiB, at least 256 MiB and at most the region: 256 MiB on i686 whatever the machine has, and on x86-64 256 MiB up to 2 GiB managed and the whole 512 GiB from 4 TiB. A page is mapped to a frame from `alloc_frame` when it is allocated and unmapped some time after it is freed, as the next bullets but one say. The map of the region's pages, a bit each, is in the image for a region of 256 MiB and in the region's first pages for a larger one, a frame for each 128 MiB.

* An object of at most 2048 bytes is a block of one of eight classes, 16 to 2048 bytes by doubling, carved from a page with a free list for each class; a larger object takes whole pages. A class page and the first page of a large object begin with a 16-byte header that gives the class or the page count, which `kfree` finds at the base of the pointer's page. `kheap_class` gives each class's counts for `/proc/slabinfo`.
* A freed object's memory stays mapped for the next of its size, as SLUB keeps empty slabs and Linux's per-CPU lists keep pages of order 3 and below: each class keeps up to two pages with no block in use, and a large object of up to eight pages leaves its run, still mapped and counted in the heap's pages, on a list for its length, up to eight runs of each. Every kept run goes back to the region, and the search is made again, when a request of the heap, a large object, a class page, a buffer cache page (`kalloc_cache_page`) or a kernel stack (`kalloc_guarded`), finds no room or no frame, and when reclaim asks the heap's shrinker (`mem_reclaim`), as Linux drains its per-CPU lists when an allocation fails after direct reclaim (`mm/page_alloc.c:4029-4037`). The spare class pages stay, as SLUB's empty slabs do.
* A run given back below the reserve, of at most 512 pages, stays mapped with its frames and its pages taken, on a list of up to 64, and the next request of its length takes it back as it is, the buffer cache's from the runs at or above the lowest of the cache's pages and the rest's from those below. When the list is full, holds 512 pages, a request finds no room or no frame, or reclaim asks, every run on it is unmapped at once and every other processor drops its translations with one request to each (`smp_kernel_flush`, which drops them all past 33 pages); only then do the frames go back and the pages come free. Linux keeps a slab's freed objects mapped and flushes the translations of many freed vmalloc areas at once (`free_vmap_area_noflush`, `mm/vmalloc.c:2411-2455`), where unmapping each run with a flush of every processor, with the heap's lock held, cost a request to each processor for each page a process's exit gave back. A longer run, and one in the reserve, goes back at once.
* `kalloc_pages` gives the lowest run of pages that fits, with no header. `kalloc_contig` gives such a run of 1 to 63 pages mapped to a run of `alloc_frames`, for SVM's permission maps, which the processor reads by physical address across their pages; its pages go back with `kfree_pages`, a frame at a time. `kalloc_cache_page`, the buffer cache's, takes pages from the top of the region down, as Linux keeps reclaimable pages apart, so the cache's holes lie among its own pages and not among the runs the rest needs.
* The top 16 MiB is a reserve of sixteen runs of 256 pages, which a request of 64 pages or more takes when the rest of the region cannot meet it, so a request of a megabyte is met beside a full cache. It costs no frame until a run is taken.
* `kalloc_guarded` gives fewer than 64 pages with the page below them marked taken and never mapped, a guard that takes no frame. A kernel stack comes this way (`kstack_alloc`, `sys/syscall_proc.c`); [the architectures' Readme](../arch/Readme.md) says how a fault in the guard ends.
* The heap never sleeps. A request it cannot meet returns NULL, and the caller answers ENOMEM or the error its contract gives.

The heap's spinlock covers its page map, runs, free lists, kept runs and counts, and the frame allocator's covers the frame table and its counts, hints and index. Each is taken with interrupts off after the big lock, the heap's before the frame allocator's. The caches change with the big lock held, which every entry to the kernel takes unless its call is unlocked ([the kernel's document](../../Readme.md)), but for the file page cache and the buffer cache's reads, which have spinlocks of their own ([the VFS's Readme](../fs/vfs.Readme.md)); the regions and the page tables have the locks of their address space, below.

### Address spaces

`struct mm` (`mm.h`) is an address space: a page directory, its regions, and what `/proc` reports of the image. It has two counts, as Linux's `mm_struct` has `mm_users` and `mm_count`. `users` counts each thread that runs in it, an `execve` that builds it, and a call from another process that reads or writes its pages, such as ptrace's, for the length of the call; the last user's `mm_put` frees the pages, the page tables, the directory and the regions. It takes the directory out of the space, its resident count and the table of spaces by directory first, so the walks over the tables give way to the big lock's waiters and the tick's switch (`sched_give_way`): `free_user_pages` after each leaf table, of 1,024 entries on i686 and 512 on x86-64, and `free_page_directory` after every 512 tables it frees on i686 and after each page directory's tables, up to 512, on x86-64, as Linux's `zap_pmd_range` calls `cond_resched` after each PMD entry (mm/memory.c:1740): nothing else reaches the tables then, a holder that is not a user finds no directory, and no processor translates through it (`smp_space_release`). At 33 ms for each GiB freed, the walk held the big lock for 67.6 ms over 2 GiB on the Lenovo without the batches. `holds` counts the users as one and each `/proc/PID/mem` descriptor, and the last hold frees the record. Such a descriptor takes a user's count only while a user remains (`mm_get_live`), so it keeps none of the memory of a process that has ended or executed another program.

`fork` gives the child a copy, made by `mm_new`, `paging_fork_copy` and `vm_copy`; `clone` with `CLONE_VM`, which `vfork` uses, gives it the parent's own with one more user. `execve` builds a new address space while the old one runs and drops the old one when it commits. A thread's exit drops its own (`mm_drop`), loading the kernel's directory first when the space it frees is loaded, and the last put makes every other processor that still has the directory loaded switch to the kernel's (`smp_space_release`).

The address space keeps the program's file, as Linux's `mm->exe_file`: a description of it that opens nothing (`fs_exe_open`), which `/proc/PID/exe` reaches and fork's copy shares. The description also keeps the selected directory entry on inode-based file systems, so fork and descriptor execution preserve the executed hard-link name even after another link remains. Every address space that keeps a file is on a list `mm_exe_holds` reads, and the KRFFS root counts each among the holders of the file's node, so an unlink of a running program, or a rename over it, leaves its node, without a name, until the last address space that keeps it goes. `mm_exe_close` takes the lock the release needs (`fs_exe_lock`) while the address space is still on the list, so no count of the file's holders runs between its leaving and the release.

The address space counts its resident pages, the present user entries of its page tables, and keeps the most there were, as Linux's `rss_stat` and `hiwater_rss`. Each writer of a user entry reports the present bits it set or cleared (`mm_resident_add`): `map_user_frame`, `alloc_user_page`, `unmap_user_range`, `paging_move_range` and the last `mm_put`. These have the directory alone, so the address spaces are also in a table by directory, under a lock of its own; each address space's lock covers the writers of its two counts, which processors faulting in it at once are, and a reader reads each count once without it, as Linux's `get_mm_hiwater_rss` does. `getrusage`'s `ru_maxrss` and the `VmRSS`, `VmHWM` and `statm` of `/proc` read the two counts and walk no table; Wine reads `getrusage` around each `sched_yield`. `/proc/PID/smaps` still walks, since it reports each region, and so does `/proc/PID/status` for `RssAnon`, `RssFile` and `RssShmem`, which divide the count by the kind of page as smaps does: a private region's pages are the process's own, except pages of a file that have no anonymous frame mark; the rest are a file's, counted as shared memory when the file is in memory (`filemap_in_memory`). Wine reads its pagefile usage from `RssAnon`.

### The regions' lock

An address space has two locks of its own, as Linux's `mm_struct` has `mmap_lock` and `page_table_lock` (`mm.h`). `mmap_lock` is a sleeping reader-writer lock (`sys/proc/mutex.c`): a fault, and any walk of the regions, holds it to read, and a change of the regions holds it to write. `ptl` is a spinlock, taken with interrupts off, around the check and the store of a user entry that a fault makes, so that two faults of one page install one frame (`install_new`, `paging.c`), as Linux's `do_anonymous_page` rechecks the entry under the page-table lock (Linux 6.12.115, `mm/memory.c:4805-4810`); the change notice's list is under it too.

A holder of the lock to read that runs under a spinlock reaches a user word through `get_user_u32_nofault` and `cmpxchg_user_u32_nofault` (`usercopy.h`), which touch it only when its page is present and allows the access now (`vm_ready_held`) and otherwise answer `EFAULT` and bring nothing in, as Linux's futex code reads its words with page faults off; the futex calls read and exchange their words so under their bucket locks ([futexes](../proc/futex.Readme.md)).

A thread keeps a record of its holds of two address spaces (`mmap_holds`, `struct process`). A hold taken again by the same thread only counts, so a fault in a copy from user memory under a walk that holds the lock to read does not wait for itself; a write wanted under a read hold panics, and `mmap_write_trylock` answers 0 there. `mmap_may_drop` says whether the thread holds the lock once and to read, the one case in which a fault may let it go across a sleep.

Every change of the regions holds the regions' lock to write and runs without the big lock, as Linux's mmap family holds mmap_lock alone (`mm/mmap.c:126`, `mm/util.c:586`, `mm/mmap.c:1640`, `mm/mprotect.c:740`, `mm/mremap.c:1101`, `mm/madvise.c:1463`, `mm/mlock.c:632,688,762,780` in Linux 6.12.115), and every reader of the regions holds it to read: a fault, as Linux's `lock_mm_and_find_vma` and `lock_vma_under_rcu` (`mm/memory.c:6197,6259`), a copy to or from user memory, a pin, a walk from /proc and a count of a shared memory segment's attachments (`shm_attaches`). The big lock is taken inside a change only around what has no lock of its own, each step named where it is taken: the change of entries that takes a present page away or takes a right from it (`unmap_user_range`, `paging_protect_range`, `paging_move_range`), over the walk that changes the entries alone, with the flush and the frees after it; the change notice's list and calls (`mmn_notify`); the release of the files whose last region went (`mm_reap`); and the caches' balance. Code that holds the big lock and does not sleep may therefore touch user memory after a residency check that let the regions' lock go, as the callers of `vm_resident` do: a page it found present stays until it sleeps, since a change of its entry waits for the big lock, and a change made after the check finds the entry already changed, whatever another processor's translation holds until the flush. KVM's guest-physical fault runs without the big lock: it holds the regions' lock to read, which keeps out every change made under the write lock, and counts on `changing` and `changes` (`mm.h`) for the changes made under the read lock, a copy-on-write break and a truncation's cut, which each count themselves under way from before the change notice's call to after the change of the entry (`mmn_change_begin`, `mmn_change_end`), as Linux's `mmu_invalidate_in_progress` and `mmu_invalidate_seq`. A walk from outside the space, such as `/proc/PID/maps`, a core dump or `process_vm_readv`, takes a user's count and the lock to read (`mm_read_begin`, `mm_read_end`). A file whose last reference went while the lock was held is released once the thread holds no regions' lock (`mm_reap`), since its release may sleep.

`brk`, `mmap`, `munmap`, `mprotect`, `pkey_mprotect`, `mremap`, `madvise`, `mlock`, `mlock2`, `munlock`, `mlockall` and `munlockall`, native and i386, run without the big lock (`syscall_unlock`, `sys/syscall.c`). Each takes the regions' lock to write around its change (`regions_begin`, `regions_end`, `regions.c`), lets the caches give frames back before it is taken, and brings in the pages `MAP_POPULATE`, `MAP_LOCKED` or a lock asks for after it is given back, as a fault would. `mmap` finds the file or object it maps under the big lock before it takes the regions' lock, since the descriptor's entry, a driver's mmap, the list of mappings and the shared disk files' pages have no lock of their own, and allocates the execute-only protection key under the regions' lock, which the keys of the address space are under. A walk of the shared disk files' mappings under the big lock takes a mapping only while its count is above 0 (`vm_file_tryget`), since a region's last put runs under the regions' lock alone. The other calls of the family, `msync`, `mincore`, `mseal`, `pkey_alloc` and `pkey_free`, enter with the big lock and take the regions' lock inside it. `fork` holds the parent's lock to write across the copy, as Linux's `dup_mmap` does (`kernel/fork.c:644`).

A walk that takes pages away from every address space, as `paging_zap_device` and the truncation of a shared file's pages do (`paging_zap_where`), holds the big lock and takes each space's lock to write without waiting; when another thread holds it, the walk lets the big lock go, waits for that lock, and starts again, and a space the walking thread itself holds to read is zapped as it stands. A walk changes each space once, though each of its threads has a record on the process list, and a walk that starts again takes a new number and zaps every space again (`mm->zap_walk`), since a thread of a space changed before the wait may have faulted the object back in while the big lock was free; only the last pass, which waits for nothing, runs whole under the big lock, as Linux's `unmap_mapping_pages` holds `i_mmap_rwsem` across the whole walk (`mm/memory.c:3822-3838`). Each zap counts in `mm->zaps`, which a fault that let the lock go compares afterwards.

The dumpable flag of `prctl` is kept here, one for every thread that shares the address space. It is set in a new address space, cleared by an exec of an image that runs with ids its caller lacks or that its caller may not read, copied by fork, and cleared when a sharer's effective uid or gid changes.

### Regions

`vm.c` keeps a process's regions in an AVL tree ordered by address. Lookup, insertion and removal take logarithmic time; rotations relink nodes without moving any surviving region. Nodes come from heap allocations of 16 and stay with the space until `vm_free`; removed nodes are reused. `vm_first`, `vm_next` and `vm_lower` give ordered access to the regions, including the walk that prints `/proc/PID/maps`. The space keeps the covered byte count as regions change, so an `RLIMIT_AS` check takes constant time. `vm_max_map_count`, `VMA_LIMIT` (65536) at boot and `/proc/sys/vm/max_map_count`, bounds live regions, as Linux's setting does; a change that would take the process past it is refused, and the kernel logs `vm: OPERATION: pid N (NAME) has used all LIMIT of its mappings` once for the process. A process already past a lower value written keeps its regions, and a fork can copy them; only a change that adds one fails. `vm_reserve` makes room for the nodes a change needs before the change starts, so a split either fails with nothing changed or cannot fail. A protection change reserves only the splits it needs and can change a whole region even at the limit.

A region, `vma_t`, is a half-open, page-aligned range of a type: `VM_CODE` or `VM_DATA` for an ELF segment, the pages of it that map the program's file or the anonymous pages past them, `VM_HEAP` for the heap `brk` grows, `VM_STACK` for the main stack, `VM_ANON` for private anonymous memory, `VM_FILE` for a private mapping of a file that `mmap` made, and `VM_SHARED` for shared anonymous memory or a shared mapping of a file on tmpfs or ext2. Its protection is `VM_PROT_READ`, `VM_PROT_WRITE` and `VM_PROT_EXEC`, with marks beside them that splits, merges and moves keep (`VM_PROT_KEPT`): `VM_PROT_NOWRITE`, a region `mprotect` may never make writable; `VM_PROT_IO`, a device region, below, which neither a core file nor `/proc/PID/mem` reads, since a read of a device register can change the device; `VM_PROT_WC` and `VM_PROT_UC`, a device region's cache type; `VM_PROT_DONTFORK`, which `madvise`'s `MADV_DONTFORK` sets and `MADV_DOFORK` clears, a region a fork's child does not get (`vm_copy` and `paging_fork_copy` pass it over); `VM_PROT_WIPEONFORK`, which `MADV_WIPEONFORK` sets on private anonymous memory and `MADV_KEEPONFORK` clears, a region a fork's child gets without its pages, so that it reads zeros (`paging_fork_copy` passes its pages over); `VM_PROT_SEALED`, which `mseal` sets and nothing clears; `VM_PROT_SECRET`, a shared mapping of a file of `memfd_secret`; `VM_PROT_VVAR`, the vDSO's data page, which `paging_access`, a pin and `vmsplice` refuse and `mprotect` may never make executable, as Linux's `get_user_pages` refuses its `VM_IO | VM_PFNMAP` region and it lacks `VM_MAYEXEC` ([the arch Readme](../arch/Readme.md)); `VM_PROT_NOREAD`, which a change of the access bits replaces rather than keeps, a region `mmap` or `mprotect` gave write or execute without `PROT_READ`, which has `VM_PROT_READ` only because x86 paging grants a read with either and lacks Linux's `VM_READ` (`VM_READABLE`): `/proc/PID/maps`, smaps and a core file's program header show it unreadable, `process_vm_readv` and a read-only VFIO DMA map, which Linux pins remotely, are refused a read of it (`PIN_SLOW`), and `vmsplice`'s pin takes a page of it only when the page is present and not the zero page, as Linux's `get_user_pages_fast` takes it from the page table while the slow path refuses the region; `VM_PROT_ACCOUNT`, Linux's `VM_ACCOUNT`, on the stack, the heap, a writable segment of the program and a private mapping that was writable when `mmap` made it or that `mprotect` first makes writable (`vm_change_prot`), kept when the region stops being writable unless it is anonymous memory of which no page was written while the region or the one it was split from held it, as Linux's `mprotect_fixup` drops `VM_ACCOUNT` from an anonymous region with no `anon_vma`, and kept by an `mprotect` that leaves the protection as it was, from which `mprotect_fixup` returns first (the region's `anon`, which every call that splits, merges or moves a region, drops its pages or changes its protection sets first when a page of it other than a zero-filled one a read brought in is mapped, `mm_note_anon` in `mm.c`, since a store sets the entry's dirty bit with no fault; a split gives both parts the mark, as Linux's gives both the `anon_vma`), which only `/proc/PID/smaps` reads, as `ac`, since the kernel keeps no commit count; `VM_PROT_NORESERVE`, a mapping made with `MAP_NORESERVE`, which never takes that mark; and `VM_PROT_PKEY`, four bits that hold the region's protection key (`VM_PROT_KEY`), 0 but where `pkey_mprotect` or the execute-only key set one. Neighbours of the same type and protection merge, and two that map a file merge only where its pages continue.

Anonymous faults use 4 KiB pages. The `anon` mark follows Linux's base-page zero-page path: a read alone does not set it. Linux's transparent huge zero page prepares an `anon_vma` on a read too, and can therefore keep `ac` after write permission is removed from a large region. Rach2 has no transparent huge pages and does not report that huge-page behavior.

A region that maps a file has a `struct vm_file`, with a reference for each region and each fault reading it, and the file's page at the region's start. The last reference puts the file on a list that `vm_file_reap` empties once the regions and the page tables agree again, at the end of `munmap`, `mmap`, `mremap`, `brk` and the other changes, through `mm_reap`, which waits until the thread holds no regions' lock. A release may sleep while it closes the file, and a region still in the tree then would be copied by a fork, or reached by a fault, after the file had gone. A region that `munmap`, `mremap` or a fixed `mmap` removes keeps its reference on the space's detached list (`vm_detach`) until the range's entries are cleared and the processors' translations of them flushed (`vm_release_detached`), as Linux frees the detached regions only after `unmap_region` has finished the TLB gather: another thread's `mm_reap`, which no lock of this space holds off, could otherwise release a device object or a buffer whose memory a processor still reached through the old entries.

### Device regions

A descriptor whose operations have `mmap` (`struct file_ops`, [the file system's Readme](../fs/Readme.md)) maps through it: `/dev/mem` first, and the DRM nodes, dma-bufs and the other driver objects after it. A device object does it with `vm_device_map`, which makes the region `VM_SHARED` with `VM_PROT_IO` and the cache type the object asks for, and its file a `struct vm_device` that holds the object and the reference the mapping took on it. The region's file is shared, as any region's, by the splits of the region and by a fork's copy of it, and the object's `put` drops the reference once the last region that maps the file goes: at munmap, exec or exit. Device memory has no copy-on-write, so a private mapping is refused with EINVAL.

Nothing is mapped at `mmap`. A fault in a device region asks the object's `page` for the physical address of the page (`device_fault`) and maps it, writable when the region is, write-combining for `VM_PROT_WC` where the page attribute table gives the type (`arch_pte_wc`) and uncached where it does not, uncached for `VM_PROT_UC`, and cached for neither, as for an object's frames of RAM. An object whose `page` never sleeps and whose pages a mapping may take at once sets `whole` in its operations, and the first fault in its region then maps every page of the region not yet present, 64 pages at a time under the same checks as the one page (`device_map_rest`), as Linux's `remap_pfn_range` maps a whole region at `mmap` for virtio-gpu's blobs of host memory and i915's fault maps a whole object; a blob of 16,384 pages costs one fault. Each mapping takes a reference on a frame the allocator counts, which unmapping drops, so an object that frees a frame its mappings still reach would leave it to them alone; a frame of a device's range has no count. A driver that moves or frees a page, or loses its device, calls `paging_zap_device`, which unmaps the object's pages of a range in every process, as Linux's `unmap_mapping_range` does. The regions stay; the next touch faults to `page` again, which maps the page where it is now, or answers -1, and the fault handler then sends `SIGBUS` with `BUS_ADRERR` at the address, as Linux does for a driver's `VM_FAULT_SIGBUS`. An object that cannot give the page yet, its wait ended by a signal or its room short for now, answers 1: a fault from user mode then returns without a page, the thread's signals are handled on the way out, and the instruction faults again, as Linux's `VM_FAULT_NOPAGE`; a resolution for one of the kernel's copies fails, which the copy reports as EFAULT. `MAP_POPULATE` and `madvise`'s dropping advice pass a device region over, `MADV_DOFORK` over one is EINVAL, and `mremap` moves one but never grows it, as Linux treats `VM_IO` and `VM_PFNMAP`.

### A new image

`execve` (`exec_build`, `sys/syscall_proc.c`) builds the new image in an address space of its own, so a failed load returns to its caller. `elf_load_image_at` (`sys/proc/elf.c`) maps each `PT_LOAD` segment privately from the program's file, as Linux does: its file pages are a region of the file, `VM_CODE` or `VM_DATA` with the file and its page, which faults read when they are first touched; the whole pages past them are an anonymous region of the same type; and the page where the file bytes end is loaded at once, with zeros after them. A page `madvise` drops reads the file again. The mapping is made as a private `mmap` makes one (`filemap_private`), with a description of the file open for reading, so the image keeps the file whatever happens to its name: an ext2 file's faults borrow the file's pages in memory and copy one only at a store, as Linux's `filemap_fault` maps the page cache's pages, and another file's read each page into a frame of the image's own. A segment the file cannot be mapped for, as [the process Readme](../proc/Readme.md) lists, is loaded whole into zeroed frames, read-only where the segment is not writable and no-execute where it is not executable. A position-independent program goes at its base, `ELF_ET_DYN_BASE` without randomization, and a position-independent interpreter just below the address space's mmap base, `vm_space_t`'s `mmap_base`, `USER_MMAP_BASE` without randomization. Each segment gets a region, the heap starts empty at the program's end, and the stack's region ends at the stack's top, `USER_ADDR_MAX` without randomization, and covers the pages from the top page down that the arguments and the environment took and 128 KiB below them, within the soft `RLIMIT_STACK`, as Linux's `setup_arg_pages` expands it (`exec_stack_base`), so that a program's first frames need no growth. The stack may grow until the whole stack is the soft `RLIMIT_STACK` at the exec, never below the mmap base (`exec_stack_window`), and to at most 8 MiB for an image that runs with ids its caller lacks.

`exec_layout` chooses the layout once the image's ids are known, as Linux's `load_elf_binary` does. `randomize_va_space` (`vm.h`), the variable behind `kernel.randomize_va_space`, and the persona the image runs with decide whether the addresses are randomized: at 0, or with `ADDR_NO_RANDOMIZE` in the persona, which `setarch -R` and GDB set with `personality`, every image is at the fixed addresses of the table above. Otherwise each offset is drawn from `krandom_u32` on its own, under the architecture's bounds, as Linux x86-64 draws them: the stack's top is lowered by whole pages, and the entry stack pointer by a multiple of 16 bytes, a pad between the strings and `AT_RANDOM`'s bytes (`uimage_move`); the mmap base is lowered, and the vDSO above it with it, and a position-independent program's base raised by whole pages; and at 2 the heap's start is raised above the program's end by whole pages. The strings are copied before the ids are known, so the stack is built at `USER_ADDR_MAX` and moved: a frame backs the same page below the top wherever the top is, and only `AT_EXECFN`'s address changes. An image that runs with ids its caller lacks, or that has capabilities given back, loses `ADDR_NO_RANDOMIZE` and the other flags of Linux's `PER_CLEAR_ON_SETID` first, so a caller cannot fix the addresses of a set-user-ID program. The variable starts at 2 where the bounds are not 0, on x86-64, and at 0 on i686, whose 3 GiB of user space is kept whole for the heap and the mappings. A fork's child copies the mmap base with the regions, so parent and child agree until either execs. A whole page of a file comes through the file page cache, for the loader (`exec_file_read`) and for a fault (`filemap_fill`, and `filemap_disk_page` for a file on ext2).

### Page faults

`_page_fault_handler` (`paging.c`) reads the fault's address and, for a fault from user mode, turns interrupts on, as Linux's `do_user_addr_fault` does, since a fill may sleep on a file's locks; the tick leaves its switch for the fault's end meanwhile (`in_fault`), as it does in a system call, and the end takes it. A fault from kernel mode keeps interrupts as they were. `page_fault` then tries, in this order:

1. A fault at a user address while the current process has an address space, from user mode or from the kernel touching a page not yet backed, goes to `vm_resolve`, unless it is a data access the running thread's PKRU denies to the region's key, which the error code's PK bit reports for a present page and `fault_key` finds for one not yet backed, or an instruction fetch from a page of no executable region (`fetch_refused`), which only x86-64's error code reports.
2. A kernel fault inside the page-cache window goes to `pc_fault`, and panics when the cache cannot serve it.
3. A user-mode fault that failed because the frame allocator refused a frame ends the process with `SIGKILL`, since a `SIGSEGV` handler that returned would fault again. The system's init is ended directly (`terminate_current_process`) and its death panics, since it drops even a forced `SIGKILL` (Linux 6.12.115, `kernel/signal.c:88-90`). Linux's OOM killer excludes init (`mm/oom_kill.c:164-171`); this kernel has no other-victim selection.
4. Any other user-mode fault, one in the page-cache window included, sends `SIGSEGV`, with `SEGV_PKUERR` and the key in `si_pkey` for one the key refused, `SEGV_ACCERR` for another address in a region and `SEGV_MAPERR` otherwise. The key comes before the region's protection, as in Linux's `access_error`.
5. A kernel fault panics, with `page fault: a kernel stack ran out` when it is in the guard page below the running thread's kernel stack. Before any other kernel fault's panic, `vm: fault: called from 0xADDR` lines name the return addresses of up to 16 frames that led to it, by the frame-pointer chain on the running thread's kernel stack (`fault_callers`), for `addr2line` on the kernel's image.

`vm_resolve_once` backs one page. Outside every region the one legal access grows the stack: `vm_grow_stack` extends the stack's region down to the page when the page is at or above `stack_limit`, the growth fits `RLIMIT_AS`, and no other region lies between. Inside a region the protection must allow the access. Then a present page that allows it needs nothing; a write to a present page that is not writable goes to `cow_fault`; a page of a device region is the one its object gives (`device_fault`); a clean private page of tmpfs or ext2 borrows the file's frame read-only with `PTE_COW`, and copies it for a store; another private file page is read into a new frame (`file_fault`), marked anonymous for a store or mapped copy-on-write for a read; a shared region maps the file's frame writable when allowed (`shared_fault`); and any other page gets a zeroed frame. A read fault of an ext2 file's page, in a private or a shared region, first maps the pages of the file around it that are in memory, its own among them, with the same entry bits, at most 16 from the 64 KiB boundary at or below the page, within the region and the page table, as Linux's `do_fault_around` maps the page cache's folios before `do_read_fault` reads the page (`mm/memory.c:5254-5284` and `5300-5330`); a page the file page cache has joins the file's pages for it, so a program started again maps its text sixteen pages a fault, and a page in neither is left to its own fault (`share_around`). When the page was not among them, the fault reads it and then maps the pages around once more, which the read may have brought in. A file's read may sleep, so the file is held across it and the region looked up again after, and when the region changed or the page was backed meanwhile the resolution runs again.

A new frame is filled or zeroed before it is mapped, since a thread on another processor runs in user mode without the big lock and would see the page at once. A private file page remains read-only until its first write gives it an anonymous frame mark; other entries are writable when the region is. An entry is no-execute when its region has no `VM_PROT_EXEC`. A resolution that may need a frame first lets the caches give frames back (`mem_balance`), which may sleep, with the regions' lock let go and the big lock held, and looks at the region again only after that.

Vector 14 runs without the big lock (`exception_unlock`), as Linux's `do_user_addr_fault` does (`arch/x86/mm/fault.c:1359`). The handler turns interrupts on when the faulting code had them on, takes the regions' lock to read, unless the thread holds it already, and resolves the page under it, as Linux's `lock_mm_and_find_vma` (`mm/memory.c:6197-6248`); growing the stack takes it to write. The signal, the end of a process out of frames and the page-cache window take the big lock. A fault that must sleep with the lock held once to read, in a file's read, a shared file's page or a device object's `page`, lets the regions' lock go across the call, as Linux's `lock_folio_maybe_drop_mmap` lets `mmap_lock` go across a read (`mm/filemap.c:3094-3119`), and takes the big lock across it unless the file's operations run without it (`struct vm_file`'s `unlocked`, `vm.h`): a mapping of an ext2 file, private or shared, and the vDSO's regions set it, so their faults take no global lock, as Linux's `filemap_fault` takes none (`mm/filemap.c:3305-3370`), while a device object's, a file in memory's and another file system's run under the big lock; then it takes the regions' lock again and maps the page only when the region is the same one and `mm->zaps` has not moved, and otherwise looks again. A fault whose thread holds the lock more than once, or to write, does not make the call and fails, since the call could wait for a file whose holder waits for the regions' lock; a copy from or to user memory brings its pages in first and holds the lock across the copy (`vm_user_begin`), so it takes no such fault. `cow_fault` copies the page with the regions' lock alone and installs the copy under the page-table lock only when the entry is still the one it copied, as Linux's `wp_page_copy` (`mm/memory.c:3384-3390`). Before the copy it takes a reference of its own on the shared frame under the page-table lock, while the entry is still the one it read, and drops it once the copy is made, as `wp_page_copy` holds the old folio (`mm/memory.c:3737`): another thread may install its copy and drop the entry's reference meanwhile, and the process that shares the frame unmap it, which would otherwise free the frame under the copy. `page_private` does the same (`cow_source_get`). The faults of one address space run at once, each holding the regions' lock to read, so the entry `cow_fault` reads may no longer be the one its caller saw: another thread's fault made it writable, or a zap made by a thread that holds the lock to read (`paging_zap_where`) made it absent. Either is resolved again, as Linux's `handle_pte_fault` leaves an entry that changed and calls `do_wp_page` only for one present and not writable (`mm/memory.c:5799-5805`); only a present page that is neither writable nor copy-on-write is refused.

### Copy-on-write

`paging_fork_copy` walks the parent's regions and the leaf tables it has in each, and maps each present user page into the child's directory with the same frame and one more reference. A page of a `VM_SHARED` region keeps its flags in both; a writable page becomes read-only and `PTE_COW` in both; a read-only page keeps its flags. On the first write `cow_fault` makes the page writable in place when this address space has the frame's last reference, and otherwise copies it. A region `mprotect` made read-only keeps its copy-on-write pages read-only, since the region's protection is checked first.

`paging_protect_range` gives the resident pages of a range `mprotect`'s protection: no access makes a page `PTE_NONE` and takes its present bit, and any access gives the bit back; read-only clears the write bit; write sets it on a page of a shared region, unless its file counts its stores (`VM_PROT_MKWRITE`), whose page gains it at its write fault, or one this address space alone has, and makes any other page copy-on-write.

`paging_access`, for ptrace and `/proc/PID/mem`, reaches another address space's pages through temporary mappings, bringing in a missing page as a fault would. A write to a private page another address space shares gives this one a copy with the same rights (`page_private`), so a breakpoint written into text leaves the text read-only, as Linux's `FOLL_FORCE` does. A device region's bytes, which its page tables may not reach, go through its object's `access` (`vm_device_access`), as Linux's `__access_remote_vm` calls the region's `access`, and an object without one is EIO.

### The mapping calls

`ksys_mmap_pgoff` (`sys/syscall_proc.c`) finds what is mapped first, in `mmap_backing`, which may sleep finding the path of an object that maps itself, and the place after, in `mmap_place`, which does not, so no thread that shares the address space can map the range between the check and the insertion. What is mapped is private or shared anonymous memory, a private mapping of a file (`filemap_private`), a shared mapping of a file on tmpfs (`filemap_shared`) or on ext2 (`filemap_disk_shared`), or an object that maps itself through its `mmap` operation (`mmap_object`), `/dev/mem` among them. A page of a file on a loop device or a USB stick, which the block layer cannot poll with interrupts off ([the block layer](../block/Readme.md)), is read as a system call reads it (`filemap_read`): a thread outside every call, faulting from user mode or writing a signal's frame, is marked in a call and runs with interrupts on for the read, and one inside a call with interrupts off fails the read with EIO. A mapping without `MAP_FIXED` or a free hint takes the highest free range below the address space's mmap base, down to the bottom of user space and below the heap's top as well, as Linux's top-down search does, and when none is free there, the highest free range between the mmap base and the stack's growth window, where Linux falls back to its bottom-up search (`mmap_free`, `vm_find_free`). An i386 Wine needs the room below the heap: its loader's heap starts above 0x7D400000, and Wine reserves nearly everything above that until its program has started. `MAP_POPULATE` without `MAP_NONBLOCK`, and `MAP_LOCKED`, back the new pages before the call returns (`vm_populate` in `paging.c`), a private writable mapping's for a write, which gives each page a frame of its own, and any other's for a read; the populate stops at the first page no frame can be had for. Each page a fault, a populate or the kernel's own touch of user memory backs or copies counts as a minor fault of the thread (`fault_count`), or as a major one when a private file mapping's page missed the file cache and was read through the file system (`filemap_fill` returns 1); `getrusage` and `wait4` report the counts.

`brk`, `munmap` and `mremap` change the regions first and the page tables after, and `madvise` drops pages and leaves the regions, or marks them for fork (`vm_advise`); a page never touched has no frame to drop. `mremap` makes every table the new range needs before it moves the entries (`paging_move_range`). `mprotect` changes the regions before the resident pages, so a fault in between reads the protection being set. Each of these calls, and `shmdt`, a `MAP_FIXED` mapping over a range and a `madvise` that drops pages, tells the ranges registered on what it changed ([the change notice](#the-change-notice)).

A sealed region (`VM_PROT_SEALED`) refuses a change of its place, size or protection with EPERM, as Linux 6.12 checks one: `munmap`, a `MAP_FIXED` mapping and the shrink of `brk` look for a seal in the whole range first (`vm_sealed_at`) and change nothing; `mprotect` changes the regions and resident pages below the first sealed one, notifies their users and then stops, including when the sealed region requires EACCES, as Linux's loop over the regions does; `mremap` checks its source and a fixed destination; and `madvise`'s advice that drops pages stops at the first sealed region of private anonymous memory without write, the regions below it advised. `shmdt` of a sealed attachment leaves it and answers 0, as Linux's ignores the error of its unmap. `/proc/PID/smaps` shows the seal as `sl`.

### Protection keys

The x86-64 kernel turns the processor's memory protection keys on where `cpuid` reports PKU and leaf 0xD lists PKRU: `fpu_init` puts PKRU in XCR0 and each processor sets CR4.PKE (`arch/x86/fpu.c`, [the PC platform](../arch/x86/Readme.md)), and `fpu_pkeys` answers 1. A region's key is in its protection (`VM_PROT_PKEY`), so a split, a merge, `mremap`, a fork's `vm_copy` and `mprotect`, which keeps the bits, carry it with no work of their own, and two regions of different keys never merge. `paging_prot_bits` puts the key in bits 59 to 62 of each entry the region's pages get (`PTE_PKEY`), and a fork's copy and a copy-on-write keep the bits of the entry they copy.

The address space keeps which keys are allocated, a bit for each in `struct mm`'s `pkeys`, key 0's set from the start but freed and given again like any other, as Linux's, and the execute-only key in `pkey_exec`, -1 until the first `PROT_EXEC` alone allocates it (`sys/syscall_proc.c`), as Linux's `mm_context_t` does. `pkey_alloc` takes the lowest free key and writes its rights into the caller's PKRU; `pkey_free` clears the bit and leaves the regions' keys; `pkey_mprotect` gives the range a key through `vm_protect_key`, which `mprotect` reaches with key -1. With key -1 a protection of `PROT_EXEC` alone gives the execute-only key, and any other moves a region of that key back to 0 (`VM_CHANGE_XO`), as Linux's `arch_override_mprotect_pkey`. A fork's child copies the bits and the execute-only key with the regions.

PKRU is a component of the thread's XSAVE image, so a switch, a fork and a ptrace's `NT_X86_XSTATE` move it with the rest of the state, and an exec's initial state has `PKRU_INIT`. The signal frame is written with PKRU 0, so a stack under a denied key still takes it, and the frame's image is marked as holding PKRU with the interrupted value, as Linux 6.12's `update_pkru_in_sigframe`; the handler starts with `PKRU_INIT`, and `sigreturn` loads the frame's.

The kernel's own access to a process's memory is checked in software, since it has no fixup for a fault in a copy: `pkey_allows` (`paging.c`) refuses a page whose key the running thread's PKRU denies the access, in `range_ready` for the checked copies, in `pin_allows` for a pin of user pages and in `vm_resolve` for a page brought in on the caller's behalf, so the copy or the pin fails with EFAULT. It applies only to the current address space: ptrace, `/proc/PID/mem` and `process_vm_readv` reach another's, or the caller's own through `paging_access`, with no check, as Linux's remote access ignores the keys. `/proc/PID/smaps` shows each region's key as `ProtectionKey:` where the keys are on.

### Memory policy

The machine has one memory node, node 0, so no allocation reads a policy: `mempolicy.c` checks each policy as Linux does, keeps it, and reports it. A policy, `struct vm_policy` (`vm.h`), is a mode, its mode flags, a home node and, when it has a flag, the node mask its caller gave. It does not change once made and is shared by reference. A thread holds the one `set_mempolicy` gave it (`process_t.mempolicy`): `fork_ids` gives a child and a new thread the caller's, an exec keeps it, and `mm_drop` puts it when the thread ends. A region holds the one `mbind` gave it (`vma_t.policy`): `vm_set_policy` splits the region at the range's ends, `vm_merge` joins neighbours only when their policies are equal, and a split, a fork's copy, `mremap`'s move and a stack's growth carry it (`vm_insert_like`).

A file in memory, which is a tmpfs or memfd file, shared anonymous memory or a System V segment, keeps the policy of its pages itself, as Linux's shared policy of a shmem inode: a list of page ranges in `struct shmem`, which `mbind` changes through any mapping, `mempolicy_at` reads for every mapping in every process, and `shmem_free` frees with the file.

Linux maps one shared zero page where an anonymous page is first read, and its policy calls tell that page from a page of memory: `mbind` under `MPOL_MF_STRICT` does not count it, `move_pages` answers `-EFAULT` for it, and `numa_maps` leaves it out. Rach2 gives such a read a frame of its own and marks the entry `PTE_ZEROFILL`, a software bit. The page stands for Linux's zero page until the processor sets the entry's dirty bit or the kernel stores into the frame (`cow_fault`, `page_private`, a pin) or maps it writable in a KVM guest's nested page tables (`kvm_tdp_fault`, which maps such a page read-only on a read fault), and a fork passes the mark to the child's entry. `paging_user_page` and `paging_user_frames` read it for the policy calls and for `numa_maps`.

`migrate_pages` and `move_pages` find every page on the node it would go to, so they check their arguments and the caller's right to inspect the process, as `ptrace` would for a read, and move nothing. `move_pages` reads a 32-bit program's addresses as 32-bit pointers at every index; Linux 6.12 misreads them past the first 16 when no nodes are given, a fault [the index of upstream faults](../../../dev-log/upstream.md) records.

### Locked memory and pins

A region locked by `mlock`, `mlock2`, `mlockall` or `MAP_LOCKED` has `VM_PROT_LOCKED` in its protection, and with `MLOCK_ONFAULT` or `MCL_ONFAULT` also `VM_PROT_LOCKONFAULT`; `vm_lock` splits and merges the regions as `mprotect` does, and passes over device memory. There is no swap, so a lock only brings the pages in (`vm_populate`), unless it is on fault, and counts them: VmLck is the bytes of the locked regions (`vm_locked`). `mlockall(MCL_FUTURE)` keeps the lock bits in the address space's `def_prot`, which `mmap` and `brk` give each new region. A fork's copy has no lock and no `def_prot`, as Linux's has no `VM_LOCKED` and no `def_flags`, and `MADV_DONTNEED`, `MADV_FREE`, `MADV_COLD` and `MADV_PAGEOUT` over a locked region fail with EINVAL. A lock that meets a region of `memfd_secret` locks it but cannot bring its pages in, since Linux's `get_user_pages` refuses them, and `mlock` answers ENOMEM, as Linux's does; `MAP_POPULATE` and `MAP_LOCKED` pass such a region over.

`mem_lock_room` checks the caller's `RLIMIT_MEMLOCK`, 8 MiB by default, which a privileged process passes: `mlock` past it fails with ENOMEM, and with a limit of 0 with EPERM, as Linux's `can_do_mlock` answers; `mlockall(MCL_CURRENT)` compares the whole address space with it; `MAP_LOCKED`, a mapping under `MCL_FUTURE` and a `mremap` that grows a locked region fail with EAGAIN; and a locked stack grows only within it.

A pin holds frames for a device, as Linux's `pin_user_pages` and `account_locked_vm` do for GPU drivers, KVM and VFIO. `frame_pin` adds `FRAME_PIN_BIAS` to a frame's count, so that the frame stays out of the pool whatever mappings go, and the count of mappings is the word modulo the bias. `pin_user` brings in each page of a user range, for a write with `PIN_WRITE`, gives the address space a frame of its own for a private page another shares, and pins the frames; `pin_frames` pins frames a driver allocated. Each pin's pages count in the address space's VmPin against the caller's `RLIMIT_MEMLOCK`, and a pin past it fails with ENOMEM, as `account_locked_vm` answers. A fork gives the child a copy of each pinned private page, as Linux's `page_needs_cow_for_dma` does, so that the device's frame stays the parent's. A pin registers its range on the change notice: an unmap of any of its pages, or the end of the address space, calls the holder's `release`, which stops the device, and then drops the frames and the charge; other changes leave a long-term pin as it is. A pin charged to no address space goes only at `unpin`. A holder with `PIN_KEEP_PAST_END`, VFIO's, keeps its pin past the end of the address space, device pages and all: only the charge goes, the holder is told nothing, and the frames stay pinned until `unpin`, as Linux's VFIO, which has no MMU notifier, keeps its pinned pages and its `VM_PFNMAP` mappings past `exit_mm`, since a device released at the close of its descriptor, after the address space ended, may still use them. The pin's range is then off the change notice, so a revocation of its device pages after the end is not heard, as Linux's Type1 hears none. Such a pin also holds each shared mapping of a disk file its range meets (`filemap_disk_pages`), from the pin to `unpin`: the file's pages in memory go with its last mapping, and without the hold a kept frame would no longer be the file's, so that a later `write(2)` would miss what the device reads. Held, the pages stay the file's, as Linux's pin holds a page cache folio. `unpin` does not sleep: it drops the hold, and the mapping's release, which writes back what the process stored when its descriptor was open for writing, waits for `vm_file_reap`, which the holder runs once it no longer walks its own lists. A long-term pin (`PIN_LONGTERM`, VFIO's, Linux's `FOLL_LONGTERM`) refuses a write pin of a writable shared mapping of a disk file with EFAULT before it takes frames or holds, as Linux's `writable_file_mapping_allowed` does (`mm/gup.c:1233`).

VFIO sets `PIN_IO` to accept device pages outside the frame allocator as well, as Linux Type1 follows `VM_PFNMAP` mappings. It sets `PIN_SLOW` as well, which refuses a read of a region mapped without `PROT_READ` whatever its page, as Linux's `pin_user_pages_remote` has no fast path to take a present one. These pages have no RAM pin or memory charge. `pin_count` counts all pages in the mapping; `pin_ram_count` counts only its RAM pages. A mixed range charges only its RAM pages. A pin containing device pages also ends before a protection change or device revocation while its address space lives, so a BAR whose decoding is disabled or whose function is reset loses its DMA mappings before its physical pages are revoked.

### The change notice

A driver that keeps something derived from a process's pages, a pin, a GPU's page table or a cache of translations, registers a range of the address space with `mmn_register`, as Linux's `mmu_interval_notifier`. `mmn_notify` calls each range a change overlaps, with the part they share, and raises its count: `MMN_UNMAP` from `munmap`, `mremap`, `brk`, a `MAP_FIXED` mapping and `shmdt`; `MMN_PROTECT` from `mprotect` and from a fork, which write-protects a writable private region; `MMN_COW` when a private page is given a copy of its frame; `MMN_DROP` from `madvise`; and `MMN_TRUNCATE` when a device object or a shared memory file takes its pages back (`paging_zap_device`, `filemap_shmem_cut`). The call comes before the pages go, under the big lock, and must not sleep; a range may unregister itself in its call. A change under the regions' lock held to write takes the big lock for the call and again for the change of the entries, not between them, since every driver that reads entries holds the regions' lock to read, which keeps the change out from its notice to its last entry. The end of the address space (`mm_put`) unregisters each range and calls it with `MMN_RELEASE` and its whole range.

### Files that regions map

`filemap.c` makes the `struct vm_file` of a mapping, a `struct filemap` with a copy of the descriptor, which keeps the open file description, so a program may close the descriptor after `mmap`. On the KRFFS root a mapping counts among the holders of the file's node (`filemap_holds`), as a descriptor does.

`shmem.c` keeps a file's bytes in memory, a frame for each page, made when the page is first written or mapped: a tmpfs file's ([tmpfs](../fs/tmpfs.Readme.md)) and shared anonymous memory's. The table has one reference to each frame and each mapping of a page one more. A truncation first takes the pages it frees out of every region that maps them (`filemap_shmem_cut`), even when a disk read-around populated them without updating the remembered file size, so a later touch maps the page the file has then. `shmem_free_yielding` frees as `shmem_free` does but gives way after each leaf of 1024 pages (`sched_give_way`), as Linux's `shmem_undo_range` calls `cond_resched` after each batch of folios (mm/shmem.c:1060 and 1101); a tmpfs file freed with its last name and hold, shared anonymous memory's own pages at their mapping's release and an i915 object's pages at its free by the holder that took the GEM lock, for the free or before it ([i915](../drm/i915/Readme.md)), use it, since no other thread reaches them, and every other free of a `struct shmem`, which may run where nothing sleeps, uses `shmem_free`.

`shmem_count` counts a page range through allocated leaves alone for cachestat, with scheduling points between leaves and no leaf pointer retained across one.

A file of `memfd_secret` is a tmpfs file of the hidden mount `memfd_create` uses, with the kernel's answers of [memfd_secret(2)](../../../man/man2/memfd_secret.2). Its pages count against a `struct shmem_quota` of its real user (`secret_user` in `fs/tmpfs.c`) whose limit, read at each page made, is the `RLIMIT_MEMLOCK` of the process that touches it, as Linux charges them to the user's `locked_vm`; a touch the quota refuses raises `SIGBUS`, as one past a full tmpfs does. Its region has `VM_PROT_SECRET`, which keeps it from every path that reaches a page through another process or a device: `paging_access`, and through it `ptrace` and `/proc/PID/mem`, answers EIO and `process_vm_readv` EFAULT, a node query by `get_mempolicy`, a pin (`pin_allows`) and a fault of a KVM guest's memory (`kvm_tdp_fault`), which also keeps a 2 MiB leaf from any range the region meets, are refused, a core file leaves the region out and `/proc/PID/smaps` shows it as `dd`. `vm_lock` and `vm_lock_all` leave its lock bits as they are, as Linux's `mlock_fixup` passes such a region over, and `mlock` then fails on it with ENOMEM, as Linux's populate does.

A file on ext2 that private or shared mappings map has a `struct dshare` with its pages in a `struct shmem`, found by mount and inode number, which on ext2 identify one file while anything has it open, in a table of 256 buckets by inode number, since every read and write of a disk file looks its file up there, as Linux reaches a file's pages from its inode. A read made without the big lock takes it only once a shared mapping through a descriptor open for writing has mapped its file (`filemap_disk_stores`): the pages of a file that only private mappings or read-only shared ones map equal the file, since a shared mapping through a descriptor open only for reading can never be made writable. The read asks again before each page, the file page cache's read among them (`filecache_file_read`'s `cut`), since such a mapping made while it slept on an earlier page may have stored into a later one, and from the first page where one has it takes the big lock and reads each page from the mapping's page in memory when there is one. The read asks under `dshare_lock`, a spinlock under which a record joins and leaves its bucket and is marked, after a count of the bucket's marked records read as one word, so a read of a file in a bucket with none takes no lock and a mapping of one file does not put the reads of another under the big lock. A page is read from the file at its first touch under the file's lock, which excludes writes and truncation until it joins the resident pages. A fault that reads the file also reads the pages of a 128 KiB window around it, from 16 pages before it, that neither the resident pages nor the file page cache has, in the file's order, into the file page cache alone, as Linux's mmap read-around reads its readahead window (`do_sync_mmap_readahead`, `mm/filemap.c:3187-3203`): each run of such pages is one call of the type's `read_frames`, which on ext2 is one transfer into their frames for each run of blocks that follow on the device, and the fault around this one and the next faults take them from memory, where a read of each page at its own fault cost a request each. The file counts the faults that read it less the faults that found their page in memory and the pages a fault mapped from memory before its read, as Linux keeps `mmap_miss`, and stops reading around above 100, so that a file touched at random is not read in windows; only an ext2 file whose pages may be the cache's frames reads around. A page not resident comes from the file page cache when the cache has it, and a page read from the file is kept there, so a program started again or a library mapped again after its last mapping went comes from memory, as Linux's page cache outlives the mappings of its folios. While no shared mapping through a writable descriptor has mapped the file, the resident page is the cache's frame itself, which the cache lends and keeps with a reference of each, as Linux maps the page cache's folio (`filemap_fault`, `mm/filemap.c:3326-3370`): the frame changes only as a write or a truncation changes the file, which drops the file's pages from the cache after. The first such mapping drops them before it is used, since its stores reach the pages before the file, and its file's pages are copies from then on. The table of the resident pages changes only under the file's lock, a page joining it at a fault and a truncation or the last release taking pages out, and its arrays, the directory and the leaves of 1024 entries, are made, replaced and freed only under the big lock as well, so a descriptor's read under the big lock alone walks them safely and sees each entry either empty or holding a page read from the file. A fault, which runs without the big lock, finds a resident page and puts in one it read under the file's lock alone, as Linux's `filemap_fault` finds and locks a folio (`mm/filemap.c:3326-3370`) and `__filemap_add_folio` adds one under the mapping's own lock (`mm/filemap.c:842-950`), and takes the big lock only when the page's leaf must be made (`shmem_has_leaf`). A private region maps the clean frame with `PTE_COW`, so shared stores and descriptor writes remain visible until the private region first writes. Only a shared mapping through a writable descriptor may write pages back. A truncation removes every page past the new EOF from private mappings too, including copies, and a later touch raises SIGBUS. The calls on the file's descriptors keep the file and the pages in step: a read takes a page in memory from it (`filemap_read_resident`), as Linux reads the page cache, and `filemap_file_written`, `filemap_file_truncated` and `filemap_sync_file` follow a write, a truncation and an fsync, and [brk(2)](../../../man/man2/brk.2) says when the pages go back. A writable shared mapping maps each page read-only until its first write fault, which marks the page as stored to under the file's lock (the file's `mkwrite`) before the entry gains write access, as Linux's `page_mkwrite` dirties a folio first; `mprotect` gives such a page write access only through that fault. The callback receives the held frame and checks under the file's lock that it is still resident at that offset; a delayed fault retries after truncation removed or replaced it, without marking the replacement. Kernel writes through ptrace, `/proc/PID/mem` and `process_vm_writev` validate and mark the shared frame before each copy too, including one already mapped writable. Only a marked page goes back, as Linux's write-back passes a clean folio by, so a page read from a hole and never stored to leaves the hole unallocated; a mark stays until a truncation frees the page. A page goes back up to the file's size with the file's node lock held from before the size is read to the end of the write, so a truncation comes wholly before or after it. Its tail past EOF is zeroed first, as Linux's mpage_writepage zeros it. Writeback copies through a 1 KiB stack buffer, mapping the frame only for each copy, so a final unmap allocates no buffer and keeps no temporary mapping across a sleeping write. A failed last release retains its mapping, descriptor, pages and marks with a reference of its own for sync to retry, and keeps its error per file for the next fsync, as Linux keeps `wb_err` apart from the folios. Every failed write of a file's pages is also recorded in its file system's write-back errors (`vfs_wb_err_set`), which each description's fsync and syncfs report once, as Linux's `mapping_set_error` records it. An msync with MS_SYNC runs the file system's fsync through the region's own description, whose cursor moves past what it answers, as Linux's msync syncs the region's file (`mm/msync.c:87`), while the pages are written through a description open for writing that any shared mapping of the file has; a page write it answers is not kept for fsync, and what the fsync answers is never kept, since it was recorded where it failed. A write-back of every page that succeeds, by fsync, sync(2), msync or another release, drops the retained reference, whatever error is kept; the error stays until an fsync returns it, on the file's record alone, with no pages, marks or descriptor, once the file's last mapping has gone. Such a record holds the file's generation, so that a later file given the same inode number does not take the error, and goes at the next fsync of the file or at its unmount. A sync snapshots the generation of the last zero publication under the reap list's lock (`vm_file_reap_start`), takes an own reference to a mapping's backing-file description before sleeping, and drains and waits for releases only through that generation. The generation is global to the reap list, so the same boundary covers files queued before the call and releases already writing. The own description writes stores even when the mapping's last reference falls between the reap and the write; later mappings and last puts cannot extend the drain. The page range is bounded before draining. Failed releases whose retry succeeds are queued for a later reap. A count falls to 0, receives its generation and joins the reap list in one hold of its lock (`vm_file_put`). Descriptor writes update any mapping made while the writer faulted its buffer in; a core-file write updates resident pages under the same file lock.

### Checked user access

`copy_from_user` and `copy_to_user` (`usercopy.c`) check the range against the user range without overflow, then copy with no lock (`arch_user_copy`, a string move), as Linux's copies do (arch/x86/include/asm/uaccess_64.h:119-131). A page that is not present, or not writable for a write, faults, and the page fault handler resolves it under the regions' lock as it would a fault of the program; a fault no resolution serves, a page in no region, in one that does not allow the access or of a PROT_NONE region, which is not present to the processor, resumes at the copy's fixup (`arch_user_copy_fixup`), which ends the copy and returns the bytes it left, as Linux's exception table does. Nothing holds a page between faults, so another thread's unmap during the copy ends it at the page that went. A failed copy has partial effects: the bytes before the fault are copied, the call returns EFAULT, and `copy_from_user` zeroes what it did not fill of the kernel buffer, as Linux's `_copy_from_user` does. A caller whose destination is live state, such as a vCPU's registers or a terminal's size, copies into a local first and publishes it only after a whole copy, as Linux stages them; `copy_from_user_left` copies without the zeroing, for a destination whose old bytes must stay, and it and `copy_to_user_left` return the bytes not copied, for a caller that counts the bytes before a fault in its result, as a read of `/dev/zero` does. `strncpy_from_user` and `strnlen_user` bring pages in one at a time, since a string may end before a page that is legitimately unmapped. `get_user_u32` and `cmpxchg_user_u32`, which `sys/proc/futex.c` uses, make one load or one compare-and-exchange of an aligned word. `vm_resident` answers, with no fault and no sleep, whether every page of a range is present with the access, by the regions and the page tables; it is true for an empty range, a range in the thread's window and a kernel address. A file system that holds a file lock copies a user buffer only in the same step as a `vm_resident` that answered 1, since under the big lock nothing unmaps the range inside that step, and on a 0 lets its locks go and brings the pages in.

A thread may open one window of kernel memory to these checks (`user_window_open`, closed by `user_window_close`): its base and length are in the thread's record (`uwin_base` and `uwin_len` in `proc/process.h`), and `user_range_ok` and `vm_prefault_range` take a range inside it as present user memory (`proc_window_covers`). The copies between descriptors open one on their buffer so that the read and write paths, which check every buffer as a user's, take it; Linux's `set_fs(KERNEL_DS)` once let `kernel_read` and `kernel_write` do the same for every kernel address. The window covers only that buffer, so a user pointer the same thread passes is checked as before.

### Memory pressure

The buffer cache and the disk page cache have a target of a quarter of managed memory together, half each ([the VFS's Readme](../fs/vfs.Readme.md) gives the buffer cache's limit). `mem_balance` (`pressure.c`) runs `mem_reclaim` when the free count is below a sixteenth of managed memory, and reclaim asks the buffer cache, the file page cache, the disk page cache and then the drivers' shrinkers in turn until the free count reaches an eighth or nothing more comes back. A shrinker, `struct mem_shrinker`, is what a driver registers for memory it may lose, a GPU's purgeable buffers; reclaim asks the last registered first for the frames the caches did not give, and says whether it may sleep. A cache gives clean entries first and writes dirty ones back only from a system call with interrupts on, so a page fault takes clean frames alone. A reclaiming process takes from the reserve, which the writes it starts need.

`mem_balance` runs before the allocation that needs the room: in `fork`, `execve`, `brk`, `mmap`, `shmat`, a fault's resolution and a write through `paging_access`. The allocators themselves never sleep. `mmap` and `brk` reserve addresses only, so a fault after them may find no frame and end the process with `SIGKILL`.

### The file page cache

The buffer cache keeps at most half the heap, a gigabyte of a machine of 16 GiB, so without more a file read again, a program started again or a library mapped again would come from the disk again. `filecache.c` keeps a copy of each whole page of a regular ext2 file that `read(2)`, exec and private mappings read, in a frame of its own, found by mount, inode number and generation. `file_read` (`sys/syscall_fs.c`), which `read`, `pread64`, `readv`, `preadv`, `preadv2` and `sendfile`, `splice` and `copy_file_range` out of a file reach, hands such a file to `filecache_file_read`: a page the cache has is copied to the caller straight from its frame, with a reference held on the frame meanwhile, after a wait while its read has not ended, and a page it lacks starts its readahead window, below, and is waited for and copied the same way; each page read is kept, the last with zeros past the file's end, and a page whose read failed is read again by the reader alone, into a frame of its own, as Linux's `filemap_read_folio` reads it (`fc_read_one`). The bytes a page gives are cut at the file's size read once the page is had, as Linux's `filemap_read` reads `i_size` after it has the folios, so a truncation that raced the read ends what it returns and the zeros past the new end are not returned as data. A read at or past the file's size gives 0 bytes before any page is looked up, as Linux's `filemap_read` stops at the size. A private mapping that fills its pages through `filemap_fill` gets a copy of a cached page; exec and the mappings of an ext2 file's pages in memory share the cache's frame, which a private region maps copy-on-write, as [files that regions map](#files-that-regions-map) says.


Readahead is Linux's on demand (`mm/readahead.c`), with the state of `struct file_ra_state` in each description (`ofd->ra`, `fs/fd.h`): the window last read, `size` pages from `start`, of which the last `async_size` start the next, the most a window takes, and the byte after the last one a read took. A read that misses a page reads a window from it at once (`fc_sync_ra`, Linux's `page_cache_sync_ra`). At the start of the file, for a read longer than the most a window takes, or for one that goes on from where the description's last read ended, the window is four times the pages the read wants rounded up to a power of two while those are at most a 32nd of the most, twice them while at most a quarter, and the most past that (`get_init_ra_size`), and its pages past those wanted start the next window, or half of it when there are none. Any other miss counts the pages the cache has just before it: no more than the read wants is a random read, which reads what it wants and leaves the state alone; more sets a window of those and the read, twice those when they reach the file's start, whose last page starts the next. The most a window takes is 32 pages, 128 KiB, Linux's `VM_READAHEAD_PAGES`, or 64 after POSIX_FADV_SEQUENTIAL, and a read longer than that may take as many pages as one request to the device moves (`ractl_max_pages`); after POSIX_FADV_RANDOM a miss reads what the read wants, up to the larger of those. The first page that starts the next window is marked, a bit of the page's record that stands for Linux's PG_readahead (`FC_MARK`), when it is put into the cache.

A read that reaches a marked page, whether its read has ended or not, clears the mark and starts the next window (`fc_async_ra`, Linux's `page_cache_async_ra`) before it takes or waits for the page: where the last window put the mark, the window moves past it and grows, four times while under a 16th of the most, twice while at most half, and the most past that (`get_next_ra_size`); a mark the description did not set, as another reader's of the file, starts a window at the first page from there that is not present, of the pages between and the read, grown. The whole of the new window starts the next, so its first page is marked.

A window is read in the reader's own context, and the reader does not wait for it (`fc_read_async`), as Linux's `page_cache_ra_unbounded` puts a window's folios in the page cache locked and submits their bios. Each run of pages the cache lacks goes into the cache at once, each page in a frame of its own and locked, a second bit of its record that stands for Linux's PG_locked on a folio not yet up to date (`FC_LOCK`), and the run, at most what one request to the device moves, goes to the type's `read_frames` with a completion: ext2 plans the run's blocks under the file's lock, starts each run of sectors with `block_read_frames_async` and returns, and fills a hole and a page another copy of which may be newer itself, in the call. The completion, from the disk's interrupt, clears the lock of each page, or drops a page whose read failed, as `folio_end_read` does, and wakes the readers waiting for its pages. A reader that reaches a locked page waits on one of 64 queues that the page's file and offset choose, as Linux waits on a folio's lock on a hashed queue, and looks again when woken. A locked page counts as present, for where a window starts or ends; no reader copies, lends or maps it, and exec and a fault's read-around read such a page themselves. A read in flight holds no lock of the file and no reference to its description or mount: a change of the file or an unmount drops its pages, a locked one among them, whose transfer then lands in a frame that only its request holds, and ext2 frees a file's blocks only once no such read over them is in flight (`block_settle`, [../block/Readme.md](../block/Readme.md)), as Linux's truncation waits on each locked folio. A window ends at a page no frame is had for, and a reader that misses then reads the page itself. POSIX_FADV_WILLNEED and readahead(2) start the range's pages the same way without a mark, at most the larger of the window's most and what one request to the device moves (`force_page_cache_ra`), and POSIX_FADV_DONTNEED drops the range's whole pages from the cache, as [readahead(2)](../../../man/man2/readahead.2) says.

A file's record holds the size and the modification time its pages were read at, and a page is used only while the file still has them. A write, a truncation, an allocation and a change of size through the VFS (`vfs_write`, `vfs_truncate`, `vfs_fallocate`, `vfs_setattr`) drop the file's pages after they change it, and an unmount every page of its files. Every way of writing a file reaches one of those calls: `write`, `pwrite`, the vectored writes, `copy_file_range`, `sendfile` and `splice` into the file, a shared mapping's writeback (`fs_write_at`) and a loop device's writes. Each counts as a change of the file in one of 256 counters, each shared by the files whose hashes have the same low bits, and a page read while a change of its file ran is not kept. The record lists the file's pages, so a change drops them without a search of the pages of every other file. `init_filecache` sizes the table of the pages and the table of the files at boot, each to a power of two between an eighth and a quarter of the managed frames, so that a lookup walks a list of a few entries when the cache holds three quarters of memory.

The cache takes a new frame while a quarter of managed memory is free and its page records, 64 bytes each on x86-64 and 32 on i686, fit in an eighth of the heap. Past either it takes the record of its least recently used page and gives that page's frame back, while a sixteenth of memory is free, above the reserve. Reclaim takes frames back, the least recently used first ([Memory pressure](#memory-pressure)), and counts only the frames that went back to the pool, not one a reader still holds; and `/proc/meminfo` counts them in Cached.

`fc_lock`, a spinlock taken with interrupts off, covers the two tables, the use order, the count and the counters of changes, so a read finds and copies a page with no big lock, as Linux's `filemap_read` takes no lock of the file's (`mm/filemap.c:2614`). The reads of the file and the copies to the caller run outside it, with a reference held on the frame of a page being read. A hit copies its page to a frame under it through a temporary kernel slot, so it comes before `kva_temp_pool` in the lock order, as Linux takes the `i_pages` lock under the page-table lock (`mm/filemap.c:89-92`).

### The disk page cache

`pagecache.c` maps a KRFFS root into the kernel: a window at `KVA_PCWIN`, supervisor-only, over a backing store read and written a page at a time. KRFFS reaches the window through pointers ([krffs.Readme.md](../fs/krffs.Readme.md)), and a fault in it is the cache's miss. The backing is the RAM-disk module under `rach2.fswindow`, or the KRFFS partition of the boot disk under `rach2.fsdisk`, `rach2.root=disk` or a root chosen by its identity. The disk must be `BLOCK_FAULT_SAFE` when the root is mounted, as ATA, AHCI and NVMe disks are before they go over to their interrupts ([the block layer](../block/Readme.md)). Any other root leaves the cache without a backing.

On i686 the window runs from `0xD0000000` to the lowest PCI memory BAR whose address lies in the 512 MiB after it, and is 512 MiB when none does. On x86-64 no physical address reaches the window's, so it is always 512 MiB. A root larger than the window is refused.

The cache has `PC_SLOTS`, 4096 slots, and uses as many as half the caches' target allows. A slot takes a frame of the DMA pool when it is first filled, since the backing may give the frame's address to a device, and gives it back under pressure (`pc_shrink`). On a miss `pc_fault` takes a free slot or the clock's victim, written back first when dirty, reads the page, and maps it read-only for a read or writable and dirty for a write; a later write to a page mapped read-only faults again and marks it dirty. The fault path polls the disk with interrupts off and never sleeps.

`pc_writeback` marks the slot `pinned`, which eviction, reclaim and other writebacks respect, then maps the page read-only and clears its dirty mark before the write, so a store during the write marks it dirty again; a failed write leaves it dirty. `pc_sync` returns `PC_SYNC_BUSY` when it passed over a pinned slot and `PC_SYNC_FAILED` when a write failed. `fsync` of a file of the KRFFS root answers EIO on either, and `sync` repeats while a slot is busy, for at most 30 seconds of ticks.

## Limits

* There is no swap.
* A page of `memfd_secret` stays in the kernel's own mapping of memory, which Linux takes it out of; only the calls and devices listed under [Files that regions map](#files-that-regions-map) are kept from it.
* `cachestat` counts no page as under writeback or evicted, since there is no swap and no record of dropped pages; on ext2 a page counts as in memory when the buffer cache holds each of its blocks.
* The i686 kernel addresses the first 4 GiB of physical memory, and every page it maps is executable. The x86-64 kernel addresses 64 TiB, or 64 GiB without 1 GiB pages.
* The heap is 256 MiB on i686 whatever the machine has.
* A file's pages are numbered in 32 bits: a mapping of a file or of shared memory past page 2^32 is refused with EOVERFLOW, and a file in memory ends at 16 TiB less a page. The file page cache keeps no page in a frame at or past 8 TiB.
* A writable shared mapping of a file is possible on tmpfs and ext2 alone. A touch of a page wholly past EOF on either raises `SIGBUS`, including through a private mapping.
* A process has at most 65536 regions, unless `vm.max_map_count` is raised.
* A KRFFS disk root is at most 512 MiB, less on i686 where a BAR shortens the window, and the disk page cache keeps at most 4096 pages.
* The MMIO region is 128 MiB, of which one window may take the longest free run, 127.8 MiB under QEMU; i686 maps it in 4 KiB pages and only below 4 GiB. The modules together have 64 MiB and must lie below 4 GiB, and i686 has 1024 temporary mappings.
* The machine is one memory node. A node mask may name 1024 nodes, as on Debian's kernel, on both architectures; `numa_maps` has no `mapmax=` and no `active=`, since the kernel counts no mappings of a page and keeps no active list; and `mbind`'s move flags count as unmovable only a page pinned for a device.
* i686 does not randomize addresses, and x86-64 places the first program, which the kernel loads itself, at fixed addresses.

## Tests

`tests/run NAME` runs a suite on the architecture in `ARCH`, i686 by default, and `ARCH=x86_64 tests/run NAME` on x86-64 ([the suite inventory](../../../tests/system/suites.md)). `default`, `fault`, `memory`, `pools` and `ext2` are in the core tier, which `make test` runs.

* `tests/run default` runs the guest probes ([the tests' Readme](../../../tests/Readme.md)): `vmprobe` (the heap, anonymous memory, a mapping below the heap once the room above it is taken, and stack growth), `forkro` and `cowregrant` (copy-on-write, and the frames of 200 forks that come back), `oomprobe` (the `SIGKILL` of a process out of memory), `usercopyfault` (EFAULT for a path that runs into an unmapped page), `musl/vmamusl` (300 mappings at once), `mmapdevprobe` (mappings of `/dev/mem`, their refusals, fork, `MADV_DONTFORK`, advice, `mremap` and `munmap`), `musl/mapmusl` (mappings of files and of shared memory, `mprotect`, `mremap`, `madvise`, `msync`, `/proc/self/mem`, and the program's own segments, which read its file again after `madvise`, in a copy of it whose file was renamed and unlinked as well), `musl/callsmusl` (the `mlock` calls with VmLck read after each, `RLIMIT_MEMLOCK`'s ENOMEM and EPERM, `MCL_FUTURE`, and `mincore`) and `musl/memcallmusl` (`mseal`, `process_madvise`, `process_mrelease`, `cachestat`, `memfd_secret` and the answers for memory keys and shadow stacks, against Linux 6.12's on each kernel and for an i386 program on the x86-64 kernel) and `musl/pkeymusl` (the memory keys: the three calls, keys in regions through splits, merges, `mremap` and fork, `SEGV_PKUERR` faults, PKRU through signals, fork, threads, exec and ptrace, the kernel's copies against Linux's remote access, the execute-only key, and what `cpuid`, `/proc/cpuinfo` and smaps show, against Linux 6.12 under QEMU's `max` processor and on one without keys).
* `numaprobe`, also of `tests/run default`, sets and reads back each memory policy of a thread and of a range, follows a range's policy through a split, a join, a fork and a second mapping of shared memory, and asks `move_pages` and `migrate_pages` about its own pages and another process's; its rows are what the same program prints on Linux 6.12 with one node, on both kernels and as a 32-bit program on x86-64.
* `tests/run fault` runs `vmfault` and `winprobe`, which touch no mapping and the page-cache window, each in a boot of its own, and each must die on `SIGSEGV` with the kernel's record of the kill and the machine running.
* `tests/run memory` requires the recovery kernel at 8 MiB to print `memory: refused` and not fault, checks the report's four numbers at 64 MiB, 3 GiB and 4 GiB against the map and the size, runs `memprobe` at 64 MiB, inside the window, and at 4 GiB, mostly past it, fails frame allocations through fork and exec under `rach2.framefail`, and runs kernel stacks out.
* `tests/run bigmem`, on x86-64 alone, requires all of a machine's 8 GiB to be counted, none of it unreachable, with MemTotal the frames the kernel manages, and a program's 5 GiB of pages to read back as written, and on a processor without 1 GiB pages a machine of 72 GiB to be counted to the direct map's 64 GiB; that machine boots only on Linux and macOS hosts, since QEMU on Windows commits its whole 72 GiB, and only where the site permits the lazy memory profile that reserves 4 GiB for it.
* `tests/run pools` requires the heap to come back to where it started after a thousand pipes, ptys and sockets each.
* `tests/run ext2` runs `musl/mapmusl` on an ext2 root, with shared mappings written back to the file.
* `tests/run large`'s case `cache` runs `musl/pagecachemusl` on a machine of 1.5 GiB, whose heap is 256 MiB: an ext2 file of 256 MiB read twice, the second time by `read`, `pread64`, `readv` and `preadv2` with no disk read (`pgpgin`); `pread64` of a small file at its size, past it and at 2^44, each giving 0 bytes and leaving Cached as it was; and a small file read into the cache and changed every way a file can be, unmounted and written through a loop device among them, before a read that must see the change.
* `tests/run stress` and `stress-ahci` write more than the disk page cache keeps through a KRFFS disk root.
* `tests/run smp` runs fork, exec and `munmap` on several processors at once.

`tests/run host` runs the host tests ([the host tests' Readme](../../../tests/host/Readme.md)): `frame_hosttest.c` (the map, from QEMU's, a laptop's, a UEFI map of 256 entries and synthetic ones, with each architecture's reach), `kheap_hosttest.c` (the heap's size, runs, reserve and guards), `paging_hosttest.c` (`paging.c` with i686's `mmu.c`: the range checks at the top of the address space, the temporary mappings and their pools on two, three and 64 processors, and the guard's panic), `devmap_hosttest.c` and `devmap64_hosttest.c` (device regions on i686 and x86-64: faults with each cache type, fork with `MADV_DONTFORK`, munmap and exit with the object's references, and revocation with `SIGBUS`), `pin_hosttest.c` and `pin64_hosttest.c` (pins and their limit, fork and release, locked regions, and the MMIO region's windows onto a BAR, in 2 MiB pages on x86-64), `mmnotify_hosttest.c` and `mmnotify64_hosttest.c` (the change notice and its calls from `paging.c`, and the shrinkers under `pressure.c`), `vm_hosttest.c` (AVL balance and stable nodes under ordered and permuted inserts and removals, split and merge, file references, gaps, byte counts, mapping limits and allocation failures, and a change of the regions through `regions.c` racing a fault and a /proc reader, which wait for it under the regions' lock), `mm_hosttest.c`, `modlayout_hosttest.c`, `filecache_hosttest.c` (a page inserted while a shrink frees its file's record between the insertion's two holds of `fc_lock`), `pagecache_hosttest.c`, `pagecache_ring_hosttest.c` (the slots against a lookup on a KRFFS disk root) and `tmpfs_hosttest.c` (`shmem.c`). `privatefilemusl` checks clean private-page visibility, copy-on-write, fork, truncation, discard and file lifetime on tmpfs and, with a directory argument, ext2. `open_hosttest.c` compiles `filemap.c`, and `pipe_copy_hosttest.c` and `unix_hosttest.c` compile `usercopy.c`.

`filecache_hosttest.c` checks only the insertion against a record freed beside it, and no suite runs the debug shell's `isolate` command, which writes one address in two page directories, or its `mmio` command.
