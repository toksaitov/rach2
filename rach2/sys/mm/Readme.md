# Memory management

The memory subsystem accounts for the physical memory the firmware's map describes and manages every frame of it, keeps the kernel's own virtual layout above user space with a heap that frees, and keeps per-process page tables, virtual memory areas (VMAs), copy-on-write fork, demand paging, checked user access, and the disk page cache. Pages are 4 KiB.

## Physical memory

`frame.c` builds the map of physical memory from the Multiboot memory map, in 64-bit arithmetic: the ranges the map calls available, less every range of another type where it overlaps one, sorted and merged, with the part at or above 4 GiB counted apart as unreachable, since this kernel addresses nothing there. It falls back to `mem_upper` as one range from 1 MiB when no usable map is present. The boot reserves the kernel image with the boot data below it and the modules, `init_paging` reserves everything below the allocator's break, the tables it carved included, and the boot reports four numbers: usable, the available bytes below 4 GiB; unreachable, the available bytes above; reserved, what the boot took of the usable ranges; managed, the whole frames the table offers above the break, which is usable less reserved within the partial frames at the ranges' ends. The map is printed entry by entry before them. A machine with less than `FRAME_MIN_MANAGED_KIB`, 1 MiB, left as managed memory is refused there by name, `memory: refused: N KiB managed after the kernel's reservations, at least 1024 KiB needed`, and the kernel stops; below that it faulted in whatever first took a frame, and the recovery image on 10 MiB, with 1408 KiB managed, is the smallest boot known to work. `frame_hosttest` builds the map from QEMU's maps at five sizes, from the Lenovo G50-70's map as its boot of 2026-09-12 printed it, held to the four numbers it printed, and from synthetic ones with holes, overlaps, a range crossing 4 GiB and a wrapping length, and `tests/run memory` boots the kernel at 64 MiB, 512 MiB, 2 GiB, 3 GiB and 4 GiB and holds the four numbers to the map and to the size given, and boots the recovery pair at 8 MiB and requires the refusal with no fault.

The kernel identity-maps `[0, HARD_MEMORY_LIMIT)`, 32 MiB, as supervisor-writable pages: the kernel image, the boot data, the page tables the boot carves, the kernel stacks and the DMA buffers a device is given a physical address of live there, where the virtual address equals the physical one. Nothing above it is reached through its physical address. The frame table has one 32-bit word per frame below the map's top: 0 for a free frame, a reference count for a used one, and a state above `FRAME_REF_MAX` for a frame the map does not offer. `alloc_frame` and `alloc_user_page` take a free frame from anywhere the map offers, from a hint that no frame below it is free, and a user frame is zeroed, copied for copy-on-write, and filled by the loader through a temporary mapping (`kmap_temp`, `paging_zero_frame`, `paging_copy_frame`), never through its physical address; a caller may sleep holding a temporary mapping, since each slot is its own. `alloc_kernel_frame`, which the page cache uses for frames it reads and writes by their physical address, stays below the window.

The kernel's virtual layout is the gigabyte from `0xC0000000`, whose 256 page tables exist at boot and are shared by every page directory, so a mapping made there after the first fork is seen by every process: the heap at `0xC0000000`, 256 MiB; the page-cache window at `0xD0000000`, 512 MiB; the MMIO region at `0xF0000000`, 128 MiB, into which `map_mmio` maps a controller's registers uncached wherever they are and returns the virtual address the driver then uses; the temporary mappings at `0xF8000000`, 1024 pages; and the module region at `0xF8400000`, 64 MiB, into which the boot maps every module wherever the loader put it, so a module above the window is read like any other and `modlayout` no longer refuses one. The heap (`kheap.c`) allocates and frees objects of any size: an object of at most 2048 bytes from a page carved into blocks of one size class, a larger one as whole pages, each page grown by a frame from anywhere and each page starting with a header that `kfree` finds at the pointer's page base; the top 16 MiB of the heap is a reserve of sixteen runs of 256 pages that allocations under 64 pages never enter, from which a run of 64 pages to a megabyte comes when the rest of the heap, its free pages scattered by the cache's one-page takes and returns, has no such run. Page tables and directories come from it once it exists, their physical addresses from the kernel directory's own mapping (`paging_virt_to_phys`), and a process record keeps its directory's pointer, since the physical address in `cr3` says nothing about where the kernel reads it. `rach2.framefail` is a test switch: a count written to `/dev/framefail` makes the count-th frame allocation inside a system call fail as a full machine's would, and `memprobe fail` sweeps the count over `fork` and `execve` and requires ENOMEM, no leak and no change to what survived. `mem_reserve` is the kernel's monotonic boot allocator. Its initial break is the greater of `_end` and the highest end of a Multiboot module wholly within the 32 MiB identity-mapped window. Modules ending above that window do not advance the break; their frames are reserved separately and their contents mapped into the module region. It skips frames already allocated after paging starts and fails before crossing the memory limit.

Before reserving module memory, `modlayout.c` rejects an empty or backwards range, a module that ends past addressable memory, a module overlapping the kernel, or two overlapping modules. The rejection includes the module number and physical range.

`alloc_frame` and `alloc_user_page` search above the 32 MiB identity-mapped window first, then below it only while more than sixty-four frames remain free there. The last sixty-four are kept for block requests and the page cache, which use `alloc_kernel_frame` to take frames from the window's top downward; devices need buffers whose physical addresses the kernel can use directly. The allocator maintains free-frame counts as frames are taken and returned. For a process whose effective uid is not 0, `alloc_frame` and `alloc_user_page` refuse a frame when the total free count is at or below the reserve, one thirty-second of managed memory. A user-page refusal reports `user page: refused: the free frames are the reserve's`, followed by the pid. Root, hardware interrupt handlers, and the kernel outside any process may allocate from the reserve. When no eligible frame remains, the user-page allocator reports the boot reservations, kernel and user frame counts, shared frames, and the requesting pid; this report can occur while the last sixty-four window frames are still free. User frames return to the pool when their reference count reaches zero; page directories and private page tables return to the kernel heap.

`mem_cache_target` defines a combined cache target of one quarter of managed memory. The buffer cache uses half that target as its capacity, with a minimum of sixteen buffers, and allocates each buffer's data frame when needed. The page cache also uses half the target as its capacity, with a minimum of one frame and a maximum of its 2048 slots, and allocates frames on demand. When the free count falls below one sixteenth of managed memory, `mem_balance` calls `mem_reclaim`, which reclaims buffers first and page-cache frames second until the free count reaches one eighth or neither cache can release more. Each cache reclaims empty or clean entries before writing dirty entries back; entries in use or whose writeback fails remain cached. Reclaim may sleep, so it runs from `fork`, `execve`, `mmap`, `brk`, and the resolution of a user page that needs a frame or a copy, a kernel prefault and a `paging_access` write included, before the resolution reads the region and the page table entry it works on. It does not run from hardware interrupt handlers or the frame allocators. A failed allocation in `fork` returns `ENOMEM`. `mmap` returns `ENOMEM` when it cannot establish a region, and a failed `brk` leaves the break unchanged; both allocate user frames later, so success does not guarantee that a later page fault can be backed. An unresolved user-mode fault terminates the process with `SIGSEGV`; failure to prefault a user buffer returns `EFAULT`. There is no swap.

## Page tables and address spaces

`init_paging` creates the kernel page directory, enables paging and CR0.WP, and registers the vector 14 handler. CR0.WP makes supervisor writes honor read-only PTEs, which the page cache uses to detect its first write to a clean page.

An address space (`mm.c`) is a page directory with its regions and a count of the processes that use it. `fork` gives the child a copy-on-write copy; `vfork`, and `clone` with `CLONE_VM`, give it the parent's own address space and one more reference. `execve` builds a new one and drops its reference to the old, and the last reference frees the pages, the page tables, the directory and the regions. `mm_drop` loads the kernel directory first when the address space it frees is the one in CR3. A process record keeps the directory and its physical address beside the pointer, since `switch.s` reads them. The address space also keeps the dumpable flag of `prctl(2)`, as Linux keeps it, so every thread that shares it has one flag: a new address space and the image `execve` builds are dumpable unless the image runs with ids its caller lacks, `fork`'s copy takes the parent's flag, and a move of any sharer's effective ids clears it.

A process page directory initially copies the kernel directory's PDEs. The referenced kernel page tables remain shared, while a user mapping first copies or allocates the page table for that process. A context switch loads the process's directory into CR3. Kernel page tables needed by every process, including the page-cache window, must exist before the first directory is cloned.

User addresses run from `USER_ADDR_MIN` (`0x02000000`) through, but not including, `USER_ADDR_MAX` (`0xC0000000`). `map_mmio` maps device registers uncached into the dedicated kernel MMIO region at `0xF0000000` and returns the virtual address the driver must use. A region reaching the top of the address space is refused, its pages counted by division rather than by adding a page less one, and `premap_kernel_window` refuses a window past the top and counts its tables rather than walking to an end address that would wrap; `paging_hosttest` holds both, compiling `paging.c` with `RACH2_HOSTTEST`, which leaves out its control-register, flags and TLB instructions. Creation of a shared kernel PDE fails after the first process directory has been cloned.

## Virtual memory areas

Each PCB contains a `vm_space_t` whose VMA array is allocated from the heap. The array starts with 16 entries and doubles as it fills, up to 65536, a limit that serves the same purpose as Linux's `max_map_count`: a mapping that needs another VMA is refused. The array is kept sorted by address, a lookup is a binary search, and neighbours of the same type and protection merge; two that map a file merge only where its pages continue. A VMA that maps a file holds a reference to a `struct vm_file`, whose owner keeps the file open, and the page of the file at its start, which splits and trims carry on. The last reference to go does not release the file: it leaves it on a list that `vm_file_reap` empties, and `munmap`, `mmap`, `mremap` and `brk` call that at their end, once the regions they changed and the page tables agree, as does the last drop of an address space. A release may sleep closing the file, and a region still in the array during that sleep would be copied by a fork, or reached by a fault, after the file had gone. A VMA is a half-open, page-aligned range with `VM_PROT_READ`, `VM_PROT_WRITE`, and `VM_PROT_EXEC` bits and one of these types:

* `VM_CODE` and `VM_DATA` describe loaded ELF segments.
* `VM_HEAP` describes the non-empty part of the `brk` heap, one VMA or several when `mprotect` has divided it.
* `VM_STACK` starts with the pages the arguments and environment took, one at least, and may grow downward to `stack_limit`, which `execve` sets from the soft `RLIMIT_STACK` in force at the exec so that the whole stack is at most that size in whole pages, never below `VM_MMAP_BASE`, and never short of the pages the arguments took. The first image gets 8 MiB, the default.
* `VM_ANON` describes an anonymous `mmap2` allocation.
* `VM_FILE` describes a private mapping of a file.
* `VM_SHARED` describes a shared mapping: of a file in memory (tmpfs), or of shared anonymous memory. Its pages are the frames of the file's `struct shmem` (`shmem.c`) or of the anonymous memory's own, so every mapping of a page maps one frame. The pages end at `SHMEM_MAX_SIZE`, 1 GiB, the most a file in memory holds: a page at or past it, which a mapping reaches from a large offset or past 1 GiB of its own length, is never backed, and its fault is unresolved.

`execve` builds the new image in a new address space while the old one still runs. It loads ELF pages eagerly, a position-independent program at `ELF_ET_DYN_BASE` (`0x08000000`) and the interpreter a `PT_INTERP` segment names just below `VM_MMAP_BASE`, then creates one VMA per loadable segment of each with the segment's permissions. It records an empty heap at the program's end, maps the initial stack's top page at `0xBFFFF000` and as many pages below it as the arguments and environment take, and places anonymous mappings below the interpreter, under `VM_MMAP_BASE` (`0xB0000000`). The heap receives a VMA on its first non-empty growth. Only when all of it is built does the process switch to the new address space. `fork` copies the complete `vm_space_t`.

The syscall contracts are:

* `brk` (45) grows or shrinks the heap range. Growth adds a read-write `VM_HEAP` region above the old top, which merges with a read-write top piece, and reserves virtual addresses only; pages are allocated on first access. Shrinking removes the range above the new top and releases its present frames. A collision or out-of-range request returns the old break.
* `mmap2` (192) takes one of `MAP_SHARED`, `MAP_PRIVATE` and `MAP_SHARED_VALIDATE`, and maps private anonymous memory (`MAP_ANONYMOUS`, or `/dev/zero`, with `MAP_PRIVATE`), shared anonymous memory (either with `MAP_SHARED`), a private mapping of a file from the page offset in EBP, or a shared mapping of a tmpfs file (`mmap_backing`). Anonymous memory ignores the offset and has its pages from its own first; an offset whose last page would not fit in 32 bits is refused with `EOVERFLOW` whatever is mapped, as in Linux. The mapping holds its file through `filemap.c`, a copy of the descriptor with its open file description, so the descriptor may be closed after the call. A shared mapping of a file on a disk file system is served as a private one when it is read-only and refused with `ENODEV` when it may be written, since there is no write-back of mapped pages. A file on a device a user page fault cannot read is refused with `ENODEV` (`mmap_fault_readable`): the fault reads with interrupts off and outside any call, where the block layer polls a disk it can and stops the machine at any other, a loop device, which sleeps its caller, and a USB stick, which answers only through its interrupts. `MAP_FIXED` replaces what its range held; what is mapped is found and the entries the change needs are made room for before the old mapping goes, so a refusal leaves it; `MAP_FIXED_NOREPLACE` refuses a range in use with `EEXIST`. Otherwise a page-aligned hint whose range is free below the stack limit is used, and without one `vm_find_free` takes the highest free range below `VM_MMAP_BASE` and above the heap's top, so a range `munmap` freed is used again. What is mapped is found first, since finding it may sleep, and the range after (`mmap_place`), so that nothing sleeps between the checks on the range and the insertion: a thread that shares the address space cannot map the range in between.
* `munmap` (91) removes full VMAs, trims either end, or splits a VMA, then releases every present frame in the range. A never-faulted page has no frame to release.
* `mprotect` (125) requires a page-aligned address and a range that VMAs cover without a gap (`ENOMEM` otherwise). A region that may never be written has `VM_PROT_NOWRITE` beside its protection: a shared mapping of a file whose descriptor was not open for writing, and a shared mapping of a disk file, which is served as a private one. Write asked of a range that reaches such a region is `EACCES`, as Linux answers for a mapping without `VM_MAYWRITE`; the range is checked for both refusals before anything changes. The bit stays through the splits, merges, copies and moves that carry the rest of the protection. `vm_protect` splits the VMAs at the range's ends, sets the new protection and merges the pieces with matching neighbours; `paging_protect_range` then changes the resident pages. A page made inaccessible stays present with its frame, supervisor-only and marked `PTE_NONE`, so fork and teardown still own it. A page made writable gets the write bit only when this process alone holds its frame, and becomes copy-on-write otherwise; a page of a `VM_SHARED` region gets it in place, since its frame is shared on purpose.
* `mremap` (163) resizes a mapping whose old range lies in one VMA: a shrink cuts its end, a growth takes the free range after it, and with `MREMAP_MAYMOVE` the mapping moves to a free range, or with `MREMAP_FIXED` to the address given; `paging_move_range` moves its page-table entries, frames and flags as they are, and the new VMA maps the same pages of the same file. The two lengths are checked as they are given, before they are rounded up to pages (`remap_args_valid`): the old range must end inside user space and the new length fit in it, so neither range can wrap past the end of the address space. A growth of a file's mapping whose last page of the file would not fit in 32 bits is `EINVAL`.
* `madvise` (219) with `MADV_DONTNEED` or `MADV_FREE` releases the range's resident frames; a later access backs the page again as a first access does. Other advice is accepted and ignored, but `MADV_REMOVE` and `MADV_HWPOISON`.
* `msync` (144) checks its arguments and returns 0: a shared mapping maps the file's pages in memory, and nothing else is written back.

`madvise` and `msync` judge the length as it is given, before rounding it up to pages: a range that runs past user space is `EINVAL`, a length within a page of 4 GiB among them, which rounds up to 0 and would pass for an empty range.

VMA allocation does not reserve physical frames. If a later user fault cannot allocate a frame, the unresolved fault terminates that process with `SIGSEGV`. A kernel prefault reports failure to its caller instead.

## Page faults

The vector 14 handler reads CR2 and the x86 error code, then handles these cases in order:

1. A user-range fault for a live process calls `vm_resolve` for an existing VMA or legal stack growth.
2. A supervisor fault inside the backed page-cache window calls `pc_fault`.
3. Any remaining user-mode fault terminates the process with `SIGSEGV`; a real init death halts the kernel.
4. Any remaining supervisor fault panics the kernel.

`vm_resolve` checks the VMA permissions first, so a write to a present copy-on-write page reaches `cow_fault` only when its VMA is writable; a VMA `mprotect` made read-only keeps its shared pages read-only. A new heap, stack, or anonymous page receives a zeroed frame. A page of a VMA that maps a file privately is read from the file into a frame, which is mapped once it is full, writable when the VMA is; a store changes the frame and never the file. A page of a `VM_SHARED` VMA is the shared frame itself (`shared_fault`), mapped writable when the VMA is. The read may sleep. The file is held from before it, so a thread that unmaps the VMA meanwhile cannot free the file under the read, and the VMA is looked up again after it: a page backed meanwhile, or a VMA that changed in any way, its protection included, leaves the frame unused, and the resolution runs again against what is there now (`vm_resolve_once`). A resolution that succeeds has left the page present and allowing the access, and `paging_access`, which may sleep in one, looks the VMA and the page up again before it reads or writes the frame. A read-only VMA remains read-only in its PTE. A write prefault of a present COW page makes the page private before kernel code writes through the pointer. A present page that cannot satisfy the requested access is rejected instead of retrying the same instruction.

Stack growth extends the stack VMA down to the faulting page when the page is at or above `stack_limit`. Growth fails if it would cross another VMA. Pages between the old and new start remain unallocated until touched.

## Copy-on-write fork

`fork` maps each present user frame into the child. A page of a `VM_SHARED` region keeps its flags in both, writable ones included, so a store by either is seen by both. Other writable pages become read-only and receive `PTE_COW` in both processes; the frame reference count increases. Genuine read-only pages, and the `PTE_NONE` pages of an inaccessible range, keep their existing flags and are not marked COW.

On the first write, `cow_fault` allocates and copies a frame when another process still references the old one. If the writer is the sole owner, it removes `PTE_COW` and restores write permission without copying. Exit, `execve`, `munmap`, and failed-fork cleanup decrement the same reference counts.

## Checked user access

`copy_from_user`, `copy_to_user`, and `strncpy_from_user` reject addresses outside the user range. They call `vm_prefault_range` before dereferencing user memory, so a valid lazy page is created and an unmapped or read-only destination returns `-EFAULT` instead of faulting in supervisor mode. Bringing a page in may sleep, and a thread that shares the address space may unmap or protect a page brought in before, so once every page is in, the range is checked again with nothing that sleeps and brought in again when a page went: the answer holds until the caller sleeps. `strncpy_from_user` checks one page at a time because the terminating NUL may appear before the next unmapped page.

The kernel also prefaults ranges before passing user buffers to code that accesses them directly. A write prefault resolves COW before any part of the operation has modified the buffer.

## Page cache

The page cache maps a backing store into a supervisor-only window at `PCWIN_BASE` (`0xD0000000`). The window ends at the lowest 32-bit PCI memory BAR within it, or at the 512 MiB cap when no BAR intervenes. Its page tables are allocated before the first process starts.

The cache reserves no data frames at boot. A slot takes a frame from the top of the identity-mapped window when first filled and returns it through `pc_shrink` under memory pressure. The cache can therefore use up to 2048 frames, 8 MiB, but allocates only what it needs and memory permits; a compile on a KRFFS disk root needs the header page of every node in the ring resident beside its hot set, since a lookup walks the ring, and 1024 frames fell short of that once the manual's pages joined the ring. Each resident page has a hash entry, a clock-replacement state, and dirty, accessed, and pinned flags.

`pc_set_backing` installs page-sized read and write callbacks. `rach2.fswindow` uses a Multiboot module as the backing store. A disk root uses the selected ATA or AHCI block device through an MBR partition view.

On a miss, `pc_fault` reads one page into the slot's frame, allocating the frame first if the slot has none. A read maps it read-only. The first supervisor write faults again, marks the page dirty, and remaps it writable. A write miss performs the read and marks the new resident page dirty immediately. A user-mode access to the window is never served.

Clock eviction writes a dirty victim before reuse. Writeback pins the slot and frame until the backing writer returns; eviction, reclaim and competing writebacks skip it. Before writing, the cache maps the page read-only and clears dirty, so a concurrent store faults and marks it dirty again. A failed write or a store during writeback leaves the page dirty and resident. `pc_sync` attempts each resident page and returns the OR of `PC_SYNC_BUSY` for skipped busy slots and `PC_SYNC_FAILED` for failed writes, continuing with other slots. Zero means neither occurred. It leaves concurrent stores dirty for a later write. `fsync` and `fdatasync` call `pc_sync` for the whole cache and report `EIO` on either bit. `sync` retries while the busy bit is set, yielding and waiting with interrupts enabled between scans so an in-flight write can finish and a redirtied page can be written. The wait ends after 3000 kernel ticks (30 seconds) if slots remain busy. A write failure alone causes no wait; `sync` always returns zero, leaving failed pages dirty for a later call.

## Files

* `frame.*` sizes the managed physical-frame pool.
* `heap.*` implements the boot-time physical allocator.
* `modlayout.*` validates Multiboot module placement.
* `paging.*` owns page tables, frame references, faults, demand paging, COW, and kernel mappings.
* `vm.*` implements VMA lookup, insertion, removal, protection changes, the free-range search, overlap checks, and stack growth.
* `filemap.*` keeps the files and the shared anonymous memory that VMAs map.
* `shmem.*` keeps a file's pages in memory, for tmpfs and shared anonymous memory.
* `usercopy.*` implements the user-pointer boundary.
* `pagecache.*` implements the disk window, residency, eviction, and writeback.

## Verification

`make test` runs `vmprobe`, `forkro`, `cowregrant`, `usercopyfault`, and `musl/vmamusl` in its default guest suite. They cover lazy heap and anonymous pages, stack growth, read-only mappings across fork, COW re-grant, checked strings crossing into an unmapped page, 300 simultaneous mappings, and at least 8 MiB of live small allocations.

The boot self-tests exercise page-table isolation and force page-cache faults, eviction, cross-page writes, and writeback through a RAM backing store. `tests/run host` runs the pure VMA, memory-map, module-layout, and page-cache bookkeeping tests under AddressSanitizer and UndefinedBehaviorSanitizer.

`musl/mapmusl` checks private file mappings (the file's bytes, zeros past its end, stores that stay in the mapping, a mapping that outlives its descriptor, fork, an offset), shared anonymous memory and a shared `/dev/shm` file across fork and against `read`, `mremap` in place and moving, and `MADV_DONTNEED`.

The test image also contains `vmfault`, `vmro`, `winprobe`, `cowprobe`, `musl/mallocqsort`, and `musl/cowfork` for dedicated or manual runs. See the [guest test inventory](../../../tests/Readme.md) for their execution contract.
