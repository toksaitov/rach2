# ext2

`ext2.c` mounts an ext2 volume through the buffer cache, as `vfat` and `exfat` do, reads and writes it, and is what `rach2.root=ext2` boots from in milestone 42's later phases.

## What is read

Revision 0 and revision 1 superblocks. Block sizes 1024, 2048 and 4096; inode sizes 128 and 256. Of the feature words the driver accepts `filetype` as the one incompatible feature and `sparse_super` and `large_file` as the read-only-compatible ones, and it ignores every compatible feature except `dir_index`. An unknown incompatible feature refuses the mount and the record names the bit; an unknown read-only-compatible feature, `dir_index`, and a block size below 4096 each mount the volume read-only with the reason in the record. `dir_index` is read-only because a writer that kept only the linear entries would leave the index stale, and the images this project makes are formatted without it; a small block is read-only because `bcache_write` writes a whole 4 KiB buffer, and two dependent metadata blocks sharing one buffer could not be written in order. A volume whose valid bit is clear or whose error bit is set is checked before a writable mount. A consistent volume can mount writable; a structural fault makes it read-only, as described below.

Every field a lookup depends on is checked against the superblock and the group descriptors before it is used. The constructor requires the descriptor table to lie inside the volume, each group's two bitmaps and inode table to lie in that group, past its superblock copy and descriptors where it has them, apart from each other and past block zero, and each group's free counts to be no more than the group holds; a descriptor outside those bounds refuses the mount by name. A block pointer must lie inside the volume and outside the structural blocks: the boot block, every copy of the superblock and the descriptor table, each group's two bitmaps and its inode table; a pointer into one of those fails the read with `EIO` and a record naming the inode and the block. A directory entry must lie within its block and within the directory's size, with a `rec_len` of at least its eight-byte header and a multiple of four, its name within the entry, and its inode number within the count; a malformed entry fails the lookup or the listing with `EIO` and a record naming the directory and the offset. The group count must leave the descriptor table within the volume and must not overflow the table's own size; a count that fails either is refused by name.

A regular file is read through its direct, indirect, double-indirect and triple-indirect blocks, with a hole read as zeros. A file's size is 64 bits, read and written with its high word; a write or truncate past the largest file the volume's block pointers and its 32-bit `i_blocks` can address answers `EFBIG`, and the file is left as it is. A symbolic link shorter than sixty bytes is in the inode's pointer words, a longer one, up to a block less one byte, in its first block, and a slow link without that block answers `EIO`; `readlink` answers `ENAMETOOLONG` when the buffer cannot hold the target. A device node reports its numbers in `stat` from the first pointer word in the old encoding, or from the second when the first is zero, and cannot be opened, because devices live in `/dev`; that is what `MS_NODEV` means here, and it is enforced by never opening one. Owners, modes, link counts and the three timestamps are the inode's, in seconds, with the year 2038 limit the format has. The owner's high sixteen bits are read from the inode's second half.

`readdir` lists every entry with an inode, `.` and `..` included, with `is_dir` from the entry's type where `filetype` is on and from the inode otherwise. The directory cursor is a byte offset into the directory. `path` rebuilds a directory's path from its `..` entry and the parent's entry that names it, for a directory descriptor's `*at` calls. `statfs` reports the format's magic, the block size, the block count, the free count summed from the group descriptors at mount, and a name limit of 255.

## Writing

Regular-file overwrites of allocated blocks and appends at the visible end of file share a mount-wide write batch across calls. Reads, stat and later appends see accepted bytes, pointers, size and times immediately under the mount lock. The batch holds an internal reference to every pending inode, independent of open descriptions. No pending metadata enters the ordinary cache while the batch collects. Data images also remain private until draining, so cache eviction cannot publish a pending pointer or lose accepted bytes.

A writable mount reserves 1152 KiB for 256 data images and 32 metadata images, plus the records for those images and sixteen pending inodes. A generation accepts at most 1 MiB of user bytes; repeated overwrites count again. Admission reserves all records and reads existing bytes before changing a block. A refusal before acceptance leaves earlier pending calls intact. A full batch drains before admission continues. A call larger than the limits is split at block boundaries. An I/O failure after accepted pieces returns their byte count and records a delayed error; with no accepted bytes it returns the error.

Sparse writes, hole fills, attribute changes and namespace changes drain older pending writes first. Sparse writes and hole fills then drain after each accepted block. `fsync`, `sync`, the periodic sync and the final release of each open description drain the whole mount. Closing one descriptor shared by `dup` or `fork` does not release its description until the last descriptor reference goes. A failed release retains the pending inode and its complete images. Reads do not update access time.

The drain writes allocation bitmaps and descriptors, then data and zeroing, then indirect blocks from leaves to roots, then any large-file feature flag, then inode-table blocks. Each stage completes cache writeback and a device flush before the next begins. The disk drivers retain their write-through flushes. A table block shared by pending inodes is written once. Only eligible images enter the cache, so its ordinary eviction and contiguous-run writeback preserve the same dependencies. A failed stage is retried from retained images; a removed device is never retried. An internal committed size advances only after the inode stage completes.

The first delayed error remains on the mount until teardown, even after close, reopen or a successful retry. Every later `fsync` reports it. A failure freezes the generation and makes the mount read-only. `sync` returns current completion status internally so an unmount can finish after a successful retry; the syscall still ignores errors. A mount with a recorded error is never marked valid. Device removal records an error even when the ordinary cache has no dirty buffers, and teardown discards retained images without writing.

Every operation that changes the volume holds the mount's namespace lock for its whole length. Descriptor operations take that lock before their open-description lock, so independent appends choose EOF under the same lock. Loop attachment drains its backing file under the mount lock and rechecks its size and busy state before publication. Each subsequent loop write still syncs the backing file.

The promise is the one the format allows without a journal: at every stop between two completed sector writes, no data is lost or shared outside the range the interrupted operation was itself changing or removing, and `e2fsck` repairs the volume without discarding a reachable file's contents. It is not a promise that every stop is structurally clean; the stops below leave what `e2fsck` reports as a count, a block-map or a topology repair, and the interruption matrix in `tests/run host` allows exactly those kinds and no other.

* An inode is freed by writing it zeroed with its deletion time, then clearing its bit and its group's count; it is allocated by setting its bit and lowering the count, then writing it initialised, then naming it. A stop between the last two leaves an allocated inode with no name, an orphan.
* A block's bitmap bit and descriptor count become durable before any pointer names it. Data, including every unwritten byte of a fresh block, becomes durable before an indirect pointer or inode size exposes it. New pointer blocks begin as private zero images and are published from leaves to roots after their children. An inode publishes its pointers, block count, size and times together after these dependencies. Namespace operations still write metadata through. A free reverses the allocation order: it writes cleared pointers and the inode before the bitmaps and descriptors. No block is freed or reused while an older file-write generation remains pending. A stop before pointer publication can leave a lost block; a stop before the final inode can leave blocks past EOF. These require bitmap or block-map repair.
* An entry is added by writing the new entry into the slack behind an existing name, where the old record still covers it, and then shortening the old record to end where the new one begins; a stop between leaves the volume as it was. A directory grows by a block zeroed with one empty entry spanning it, allocated and chained with `i_blocks`, then covered by the size, then written with the entry.
* An entry is removed before the inode's link count is lowered, the first entry of a block by clearing its inode number and any other by merging it into its predecessor's record. The inode is freed, with its blocks, when the count reaches zero and nothing holds it; a held node keeps its inode and blocks until its last `put`, which is what makes an open unlinked file work, and a crash while it is held leaves an orphan.
* A truncation writes the smaller size first, zeroes the tail of the last block kept, then clears the pointers from the end, each written through before its block is freed, with `i_blocks` following; a stop between leaves blocks past the end. A growth writes the size over a hole.
* `mkdir` allocates the inode's bit, writes the new directory's block with `.` and `..`, then its inode with a link count of two and its size, then the parent's count, and the parent's entry last. `rmdir` is the reverse, on a directory with nothing but `.` and `..`, and refuses one a description or a working directory holds with `EBUSY`.
* `link` raises the count, then writes the name; a stop between is a count one too high. `symlink` writes a target shorter than sixty bytes into the inode's pointer words, a longer one into a block written before the inode, and the name last.
* `rename` of a file within a mount is a `link` followed by an `unlink`: the count is raised, the new entry written, the old entry removed, the count lowered, so the file has a name at every stop. A rename whose source and destination are one inode changes nothing. A rename onto an existing file raises the source's count, rewrites the destination entry to the source's inode, lowers the victim's count and frees it as an unlink does, then removes the old entry and lowers the source's count; the stop after the rewrite leaves the victim an orphan. A rename onto an existing empty directory is refused unless the source is a directory, and then the victim goes as `rmdir`'s does before the move. A directory may not be moved into itself or a descendant, which the walk from the destination's parent to the root decides before anything is written, with `EINVAL`. A directory's rename across parents writes the new entry, rewrites its `..`, raises the new parent's count, removes the old entry and lowers the old parent's count; the stops inside leave the directory with two names or with a `..` naming one parent while an entry names another, which `e2fsck` repairs as topology.

The superblock's free counts are summaries the group descriptors hold exactly, and they are written at `sync` and at unmount; changed descriptors become durable with their bitmaps at the allocation stage. Mounting for writing clears `s_state`'s valid bit with `bcache_write` before the mount is published, and `prepare_unmount` sets it again after everything has reached the disk and only when the error bit is clear. A mount that went read-only after a failed write keeps the volume invalid for the next mount's check. An abandoned prepared unmount clears the valid bit before the mount is reused.

## The check

A volume whose valid bit is clear was not unmounted, and one whose error bit is set was found wanting by an earlier mount. Either is checked before a writable mount is published; a mount asked for read-only, or one read-only for another reason, the block size, `dir_index` or an unknown feature, is not checked and writes nothing. The check runs under the walk lock and in the block bitmap the FAT drivers share, taken from the heap for the volume, one walk at a time, and keeps its own state in one record from the heap: a reached-inode set of one bit per inode, thirty-two directory levels, a table of 512 hard-linked files and one bitmap block. It seeds the bitmap with every structural block, the superblock and its copies, the descriptors and their copies, both bitmaps and the inode table of every group, and the blocks of the reserved inodes below `s_first_ino`, so that none can be claimed as data. It walks the tree from the root with the reached set, so that a hard link and `..` are revisits and not duplicates, and marks every block every reached inode names through every level of pointer. Then it scans the inodes the inode bitmap calls used that the walk did not reach: each is an orphan, its pointers validated and its blocks marked so that the allocator cannot give them away; one whose link count is zero is a deleted inode whose bit was not yet cleared, counted with the orphans because `e2fsck` is owed the bit, its pointers not read because they mean nothing, as `e2fsck` reads it. Then it compares the bitmaps with the marks and recounts each group's free blocks and inodes into its descriptor, because a crash leaves the counts stale.

The check repairs nothing but the free counts, which it recounts from the bitmaps and writes back. A used block the walk did not mark is lost, and an orphan is an orphan: both are counted, kept where they are, held out of the allocator by the bits they still have, and recorded as `ext2: check: N lost blocks, M orphan inodes, kept for e2fsck`; the volume mounts writable and the error bit is set in `s_state` so that it is not marked clean again before `e2fsck` has run, whatever unmounts it. A fault mounts the volume read-only, with the error bit set, the counts left as the disk had them, and the first fault recorded as `ext2: check: inode N: WHY`: a block out of range or claimed twice, an inode whose pointers do not match its size or its `i_blocks`, an inode that keeps blocks and should keep none, a directory with two parents, without `.` and `..` in their places, with a hole or a size that is not whole blocks, an entry of the wrong form or naming a free inode or an inode past the count, a link count that does not match the entries, a directory deeper than the levels, more hard-linked files than the table, a used block or a reached inode the bitmap calls free. A consistent volume whose valid bit was merely clear records `ext2: check: clean` and mounts as a clean one does. A volume whose bitmap or inode set the heap cannot supply mounts read-only when dirty and says which.

The stops the writer's order leaves are what the check's rules allow: a lost block, an orphan, and, read-only, a count behind what it counts, since an entry and its link count, and a file's pointers and its size and `i_blocks`, are separate writes, and a directory between its two parents in a move. `e2fsck -p` repairs the counts and the bitmaps without a question; an unattached inode with data it leaves to a person, which is `e2fsck -y` over SSH from recovery. That is a smaller check than FAT32's on purpose: ext2 has a real checker, it is ported and lives on the recovery partition, and a kernel that repaired what `e2fsck` repairs would be a second, worse `e2fsck`.

## The root

`rach2.root=ext2` scans the partitions in MBR order for the first whose superblock has the magic and a feature set this driver can mount at all, and mounts it as the root, entry zero of the mount table, through `vfs_init_root`, with `/dev` and `/proc` over it as always; the check decides whether that root is writable, and a later partition is never tried in its place. The window is claimed as `mount(2)` claims one, so the partition cannot be mounted twice. The block layer and the buffer cache are up before the root and the USB stack comes up after it, so a root on a stick is not found. `/proc/mounts` reports the root as `/dev/disk0pN / ext2 rw,relatime 0 0`, or `ro,relatime` when the check made it so. `init`, `login` and every program run from it through `execve`'s read path for a mount of another type, scripts included, and the kernel's own start of `init` reads the program the same way. An orderly stop unmounts the root as `mount(2)`'s mounts are unmounted: the buffers written and the valid bit set when the mount was writable, its error bit clear and those writes succeeded, recorded as `shutdown: root: unmounted`; otherwise the next mount checks it. A boot line that names the root and finds no ext2 partition, or a partition the driver refuses, leaves nothing mounted and halts as a missing KRFFS root does; the KRFFS module is not tried in its place, which is what lets a boot loader's trial of a candidate root fall back to the entry that came up.

A dirty root that fails its check mounts read-only with the error bit set, and what happens next is not promised by that root. The promise is made by recovery, a RAM root that needs nothing from the disk: it carries `e2fsck`, its `init` runs `e2fsck -p` on each of the four MBR partition nodes that has the ext2 magic before it starts anything else when its boot line has `rach2.fsck`, which the menu's repair entry puts there and the plain recovery entries do not, and the record of that run is in its boot log as `init: e2fsck: /dev/disk0pN: status S`. For that, the recovery build's partition nodes are writable, the one build where they are, under the authority that publishes `/dev/disk0` there; every other build answers a write with `EPERM`.

An inode is allocated in the parent's group when it has one free, else in the first group that has one. A block is allocated first-fit from the block after the last one given out, wrapping once through every group. For a file's write, `ENOSPC` is decided under the mount's lock before any bitmap is written, from the blocks the range lacks and the pointer blocks its highest index needs; a directory's growth is decided the same way before its block is allocated. A namespace operation allocates its inode before its entry, so one may write the inode bitmap and then meet `ENOSPC` at the entry, after which it frees what it took and restores the counts it raised. The root's reserved blocks are refused to a caller who is not root. The file-size limit is the smaller of the direct and three indirect pointer levels' reach and the capacity of the 32-bit `i_blocks` sector count, with space reserved for pointer blocks. For a writable volume, whose blocks are 4096 bytes, the limit is 2196875759616 bytes. A write or truncate beyond it returns `EFBIG`. A name of 256 bytes answers `ENAMETOOLONG`; a symbolic link's target may be up to 511 bytes.

## Symbolic links

The walker follows a symbolic link when it is not the last component. For the last component the operation decides, as on Linux: `open` follows unless `O_NOFOLLOW` is given, in which case a link answers `ELOOP`, or `O_CREAT|O_EXCL` is given, in which case a link, dangling or not, answers `EEXIST`; `stat`, `access`, `chdir`, `execve`, `truncate`, `chmod`, `chown` and `utimensat` without `AT_SYMLINK_NOFOLLOW` follow; `lstat`, `readlink`, `unlink`, `rename`, `link`, `symlink` and `rmdir` do not. A followed link's target replaces the component, an absolute target restarts at the root, and the walk continues from the directory the link was found in, with a bound of forty links along one path, after which `ELOOP`. `..` is physical, so `link/..` goes to the parent of the target, as it does on Linux, and `..` after a link to a file answers `ENOTDIR`. `symlink`, `symlinkat` and `readlinkat` are real syscalls, and `link` and `linkat` are real on ext2, with `EPERM` for a directory, `EXDEV` across mounts and `EROFS` on a read-only mount; on KRFFS and the synthetic types both answer `EPERM`. [vfs.Readme.md](vfs.Readme.md) has the resolver.

## Limits

| Limit | Value |
|-------|-------|
| Block sizes | 1024, 2048, 4096 read; 4096 written |
| Inode sizes | 128, 256 |
| Groups | as many as fit a descriptor table inside the volume |
| Largest file | what the block pointers and the 32-bit `i_blocks` address for the block size; a write or truncate past it answers `EFBIG` |
| Symbolic links along one path | 40 |
| A symbolic link's target | 511 bytes, the resolver's bound; the format allows a block less one |
| A followed target and the rest of its path | 511 bytes; `ENAMETOOLONG` past that |
| Name | 255 bytes, the format's and the kernel's |
| Timestamps | 32-bit seconds, until 2038 |
| Held nodes per mount | from the heap, without a fixed count; `ENOMEM` when it has no room |
| Mounts at once | from the heap, without a fixed count |
| The check's state | the block bitmap and the inode set from the heap, for the volume's counts; 32 directory levels; 512 hard-linked files. A dirty volume the heap cannot serve, or one past those two, mounts read-only and says which |

## What stays out

ext3's journal and ext4's extents, 64-bit block numbers, checksums, flexible groups and large inodes: refused or read-only by the feature rules, which is what the three feature words are for. Extended attributes and access lists: ignored on read. Quotas: no. `mknod`: no, devices live in `/dev`.

## Verification

`tests/run host` runs `ext2_hosttest`: the driver over the buffer cache over volumes the host's `mke2fs` made from a staged tree at 4 KiB blocks with 128- and 256-byte inodes, at 2 KiB, and at revision 0 without `filetype`, with `debugfs` adding device nodes in both encodings and a size past the kernel's offset; every file reads back against the tree and, on the profile volume, every node against `setidcheck`'s reader; a 1 KiB volume has a sparse file with a byte behind each pointer level and mounts read-only with the reason recorded; a `dir_index` volume and an unknown read-only feature mount read-only with the reason recorded, and a clear valid bit is not checked for a read-only mount; an unknown incompatible feature, no magic, a free count past the group and tables placed where a group's cannot be refuse the mount by name; a block past the volume, a block inside the descriptors, a block inside the inode table, an entry whose `rec_len` runs past its block, an entry past the directory's size, an entry naming an inode past the count and a slow link without its block fail by name; a slow link of 1021 bytes reads; a size of 4 GiB less one reads and one past it answers `EOVERFLOW`; and two hundred nodes are held at once, past the sixty-four the pool once had. The writer's rows run thirteen sequences on a fresh volume each, create and write, extension through the pointer levels, a write past the end, truncate, unlink, mkdir and rmdir, rename, rename over a file, a directory renamed across parents and over an empty one, link, symlink, an open unlinked file and three hundred files; each reads back through the driver, unmounts, is called clean by `e2fsck -fn`, is walked by the guard's reader, and reads back the same after a remount; `debugfs` lists what the driver wrote. The refusals decided before anything is written, a name of 256 bytes, a write past the offset and the reserve to a caller who is not root, leave the volume byte for byte as it was; a hundred nodes are made and held at once; the superblock's counts stay as they were through a sequence and are written at `sync`, and the valid bit is cleared by the mount and set by the unmount. The interruption matrix then stops every sequence after each of its block writes, on a volume whose free blocks hold junk (a block torn between its sectors is not a stop the matrix makes; that is a repair `e2fsck` makes), and judges the stop three ways: the volume mounts with the base files intact and the sequence's files reading only what was written or zeros, and a renamed or linked file reachable by a name at every stop past the operation's start; `e2fsck -fn` reports nothing but the count, block-map, orphan and topology repairs the order of writes lists; `e2fsck -fy` on a copy repairs it with the base files intact and the file's name kept; and the check, on a copy, mounts the stop writable or read-only on one of the counts the order leaves behind. A base file changed under a repaired copy fails the comparison. The dirty-volume rows mount a consistent volume whose valid bit is clear writable with `check: clean` and unmount it valid; recount free counts a fixture set wrong; keep a lost block and an orphan through a fill of the volume, with the error bit set and surviving a mount and an unmount, until `e2fsck -p` repairs the volume and it mounts without a check; and mount read-only by name, refusing a create with `EROFS` and setting the error bit on disk, an orphan whose block the bitmap calls free, a file pointing into the inode table, a reached inode whose bit is clear, a link count above its names, a directory count above its entries, a directory named twice, a size behind its pointers, an `i_blocks` behind its pointers and an entry of the wrong form; a read-only mount of a dirty volume writes nothing. `tests/run ext2` boots the harness kernel beside a fixture disk `tests/system/mkext2fixture.sh` wrote and runs `ext2probe`'s link rows on the mounted volume, then boots the ordinary kernel with `rach2.root=ext2` on a disk with the os-real system on an ext2 first partition and an empty ext2 second one: the root mounts writable before the USB stack starts and `/proc/mounts` names it, a write to a partition node answers `EPERM`, a file written and synced survives the machine being killed, the boot after records `check: clean` and unmounts the root at `poweroff` with the valid bit set, a lost block mounts writable with the error bit and `e2fsck -fn` still owed it, a reached inode whose bit is clear mounts the root read-only with the fault named, a recovery boot without `rach2.fsck` reaches its login with the disk byte for byte as it was, recovery's `init` under `rach2.fsck` runs `e2fsck -p` on both partitions with the statuses recorded and its partition nodes take a write, and the repaired root boots without a check ([tests/system/Readme.md](../../../tests/system/Readme.md)).
