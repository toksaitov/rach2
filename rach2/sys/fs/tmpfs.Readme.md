# tmpfs

`tmpfs.c` is a file system in memory, as Linux's tmpfs is: its files go when it is unmounted. It is the type `tmpfs` of `mount(2)`, which stands on no device, the permanent mount `/dev/shm`, and the mount the files of `memfd_create` are on.

## Nodes

tmpfs has every kind of node: regular files, directories, symbolic links, hard links, FIFOs, socket files and device nodes. A node is a record from the heap with its mode, its owner, its three times with nanoseconds, a device node's number, and a symbolic link's target; its inode number counts up from 1, the root's, and is not reused while the mount lasts. A node counts the holds of lookups, descriptions, working directories and mounts, and the names that name it, and is freed when both are gone, so a file unlinked while open stays readable until its last close. A directory holds its parent as well, from the name that makes it a subdirectory until it is freed, and a rename moves the hold to the new parent: a removed directory that a process still has keeps its removed parent, which its `..` lists and reaches, and the two go with the last hold. A directory's link count is two and one for each subdirectory, and its size is twenty bytes for each name and for `.` and `..`, as Linux reports.

A regular file's bytes are a `struct shmem` (`../mm/shmem.c`): a table of frames, one per page, a page made when it is first written or mapped, so a hole costs nothing. A shared mapping of the file maps those frames, and a truncation takes the pages past the new end out of every mapping before it frees them from the table, so a later touch of the mapping maps the page the file has then. A file is at most 1 GiB (`SHMEM_MAX_SIZE`), `EFBIG` past that, and a page the frame allocator cannot give fails a write with `ENOSPC`. There is no quota of its own: tmpfs files take the machine's memory, and `statfs` reports the frames in all and free as its blocks.

A directory lists `.`, `..`, then its names in the order they were made or renamed; a name removed during a listing moves the ones after it down. `rename` moves a name within the mount, replaces a file or an empty directory, and refuses a directory under itself with `EINVAL`. A device node does not open through tmpfs itself: `open(2)` opens the `/dev` device with its number, as it does on ext2.

## Mounts

`mount -t tmpfs SOURCE DIR`, with any source string, `none` or `tmpfs` by custom, makes an empty tmpfs whose root has mode 1777, or the octal mode an option `mode=` gives; the other options Linux's tmpfs takes, `size=` among them, are accepted and change nothing. Nothing is claimed and nothing is written at unmount, which frees every node.

`/dev/shm` is a tmpfs the kernel mounts at boot, with `nosuid` and `nodev` as Linux systems mount it, where GNU libc's `shm_open` and `sem_open` make their files. `/dev` is devfs, a synthetic type that is handed the rest of a path in one call and has no directory node a mount could cover, so `/dev/shm` is a nameless mount standing in `/dev`'s root directory, found by its name as `/dev` and `/proc` are in the root's: the resolver enters it before devfs sees the rest of the path, and the `/dev` listing shows it as a directory. It is permanent: `umount2` refuses it with `EBUSY` ([vfs.Readme.md](vfs.Readme.md)).

## memfd and seals

`memfd_create(2)` makes a regular file on a tmpfs the kernel mounts at boot with no parent and no path, which nothing reaches by name and `/proc/mounts` does not list (`vfs_memfd_mount`). The file is a node that no directory names (`tmpfs_memfd`), made with one hold that the new descriptor's description takes, so it goes with the description's last close as an unlinked file does. It keeps the name it was made with, and `/proc/PID/fd` shows the descriptor as `/memfd:NAME (deleted)`, as Linux does.

A regular file has seals, fcntl's `F_SEAL_` bits (`TMPFS_SEAL_` in `tmpfs.h`): `F_SEAL_SHRINK` refuses a smaller size and `F_SEAL_GROW` a larger one, to a truncation and to `setattr`; `F_SEAL_GROW` refuses a write past the end whole; `F_SEAL_WRITE` and `F_SEAL_FUTURE_WRITE` refuse every write; `F_SEAL_EXEC` refuses a change of the execute bits, and a file that has execute bits when it is sealed so is sealed against writing too; `F_SEAL_SEAL` refuses more seals. Seals are only added. Every file starts with `F_SEAL_SEAL` alone, as Linux's tmpfs files do, but a memfd made with `MFD_ALLOW_SEALING`, which starts with none, and one made with `MFD_NOEXEC_SEAL`, which starts with `F_SEAL_EXEC`. The seals do not reach a shared mapping: `mmap(2)` does not refuse a writable shared mapping of a file sealed against writing, and `F_SEAL_WRITE` is not refused while one exists, as it is on Linux; the mapping code can read the seals with `tmpfs_seals`.

## Verification

`tests/host/tmpfs_hosttest.c` runs the type over a pool of host pages: a file's bytes across a hole, a cut and a growth; directory link counts; hard links; rename's replacements and refusals; symbolic links, FIFOs and device nodes with their numbers; the listing's order and types; a directory's path; a node held after its last name; a removed directory held after its parent is removed too, whose `..` still lists and reaches the parent; a shared mapping's reference to a page, and a truncation taking the pages it frees out of the mappings first; a memfd's node, its name and each seal's refusals; and every frame back after the unmount. `tests/musl/tmpfsmusl.c`, in the default suite, mounts one on Rach2 and checks its files, directories, links and statfs, its lines in `/proc/mounts` and `/proc/filesystems`, the unmount refused while a file is open and done after, and `/dev/shm`: listed in `/dev`, a directory of mode 1777 where a file is made, written, read and removed, whose device nodes do not open, and which cannot be unmounted. `tests/musl/memfdmusl.c` makes memfds with each flag and adds each seal in turn, checking the descriptor, the mode, the name under `/proc/self/fd` and what each seal refuses.
