# Synthetic file systems

The kernel makes `/dev`, `/proc` and `/sys` from its own tables each time a program opens, stats or lists them, and stores none of the three. `/dev` gives the devices, `/proc` the processes and the system's counters as text, and `/sys` the device records that Linux's tools read. They exist so that musl, BusyBox, util-linux and the GNU programs find the files they open on Linux, at the same paths and in the same formats. [synthfs.c](synthfs.c) turns a path into a kind and its coordinates, [devfs.c](devfs.c) implements the devices, [procfs.c](procfs.c) writes the text of `/proc` and `/sys`, and the system-call layer, [../syscall_fs.c](../syscall_fs.c), opens, stats and lists all three.

## Interfaces

`install_permanent` in [vfs.c](vfs.c) mounts the three at boot as permanent entries of the mount table; the table in [vfs.Readme.md](vfs.Readme.md) gives their slots and flags. Each has a device number of its own:

| Path | Type | `st_dev` |
| --- | --- | --- |
| `/dev` | `devfs` | 5 (`DEVFS_FSID`) |
| `/proc` | `proc` | 6 (`PROCFS_FSID`) |
| `/sys` | `sysfs` | 7 (`SYSFS_FSID`) |

A namespace file reached through `/proc/PID/ns` has device 4 (`NSFS_DEV`), as on Linux. `statfs` gives each mount Linux's magic number for its type ([statfs(2)](../../../man/man2/statfs.2)).

The manual pages give what each file contains and what each call on it returns:

* [null(4)](../../../man/man4/null.4) (`null`, `zero`, `full`), [random(4)](../../../man/man4/random.4) (`random`, `urandom`) and [mem(4)](../../../man/man4/mem.4).
* [console(4)](../../../man/man4/console.4) (`console`, `tty`, `ptmx`, `pts/N`) and [bootlog(4)](../../../man/man4/bootlog.4) (`bootlog`, `screenlog`, `framefail`).
* [disk(4)](../../../man/man4/disk.4) (`diskN`, `diskNpM`, `bootpart`, `grubcore`), [loop(4)](../../../man/man4/loop.4) (`loop0` to `loop3`, `loop-control`) and [rtc(4)](../../../man/man4/rtc.4) (`rtc0`); their block requests are in [ioctl(2)](../../../man/man2/ioctl.2).
* [busybox-sysklogd(8)](../../../man/man8/busybox-sysklogd.8): `/dev/log`, a link to `/var/run/log` (`SYNTH_DEV_LOG_TARGET`), where `syslogd` makes its socket.
* [proc(5)](../../../man/man5/proc.5): every file of `/proc`, and `/dev/fd`, `/dev/fd/N`, `/dev/stdin`, `/dev/stdout` and `/dev/stderr`, which are the caller's `/proc/self/fd` and its links.
* [sysfs(5)](../../../man/man5/sysfs.5): every file of `/sys`.

Other parts of the kernel call devfs:

* `disk_register` (`../block/disk.c`) makes a new disk record's nodes with `devfs_disk_nodes`, and each scan of its table renames them (`devfs_disk_part_nodes`). `devfs_disk_publish` publishes the whole-disk window of every registered disk at boot (`publish_disks` in `../../kernel.c`) and of a stick when it arrives (`../block/usbdisk.c`).
* `discover_boot_devices` in `kernel.c` publishes `/dev/bootpart` and `/dev/grubcore`. The disk root's mount withdraws `/dev/bootpart` when the root is on that partition, and the debug shell's `ahci` command withdraws every window before it probes the controller again.
* `mount(2)` (`vfs_do_mount` in `vfs.c`) and the kernel's ext2 root turn a `/dev` path into a sector range with `devfs_window_of` and claim it with `devfs_claim`.
* An open of a device node on a disk file system opens the devfs device of the same kind and number (`open_device` in `syscall_fs.c`, `devfs_name_of`), and fails with `ENXIO` when devfs has none.

## Design

### Classification

`synth_classify` in `synthfs.c` takes a path below the root directory, without its leading slash, and fills a `struct vpath` (`synthfs.h`): a `kind`, one of `enum vnode_kind`, and the coordinates that kind uses, such as a device's leaf, a process (`SYNTH_PID_SELF`, -1, for `self`), a descriptor, or a `/sys` node and its device. `VNODE_KRFFS` means the path is not synthetic; `VNODE_ENOENT` and `VNODE_ENOTDIR` are the two misses.

The classifier reads the characters of the path and no kernel state, so it compiles hosted as well, and `tests/host/synthfs_hosttest.c` runs it under the sanitizers. Whether a device, process, descriptor or PCI function exists is checked afterwards by the caller: a two-component `/dev` path other than `pts`, `fd`, a standard stream or `log` is `VNODE_DEV` whatever its leaf, and devfs looks the leaf up. A path is split into at most `SYNTH_MAXC` + 1 = 8 components, one more than the deepest path any rule accepts, `/sys/class/rtc/rtc0/device/power/wakeup`, so a deeper path misses instead of being taken for a shorter one.

The names are tables in `synthfs.c`: the files of a process (`synth_pid_file`, 15 besides `stat`, `cmdline`, `exe`, `cwd` and `root`), the global files of `/proc` (`synth_global_file`), the files of `/proc/net`, `/proc/sysvipc` and `/proc/PID/ns`, the attribute files of each `/sys` directory (`sysfs_attr`), and `/proc/sys`, the 32 entries of `sysents`. Entry 0 is `/proc/sys` itself, and every other entry has its directory's index and, for a file, its text. New entries go at the end, so that `SYNTH_SYS_HOSTNAME` (11), `SYNTH_SYS_DOMAINNAME` (12) and `SYNTH_SYS_IP_FORWARD` (22) keep their values.

A `/sys` device is classified by its name as a process is by its digits. `sys_pci_key` turns `0000:BB:DD.F` into `BB << 8 | DD << 3 | F`, below 2^16. `sys_usb_key` turns `B-P.P...` into the controller less 1 in bits 28 and 29, the root port in bits 20 to 27 and up to five hub ports in four bits each, at least 2^20, so no USB key equals a PCI one. Each directory of `/sys` has a node number, `SYSFS_ROOT` (0) to `SYSFS_BLOCK_LOOP` (32); a keyed node (`SYSFS_KEYED`: a PCI function, a USB device, a network interface, a processor, a disk node) exists only while its device does.

### Routing

The three mounts cover no node of the root file system. The resolver enters each by its name in the root directory and gives the rest of the path, in one call, to the type's `lookup_rest` (`devfs_rest`, `procfs_rest`, `sysfs_rest` in `vfs.c`). `synth_rest` resolves `.` and `..` lexically, since the namespace is a table of names and not a tree of nodes, puts the mount's name in front, and classifies the result, which must be shorter than 256 bytes (`ENAMETOOLONG`). A `..` above the mount returns `VFS_CLIMB`, and the resolver goes on above it. The nameless mounts in `/dev`, `shm` and `mqueue`, are entered by the resolver's ordinary step before devfs is given the path (`named_in_rest`); `synth_rest` returns `VFS_ROOT` for such a name met at the mount's root later in a path, as in `/dev/pts/../shm`.

A resolved node is a `struct synth_node`, the `vpath` and a reference count, from the heap (`ENOMEM` when it has no room), freed when its last holder puts it: it lasts one call, except a mount's root, which lasts as long as the mount. `synth_getattr` gives the resolver only what a walk needs: a directory, of mode 0755 in `/dev` and 0555 in `/proc` and `/sys`; a link (`exe`, `cwd`, `root` and `/dev/log`); or a file. `/proc/self` and the device links of `/sys` are classified, not resolved, so to the resolver each is the directory it leads to, while `lstat` and `readlink` report a link. The descriptor and namespace links of `/proc/PID` are files to the resolver, and `stat` and `open` follow them themselves. `/proc/PID/exe` is followed to the program's file and not to a path: `walk_exe` goes on from the mount and node the address space keeps (`procfs_exe_file`), so the link reaches the program after a rename and after its name is gone. `cwd`, `root` and `/dev/log` are followed by their text (`synth_readlink`).

The system-call layer reads the classification back (`vfs_synth_vpath`) and does the rest. A stat that follows `/proc/PID/fd/N` reports the open object's attributes or the error from its file system's attribute read. A synthetic type has no create, remove, rename or write operation, so the calls that need one fail with `EROFS`, after `EEXIST` for a name that exists (`synth_name_exists`), in Linux's order. `chmod` and `chown` of a pty slave store its mode and owner on the pty (`chown_synth`); every other node is root's with a fixed mode, so root's `chmod` succeeds and changes nothing, and `chown` succeeds only for an owner and group of 0 or -1.

### Descriptors

`synth_open` in `syscall_fs.c` makes a descriptor of the kind's own sort:

* A device: `devfs_open` binds the registry entry's `file_ops` to an `FD_TYPE_DEVICE` descriptor whose `dev` points at the entry, so the generic read, write, poll, ioctl and close dispatch through the table and no device code is in the system-call layer. `console`, and `tty` when it is the console, give an `FD_TYPE_CONSOLE` descriptor; the pty ends come from `../tty/pty.c`.
* A directory: an `FD_TYPE_SYNTH_DIR` descriptor with a `struct synth_dir` from the heap, freed at the last close: the directory's kind, its process as the caller's PID namespace numbers it, and a thread under `task`, or for `/proc/sys` its entry and for `/sys` its node and key. `synth_dir_path` makes the path from the record for the `*at` calls, `fchdir` and the `/proc/PID/fd` link. A working directory in a synthetic namespace is kept as its canonical path, with `self` replaced by the caller's number.
* A file of `/proc` or `/sys`: an `FD_TYPE_PROC` descriptor with a `struct procfs_file` (below).
* `/proc/PID/fd/N`: a file or directory of a mounted type is opened again by its node, with an open's checks (`proc_fd_reopen`); anything else shares the descriptor's own description, as `dup` does (`proc_fd_share`). `/proc/PID/ns/KIND` gives a descriptor on the namespace (`procfs_open_ns`).
* `O_PATH`: `synth_open_path` opens nothing. A directory gives an `FD_TYPE_SYNTH_DIR` descriptor with `FD_FLAG_PATH`, and anything else an `FD_TYPE_SYNTH_PATH` descriptor with a copy of the `vpath` for `fstat` and `fstatfs`, so no device is opened and no text is made.

`synth_stat` makes every `stat` answer from the classification: the namespace's device, a fixed inode, a block size of 4096, a link count of 1 except for a task directory, and for every time the moment the clock was read at boot (`rtc_boot_time`), or 0 when it was not read. The times are fixed so that `make` never finds a synthetic file changed; a pty slave has its own access and modification times.

### devfs

`dev_table` in `devfs.c` is the registry: 20 entries, each a leaf name, a major and a minor number, a permission mode, whether a seek goes to offset 0, and the `file_ops` an open binds. Every entry is root's, and `synth_open` checks the access asked for against its mode as for a file (`cred_access_bits`). The memory devices, the terminals and the loop devices have Linux's majors; the others use 240 and 254, which Linux reserves for local and experimental use.

A disk node is a `struct disk_node` whose first member is a `devfs_entry`, so a pointer to the entry is a pointer to the node; `disk_node_of` tells a node from a fixed entry by its operations, `diskwin_ops`. `devfs_disk_nodes` takes 16 of the 128 records (8 disks, `DISK_MAX`, of `DISK_PARTS` + 1 windows) the first time a disk record is registered, one for the whole disk and 15 for partitions, and a released record keeps them. `devfs_disk_part_nodes` names the partition nodes after each scan of the table, from the numbers of its entries.

`bootpart` and `grubcore` exist while their windows are published, and a disk node while its disk is present and its window is published; the loop nodes are always there. Lookup (`devfs_find`), `stat`, `open` and the listing (`devfs_dirent`) apply the same test, so a device is listed exactly when it opens. The listing passes over an absent entry and goes on, since a machine can have a later entry without an earlier one, as the metal kernel has `disk0` and no `bootpart`.

Inodes do not depend on what is present: `/dev` is 2, entry `i` of the table is 16 + `i`, and the disk nodes follow the table in the order they were made; `/dev/pts` is 3, `/dev/log` 4, and pty slave N is 0x1000 + N. `ttyname` compares `st_dev` and `st_ino`, so `stat` of the path, `fstat` of a descriptor and the listing must agree. Disk and loop nodes are `S_IFBLK` and every other device `S_IFCHR` (`devfs_type_bits`), since `blkid`, `findfs` and `mount LABEL=` look only at block devices.

`devfs_open` fails `O_CREAT|O_EXCL` with `EEXIST` before it allocates a descriptor or a pty pair, and `O_DIRECTORY` with `ENOTDIR`. `ptmx` goes to `pty_open_master`. `tty` is the console when the caller is in the console's session, else the pty slave of the caller's session (`pty_session_slave`), else `ENXIO`; a job-control shell on a pty would otherwise get the console, never find itself in the foreground, and stop on `SIGTTIN`.

`sys_lseek` in `syscall_fs.c` seeks a device by what it is. The raw windows, `/dev/mem` and the loop nodes (`devfs_fd_is_raw`) seek the description's 64-bit `raw_offset` within the size `devfs_fd_raw_size` reports; the boot log seeks the ordinary offset against the ring's length (`seek_bootlog`); `null`, `zero` and `full` go to offset 0; any other device fails with `ESPIPE`. A read or write of a device whose transfer moves the offset, a raw window, `/dev/mem`, a loop node, the boot log or the screen log (`devfs_fd_moves_offset`), locks the open file description for its length (`ops_offset_held`). The transfer may sleep, in a disk request or in a fault on the caller's buffer, before it moves the offset, and a seek or a second transfer through a description it shares must wait or be lost. `pread64` and `pwrite64` lock nothing, since they work on a copy.

`/dev/mem` (`dev_mem_rw`) moves at most a page at a time through a 256-byte buffer on the stack, so the frame's temporary mapping (`kmap_temp`) is never kept over a copy to or from the caller, which may fault. `/dev/bootlog` reads the kernel log's 16 KiB ring (`KLOG_RING_SIZE`) through `klog_read`. `/dev/rtc0` attaches the clock's alarm interrupt the first time it is used (`rtc_irq_setup`); the handler counts the alarm, wakes the readers and ends a suspend to idle (`suspend_wake`), and its wake alarm is the one `/sys/class/rtc/rtc0/wakealarm` reads and sets (`devfs_rtc_set_wakealarm`).

### Raw disk windows

A window is a `struct disk_window` (`../block/disk.h`): a partition view (`block_partition_t`) cut from a backing device, and whether it is published. A disk record has `whole`, for `/dev/diskN`, and `views`, one for each partition; devfs has two windows of its own, `bootpart` and `grubcore`. Boot-device discovery chooses the sectors of the boot windows ([../block/Readme.md](../block/Readme.md)), and `devfs_bootpart_publish` adds one check: it publishes no partition of 2 GiB or more, so that the 32-bit `lseek` reaches every byte. A descriptor stays bound to its window when the window is withdrawn: a read of a disk node then fails with `EIO`, and a transfer of a boot window with `ENXIO`, until the window is published again.

There are three transfer paths. `raw_window_read` and `raw_window_write` move whole sectors at whole-sector offsets, for the boot windows' reads and every raw write. `raw_window_read_bytes` reads a disk node at any byte range, by reading the covering sectors and copying out the bytes asked for, since `blkid` reads a superblock's structure at whatever offset it has. `loop_node_transfer` moves whole sectors of a loop node. All three call `block_request` with a kernel buffer and never with a user pointer, since AHCI and NVMe give the controller the buffer's physical address.

`raw_batch_take` gives a transfer pages of its own from the heap, the least of the call, the device's largest request (`block_max_sectors`) and `DEVFS_RAW_BATCH_SECTORS`, 2048 sectors (1 MiB), while fewer than `RAW_BATCH_POOL` (8) are out, so that transfers on two disks each sleep on their own device. When the heap has no pages, or eight are out, the transfer waits its turn for the static buffer of 64 sectors in `.bss` (`DEVFS_RAW_BATCH_STATIC_SECTORS`), whose virtual address is its physical one. The batch makes a whole-disk write finishable: one sector a call would make a 500 MiB write a million driver calls and as many cache flushes. `raw_calls` counts the driver calls, and `/proc/disk` reports it beside the batch size, since a transfer returns the same bytes however many calls it took.

A write is judged whole before its first sector is sent: one that starts at or crosses the end writes nothing and fails with `ENOSPC`. The caller's privilege is checked at each write and not taken from the open, since a process can open the device while privileged and then drop privilege. A short write counts only the batches that completed; the batch that failed may have reached the disk in part, since the block interface reports a command's success and not its progress, and nothing after it was tried. Whether a kernel writes disk nodes is fixed when it is built: `dev_disk_write` has its body only under `-DRACH2_RECOVERY` and fails with `EPERM` otherwise, and `tools/inspect/check_recovery.sh` reads from the kernel's banner which one it has. The boot windows take root's writes in every build, and the metal kernel's driver policy stops them below devfs ([../block/Readme.md](../block/Readme.md)).

Two writers over one range at once would each write their whole length, each report success, and leave neither image on the disk, so each disk has one writer. A write-capable open of a window `raw_write_window` counts, the whole disk and the two boot windows in every build and a partition in the recovery build, records its range in the disk's `writer_held`, `writer_first` and `writer_last`, and a second such open on that disk fails with `EBUSY` until the first description is closed (`raw_close`). The windows are one disk under several names, so they share the reservation; readers are not counted. `/dev/grubcore` has one open description at a time, readers included (`grubcore_held`): replacing the BIOS core is a read of the tail in use, a write of the other, a read back and a rewrite of the selector, and two of those at once can leave the selector pointing at one image with the other's length, which does not boot. The flag clears at the last close, so a tool that dies does not leave the device locked.

The claim table, `claims` in `devfs.c`, has the sector ranges of the mounted volumes, by the rules of [vfs.Readme.md](vfs.Readme.md). `devfs_window_of` gives a source path's view, backing device and range; a loop device has no backing, since a file has no sectors on a disk. `devfs_claim` takes a range. `devfs_disk_claimed` makes `BLKRRPART` (`disk_rescan`) fail on a disk with a mount, and `devfs_window_alias` makes `/proc/diskstats` count the kernel's own view of an ext2 boot root as the partition node's.

### procfs

`procfs_open` writes a file's whole text when it is opened, into a `struct procfs_text`: a heap buffer of 256 bytes (`PROCFS_TEXT_FIRST`) that doubles when an append does not fit. The `ap_*` functions format the numbers, since the kernel has no `snprintf`, and 64-bit numbers go through `diskinfo_u64_dec`, since the i686 kernel has no 64-bit division. A text has every row there is, every mount, connection and vector. When the heap cannot grow the buffer, the text is dropped, the open fails with `ENOMEM`, and the kernel logs `procfs: NAME: no memory for the text`; no text is served short.

The text is kept in a `struct procfs_file`, which an `FD_TYPE_PROC` descriptor's `priv` points at, with its origin: the process, the kind of file, the thread's process for a path under `task`, and for `/sys` the node and attribute as `node << 8 | attribute`. `fstat` (`procfs_fd_ino`), `fstatfs` (`procfs_fd_is_sys`), the owner (`procfs_fd_owner`) and the `/proc/PID/fd` link (`procfs_readlink_fd`) come from the origin, so a descriptor reports what its path did without the text being made again. A read copies from the text at the description's offset. `dup` and `fork` share the description and with it the text, which is freed at the description's last close, so a process's file stays readable after the process is gone. Every read and write of a `/proc` or `/sys` file locks the description, as a device's does.

`/proc/disk` alone has a fixed size, `PROCFS_MAX_DISK`: `DISKINFO_RECORD_BYTES` (1024) for the first record and `DISKINFO_DISKS_BYTES` for 8 disks of 15 partitions (`DISK_MAX`, `PART_MAX`), 8 x (96 + 15 x 112), 15232 bytes in all. `diskinfo_format` cuts a text at the size it is given without saying so, so a text that reaches 15231 bytes fails with `EOVERFLOW`, and the kernel logs it. The file is made from the record taken at boot, and opening it sends no command to a disk. `/proc/cpuinfo` reserves `CPUINFO_TEXT_MAX`, 2048 bytes, for each processor online, and `cpuinfo_text` (`cpuinfo.h`, `../arch/x86/cpuinfo.c`) writes it.

Some descriptors keep no text and read the kernel's value at each read, through operations of their own: `/proc/PID/oom_score_adj` and `/proc/PID/mem` always, and, when opened for writing, a user namespace's `uid_map`, `gid_map` and `setgroups`, the three writable files of `/proc/sys` (`kernel/hostname`, `kernel/domainname`, `net/ipv4/ip_forward`) and the two of `/sys` (`class/rtc/rtc0/wakealarm`, `power/state`). A `/proc/PID/mem` descriptor takes `mm_hold` on the record of the address space its open allowed, and keeps none of its memory. A read or write takes a user's count of the address space (`mm_get_live`) only while something still runs in it, and returns 0 after; a program the process executes later is out of reach of a descriptor opened before, and an ended process's pages are freed at its end.

A process number in a path is one of the caller's PID namespace (`procfs_resolve_pid`, through `pid_named`), and `self` is the calling thread's process. A path under `/proc/PID/task/TID` needs both numbers: `procfs_resolve_id` accepts the thread only when it is one of the process's threads and not a zombie other than the leader. `procfs_may_read` is the test for reading a process's memory, descriptors and links; an unprivileged open of another process's `mem` also needs that process to be dumpable. `stat` gives `/proc/PID` and its files the process's effective user and group while its address space is dumpable, and root otherwise (`procfs_oom_owner`, `synth_pid_owner`).

Each global file of `/proc` has a fixed inode (`PROCFS_INO_*`: 0x100 to 0x11F, the files of `/proc/net` from 0x120 and the `/proc/sys` entries from 0x140), so `stat` and `fstat` agree and no two files share one. `procfs_mount_dev` gives the device number that `stat` reports for the files of each mount, which `/proc/PID/mountinfo` prints: 0 for a KRFFS root, the numbers of the `/dev` node a disk or loop mount was made from, a synthetic type's own number, and 16 plus the mount's slot for any other.

### Listings

`synth_getdents` in `syscall_fs.c` writes `linux_dirent64` records from `synth_dirent_at`. The description's offset is the index of the next entry; `.` and `..` are entries 0 and 1, both of inode 1. Each call reads the kernel's tables as they are then, from the saved index. `/proc` lists its 25 fixed entries and then each process once, by its leader, as the reader's PID namespace numbers it, without the idle process (`procfs_nth_pid`). `/dev` lists the nameless mounts in it (`shm`, `mqueue`), then `log`, then `fd`, `stdin`, `stdout` and `stderr`, then the devices present. `lseek` on a synthetic directory takes any index up to 0x7FFFFFFF, and on a `/proc` or `/sys` file only `SEEK_SET` and `SEEK_CUR`, since a text has no size to seek from (`seek_listing`).

### sysfs

`/sys` keeps no table of its own: `synthfs.c` classifies its paths, `procfs.c` writes its files from the kernel's device tables, and `syscall_fs.c` lists it (`synth_sys_dirent`). Every `stat`, open and listing of a keyed directory checks that its device is still there (`sysfs_device_exists`): a PCI function by its vendor register, and a function other than 0 also by the multifunction bit of function 0; a USB device by the USB core's table (`usb_core_row`); a network interface by the interface table; a processor by `cpu_table`; and a disk node by devfs's table (`devfs_disk_row`). `/sys/block` and `/sys/dev/block` come from that table, the disk nodes first and then each loop device with a file attached, as a disk with no partitions.

The links, `/sys/bus/pci/devices/NAME`, `/sys/bus/usb/devices/NAME`, `/sys/class/net/IF/device` and `/sys/dev/block/MAJOR:MINOR`, are classified as the directories they lead to; `lstat` reports mode 0120777 and `readlink` a relative target (`synth_sys_link`). An attribute file is a snapshot, as a `/proc` file is, written by `procfs_gen_netattr`, `procfs_gen_sysattr`, `procfs_gen_blockattr` or `procfs_gen_uevent`, and reports a size of 4096, as Linux's do. `sysfs_ino` makes inodes from the node, the key and the attribute's place. The two writable files take a privileged caller's write: `wakealarm` sets the alarm of `/dev/rtc0`, and `power/state` calls `suspend_to_idle` (`../proc/suspend.c`).

## Limits

* The namespaces are fixed. Nothing in them can be created, removed, renamed or given new times (`EROFS`), used as a mount point (`EINVAL`, `target_check` in `vfs.c`) or executed (`EACCES`, `syscall_proc.c`). `/dev/shm` and `/dev/mqueue` are separate mounts, entered by name from `/dev` ([tmpfs.Readme.md](tmpfs.Readme.md), [../ipc/Readme.md](../ipc/Readme.md)).
* No device node can be made in `/dev`. A device node on a disk file system opens the devfs device with its number, and a number devfs does not have fails with `ENXIO`.
* A path does not go on through a link of `/proc`: `/proc/PID/cwd/NAME`, `/proc/PID/root/NAME` and `/proc/PID/fd/N/NAME` fail with `ENOENT`, and `/dev/fd/N/NAME` with `ENOTDIR`, where Linux goes on in the directory the link reaches. The links are followed only as the last component of a path.
* `/dev/pts` opens and lists, but the listing of `/dev` does not show it.
* A listing of the root directory shows `dev`, `proc` and `sys` only where the root file system has directories of those names.
* Every entry of one `/proc/PID`, the directory, its files and its links, reports the one inode 0x200 + (PID & 0xFFFF), so a program that tells files apart by inode takes them for one file.
* A `/proc` file reports a size of 0, and a `/sys` attribute 4096, whatever the length of its text.
* `/proc/PID/mounts` and `/proc/PID/mountinfo` list the mounts visible in the reader's mount namespace, not in that of process PID.
* `/proc/filesystems` lists `devfs` and `proc` and not `sysfs`.
* A listing is consistent only within one `getdents64` call.
* Disk nodes exist for at most 8 disks of 15 partitions each.
* A USB device on a fifth controller, on a root port past 255, behind more than five hubs or on a hub port past 15 has no directory in `/sys` (`sys_usb_key`).
* A path below a synthetic mount has at most 7 components and, with the mount's name, fewer than 256 bytes.
* The framebuffer and the mouse are `/fb` and `/mouse` at the root, outside devfs.

## Tests

* `tests/run default` (core tier) boots every guest probe on the test image. `tests/devprobe.c` checks the memory devices, `BLKRRPART` failing on `/dev/null`, the inode `fstat` and the listing agree on, `/proc/self/stat` and the console behind `/proc/self/fd/0`; `tests/ptyprobe.c` the pty pairs; `tests/procprobe.c` the snapshot (a child's `stat` opened, the child reaped, the file read after), whole texts, distinct inodes, the system files and `/sys`; `tests/musl/statmusl.c` the fixed times; `tests/musl/callsmusl.c` `/dev/mem`; and `tests/musl/opathmusl.c` and `tests/musl/direntmusl.c` the `O_PATH` descriptors and the entry types of a listing.
* `tests/run procfiles` (full) boots the test image from each of the three root mount sources, which `/proc/mounts` must show, and runs BusyBox's `ps`, `df`, `free`, `uptime`, `dmesg`, `route`, `arp` and `netstat` on the real image.
* `tests/run bootpart` (full) checks an absent boot partition, a FAT fixture read and written through `/dev/bootpart`, both boot windows under a RAM root, and reads at 5 GiB and 258 GiB of a sparse AHCI disk. `tests/run authority` (core) boots the ordinary kernel, which fails a whole-disk write and leaves the sector as it was, and the recovery kernel, which writes past 2 GiB and takes a 200-sector write in one driver call.
* `tests/run fdlock` (full) includes concurrent raw offsets through shared descriptions; `tests/run loopdev` (full) the loop nodes; `tests/run parts` (core) the partition nodes as each table numbers them, with `/sys/block` and `/sys/dev/block`; `tests/run disks` (core) two disks' nodes and their lines in `/proc/disk`; and `tests/run diskdiag` (full) `/proc/disk` and `/dev/disk0` on the read-only kernel.
* `tests/run host` (full) runs `tests/host/synthfs_hosttest.c` (the classifier), `devfs_hosttest.c` (exclusive creation before allocation, which devices lock the description, where `/dev/grubcore` is published), `procfs_hosttest.c` (allocation failure, the CPU times in `stat`, descriptor links, task paths, the counts of a `mem` descriptor, `exe`, arguments read while the process is reaped, `oom_score_adj`, the paths in `maps`), `mbr_hosttest.c` and `diskinfo_hosttest.c`. `sh tests/host/synth_open_mutate.sh` compiles faults into the devfs and procfs host tests and requires each to fail.
