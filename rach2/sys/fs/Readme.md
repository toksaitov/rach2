# The file system layer

The file system layer is the part of the kernel between the system calls on files and descriptors and the file systems that keep them. It keeps each process's descriptor table and the open file descriptions its descriptors share (`fd.c`, `fd.h`, `file.h`), makes the paths the calls are given absolute for the resolver (`pathbuf.c` and `../syscall_fs.c`), applies the rules of permission, ownership and time, and defines what reaches the medium at `fsync`, `sync`, unmount and `reboot`. The mount table, the resolver and each file system have documents of their own:

* [vfs.Readme.md](vfs.Readme.md): the mount table, the operations every type provides, `mount(2)` and `umount2(2)`, binds, the resolver, a process's root and working directory, claims on a disk's sectors, and the buffer cache.
* [krffs.Readme.md](krffs.Readme.md): KRFFS, the root of the RAM images, which the boot line or `mount(2)` can also place on a disk partition.
* [ext2.Readme.md](ext2.Readme.md), [fat32.Readme.md](fat32.Readme.md) (the type `vfat`) and [exfat.Readme.md](exfat.Readme.md): the disk formats of other systems.
* [tmpfs.Readme.md](tmpfs.Readme.md): tmpfs, `/dev/shm`, and the files of `memfd_create(2)`.
* [synthfs.Readme.md](synthfs.Readme.md): `/dev`, the raw disk windows, `/proc` and `/sys`.
* [debugfs.Readme.md](debugfs.Readme.md): debugfs at `/sys/kernel/debug`, the files the kernel's subsystems register for test programs.
* [lock.Readme.md](lock.Readme.md): the advisory locks of `fcntl(2)` and `flock(2)`.
* [../ipc/Readme.md](../ipc/Readme.md): the POSIX message queues at `/dev/mqueue`.
* [../mm/Readme.md](../mm/Readme.md): the page cache under the KRFFS root and the mappings of files; [../block/Readme.md](../block/Readme.md): the disks.

## Interfaces

The system calls are in `../syscall_fs.c`, and the manual pages give their contracts: [open(2)](../../../man/man2/open.2) (with `close` and `O_PATH`), [openat2(2)](../../../man/man2/openat2.2), [dup(2)](../../../man/man2/dup.2), [fcntl(2)](../../../man/man2/fcntl.2), [read(2)](../../../man/man2/read.2), [write(2)](../../../man/man2/write.2), [lseek(2)](../../../man/man2/lseek.2), [getdents64(2)](../../../man/man2/getdents64.2), [stat(2)](../../../man/man2/stat.2), [statfs(2)](../../../man/man2/statfs.2), [ustat(2)](../../../man/man2/ustat.2), [sysfs(2)](../../../man/man2/sysfs.2), [access(2)](../../../man/man2/access.2), [chmod(2)](../../../man/man2/chmod.2), [chown(2)](../../../man/man2/chown.2), [umask(2)](../../../man/man2/umask.2), [chdir(2)](../../../man/man2/chdir.2) (with `fchdir` and `getcwd`), [chroot(2)](../../../man/man2/chroot.2), [mkdir(2)](../../../man/man2/mkdir.2) (with `rmdir`), [mknod(2)](../../../man/man2/mknod.2), [link(2)](../../../man/man2/link.2) (with `unlink`), [symlink(2)](../../../man/man2/symlink.2), [rename(2)](../../../man/man2/rename.2), [truncate(2)](../../../man/man2/truncate.2), [fallocate(2)](../../../man/man2/fallocate.2), [splice(2)](../../../man/man2/splice.2) (with `tee`, `sendfile` and `copy_file_range`), [sync(2)](../../../man/man2/sync.2) (with `fsync` and `syncfs`), [getxattr(2)](../../../man/man2/getxattr.2) and [gettimeofday(2)](../../../man/man2/gettimeofday.2) (with `utimensat`). The descriptor limit is in [limits(7)](../../../man/man7/limits.7) and `/proc/PID/fd` in [proc(5)](../../../man/man5/proc.5).

The rest of the kernel uses `fd.h` (the tables, entries and descriptions; `fd_alloc`, `fd_get`, `fd_ofd_ref`, `fd_ofd_unref` and the description lock `fd_ofd_lock`); `file.h` (`struct file_ops`, the read, write, poll, ioctl, close, mmap and llseek that a pipe, a pseudo-terminal, a device, a `/proc` file, an AF_UNIX socket or an anonymous descriptor such as an epoll set installs on its entry); `pathbuf.h` (`path_buf_get`, `path_buf_put` and `proc_cwd`); and from `syscall_internal.h` `resolve_named`, `copy_path_cwd`, `canonicalize_named` and `resolve_named_real` for `execve`, the permission checks, `fd_release_backing`, and `fd_holds_release`, which the dispatcher calls as each call returns.

## Design

### Descriptor tables

A process's record points to its table (`fd_table_t`), whose entries are one array from the heap. A table starts with `FD_TABLE_FIRST`, 16, entries and doubles as it fills; a caller is given no descriptor at or past its soft `RLIMIT_NOFILE`, and none at or past `fd_nr_open`, fs.nr_open, 1,048,576 by default (`fd_limit`). The search for the lowest free descriptor begins at `next_free`, below which no slot is free, as Linux's `next_fd`. `fd_file_max`, fs.file-max, bounds the open file descriptions of the machine for a caller that is not privileged, with `ENFILE`; it is `LONG_MAX` by default, and `fd_files_open` counts them. `clone` with `CLONE_FILES` shares a table and counts its sharers in `refs`. `fork` gives the child a copy whose descriptors take another reference to the same descriptions (`files_copy` in `../syscall_proc.c`); `execve`, `close_range` with `CLOSE_RANGE_UNSHARE` and `unshare` with `CLONE_FILES` give a sharer a copy of its own (`proc_files_unshare`); and the last sharer to go closes every descriptor (`release_fd_table`).

An entry has its type (`fd_type_t`), what it is open on, its description, and its own flags: read, write, close-on-exec, `O_PATH`, and the two closing marks below. An entry with a `struct file_ops` is dispatched through it, and the others by their type: the files and directories of every file system, the console, network sockets, the framebuffer and the mouse. A new process has descriptors 0, 1 and 2 on the console, each open for reading and writing with a description of its own (`fd_init_stdio`), as Linux gives init `/dev/console`.

An object's `mmap` gives a new region its backing, after the call has checked the descriptor's access as for a file: the region it is given has no address yet, its start 0 and its end the length, its kind `VM_SHARED` for a shared mapping and `VM_FILE` for a private one, and the call's protection and page offset. The operation attaches the object's pages or device memory with a reference on the object, which the region keeps until munmap, exec or exit and which fork copies; a device object does it with `vm_device_map` ([`mm/Readme.md`](../mm/Readme.md)). It answers ENODEV for an object that cannot be mapped, EINVAL for a range outside it or a private mapping it refuses, and EACCES or EPERM for a protection or a caller it refuses. A descriptor of any type whose operations have `mmap` maps through it, `/dev/mem` the first. An object's `llseek` moves the description's offset for `lseek` and `_llseek` and returns the new offset, which the call stores; an object with no position answers ESPIPE. Both seek calls use `llseek` before dispatching on the descriptor's type. A dma-buf uses it for its size query and rewind; its anonymous descriptor also reports the buffer's own inode and size through the stat calls.

`fd_alloc` reserves a slot by giving it a new description and no type. A reserved slot is no descriptor to `fd_get`, to `fd_alloc` or to a copy of the table. An open reserves its descriptor before it resolves the path and gives the entry its type as its last step (`do_open`, `open_install`), so an open that can get no descriptor has created and truncated nothing.

A call on a shared table keeps every descriptor it looks up: `fd_get` sets the descriptor's bit in the calling thread's `fd_held` map, and the dispatcher clears the map as the call returns (`fd_holds_release`). `close_fd` drops the table's record locks on the file at once (`fd_close_locks`); if the descriptor's bit is set in another thread's map, it only sets `FD_FLAG_CLOSING`, which no lookup passes, and the release runs as the last such call ends. A release sets `FD_FLAG_CLOSING` and `FD_FLAG_RELEASING` before it begins, since it may sleep in a file system's `release`, and until it ends no lookup, `dup2`, copy of the table or second release takes the entry. So `poll` and `select` keep each descriptor they wait on until the wait ends, as Linux's references from their wait queues do. An `epoll_wait` asleep does not, since Linux's epoll takes no reference to what it watches and a thread may wait in it for as long as the program runs, as Go's network poller does: `close_fd`, and `dup_clear` for `dup2`, first take every such wait that holds the descriptor off the queues it sleeps on, which `poll_wait` names in the thread's record while it sleeps, clear its hold and wake it (`epoll_waits_let_go`), so the descriptor is released at once and the wait scans its set again. The set's own descriptor stays held, since the wait reads the set until it ends. `fd_alloc` holds the slot it reserves in the same way. A thread's map is from the heap and as wide as its table: `fd_table_share` widens the new sharer's map, and the owner's on the table's first share, and a growth of a shared table widens every sharer's before it moves the entries, so `fd_get` never allocates and a clone with CLONE_FILES walks no list of processes. `fd_holding` is one more than the highest word with a bit set, and `fd_holds_release` scans no further.

A growth moves the entries to a new array with no sleep between, so a lookup by number always finds an entry where it is now, and the code outside `fd.c` indexes `entries[]` directly. A call that took the address of an entry and then slept may meanwhile have had the table grown by another sharer, or by itself through `fd_alloc`. The array a growth replaces therefore stays on the table's `retired` list, unchanged, so such an address reads what it read before, until `fd_table_reap` frees it at the end of a call when no other sharer's call holds a descriptor. What may differ is what was written after the move, which only the new array has: a call that writes an entry after a sleep, reads a field another thread may have changed, such as `FD_FLAG_CLOSING`, or compares an entry by address, first takes the entry as it is now with `fd_entry_now`. The open of a file (`open_install`) and of a FIFO (`fifo_attach`), the release of an orphan (`fd_release_orphan`), `fcntl`'s record locks and the core file do so; `dup_clear` looks its slot up again by number, `fd_in_table` knows the retired arrays, and `vfs_repoint` moves a node in them too (`fd_table_repoint`). An exec's staged table of its own (`exec_files_stage`) is widened again after the exec's last sleep (`exec_files_fit`), since another sharer may have grown the shared table meanwhile.

### Open file descriptions

A description (`struct open_file`) is shared by the descriptors that `dup` and `fork` make from one open. It has the reference count; the 64-bit offset; `raw_offset`, a raw disk window's offset; the `O_APPEND` and `O_NONBLOCK` flags; and for a file of a mounted type the mount, the node and the type's per-open handle (`vmnt`, `vnode`, `fhandle`), the inode number at the open, and the pin of an `O_PATH` description on a type that needs one. Descriptions come from the heap, each in a record with the wait queue of its lock (`struct ofd_rec` in `fd.c`), on one list. A description's serial number is the count made before it, so `fd_ofd_live` can tell whether a description an epoll registration remembers is still open without reading an address the heap may have given to a later one. The last reference drops the description's own locks (`lock_ofd_gone`), reports the close to inotify, drops the pin, and calls the type's `release` through `vfs_desc_close`.

`truncate(2)` truncates through a description of its own, so it runs the type's `open` and `release`, and is counted in the unmount's log record, as an `open(2)` without `O_PATH` is ([vfs.Readme.md](vfs.Readme.md)).

The description lock (`fd_ofd_lock`) keeps a sharer from using the offset while another sleeps in a disk request with it. On a type that sets `ns_serialised` ([vfs.Readme.md](vfs.Readme.md)), it takes the mount's namespace lock first. `read`, `write`, `lseek`, `getdents64`, `ftruncate`, `truncate` and `fallocate` hold it, and so does the read or write of a device, `/proc` or debugfs file whose offset moves; `pread64` and `pwrite64` hold it on a regular file and give a device, `/proc` or debugfs file a copy of the description instead (`pio_view`). An `O_APPEND` write reads the file's size under it. A directory's offset is its listing's cursor, a value of the type's own, so `lseek` on a directory of a file system takes only 0, the current cursor, or one the listing reports, which it finds by reading the listing from the start (`dir_cursor_valid`).

`read` and `write` check the descriptor and its access first, then the full requested address range, then whether the count is negative as the kernel's signed size, then, on a descriptor that can seek, whether the end at the description's offset passes the signed 64-bit range (`rw_offset_end`), before limiting the transfer to `MAX_RW_COUNT`, as Linux's `rw_verify_area` does; `readv` and `writev` check that end with the vector's total. This keeps an overflowing range at EFAULT even for a directory, and a native i686 count with its sign bit set at EINVAL once its range is valid. `pread64` and `pwrite64` first check the offset and whether the descriptor can seek, then make the same checks at their own offset before limiting the count. `/proc/PID/mem` and `/dev/mem` take unsigned offsets, as Linux's `FMODE_UNSIGNED_OFFSET` makes them, so no end of theirs is refused (`rw_end_past`). The i386 calls on x86-64 use the kernel's 64-bit count for these checks.

A `readv` of anything but a mounted file copies the vector into the kernel once (`iov_import`) and reads through that copy, so a buffer that overwrites a later entry of the caller's list does not move that entry's destination, as Linux copies the vector before any read. A pipe reads the copy as one read ([the IPC layer](../ipc/Readme.md)), a stream socket as one read and a datagram socket as one datagram ([the network layer](../network/Readme.md)); a device or a `/proc` file is read for its first buffer and then only while it reports input waiting, each buffer cut before its first page that cannot be written, and a first buffer of which no byte can be written goes to the read whole, so that the object answers its wait and end of input first.

The `preadv2` and `pwritev2` entry checks the descriptor, imports one copy of the vector, returns zero for no bytes, and only then checks flags, following Linux 6.12's `fs/read_write.c` and `lib/iov_iter.c`. The import range-checks buffers but leaves data faults to the transfer after the flags. It caps the total at `MAX_RW_COUNT` and keeps the caller's layout, so native and compat calls use the same copy during I/O.

A `writev` of a mounted file, and a vector append through `pwritev` or `pwritev2`, holds the description and file locks across its elements, or the mount's namespace lock where the type has no file locks, and checks the end of the whole vector at the shared offset under them, as Linux holds `f_pos_lock` across a vector. O_APPEND and RWF_APPEND both use this path. A `readv` or `preadv` of a mounted file holds the description across its elements in the same way (`iov_file_read`), and a `pwritev` of one goes through the same locked vector write; each takes the vector once, whole, as Linux's `vfs_iter_read` and `vfs_iter_write` take an `iov_iter`. A read of an ext2 file whose pages mappings hold takes each such page from memory (`file_read_locked`, with `filemap_read_resident`), as Linux's `filemap_read` copies the page cache's folio, so it sees a shared mapping's stores without writing them back, and an element of a `readv` sees what an earlier one stored into a mapping of the file. A growth seal is checked against the whole vector before any element is written. The vector's address ranges are checked first; its buffers are then brought in before taking the locks, for reading for a write and for writing for a read, retaining only the bytes before the first bad data page (`iov_prefix`), so that the transfer ends there with the bytes before it. A buffer page lost during a disk wait ends the call with its completed prefix, including earlier elements, without releasing the file lock to fault it in. Only a call that moved no byte may release the lock and resume after faulting. An explicit position leaves the shared offset alone.

`RWF_NOAPPEND` uses the same locked vector write with end placement disabled, without changing the description's O_APPEND flag. An explicit position leaves the shared offset alone; -1 uses and advances it. Reads accept NOAPPEND and ignore it. Both directions reject APPEND together with NOAPPEND for a nonempty vector, as Linux 6.12's `kiocb_set_rw_flags` in `include/linux/fs.h` does.

A synthetic descriptor keeps the mount where its node was opened, so following its `/proc/PID/fd/N` link under `RESOLVE_NO_XDEV` compares the target's actual mount. A descriptor on no file-system mount, such as a pipe or a socket, gives `EXDEV` when its link is followed under `RESOLVE_NO_XDEV` (`proc_fd_xdev` in `../syscall_fs.c`). The replay keeps the original mount restriction and checks the descriptor again before opening its target.

### Copies between descriptors

`sendfile`, `splice`, `tee` and `copy_file_range` copy in the kernel, through a heap buffer of 32 KiB (`COPY_CHUNK` in `../syscall_fs.c`). The read and write paths take only user buffers and check them as such, so the call opens the buffer to those checks for its length (`user_window_open`, [../mm/Readme.md](../mm/Readme.md)) and passes it to `file_read` with an offset of its own, as `pread64` reads, and to `write_fd`, `file_write` or the pipe's write. Every destination then behaves as it does for `write(2)`: a file's offset, `O_APPEND`, size limit, set-ID bits and inotify report, a socket's `O_NONBLOCK`, a pipe's `SIGPIPE`. A source is a regular file of the KRFFS root or of a mounted type (`copy_regular`), or for `splice` and `tee` a pipe. The source's offset moves only past what the destination took, so a short write loses nothing; a pipe's bytes are copied out, written, and only then taken from the ring (`pipe_splice_peek` and `pipe_splice_consume`, [../ipc/Readme.md](../ipc/Readme.md)). Into a pipe the copy waits for room before its first chunk and reads no more than the room, as Linux's splice returns what fitted, so a program that splices into a pipe it reads itself does not wait forever; a chunk the room cuts is the last, and one `COPY_CHUNK` cuts ends at a page of the file, so that each page of the file is one buffer of the pipe, as Linux links it once. Pipe to pipe goes ring to ring (`pipe_tee`). A copy stops at a signal once a byte has moved.

`lseek`'s `SEEK_DATA` and `SEEK_HOLE` and the clone requests of `ioctl`, `FICLONE` and `FICLONERANGE` (`fs_clone_ioctl`), answer as Linux does for a file system that keeps no map of its holes and shares no extents: the whole file is data with its hole at the end, and a clone fails with `EOPNOTSUPP` after the checks Linux makes first.

### Paths

A call copies each path into a page from the calling process's set (`path_buf_get`), since a path may be `VFS_PATH_MAX`, 4096 bytes with its terminator, a quarter of the 16 KiB kernel stack. A process has up to `PATH_BUFS`, eight, pages, each taken the first time one of its calls needs that many and kept until the record is freed; the deepest call takes six, openat2's path, the path its walk reached, the anchor's path, the joined path and a link's two pages. So a path costs a frame only once, and a test that fails a chosen frame allocation with `rach2.framefail` is not moved by the paths a program uses.

`copy_path_at` makes every path absolute and canonical. A relative path is joined, in its page, to the working directory's path (`proc_cwd`) or to the path of the directory a descriptor is open on (`fd_dir_path`), and the whole is held to 4096 bytes. `canonicalize_abs` removes repeated slashes and `.` components and keeps `..`, which the resolver walks physically ([vfs.Readme.md](vfs.Readme.md)). How the path as written ended is kept beside it (`path_names_dir`), since a path that ends in a slash, `.` or `..` must reach a directory and the canonical copy no longer shows the ending. A last `.` is put back (`path_put_dot`), so the walk looks it up in the directory before it, with the search permission and the `ENOTDIR` of Linux's walk, and `resolve_named` makes such a path follow a final symbolic link and reach a directory. `execve` runs the node its one walk returned, and so does an interpreter's walk, so a symbolic link replaced between two walks cannot change what runs; it names the program, for `/proc/PID/exe`, by the path that walk took, its links resolved (`resolve_named_real`), so such a link cannot change the name either.

The join passes through the directories above the working directory, which Linux's relative walk never enters; [vfs.Readme.md](vfs.Readme.md) says how the resolver judges search permission on them. A removed directory that a descriptor or a working directory still has stays empty: a relative name joined to its old path names nothing, and a path through `/proc/PID/fd/N` reaches the directory itself, where ext2 and tmpfs answer `ENOENT` to a new name. FAT32 and exFAT remove no directory that something holds. A `..` at the front of a path relative to a removed working directory is taken off the string instead (`removed_cwd_parents`), so `cd ..` leaves it.

A directory descriptor's path is made again at each use: a synthetic directory's from its kind and process; a directory's of a type with a `path` operation by the type, so the descriptor follows a rename; and a KRFFS root directory's from its node, which must still resolve to itself, or the call answers `EBADF`. The message queue file system, the one type without `path`, uses the path recorded at the open in the description's `dirpath`, a copy from the heap of any length the walk takes, which `/proc/PID/fd` also reports for a file of every type but KRFFS. The path is then made relative to the process's root (`path_in_root`); one outside that root, from a descriptor opened before a `chroot`, keeps its path from the root of the mount table, with leading slashes that make the resolver start there, as Linux walks from such a descriptor.

The working directory's path is in the `fs_struct` that `CLONE_FS` shares, in its 64 bytes (`CWD_MAX`) when it fits and in the heap, up to 4096 bytes, when it does not (`proc_cwd_set`).

An `O_PATH` open of a proc descriptor link keeps the mounted file or synthetic object the source descriptor names. A mounted inode gets a new path description, and a synthetic object shares its held description with access disabled on the new descriptor, so closing the source does not invalidate the path.

### Permissions, ownership and times

A process is privileged when `proc_privileged` is true of it; [the process subsystem's Readme](../proc/Readme.md) gives the rule. `cred_access_bits` judges one class, owner, group or other, by the effective ids, or the real ones for `access`, and passes a caller whose user id of that kind is 0 and who has kept its capabilities. `cred_access_node` applies it to a node of the KRFFS root and `cred_access_ref` to a node of another type, from the attributes the type reports. Both answer `EACCES` to the execution of a non-directory with no execute bit, even for root, and `cred_access_ref` answers `EPERM` to a write of an immutable file. The KRFFS root directory is judged as mode 0755 and not sticky by its identity, since its stored mode has the dirty flag where the setuid bit would be ([krffs.Readme.md](krffs.Readme.md)).

`cred_kill_setid` on the KRFFS root and `vfs_kill_setid` elsewhere take the set-id bits from a file that is not a directory, setuid always and setgid when group execute is set, after an unprivileged write that moved bytes or truncation, and after any `chown` that changes an owner. The sticky rule is `cred_sticky_ok` on the KRFFS root and `cred_remove_ref` elsewhere, each after the write check on the parent. Each call's page gives the rules it applies.

Linux's four `fs.protected_*` sysctls are kept, at the values Debian and Ubuntu set at boot, in `vfs_protected_hardlinks`, `vfs_protected_symlinks`, `vfs_protected_fifos` and `vfs_protected_regular` of `vfs.c`, which the files of `/proc/sys/fs` read and write ([proc(5)](../../../man/man5/proc.5)). The resolver's `may_follow_link` refuses a link at the end of a path in a sticky directory others may write, unless the follower or the directory's owner owns it ([vfs.Readme.md](vfs.Readme.md)). `may_linkat` refuses `link` to another user's file that is not a regular file the caller may read and write without set-id bits, after `EROFS` and before the parent's write check, as Linux orders them. `may_create_in_sticky` refuses an `O_CREAT` open without `O_EXCL` of an existing file in a sticky directory owned by neither the caller nor the directory's owner, from the directory's attributes that the open's walk records (`vfs_resolve_entry`), after `EEXIST` and before the checks of the file's kind. Each refuses root too, as Linux 6.12's `fs/namei.c:1112-1291` does without its id-mapped mounts, and answers `EACCES`, or `EPERM` for the link.

A new node takes the caller's effective ids and the mode under the umask. On KRFFS, ext2 and tmpfs a set-group-ID directory gives a new node its group, and a new directory the bit; FAT32 and exFAT report the mount's ids and mask. Each type keeps its own times and is given new ones through `setattr`; `utimensat` leaves the KRFFS root directory's times alone and succeeds. Only tmpfs advances a file's access time on a read.

### The lifetime of a file of the KRFFS root

The KRFFS root keeps no count of a node's holders; `fd_node_holders` counts them by a scan: every descriptor in every table that has the node, a descriptor in flight on an AF_UNIX socket, a mapping of the file, an address space that runs it, and for a FIFO each description, since its pipe is found by the node's address. A bind mount shows the same node: descriptor and mapping holders use the current node of their description, and executable holders compare the underlying mounts. An `unlink`, or a `rename` over a name, whose node has holders takes the name and keeps the node (`krffs_unlink_held`); the orphan is in no lookup, listing or count, and its last holder's release frees it (`fd_release_orphan`).

The count and the free run under the root's namespace lock (`fd_release_lock`), which `unlink` takes with its walk, `rename` after its two walks, an open from its walk until it has published its descriptor, and every allocation on the root. So the count includes every descriptor an open has made, and nothing allocates the extent or counts again while a free sleeps reading a neighbouring header. A holder kept in a list of its own, a mapping, a descriptor in flight or an address space, takes the lock before it leaves the list.

A directory is never an orphan: `rmdir` fails with `EBUSY` on one that a description or a working directory has, before it looks for names in it (`root_dir_in_use`), since a descriptor of the root finds its directory by the node's place, which the allocator would give to the next node made. Every other type keeps a node for its holders itself ([vfs.Readme.md](vfs.Readme.md)), and [mkdir(2)](../../../man/man2/mkdir.2) gives each type's answer to `rmdir` of a directory in use.

### Durability

The boot line chooses the root and how KRFFS reaches it ([../../Readme.md](../../Readme.md), [krffs.Readme.md](krffs.Readme.md)). `fsync` writes back the file's shared mappings (`filemap_sync_file`) and then calls the type's `fsync` through `vfs_fsync`, as `fdatasync` does through `vfs_fdatasync`, by the type's `fdatasync` or else its `fsync`, which flushes the disk's write cache after a type on a block device has written. A descriptor with no mount, a pipe or a device, writes the page cache.

A KRFFS root on a disk partition is on no mount's device, so no `fsync`, `sync` or `reboot(2)` calls `block_flush` for it. Its pages leave through the disk driver's polled `write`, which returns only when they are on the medium: ATA and AHCI end each write with a cache flush, and NVMe sends the write with force unit access, flushing too while the disk has writes answered unflushed ([../block/Readme.md](../block/Readme.md)).

| --- | --- | --- | --- |
| KRFFS root on a RAM module | nothing | no disk | no |
| KRFFS root through the window, on a RAM module | every dirty page, into the module | no disk | no |
| KRFFS root on a disk partition | every dirty page of the window | by each page's write | yes |
| KRFFS volume | the file's dirty blocks and its header | yes | yes |
| FAT32, exFAT | the file's dirty blocks, then the dirty blocks no one file owns | yes | yes |
| ext2, a regular file | the mount's pending files, then the bitmaps and descriptors dirtied for the file, its dirty blocks and its inode's table block | yes | yes |
| ext2, any other file | the mount's pending files, then every dirty buffer of the device | yes | yes |
| tmpfs, memfd | nothing | no disk | no |

`sync` writes every file's shared mappings; then, for each active mount on a device, runs the type's `sync`, writes the device's dirty buffers and flushes the device; then writes the page cache, waiting up to 30 seconds of ticks for pages under a write. It returns 0 whatever failed; a failed write leaves its buffer dirty and the mounts on its device read-only ([vfs.Readme.md](vfs.Readme.md)). `syncfs` is `sync` once it has checked its descriptor. A successful `umount2` has run the type's `sync` and `prepare_unmount`, written the buffer cache and flushed the device; a failure leaves the volume mounted.

The kernel writes back nothing on a timer: [update(8)](../../../man/man8/update.8), which init starts, calls `sync` every thirty seconds. `reboot(2)` writes each file system on a disk (`kernel_shutdown` in `../../kernel.c`), once init has ended every other process ([init(8)](../../../man/man8/init.8)). Each writable volume placed by `mount(2)` on a device that has not gone, but a bind mount, is prepared as its unmount prepares it, newest mount first, and logged as `shutdown: SOURCE: unmounted`, or as failed when it could not be marked clean; then the root. A KRFFS root on a disk has its page cache written, its dirty flag cleared and the cache written again; an ext2 volume, the root or another, is closed to writers, synced and marked valid, as its unmount leaves it, or left unmarked when a writer is still inside after 10 s or a removed file is still open ([ext2.Readme.md](ext2.Readme.md)); any other root has its page cache written.

## Limits

* A KRFFS root on a disk puts each page on the medium with its own write, so a `sync` of many dirty pages waits for a cache flush or a write with force unit access per page, where the buffer cache on an AHCI or NVMe disk writes its run unflushed and flushes once.
* `fdatasync` has its own call and its own operation in `vfs_ops`, which only ext2 has, leaving out an inode whose times alone changed; on the other types it does what `fsync` does. Neither call is narrowed to the one file on a KRFFS root, where it writes the whole page cache, or for an ext2 directory, where it writes the whole device. `syncfs` writes what `sync` writes and, like it, reports no failure.
* `reboot(2)` writes no volume placed by `mount(2)`.
* No file system shares extents or keeps a map of its holes: `FICLONE` is `EOPNOTSUPP`, `copy_file_range` copies every byte, and `SEEK_HOLE` finds only the end of a file.
* No file system keeps extended attributes: getting, setting and removing one answer `EOPNOTSUPP`, and a list is empty. There are no ACLs, file capabilities, per-user quotas or journal. Of the types that store files, only ext2 and tmpfs have hard links and symbolic links.
* A path joined to its directory must fit 4096 bytes with its terminator, where Linux bounds only the path the caller gave.
* Each type bounds the climb that rebuilds a directory descriptor's path, and `fchdir` or a relative `*at` call through a deeper directory answers `ENAMETOOLONG` however short its path. The Limits of [krffs.Readme.md](krffs.Readme.md), [ext2.Readme.md](ext2.Readme.md), [fat32.Readme.md](fat32.Readme.md) and [exfat.Readme.md](exfat.Readme.md) give each type's bound.
* The holders of a KRFFS root node are counted by a scan of every descriptor table, so an `unlink`, a `rename` over a name and the release of an orphan take time in proportion to the descriptors open on the machine.

## Tests

* `tests/run default` runs, among the other probes on the test image, `ofdprobe` (shared descriptions), `fdfull` and `limitprobe` (the descriptor limit), `fdstale` (a descriptor across an unlink, a rename and a relocation, and `rmdir` of a directory in use), `dirprobe`, `dirgrow`, `unlinkdirprobe`, `pathcanon` and `vfsprobe` (directories and paths), `ownprobe`, `permprobe`, `fsidprobe`, `modeprobe`, `searchprobe` and `stickyprobe` (ownership and permission), `protectprobe` (the `fs.protected_*` rules on a tmpfs), `openat2probe` (openat2's RESOLVE_ flags), `oldfsprobe` (sysfs and ustat), and the musl programs `pathmaxmusl`, `fdcallmusl`, `atcallmusl`, `preadmusl`, `truncmusl`, `opathmusl`, `lchownmusl`, `direntmusl`, `statfsmusl`, `statmusl`, `stampmusl` and `threadmusl`.
* `tests/run fdlock` boots a KRFFS disk root for `fdstale` and for concurrent offsets of a raw disk window.
* `tests/run persist` boots a copy of a KRFFS disk on IDE twice, cuts the first boot off once the file is written, `fsync`ed and `sync`ed, and requires the file to be read back on the second.
* `tests/run diskfull` fills the KRFFS root of the test image until a write fails with `ENOSPC` after bytes were written, and requires the space back after an unlink.
* `tests/run host` runs `fd_hosttest` (descriptions, each sharer's descriptor limit, the errors of an allocation) and `open_hosttest` (opens and truncations, the close of a descriptor whose release sleeps, the key of a file's locks, the order of the node locks on a `file_locked` type, the release of a KRFFS root orphan, and `may_linkat` and `may_create_in_sticky` at each level of their sysctls).
* `tests/run fatwrite` and `tests/run exfat` run `lagprobe writers`, whose two appenders to one file, one on an `O_APPEND` description by `writev`, `pwritev` at offset 0 and `pwritev2` at offset 0 in turn, whose positioned writes must leave the shared offset where it was, and one by `pwritev2` with `RWF_APPEND` on a description without `O_APPEND`, must leave each two-element record whole while the volume is synced beside them.
* `/musl/catfile` and `/musl/ofdmusl` are staged on the test image and run by no suite.
