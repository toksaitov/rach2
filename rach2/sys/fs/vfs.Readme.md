# Mounts and the VFS

The virtual file system, the VFS, is the layer between the system calls and the file systems: the mount table, the path resolver, the table of operations every type answers, `mount(2)` and `umount2(2)`, and the buffer cache the disk file systems read and write through. It exists so that one resolver, one permission check and one set of default answers serve every type, and a type implements only the operations it has. The table and the resolver are `vfs.h` and `vfs.c`, and the locks of files and directories `nodelock.c`; the cache is `bcache.h` and `bcache.c`. Descriptors, the copying of paths in the system calls, modes and durability are described in [Readme.md](Readme.md).

## Interfaces

* `mount(2)` and `umount2(2)`, system calls 21 and 52 on i686 and 165 and 166 on x86-64, with `MS_BIND`, `MS_REC`, `MS_REMOUNT` and `MNT_DETACH`. [mount.2](../../../man/man2/mount.2) has the flags, the order of the checks and the errors. `sys_mount` and `sys_umount2` in `syscall_fs.c` check privilege, copy the strings and make the target absolute; `vfs_do_mount`, `vfs_do_bind`, `vfs_remount`, `vfs_remount_bind`, `vfs_do_umount` and `vfs_do_detach` do the rest.
* `pivot_root(2)`, system call 217 on i686 and 155 on x86-64 ([pivot_root.2](../../../man/man2/pivot_root.2)). `sys_pivot_root` in `syscall_fs.c` checks privilege and moves the processes' roots; `vfs_pivot_mounts` changes the mounts.
* The types `mount(2)` finds by name, in the order `vfs_type_at` gives them to `/proc/filesystems`: `vfat` ([fat32.Readme.md](fat32.Readme.md)), `exfat` ([exfat.Readme.md](exfat.Readme.md)), `ext2` ([ext2.Readme.md](ext2.Readme.md)), `krffs` ([krffs.Readme.md](krffs.Readme.md)), `tmpfs` ([tmpfs.Readme.md](tmpfs.Readme.md)) and `mqueue` ([../ipc/Readme.md](../ipc/Readme.md)). The type `proc` over a directory of `/proc` succeeds and changes nothing; over any other directory it places a mount of the one proc file system, as a sandbox mounts it in the root it builds. [proc.5](../../../man/man5/proc.5) describes `/proc/mounts`, `/proc/PID/mountinfo` and `/proc/filesystems`.
* For a file system: `struct vfs_type`, with the name, the constructor, the operations and the `ns_serialised`, `nodev`, `name_cache` and `file_locked` bits, and `struct vfs_ops`, both in `vfs.h`; and the sleeping lock, `struct sleep_lock` with `sleep_lock_take`, `sleep_lock_give`, `sleep_lock_held` and `sleep_lock_assert`, in `sleeplock.h`.
* For the system call layer: `vfs_resolve` and its flags, `vfs_resolve_real`, `vfs_resolve_entry`, `vfs_resolve_scoped` with `vfs_tree_seq`, `vfs_tree_changed`, `vfs_replay` and `vfs_replay_end`, `vfs_ref_release`, the wrappers `vfs_read` to `vfs_statfs`, `vfs_desc_open` and `vfs_desc_close`, `vfs_cwd_set`, `vfs_root_set`, `vfs_node_path`, `vfs_leaf_mount`, `vfs_leaf_root`, `vfs_sync_all`, `vfs_repoint`, and the locks `vfs_node_lock`, `vfs_child_lock`, `vfs_rename_lock` and `vfs_cover_lock` with their gives.
* For the disk file systems: `bcache_get`, `bcache_get_blank`, `bcache_release`, `bcache_dirty`, `bcache_dirty_ordered`, `bcache_dirty_owned`, `bcache_dirty_pointer`, `bcache_write`, `bcache_write_unflushed`, `bcache_sync`, `bcache_sync_unflushed`, `bcache_sync_last`, `bcache_sync_owned`, `bcache_sync_block`, `bcache_sync_block_ready`, `bcache_reserve`, `bcache_invalidate`, `bcache_dirty_level`, `bcache_marks` and `bcache_writeback`; for the disk layer `bcache_device_gone`, and for memory reclaim `bcache_shrink`.
* Kernel log records, which the suites read: `vfs: mounted: SOURCE on TARGET (TYPE)`, with `, read-only` after the type for a read-only mount; `vfs: bound: SOURCE on TARGET`; `vfs: remounted: TARGET (read-only)` or `(writable)`; `vfs: unmounted TARGET: N opens, N releases`; `vfs: detached: TARGET` for a lazy unmount; `vfs: pivoted: TARGET` for the new root of `pivot_root`; and `vfs: read-only: TARGET: write of sector N failed (ERRNO)`.
* `/proc/disk` has the cache's counters `cache-hits`, `cache-fills`, `cache-waits` and `cache-visits`, and its size: `cache-buffers`, the buffers it has, `cache-limit`, the most it makes, and `cache-buckets`, the buckets of its index.

A descriptor write updates resident mapped pages after each piece, including a mapping made while the writer faulted its buffer in. A core-file write does so under the file's node lock too, so a later mapped writeback cannot restore older file bytes.

A file used as an executable or its ELF interpreter excludes writers with `ETXTBSY`. `fd_ofd_access` counts the reservation on the file's record before an open can sleep, under the big kernel lock. A writer excludes exec, including an `O_CLOEXEC` writer that exec would close. An executable reference excludes a write open, `O_TRUNC` and `truncate`; a writable descriptor needed for `ftruncate` or `fallocate` cannot coexist with it. A read-only descriptor keeps the usual errors of those calls (`EINVAL` and `EBADF`). Bind mounts share the reservation of their underlying file system. Each file's reservations are counted by its mount base and node in a hash table of `fs/fd.c`, as Linux counts them in `i_writecount`, so the check walks no list of descriptions. Each description brings a record of its own when it is made, which becomes the file's record or waits on it as a spare until the description leaves, so a reservation, its release and its move when a KRFFS node relocates need no memory and cannot fail on it. Fork shares the references; exit and a successful exec release them, and a failed exec releases only its proposed image. The last executable reference permits writing again. Rename and unlink remain permitted. On the KRFFS boot root, including through a bind mount, the holder count keeps both the program and its interpreter allocated after unlink.

## Design

### The mount table

`mounts` in `vfs.c` is an array of pointers to `struct vfs_mount` records. A record comes from the heap when its mount is made and goes back at the unmount, so its address does not change when the array grows. The array starts with eight slots and doubles when a new mount finds none free. The first eight entries, `VFS_PERMANENT`, are made at boot and never unmounted:

| Entry | Path | Type | Flags |
| --- | --- | --- | --- |
| 0 | `/` | KRFFS, or a type with a device | |
| 1 | `/dev` | devfs | |
| 2 | `/proc` | proc | |
| 3 | `/dev/shm` | tmpfs, root mode 1777 | nosuid, nodev |
| 4 | none | tmpfs of `memfd_create`, root mode 0555 | nosuid, nodev |
| 5 | `/sys` | sysfs | ro, nosuid, nodev, noexec |
| 6 | `/dev/mqueue` | mqueue | nosuid, nodev, noexec |
| 7 | `/sys/kernel/debug` | debugfs ([debugfs.Readme.md](debugfs.Readme.md)) | nosuid, nodev, noexec |

`vfs_init` installs the KRFFS root at entry 0, and `vfs_init_root` a root of another type, the ext2 root of `rach2.root=ext2` ([../../Readme.md](../../Readme.md)), with the partition's claim kept in the entry; either then installs the other seven (`install_permanent`). A permanent mount that fails to construct panics. A mount placed by `mount(2)` takes a slot past the permanent ones.

A record has its type, its device (NULL for a type with none), its flags, its state, its parent and the node it covers, the covered path (its target's path from the root of the mount table, at most 255 bytes), the source string (kept to 31 bytes), a reference count, a count of operations in progress, its namespace lock, its root node, the type's private state, the counts of opens and releases, its first write error, its claim, the ids of the live mount namespaces that see it (`ns_seen`, kept by `vfs_ns.c`, [../proc/ns.Readme.md](../proc/ns.Readme.md)), and for a bind its base and the path of its root within the base.

A mount is `VFS_FREE`, `VFS_MOUNTING`, `VFS_ACTIVE` or `VFS_UNMOUNTING`. `vfs_enter` counts an operation in `inprogress` and refuses with `EBUSY` unless the mount is active; `vfs_leave` ends it and wakes an unmount waiting for the count to reach zero. A resolution returns with that count taken on the mount it ends on, and `vfs_ref_release` puts the node and leaves the mount. `refs` counts what keeps a mount from being unmounted: its open file descriptions (`vfs_desc_open`), the one each address space keeps of its program among them, the working directories and process roots on it, its child mounts, and the binds that show it.

A mount point is the covered directory's node, held through the parent type's `hold` for the life of the mount. The resolver replaces it with the mount's root (`mount_covering`), `..` at the mount's root climbs back to it, and `vfs_leaf_mount` shows it to a namespace change, so `mkdir` of its name answers `EEXIST` and `unlink`, `rmdir` and `rename` answer `EBUSY`. A mount still `VFS_MOUNTING` covers its node as an active one does, so a directory cannot be removed or renamed while a constructor sleeps on its device.

The synthetic types have no node to cover, so `/dev`, `/proc` and `/sys` are nameless mounts: each is entered by the last component of its covered path from the root directory of its parent (`mount_named_at`), and `/dev/shm` and `/dev/mqueue` are entered by name from `/dev`'s root directory in the same way. A nameless mount's name is its recorded path below its parent's (`mount_entry_name`), and it may be more than one name: debugfs is entered from `/sys`'s root directory by `kernel/debug`. A type that takes the rest of a path in one call answers `VFS_ENTER` with that mount when the rest, its `.` and `..` resolved as text, reaches those names, and the walk enters it there; `..` at its root goes to its parent's root directory with the names before its last put in front of the rest of the path (`nameless_up`), so it is `/sys/kernel`. A listing of the parent's root directory shows no such mount, whose last name is the type's own entry in a directory below. The memfd tmpfs has no parent and no path, and no walk reaches it.

### Types and operations

`struct vfs_ops` is one table per type. A node handle is the type's own: an address in the mapped image for the KRFFS root, an offset plus one for a KRFFS volume, a heap record of a classified path for the synthetic types. Whoever receives a node from `lookup`, `create`, `mknod` or a mount's root owns one hold on it and puts it back; a type whose nodes need no counting leaves `hold` and `put` NULL. `open` runs once for each description that opens the node and returns the per-open handle, or the node itself for a type that needs none, and `release` runs at the description's last close; an `O_PATH` description has no handle and runs neither. The counts of opens and releases go into the unmount record.

An operation a type does not have is a NULL pointer, and the wrapper in `vfs.c` answers for it, so each default is written once: `EROFS` for `write`, `truncate`, `setattr`, `create`, `unlink`, `mkdir`, `rmdir` and `rename`; `EPERM` for `link`, `symlink` and `mknod`; `EOPNOTSUPP` for `fallocate`; and `EINVAL` for `read`, `getattr`, `readdir` and `statfs`. A missing `xattr` lists no names and answers `EOPNOTSUPP` for get, set and remove; ext2 implements user attributes in kernel buffers through `struct vfs_xattr`, with the caller holding the node lock and checking permission. `vfs_xattr` enforces the mount and inode flags and reports successful changes to inotify. A missing `fsync` writes the device's dirty buffers instead, and a missing `fdatasync` does what `fsync` does. A failed write on a mount's device, whoever made it, is recorded in the file system's two error sequences, Linux's errseq (`vfs_wb_err_set`), and each open description keeps a cursor into each, sampled at its open (`vfs_wb_err_sample`): `vfs_fsync` and `vfs_fdatasync` answer, after the type's own sync and when that succeeds, an error recorded since the description's cursor last looked, and move the cursor past it, as Linux's `file_check_and_advance_wb_err` does, and syncfs does the same with the other sequence. So a failed write-back of the flusher or of an eviction is not hidden by a later write of the same block that succeeds, and each description hears of it once; a description opened after the failure hears of it only when no sync has reported it yet. One lock serialises every record and report, so two syncs of one description at once report an error once. The mount's `write_error`, the first failure, is the latch that keeps it read-only, and no sync reports it. `cachestat` counts a range of file pages (`vfs_cachestat`): tmpfs walks allocated shmem leaves, and ext2 walks allocated branches of its resident block map, counting the pending write batch and the buffer cache (`bcache_state`). Neither visits each page of a hole or reads a disk block; long walks offer scheduling. A type without the operation counts no page. `read_frames` reads a run of a regular file's pages into page frames for the file page cache, the device's transfer landing in the frames where it can, and given a completion starts the reads and returns, the completion called for each page once; ext2 alone has it, and `vfs_read_frames` answers `ENOSYS` for any other type, whose pages are read with `read`. `handle_node` gives the node behind a handle that a type's `open` made of its own, as ext2's holds its node and a directory's cursor, and a mounted KRFFS volume's is the record of the node's opens; the wrappers reach the node through it to ask whether the file backs a loop device, to forget the file's cached pages after a write, a truncation or `fallocate` and to read its immutable and append-only flags, and a type without it has handles that are its nodes. `writeback` moves into the buffer cache what a type keeps dirty outside it and has kept since a given tick, for the flusher, which then writes all of the device's dirty buffers with no flush, as Linux writes all of an expired inode's pages (`vfs_writeback_all`, [Readme.md](Readme.md)); ext2 drains its file-write batch once the batch's first byte is that old, and a type without the operation keeps nothing there. Every wrapper but `vfs_release` answers `EIO` once the mount's device has gone, and the write-side wrappers answer `EROFS` on a read-only mount, or a bind whose base is read-only, before they call the type. `vfs_truncate`, `vfs_fallocate` and a size change through `vfs_setattr` answer `EBUSY` for a file that backs a loop device, whichever open of it and whichever bind of its mount the handle is, and so do `vfs_unlink_name` for such a file and `vfs_rename` for a new name that has one other than the file moved, under the locks their callers hold for the change ([../block/Readme.md](../block/Readme.md)).

The wrappers enforce the immutable and append-only flags a type reports through `getattr` with `flags_known` set, which only ext2 does, by Linux's rules (`notify_change`, `may_delete`, `may_create`, `vfs_link`, `vfs_fallocate`): `setattr` of anything but the flags is `EPERM` on a file with either; `unlink`, `rmdir` and `rename` take no name out of a directory with either nor away from a file with either; `rename` puts no name into an immutable directory and replaces no file that has either flag or is in an append-only directory; `link` makes no name for a file with either nor in an immutable directory; and `fallocate` changes no immutable file and on an append-only one only allocates, with or without `FALLOC_FL_KEEP_SIZE`. After a namespace change or a `setattr` succeeds, the wrapper tells inotify while any watch exists ([../io/Readme.md](../io/Readme.md)), and a write, a truncation or a size change drops the file's pages from the file cache ([../mm/Readme.md](../mm/Readme.md)).

`ns_serialised` asks for the mount's namespace lock around a description's use of the file system. The KRFFS root, KRFFS volumes and tmpfs set it: KRFFS moves a file's bytes while the file is open, so an open on it must register its description under the lock. ext2, FAT32, exFAT, mqueue and the synthetic types leave it clear, so that two readers of one volume reach the buffer cache together. `nodev` marks a type with no device: `mount(2)` takes any source string for it and claims nothing. `name_cache` lets the name cache keep the type's lookups; ext2 alone sets it. `file_locked` marks a type that locks each file on its own, through its `lock_node` and `unlock_node`, in place of the mount's namespace lock, in the order that [Locks](#locks) gives. ext2 alone sets it and has the two operations; every other type's are NULL. `reads_unlocked` marks a type whose `read`, `readdir`, `readlink`, `getattr`, `open`, `release`, `hold` and `put` may be called without the big lock, each taking it where it needs it, so that the file calls read, list, stat, open and close its regular files and directories, and read its links, without it ([Readme.md](Readme.md)); ext2 alone sets it ([ext2.Readme.md](ext2.Readme.md)). `writes_unlocked`, which only a type that sets `reads_unlocked` sets, marks one whose `write`, `truncate`, `fallocate`, `fsync` and `fdatasync` of a regular file may be called without the big lock, the first three under the file's lock (`lock_node`), so that write, pwrite64, writev, ftruncate, fallocate, fsync and fdatasync run on its files without it (`file_vfs_writes_unlocked`); ext2 alone sets it.

`vfs_repoint` is how a KRFFS relocation reaches everything that refers to the moved node: the working directories and process roots, the mounts covering it, the mount's root, the descriptions (`fd_ofd_repoint`), the loop devices (`loop_repoint`), and the advisory locks and their waits (`lock_repoint`, [lock.Readme.md](lock.Readme.md)). It does this on the moving mount and on each bind of it, and on the boot root also in every descriptor table.

### The resolver

`vfs_resolve` walks a path one component at a time: one name in one directory on one mount. An absolute path, or any path when `start` is NULL, starts at the caller's root; otherwise the walk starts at the directory an `*at` call passes. The system call layer has already joined a relative path to the working directory's ([Readme.md](Readme.md)). A path that begins with two slashes starts at the root of the mount table and keeps the caller's root for `..` and absolute links; the system call layer makes one for a name relative to a directory descriptor outside the caller's root.

Before each component the resolver checks search permission on the directory (`may_search`), once and in the same way for every type: the nine-bit rule over what `getattr` reports, one identity class chosen and judged alone, by the file-system ids, which are the effective ones unless `setfsuid(2)` set them apart, or, with `VFS_WALK_REAL_IDS` for `access(2)`, the real ones, and uid 0 passing unless the thread gave up its capabilities. A type without `getattr` is searchable. A component on the way to the caller's working directory is not checked (`toward_cwd`): the walk starts at the root where Linux starts at the working directory and checks nothing above it, so a process left in a directory it may not reach by its path, as `su` from root's home leaves one, can still name files there.

A component longer than `VFS_NAME_MAX`, 255 bytes, is `ENAMETOOLONG`. Then:

* `.` is passed over.
* `..` is physical. At the walk's root, and at the root of the root mount whatever the walk's root is, it stays. At the root of a mount over a directory the walk moves to the covered node and takes the same `..` again there. At the root of a nameless mount it is the parent's root directory, and the root of each mount over that in turn, as Linux's `handle_dots` steps into the parent through `handle_mounts`, or for one entered by more than one name the directory there that holds it. Anywhere else it is the type's `lookup` of `..`. A missing or unsearchable directory before a `..` fails the path, as on Linux.
* In a root directory, the name of a nameless mount there enters that mount.
* Otherwise the type's `lookup` gives the node, or the name cache gives what it gave before. On a type with `readlink`, a node `getattr` reports as a symbolic link is followed when more of the path comes after it, and at the last component unless the caller passed `VFS_WALK_NOFOLLOW`. At the last component `may_follow_link` applies `fs.protected_symlinks` first, as Linux's `pick_link` does: in a directory whose mode has both the sticky bit and other-write, a link owned by neither the follower, its file-system uid or for `access` its real uid, nor the directory's owner is `EACCES`, for root too. The target replaces the component: an absolute one restarts at the walk's root, a relative one goes on in the directory the link was found in. The target and the rest of the path must fit `VFS_PATH_MAX`, 4096 bytes with the terminator (`ENAMETOOLONG`); the forty-first link is `ELOOP` (`VFS_LINK_MAX` is 40); an empty target is `ENOENT`. The walk takes two path pages at its first link and gives them back when it returns.
* A node a mount covers is replaced by that mount's root.

A type with `lookup_rest` in place of `lookup`, one of the three synthetic types ([synthfs.Readme.md](synthfs.Readme.md)), is handed the rest of the path in one call, since its namespace is a table classified by string. A `..` that would climb above its root answers `VFS_CLIMB` with the rest from that `..`, and the walk takes the `..` at the mount's root as at the root of any other mount: at a bind over a directory it is taken again at the covered directory, so `/mnt/x/..` is `/mnt` when `/proc` is bound on `/mnt/x`. A `..` first at that root is not handed to the type (`climbs`). A rest that comes back to the root directory in front of the name of a nameless mount there answers `VFS_ROOT`, and the walk enters that mount, so `/dev/pts/../shm` is `/dev/shm`; a nameless mount named first at such a root is entered before the type sees the rest (`named_in_rest`). Four links of these types are followed to the object they refer to, as Linux follows them, and not by their text. `/proc/PID/exe` goes on at the program file the process's address space keeps (`walk_exe`). `/proc/PID/fd/N`, with `/dev/fd/N`, `/dev/stdin`, `/dev/stdout` and `/dev/stderr`, and `/proc/PID/cwd` and `root` go on at the file or directory a descriptor is open on, or the process's working directory or root (`walk_object`, with `procfs_link_target` in `procfs.c`): the type answers `VFS_LINK` for a rest that goes on past one, with the rest after it, so a `..` after the link climbs from the directory; the last component of a parent walk is followed the same way, and `cwd` and `root` also at the last component unless `VFS_WALK_NOFOLLOW`. A `/proc/PID/fd/N` at the last component stays the link's node, which the system call layer opens and reports itself. Each moves to the root of the object's mount, taking its lock for a locked walk, and reads the object again once there, since the wait may let it move or the descriptor close; it does not cross a mount over the object, as Linux crosses none there, and a component after it gets the search check even on the way to the working directory. A jump uses up a component of the path, so a chain of them ends, and none counts toward `VFS_LINK_MAX`. Another process's link needs a caller that may read the process's memory (`EACCES`), a descriptor on a pipe, a socket or a device is `ENOTDIR` before more of a path, and one not open is `ENOENT`. A directory of `/dev`, `/proc` or `/sys`, and a working directory there, has no node, and the walk goes on from its path as from an absolute link's target. `/dev/log` is followed by the text `readlink` gives. The path a description records for `/proc/PID/fd` to show names the object and not the link (`path_expand_links` in `syscall_fs.c`), and so does the working directory's.

`vfs_resolve_real` is the same walk from the caller's root, which also records the path it took to the node: each name it looks up or enters is appended, each `..` it takes drops the last, and a symbolic link it follows is dropped for its target, an absolute one starting the record again at the root. That is realpath(3)'s answer, and `execve` names its program by it ([Readme.md](Readme.md)), since it is taken from the walk that found the node and a second walk could meet a link replaced in between. What a synthetic type uses up is recorded as the text of the path, so a link there that refers to an object, such as `/proc/self/cwd`, stays a name. A record that would pass `VFS_PATH_MAX` is given as an empty string.

`VFS_WALK_PARENT` stops before the last component and returns the parent, its search permission checked, with the leaf copied out; create, unlink, mkdir, rmdir and rename start there. `VFS_WALK_LOCK` takes each mount's namespace lock before its lookups, releases it when the walk crosses to another mount, and returns with the last mount locked, all only for a type that sets `ns_serialised`; the caller releases it with `vfs_walk_unlock` once its description is registered or its change made. A walk that meets a mount whose device has gone answers `EIO`, and so does one that ends on such a mount, except the walk of `umount2`.

`vfs_resolve_scoped` is the walk of openat2(2), which `struct vfs_scope` gives its RESOLVE_ flags, its anchor (the directory the call names, held, with its real path) and the tree's sequence when the call began. A relative path starts at the anchor; under `BENEATH` an absolute path, an absolute link and `..` at the anchor are `EXDEV`, and under `IN_ROOT` the anchor is the walk's root, so that an absolute path or link starts there and `..` there stays there. `NO_SYMLINKS` makes every link the walk would follow `ELOOP`, `NO_MAGICLINKS` every link of `/proc` to an object (a descriptor, a working directory, a root, a program or a namespace), and a scoped walk answers such a link `EXDEV`. `NO_XDEV` is `EXDEV` at any step onto another mount. `CACHED` looks each name up in the name cache alone (`dcache_lookup_cached`): a name the cache does not hold on a type that keeps its names there, or any name on a type on a device that does not, is `EAGAIN`; a type of no device, tmpfs and the synthetic ones, answers from memory. `VFS_WALK_CREATE` lets the last name be missing, for `O_CREAT`: the walk then returns `VFS_MISSING` with the parent held and the name copied out. An anchor inside a synthetic type, which takes the rest of a path from its mount's root, is reached by its real path from the caller's root, with the path's `..`s applied in the text first (`scope_text`, `WALK_SYNTH`).

The tree's sequence (`vfs_tree_seq`) moves at every rename, before and after it (`vfs_tree_changed`), and at every change of what is mounted where. A scoped walk's `..` is `EAGAIN` once it has moved since the call began, as Linux answers a rename or a mount racing such a walk, since the `..` may then climb past the anchor by a path that no longer holds. openat2 opens the file by the real path its checked walk recorded, with no `..` and no link in it but a link of `/proc` to an object the flags allow, through the ordinary open, as a replay (`vfs_replay`): a walk of the replay that meets another link, or that ends after the sequence has moved since the checked walk began, is `EAGAIN`, so the open never reaches a file the checked walk did not. The system call then walks again, four times in all ([openat2(2)](../../../man/man2/openat2.2)).

A walk that records nothing, has no scope, replay or parent and makes nothing first tries the path from the name cache alone, without the big lock (`resolve_cached`), as Linux first walks a path under RCU and walks it again with references when that fails (`filename_lookup`, fs/namei.c:2651-2653). It starts at the caller's root, read under the root's lock, or at the `start` the caller holds, and takes each step only on a mount of a type that sets `name_cache` and `reads_unlocked` and not `ns_serialised`, ext2 alone, since it calls the type's `getattr`, `hold` and `put` without the big lock (`walk_cacheable`): the search check, which reads the held directory alone, then the name's cached entry (`dcache_lookup_hit`), whose node it holds, and the type's `getattr` of that node for a link. A link whose target the node holds (`readlink_cached`, ext2's fast link) it follows, as Linux's walk under RCU reads `i_link` (fs/namei.c:1860-1870): from the caller's root for an absolute target, whatever slashes the spliced path begins with, as Linux's `pick_link` calls `nd_jump_root` (fs/namei.c:1877-1882), and from the link's directory for a relative one. A directory a mount covers it leaves for that mount's root, and for the root of each mount over that in turn (`cached_cross`), as Linux's `__follow_mount_rcu` does (fs/namei.c:1521-1563): it finds the mount the caller's namespace sees in the table under the table's lock and enters it there, as it takes the root mount. A namespace's view is read from the first word of the mount's set alone (`vfs_mount_seen_word`), since its other words grow under the big lock. A nameless mount it enters by its name from its parent's root, as the full walk's `mount_named` does, found in the table under the same lock (`cached_named`), and crosses the mounts over its root, as the full walk's `walk_enter` does, so that a trial boot's `/data`, the old root left nameless under the image's, stays off the big lock. It keeps the directories it came down through, held, up to 24 (`struct cached_dots`), and climbs a `..` to the one it came from (`cached_dotdot`), as Linux's walk under RCU climbs to `d_parent` (`follow_dotdot_rcu`, fs/namei.c:1968-2006): from a covering mount's root to the directory the covered one is in, crossing the mounts over it, from a nameless mount's root to its parent's root, crossing the mounts over it, and at the caller's root or the root mount's root it stays, as `dotdot_stays` says. The directory kept is the parent while no unlink or rename has begun since the walk started (`vfs_name_seq_still`), as Linux checks the child's `d_seq` (fs/namei.c:1994); so Wine's `dosdevices/c:`, a link to `../drive_c`, is followed without the big lock. A negative entry answers `ENOENT` at once. A `..` after a change of names, after the root moved or above the directories kept, a name the cache does not hold, a failed search check, which the full walk may excuse on the way to the working directory, any other link, a mount being made or unmounted, a caller whose mount namespace has an id above 31, and a gone device each end it with what it held let go of, and the full walk takes the path whole under the big lock (`resolve_full`), so every path the cached walk finishes has the answer the full walk gives. It drops each hold that is not the last without the big lock (`put_unless_last`) and takes the big lock for any other. The name cache counts its hits once it finishes, so a path walked again counts each name once.

The synthetic lookup returns `/proc/self` as a text link before reading the rest of its path, so `RESOLVE_NO_SYMLINKS` refuses that traversal too. A scoped walk checks search permission at its anchor and every directory below it, even when their names match the caller's working directory.

### The name cache

`dcache.c` keeps the resolver's lookups on a type that sets `name_cache`, so that a warm path is walked without reading a directory. An entry is one name in one directory of one mount's base: a positive entry holds the node the name found, through the type's `hold`, and a negative one records that the name was not there. Every entry holds its directory as well, so that no directory's address is reused while an entry names it. The cache keeps at most `DCACHE_LIMIT`, 8192, entries in a hash of 4096 chains, and gives back the least recently used. `.` and `..` are never kept: the first costs nothing, and the second changes when its directory moves.

The cache answers after `may_search` has judged the directory, so an entry lets nobody through who could not search there, and a change of a directory's mode needs no forgetting. Each namespace wrapper forgets the names it changes after the type's call, whether or not it succeeded: `create`, `mknod`, `mkdir`, `symlink` and `link` their new name, `unlink` and `rmdir` the old one, and `rename` both. A wrapper that removes a name forgets it before the call as well, and `rmdir` and `rename` forget then every entry in the directory the removed name names (`dcache_forget_victim`), and again after the call, so that the type finds none of the cache's holds on what it removes: ext2 frees such an inode at once, and not at the cache's last put, which would first drain its batch of writes. An unmount forgets the mount's entries once its operations have drained and before the type is written or let go; a bind's entries are its base's.

A lookup that sleeps in the type while a mutator runs could bring back the name as it was. Each forget moves a generation count, and a lookup that finds it moved since it began keeps its answer out of the cache. An entry's `put` takes its mount's namespace lock, so an entry given back while the caller holds another mount's lock is put later, at the cache's next call from a caller that holds none (`vfs_ns_held_other`), as the buffer cache passes over a victim whose writeback would take another mount's lock.

The cache's lists, counts and generation are under its spinlock, `dcache_lock`, which is held only while they change or a found node gains a hold, so a type that sets `name_cache` has a `hold` that takes no lock. `dcache_lookup_hit`, the cached walk's lookup, takes nothing else and does not sleep; every other entry point runs under the big lock, since it calls the type's `lookup` or `put`, which may sleep, and puts an entry only once it has left the lists.

`/proc/stat` gives the counts: `namecache_hits` and `namecache_misses`, the lookups the cache answered and those it passed to the type, each a read of a directory, since boot; and `namecache_entries` and `namecache_negative`, the entries now and the negative ones among them.

### Roots and working directories

A process's root is `root_mnt` and `root_node` in its `struct fs_struct`, which `CLONE_FS` shares with the working directory and the umask; NULL is the root of the mount table. `vfs_root_set` holds the new root and counts a reference on its mount, stores it, and only then lets go of the old one, whose put may sleep, so a thread sharing the record always finds one of the two. The record's spinlock, `lock`, covers the stores of the root and of the working directory, which change under the big lock as well, so that the cached walk reads the root and holds it under that lock alone, as Linux's `set_root` reads `fs->root` under its sequence (fs/namei.c:943-965). `vfs_root_copy` gives a child of `fork` its parent's root, and `vfs_root_clear` lets go at exit. The resolver uses the root in three places: an absolute path starts there (`walk_root`), an absolute link target restarts there, and `..` stops there (`dotdot_stays`). A walk keeps the root it started from. When a thread sharing it changes root while the walk sleeps, the walk sees that at its next `..` or absolute link (`root_current`) and starts over, so no walk judges one path by two roots.

The working directory is `cwd_mnt` and `cwd_node` beside the path the process record keeps; `vfs_cwd_set` takes its hold and its reference in the same order. `/dev` and `/proc` take neither. Since KRFFS counts no holds on its nodes, `rmdir` would free a directory that a process record still refers to: `vfs_leaf_root` answers `EBUSY` for a directory that is any process's root or the root of a bind, and a KRFFS volume looks for a working directory itself ([krffs.Readme.md](krffs.Readme.md)). `fchdir` to a directory outside the root, as a sandbox enters its old root after `pivot_root`, keeps the path from the root of the mount table with a second `/` in front (`cwd_outside` in `syscall_fs.c`), and a relative path walks from there, as a `//` path walks from the root of the mount table; `getcwd` then fails with `ENOENT`. A directory of `/dev`, `/proc` or `/sys` cannot be a root, since the resolver could not stop `..` inside a type that takes the rest of a path in one call; [chroot.2](../../../man/man2/chroot.2) has the contract and its one exception, `/proc/PID/fdinfo`.

### mount, binds and umount2

`vfs_do_mount` resolves and holds the target and checks it (`target_check`). Then, under the parent mount's namespace lock, so that no namespace change runs between the check and the reservation, it refuses a covered or reserved target, resolves the source to a device and claims its sectors (`mount_source`), and takes a slot as `VFS_MOUNTING` (`mount_place`), which keeps the covered node's hold and counts a reference on the parent. The constructor runs under the new mount's own namespace lock and may sleep on the device; the mount becomes active only when it succeeds. A failure releases what the steps before it took and drops from the cache every buffer of the device the constructor read (`mount_refused`), since a program such as mkfs may write the device past the cache before the next mount. A device that refuses writes makes the mount read-only whatever the flags ask. The target is recorded by its path from the root of the mount table, which `vfs_node_path` rebuilds from the node the walk reached, so a target named through a link, with `..`, or from a root `chroot` gave, is recorded where it is. A new mount is seen in the caller's mount namespace and in the namespaces made from it later. The root of a mount, the root of the mount table excepted, is a target like any other, and a mount placed there stacks on it, as on Linux: the walk crosses every mount on a node, the one placed last at the end (`walk_cross`), and `/proc/PID/mountinfo` lists mounts in the order they were made (`seq`), so that the one on top comes later. The root of a bind of `/dev`, `/proc` or `/sys` takes a mount too, which is how bubblewrap mounts a tmpfs over its own `/dev`, and a mount of `devpts` is a view of the system's `/dev/pts` (`synth_mount_root`).

`vfs_remount`, for `MS_REMOUNT`, gives an active mount new flags. A caller without privilege over the whole system may remount only a bind, with `MS_BIND`, that no other live mount namespace sees (`vfs_mount_shared`), and may add `MS_RDONLY`, `MS_NOSUID`, `MS_NODEV` and `MS_NOEXEC` but not clear one, as Linux locks those flags of the mounts a user namespace inherits (`remount_at` in `rach2/sys/syscall_fs.c`). A change between read-only and writable goes through the type's `remount`, which only ext2 and tmpfs have; a type without one refuses that change with `EINVAL` and takes the other flags. A mount whose device refuses writes, or has failed one, is not made writable (`EROFS`).

A bind (`vfs_do_bind`) is a record whose base (`bind_of`) is the mount whose file system it shows, never itself a bind. It has the base's type, device and private state, and its own root (the source directory or file, held for its life), place and flags, the flags copied from the source's mount. Every wrapper passes the base to the type, and a bind's namespace lock is its base's, so a type never sees a bind and two mounts of one file system serialise as one. A file is the same file by its inode number on the base (`vfs_mount_base`), which is what record locks, inotify, FIFOs, socket files, shared mappings and the device `stat` reports go by. A write through a bind is refused when the bind or its base is read-only, and `MS_REMOUNT` with `MS_BIND` changes the bind's own flags (`vfs_remount_bind`). The base counts the bind among its references. `..` at a bind's root climbs to the directory it covers, and `vfs_node_path` gives a path below the bind's place, or `ENOENT` for a node outside the tree it shows. With `MS_REC`, `bind_below` places a bind of each mount the caller sees below the source, shallowest first, each under the bind of its parent, and leaves out, with a log record, a KRFFS volume and a mount whose new path would be longer than 255 bytes. A bind of a place inside a synthetic type resolves below its root under the place's path within the type (`synth_lookup_rest` with the bind's root path), as bubblewrap binds `/proc/sys` read-only over itself and device files of `/dev` onto the `/dev` it builds; its path is the walk's record, which must name the node the walk found (`synth_names`), and `/proc/PID/fd/N` is refused. Inside a synthetic type a bind's target is the root of a mount that is not permanent, or a name in the root directory of any mount of one (`synth_root_child`), over which the bind is a nameless mount entered by that name, as `/dev/shm` is; a deeper place would be passed over by the type's lookup of the rest. A file of `/proc` opened for writing, and a place of it that access(2) asks to write once the permission allows it, through a read-only mount are `EROFS` (`proc_read_only` in `syscall_fs.c`), but for `/proc/PID/fd/N`, which leads to a file of another mount; `/sys` is mounted read-only though its attributes take writes, and keeps them. A directory of a synthetic type opened through a mount other than the system's `/dev`, `/proc` and `/sys`, a bind or a proc mounted in a sandbox's root, keeps the path that reached it, from the root of the mount table so that a later `chroot` does not move it, which `/proc/PID/fd/N` shows from the reader's root and the `*at` calls resolve names against from the caller's (`synth_dir_record`), as bubblewrap reads the link to find its mount in mountinfo. A bind of a file covers a file and a bind of a directory a directory (`ENOTDIR`); the source and the target are recorded by the paths they resolve to (`vfs_resolve_real`, `table_path`), so that a bind over a symbolic link covers the file it names, and `vfs_node_path` of a bind's root is its covered path, with no walk of the file system for a file. A bind of a KRFFS directory follows the directory when its node moves (`vfs_repoint`).

`vfs_do_umount` finds the mount by a walk that may end on a mount whose device has gone. When an ancestor's device has gone the walk answers `EIO`, and the mount is found instead by its recorded path (`unmount_below_gone`): the target, made a path from the root of the mount table by putting the path of the caller's root in front of it (`unmount_target`), must equal the covered path of exactly one active mount below a gone ancestor. A target that ends in a slash, `.` or `..` must reach a directory, and the node checked is the node unmounted. A mount that another live namespace sees is hidden from the caller's namespace and stays.

The unmount itself (`unmount_mount`) sets `VFS_UNMOUNTING`, which refuses new work, waits for the operations in progress to drain, and answers `EBUSY` while `refs` is not zero. A bind ends there: its root and covered node are put and its parent and base let go, with nothing written. For any other mount, under its namespace lock, the type's `sync` and `prepare_unmount` run, the cache writes the device's dirty buffers (`bcache_sync`), the device flushes its own cache (`bcache_flush`, [../block/Readme.md](../block/Readme.md)), and the cache drops the device's buffers (`bcache_invalidate`). `prepare_unmount` writes the volume's last metadata into the cache and dismantles nothing, so up to here the unmount can be abandoned: a failure returns the mount to `VFS_ACTIVE`, and a failure from the writeback on also calls the type's `abort_unmount`, which puts back what `prepare_unmount` wrote (KRFFS sets its dirty flag again, ext2 clears its valid bit). Then the record is logged, the root put, inotify and the file cache told, the type's `unmount` frees its state, and the covered node, the parent's reference, the claim and the slot are released. A device that has gone takes nothing, so the sync, the preparation, the writeback and the flush are skipped for it. When a mount namespace ends, `vfs_mntns_gone` unmounts, child before parent, each mount only that namespace saw. The root is never unmounted; the shutdown prepares it instead, with the type's `shutdown` when it has one, which closes the volume to writers and waits for them until a deadline, since a `file_locked` type's writers take no namespace lock, and otherwise with its namespace lock taken for good and `prepare_unmount`.

A lazy unmount, `umount2` with `MNT_DETACH` (`vfs_do_detach`), finds the mount as `vfs_do_umount` does and hides it from the caller's namespace at once, however busy it is, with every mount whose chain of parents meets it before it meets the mount of the caller's root (`detached_by`): the caller's root and what is below it stay, so that after `pivot_root` the old root can be let go of while the new one, which was below it, is in use. A permanent mount may be hidden and stays mounted; the root of the mount table is `EINVAL`. A mount no live namespace sees and nothing holds is unmounted by `vfs_reap_detached`, which runs after a lazy unmount, at the end of a namespace, and when the last description or hold on such a mount goes (`reap_if_detached`), until a pass unmounts nothing more, so that a child goes before its parent. It reads the live namespaces again for each mount it weighs, as `vfs_mntns_gone` does, since an unmount may sleep while a namespace is made and a mount made in it.

`pivot_root` (`vfs_pivot_mounts`) takes the root of a mount as the new root and a directory at or below it as `put_old`, and requires the caller's root to be the root of a mount. With `MS_REC`'s walk (`bind_refs`, `bind_below`) it shows the old root at `put_old` with the mounts below it but the new root and those below that, and hides from the caller's namespace the originals below the old root except the new root, the mounts it is below and those below it, and the permanent ones; Linux moves them instead. With `put_old` the new root itself, as bubblewrap calls it with `.` and `.`, nothing is shown or hidden: Linux stacks the old root over the new one, and the caller lets go of it with `fchdir` to a descriptor of it and a lazy unmount of `.`. `sys_pivot_root` then gives the new root to every process of the caller's namespace whose root was the old one, and keeps each one's working directory in place (`pivot_one`).

### Selected file names

An inode can have several hard links, so its first reconstructed path need not be the entry an open or exec selected. `vfs_resolve_entry` records the parent directory and final regular-file leaf during the same lookup that found the file, after following symbolic links, and with a `dir` buffer the attributes of the directory the last name was looked up in, Linux's `nd->dir_mode` and `dir_vfsuid`, which `may_create_in_sticky` judges. A file bound over that leaf is the bind's root on another mount, so a walk that crosses a mount at its last name records no entry, and the file's path is the bind's place (`vfs_node_path`), as Linux's `d_path` gives a mount's root. `name.c` and `name.h` keep that entry for types with counted node holds. The record owns the parent node and one mount reference. Ordinary opens, O_PATH and creation transfer it to the open description; fork shares that description, and an exec or reopen through a descriptor shares its name record. The last reference releases both parent and mount. The old `dirpath` string remains available to interfaces that need their original path spelling.

The list of records and each record's count are under `names_lock`, a spinlock, so that an open and a last close without the big lock make and end a record (`vfs_name_capture_at`, `vfs_name_put`); a record's parent, leaf and deleted mark change under the big lock alone, while the record is held, and the walks that change them hold the spinlock or a reference to each record they reach. With `entry` given, the cached walk records a regular file's entry at its last name as the full walk does (`cached_entry`). An unlink and a rename bracket their change, from the name cache's first forget to the records' update (`vfs_name_change_begin`, `vfs_name_change_end`), and a record whose walk began before a bracket that is open or has closed since is refused and the walk goes to the full walk, since the walk may have found the name before the change and the update passed the record by, as Linux's walk under RCU retries when `rename_lock` moved (fs/namei.c:2071, 2501).

Successful unlink marks only that entry deleted, even when another hard link remains. Successful rename moves the selected entry and marks a replaced entry deleted; a rename between names of the same inode changes neither record. The records stay held while an old-parent release can sleep. Parent directory renames need no string updates: the held directory's path is reconstructed, then the selected leaf is appended. A bind view that no longer contains the parent uses its underlying mount's path. Procfs converts the complete path to the reader's root after releasing the file's namespace lock. It never chooses another inode alias for a recorded entry. Mount and bind roots are directories here and cannot be executable entries. KRFFS types have no hard-link operation or counted vnode holds and retain their existing per-node paths and pins.

### Claims

A claim (`devfs_claim` in `devfs.c`) is a mount's sector range on the physical disk under its source, taken before the constructor runs and released at the unmount. There are eight (`DEVFS_CLAIMS`); a mount that finds none free answers `ENOMEM`. Ranges are compared on the disk `block_physical` reaches and never by the device they were named through, since `/dev/bootpart`, `/dev/disk0p1` and `/dev/disk0` can describe one range. While a range is claimed, a second mount overlapping it and a write-capable open of a raw window over it answer `EBUSY`, and while such a window is open, a claim of its range answers `EBUSY`. This is how a mounted boot partition and `bootctl` exclude each other ([synthfs.Readme.md](synthfs.Readme.md)). A loop device has no range: the device is the identity, and one mount at a time may use it. A source device that already has a mount is `EBUSY`.

### Locks

The VFS changes its state under the kernel's big lock ([../proc/Readme.md](../proc/Readme.md)), which the file calls that enter without it take for every step on a file of a mount ([Readme.md](Readme.md)), so a process finds a namespace lock, a description or a buffer held only while its holder sleeps for the disk. What a call may read without that lock has a lock of its own. The sleeping locks come in this order: an open file description's lock, then the rename lock, directories and nodes of a `file_locked` type, then a mount's namespace lock, as Linux takes `f_pos_lock` (fs/file.c:1167) before `i_rwsem`; then buffers of the cache by the cache's rules. The spinlocks come after every sleeping lock, are taken with interrupts off, and none is taken under another but a wait queue's lock, which a wake under them takes, and the run queues' lock under that:

* a descriptor table's `lock` and the description list's `ofd_lock` ([Readme.md](Readme.md));
* `mount_table_lock` in `vfs.c`, over the array of mounts, its length and what each slot holds: a growth makes the new array before it takes the lock and frees the old one after, an unmount frees a record only once its slot is empty, and a record's fields change under the big lock alone, so a reader under this lock sees a mount being made or unmade either way;
* a process's `fs_struct` `lock`, over its root and working directory;
* `dcache_lock`, over the name cache;
* `cache_spin` in `bcache.c`, over the buffer cache's index and lists ([The buffer cache](#the-buffer-cache));
* `names_lock` in `name.c`, over the list of name records and their counts ([Selected file names](#selected-file-names)).

A mount's `refs`, `inprogress`, `opens` and `releases`, a description's reference count and an ext2 node's holds change in one atomic step, and a description that ends without the big lock takes it to reap a detached mount it was the last to hold (`reap_if_detached`): the put's own count decides, and the mount is read only under the big lock and once the table still has it, since an unmount or another closer may free it as soon as the count is 0, as Linux's `mntput_no_expire` decides under `lock_mount_hash` (fs/namespace.c:1405-1430). The unmount stores `VFS_UNMOUNTING` with a full barrier before it reads `inprogress`, and `vfs_enter` counts before it reads the state, so a walk that enters a mount being unmounted leaves it, as Linux's `__legitimize_mnt` pairs with `mnt_make_shortterm`. The operations of a description type that sets `FILE_OPS_UNLOCKED` ([Readme.md](Readme.md)) run without the big lock, and so do the cached walk and the operations of a type that sets `reads_unlocked` that nine calls make: read, pread64, fstat, fstatat64, newfstatat, open, openat, getdents64 and close, and of a type that sets `writes_unlocked` that seven more make on a regular file: write, pwrite64, writev, ftruncate, fallocate, fsync and fdatasync, as `unlock_file_calls` in `syscall.c` marks them ([Readme.md](Readme.md)); every other step of those calls, and every other call that resolves a path, takes it.

The namespace lock (`vfs_ns_lock`) is taken by every namespace change on a mount, by its constructor and its unmount, and by a writing type around its data operations, so every change to a volume runs under one lock. It is a sleeping lock (`sleeplock.c`), the mount's `ns`, which a bind shares with its base. A caller takes a place in line (`next`) by compare-and-exchange and waits until its place is served (`serving`), which the last give advances by an exchange, so a writer that locks for each call cannot take the lock back before a waiter has had it, and a take and a give with no one in line pass no spinlock, as Linux's uncontended `mutex_lock` and `mutex_unlock` are one atomic operation each. A waiter spins while the holder runs, the current thread of the processor it took the lock on, not halted there and not preempted by the hypervisor, and sleeps otherwise (`sched_spin_on`), as Linux's mutex spins on its owner (kernel/locking/mutex.c:350-385): a hold is often shorter than a sleep and a wake, whose interprocessor interrupt is an exit for the sender and an injection for the receiver under a hypervisor. It spins on while the lock passes to a waiter ahead and no waiter sleeps, and not at all while it holds the big lock and another processor has claimed that or the holder's processor waits for it (`bkl_spin_ok`). The holder may take it again (`depth`), since a type's operations lock for the callers that arrive unlocked and are also reached under the lock, and a give by a thread that does not hold the lock panics. A signal does not end the wait: a waiter that retried without sleeping would never let the holder run. An unmount waits for the operations in progress on a queue of its own, `drain_wq`.

The system calls lock a file or a directory through `nodelock.c`, which takes the type's node lock on a `file_locked` type and the mount's namespace lock on every other, so that a type keeps its behaviour until it sets the bit. `vfs_node_lock` locks one node, the mount's root for a reference without one; `vfs_child_lock` looks a name up under its locked directory and locks the node it names; `vfs_cover_lock` locks a mount's target and answers `ENOENT` once the directory has no links, so a mount and the `rmdir` of its target exclude each other on the target's lock. A `file_locked` type is locked in this order: the mount's rename lock (`rename`, which a bind shares with its base), then directories, an ancestor before its descendant and unrelated ones by inode number, then other nodes by inode number. `vfs_rename_lock` takes the rename lock only when the two directories differ, finds which is the ancestor by walking `..` up from each, locks both directories and both children, and looks the two names up again under the directories' locks, starting over if either names another node. A call that sleeps while the lock is held makes its checks again under it: write permission and search on the directory, a mount on the name, the caller's root, presence, and `RENAME_NOREPLACE`'s target (`dir_recheck` in `syscall_fs.c`). A write holds its file's lock across the size read of `O_APPEND` and the write; when the type answers a short count at a page that is not resident, the write gives the lock back, faults the page in, takes the lock again and goes on, up to eight times; under `O_APPEND` it goes on at the file's end as it is now, cut again to what RLIMIT_FSIZE lets through. A truncation calls `filemap_file_truncated` before the lock is given back. The name cache's puts that were put off while a file lock was held are made at the last file lock's give (`dcache_drain`).

A process counts the disk waits it has finished in the block layer (`disk_waits`, [../block/Readme.md](../block/Readme.md)). While `sleep_lock_stat`, the sysctl `kernel.lock_stat`, is on, a sleeping lock keeps the count and a stamp of the time at its first take; it is off at boot, so that a take reads no clock, which is Rach2's choice: Linux built with `CONFIG_LOCK_STAT` has its lock_stat on from boot (kernel/locking/lockdep.c:75, :94). A timed hold during which the count moved crossed a disk wait: at its last give the lock counts it in its kind's record (`struct sleep_lock_record`), which keeps the longest such hold in microseconds with its holder's thread ID and name; a hold is timed by the processor's counter where its rate was measured and every processor's counter agrees with the boot processor's (`timer_cycles_agree`), and by the clock elsewhere, as Linux's lock_stat falls back from the TSC through `local_clock`; `sleep_lock_records` lists the kinds, the mounts' lock among them as `mount`, and `/proc/fs/lockwait` shows each, as proc(5) gives. A lock made with `SLEEP_LOCK_FILE`, a file's or an allocator's, also counts in its holder's `file_locks` for the length of a hold. `vfs_ns_held_by_caller` is true while the caller holds a mount's lock or a file lock, and lets the buffer cache pass over a victim whose writeback would take another mount's lock; `vfs_ns_held_other` is true while it holds a file lock or another mount's, and makes the name cache put its entries later.

### The buffer cache

`bcache.c` keeps blocks of 4 KiB, eight sectors each, for the disk file systems that are mounted: FAT32, exFAT, ext2, as a mount or as the root, and KRFFS volumes. A KRFFS root on a disk goes through the page cache instead ([../mm/Readme.md](../mm/Readme.md)). The operations are those of Lions' commentary: get a block and hold it, release it, mark it dirty, write it through, write a device's dirty buffers, and drop a device's buffers.

A read of a regular ext2 file comes first from the file page cache, which keeps whole pages of the file in free frames past this cache's limit, and only a page it lacks is read through the type's `read` and so through this cache ([The file page cache](../mm/Readme.md#the-file-page-cache)). `vfs_write`, `vfs_truncate`, `vfs_fallocate` and `vfs_setattr` with a new size drop the file's pages from it after the type's operation, and an unmount every page of the mount's files, so a read after any of them reads the file as it is.

A buffer (`struct bbuf`) is a record and a page of the heap, made when it is needed. The cache makes at most the smaller of half of what the caches together may keep under memory pressure (`mem_cache_target`, a quarter of the frames) and half of the kernel heap's pages, and never fewer than `BCACHE_MIN_BUFFERS`, 16. On i686, whose heap is 256 MiB, the cache has at most 32768 buffers; [../mm/Readme.md](../mm/Readme.md) gives the heap's size on each architecture. The last block of a device whose sector count is not a multiple of eight has only the sectors that exist.

Every buffer is on the list of all buffers, linked both ways. A keyed buffer is also in a hash index by device and block and on a list in release order; an empty one is on the list of empties, a dirty one on the dirty list, and a held one on its holder's list (`bcache_held` in the process record). So a get, a choice of victim, a sync and a shrink read the few buffers they need and not the whole cache. `cache-visits` counts the buffers these walks read, and `bcache_cost_hosttest.c` keeps it under bounds.

The index has a bucket for each buffer the limit allows, so that a bucket holds one buffer on average when the cache is full: 32768 buckets for 32768 buffers, where a fixed 4096 would give each bucket eight on i686 and some 64 on a machine of 8 GiB. It starts with 4096 buckets in the kernel's data, which need no heap at boot, and when the buffers outnumber them it moves to a table from the heap of the limit rounded up to a power of two, at most 2^22 buckets (`index_fit`); a heap with no room leaves it as it is until the buffers have doubled. The move goes a bucket of the old table at a time, and a lookup meanwhile reads the old table for a bucket not yet moved and the new one for the rest, as Linux's rhashtable moves to a new table (lib/rhashtable.c:319-355); the new table is taken and the old one given back with `cache_spin` let go. A block's bucket is its number, so consecutive blocks have buckets of their own, moved by the top bits of the product of its device's address with the golden ratio's fraction, so that two devices' blocks fall in different places.

A miss keys and holds a buffer before it reads the block, so a second process asking for the block waits for that buffer instead of filling another. The buffer is an empty one, else a new one while the cache is under its limit, else the least recently released one nobody holds; a dirty victim is written first, and one whose last write failed, or whose write the caller's holds would not allow, is passed over. A buffer passed over goes to the tail of the release order (`victim_find`), so that the next miss does not read it again before every buffer ahead of it has been taken or passed over: a miss at the cap reads the buffer it takes and those it passes over, and a buffer that stays unfit, as one on a device that fails its writes does, costs a read for each turn of the cache and not one for every miss. The search reads 32 buffers at a time and lets `cache_spin` go between, and a turn ends once it has passed over as many buffers as the cache has. A buffer let go meanwhile may have been passed over and gone to the tail fit, so a turn during which a buffer a miss may take was let go, clean or dirty with a write that is not barred, or a fill ended the keep of a clean one, is progress and is followed by another, as is a dirty victim's write; a release of a buffer whose write is barred is not progress, and a turn without progress is retried 16 times in a row before the miss fails (`fit_gos`, `victim_any`). Linux counts the reclaim loops that made no progress, sets the count to 0 after one that made some, and retries `MAX_RECLAIM_RETRIES`, 16, of them (mm/internal.h:460-464, mm/page_alloc.c:4179-4185), while its reclaimable pages, dirty file pages among them, could meet the watermark (mm/page_alloc.c:4206-4219); its getblk never fails (fs/buffer.c:1131-1140). Each turn ends by giving way (`sched_give_way`), which lets the cache's write lock, and the big lock where the caller holds it, go to a processor waiting for them, as `should_reclaim_retry` calls `cond_resched` before each retry (mm/page_alloc.c:4226-4233), so a write or a sync that would make a buffer fit runs between turns while readers keep a buffer busy. A search with interrupts off, as a fault's read in place inside such a call (`filemap_read`), does not give way, as Linux's `__cond_resched` tests `irqs_disabled` (kernel/sched/core.c:7289), and takes no write lock, which is a mutex: it takes only an empty or a clean buffer, and fails when its turns find none, as Linux reads nothing at all in a fault taken with page faults off (arch/x86/mm/fault.c:1270-1273). A miss at the block after the one last filled is a reader going through the device in order: the cache reads that block and the uncached whole blocks after it in one request, up to 32 blocks, what the device takes at once and half the cache's limit, through a staging buffer of 1 MiB (`fill_run`). 32 blocks, 128 KiB, is Linux's default readahead window at its most (`VM_READAHEAD_PAGES`, include/linux/pagemap.h:1375), and Linux's first window for a read of more than 32 KiB (`get_init_ra_size`, mm/readahead.c:361-372); the cache sees the pages of a read, not its size. A longer run reads what a program that takes small pieces of a large archive out of order, as a game reads its packs, never asks for. `bcache_get_blank` gives a block the caller will overwrite, zeroed and not read.

A held buffer is busy: another process sleeps on its queue until the release, uninterruptibly, and the wait is counted in `cache-waits`. A release wakes the queue before it lets `cache_spin` go, and only when a sleeper is counted in `waiters`, since once the lock goes a shrink may free a buffer whose waiters have left (`unhold_wake`), as Linux's `unlock_buffer` wakes while the holder keeps its reference and only a queue with a sleeper (fs/buffer.c:75-80, kernel/sched/wait_bit.c:121-127). Two rules keep holders out of deadlock, checked at every get: a process holds at most `BCACHE_HOLD_MAX`, four, buffers, and a buffer it takes must be of a higher block than every buffer it holds of the same device, and of a device below every other device it holds a buffer of, as a loop device's read of its file is. A release, a dirty mark or a write by a process that does not hold the buffer, and a sync by one that holds a buffer of the device, are defects too. The cache panics on each, so a file system that breaks a rule fails in the host test.

`cache_spin`, a spinlock taken with interrupts off, covers the index and each buffer's key, the release order, the empties, the list of all buffers, each buffer's holder, waiters, stamp and discard mark, and the state of the run being filled; it is let go before every sleep and every device request. A walk of the release order, the empties, the list of all buffers or the index's buckets lets it go every 32 buffers, and the reserve counts the empties by their number with no walk (`WALK_BATCH`, `walk_pause`), as Linux's LRU scan takes `SWAP_CLUSTER_MAX` pages at a time under `lru_lock` (mm/vmscan.c:5729) and its invalidate goes a batch at a time (mm/truncate.c:509-541), keeping the buffer it goes on from counted in `waiters` so that no shrink frees it. A buffer freed in a walk, and the index's old table, go back to the heap after the lock is let go, since a free of a page flushes every processor's translations. The cache's write lock, `wb_lock`, a mutex, covers the dirty lists and the order of writeback, so every dirty mark, write, sync, reserve, shrink's write and eviction of a dirty buffer, and no call of the cache needs the big lock. The lock is given up around every sleep, each request, each wait for a buffer and each service point, and taken again after, as the big lock it replaced was, so a step between two sleeps sees the lists whole and the step after a sleep looks again; nothing is waited for while it is held, and its place in the kernel's order is after a caller's sleeping locks and buffers and before `cache_spin` ([../proc/Readme.md](../proc/Readme.md#locking)). A buffer's dirty mark, failed write and level, and a device's failed-write mark and blocks written last, which a release reads under `cache_spin` alone, change under both locks, so a buffer nobody holds keeps its dirty mark while either is held. Linux takes no global lock to dirty a buffer either: `mark_buffer_dirty` sets the buffer's bit, the folio's under the mapping's `i_pages` lock and the inode's place on the writeback list under `wb->list_lock` (fs/buffer.c:1179-1210, mm/page-writeback.c:2789-2802, fs/fs-writeback.c:2654), and writeback lets `list_lock` go around each inode's write (fs/fs-writeback.c:2003-2016). A hit, and a miss that finds an empty buffer, room under the limit or a clean buffer nobody holds among the first 32 of the release order (`victim_clean`), take `cache_spin` alone, so a reader reads a cached block, or fills one the cache makes room for without a write, as Linux's `__getblk_slow` (fs/buffer.c:1117) finds and fills a block under the block device's own locks (fs/buffer.c:197-203). The fill's request takes no lock of the cache's: it waits on its own completion, as Linux's `submit_bio_wait` (block/bio.c:1469-1481), and the block layer takes no big lock for it, since every driver serializes on locks of its own (`device_read`, [../block/Readme.md](../block/Readme.md)). A miss that finds no clean victim there takes the write lock for its search, and a caller with the big lock takes it at once, past the empties and the room under the limit, as it always has; the search lets it go at the end of each turn of the release order and at each sleep, and before the miss's read. A failed write is recorded against the device's mounts under the big lock, which the cache takes for it when the caller runs without it, with the write lock let go (`device_failed`).

`bcache_write` writes a held buffer through before it returns, so the order in which a driver writes its metadata is the order in which it reaches the disk. `bcache_dirty` leaves the buffer to be written back at eviction, at `fsync`, at `sync` or by the flusher ([Readme.md](Readme.md)). An eviction, a shrink and a reserve write a victim without the disk's flush, as Linux's `pageout` writes a page, but a first, which keeps its flush. `bcache_dirty_ordered` gives a dirty buffer a place in its device's writeback: a `BCACHE_ORDER_FIRST` buffer reaches the device before a `BCACHE_ORDER_AFTER` buffer of that device whose last mark came after the first went dirty, whichever path writes. Each dirty mark is counted, and a buffer keeps the count at which it went dirty and the count of its last mark, so the cache knows what a block may have been written after. A sync writes the firsts in a pass of their own, and before an after the firsts it follows; an eviction or a reclaim that chose an after writes every first of its device before it, or passes it over while one of them is held, failed its write or waits itself. ext2 uses the marks ([ext2.Readme.md](ext2.Readme.md)).

The count of marks is also the cache's clock for write-back, since the cache reads no clock of its own. `bcache_writeback` writes a device's buffers that went dirty at or before a given count, in a sync's passes, runs and order and without the flush, and leaves a device whose write has failed to the next sync. The flusher (`writeback.c`) reads the count, `bcache_marks`, at each of its turns, at the first dirty buffer of a clean cache, which wakes it, and a 32nd of the expiry period apart while any buffer is dirty, and keeps 64 readings with their ticks; to write back what has been dirty for `dirty_expire_centisecs` it takes the newest reading at least that old, never a newer one, so no block is written before its period, as Linux's `wb_check_old_data_flush` writes the inodes dirtied before `jiffies - dirty_expire_interval` (fs/fs-writeback.c). `bcache_dirty_level` places the dirty buffers against the background threshold and the dirty limit, `dirty_background_ratio` and `vm_dirty_ratio` per cent of the cache's limit, or the byte counts when set, with the background threshold at half the limit when it is not below it, as Linux's `domain_dirty_limits` computes them (mm/page-writeback.c); Linux takes the ratios of the memory its page cache may grow into, and here dirty data can grow only into the buffer cache. A dirty mark that leaves the cache at or past the background threshold wakes the flusher, which writes back from its oldest reading forward until the cache is under the threshold; past the dirty limit a writer writes back itself, as `balance_dirty_pages` holds a writer there (`ext2_em_balance`). The cache's write lock serializes these writes with every other write of the device, so the order the marks promise holds whichever path writes.

`bcache_sync` writes a device's dirty buffers, the firsts in one pass and the rest in another, each in ascending block order, in runs of adjacent blocks of up to what one request moves, 256 blocks at the most. It waits for a buffer another process holds rather than pass over it, and answers the first failed write's errno with that buffer and the rest still dirty. A pass gathers its blocks in one walk of the dirty list into a batch kept as a heap: 128 blocks on its stack, or, with more dirty than that, up to 256 pages from the heap, which hold 131072 blocks. A sync owes only the buffers dirty when it began: one that goes dirty later is the next sync's, so a writer that never stops does not keep it. On a disk that makes each write durable before it answers (`BLOCK_WRITE_THROUGH`), the sync writes without the disk's flush and flushes once at the end, but writes a run of firsts with the flush, and has the disk flushed before a block that waits for others, an after or one of the blocks the next two paragraphs name, so that what it waits for is on the medium first. `bcache_write_unflushed` and `bcache_sync_unflushed` make the same writes without the flush, for a caller that flushes later.

A file system names the blocks that point at others with `bcache_sync_last`, and with its second callback which owners' blocks each may name. Such a block reaches the device, by any path, only after every dirty block it may name that went dirty before its last mark: one not of its class nor an after, shared or of an owner it names. A sync first writes the rest, with the afters while none of those blocks is a first, and writes those blocks only when that went well; whoever writes one holds it from the look that finds nothing left to wait for until its write ends, writing what it waits for first, so nothing is stored in it meanwhile and what it waits for stops growing. A failed write so keeps every such block that may name the failed one off the device, and the afters behind it. An eviction, a shrink or a reserve passes over such a block while it waits, and once a write of the device has failed writes none of them: not alone, not in another block's run, and not ahead of an after, which stays dirty while such a block is a first. A sync still retries them.

`bcache_dirty_pointer` marks a dirty buffer as a pointer block of an owner, shared with 0, at a level in the owner's tree, 1 for one that names data; `bcache_dirty_owned` makes it a leaf again, and the write clears it. Such a block reaches the device, by any path, only after every dirty block of its owner below its level that went dirty before its last mark, and is not an after or one of the blocks above: data before its pointer block, and a pointer block before the one above it. The cache treats it as it treats the blocks above: it is held while what it waits for is written, passed over by an eviction, a shrink or a reserve while it waits, and written by none of them once a write of the device has failed. Each kind of wait leads to a block of a higher rank, a level, then the blocks written last, then the afters, so the waits make no cycle.

`bcache_dirty_owned` tags a dirty buffer as a block of one file, by a nonzero number the file system chooses, or makes it shared again with 0; the tag lasts until the write, the last one given stands, and a plain dirty mark leaves it. A stale tag costs one needless write. `bcache_sync_owned` writes one owner's dirty buffers of a device in the two passes of a sync, in runs that hold only its blocks, so a dirty neighbour stays dirty and no request grows by it, and leaves the flush to the caller. `bcache_sync_block` writes one dirty block alone, for a shared block such as a bitmap, and `bcache_sync_block_ready` clears its way, so that a caller can check what it needs in the step that starts the write. Both write a block of the `after` class only once the firsts it follows are written, whoever dirtied them, and a block named by `bcache_sync_last` only once what it may name is written, and both write a `first` with the flush, since the caller's own flush comes too late for another process's `after`. KRFFS volumes call both at `fsync`, tagged by the file's open record ([krffs.Readme.md](krffs.Readme.md)). FAT32 and exFAT call `bcache_sync_owned` in their `write` and `fsync` ([fat32.Readme.md](fat32.Readme.md)). ext2 tags a file's data and pointer blocks by its inode number and calls both at `fsync` and `fdatasync` ([ext2.Readme.md](ext2.Readme.md)).

`bcache_reserve` is for a caller about to take many buffers under a short lock. With no file lock held, it writes the dirty buffers a miss would take, oldest first and in runs, until the next `n` misses of the device can have a buffer with no write: empties, room under the limit, and clean buffers at the head of the release order. It pins nothing, so it is a best effort; a failed write ends it, and it answers how many were ready.

`bcache_shrink` gives buffers back under memory pressure: the empty ones, then clean ones oldest first, then dirty ones written back, and never one a process waits for. The first two are one walk each, of the empties and of the release order, since freeing a clean buffer does not sleep; the third walks the release order from its head again after each write, which sleeps, and frees a written buffer only when it is still keyed, unheld and unwaited for, since a fill may have emptied it onto the empties while the write let it go, and a buffer is freed only off every list it is on, as Linux detaches buffers before it frees them (fs/buffer.c:2922-2933, 2999-3007). Each walk lets `cache_spin` go every 32 buffers, and the buffers it freed go back to the heap then; the walk of the empties goes on from the last buffer it passed over, and a walk of the release order ends where the buffer it goes on from has left the order meanwhile. `bcache_reserve`'s walk lets the lock go in the same way, and keeps the answer of its look for a held or failed first of a device across those pauses as a hint, which `write_firsts` checks again before an after is written.

### Failures

The cache handles a write that fails and a device that goes in one place, for every type above it.

A write that fails, through `bcache_write` or writeback, keeps its buffer dirty and calls `vfs_device_failed`, and so does a failed flush that FAT32, exFAT, a KRFFS volume or the VFS makes, since each goes through `bcache_flush`: every mount on the device goes read-only for the rest of its life, with a `vfs: read-only` record, and `/proc/mounts` shows `ro`, and each file system on the device records the error once in its write-back errors, however many binds show it, so that a sync between two records cannot report one failure twice. The cache answers the device's later `bcache_write` calls with `EROFS` until the unmount drops its buffers, so an operation that was in progress stops at its next metadata write. A write-back cache cannot return a later failure to the `write(2)` that dirtied the buffer, and a disk that has begun to refuse writes is not one to go on writing. A remount does not make such a mount writable. Its unmount still writes the dirty buffers, and a write that fails there leaves the mount in place. Ext2 flushes its device with `block_flush` itself, in its `sync` and `fsync`, its write-out of a node's shared blocks and its strict batch, and records a failed flush or write-out through `ext2_writeback_error` alone, which makes its own mount read-only and records the error in its write-back errors (`vfs_wb_err_set`, [ext2.Readme.md](ext2.Readme.md)). A buffer write of its device that fails goes through `vfs_device_failed` as well, as for any type, so that one failure may be recorded twice, as Linux's per-folio `mapping_set_error` may record one failed bio twice.

When the disk layer reports a device gone (`bcache_device_gone`), every mount on it goes read-only, every buffer of the device is made clean, one nobody holds is dropped at once, and a held one is dropped at its release, since a buffer cannot be given away under its holder. From then on every operation on those mounts answers `EIO`, `/proc/mounts` omits them, and an unmount writes nothing and only releases what the mount had, once nothing refers to it.

A sector torn in the middle of a write, or a write the disk acknowledged and lost, is outside what the cache can see; the volume's own check judges that afterwards.

## Limits

* There is no `MS_MOVE`, no forced unmount, no `UMOUNT_NOFOLLOW`, and no mount propagation.
* A mount is hidden from a namespace, not moved: after `pivot_root` the mounts of the old root are shown at `put_old` by binds, and a descriptor or working directory outside the root reaches a hidden mount by its path from the root of the mount table, as long as the path leads there.
* `pivot_root` needs the caller's root to be the root of a mount, as Linux does; a root `chroot` gave a directory is `EINVAL`.
* A mount target's path from the root of the mount table is at most 255 bytes, and the source string is recorded to 31 bytes.
* A mount of `devpts` shows the system's own `/dev/pts`: `newinstance` is not honoured, so a sandbox that mounts one sees every terminal of the machine, each under its own owner and mode.
* Nothing but a bind is mounted inside the system's `/dev`, `/proc` or `/sys`, and a bind only on a name in the root directory of one of their mounts, which it is entered by, as `/dev/shm` is. The root of a bind of one of them takes a mount. A bind of `/proc/self` follows the process that looks it up, not the one that made it.
* `MS_REC` does not show a KRFFS volume below the source.
* Through a bind of the KRFFS boot root a file's mode, owner and times do not change (`EROFS`), since the root changes them only through the system call layer's own paths.
* `sysfs` is not a type `mount(2)` finds (`ENODEV`), though its privilege check admits it.
* Only tmpfs updates an access time on a read ([Readme.md](Readme.md)); `MS_NOATIME`, `MS_NODIRATIME` and `MS_RELATIME` are recorded and shown and change nothing.
* A mount that went read-only after a failed write stays read-only until it is unmounted.
* The cache keeps no list of a mount's or an owner's own dirty buffers: a sync writes a whole device, and an owned sync reads every dirty buffer to find its blocks.
* openat2's `RESOLVE_CACHED` finds a name of KRFFS, FAT32 or exFAT in no cache, so it answers `EAGAIN` for every name on them past `.` and `..`, where Linux's dentry cache would hold one already looked up. A link whose target climbs with `..` from a directory of a synthetic type, under `BENEATH` or `IN_ROOT`, is `EXDEV`, where Linux may follow it inside the anchor. The replay's `EAGAIN` that four walks did not clear reaches the caller under any RESOLVE_ flag, where Linux gives it only under `BENEATH` and `IN_ROOT`.
* The cached walk takes a `..` only to a directory it came down through and before any unlink or rename since it began, and follows only a link whose target the inode holds, where Linux's RCU walk takes any `..` whose dentry has not moved and asks the file system for any other target under RCU, and crosses no mount for a caller in a mount namespace with an id above 31; such a path, and every path on a type other than ext2, goes to the full walk under the big lock.
* The name cache keeps only ext2's names, and only the resolver's lookups: the last component of a parent walk, which the system call layer looks up itself for an open with `O_CREAT`, an unlink or a rename, goes to the type every time. Its counts are the machine's, not a mount's.
* One run at a time uses the staging buffer; while it is in use a writer writes its blocks one at a time and a sequential reader fills its block alone.
