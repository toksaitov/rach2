# Processes

The process subsystem, `rach2/sys/proc/` with the handlers in `rach2/sys/syscall_proc.c`, runs programs as processes. It keeps a record for each thread and a thread group that makes a process of several; makes processes and threads with `fork` and `clone`, loads programs with `execve`, and ends them with `exit` and reports their end to `wait`; schedules them on every processor, with the big lock over the kernel code that has no lock of its own; and keeps their credentials, resource limits and seccomp filters, writes their core files, and keeps them from running during a suspend to idle. A program sees Linux's process calls for its architecture, whose contracts are in section 2 of the manual. Four parts of this directory have documents of their own: [signals](signal.Readme.md), [ptrace](ptrace.Readme.md), [futexes](futex.Readme.md) and [namespaces](ns.Readme.md). The context switch and the entry to the kernel are [the architectures'](../arch/Readme.md), the thread pointer is [thread-local storage](../arch/tls.Readme.md), and the address space a process runs in is [memory's](../mm/Readme.md).

## Results

A thread woken from a timed wait under load returns tens of milliseconds late, where Linux returns within a few, because the woken CPU waits for the big kernel lock. In the latest measurement, on 2026-11-10 on the testing PC's WSL under KVM with four CPUs and 512 MiB, `wakelatmusl` under the mixed load (one arithmetic and one system-call thread on each CPU) had 158 of its 384 timed waits return more than 10 ms late, with a maximum of 80.920 ms; Debian 13's kernel 6.12.115 under the same load had none over 10 ms and a maximum of 4.637 ms. The console's writes offer the lock between their 256-byte chunks ([the terminal layer](../tty/Readme.md#the-console-terminal)). No wake-latency bound is established; the owner left the change to the big lock for the next locking milestone. The measurements, the accounting of the late waits and the lock holders behind them are in the timed-wake task's record under `dev-log/`.

To repeat the Rach2 measurement on the testing host, use `ARCH=x86_64 RACH2_QEMU_ACCEL=kvm RACH2_WORKERS=1 tests/run wakelat`. The Debian reference runs the same executable with `tests/graphics/debian-ref/debian-ref.sh run -p std-vga -c 4 -m 512 -i build/x86_64/tests/musl/wakelatmusl`, `ACCEL=kvm`, and the guest command `/tmp/wakelatmusl 64 N` for load bits N from 0 to 3.

### The kernel's interfaces

The rest of the kernel reaches processes through these headers:

* `process.h`: `current_proc`, the running thread's record (`percpu.h`); `get_process`, a record by its id; `proc_privileged`, whether a thread has privilege over the whole system; `proc_in_syscall`; and the signal functions, `signal_post` and the rest, which [signals](signal.Readme.md) describes.
* `sched.h`: `schedule`, `sched_make_ready`, which every wake goes through, `sched_preempt`, which an interrupt calls on its way out, `sched_service_point` for a long system call, and `idle_wait_irq_off` and `idle_wait_irq_on`, the only idle waits.
* `wait_queue.h`: `wq_wait_event`, `wq_wait_event_as`, which names its sleep for /proc/PID/wchan, `wq_wait_event_nointr`, `wq_wait_event_killable`, `wq_wait_event_idle`, `wq_wake`, `wq_wake_all`, `wq_wake_proc` for a waker that took a sleeper off its queues itself, `wq_complete`, which sets a done flag and wakes together, and `wq_poll_add` and `wq_poll_remove` for `poll` and `epoll`.
* `mutex.h`: `mutex_init`, `mutex_lock`, `mutex_trylock` and `mutex_unlock`, as Linux's `struct mutex` (kernel/locking/mutex.c:281), and `rwsem_init`, `down_read`, `down_read_trylock`, `down_write`, `up_read` and `up_write`, as its `struct rw_semaphore` (kernel/locking/rwsem.c:1521,1574); each keeps its state under a spinlock of its own and its waiters on a wait queue, and each init site is a class of the lock-order checker.
* `smp.h`: `bkl_enter` and `bkl_exit`, which the interrupt routers call (`rach2/sys/arch/x86/isr.c`), `bkl_held`, and `bkl_assert_held` (`rach2/sys/lib/lockdep.h`) for code that still needs the lock; `smp_tlb_shootdown`, `smp_space_release`, `smp_kernel_mapping_changed` and `smp_kernel_flush`, which the page tables call; `smp_barrier`, which `membarrier` calls; `smp_call`, which KVM's VMX backend calls to clear a VMCS on the processor where it is active; `smp_stop_others`, for a panic and a power off; and `smp_start`.
* `seccomp.h`: `seccomp_permit`, which the system call dispatcher calls (`rach2/sys/syscall.c`).
* `coredump.h`: `core_notes` and `core_write`, which `fs_core_file` in `rach2/sys/syscall_fs.c` writes through.
* `suspend.h`: `suspend_to_idle`, which a write of `freeze` or `mem` to `/sys/power/state` calls, and `suspend_wake`, which the clock's alarm and the keyboard call.

## Design

`proc_timer_update` keeps records with a real alarm or a blocked timed wait on an intrusive list. Blocking in `schedule`, a wake in `sched_make_ready`, alarm changes and record deletion refresh membership under the big lock with local interrupts masked. The timer pass visits only this list; untimed blocked threads add no timer work. The boot processor's tick makes the pass, and so does another processor's tick that has the big lock when the tick count has not moved over two of its ticks, so that no timeout waits while the boot processor's ticks find the lock held (`timer_handler`, `kernel.c`); `/proc/stat` counts those as `timer_passes_late`. Its cursor follows removals made by signal wakeups during the same tick. `/proc/stat` reports the pid, uid and timer entries examined as `process_pid_steps`, `process_uid_steps` and `process_timer_steps`, and timer passes as `process_timer_passes`, modulo 2^32.

The big lock accumulates time-stamp counter cycles around each outer acquisition. `/proc/stat` reports the sum and longest acquisition as `bkl_wait_us` and `bkl_wait_max_us`, converted at the calibrated invariant TSC rate, or zero when none was calibrated. `bkl_wait_max_holds` counts outer holds completed during that same longest acquisition, modulo 2^32, including a hold already in progress when it began. A drop for an idle wait counts as a release; the count is of holds, not distinct processors. These times include time a hypervisor stopped the waiting processor. The counters change and are read under the big lock; an acquirer snapshots the 32-bit release count before waiting and subtracts it after taking the lock.

Each `bkl_wait_max_hold` line names one of those holds: entry vector, system call number (-1 for none), and full hold time in microseconds. The last 32 are kept, oldest first, or all when fewer. A hold may begin before the acquisition, so its full time can exceed the wait. The release records are copied only when an acquisition sets a new maximum; later holds do not replace them.

debugfs's `bkl/calls` and `bkl/profile` split the lock's time by what holds it ([debugfs(5)](../../../man/man5/debugfs.5)). The router (`_isr_router`, and `ia32_fast_syscall` for an i386 call through `__kernel_vsyscall`) reads the cycle count before a system call's entry takes the lock and passes it to `smp_call_end` at the handler's return, which counts the call and its time under its number; an ioctl's request, of either ABI on x86-64, takes a slot of 256 (`isr_call_ioctl`, `bkl_note_ioctl`) and counts there too. `bkl_acquire` keeps each outer wait in the processor's record, and `bkl_hold_end` adds it, with the hold, to the entry the hold is charged to and to the ioctl request it took the lock for. The tick that finds its processor already holding the lock samples the instruction it stopped and three callers above it, with the entry the running process is in, into a table of 16384 slots (`bkl_profile_sample`), so that the samples, at 1000 Hz a processor, give the kernel's time under the lock by function, by call path and by the system call, vector or ioctl request that spent it; code that keeps interrupts off is not sampled, nor is the writing of `bkl/profile`'s text (`smp_profile_show`), so that its lines and `lost` sum to its samples; the rest of a read, its entry, `text_fill`'s allocation and the copy out, is sampled. The entry is kept in the process's record: each router marks it there before its handlers run and puts the outer one back after them (`bkl_entry_push`, `bkl_entry_pop`), so that it stays with a call that sleeps while the processor, still holding the lock, runs another process's. A write to either file zeroes it; the requests keep their slots, so a call under way when the counts are zeroed is still counted under its own request. `kernel.c` registers both files after the processors start.

### The records

Each thread has a record, `struct process` (`process.h`), from the kernel heap (`alloc_process`). The records are on one list, `proc_list`, in the order they were made; `get_process` finds one in a pid hash that doubles before its load exceeds one record per bucket, and separate ready lists hold the threads waiting to run. A record is in one of six states: `PROC_READY`, `PROC_RUNNING`, `PROC_BLOCKED`, `PROC_STOPPED`, `PROC_ZOMBIE`, and `PROC_UNUSED`, which marks a record that `fork` is still building or that a reaper has taken and is freeing, so that no wait, signal or selection takes it. A new record takes the id after the last one given, passing over any id a live record has; after 1,999,999,999 the ids start again from 1. The boot's self-tests and the kernel threads a driver starts at its bind take ids before the first program, and `proc_reclaim_boot_pids` then starts the numbering again at 1, giving a kernel thread that holds id 1, such as the DRM commit worker, the next free id, so that init is process 1, which BusyBox's `reboot`, `halt` and `poweroff` signal.

A process is a thread group, `struct tgroup` (`tgroup.h`). Each thread is a record of its own, with its id, registers, kernel stack, thread pointer, blocked mask, pending signals and CPU time. The group has what the threads share: the signal dispositions and the signals sent to the process, a stop in effect, the POSIX timers and the interval timers of processor time, the CPU time and page faults of the threads that have ended and of the children reaped, the most memory an address space of the process had in use, the OOM score adjustment, and the process's end: `exiting` and the status the process ends with after `exit_group` or a fatal signal, `exec_task` while an `execve` ends the other threads, and `core_dumping` while a core is written. The thread whose id is the process id is the group's `leader`. Every record's `tgid` is that id, which `getpid` reports, and its `pid` is the thread's own, which `gettid` reports. `live` counts the threads that have not ended, and `refs` the records that point at the group.

Three more parts of a process are counted records of their own, which `clone` shares or copies: the address space, `struct mm`, shared under `CLONE_VM` and copied on write otherwise ([memory](../mm/Readme.md)); the descriptor table, shared under `CLONE_FILES` ([the file system layer](../fs/Readme.md)); and `struct fs_struct` (`process.h`), the working directory, the root directory `chroot` set and the file mode creation mask, shared under `CLONE_FS`. A thread that a C library makes shares all three with the rest of its process.

The thread group's `execed` flag records a successful `execve` since the group was made. `exec_commit` sets it after any change of leader, and a new group starts with it clear. `setpgid` refuses a parent's request for a child whose flag is set with `EACCES`; a process may still change its own group ([getpid(2)](../../../man/man2/getpid.2)).

Process 0, `proc_idle`, is the kernel's own. `kernel_main` (`rach2/kernel.c`) makes it on the boot stack with no address space, and the boot and the debug shell run as it. The first program, and each program the debug shell runs, start on the boot stack too, without a fork (`enter_program` in `rach2/kernel.c`). Each processor also has an idle task (`smp_idle_task` in `smp.c`): a record off the list, with id 0 and a guarded stack of its own, which no system call can reach and no reaper frees.

### Fork and clone

`fork`, `vfork`, `clone` and `clone3` all reach `do_fork` (`rach2/sys/syscall_proc.c`) with a `struct fork_req`: the clone flags, the child's stack pointer, and the addresses of the ids the call stores. `clone_with` refuses a flag it does not know with `EINVAL`, and accepts zero or `SIGCHLD` as the exit signal of a new process; `CLONE_THREAD` needs `CLONE_SIGHAND`, which needs `CLONE_VM`. `do_fork` works in this order, and a failure at any step returns to the parent with what was built for the child given back:

1. It begins recording signals sent to several processes during the build (`fork_delay_begin`; [signals](signal.Readme.md#sending)), restarts after taking any signal work already pending, lets the caches give back memory (`mem_balance`), and refuses with `EAGAIN` a caller whose real user already has `RLIMIT_NPROC` records, each thread and each zombie counted (`fork_nproc`). A count for each real uid is kept from allocation until the record is freed, and a change of real uid transfers that charge. A child being built reserves its place before any building step can sleep.
2. It takes a record already marked `PROC_UNUSED` while the child is built, since the building may sleep (`alloc_process_fork`). The record starts without a descriptor table or standard descriptions. A thread takes a reference to its parent's group directly, and `CLONE_FS` takes a reference to the directories directly; neither allocates a record that the clone would discard. A shared group counts the new thread as live only at step 9; a failed build drops its reference without changing the live count.
3. It gives the child its address space, the parent's own with one more user under `CLONE_VM` and a copy-on-write copy otherwise (`fork_mm`), and a kernel stack (`kstack_alloc`), whose guard page [the architectures' Readme](../arch/Readme.md) describes.
4. The child's parent is the caller's process, or the caller's parent under `CLONE_THREAD` and `CLONE_PARENT`. `fork_ids` copies the credentials, the limits, the session and process group, the nice value and I/O priority, the persona, `no_new_privs`, the capabilities and the bounding set, the seccomp mode and filters, the OOM score adjustment and the program name.
5. The child's thread pointer is the one given with `CLONE_SETTLS`, or the parent's ([thread-local storage](../arch/tls.Readme.md)), and the floating-point registers are saved into the child's area as they are now.
6. `fork_shares` shares or copies the directories and the descriptor table. A copied table refers to the same open file descriptions, each with one more reference. `CLONE_FS` fails with `EAGAIN` while a thread that shares the record is in an `execve` that applies set-id bits (Credentials, below). Then `ns_fork` gives the child its namespaces and its numbers in its PID namespaces ([namespaces](ns.Readme.md)), so a failure to copy the files or directories reserves no PID there, as Linux 6.12.115's `copy_process` orders these steps (`kernel/fork.c:2403-2406, 2431-2437`).
7. The child's id is stored where `CLONE_CHILD_SETTID` and `CLONE_PARENT_SETTID` ask, and the address given with `CLONE_CHILD_CLEARTID` is kept for the thread's end ([futexes](futex.Readme.md)). Under `CLONE_PIDFD` a pidfd of the child is made, its descriptor reserved in the caller's table and its number stored where the call asks (`fork_pidfd`); it is installed after the next step, and given back if that step refuses the child.
8. A SIGKILL pending for the caller, an `exit_group` or an `execve` by another of its threads refuses the child with `EINTR`, since a child made then would outlive its process's end. Nothing after this step sleeps. `ns_fork_commit` rechecks that the child's PID namespaces still admit it and publishes a new namespace's reaper ([namespaces](ns.Readme.md)).
9. `fork_signals` adds the child to the caller's group under `CLONE_THREAD`, and otherwise gives its new group a copy of the dispositions; either way it has the caller's blocked mask and no inherited pending signal of its own. clone3's `CLONE_CLEAR_SIGHAND` then sets every handler the child's group has back to the default and keeps the ignored signals ignored (`fork_clear_handlers`). `arch_fork_frame` lays out its kernel stack so that its first switch returns to user mode with 0 as the call's result.
10. The child takes the parent's processor and affinity and a depth of 1 in the big lock. `fork_start` gives a new process the signals recorded during the build, ends the recording and makes the child runnable, with interrupts off; it sends SIGKILL to any child whose caller's process began to end after step 8 ([signals](signal.Readme.md#sending)). A tracer's event is reported ([ptrace](ptrace.Readme.md)). Under `CLONE_VFORK` the parent then waits, in a sleep only SIGKILL ends, until the child calls `execve` or ends (`proc_vfork_wait`).

The parent gets the child's id in the parent's PID namespace.

A zero-signal child sets its group's `no_child_signal`: its end wakes the real parent's wait without posting SIGCHLD, and an ordinary wait does not select it. `__WCLONE` selects it, and `__WALL` selects either kind. `CLONE_PARENT` inherits the caller's exit notification choice and parent generation snapshot. `CLONE_UNTRACED` prevents inherited tracing and the parent's fork event; it does not prevent a later explicit attach. A tracer's wait includes every tracee regardless of these wait flags.

A successful exec and orphan adoption restore SIGCHLD. A child also records its real parent's successful-exec generation; if that generation changed before notification, the child's end restores SIGCHLD and ordinary wait selection. Generation wrap resets existing children's snapshots to zero before setting the parent's next generation to one, so an old child cannot compare equal by wrap. `child_signal.c` implements generation advance and notification choice.

### execve

When a nonleader thread takes its leader's place (`exec_take_leader`), `proc_exchange_pids` exchanges both kernel IDs and the IDs in every PID namespace, as Linux 6.12.115's `de_thread` exchanges whole PID objects (`fs/exec.c:1112`). The process keeps its number in every namespace, and releasing the old leader's record frees the former thread's numbers.

`sys_execve` builds the new image beside the old one and replaces the old one only when nothing can fail any more, so every refusal and every failure of the load returns to the caller with its image, its credentials and its descriptors as they were. Each call has a workspace of its own, `struct exec_state`, from the heap, which the caller's record points at (`exec_ws`), since a read of a program on a mounted volume sleeps and another `execve` may run meanwhile. `exec_run` works in this order:

1. It copies the path, joined to the working directory when it is relative, and makes the new address space (`mm_new`).
2. `exec_open` resolves the path from the caller's root, checks the execute right, and opens the program, noting whether the caller may read the file and what its set-id bits would do; [execve(2)](../../../man/man2/execve.2) has what it refuses. The new address space keeps the program's file from then on ([memory](../mm/Readme.md)), and the load reads that file whatever is put at its path meanwhile. A path that ends on a link of `/proc/PID/fd` goes on to the file its descriptor is open on (`proc_fd_file`), which is checked as one named by its own path; a file off the KRFFS root then gives the new address space the path its descriptor was opened by as its name. A path through `/proc/PID/exe` is replaced by the program's own path (`exec_link_name`).
3. `exec_copy_args` copies the path and the strings of the environment and of argv onto pages taken for the new stack (`uimage.c`, below).
4. A file that is not an ELF image of the architecture and begins with `#!` gives the path of its interpreter (`exec_script`, `exec_shebang`): argv[0] is taken away, the interpreter, its one argument and the script's path go in its place, and the interpreter is opened as the program. An interpreter that is itself a script is refused.
5. `uimage_place` makes room for the pointers and the auxiliary vector below the strings. `exec_ids` chooses the ids the image runs with (Credentials, below), and `exec_build` loads the program, and the interpreter whose path its `PT_INTERP` gives, into the new address space (`elf.c`, below), makes the regions, maps the vDSO one free page above the mmap base (`vdso_map`), refuses with `ENOMEM` an image whose regions pass `RLIMIT_AS`, and writes the initial stack, with 16 bytes from the kernel's random generator for `AT_RANDOM` and, on x86-64, the vDSO's address for `AT_SYSINFO_EHDR`. On x86-64 an ELF32 i386 program (`exec_classify`) gets Linux's compat layout from `exec_layout`, the `IA32_` addresses of `arch/x86_64/cpu.h`, the 32-bit vDSO, and `AT_HWCAP`, `AT_PLATFORM` and `AT_SYSINFO` beside the rest; its address space is marked `compat` in `struct mm`, which the exec frame (`arch_exec_frame`), `/proc/PID/auxv` and the mapping calls read.
6. `exec_files_stage` takes the storage of a descriptor table of the caller's own when the caller shares one, so that the allocation fails while the call can still return.
7. `exec_one_thread` sends every other thread of the process SIGKILL and waits until they have ended or SIGKILL is pending for the caller. A pending SIGKILL clears `exec_task` and returns `EAGAIN` before the new image is committed; the caller ends on its way back to user mode, as Linux 6.12.115's `de_thread` does (`fs/exec.c:1052-1059,1080-1085,1151-1157`). A process already ending, or one in which another thread's `execve` has begun that wait, also returns `EAGAIN`, leaving `exec_task` to the thread that set it.
8. `exec_commit` makes the image the process's and cannot fail. The thread releases its robust futexes ([futexes](futex.Readme.md)), and a thread other than the leader takes the leader's place and id (`exec_take_leader`). The POSIX timers are deleted; a caller that shares its descriptor table gets one of its own, and the close-on-exec descriptors are closed; the new effective ids become the saved ids too; caught signals go back to their default action and the alternate signal stack is cleared; the program name is set from the path. The new address space is loaded and the old one put, a parent waiting in `vfork` is let go, the frame is set at the new entry (`arch_exec_frame`), the thread pointer becomes 0, and the floating-point state is reset.

`elf.c` accepts an image of the architecture's class and machine, `ELF_CLASS` and `ELF_MACHINE` in its `cpu.h` (ELFCLASS32 `EM_386` on i686, ELFCLASS64 `EM_X86_64` on x86-64), little-endian, of type `ET_EXEC` or `ET_DYN` (`elf_valid_exec`). On x86-64, where `ELF_IA32` is 1, `elf_read_layout` and `elf_load_image_at` also take ELFCLASS32 `EM_386` programs, whose headers `elf_read_headers` widens in place to the native types, and bound them by `IA32_TASK_SIZE`; the image and the layout say which class they are of in `cls`, and `elf_load_image`, which loads the boot's first program, takes the native class alone. The loader reads the file a piece at a time through a function, `elf_read_fn`, and never has it whole in memory, so a program's size has no bound; `exec_file_read` takes a whole page of a file on a mounted volume from the file page cache when it is there and leaves it there when it is not, so a program started again reads none of its text from the disk. `elf_read_layout` reads at most `ELF_MAX_PHNUM`, 32, program headers, the span of the `PT_LOAD` segments, and the interpreter's path, absolute and at most `ELF_INTERP_MAX`, 256, bytes with its NUL. `elf_load_image_at` checks each `PT_LOAD` before it takes a page: within the user range below the stack, not wrapping, and starting at or after the page where the segment before it ends. A segment whose file offset and address agree modulo the page is mapped privately from the file, as Linux's `elf_map` maps it: `exec_open` makes the mapping (`exec_map`), a description of the file open for reading kept by the mapping as an `mmap` of the file keeps one ([memory](../mm/Readme.md)), and the loader takes no page for the segment's file bytes, which a fault reads from the file when a page is first touched and again after `madvise` drops it. The whole pages past the file bytes are anonymous memory, and the page where the file bytes end, when the segment goes on past them, is loaded at once with zeros after them, as Linux's `padzero` clears it; the loader reads the segment's last file byte, so a file shorter than its headers say is refused at the exec. A segment whose offset and address disagree, every segment of a file that is not regular, and the first program the boot loads are copied into zeroed pages whole. A page the loader fills is made read-only where its segment has no `PF_W`, and not executable where it has no `PF_X`, and a page a fault backs takes its region's protection; i686 maps every page executable ([the architectures' Readme](../arch/Readme.md)). At most `ELF_MAX_SEGS`, 8, `PT_LOAD` segments are taken, from which `elf_setup_vmas` and `elf_add_vmas` make the regions: a region of the file for a mapped segment's file pages, with the file's page at its start, and an anonymous one for the rest. The image keeps its file through a close, a rename or an unlink, and a fork's child shares the mapping. An open of the file for writing meanwhile fails with `ETXTBSY`, as on Linux ([the VFS Readme](../fs/vfs.Readme.md)). A position-independent program is moved to `ELF_ET_DYN_BASE` and a position-independent interpreter to just below `USER_MMAP_BASE` (`exec_build`, `exec_interp`), each moved again by a random offset on x86-64 unless the persona has `ADDR_NO_RANDOMIZE` (`exec_layout`); [memory](../mm/Readme.md) has the layout these constants give on each architecture, and how it is randomized.

`uimage.c` builds the initial stack in frames taken for the new image while the old one runs, as Linux's `linux_binprm` has its argument pages. The strings are copied from the top down: the program's path, the environment from its last string, and argv from its last, so argv[0] is the lowest. One string may be `UIMAGE_STRING_MAX`, 131072, bytes with its NUL, and the strings with their pointers may take a quarter of the soft `RLIMIT_STACK`, at least 128 KiB and at most 6 MiB (`uimage_budget`), as on Linux. Below the strings `uimage_write` puts the 16 bytes of `AT_RANDOM`, aligned to 16 bytes, then argc, the argv and envp pointers each ended by NULL, and the auxiliary vector of `UIMAGE_AUXV`, 22, entries (`auxv.h`), the unused ones at the end `AT_NULL`, each a word of a pointer's width, or of 4 bytes for an i386 program (`u->word`), whose `AT_PLATFORM` string lies above the `AT_RANDOM` bytes; the entry stack pointer is aligned to 16 bytes. `uimage_map` maps the frames into the new directory where the stack is. [execve(2)](../../../man/man2/execve.2) has the vector's entries and the contract.

### Exit and wait

A thread ends by `exit` (`exit_current` in `rach2/sys/syscall_proc.c`), and a process by `exit_group`, which first sends every other thread SIGKILL and records the status the process ends with (`proc_group_exit`). A signal whose default action ends the process reaches `terminate_current_process` (`rach2/kernel.c`), which writes a core file when the action asks for one (Core files, below), sends the other threads SIGKILL the same way, and ends the thread. The exit event of a thread parked for a core reports the group's status before the dump, without `WCOREFLAG`; the dumper's reports it after the dump. The final wait of a traced thread reports the group's status once its end has begun, as Linux 6.12.115's `wait_task_zombie` selects it (`kernel/exit.c:1241-1242`). An init's line under the debug shell reports that same status, and a signal gives the harness 128 plus its number. Both paths run `proc_exit_cleanup` (`exit.c`), in this order:

1. It sets `in_syscall`, so that an interrupt only asks for a switch, and the thread's own part goes: the word given with `CLONE_CHILD_CLEARTID` is cleared and a waiter on it woken, and the thread's robust futexes are released (`proc_thread_gone`, [futexes](futex.Readme.md)).
2. The thread drops its address space and runs on the kernel's page directory; the last user's drop frees the memory ([memory](../mm/Readme.md)).
3. It drops its descriptor table and its directories; the last reference closes the descriptors and lets go of the working directory and the root. Both may sleep, so they come before the zombie is published. A parent waiting in `vfork` is let go.
4. With the process's last thread, the POSIX timers and the System V semaphore adjustments go, the threads the process traces are let go, the init of a PID namespace sends the rest of its namespace SIGKILL ([namespaces](ns.Readme.md)), the children are given to a child subreaper or to init (`reparent_children`), and the leader takes the group's status when `exit_group` or a fatal signal ended the process.
5. The record becomes `PROC_ZOMBIE`. A thread that is not the last wakes an `execve` or a core dump that waits for it. The last sends the parent SIGCHLD and wakes its wait, unless a process other than the parent traces the leader: that tracer's wait reports the end first and then lets the parent have it ([ptrace](ptrace.Readme.md)).

The thread then leaves the processor for good. A thread that is not the leader and has no tracer is freed at the next return to user mode of any thread (`reap_threads`; `proc_dead_threads` counts them). The leader's record stays until the parent reaps the process. Both the last thread's exit and the removal of the leader's record wake the group's `exited` queue, so pidfd pollers see readability at exit and hangup at reap. A process that ends gives up the framebuffer if it has it, and one that leads its session gives up the console and the pseudo-terminals the session controls.

`reparent_children` (`process.c`) gives each child of an ending process to the nearest ancestor of that process that is a child subreaper and has a thread that has not ended (`proc_subreaper`). A process becomes one with `prctl`'s `PR_SET_CHILD_SUBREAPER`, which sets `child_subreaper` in its thread group; a fork starts without it and an exec keeps it. The search goes up by parent and stops at the first init it meets, the ending process included, so it stays in the ending process's PID namespace. With no subreaper the child goes to the init of the ending process's PID namespace. The new parent is sent SIGCHLD for a child that is already a zombie, and its wait is woken, so that it reaps the child, and the reap adds the child's CPU time to the new parent's children's totals as any reap does. Each living child is then sent the parent-death signal `prctl` set. `/proc/PID/task/TID/children` lists the children of a process ([synthetic file systems](../fs/synthfs.Readme.md)). When init itself ends, a real `/sbin/init` panics the kernel (`panic_init_died`); under the debug shell, which runs each program it starts as init, the kernel ends and reaps every other user process (`proc_end_others`) and returns to the shell ([the kernel's Readme](../../Readme.md)).

`wait4`, `waitid` and i686's `waitpid` share `wait_find`. It walks the records for a child the call selects that has an event the call asks for, an end, a stop or a continue, and for a thread the caller traces; with none it sleeps on the group's `chld` queue. The event is reserved for the caller while the report is copied out (`wait_hold`): a zombie to reap is marked `PROC_UNUSED`, so that no other thread's wait takes it, and a copy that fails because another thread unmapped the buffer meanwhile returns `EFAULT` and puts the event back (`wait_done`). The reap adds the child's CPU time and page faults, with those of the children it reaped, to the caller's group, and frees the child's address space, kernel stack and record (`proc_release`).

### Scheduling

`sched.c` selects real-time threads by effective priority before ordinary threads, which run in turn on each processor. FIFO retains the CPU against equal-priority peers until yield or block; RR rotates equals at each tick. PI futex owners inherit the priorities of their blocked waiters, through chains of owners, as [futexes](futex.Readme.md) describes. Each processor has a doubly linked ready list and a count, and each queued record's `cpu` names that list. The current and idle tasks are off the lists. A wake appends a record once; selection and deletion unlink it in constant work, and a runnable thread switched away appends at the tail. A spinlock, `sched_lock`, covers the links and counts and is taken after the big lock. Blocked records add no selection work. `/proc/stat` reports selection attempts as `scheduler_picks` and ready entries examined by local selection and stealing as `scheduler_steps`, modulo 2^32. Each record keeps Linux's `sched_info`, which `/proc/PID/schedstat` gives: a thread appended to a ready list, after the scheduler is on, notes the moment on the monotonic clock, in 64-bit nanoseconds, unless it already waits, so a move to another processor's list keeps the wait, and when it is selected to run, or runs on as the current task, the wait is added to `run_delay` in nanoseconds; each switch onto a processor counts in `pcount`. KVM's steal time adds the growth of a vCPU thread's `run_delay` to its guest's record ([kvm](../kvm/Readme.md)).

`schedule` chooses the next thread for the processor it runs on, alternating two kinds of selection. An ordinary selection takes the first eligible record of the processor's ready list. A wake preference takes a record a wait queue woke (`woken`), once, without advancing past the records before it, so that a reader runs soon after its data arrives. At least every second selection is an ordinary one, so a thread that sleeps and wakes often still waits its turn. When its own queue has nothing to run, a processor goes on with its current thread if that one can still run; otherwise it tries other lists by their ready counts, busiest first, and takes the first eligible record (`sched_steal`), and with nothing there either it switches to its idle task. A record may run on a processor its affinity has, a 64-bit mask that `sched_setaffinity` sets, and only once no other processor is running it. `sched_make_ready`, through which every wake goes, puts a record on the queue of the processor it last ran on, unless that one is busy and another it may use is idle, and sends an idle processor an interprocessor interrupt so that it looks at once.

`sched_set_affinity` completes a move before returning, as Linux's `affine_move_task` does. A remote thread running outside its new set gets `need_resched` and an interprocessor interrupt; the caller sleeps on a completion kept on its own stack until the target switches away. A later request that permits the target's current processor also completes the wait. Completion removes the target pointer before waking the caller, so a target that exits and is reaped cannot leave a stale pointer in the wait. An interrupt in user mode takes the switch at once; a thread in a system call takes it at its next scheduling point.

`rseq.c` keeps the registered area of each thread as [rseq(2)](../../../man/man2/rseq.2) describes. A switch away and a move between processor queues mark the area for the next return to user mode. `isr_leave`, after signal delivery, aborts an interrupted critical section and writes the running processor into `cpu_id_start`, `cpu_id` and `mm_cid`, with node 0. Registration and a forked child's first return also request the update. The update repeats if a user-memory fault sleeps and the thread moves while its area is being written.

Before the switch `schedule` saves the floating-point registers into the outgoing record's area and loads the incoming record's, and makes the incoming record the processor's `current`. `switch_context` then changes the stack, the page directory and the thread pointer ([the architectures' Readme](../arch/Readme.md)). Interrupts are off from the selection to the switch. The big lock does not cross it: the outgoing thread's depth is saved in its record (`bkl_depth`) and the lock let go (`bkl_drop`), and the incoming thread's tail (`schedule_tail`) takes it back at that thread's own depth, none for the idle task or a thread that switched away outside the lock, counted as a switch's take (`bkl_take_as`), as Linux 2.6 gave the big kernel lock up around a switch (`release_kernel_lock`). So a processor that goes idle, or runs a thread that holds nothing, keeps the lock from no one. A thread's `on_cpu` says that a processor may still run on its stack, as Linux's does (kernel/sched/core.c:4972-4990): it is set before the switch to the thread, and the tail of the next switch clears it once the switch has saved the thread's registers. A thread woken while it still switches away on another processor may be selected meanwhile; the switch to it waits for its `on_cpu` to clear first (`sched_wait_off_cpu`), outside the run queues' lock, and a reaper waits for it too before it frees a dead thread's stack.

Each processor's timer interrupts it 1000 times a second (`TICK_HZ` in `rach2/sys/timer.h`; [the PC platform](../arch/x86/Readme.md)), and the tick's handler (`timer_handler` in `rach2/kernel.c`) and every device's interrupt end with `sched_preempt`. A thread interrupted in user mode, process 0 and the debug shell's test threads are switched at once, except process 0 or a test thread inside klog (`klog_inside` in `rach2/sys/klog.h`), in a record, a console write or a console byte, as process 0 is while the debug shell prints a line: klog's count of its users would stay up while the big lock passed on, so the request waits in the record and the thread gives way at a later tick, once it has left klog, as Linux writes a console record with interrupts off and gives way only between records (kernel/printk/printk.c:3074-3089). A thread inside a system call is not, since the call's state may be half changed: the request is kept in the record (`need_resched`), and the dispatcher takes it at the call's exit (`sched_take_preempt`), so a process that is always inside a call still gives way once per call. A fault from user mode, which runs with interrupts on ([memory](../mm/Readme.md)), keeps the request the same way (`in_fault`) and takes it at its end. A kernel thread is not switched either (`no_tick_switch`, which `setup_process_stack` sets and the shell's `test_process` clears, since its tests are of the tick's switch): its work changes state that only the big lock guards, and the switch lets the lock go, so a request waits in the record for the thread's next sleep or service point. This is Linux without `CONFIG_PREEMPTION`, where the tick only sets `TIF_NEED_RESCHED` (kernel/sched/core.c:1094), a kernel thread is switched where it calls `schedule` or `cond_resched` (:7287), and an interrupt's return to kernel mode switches nothing (kernel/entry/common.c:356). The workers kacpid, kwlan, kinputd, kpsmoused, kdrm, kdrmcon, ki915, virtio_gpu, kvkms and vgpu-shm reach a service point after each work or pass, as Linux's worker calls `cond_resched` between works (kernel/workqueue.c:3290-3299), and vgpu-shm also after each look for the device's answer that fails (`vshm_await`), as vhost's worker does between works (drivers/vhost/vhost.c:440). A call that loops over a large buffer takes the switch between two pieces of its loop through `sched_service_point`. `schedule` clears the outgoing thread's request under the run queues' lock once it has selected, whether or not it switches, as `__schedule` does (kernel/sched/core.c:6707), so a request made after the selection is kept for the next point. Both `sched_service_point` and `schedule` count for the soft-lockup detector as the schedule Linux's stopper thread waits for (`watchdog_sched`). A processor's idle task is not switched from the interrupt either; its loop selects as soon as the handler returns.

`waketime.c` accounts each blocked user thread that a timed wait or a timerfd expiration wakes, from its deadline tick to `isr_leave` just before its return to user mode. The thread's `TimedWakeCount`, `TimedWakeLast`, `TimedWakeWorst` and `TimedWakeSum` in `/proc/PID/status`, or its task's `status`, report the completed count, last wake, longest wake and sums. The eight microsecond columns are expiry to the servicing timer interrupt, that interrupt's wait for the big lock after expiry, the remaining timer work, time queued, time running toward user mode, time blocked again, and two subsets: the queued CPU's waits for the big lock and the returning thread's waits for it. The first six sum to the accounted delay; the last two must not be added again. Queuing after a second preemption and moving to another CPU preserve the accounting. The first deadline stays until the return, even if the thread blocks again. Other sleeping locks appear in the blocked-again column. Spinning while running remains in the return column.

The timestamps use the vDSO's checked, common TSC clock when available and the platform's monotonic microsecond clock otherwise. They include time a hypervisor deschedules a virtual CPU. Per-stage clocks and the completed count wrap at 2^32; sums have 64 bits. A stage must be shorter than half the microsecond clock's period, about 35 minutes. The interrupt columns describe the interrupt that actually made the timer pass; earlier ticks that bypassed the big lock are counted separately in `/proc/stat`. The deadline is rounded to the kernel's millisecond tick; time before the wait is armed and the final register restore and return instruction are outside this record. The probe measures those too in user space. Kernel threads have no user return and start no record. A fork starts with empty records.

An idle wait, a halt with interrupts on that expects to resume, goes through `idle_wait_irq_off` or `idle_wait_irq_on`. Each marks the processor idle for the tick to see, lets the big lock go for the halt and takes it again after. The first enters with interrupts off and returns with them off. An `sti` takes effect only after the instruction that follows it, so an interrupt that became pending while the caller tested its condition arrives once the `hlt` has begun, and ends it. An interrupt that ended the halt returns with interrupts off (`_irq_router`), so that the wait goes on before the next tick, however long the big lock takes. `tests/run style` refuses a `sti; hlt`, or a call of the architecture's halt, anywhere else ([style.sh](../../../tests/cases/host/style.sh)).

The tick charges the thread it interrupted with user time when the interrupted code was ring 3's and with system time otherwise, and a tick that found the processor in an idle wait to no one (`sched_account_tick`); a processor counts the global ticks it missed with its next. The same tick runs the process's `ITIMER_VIRTUAL` and `ITIMER_PROF` timers and the POSIX timers of processor time. Every five seconds and a tick, 5001 ticks by the tick count, the boot processor folds the threads that are running or ready into the three load averages, as Linux's `calc_load` does (`sched_load_tick`); a sample made late keeps the period's phase, and the samples a longer gap passed over are folded at once with the decay to their power, as Linux's `calc_load_n` folds them. `times`, `getrusage`, `wait4`, `/proc/stat` and `/proc/PID/stat` report these counts.

Each record keeps a nice value, from -20 to 19, the slice `sched_setattr` asked for (`sched_slice`, 0 for Linux's default), and an I/O priority, which a fork passes on and an exec keeps; the scheduler reads none of them. The scheduling calls keep `SCHED_OTHER`, `SCHED_BATCH` and `SCHED_IDLE` at priority 0, and `SCHED_FIFO` and `SCHED_RR` at priorities 1 to 99. `sched_setattr` changes the supported policies and `sched_getattr` reads their parameters, in Linux's order and with its errors (`sched_apply` in `rach2/sys/syscall_proc.c`). Only `SCHED_OTHER` and `SCHED_BATCH` change the nice value and slice; `SCHED_IDLE` keeps them. A caller without privilege is held to the target's `RLIMIT_NICE` and `RLIMIT_RTPRIO`, as Linux holds one without `CAP_SYS_NICE` (`sched_user_check`); both are 0 by default, which allows no lower nice value and no real-time policy, and such a caller may never set `SCHED_DEADLINE`. The scheduler has no deadline class. After the argument, privilege and affinity checks, every request for `SCHED_DEADLINE` is refused with `EBUSY`, as Linux's `sched_dl_overflow` refuses bandwidth it cannot provide. Fork inherits the policy and its parameters; with `SCHED_RESET_ON_FORK` it gives a real-time or deadline child `SCHED_OTHER` at nice 0, and any child a nice value of 0 or more and the default slice, and a deadline thread without the flag may not fork. PI donations are neither inherited nor included in `sched_getparam`.

### Wait queues

A wait queue, `wait_queue_t` (`wait_queue.h`), is the list of the threads that sleep until one condition is true: data in a pipe, a datagram on a socket, a line from a terminal, a disk's answer. A sleeper's entry is the `struct wq_waiter` in its own record, and `poll` brings one for each object it watches, from an array it took before it began, so entering a queue allocates nothing and no queue has a size.

`wq_wait_event` puts the thread on the queue and marks it `PROC_BLOCKED` under the wait queues' spinlock, `wq_spin`, and only then tests the condition, and a pending signal, with interrupts off; it calls `schedule` when both are false, and files itself and tests again when it runs, as Linux's `prepare_to_wait` comes before the test (kernel/sched/wait.c:247). A waker changes the condition first and wakes after, so a wake either came before the test, which then saw the condition true, or finds the thread on the queue and makes it ready, and `schedule` keeps it running. `wq_complete` sets a done flag and wakes in one hold of `wq_spin`, for a waiter whose flag lives on a stack that ends with its wait. A thread still blocked when `schedule` returns, because the processor had nothing else to run, waits in `idle_wait_irq_off`. A pending signal ends the wait with `EINTR`; a signal does not end `wq_wait_event_nointr`, the wait for a lock another thread has or for a transfer a device has in flight for the caller, whose sleeper /proc shows in the state D and counts in `procs_blocked`. Nor does a signal end `wq_wait_event_idle`, a kernel thread's wait for work, whose sleeper /proc shows in the state S and does not count, as Linux does not count TASK_IDLE. A deadline is `wakeup_tick` in the record, which the tick's `proc_wake_sleepers` (`process.c`) acts on. `wq_wake` empties the queue and makes each sleeper ready with one wake preference, in the order the sleepers joined it, oldest first, and the ready list runs them in that order; each sleeper tests its own condition again, so a wake that was not for it costs one test. A sleeper that finds its condition still false joins the tail again, so the oldest waiter for a file lock takes the next release, and processes that ask for it again and again cannot pass it over. A wake also counts what kind of change it was, data, room or a hangup, which an edge-triggered `epoll` reads ([readiness](../io/Readme.md)). Each list is under `wq_spin`, and a wake walks it there, so a record leaves its queue only under the lock.

`wq_wait_event_killable` is the wait of a `vfork` parent and of `execve` for its other threads. Its caller supplies a condition that becomes true when SIGKILL is pending for the thread or its process; the queue code tests no signal itself and returns 0 when that condition is true. The caller then handles the pending SIGKILL, with `exec_one_thread` returning `EAGAIN`. Like Linux's TASK_KILLABLE, the sleep appears in /proc as D, but the hung-task detector skips it. Other signals may wake it to test the condition again and do not end the wait.

### Processors and the big lock

The kernel runs on each enabled processor the firmware lists, up to `NR_CPUS`, 64 (`percpu.h`), or as many as `maxcpus=N` on the command line allows; [the PC platform](../arch/x86/Readme.md) finds and starts them. `smp_start` (`smp.c`) makes the boot processor's idle task, then for each other processor makes its idle task, has the platform start it, and waits up to 100 ms for it to come online. The boot and the processor each decide in one compare-and-exchange of the processor's `admit` word whether it is counted or refused, so a processor that comes as the wait ends is either counted or stopped, never running uncounted. The log says `smp: processors: N online of M`.

Each processor has a `struct percpu` in `cpu_table` (`percpu.h`): the thread it runs, its idle task, the page directory it translates through, its depth in the big lock, its tick counts, and the requests other processors leave it. `this_cpu()` is the running processor's entry, which `arch_cpu_id()` indexes, and `current_proc` is its `current`. A processor changes its own fields; another reads them while it has the big lock, or for a request under `ipi_lock`, and writes only the requests.

The big lock covers the kernel code that has no lock of its own. An entry to the kernel, a system call, a fault or an interrupt, takes it (`bkl_enter`), again when the processor has it already, unless the entry is marked to run without it, and its return gives back what the entry took (`bkl_exit`): each entry frame records in a bit of the thread's `bkl_frames` whether it took the lock (`bkl_frame_push`, `bkl_frame_pop`). A system call runs without it when its number is marked for its ABI (`syscall_unlock`), judged after the tracer's entry stop on the handler the call will run; the dispatcher takes it all the same for a traced thread, a thread with a seccomp filter, descriptor holds left to give back and USB work pending (`syscall_entry_locked`). `sched_yield` is marked, native and i386, and so are the calls that change the regions, `brk`, `mmap`, `munmap`, `mprotect`, `pkey_mprotect`, `mremap` and `madvise` ([memory's Readme](../mm/Readme.md)), and the file calls read, write, pread64, pwrite64, ioctl, fstat, close, poll and ppoll, which take the lock for every step on a descriptor whose type does not declare that it runs without it ([../fs/Readme.md](../fs/Readme.md)) and for the signal state. An interrupt's chain runs without it when every handler of the vector was registered with `ISR_UNLOCKED` (`isr_register_flags`), and an exception when its vector is marked (`exception_unlock`), which the page fault's is. An entry that ran without the lock takes it on its return to user mode only when a signal, a restart, a tracer's stop or an rseq notice waits there (`signal_return_work`). The depth is each thread's: a switch saves it in the outgoing record and the incoming thread takes the lock back at its own (Scheduling), and every sleep gives the lock up, since each goes through `schedule`. An idle wait lets it go whatever the depth (`bkl_drop`) and takes it again at the same depth (`bkl_take_as`). A copy to or from user memory and a prefault hold the address space's `mmap_lock` instead, the residency check needs the big lock held (`vm_resident`, `mm/paging.c`), and memory reclaim takes it when its caller runs without it (`mm/pressure.c`). Code that still needs it checks that it is held in the `rach2-lockdep` kernel (`bkl_assert_held`): the process list and the pid hash, signal posting, the network's receive path and the buffer cache. The lock is a word set by an atomic exchange, and its holder is the processor whose depth is above 0. A waiter past a fixed count of spins claims the lock (`bkl_claim`), and the others leave it to the claimant, since an exchange alone favours the holder's hyperthread and can pass over the others for seconds; a claimant that does not take a free lock is passed over, as under a hypervisor. A switch gives the lock up, and `sched_service_point` lets a claimant have it in a long call on a processor with no switch to make (`bkl_yield`), since the call would otherwise keep it for its whole length. A processor that waits for it answers the requests left for it meanwhile, since the holder may be waiting for that answer, and keeps the lockup detectors going: a wait for the big lock counts as the waiter's watchdog timer, so that the holder alone is reported ([the lockup detectors](../watchdog.Readme.md)). The interprocessor interrupt, the NMI, the machine check and the double fault are taken without it ([the architectures' Readme](../arch/Readme.md)), and so is the tick of a processor that finds another holding it: `bkl_try_enter` takes the lock only when it is free or the processor's own, and the tick that cannot take it ends at once and leaves its charge to the next (`sched_account_tick`), since waiting would take from that processor's user code all the time the holder keeps the lock, and all of it once the waits pass a tick, when the next tick is pending at each return to user mode. The fourth such tick in a row with a process on the processor's queue waits instead (`sched_tick_waits`): under a kernel that always holds the lock no tick would end a slice, and what is queued would wait until the running process blocks. The boot processor's tick waits as well at its fourth in a row, so that its periodic work is at most that late, and while no reference keeps the clock. The parts of the kernel that every processor enters on its ticks, faults and allocations, the run queues, the wait queues, the frame allocator, the heap, the timers and the console, also have spinlocks of their own (`rach2/sys/lib/spinlock.h`). Each is taken after the big lock when both are held, and none is held while the big lock is waited for: `sched_tick_waits` reads the run queue under the run queues' lock alone and lets it go before its tick waits. Locking, below, gives the order of every lock.

A request is a word in the target's record and an interprocessor interrupt that has it look (`smp_service`):

* A shootdown (`smp_tlb_shootdown`): after the entries of a range of user pages change, each other processor that translates through that page directory drops the range's translations, or every user translation, on one request, and the sender waits until each has cleared its word. One sender at a time sends and waits, under `ipi_lock`, with interrupts off, and a processor that waits for that lock answers its own requests meanwhile. `/proc/stat` counts the shootdowns that interrupted a processor as `tlb_shootdowns`, and the interrupts they sent as `tlb_shootdown_ipis`. A processor whose thread has no address space, an idle task or a kernel thread that kept the directory loaded, is not interrupted; the directory is marked stale there and loaded again at the switch to one of its threads. The sender marks it stale, passes a full barrier and reads the processor's thread again, and interrupts it after all when a thread with an address space has come; the switch publishes its thread, passes the run queues' lock, whose release is a locked exchange, and reads the mark, so one of the two sees the other.
* A release (`smp_space_release`): before a directory that no thread uses is freed, each processor that still translates through it loads the kernel's.
* A change of a kernel mapping is dropped on every other processor before the change returns, as Linux's `flush_tlb_kernel_range` does (`arch/x86/mm/tlb.c`): `smp_kernel_flush` sends the range, or all of it from `smp_kernel_mapping_changed`, and waits for each answer, under `ipi_lock`, from any context, with or without the big lock. The kernel maps nothing global, so a processor that drops all its translations drops the kernel's too.
* A barrier (`smp_barrier`), for `membarrier`: each processor named answers with a locked exchange, a full memory barrier, after an `iret` to the next instruction (`arch_sync_core`) for the sync-core barrier, and the sender waits for each answer. The sender holds the big lock, so the threads it found running stay there until the answers come. A thread that `MEMBARRIER_CMD_PRIVATE_EXPEDITED_RSEQ` reached has its rseq critical section aborted on the interrupt's return to user mode.
* A call (`smp_call`): a function runs on the processor named, with interrupts off there, and the sender waits until it has returned, as Linux's `smp_call_function_single` with `wait` does. The processor answers after a full barrier, so the sender sees what the function wrote; on the sender's own processor the function runs at once.
* A stop (`smp_stop_others`), for a panic and a power off, is final. The sender waits up to a second for each processor to take it, then sends each that has not an NMI, which stops it with its interrupts off, and waits 10 ms more, as Linux's x86 stop does.

### Locking

Each lock has a row in one order, outermost first, and a lock is taken only while every lock held is of an earlier row; two locks of one class nest only by a subclass that the lock-order checker is told, as a rename's directories and nodes are (`sleep_lock_subclass`). The `rach2-lockdep` kernel checks the order as it runs, and /proc/lockdep lists each class it has met with its orders ([the lock-order checker](../lib/lockdep.Readme.md)). Rows 2 to 8 are sleeping locks, `struct mutex` and `struct rwsem` (`mutex.h`) and `struct sleep_lock` (`../fs/sleeplock.h`), and rows 9 to 14 spinlocks. No sleeping lock is taken under a spinlock, a sleeping lock's waiter gives up the big lock as every sleep does, and the big lock is never waited for under a spinlock. A kernel thread keeps the big lock from one sleep or service point to the next, since the tick does not switch it (Scheduling), so no processor that takes the lock at a switch sees what the thread changes under it half changed. The one exception is kpsmoused inside a run of mouse commands: its waits for the mouse's bytes let the lock go to a processor that waits for it (`bkl_yield` in `wait_turn`, `rach2/sys/arch/x86/ps2mouse.c`), so that the keyboard's handler runs meanwhile; the run's own state is kept by `cmd_busy`, which makes every other run of commands wait, not by the big lock. A row whose Here is empty names the place of the lock Linux has there, which the kernel has not yet.

### Credentials

Each record has the real, effective and saved user and group ids and up to `NGROUPS_MAX`, 8, supplementary groups (`process.h`). The ids are the kernel's, those of the first user namespace; a process in another one sees and names them through its maps ([namespaces](ns.Readme.md)). The setters change the calling thread's ids, as Linux's do, under the saved-id rules of POSIX: a privileged caller sets any id its user namespace maps, and another moves its ids only among its real, effective and saved ones. A change of an effective id clears the address space's dumpable flag and the parent-death signal, as Linux's `commit_creds` does, and a change of the effective user id takes away the capabilities held in a user namespace (`cred_moved`).

A thread also has a file-system user id and group id, which every check of access to a file and the owner of a new file go by (`proc_fsuid`, `proc_fsgid`); `access(2)` alone judges by the real ids. Each is the effective id until `setfsuid` or `setfsgid` sets it apart (`fsuid`, `fsgid` and the bits of `fs_own`), so a record that never called them needs no second copy kept in step. Every setter of the user ids and every exec clears the bit, which makes the file-system id the effective one again as Linux's setters do (`fsuid_follow`, `exec_commit`); a fork copies it. `setfsuid` takes an id that is the caller's real, effective, saved or file-system one, or any mapped id from a privileged caller, returns the previous id whether or not it changed, and clears the dumpable flag and the parent-death signal when it did (`fsuid_set`). The eight capabilities of Linux's `CAP_FS_SET` are in the effective set by the file-system user id, as Linux's `cap_task_fix_setuid` leaves them: a thread whose file-system user id left 0 fails the file checks an ordinary user fails though its effective user id is 0 (`cap_eff_word` in `ns.c`, `proc_fs_privileged`). A call that sets user ids brings that id back to 0 without them, which the bit `PROC_FSCAPS_OFF` of `fs_own` records until `setfsuid` returns the id to 0, the effective user id comes to 0 from another (`cred_moved`) or an exec; [setfsuid(2)](../../../man/man2/setfsuid.2) has the rules.

A thread holds Linux's 41 capabilities, numbered 0 to 40, but those it gave up (`cap_lost`), while its ids give them: as effective user id 0, or in a user namespace as [namespaces](ns.Readme.md) says (`cap_ids` in `ns.c`); or while an exec gave it those of its ambient set (`amb_granted`, `cap_word`). The kernel keeps one set for the effective and permitted ones, and the inheritable and ambient sets (`cap_inh`, `cap_amb`) with Linux's rules. `capset` keeps the capabilities of the permitted set it is given (`cap_store`) and the inheritable set it is given, and narrows the ambient set to both. An exec of an image of root gives back those of the bounding set (`bset_lost`), from which `PR_CAPBSET_DROP` takes one for good, and of the inheritable set, except under `no_new_privs`, a tracer that is not privileged or directories another process shares, where the image holds no capability its caller lacked, a thread that holds only what an exec gave it from its ambient set as much as any (`exec_ids` in `syscall_proc.c`); a fork passes all four on. `PR_CAP_AMBIENT` raises a capability that is held and inheritable into the ambient set, which an exec keeps for an image without set-id bits and empties for any other, and which a change of the user ids away from root empties. An image whose ids give no capability then holds those of the ambient set and has lost the rest (`exec_ambient` in `syscall_proc.c`), as Linux gives them whatever the uid; bubblewrap's `--cap-add` keeps its capabilities this way, when root runs it and when an ordinary user does in a user namespace. What only a privileged thread may do needs `CAP_SYS_ADMIN`: `proc_privileged` (`process.h`) is true for a thread with effective user id 0 in the first user namespace that has not given it up (`nocaps`), and `PR_CAPBSET_DROP` also needs `CAP_SETPCAP`. `chroot` checks `CAP_SYS_CHROOT`; the other capabilities guard nothing of their own ([capget.2](../../../man/man2/capget.2)).

`exec_ids` chooses the ids of a new image from the file's set-id bits and the caller's effective ids, and `exec_privileges` makes an image that runs with ids its caller lacks not dumpable and lowers its soft `RLIMIT_STACK`, when above 8 MiB, to 8 MiB; [execve(2)](../../../man/man2/execve.2) has the rules. For a caller that is not privileged, the bits do not apply when its thread has a tracer that is not privileged or shares its directories with a process outside its group, since either could change the image once it had the ids. While an exec that applies them runs, `CLONE_FS` fails in the threads that share its directories (`in_exec` in `struct fs_struct`), so that the choice stays true until the image is the process's.

### Resource limits

A record has nine limits, `RLIM_COUNT` in `process.h`, each a soft value that is enforced and a hard value the soft one may be raised to, `RLIM_INFINITY` for none. A limit is a `long`: 32 bits on i686, where a 64-bit value from `prlimit64` past them is kept as no limit, and 64 bits on x86-64. A fork copies the limits and an exec keeps them, but for the lowered stack limit above. `rlimit_set` (`rach2/sys/syscall_proc.c`) writes the limit into every thread of the process; it refuses a soft value above the hard one with `EINVAL`, a raised hard value from a caller that is not privileged with `EPERM`, and a hard `RLIMIT_NOFILE` above `fd_nr_open`, fs.nr_open, with `EPERM` even to root, as Linux does. A resource Linux has and this kernel does not keep reads as unlimited, and a set of one is accepted and changes nothing.

### seccomp

A thread has a chain of filters, newest first, each a classic BPF program, the instruction set of the BSD packet filter (`seccomp.c`). A filter runs over Linux's `struct seccomp_data`: the call's number, the architecture's audit number, `SC_AUDIT_ARCH` of the frame in its `cpu.h` (`0x40000003` on i686, `0xC000003E` on x86-64, and `0x40000003` there for an i386 call by `int 0x80`), the instruction pointer, and the six arguments, each widened to 64 bits. The check at the install, as Linux's `seccomp_check_filter`, takes at most 4096 instructions, loads inside the structure, sixteen scratch words, and jumps that go forward and stay inside the program, so every program ends at a return. A chain may have 32768 instructions, each filter counted with four more. A caller without `no_new_privs` must be privileged to install a filter, and `SECCOMP_FILTER_FLAG_TSYNC` gives the chain to every thread of the process.

The dispatcher (`_syscall_handler` in `rach2/sys/syscall.c`) runs the filters after a tracer's stop at the call's entry, on the call the tracer left, and before the handler. Every filter of the chain runs (`chain_action`), and the action of highest precedence is taken, the actions compared as signed numbers as Linux compares them (`precedence`); [seccomp(2)](../../../man/man2/seccomp.2) has what each action does. The strict mode's four calls are `SECCOMP_NR_` in each `cpu.h`, with `rt_sigreturn` in place of `sigreturn` on x86-64, and for an i386 call there the i386 numbers, `SECCOMP_NR32_` (`strict_allows`). A fork passes the mode and the chain on, a chain is shared and counted by the threads and children that have it, and an exec keeps both.

### Core files

A signal whose default action dumps core, a seccomp kill of the process, and a signal frame that cannot be built or read back end the process through `terminate_current_process` with a core asked for. `terminate_current_process` (`rach2/kernel.c`) writes the core when the process is dumpable ([prctl(2)](../../../man/man2/prctl.2)), its soft `RLIMIT_CORE` is at least a page, and no other thread has begun to end it ([core(5)](../../../man/man5/core.5)). It sets the group's `core_dumping`, sends the other threads `SIGKILL` (`proc_group_exit`), and calls `fs_core_file` (`rach2/sys/syscall_fs.c`) before this thread releases anything. Each other thread, ending by that `SIGKILL`, saves its floating-point state and parks before it releases anything (`core_park` in `coredump.c`), so that none runs in user mode on another processor while its registers are copied or the memory written.

`core_notes` waits until each other thread has parked or ended, as Linux's `coredump_wait` waits, or until an exec by one of them waits for the rest, and builds the `PT_NOTE` segment in the heap: the dumping thread's `elf_prstatus`, the process's `elf_prpsinfo` and auxiliary vector, the thread's floating-point notes (`arch_core_fp_notes`), then each other thread's `elf_prstatus` and floating-point notes. The registers are those `arch_regs_get` reads from the frame at the top of each kernel stack, as the ptrace requests read them ([ptrace](ptrace.Readme.md)). An i386 program's core on x86-64 is ELF32 for `EM_386`, its headers' sizes and offsets those of `core_ia32` where any other has `core_native`: its notes are the i386 structures, `core_prstatus32` with the registers of `ia32_regs_get` and `core_prpsinfo32`, the vector in 4-byte words through `AT_NULL`, and the floating-point and TLS notes of `ia32_core_fp_notes` (`arch/x86_64/ia32_core.c`).

`core_write` takes the regions once into a list, which the program headers and the pages follow, since another process that shares the address space, as a `vfork` child does, is not ended and may change the regions while the writer sleeps; each page is looked up again as it is read, and one unmapped meanwhile is a hole. Each page is read through `paging_access`, which brings in from the file a page of a mapped file the process never touched; a page of anonymous memory it never touched is a hole, which the writer may skip, and so is the vDSO's data page, [vvar], as on Linux (`vdso_is_data`). A process may have up to `VMA_LIMIT`, 65536, regions (`rach2/sys/mm/vm.h`), more than the ELF header's 16-bit count of program headers can record, so a file of 65535 headers or more uses ELF's extended numbering. `fs_core_file` writes the file `core` in the working directory: it unlinks whatever has the name, creates the file with `O_EXCL` and `O_NOFOLLOW`, and writes through a descriptor marked closing from the moment it is opened, so that a process sharing the descriptor table cannot use it. The parked threads go on to their end once the file is written or given up (`core_release`), and the wait status has `WCOREFLAG` only when the whole file was written. A `SIGKILL` sent to the process during the dump is the one signal that is not dropped then: it makes the process's status `SIGKILL`'s and sends every thread `SIGKILL` (`sig_complete`), and the writer stops before its next piece (`core_file_put`), as Linux's `dump_interrupted` stops it, and leaves `WCOREFLAG` out (`terminate_core`).

### Suspend to idle

A write of `freeze` or `mem` to `/sys/power/state` (`rach2/sys/fs/procfs.c`) calls `suspend_to_idle` (`suspend.c`), the sleep state Linux calls freeze. The writer sleeps on a wait queue, and until it wakes the scheduler runs no other process (`suspend_lets_run`), so each processor idles. Interrupts are taken and the clocks count, but no thread's wait on a run queue does: the freeze adds each queued thread's wait so far to its `run_delay` and starts it again when the writer resumes (`sched_hold_waits`), as Linux's frozen tasks leave their queues. The Atheros Wi-Fi station stops before the freeze and restarts after it if it was wanted and rfkill permits it; its association is cleared ([the driver](../network/driver/ath9k/Readme.md)). The clock's alarm interrupt (`rach2/sys/fs/devfs.c`) and a key event (`input_key_event` in `rach2/sys/input.c`) are the wake events (`suspend_wake`): the writer runs, its write returns, and the other processes run again. A signal ends the wait with `EINTR`, and a write while another suspend is in force fails with `EBUSY`.

## Limits

* Most kernel code still runs under the big lock, on one processor at a time, and a long system call delays every other processor's entry that takes it; `sched_yield` runs without it, and the file calls marked above take it for every descriptor type, since none yet declares that it runs without it. The timed-wake measurements under Results show the delay this causes under load. Console writes now offer the lock after each chunk; a single chunk and interrupt work still hold it.
* Ordinary threads and equal-priority RR threads have a slice of one 1 ms tick; nice values, the slices `sched_setattr` asks for and I/O priorities are kept and not read. The load averages count no sleeper, uninterruptible or not.
* `SCHED_DEADLINE` is refused with `EBUSY` after its argument, privilege and affinity checks because the scheduler cannot provide deadline bandwidth. The utilization clamps are refused with `EOPNOTSUPP`, as by a Linux built without `CONFIG_UCLAMP_TASK`.
* The kernel runs on at most 64 processors, and an affinity mask has 64 bits.
* Privilege is `CAP_SYS_ADMIN` for every operation that asks for it, where Linux asks for the one capability each needs; the effective set is the permitted one. A thread whose ids are not root holds no capability but those an exec gave it from its ambient set.
* A thread has at most 8 supplementary groups, where Linux allows 65536.
* `clone` refuses `CLONE_SIGHAND` without `CLONE_THREAD`, an exit signal other than zero or `SIGCHLD` for a process, `CLONE_PIDFD`, and the cgroup and time namespaces. No descriptor refers to a process, so `waitid`'s `P_PIDFD` fails with `EBADF`.
* `execve` follows one level of `#!`, and reads a first line of at most 128 bytes.
* Nine resource limits are kept; Linux's others read as unlimited.
* `getrusage` and `wait4` report CPU time, resident memory, page faults and voluntary and involuntary context switches; the other resource counters are zero. Context switches include ended threads and reaped descendants. The resident memory peak is sampled when asked and where an address space ends, not at every fault.
* `prctl` takes twelve options, the parent-death signal, the dumpable flag, the name, the child subreaper flag, `no_new_privs` and the seccomp mode, each set and read; any other is `EINVAL`.
* seccomp has no user notification: a filter cannot be installed with a listener, and `SECCOMP_RET_USER_NOTIF` fails the call with `ENOSYS`. `SECCOMP_RET_LOG` allows the call and logs nothing.
* `personality` takes only `PER_LINUX` and `PER_LINUX32`, and its flags change nothing; the kernel places no address at random.
* Suspend to idle stops the Atheros Wi-Fi station; other devices stay up. A write of `mem` to `/sys/power/state` suspends to idle as `freeze` does, and the kernel has no suspend to memory or to disk.

* `tests/schedattrprobe.c`: every supported policy set with `sched_setattr` and read back with `sched_getattr`, `sched_getscheduler` and `sched_getparam`, the structure's size rules, the slices, the deadline refusal and affinity checks, a fork's reset, and what a caller without root is refused and what `RLIMIT_NICE` and `RLIMIT_RTPRIO` allow it.

* `tests/musl/schedmusl.c`, `tests/musl/prctlmusl.c`, `tests/musl/seccompmusl.c`, `tests/musl/coremusl.c` and `tests/musl/callsmusl.c`: thread ids, nice values and the scheduling calls, `prctl`, seccomp filters, core files, and among other calls `getcpu`, `personality` and a suspend to idle.

Other suites ([the suites](../../../tests/system/suites.md)):

* `tests/run smp` boots one processor, four, and two of four, and on each runs `tests/musl/smpmusl.c`, which finds the processors and runs a stress of fork, exec, pipes, futexes and `munmap` across them. On two processors it also runs the debug shell's preemption test and ring-3 payload, raises an NMI, which must stop the machine, holds the debug shell's lockups for the lockup detectors to report, and it runs a parallel build on four whose every processor must count user time. Each boot is a machine case of [`tests/cases/machine.smp.json`](../../../tests/cases/machine.smp.json).
* `tests/run fpu` checks that a process's floating-point state is its own across switches.
* `tests/run wakelat` runs `wakelatmusl` on four CPUs, with idle, arithmetic, system-call and mixed loads. Each mode makes 64 waits through each of nanosleep, absolute clock_nanosleep, poll, epoll_wait, timerfd and a timed futex. Each busy CPU has one pinned thread of each selected kind; the system-call load maps, faults, protects and unmaps 128 pages per iteration. The probe prints lateness percentiles and the counts above for the eight latest-returning samples, checks the timeout results and accounting subsets, and joins every worker. It prints `/proc/stat`'s `bkl_` lines before the load, after each interface's measurements and after joining the workers. Its arguments select the sample count, load bits (1 for arithmetic, 2 for system calls) and sleeper CPU. The same static executable runs on Linux, whose status file has no Rach2 counters. Times are printed for comparison, not judged against a fixed machine-dependent limit.
* `tests/run exitline` checks that the plain process-exit line is printed under the debug shell and nowhere else.
* `tests/run memory` includes the overrun of a kernel stack ([the architectures' Readme](../arch/Readme.md)).

`tests/run host` runs the host tests ([the host tests](../../../tests/host/Readme.md)) of this directory: `sched_hosttest.c`, `wait_queue_hosttest.c`, `smp_hosttest.c`, `process_timer_hosttest.c`, `exit_hosttest.c`, `elf_hosttest.c`, `uimage_hosttest.c`, `coredump_hosttest.c` and `corefile_hosttest.c`, in `tests/host/`.
