# Processes

The process subsystem, `rach2/sys/proc/` with the handlers in `rach2/sys/syscall_proc.c`, runs programs as processes. It keeps a record for each thread and a thread group that makes a process of several; makes processes and threads with `fork` and `clone`, loads programs with `execve`, and ends them with `exit` and reports their end to `wait`; schedules them on every processor, with the big lock over the kernel code that has no lock of its own; and keeps their credentials, resource limits and seccomp filters, writes their core files, and keeps them from running during a suspend to idle. A program sees Linux's process calls for its architecture, whose contracts are in section 2 of the manual. Four parts of this directory have documents of their own: [signals](signal.Readme.md), [ptrace](ptrace.Readme.md), [futexes](futex.Readme.md) and [namespaces](ns.Readme.md). The context switch and the entry to the kernel are [the architectures'](../arch/Readme.md), the thread pointer is [thread-local storage](../arch/tls.Readme.md), and the address space a process runs in is [memory's](../mm/Readme.md).

## Results

A thread woken from a timed wait under load returns tens of milliseconds late, where Linux returns within a few, because the woken CPU waits for the big kernel lock. In the latest measurement, on 2026-11-10 on the testing PC's WSL under KVM with four CPUs and 512 MiB, `wakelatmusl` under the mixed load (one arithmetic and one system-call thread on each CPU) had 158 of its 384 timed waits return more than 10 ms late, with a maximum of 80.920 ms; Debian 13's kernel 6.12.115 under the same load had none over 10 ms and a maximum of 4.637 ms. The console's writes offer the lock between their 256-byte chunks ([the terminal layer](../tty/Readme.md#the-console-terminal)). No wake-latency bound is established; the owner left the change to the big lock for the next locking milestone. The measurements, the accounting of the late waits and the lock holders behind them are in the timed-wake task's record under `dev-log/`.

To repeat the Rach2 measurement on the testing host, use `ARCH=x86_64 RACH2_QEMU_ACCEL=kvm RACH2_WORKERS=1 tests/run wakelat`. The Debian reference runs the same executable with `tests/graphics/debian-ref/debian-ref.sh run -p std-vga -c 4 -m 512 -i build/x86_64/tests/musl/wakelatmusl`, `ACCEL=kvm`, and the guest command `/tmp/wakelatmusl 64 N` for load bits N from 0 to 3.

### The kernel's interfaces

The rest of the kernel reaches processes through these headers:

* `process.h`: `current_proc`, the running thread's record (`percpu.h`); `get_process`, a record by its id; `proc_privileged`, whether a thread has privilege over the whole system; `proc_in_syscall`; and the signal functions, `signal_post` and the rest, which [signals](signal.Readme.md) describes.
* `sched.h`: `schedule`; `sched_make_ready`, which makes a new or a stopped thread ready; `sched_wake_stopped`, which makes a thread ready only while it is stopped, testing the state under the run queues' lock, for a `SIGKILL` that a post without the big lock and a holder of it may both send; the wakes of a blocked thread, which test its state under the run queues' lock so that of two wakers one makes it ready, and mark it woken: `sched_wake_blocked`, a wait queue's, which returns the processor to interrupt, `sched_wake_signal`, a signal's, which clears its deadline, or interrupts the processor a running thread is on, and `sched_wake_due`, its deadline's; `sched_kick_cpus`, which sends the interrupts a waker gathered once its own locks are let go; `sched_preempt`, which `sched_tick` calls once a switch is due, `sched_tick`, which an interrupt calls on its way out, `sched_service_point` for a long system call, `sched_give_way` for a long walk that may sleep, and `idle_wait_irq_off` and `idle_wait_irq_on`, the only idle waits.
* `wait_queue.h`: `wq_wait_event`, which a signal ends, with the big lock or without it, `wq_wait_event_as`, which names its sleep for /proc/PID/wchan, `wq_wait_event_nointr`, `wq_wait_event_killable`, `wq_wait_event_idle`, `wq_wait_event_sigflag`, which the signal-work flag alone ends, for a caller that judges the signal itself, `wq_wake`, `wq_wake_all`, `wq_wake_proc` for a waker that took a sleeper off its queues itself, `wq_wake_all_deferred`, which adds the processors to interrupt to its caller's set for `sched_kick_cpus` after the caller's lock, `wq_complete`, which sets a done flag and wakes together, `wq_poll_add` and `wq_poll_remove` for `poll`, `wq_entry_add` and `wq_entry_remove` for a record with a wake function that another thread may free the queue under, `wq_wake_nested` for a wake function that wakes a queue of its own, `wq_ready_deferred` for one that makes its sleeper ready, and `wq_wake_free`, which tells each such record that its queue is about to be freed.
* `mutex.h`: `mutex_init`, `mutex_lock`, `mutex_lock_nested`, which tells the lock checker the depth of a take of a mutex of the same class, `mutex_lock_interruptible`, `mutex_lock_killable`, whose wait only SIGKILL ends, `mutex_trylock` and `mutex_unlock`, as Linux's `struct mutex` (kernel/locking/mutex.c:281,990,1014), and `rwsem_init`, `down_read`, `down_read_trylock`, `down_write`, `up_read` and `up_write`, as its `struct rw_semaphore` (kernel/locking/rwsem.c:1521,1574); each keeps its state in an atomic word, so that a take that finds it free and a release are one atomic operation each, as Linux's fast paths are (kernel/locking/mutex.c:166-182, kernel/locking/rwsem.c:248-272), the mutex's word holding its holder's record and the rwsem's spinlock keeping only the count of waiting writers, and each keeps its waiters on a wait queue, which a release wakes only when a waiter is on it, as Linux's releases wake only with a waiter recorded, and each init site is a class of the lock-order checker. A mutex's taker that finds it held spins while the holder runs on another processor, as Linux's `mutex_optimistic_spin` (kernel/locking/mutex.c:441-510): the spinners queue one behind another, each on its processor's place, so that only the first tries the word (`osq_lock`, as Linux's kernel/locking/osq_lock.c), and a spinner gives up and sleeps when the holder sleeps or halts, its processor is preempted by the hypervisor (`arch_cpu_preempted`), the holder waits for the big lock the spinner holds, or the spinner must give way (`sched_spin_on`). Only a thread that no interrupt switches spins (`sched_spin_pinned`), since its place is its processor's. A sleeper that wakes to find the mutex taken again sets the word's handoff flag, and the next release gives the mutex to the oldest sleeper and wakes that one alone (`wq_wake_first`), as Linux's MUTEX_FLAG_HANDOFF, so that spinners do not starve the sleepers; a sleeper whose wait a signal ends but that was handed the mutex first holds it. An interruptible mutex wait tests only the signal-work flag; with no mutex held or recorded as held, it judges the signal under the big lock, discarding an ignored signal and waiting again.
* `smp.h`: `bkl_enter` and `bkl_exit`, which the interrupt routers call (`rach2/sys/arch/x86/isr.c`), `bkl_held`, and `bkl_assert_held` (`rach2/sys/lib/lockdep.h`) for code that still needs the lock; `smp_tlb_shootdown`, `smp_space_release`, `smp_kernel_mapping_changed` and `smp_kernel_flush`, which the page tables call; `smp_barrier`, which `membarrier` calls; `smp_call`, which KVM's VMX backend calls to clear a VMCS on the processor where it is active; `smp_stop_others`, for a panic and a power off; and `smp_start`.
* `seccomp.h`: `seccomp_permit`, which the system call dispatcher calls (`rach2/sys/syscall.c`).
* `coredump.h`: `core_notes` and `core_write`, which `fs_core_file` in `rach2/sys/syscall_fs.c` writes through.
* `suspend.h`: `suspend_to_idle`, which a write of `freeze` or `mem` to `/sys/power/state` calls, and `suspend_wake`, which the clock's alarm and the keyboard call.

## Design

Real interval timers keep monotonic nanosecond deadlines and intervals; their signal consumption forwards the original grid, with no rounding to coarse ticks. `proc_timer_update` keeps records with a real alarm or a blocked timed wait on an intrusive list and arms their next deadline on the local event timer, including a deadline measured only in ticks. A blocked thread records its wake event's CPU, and an alarm its arming CPU; a pass on another processor may wake a due thread or mark its alarm, but rearms no future event of that CPU. Blocking in `schedule` and a wake (`sched_ready_locked`), both under `sched_lock`, a timed sleep's own blocking (`sleep_time_come`), a change of the alarm (`proc_alarm_set` or `proc_alarm_set_ns`) and a record's deletion refresh membership under the list's own spinlock, `timer_list`, which comes after `sched_lock` (Locking), as Linux links and unlinks a timer under its base's lock (`lock_timer_base`, kernel/time/timer.c:1034-1051). The timer pass visits only this list, under the same lock, which it lets go before it wakes the records due, holding `sched_lock` across both so that no record collected is freed before its wake (`timer_pass`), as Linux's `expire_timers` lets its base's lock go around each callback (kernel/time/timer.c:1813-1850); untimed blocked threads add no timer work. The tick that makes the clock's pass makes the timer pass: the boot processor's, or another processor's when the tick count has not moved over two of its ticks, so that no timeout waits while the boot processor runs with interrupts off (`timer_handler`, `kernel.c`); `/proc/stat` counts those as `timer_passes_late`. A wait whose deadline is an absolute time of real time, an absolute `clock_nanosleep` on `CLOCK_REALTIME`, a futex wait on that clock or an `mq_timedsend` or `mq_timedreceive`, keeps in `rt_steps` the clock's step count (`rtc_step_count`) it counted its tick at; the pass also wakes such a thread once a step of the clock, a setting (`rtc_set_realtime`, `rtc_shift_realtime`) or a leap second, has moved the count on, and the wait counts its tick again from the clock as it then is, as Linux's clock_was_set retriggers the hrtimers of the real-time base. A slew moves no tick, since the tick count is slewed with real time ([the kernel](../../Readme.md)). A wait whose tick comes before real time reaches its time, as one can when the clock between ticks reads a little behind the tick count, counts its tick again too, since Linux's hrtimer never expires before its clock reaches its time. A sleep that keeps the time it ends at in `wakeup_ns`, a `nanosleep` or a `clock_nanosleep` on the monotonic, boot or real-time clock, a timed futex wait or an `mq_timedsend` or `mq_timedreceive`, ends at that time and not at its tick: when it blocks, the sleep puts itself on the list and arms the timer's interrupt between ticks for its time however far it is (`timer_wake_at`), as Linux starts the sleep's hrtimer, and every pass arms each sleeper's time again, since a processor keeps only the earliest time asked of it; the event's combined time and tick pass (`proc_wake_sleepers`), which takes no big lock, make ready each sleeper whose time the monotonic clock has reached, as Linux's hrtimer sleeper ends one; the wake's lateness is read from the clock at the wake, not from the pass's one reading. A sleeper that the pass finds at its time is marked expired (`wakeup_fired`), the record being the time the pass tested, which a wait accepts only as its own: a wait sets its time and step count, clears the record of the waits before it, and ends, under `sched_lock` (`proc_wait_set`), which the pass holds from its test to its record, so no pass marks expired a wait whose time it did not test, as Linux's sleeper waits for its hrtimer's callback to finish before its next sleep (`hrtimer_cancel` in `do_nanosleep`). The end returns the record as it stands under that lock, and a futex, message-queue or real-time sleep judges its expiry by that value, never by a reading before the end, which a pass held between its test and its record would leave short while a step of the clock let the thread leave its wait. A `nanosleep` or `clock_nanosleep` that finds a signal pending before its time ends its wait so first, and returns 0, with no remainder and nothing for restart_syscall, when the record is its time, as Linux's do_nanosleep returns 0 once its hrtimer's callback has cleared its task, before it looks at the signal (`sleep_until`, `syscall.c`). The clock decides, not the tick count, which runs behind it by up to half a tick. A signal's remainder is the time left to that time where the interrupt between ticks ends the sleep (`timer_wakes_between`). A time past what nanoseconds since boot hold, about 292 years, is none, and such a sleep ends at its tick ([the timer between ticks](../arch/x86/Readme.md)). `/proc/stat` reports the pid, uid and timer entries examined as `process_pid_steps`, `process_uid_steps` and `process_timer_steps`, and timer passes as `process_timer_passes`, modulo 2^32.

The big lock accumulates time-stamp counter cycles around each outer acquisition. `/proc/stat` reports the sum and longest acquisition as `bkl_wait_us` and `bkl_wait_max_us`, converted at the calibrated invariant TSC rate, or zero when none was calibrated. `bkl_wait_max_holds` counts outer holds completed during that same longest acquisition, modulo 2^32, including a hold already in progress when it began. A drop for an idle wait counts as a release; the count is of holds, not distinct processors. These times include time a hypervisor stopped the waiting processor. The counters change and are read under the big lock; an acquirer snapshots the 32-bit release count before waiting and subtracts it after taking the lock.

Each `bkl_wait_max_hold` line names one of those holds: its entry, as vector and system call number (-1 for none) or as `take 0` or `take 1` for a take after an idle wait or a switch, which `smp.c` records as `BKL_NR_IDLE` and `BKL_NR_SWITCH`, and its full hold time in microseconds. The last 32 are kept, oldest first, or all when fewer. A hold may begin before the acquisition, so its full time can exceed the wait. The release records are copied only when an acquisition sets a new maximum; later holds do not replace them.

debugfs's `bkl/calls`, `bkl/profile` and `bkl/tick` split the lock's time by what holds it ([debugfs(5)](../../../man/man5/debugfs.5)). The router (`_isr_router`, and `ia32_fast_syscall` for an i386 call through `__kernel_vsyscall`) reads the cycle count before a system call's entry takes the lock and passes it to `smp_call_end` at the handler's return, which counts the call and its time under its number; an ioctl's request, of either ABI on x86-64, takes a slot of 256 (`isr_call_ioctl`, `bkl_note_ioctl`) and counts there too. `bkl_acquire` keeps each outer wait in the processor's record, and `bkl_hold_end` adds it, with the hold, to the entry the hold is charged to and to the ioctl request it took the lock for. The tick that finds its processor already holding the lock samples the instruction it stopped and three callers above it, with the entry the running process is in, into a table of 16384 slots (`bkl_profile_sample`), so that the samples, at the processor's scheduler rate, give the kernel's time under the lock by function, by call path and by the system call, vector or ioctl request that spent it; code that keeps interrupts off is not sampled, nor is the writing of `bkl/profile`'s text (`smp_profile_show`), so that its lines and `lost` sum to its samples; the rest of a read, its entry, `text_fill`'s allocation and the copy out, is sampled. The entry is kept in the process's record: each router marks it there before its handlers run and puts the outer one back after them (`bkl_entry_push`, `bkl_entry_pop`), so that it stays with a sleeping call's process while the switch lets the lock go (`schedule`, `bkl_drop`) and the processor runs another process, which takes the lock again at its own depth in the switch's tail (`schedule_tail`), and the sleeping process takes it again at the depth it slept with when it runs. The tick's handler (`timer_handler`, `kernel.c`) reads the cycle count after each part it runs and charges the part's time to its row (`bkl_tick_charge`), in rows each processor keeps for its own ticks, which run without the lock, and `bkl/tick` sums: the clock's pass, the accounting, the timer pass and the boot processor's services with locks of their own without the lock, then the try for it, `lock`, and the parts under it. A locked part that ran inside a hold of the code the tick interrupted is charged to `nested` as well, since its time is that hold's. A write of `kernel` to `bkl/profile` chooses its whole-kernel mode, every tick in kernel mode outside an idle halt, and `kernel TID` that mode for the thread TID alone. A write to any of the three files zeroes it; the requests keep their slots, so a call under way when the counts are zeroed is still counted under its own request. A write of `thread TID` or `thread NAME` to `bkl/calls` has it count one thread alone, its calls, entries and holds (`filter_wants`), and note under the run queues' lock each switch away from it (`bkl_note_switch`, called by `schedule`): the thread switched to while it could still run, in a yield or not, and the call and ioctl request it slept in, so that a program's loop is split by thread, as Wine's command thread's waits are split from its spinning sibling's. `kernel.c` registers the three files after the processors start.

`bkl/long` keeps the latest interrupt sample of each of the last 32 holds sampled at 16 ms or older. A record has the sample's TSC timestamp, the hold's age, CPU, thread, command, entry and eight stack PCs. Later interrupts in the same hold replace its sample. The ring is written under the big lock with local interrupts off; a read copies it with interrupts off before sizing and rendering the same bounded snapshot. The read path does not sleep between these calls. A write empties it. A hold entirely spent with interrupts off can leave no sample. `kernel.c` registers this file beside `bkl/calls` and `bkl/profile`; [debugfs(5)](../../../man/man5/debugfs.5) gives the columns.

### The records

Each thread has a record, `struct process` (`process.h`), from the kernel heap (`alloc_process`). The records are on one list, `proc_list`, in the order they were made; `get_process` finds one in a pid hash that doubles before its load exceeds one record per bucket, and separate ready lists hold the threads waiting to run. A record is in one of six states: `PROC_READY`, `PROC_RUNNING`, `PROC_BLOCKED`, `PROC_STOPPED`, `PROC_ZOMBIE`, and `PROC_UNUSED`, which marks a record that `fork` is still building or that a reaper has taken and is freeing, so that no wait, signal or selection takes it. A new record takes the id after the last one given, passing over any id a record has as its own, its process group or its session, which two more hashes of the same size index by group and by session (`proc_set_group`, `proc_group_held`), so that neither the allocator nor `setsid` walks the list; the ids are below `pid_max`, 2,000,000,000 unless `/proc/sys/kernel/pid_max` has been written, and past it start again from 300, or from 1 before 300 has been given, as Linux 6.12's `alloc_pid` does. A free id comes within three tries for each record, and when one lap of the range finds none, `fork` fails with `EAGAIN` (`pid_next`). The boot's self-tests and the kernel threads a driver starts at its bind take ids before the first program, and `proc_reclaim_boot_pids` then starts the numbering again at 1, giving a kernel thread that holds id 1, such as the DRM commit worker, the next free id, so that init is process 1, which BusyBox's `reboot`, `halt` and `poweroff` signal. Within one boot, then, an id names one process until two thousand million more have been made, unless root lowers `pid_max`; `tools/flow/release.sh` relies on this when it takes an id with `/proc/sys/kernel/random/boot_id` as a process's identity on the Lenovo, and a change of `pid_next` that reuses ids sooner changes that.

The list, the pid index, the indexes by group, by session, by parent and by tracer, and each thread group's list of its threads change under the big lock and under the list lock, `tasklist_lock` (`process.c`), as a writer, as Linux 6.12's change under `tasklist_lock`: a record's publication (`proc_publish`) and its free, a change of parent, tracer, group or session (`proc_set_parent`, `proc_set_tracer`, `proc_set_group`), and the exchange of ids at `execve` (`proc_exchange_pids`). A walk under the big lock alone therefore stays correct, and code that runs without the big lock walks them under the list lock as a reader (`tasklist_read_lock`), which `get_process`, `proc_children`, `proc_tracees` and `proc_group_held` accept as they accept the big lock. The lock is a spinlock held with interrupts off, so a reader excludes other readers as well as writers, and neither sleeps under it.

`get_process_ref` finds a record by its id with neither lock, as Linux's `find_get_task_by_vpid` does: it walks the pid index under `rcu_read_lock` (`../lib/rcu.h`) and takes a reference in the record's `refs`, only while the count is above 0. The list holds one reference from the record's publication until `free_process`, which takes the record off the list and the indexes, gives back its descriptors, directories, filters, namespaces and exec workspace, and drops that reference; the last `proc_ref_put` queues the record for a grace period later (`call_rcu`), when the grace-period thread frees it with its floating-point area and drops its reference to its thread group, as Linux's `put_task_struct` and `delayed_put_task_struct` do. A lookup that is in its read section when the record leaves the index may still be on it, and the grace period outlasts the lookup. A holder of a reference may read the fields that do not change once the record is made, the record's thread group with its signal state, and the floating-point area, while the record ends and is reaped; the record's address space and kernel stack go at the reap whatever references are held. A growth of the pid index frees the old one a grace period later, and a growth or an exchange of ids, which moves records between chains, marks a sequence count that sends a lookup that found nothing round again (`pid_seq`).

A process is a thread group, `struct tgroup` (`tgroup.h`). Each thread is a record of its own, with its id, registers, kernel stack, thread pointer, blocked mask, pending signals and CPU time. The group has what the threads share: the signal dispositions and the signals sent to the process, a stop in effect, the POSIX timers and the interval timers of processor time, the CPU time and page faults of the threads that have ended and of the children reaped, the most memory an address space of the process had in use, the OOM score adjustment, and the process's end: `exiting` and the status the process ends with after `exit_group` or a fatal signal, `exec_task` while an `execve` ends the other threads, and `core_dumping` while a core is written. The thread whose id is the process id is the group's `leader`. Every record's `tgid` is that id, which `getpid` reports, and its `pid` is the thread's own, which `gettid` reports. `live` counts the threads that have not ended, and `refs` the records, pidfds and CPU clocks that point at the group, by atomic operations (`tgroup_get`, `tgroup_put`), since a record's last reference may go without the big lock.

Three more parts of a process are counted records of their own, which `clone` shares or copies: the address space, `struct mm`, shared under `CLONE_VM` and copied on write otherwise ([memory](../mm/Readme.md)); the descriptor table, shared under `CLONE_FILES` ([the file system layer](../fs/Readme.md)); and `struct fs_struct` (`process.h`), the working directory, the root directory `chroot` set and the file mode creation mask, shared under `CLONE_FS`. A thread that a C library makes shares all three with the rest of its process.

The thread group's `execed` flag records a successful `execve` since the group was made. `exec_commit` sets it after any change of leader, and a new group starts with it clear. `setpgid` refuses a parent's request for a child whose flag is set with `EACCES`; a process may still change its own group ([getpid(2)](../../../man/man2/getpid.2)).

Process 0, `proc_idle`, is the kernel's own. `kernel_main` (`rach2/kernel.c`) makes it on the boot stack with no address space, and the boot and the debug shell run as it. The first program, and each program the debug shell runs, start on the boot stack too, without a fork (`enter_program` in `rach2/kernel.c`). Each processor also has an idle task (`smp_idle_task` in `smp.c`): a record off the list, with id 0 and a guarded stack of its own, which no system call can reach and no reaper frees.

### Fork and clone

`fork`, `vfork`, `clone` and `clone3` all reach `do_fork` (`rach2/sys/syscall_proc.c`) with a `struct fork_req`: the clone flags, the child's stack pointer, and the addresses of the ids the call stores. `clone_with` refuses a flag it does not know with `EINVAL`, and accepts zero or `SIGCHLD` as the exit signal of a new process; `CLONE_THREAD` needs `CLONE_SIGHAND`, which needs `CLONE_VM`. `do_fork` works in this order, and a failure at any step returns to the parent with what was built for the child given back:

1. It begins recording signals sent to several processes during the build (`fork_delay_begin`; [signals](signal.Readme.md#sending)), restarts after taking any signal work already pending, lets the caches give back memory (`mem_balance`), and refuses with `EAGAIN` a caller whose real user already has `RLIMIT_NPROC` records, each thread and each zombie counted (`fork_nproc`). A count for each real uid is kept from allocation until the record is freed, and a change of real uid transfers that charge. A child being built reserves its place before any building step can sleep.
2. It takes a record already marked `PROC_UNUSED` while the child is built, since the building may sleep (`alloc_process_fork`). The record starts without a descriptor table or standard descriptions. A thread takes a reference to its parent's group directly, and `CLONE_FS` takes a reference to the directories directly; neither allocates a record that the clone would discard. A shared group counts the new thread as live only at step 9; a failed build drops its reference without changing the live count.
3. It gives the child its address space, the parent's own with one more user under `CLONE_VM` and a copy-on-write copy otherwise (`fork_mm`), and a kernel stack (`kstack_alloc`), whose guard page [the architectures' Readme](../arch/Readme.md) describes.
4. The child's parent is the caller's process, or the caller's parent under `CLONE_THREAD` and `CLONE_PARENT`. `fork_ids` copies the credentials, the limits, the session and process group, the nice value and I/O priority, the persona, `no_new_privs`, the capabilities and the bounding set, the seccomp mode and filters, the OOM score adjustment and the program name.
5. The child's thread pointer is the one given with `CLONE_SETTLS`, or the parent's ([thread-local storage](../arch/tls.Readme.md)), and the floating-point registers are saved into the child's area as they are now.
6. `fork_shares` shares or copies the directories and the descriptor table. A copied table refers to the same open file descriptions, each with one more reference. `CLONE_FS` fails with `EAGAIN` while a thread that shares the record is in an `execve` that applies set-id bits (Credentials, below). Then `ns_fork` gives the child its namespaces and its numbers in its PID namespaces ([namespaces](ns.Readme.md)), so a failure to copy the files or directories reserves no PID there, as Linux 6.12.115's `copy_process` orders these steps (`kernel/fork.c:2403-2406, 2431-2437`).
7. The child's id is stored where `CLONE_CHILD_SETTID` and `CLONE_PARENT_SETTID` ask, and the address given with `CLONE_CHILD_CLEARTID` is kept for the thread's end ([futexes](futex.Readme.md)). Under `CLONE_PIDFD` a pidfd of the child is made, of the new thread alone under `CLONE_THREAD` as on Linux 6.9, its descriptor reserved in the caller's table and its number stored where the call asks (`fork_pidfd`); it is installed after the next step, and given back if that step refuses the child.
8. A SIGKILL pending for the caller, an `exit_group` or an `execve` by another of its threads refuses the child with `EINTR`, since a child made then would outlive its process's end. Nothing after this step sleeps. `ns_fork_commit` rechecks that the child's PID namespaces still admit it and publishes a new namespace's reaper ([namespaces](ns.Readme.md)).
9. `fork_signals` adds the child to the caller's group under `CLONE_THREAD`, and otherwise gives its new group a copy of the dispositions; either way it has the caller's blocked mask and no inherited pending signal of its own. clone3's `CLONE_CLEAR_SIGHAND` then sets every handler the child's group has back to the default and keeps the ignored signals ignored (`fork_clear_handlers`). `arch_fork_frame` lays out its kernel stack so that its first switch returns to user mode with 0 as the call's result.
10. The child takes the parent's processor and affinity and a depth of 1 in the big lock. `fork_start` gives a new process the signals recorded during the build, ends the recording and makes the child runnable, with interrupts off; it sends SIGKILL to any child whose caller's process began to end after step 8 ([signals](signal.Readme.md#sending)). A tracer's event is reported ([ptrace](ptrace.Readme.md)). Under `CLONE_VFORK` the parent then waits, in a sleep only SIGKILL ends, until the child calls `execve` or ends (`proc_vfork_wait`).

The parent gets the child's id in the parent's PID namespace.

A zero-signal child sets its group's `no_child_signal`: its end wakes the real parent's wait without posting SIGCHLD, and an ordinary wait does not select it. `__WCLONE` selects it, and `__WALL` selects either kind. `CLONE_PARENT` inherits the caller's exit notification choice and parent generation snapshot. `CLONE_UNTRACED` prevents inherited tracing and the parent's fork event; it does not prevent a later explicit attach. A tracer's wait includes every tracee regardless of these wait flags.

A successful exec and orphan adoption restore SIGCHLD. A child also records its real parent's successful-exec generation; if that generation changed before notification, the child's end restores SIGCHLD and ordinary wait selection. Generation wrap resets existing children's snapshots to zero before setting the parent's next generation to one, so an old child cannot compare equal by wrap. `child_signal.c` implements generation advance and notification choice.

### execve

When a nonleader thread takes its leader's place (`exec_take_leader`), `proc_exchange_pids` exchanges both kernel IDs, the IDs in every PID namespace and the `serial` of each ID's lifetime, as Linux 6.12.115's `de_thread` exchanges whole PID objects (`fs/exec.c:1112`). The process keeps its number in every namespace, so its pidfds and the leader's go on naming it, and releasing the old leader's record frees the former thread's numbers and hangs up the thread's pidfds.

`sys_execve` builds the new image beside the old one and replaces the old one only when nothing can fail any more, so every refusal and every failure of the load returns to the caller with its image, its credentials and its descriptors as they were. Each call has a workspace of its own, `struct exec_state`, from the heap, which the caller's record points at (`exec_ws`), since a read of a program on a mounted volume sleeps and another `execve` may run meanwhile. `exec_run` works in this order:

1. It copies the path, joined to the working directory when it is relative, and makes the new address space (`mm_new`).
2. `exec_open` resolves the path from the caller's root, checks the execute right, and opens the program, noting whether the caller may read the file and what its set-id bits would do; [execve(2)](../../../man/man2/execve.2) has what it refuses. The new address space keeps the program's file from then on ([memory](../mm/Readme.md)), and the load reads that file whatever is put at its path meanwhile. A path that ends on a link of `/proc/PID/fd` goes on to the file its descriptor is open on (`proc_fd_file`), which is checked as one named by its own path; a file off the KRFFS root then gives the new address space the path its descriptor was opened by as its name. A path through `/proc/PID/exe` is replaced by the program's own path (`exec_link_name`).
3. `exec_copy_args` copies the path and the strings of the environment and of argv onto pages taken for the new stack (`uimage.c`, below).
4. A file that is not an ELF image of the architecture and begins with `#!` gives the path of its interpreter (`exec_script`, `exec_shebang`): argv[0] is taken away, the interpreter, its one argument and the script's path go in its place, and the interpreter is opened as the program. An interpreter that is itself a script is refused.
5. `uimage_place` makes room for the pointers and the auxiliary vector below the strings. `exec_ids` chooses the ids the image runs with (Credentials, below), and `exec_build` loads the program, and the interpreter whose path its `PT_INTERP` gives, into the new address space (`elf.c`, below), makes the regions, maps the vDSO one free page above the mmap base (`vdso_map`), refuses with `ENOMEM` an image whose regions pass `RLIMIT_AS`, and writes the initial stack, with 16 bytes from the kernel's random generator for `AT_RANDOM` and, on x86-64, the vDSO's address for `AT_SYSINFO_EHDR`. On x86-64 an ELF32 i386 program (`exec_classify`) gets Linux's compat layout from `exec_layout`, the `IA32_` addresses of `arch/x86_64/cpu.h`, the 32-bit vDSO, `AT_PLATFORM` `i686`, and `AT_SYSINFO` beside the rest; its address space is marked `compat` in `struct mm`, which the exec frame (`arch_exec_frame`), `/proc/PID/auxv` and the mapping calls read.
6. `exec_files_stage` takes the storage of a descriptor table of the caller's own when the caller shares one, so that the allocation fails while the call can still return.
7. `exec_one_thread` sends every other thread of the process SIGKILL and waits until they have ended or SIGKILL is pending for the caller. A pending SIGKILL clears `exec_task` and returns `EAGAIN` before the new image is committed; the caller ends on its way back to user mode, as Linux 6.12.115's `de_thread` does (`fs/exec.c:1052-1059,1080-1085,1151-1157`). A process already ending, or one in which another thread's `execve` has begun that wait, also returns `EAGAIN`, leaving `exec_task` to the thread that set it.
8. `exec_commit` makes the image the process's and cannot fail. The thread releases its robust futexes ([futexes](futex.Readme.md)), and a thread other than the leader takes the leader's place and id (`exec_take_leader`). The POSIX timers are deleted; a caller that shares its descriptor table gets one of its own, and the close-on-exec descriptors are closed; the new effective ids become the saved ids too; caught signals go back to their default action and the alternate signal stack is cleared; the program name is set from the path. The new address space is loaded and the old one put, a parent waiting in `vfork` is let go, the frame is set at the new entry (`arch_exec_frame`), the thread pointer becomes 0, and the floating-point state is reset.

`elf.c` accepts an image of the architecture's class and machine, `ELF_CLASS` and `ELF_MACHINE` in its `cpu.h` (ELFCLASS32 `EM_386` on i686, ELFCLASS64 `EM_X86_64` on x86-64), little-endian, of type `ET_EXEC` or `ET_DYN` (`elf_valid_exec`). On x86-64, where `ELF_IA32` is 1, `elf_read_layout` and `elf_load_image_at` also take ELFCLASS32 `EM_386` programs, whose headers `elf_read_headers` widens in place to the native types, and bound them by `IA32_TASK_SIZE`; the image and the layout say which class they are of in `cls`, and `elf_load_image`, which loads the boot's first program, takes the native class alone. The loader reads the file a piece at a time through a function, `elf_read_fn`, and never has it whole in memory, so a program's size has no bound; `exec_file_read` takes a whole page of a file on a mounted volume from the file page cache when it is there and leaves it there when it is not, so a program started again reads none of its text from the disk. `elf_read_layout` reads at most `ELF_MAX_PHNUM`, 32, program headers, the span of the `PT_LOAD` segments, and the interpreter's path, absolute and at most `ELF_INTERP_MAX`, 256, bytes with its NUL. `elf_load_image_at` checks each `PT_LOAD` before it takes a page: within the user range below the stack, not wrapping, and starting at or after the page where the segment before it ends. A segment whose file offset and address agree modulo the page is mapped privately from the file, as Linux's `elf_map` maps it: `exec_open` makes the mapping (`exec_map`), a description of the file open for reading kept by the mapping as an `mmap` of the file keeps one ([memory](../mm/Readme.md)), and the loader takes no page for the segment's file bytes, which a fault reads from the file when a page is first touched and again after `madvise` drops it. The whole pages past the file bytes are anonymous memory, and the page where the file bytes end, when the segment goes on past them, is loaded at once with zeros after them, as Linux's `padzero` clears it; the loader reads the segment's last file byte, so a file shorter than its headers say is refused at the exec. A segment whose offset and address disagree, every segment of a file that is not regular, and the first program the boot loads are copied into zeroed pages whole. A page the loader fills is made read-only where its segment has no `PF_W`, and not executable where it has no `PF_X`, and a page a fault backs takes its region's protection; i686 maps every page executable ([the architectures' Readme](../arch/Readme.md)). At most `ELF_MAX_SEGS`, 8, `PT_LOAD` segments are taken, from which `elf_setup_vmas` and `elf_add_vmas` make the regions: a region of the file for a mapped segment's file pages, with the file's page at its start, and an anonymous one for the rest. The image keeps its file through a close, a rename or an unlink, and a fork's child shares the mapping. An open of the file for writing meanwhile fails with `ETXTBSY`, as on Linux ([the VFS Readme](../fs/vfs.Readme.md)). A position-independent program is moved to `ELF_ET_DYN_BASE` and a position-independent interpreter to just below `USER_MMAP_BASE` (`exec_build`, `exec_interp`), each moved again by a random offset on x86-64 unless the persona has `ADDR_NO_RANDOMIZE` (`exec_layout`); [memory](../mm/Readme.md) has the layout these constants give on each architecture, and how it is randomized.

`uimage.c` builds the initial stack in frames taken for the new image while the old one runs, as Linux's `linux_binprm` has its argument pages. The strings are copied from the top down: the program's path, the environment from its last string, and argv from its last, so argv[0] is the lowest. One string may be `UIMAGE_STRING_MAX`, 131072, bytes with its NUL, and the strings with their pointers may take a quarter of the soft `RLIMIT_STACK`, at least 128 KiB and at most 6 MiB (`uimage_budget`), as on Linux. Below the strings `uimage_write` puts the 16 bytes of `AT_RANDOM`, aligned to 16 bytes, then argc, the argv and envp pointers each ended by NULL, and the auxiliary vector of `UIMAGE_AUXV`, 24, entries (`auxv.h`), the unused ones at the end `AT_NULL`, each a word of a pointer's width, or of 4 bytes for an i386 program (`u->word`), whose `AT_PLATFORM` string lies above the `AT_RANDOM` bytes; the entry stack pointer is aligned to 16 bytes. `uimage_map` maps the frames into the new directory where the stack is. [execve(2)](../../../man/man2/execve.2) has the vector's entries and the contract.

### Exit and wait

A thread ends by `exit` (`exit_current` in `rach2/sys/syscall_proc.c`), and a process by `exit_group`, which first sends every other thread SIGKILL and records the status the process ends with (`proc_group_exit`). A signal whose default action ends the process reaches `terminate_current_process` (`rach2/kernel.c`), which writes a core file when the action asks for one (Core files, below), sends the other threads SIGKILL the same way, and ends the thread. The exit event of a thread parked for a core reports the group's status before the dump, without `WCOREFLAG`; the dumper's reports it after the dump. The final wait of a traced thread reports the group's status once its end has begun, as Linux 6.12.115's `wait_task_zombie` selects it (`kernel/exit.c:1241-1242`). An init's line under the debug shell reports that same status, and a signal gives the harness 128 plus its number. Both paths run `proc_exit_cleanup` (`exit.c`), in this order:

1. It sets `in_syscall`, so that an interrupt only asks for a switch, and the thread's own part goes: the word given with `CLONE_CHILD_CLEARTID` is cleared and a waiter on it woken, and the thread's robust futexes are released (`proc_thread_gone`, [futexes](futex.Readme.md)).
2. The thread drops its address space and runs on the kernel's page directory; the last user's drop frees the memory ([memory](../mm/Readme.md)).
3. It drops its descriptor table and its directories; the last reference closes the descriptors and lets go of the working directory and the root. Both may sleep, so they come before the zombie is published. A parent waiting in `vfork` is let go.
4. With the process's last thread, the POSIX timers and the System V semaphore adjustments go, the threads the process traces are let go, the init of a PID namespace sends the rest of its namespace SIGKILL ([namespaces](ns.Readme.md)), the children are given to a child subreaper or to init (`reparent_children`), and the leader takes the group's status when `exit_group` or a fatal signal ended the process.
5. The signals of the POSIX timers that `SIGEV_THREAD_ID` aims at the thread, pending, waiting there or not yet posted, go, as Linux flushes an ending thread's pending signals (`ptimer_thread_exit`, [io](../io/Readme.md)). The record becomes `PROC_ZOMBIE` under the same timers' lock, so no deferred expiration can join between the discard and publication of death. A thread that is not the last wakes an `execve` or a core dump that waits for it. The last sends the parent SIGCHLD and wakes its wait, unless a process other than the parent traces the leader: that tracer's wait reports the end first and then lets the parent have it ([ptrace](ptrace.Readme.md)).

The thread then leaves the processor for good. A thread that is not the leader and has no tracer is freed at the next return to user mode of any thread (`reap_threads`; `proc_dead_threads` counts them). The leader's record stays until the parent reaps the process. A pidfd keeps the id it names with the record's `serial`, a count of the records made since boot that no later thread given the id shares, as Linux's pidfd holds a struct pid; `proc_exchange_pids` moves the serial with the id. Each pidfd has its own queue, on its group's list, and a change of its id's lifetime alone wakes it, as Linux wakes one struct pid's `wait_pidfd`: a thread's exit wakes the pidfds of its id, the last thread's those of the leader's too, which are the process's (`pidfd_exit`), and the release of an id at the free of its record or the detach of a zombie thread wakes them once more, unless the thread let the id go at its exit (`pidfd_id_gone`). So a poller of a process's pidfd sees readability at the last thread's exit and hangup at the reap, and a poller of a thread's pidfd (`PIDFD_THREAD`) readability at that thread's exit and hangup once it lets its id go, at once for a thread that does not lead its process and has no tracer, as Linux's release_task frees it in exit_notify (`proc_tid_gone`). A process that ends gives up the framebuffer if it has it, and one that leads its session gives up the console and the pseudo-terminals the session controls.

`reparent_children` (`process.c`) gives each child of an ending process to the nearest ancestor of that process that is a child subreaper and has a thread that has not ended (`proc_subreaper`). A process becomes one with `prctl`'s `PR_SET_CHILD_SUBREAPER`, which sets `child_subreaper` in its thread group; a fork starts without it and an exec keeps it. The search goes up by parent and stops at the first init it meets, the ending process included, so it stays in the ending process's PID namespace. With no subreaper the child goes to the init of the ending process's PID namespace. The new parent is sent SIGCHLD for a child that is already a zombie, and its wait is woken, so that it reaps the child, and the reap adds the child's CPU time to the new parent's children's totals as any reap does. Each living child is then sent the parent-death signal `prctl` set. `/proc/PID/task/TID/children` lists the children of a process ([synthetic file systems](../fs/synthfs.Readme.md)). When init itself ends, a real `/sbin/init` panics the kernel (`panic_init_died`); under the debug shell, which runs each program it starts as init, the kernel ends and reaps every other user process (`proc_end_others`) and returns to the shell ([the kernel's Readme](../../Readme.md)).

`wait4`, `waitid` and i686's `waitpid` share `wait_find`. It looks for a child the call selects that has an event the call asks for, an end, a stop or a continue, and for a thread the caller traces; with none it sleeps on the group's `chld` queue. It looks only at what the caller has, as Linux's `do_wait` walks the caller's `children` and `ptraced` lists: two more hashes of the pid hash's size keep the process leaders by their parent and the traced threads by their tracer, each key's records in a chain in the order they took the key, which `proc_set_parent` and `proc_set_tracer` keep and `proc_children` and `proc_tracees` give; an exec that makes a thread its process's leader gives it the old leader's place (`proc_exchange_pids`), as Linux's `de_thread` does. The wait looks at the children first and then at the traced threads that are not its children. Each process's group also lists its records (`threads` in `tgroup.h`), which the sums of its CPU time, page faults and switches walk, as Linux's `getrusage` walks the process's threads; a wait sums its child's usage only for a caller that gave `wait4` or `waitid` a buffer for it, as Linux's `wait_task_stopped` fills it only then. So a tracer's stop costs the same however many threads the machine runs. The event is reserved for the caller while the report is copied out (`wait_hold`): a zombie to reap is marked `PROC_UNUSED`, so that no other thread's wait takes it, and a copy that fails because another thread unmapped the buffer meanwhile returns `EFAULT` and puts the event back (`wait_done`). The reap adds the child's CPU time and page faults, with those of the children it reaped, to the caller's group, and frees the child's address space, kernel stack and record (`proc_release`).

The three calls run without the big lock, as Linux 6.12's `do_wait` runs under `tasklist_lock` and the child's `siglock`. The look walks the indexes under the list lock as a reader, and reads and reserves each child's events under the signal state's lock, `sig_lock` (`wait_scan`, `signal_state_lock`). The list lock is one spinlock, so the looks of two threads' waits do not overlap. A tracee publishes its ptrace stop under `sig_lock` (`ptrace_stop`), so a look sees a stop's status and whether it was reported together; a stop or a continue of a process is reserved by a compare-and-exchange that finds the report the look read (`jc_status`). A reserved stop or continue holds a reference to its record (`proc_ref_get`), so that a report given back after a failed copy finds the record it reserved. The child's usage, when asked for, is summed under the list lock after `sig_lock` is let go. An end is taken under the big lock: the reap of a zombie, the free of a traced thread that ended, and a tracer's report of a process's end, whose release sleeps and frees what the big lock guards. The ending thread holds the big lock from the zombie's publication in `ptimer_thread_exit` through its notice to the parent, the SIGCHLD and the wake of the `chld` queue, until it has left the processor, so a wait that holds the lock finds the end complete. A look without the lock that meets such an end leaves the queue, takes the lock and looks again, so that the reports keep the walk's order; that call keeps the lock until it returns, and `wait_done` lets it go after the report is copied out. A wait in a PID or user namespace below the first takes the big lock around the translation of ids (`ids_lock`), and waitid around the look-up of a pidfd. The caller sleeps on its group's `chld` queue, which a child's end, a stop and a continue wake, as Linux's `wait_chldexit`; it joins the queue and is marked blocked before it looks, so a wake after the look makes it ready.

### Scheduling

`sched.c` schedules two classes on each processor, as Linux 6.12 does: real-time threads, those of `SCHED_FIFO` and `SCHED_RR` and those a priority-inheriting futex raises, and ordinary threads, those of `SCHED_OTHER`, `SCHED_BATCH` and `SCHED_IDLE`, which the fair class schedules (`fair.c`, `fair_group.c`, `pelt.c`, `balance.c` and `autogroup.c`, which share `fair.h`). Selection (`sched_select`) takes the real-time thread of the highest effective priority that may run on the processor, from any processor's list (`sched_find_rt`); ahead of it, the thread the fair class picks while the fair server gives the ordinary threads their turn (`fair_server_takes`); and with no real-time thread, that ordinary one (`fair_pick`). With nothing to run and the outgoing thread leaving, the processor first pulls an ordinary thread from a busier one (`fair_balance_newidle`), as Linux's `pick_next_task_fair` balances a processor about to go idle (kernel/sched/fair.c:8981-9000); with nothing there either, it goes on with its current thread if that one can still run, or switches to its idle task. A record may run on a processor its affinity has, a 64-bit mask that `sched_setaffinity` sets, and only once no other processor is running it. One spinlock, `sched_lock`, taken after the big lock, covers both classes' queues, the fair class's state and the fair server, and every hook of `fair.h` runs under it with interrupts off. Blocked records add no selection work. `/proc/stat` reports selection attempts as `scheduler_picks` and the real-time records selection examined as `scheduler_steps`, modulo 2^32.

Each processor has a doubly linked list of its ready real-time threads, with a count, and each queued record's `cpu` names its list; a wake appends a record once, and selection and deletion unlink it in constant work. The current and idle tasks are off the lists. FIFO keeps the processor against equal-priority peers until it yields or blocks. RR's slice is Linux's 100 ms (`SCHED_RR_TIMESLICE_MS`, include/linux/sched/rt.h:84), counted by the periodic tick alone, in its 4 ms ticks (`sched_rr_tick`), as Linux's `task_tick_rt` counts it in jiffies (kernel/sched/rt.c:2586-2604). A thread preempted by a higher priority keeps the rest of its slice (`rr_used`) and its place at the head of its priority's list, and goes behind its peers only when its slice runs out with a peer queued, or when it yields (`sched_yielded`, `sched_keeps`), as Linux's `requeue_task_rt` moves it only then (rt.c:1516-1530). `sched_set_rr_timeslice_ms` sets the slice as Linux's `sched_rr_handler` does (rt.c:2966-2987): a value of 0 or less restores 100 ms, and any other is counted in ticks rounded up. The tick ends a real-time thread's turn when a queued real-time thread that selection on its processor could take, from any processor's list, outranks it, so an equal RR peer waits for the slice (`sched_rt_outranks`). A wake, a priority change and an affinity move that put a thread on a list where it outranks the running thread ask that thread to switch (`need_resched`) and interrupt its processor, as Linux's `wakeup_preempt`, `prio_changed_rt`, `switched_to_rt` and `move_queued_task` call `resched_curr` on the list's current task (core.c:2151-2156, 2462-2463; rt.c:1657-1658, 2486-2492, 2526-2533); the interrupt switches it in user mode, and a call switches at its exit. A running thread whose priority falls below a queued real-time thread's asks itself (rt.c:2519-2520). A woken real-time thread whose processor runs a real-time thread of its rank or above, or one that may run nowhere else, goes instead to the processor it may use whose highest real-time priority, of its running thread and the ready threads on its list, is lowest, its own first, then the waker's, when it outranks every thread there (`sched_rt_place`), as `select_task_rq_rt` and `find_lowest_rq` place it by each queue's `highest_prio.curr`, which counts the running task (rt.c:1108-1144, 1577-1597, 1807-1880). PI futex owners inherit the priorities of their blocked waiters, through chains of owners, as [futexes](futex.Readme.md) describes. A change of effective class, a donation's among them, moves the thread between the classes' queues with its accounting, whether it runs, waits or is delayed (`sched_priority_changed`), as Linux's `__sched_setscheduler` and `rt_mutex_setprio` dequeue it, change its class and enqueue it (kernel/sched/syscalls.c:695-760, core.c:7140-7260): an ordinary thread that becomes real-time leaves its fair queue keeping its lag, and one that becomes ordinary comes back with it and asks to be selected. A real-time thread's run is charged into its entity's `sum_exec_runtime` at the tick, at the switch away and at a change of class (`sched_charge_rt`), as Linux's `update_curr_rt` charges it (rt.c:989-1000), and into the processor's real-time average (`pelt_update_rt`). `sched_set_rt_bandwidth` takes Linux's real-time period and runtime with its checks, refusing with `EBUSY` a runtime whose share of the processors is below the fair servers' together, and throttles nothing, as on Debian's kernel, which has no `CONFIG_RT_GROUP_SCHED`.

The fair server keeps the ordinary threads from starving under a real-time load, as Linux 6.12's deferred deadline server does (kernel/sched/deadline.c:1629-1860), with a budget of 50 ms in every 1000 ms on each processor. It starts when an ordinary thread becomes runnable on its processor and stops when none is (`fair_server_track`). Every ordinary thread's run there spends the budget (`fair_server_spend`). While the server waits, a budget that the ordinary threads spent on their own starts a new period, so the server runs only for threads that starve: from its zero laxity, the latest moment at which the rest of its budget still fits in the period, until the budget is spent, and then it is throttled to the period's end and starts again (`fair_server_advance`). While it runs, selection takes the fair class's pick ahead of a real-time thread, except one that runs on a priority a futex lends it, which no budget holds back. While both classes compete, the slice event is armed at the server's next change (`fair_server_event`). `sched_set_fair_server` takes a runtime and a period with Linux's checks, among them that the servers' share of the processors stay within the real-time runtime's (debug.c:344-402, deadline.c:1895-1915), and a runtime of 0 turns the server off.

Each ordinary thread has an entity in its record (`se`, `struct sched_entity`), which is on a fair queue (`struct cfs_rq`) while the thread is runnable, the running thread included: its processor's root queue in `fair_rqs`, or its group's queue on that processor (below). A queue keeps its entities in Linux's augmented red-black tree (`../lib/rbtree.c`), ordered by virtual deadline, each node keeping its subtree's least virtual runtime and least slice. A thread's virtual runtime grows by the time it is charged times 1024 over its weight (`calc_delta_fair`). V, the queue's average virtual runtime weighted by its entities' weights (`fair_avg_vruntime`), is kept as a sum relative to a moving zero, within the bounds `fair.h` states for 64-bit products. An entity is eligible, owed service, while its virtual runtime is at most V, and `pick_eevdf` takes the eligible entity of the earliest virtual deadline in O(log n) steps, passing over each subtree with no eligible entity (kernel/sched/fair.c:926). A deadline is the virtual runtime plus a slice in virtual time. The base slice is Linux's 0.70 ms times 1 + log2 of the processors online, eight at most, 2.1 ms with four (`sysctl_sched_base_slice`, fair.c:76, 212-220), computed again as each processor starts (`sched_cache_join`); a slice that `sched_setattr` sets is kept between 0.1 and 100 ms (`fair_set_slice`). `update_curr` charges the current entity, and the group entities above it, at each switch, tick, wake, slice event and change of weight or class; an entity that reaches its deadline takes a new one a slice on and, when another competes, asks its processor to select again (fair.c:1022-1045, 1230-1273). The class has Linux's scheduler features as Debian's kernel sets them (`sched_features`). With RUN_TO_PARITY the current entity keeps the processor while it is eligible and runs on the deadline it was picked with. With PREEMPT_SHORT an eligible woken entity of a shorter slice ends that protection, and the current entity's loss of eligibility once unprotected asks for selection. With PICK_BUDDY the entity a group member nominated as it slept, its group's, is picked while it is eligible.

A thread's lag, V less its virtual runtime, clamped to the virtual time of twice its slice or a tick, whichever is longer, is saved when it leaves its queue (`update_entity_lag`, fair.c:739), and its next enqueue places it at V less that lag, scaled up so that the lag survives the move of V the placement itself makes (`place_entity`, PLACE_LAG, fair.c:5291). So a thread that ran less than its share comes back early and one that ran more comes back late. A new thread starts at V with half a slice (PLACE_DEADLINE_INITIAL), on the processor chosen for it; a dequeue that is not a sleep, a move between queues, classes or groups, keeps the deadline relative to the virtual runtime and restores it (PLACE_REL_DEADLINE). With DELAY_DEQUEUE a thread that sleeps while it is not eligible stays on its queue, marked delayed (`sched_delayed`), counted in the queue's load but not as runnable, until its negative lag is repaid: it never runs; a pick that takes it finishes its dequeue and picks again (`fair_hooks.blocked`); and a wake requeues it in place (`requeue_delayed_entity`, fair.c:6981), where a positive lag is dropped (DELAY_ZERO). A stop, an exit, a move off a processor its affinity no longer has, a suspend's hold and a change of class finish the dequeue first, since a delay counts on a later wake that those never give. A thread woken before its switch away, while still current, runs on without leaving its queue, as Linux's `ttwu_runnable` (kernel/sched/core.c:3756-3780).

A thread's weight is Linux's for its nice value, 1024 at nice 0 and about 1.25 times less for each step up (`sched_prio_to_weight`, kernel/sched/core.c:10073), and 3 under `SCHED_IDLE`. A change of nice value or policy reweights the thread, queued or not, keeping its lag and its deadline's distance in real time (`fair_reweight`, Linux's `reweight_entity`, fair.c:3898), and a running thread that lost weight selects again. With group scheduling a thread's entity is on its group's queue on its processor, and the group's entity there on the root queue, as Linux's hierarchy is with autogroup: a pick goes down every level, a charge, a tick and the slice event go up every level, and a wake preempts by the pick at the level the two threads share (`find_matching_se`). A group's weight on one processor is its share split by its load there (`calc_group_shares`, fair.c:4030, in `fair_group.c`), computed again at each enqueue, dequeue and tick of the group's entity.

Autogroup (`autogroup.c`) gives each session a group, as Debian's kernel builds `CONFIG_SCHED_AUTOGROUP`. `setsid` makes one and moves into it every thread of the caller's thread group that has not begun to end (`autogroup_setsid`); a new thread group shares its parent's group, and a new thread joins its thread group's (`autogroup_fork`); a thread that ends leaves for the root group, and a thread group's last thread lets its group go (`autogroup_exit`). A group and its queues are freed once no thread group names it and no thread is in it. A thread group whose session no `setsid` made, the kernel's threads among them, is in the root group. A group's share is the weight of its nice value, 1024 at 0, which `autogroup_nice` sets with Linux's checks. `autogroup_set_enabled` moves every thread at once to its group's queues or to the root queues, each thread keeping its group while the groups are off, where Linux moves a thread only at its next change of group. A thread moves between queues under `sched_lock`, dequeued, given its new queue and enqueued with its lag (`tg_move_task`).

The fair class charges by each processor's task clock (`sched_clock_task`): the monotonic clock less the time spent in interrupt handlers and the steal time a hypervisor reports, as Linux's `update_rq_clock_task` (kernel/sched/core.c:746-801). The interrupts' time is the processor's `irq_cycles`, which the interrupt router adds at the outermost interrupt's exit, converted by the cycle counter's measured rate. Each is taken out at most to the time that passed; the interrupts' rest is kept for the next move and the steal time's dropped, and what is taken out goes to the interrupt average (`pelt_update_irq`). The slice event, Linux's hrtick, is armed on the local event timer at the monotonic moment the current ordinary thread, or a group entity above it, reaches its deadline while another entity competes at that level (`fair_next_event_ns`), converted back through the weight; it is armed again at each switch's tail, each tick and each pass of the event timer (`sched_slice_rearm`), and at that moment the charge gives the thread a new deadline and asks for selection. The periodic tick charges and checks the same way (`fair_tick`, Linux's `task_tick_fair`). Only the tick's handler calls `sched_tick`, so an RR slice, the fair server's budget and the balance's intervals count the tick alone, as Linux's `sched_tick` runs only from the tick (core.c:5614-5660); every other interrupt ends with `sched_irq_exit`, which only takes a switch that a wake or the tick asked for.

A wake (`sched_ready_locked`) places an ordinary thread where Linux's `select_task_rq_fair` places it (`fair_select_cpu`, fair.c:8687), and its entity moves there with its lag and load (`fair_migrate`, Linux's `migrate_task_rq_fair`, fair.c:8761). The target is the waker's processor or the thread's last one, chosen by `wake_affine`'s tests of idleness and load (WA_IDLE, WA_WEIGHT and WA_BIAS, fair.c:7517), or the last one when the waker's wakes go to many threads in turn (`wake_wide`). From the target, `select_idle_sibling` (fair.c:7934) takes the target when it is idle, else the last one, the thread's recently used one, or an idle processor sharing their last-level cache, an idle SMT core's first, in a scan whose length the cache domain's utilization sets (SIS_UTIL). A new thread goes to the idlest processor of the widest domain that balances forks (`find_dst_cpu`), with half a slice and no lag or load to move. A processor counts as idle only when it runs its idle task, its queues are empty and no wake has asked it to select (`sched_cpu_free`), as Linux's `idle_cpu` requires (kernel/sched/syscalls.c:202-218), so the two wakes one interrupt makes go to two processors. A real-time thread stays where it ran, unless its affinity has left that processor or `sched_rt_place` moves it. Then the wake asks the processor to select (`sched_wake_preempt`): one that is idle, one whose running thread the woken one outranks by class or priority, or, between two ordinary threads, one where `pick_eevdf` at the queue the two share would take the woken one (`fair_wake_preempt`, Linux's `check_preempt_wakeup_fair`, fair.c:8862-8951), with Linux's rules that an entity of the idle policy gives way to any other and takes from none, and that a `SCHED_BATCH` or `SCHED_IDLE` thread preempts nothing. A start and an affinity move ask the same, as Linux's `move_queued_task` calls `wakeup_preempt` (core.c:2449-2465). A kernel thread so asked switches at its next sleep or service point and is sent no interrupt, which would switch nothing. A thread moved off a processor its affinity no longer has goes to the first idle processor it may use with nothing on its way, else to the first it may use (`sched_choose`). A wake asks an idle processor to look at once (`smp_kick`), only once before that processor's next selection, as its idle task's `need_resched` marks, as Linux's `resched_curr` asks a task whose flag is already set nothing: one polling before its halt, or whose idle task is awake after an interrupt ended its halt and has not yet switched or halted again (`sched_idle_awake`), as Linux's idle task keeps its polling bit set outside the halt, sees its poll word change, and any other gets an interprocessor interrupt; a waker that holds a spinlock of its own asks after that lock (`sched_kick_cpus`), the processors of a wake of many in one message for each x2APIC cluster (`smp_kick_many`). A record still current on its processor, between its marking as blocked and its switch away, is made ready with no kick where that processor has an idle task, since its own selection then finds it ready and it runs on; only a thread that halts in place as current, with no idle task or the scheduler off, is kicked.

The balance (`balance.c`) is Linux's for an x86 machine without NUMA. Each processor's domains, its SMT siblings, the processors sharing its last-level cache and the package, are built from the masks each processor records by `cpuid` as it starts (`cpuinfo_llc_shared`, `cpuinfo_siblings`, `balance_cpu_topology`), and built again whenever one starts, a level that adds nothing to the one below dropped; a processor that describes no cache shares its package's. Load is PELT's (`pelt.c`): geometric sums per entity, queue and group over periods of 1,048,576 ns of the task clock that halve in 32 periods, with the load of blocked threads decaying, and per processor the real-time and interrupt averages, whose share is taken from the capacity the balance gives the fair class (`balance_capacity`). A processor whose queues empty balances first, while its expected idle time pays for the balance. The tick balances each domain whose interval has passed (`fair_balance_tick`, Linux's `sched_balance_domains`, fair.c:12261), moving queued threads from the busiest group and processor by load, at most 32 a pass; a thread that ran within the last 0.5 ms (`sysctl_sched_migration_cost`) stays unless balances keep failing. After repeated failures an active balance has the busiest processor push its running thread away at its next selection (`sched_balance_push`, Linux's `active_load_balance_cpu_stop`, fair.c:12110), which may move a cache-hot thread. A busy processor's tick asks an idle one whose tick has stopped to balance for every such processor (`fair_nohz_kick`, Linux's `nohz_balancer_kick`, fair.c:12426), which it does on its way into its idle wait (`sched_idle_balance`, `fair_nohz_balance`), where it also decays the blocked load a newly idle balance left it. A move is a dequeue, `fair_migrate` and an enqueue under `sched_lock` (`sched_balance_move`), with a request that the target select if the thread should run there now.

`sched_yield` marks the caller (`sched_yielded`) and selects: an ordinary yielder that is eligible has its virtual runtime moved to its deadline and takes a new deadline (`fair_yield`, Linux's `yield_task_fair`, fair.c:9100), and a real-time one goes behind its peers. A yield whose processor has no other thread waiting, with no real-time thread queued on any list and no switch asked of the caller, returns without taking `sched_lock` and without a selection, which it does not count (`sched_yield_alone`), as Linux's yield takes only its own processor's queue's lock and returns at once from a queue that holds the yielder alone, whose schedule then picks it again (kernel/sched/syscalls.c:1410-1425, fair.c:9109-9110): Wine's spin calls it hundreds of thousands of times a second, and each take of the one lock of every queue moved that lock's line between the spinning processor and those whose threads block and wake. Each record keeps Linux's `sched_info`, which `/proc/PID/schedstat` gives: a thread made ready, after the scheduler is on, notes the moment on the monotonic clock, in 64-bit nanoseconds, unless it already waits, so a move to another processor's queue keeps the wait, and when it is selected to run, or runs on as the current task, the wait is added to `run_delay` in nanoseconds; each switch onto a processor counts in `pcount`. KVM's steal time adds the growth of a vCPU thread's `run_delay` to its guest's record ([kvm](../kvm/Readme.md)). `sched_rr_get_interval` gives an RR thread its slice, a FIFO thread 0, and an ordinary thread its slice in whole ticks, rounded down, while its processor's fair queue has load, else 0, as Linux's `get_rr_interval_fair` (fair.c:13716-13729), so a slice of 2.1 ms reads 0.

`sched_set_affinity` completes a move before returning, as Linux's `affine_move_task` does. A remote thread running outside its new set gets `need_resched` and an interprocessor interrupt; the caller sleeps on a completion kept on its own stack until the target switches away. A later request that permits the target's current processor also completes the wait. Completion removes the target pointer before waking the caller, so a target that exits and is reaped cannot leave a stale pointer in the wait. An interrupt in user mode takes the switch at once; a thread in a system call takes it at its next scheduling point.

`rseq.c` keeps the registered area of each thread as [rseq(2)](../../../man/man2/rseq.2) describes. A switch away and a move between processor queues mark the area for the next return to user mode. `isr_leave`, after signal delivery, aborts an interrupted critical section and writes the running processor into `cpu_id_start`, `cpu_id` and `mm_cid`, with node 0. Registration and a forked child's first return also request the update. The update repeats if a user-memory fault sleeps and the thread moves while its area is being written.

Before the switch `schedule` saves the floating-point registers into the outgoing record's area and loads the incoming record's, and makes the incoming record the processor's `current`. `switch_context` then changes the stack, the page directory and the thread pointer ([the architectures' Readme](../arch/Readme.md)). Interrupts are off from the selection to the switch. The big lock does not cross it: the outgoing thread's depth is saved in its record (`bkl_depth`) and the lock let go (`bkl_drop`), and the incoming thread's tail (`schedule_tail`) takes it back at that thread's own depth, none for the idle task or a thread that switched away outside the lock, counted as a switch's take (`bkl_take_as`), as Linux 2.6 gave the big kernel lock up around a switch (`release_kernel_lock`). So a processor that goes idle, or runs a thread that holds nothing, keeps the lock from no one. A thread's `on_cpu` says that a processor may still run on its stack, as Linux's does (kernel/sched/core.c:4972-4990): it is set before the switch to the thread, and the tail of the next switch clears it once the switch has saved the thread's registers. A thread woken while it still switches away on another processor may be selected meanwhile; the switch to it waits for its `on_cpu` to clear first (`sched_wait_off_cpu`), outside the run queues' lock, and a reaper waits for it too before it frees a dead thread's stack.

Each busy processor's scheduler tick runs at 250 Hz on either architecture ([the PC platform](../arch/x86/Readme.md)); coarse clocks and CPU accounting use 4 ms units (`TICK_HZ` in `rach2/sys/timer.h`), the tick's handler (`timer_handler` in `rach2/kernel.c`) ends with `sched_tick`, which asks the current thread to switch (`need_resched`) once its slice has run out, a real-time thread outranks it or the fair server's turn has come, and every interrupt, the tick's and each device's, ends with `sched_irq_exit`, which calls `sched_preempt` for a thread so asked. A thread interrupted in user mode, process 0 and the debug shell's test threads are switched at once, except process 0 or a test thread inside klog (`klog_inside` in `rach2/sys/klog.h`), in a record, a console write or a console byte, as process 0 is while the debug shell prints a line: klog's count of its users would stay up while the big lock passed on, so the request waits in the record and the thread gives way at a later tick, once it has left klog, as Linux writes a console record with interrupts off and gives way only between records (kernel/printk/printk.c:3074-3089). A thread inside a system call is not, since the call's state may be half changed: the request is kept in the record (`need_resched`), and the dispatcher takes it at the call's exit (`sched_take_preempt`), so a process that is always inside a call still gives way once per call. A fault from user mode, which runs with interrupts on ([memory](../mm/Readme.md)), keeps the request the same way (`in_fault`) and takes it at its end. A kernel thread is not switched either (`no_tick_switch`, which `setup_process_stack` sets and the shell's `test_process` clears, since its tests are of the tick's switch): its work changes state that only the big lock guards, and the switch lets the lock go, so a request waits in the record for the thread's next sleep or service point. This is Linux without `CONFIG_PREEMPTION`, where the tick only sets `TIF_NEED_RESCHED` (kernel/sched/core.c:1094), a kernel thread is switched where it calls `schedule` or `cond_resched` (:7287), and an interrupt's return to kernel mode switches nothing (kernel/entry/common.c:356). The workers kacpid, kwlan, kinputd, kpsmoused, kdrm, kdrmcon, ki915, virtio_gpu, kvkms, vgpu-shm, vgpu-shm-irq, khda and kconsoled reach a service point after each work or pass, kconsoled's a batch of at most 64 bytes of echo, as Linux's worker calls `cond_resched` between works (kernel/workqueue.c:3290-3299), kvkms also after each row of a frame ([DRM](../drm/Readme.md)), and vgpu-shm also after each look for the device's answer that fails (`vshm_await`), as vhost's worker does between works (drivers/vhost/vhost.c:440). A call that loops over a large buffer takes the switch between two pieces of its loop through `sched_service_point`. A walk that frees a large structure no other thread reaches gives way the same way every bounded batch through `sched_give_way`, which calls the service point only with interrupts on outside an interrupt handler, as Linux's `__cond_resched` tests `irqs_disabled` (kernel/sched/core.c:7287-7292), since every spinlock is taken with interrupts off: an address space's last put after each leaf table ([memory](../mm/Readme.md)), a file in memory's last free after each leaf of 1024 pages, and the i915's clear of the global GTT after each 512 entries under the GEM lock ([i915](../drm/i915/Readme.md)). `schedule` clears the outgoing thread's request under the run queues' lock once it has selected, whether or not it switches, as `__schedule` does (kernel/sched/core.c:6707), so a request made after the selection is kept for the next point. Both `sched_service_point` and `schedule` count for the soft-lockup detector as the schedule Linux's stopper thread waits for (`watchdog_sched`). A processor's idle task is not switched from the interrupt either; its loop selects as soon as the handler returns. A busy processor's tick asks a processor whose tick has stopped to balance for the idle ones (`fair_nohz_kick`, above). Its tick stays stopped across interrupts which return to idle, and restarts only when a selection leaves the idle task. Its adaptive poll takes interrupts with them enabled and reads no APIC request registers. A running tick is retained through the short poll, as Linux's halt-poll governor requests. A halt shorter than a scheduler period without a scheduler tick predicts another short halt and retains the tick there too. A retained tick clears that prediction, including during a poll, so a quiet CPU stops it at the next idle entry; an already stopped tick skips the poll and commits its deferred events before the halt. A wake marks the idle task for selection, so work ready before or during preparation skips the halt. Only the idle loop consumes that request: service points cannot switch inside post-halt idle work. A device or interprocessor interrupt marks the poll kicked, so that it returns to the selection and service work before halting.

`waketime.c` accounts each blocked user thread that a timed wait or a timerfd expiration wakes, from its deadline tick to `isr_leave` just before its return to user mode. The thread's `TimedWakeCount`, `TimedWakeLast`, `TimedWakeWorst` and `TimedWakeSum` in `/proc/PID/status`, or its task's `status`, report the completed count, last wake, longest wake and sums. The eight microsecond columns are expiry to the servicing timer interrupt, that interrupt's wait for the big lock after expiry, the remaining timer work, time queued, time running toward user mode, time blocked again, and two subsets: the queued CPU's waits for the big lock and the returning thread's waits for it. The first six sum to the accounted delay; the last two must not be added again. Queuing after a second preemption and moving to another CPU preserve the accounting. The first deadline stays until the return, even if the thread blocks again. A record is begun only under `sched_lock`, under which every wake moves its stage: timerfd's expiry walks its readers under the queue's lock and takes `sched_lock` for each, as Linux's `try_to_wake_up` tests a task's state under its `pi_lock` (kernel/sched/core.c:4191-4194). Other sleeping locks appear in the blocked-again column. Spinning while running remains in the return column.

The timestamps are the monotonic clock's in microseconds (`rtc_monotonic`), one continuous clock whether the vDSO's TSC clock or the tick's reads it underneath, held to its last reading, so that a stage that starts on one and ends on the other, or spans a slew, is measured on one scale. They include time a hypervisor deschedules a virtual CPU. Per-stage clocks and the completed count wrap at 2^32; sums have 64 bits. A stage must be shorter than half the microsecond clock's period, about 35 minutes. The interrupt columns describe the interrupt that made the timer pass, which takes no big lock before it, so the column before the lock is that interrupt's entry. The deadline is rounded to the kernel's 4 ms tick; time before the wait is armed and the final register restore and return instruction are outside this record. The probe measures those too in user space. Kernel threads have no user return and start no record. A fork starts with empty records.

An idle wait, a halt with interrupts on that expects to resume, goes through `idle_wait_irq_off` or `idle_wait_irq_on`. Each marks the processor idle for the tick to see, lets the big lock go for the halt and takes it again after. The first enters with interrupts off and returns with them off. An `sti` takes effect only after the instruction that follows it, so an interrupt that became pending while the caller tested its condition arrives once the `hlt` has begun, and ends it. An interrupt that ended the halt returns with interrupts off (`_irq_router`), so that the wait goes on before the next tick, however long the big lock takes. Where KVM hints that the guest's processors are its own (KVM_HINTS_REALTIME) or the boot line has `cpuidle_haltpoll.force` (`arch_idle_poll`), as Linux loads cpuidle-haltpoll (drivers/cpuidle/cpuidle-haltpoll.c:96-111), the wait first polls with interrupts off for up to its processor's poll length (`idle_halt`), answering the other processors' requests in its loop (`smp_service`), so that their interrupts, pending meanwhile, are taken once at its end and not one by one inside it, each with a guest's exits. Every 10 us it reads the local APIC's request register, and the 8259's while the 8259 delivers the lines (`arch_irq_waiting`), and a device's or a timer's interrupt waiting there ends the poll in the halt, which takes it at once, as Linux's poll_idle takes it with interrupts on. A wait that a wake ended, in its poll or before it while the idle task was awake (`sched_idle_awake`), and every other return without a halt, a loopback drain's or the idle task's when ready work cancels the halt before or after its marker or once the tick has stopped, lets interrupts in for one instruction before it returns (`idle_kicked_window`), so that one pending then is taken before the caller checks its condition again, selects or waits for the big lock, as Linux's `call_cpuidle` enables interrupts when a reschedule request cancels the idle entry (kernel/sched/idle.c:144-148). The windows of a wake, and of ready work found after the marker is set or while the tick stops, open while the processor is still marked idle; those of a loopback drain and of ready work found before the marker open before it is set. Each returns with interrupts off. A wake from another processor marks the poll word by compare-and-exchange and sends no interrupt, so that a renderer's threads, which hand work to each other thousands of times a second, are woken without an interrupt sent under the big lock and a halt's exit, which a hypervisor makes dear. The length adapts as Linux's cpuidle-haltpoll does: a wait that the halt ended within 200 us doubles it, to at least 50 us, and a longer one halves it, to 0 below 50 us, so that a processor the tick alone wakes soon halts at once again. Elsewhere the wait halts at once: on a machine of its own an interrupt and a halt cost a few microseconds, and under a host that shares its processors, as QEMU's KVM does without `kvm-hint-dedicated`, each look at the request register is an exit, and a tar through a pipe made 2.5 times the exits with the poll. `tests/run style` refuses a `sti; hlt`, or a call of the architecture's halt, anywhere else ([style.sh](../../../tests/cases/host/style.sh)).

The tick charges the thread it interrupted with user time when the interrupted code was ring 3's and with system time otherwise, and a tick that found the processor in an idle wait to no one (`sched_account_tick`). A processor counts the ticks of its own clock, the monotonic time since its last count in whole ticks, so one it missed while its interrupts were off counts with its next, and the boot processor's late tick moves no other processor's count, as Linux charges each processor's tick to that processor (`account_process_tick`, kernel/sched/cputime.c:474-500). A system call's handler runs with interrupts on, and its entry runs with them off until the dispatcher turns them on. Its exit turns them off after the handler and keeps them off through the loopback drain and a preemption; the signal delivery and rseq update of the return to user mode (`deliver_signals` and `rseq_return`, in `isr_leave_work`) run with them on, so a tick that comes then is taken at once, in kernel mode; and they are off again from that work's end to the return to user mode. A held spinlock, the scheduler's switch and an interrupt's handler run with them off too. A tick that comes while interrupts are off is held and taken only as they come back on. By default a held tick is charged where it is taken, and no entry or return reads the cycle counter, as the Debian kernel measured for the one-byte calls charges on the tick (its `VIRT_CPU_ACCOUNTING_GEN` serves only `nohz_full` processors). With `rach2.cycleaccount` on the command line (`sched_cycle_account`), one held to the return to user mode, or to the start of an idle wait's halt, which would be charged to the program or to idle although it came in the kernel, is corrected instead: the ticks that would have come before that point, by their time (`timer_tick_due`) and the average delay of the tick's interrupt (`tick_late_ns`), which a hypervisor makes microseconds long, against the cycle counts `user_cycles` and `idle_cycles`, are charged where a tick that came on time would have been taken: as system time, or as idle when the stretch that held them began at the end of an earlier idle wait, where Linux's idle task loops (`update_process_times`, kernel/time/timer.c:2519). Under KVM a processor gives KVM its steal-time record as it starts (`kvmsteal.c`), and a tick's worth of steal time not yet counted makes a tick stolen, charged to no one and counted in `/proc/stat`'s steal column, as Linux takes the steal time out of the tick it charges (kernel/sched/cputime.c:253-269, 486-492). The same tick runs the process's `ITIMER_VIRTUAL` and `ITIMER_PROF` timers, under the thread group's `cpu_lock`, which setitimer and getitimer take too, as Linux's `check_cpu_itimer` runs under the signal handler's lock (kernel/time/posix-cpu-timers.c:972-994), and the POSIX timers of processor time, under timerfd's `timer_lock`. setitimer starts either of the first two a tick longer than asked and keeps its interval when it disarms it, as Linux's set_cpu_itimer adds TICK_NSEC to a value that is not 0 and stores the interval whatever the value (kernel/time/itimer.c:175-188), so that at 250 Hz a 10 ms timer expires at the fourth tick charged. The tick runs without the big lock, under which signals are posted, so a timer that runs out leaves its signal for a holder: SIGVTALRM, SIGPROF and the real-time timer's SIGALRM wait on the list of the tick's signals (`proc_tick_signal`, `process.c`), a POSIX timer on timerfd's list (`ptimer_fire_later`). The tick's locked part posts what waits on both (`proc_tick_signals_post`, `ptimer_post_due`), and a thread's own return to user mode posts its own (`proc_tick_signals_own`, from `isr_leave`), as Linux hands a CPU timer's expiry to the task's return (kernel/time/posix-cpu-timers.c:1274). A real-time timer stops once its SIGALRM is posted (`alarm_stop`), keeping its interval and its nanosecond expiry (`alarm_last`), as Linux's `it_real_fn` leaves its timer stopped (kernel/time/itimer.c:156-166); a periodic one runs again when a SIGALRM is taken from the process's pending set (`proc_alarm_taken`, from `sig_dequeue`), at the first expiry of its interval's grid after then, as Linux's `dequeue_signal` restarts it with `hrtimer_forward` from the old expiry (kernel/signal.c:654-662, kernel/time/hrtimer.c:1046-1078). The timer pass marks a due timer once (`alarm_due`), so no setting sends two, and while a SIGALRM is pending no tick sends another. A setitimer or alarm made while a marked SIGALRM waits posts it as it takes the new setting (`proc_alarm_set`), since Linux sends SIGALRM at expiry (`it_real_fn`, kernel/time/itimer.c:156-166) and its setitimer only cancels the timer; once the pass marks the SIGALRM, and while the timer is stopped, getitimer and setitimer's old value report no time left with the interval (`proc_alarm_read_ns`); an active expiry not yet collected reports one microsecond, as Linux's `itimer_get_remtime` reports 0 for the inactive timer (kernel/time/itimer.c:29-45). An exec that makes another thread the leader moves the timer to it as it stands (`proc_alarm_take`). Every five seconds and a tick, 1251 ticks by the tick count, the boot processor folds the threads that are running or ready into the three load averages, as Linux's `calc_load` does (`sched_load_tick`); a sample made late keeps the period's phase, and the samples a longer gap passed over are folded at once with the decay to their power, as Linux's `calc_load_n` folds them. `times`, `getrusage`, `wait4`, `/proc/stat` and `/proc/PID/stat` report these counts. A thread's counts are 64 bits, which the i686 adds to in two halves, so a reader of another thread's, or of the whole process's, reads them under `timer_lock`, which the tick adds under (`thread_cpu_time`, `tgroup_cpu_time`), as a 32-bit Linux reads a thread's run time under its run queue's lock (`task_sched_runtime`) and a process's under the signal handler's `stats_lock` (`thread_group_cputime`), and sees each count whole; the end of a thread moves its counts into the thread group's under the same lock (`proc_thread_fold`), so that a reader counts them once.

Each record keeps a nice value, from -20 to 19, the slice `sched_setattr` asked for (`sched_slice`, 0 for Linux's default), and an I/O priority, which a fork passes on and an exec keeps. The fair class weighs a thread by its nice value and gives it that slice (above); nothing reads the I/O priority, which Linux's block layer alone reads. The scheduling calls keep `SCHED_OTHER`, `SCHED_BATCH` and `SCHED_IDLE` at priority 0, and `SCHED_FIFO` and `SCHED_RR` at priorities 1 to 99. `sched_setattr` changes the supported policies and `sched_getattr` reads their parameters, in Linux's order and with its errors (`sched_apply` in `rach2/sys/syscall_proc.c`). Only `SCHED_OTHER` and `SCHED_BATCH` change the nice value and slice; `SCHED_IDLE` keeps them. A caller without privilege is held to the target's `RLIMIT_NICE` and `RLIMIT_RTPRIO`, as Linux holds one without `CAP_SYS_NICE` (`sched_user_check`); both are 0 by default, which allows no lower nice value and no real-time policy, and such a caller may never set `SCHED_DEADLINE`. The scheduler has no deadline class. After the argument, privilege and affinity checks, every request for `SCHED_DEADLINE` is refused with `EBUSY`, as Linux's `sched_dl_overflow` refuses bandwidth it cannot provide. Fork inherits the policy and its parameters; with `SCHED_RESET_ON_FORK` it gives a real-time or deadline child `SCHED_OTHER` at nice 0, and any child a nice value of 0 or more and the default slice, and a deadline thread without the flag may not fork. PI donations are neither inherited nor included in `sched_getparam`.

### Wait queues

A wait queue, `wait_queue_t` (`wait_queue.h`), is the list of the threads that sleep until one condition is true: data in a pipe, a datagram on a socket, a line from a terminal, a disk's answer. A sleeper's entry is the `struct wq_waiter` in its own record, and `poll` brings one for each object it watches, from an array it took before it began, so entering a queue allocates nothing and no queue has a size.

`wq_wait_event` puts the thread on the queue and marks it `PROC_BLOCKED` under the queue's own spinlock, and only then tests the condition, and a pending signal, with interrupts off; it calls `schedule` when both are false, and files itself and tests again when it runs, as Linux's `prepare_to_wait` comes before the test (kernel/sched/wait.c:247). A waker changes the condition first and wakes after, so a wake either came before the test, which then saw the condition true, or finds the thread on the queue and makes it ready, and `schedule` keeps it running. `wq_complete` sets a done flag and wakes in one hold of the queue's lock, for a waiter whose flag lives on a stack that ends with its wait. A thread still blocked when `schedule` returns, because the processor had nothing else to run, waits in `idle_wait_irq_off`. A pending signal ends the wait with `EINTR`. `signal_pending`, which judges it, reads and changes the signal state under the big lock, so a caller without the big lock, a futex's or an advisory lock's wait among them, tests only the signal-work flag before it sleeps, as `wq_wait_event_sigflag` does, and once the flag ends the sleep takes the big lock to call `signal_pending`; an ignored signal is discarded there and the wait sleeps again, its deadline armed again. A signal does not end `wq_wait_event_nointr`, the wait for a lock another thread has or for a transfer a device has in flight for the caller, whose sleeper /proc shows in the state D and counts in `procs_blocked`. Nor does a signal end `wq_wait_event_idle`, a kernel thread's wait for work, whose sleeper /proc shows in the state S and does not count, as Linux does not count TASK_IDLE. A deadline is `wakeup_tick` in the record, which the tick's `proc_wake_sleepers` (`process.c`) acts on without the big lock, in three steps under `sched_lock`: it collects the records due under the timer list's own lock, lets that lock go, and wakes each as `sched_wake_due` does, its state, its deadline and the reason it was collected for, its tick, a setting of the real-time clock or its time of the monotonic clock, tested again at the wake (`timer_wake`), since a thread whose condition came true leaves its wait without `sched_lock` and may start another, whose deadline the wake would otherwise clear, as Linux's sleeper waits for a running timer callback before its next sleep (`hrtimer_cancel`, kernel/time/hrtimer.c:1501-1512), as Linux's timer base expires its timers under its own lock and wakes each sleeper through `try_to_wake_up`; holding `sched_lock` across the three keeps each record collected from being freed before its wake, since `free_process` takes it (`sched_forget`). `wq_wake` takes each sleeper off the queue and makes it ready, in the order the sleepers joined it, oldest first. The fair class then runs them by their virtual deadlines, not in that order, so a lock whose oldest waiter must be served first hands itself over: the mutex to its oldest sleeper (`MUTEX_HANDOFF`), and the rwsem by keeping new readers out while a writer waits (`RWSEM_WAITING`). Each sleeper tests its own condition again, so a wake that was not for it costs one test. A record with a wake function, `func`, as Linux's wait entry, stays on the queue: the wake calls the function with the kinds of change and the lock checker's nesting, every record without `WQ_EXCLUSIVE` and then the exclusive ones in turn until one returns nonzero, as Linux's `__wake_up_common` (kernel/sched/wait.c:73-97). `poll` and `select` file such records for the whole wait, `epoll_wait` one exclusive record, and each epoll registration one on the queue of what it watches ([readiness](../io/Readme.md)). A queue that is freed while records may be on it, a thread group's signalfd queue, first calls each function with `WQ_FREE` and takes it off (`wq_wake_free`), as Linux's `wake_up_pollfree`; `wq_entry_remove` reads the record's queue under `wq_free_lock`, which `wq_wake_free` also holds, so it never takes the lock of a queue freed meanwhile. A sleeper that finds its condition still false joins the tail again, so it is woken before those that came after it. A wake also counts what kind of change it was, data, room or a hangup (`wq_wakes`). Each queue has its own lock over its list and its counts, as Linux's `wq_head->lock` (kernel/sched/wait.c:8-13, 99-108), so wakers and sleepers of two queues do not wait on each other; a wake walks the list under it, so a record leaves its queue only under the lock. The lock is a word that zero leaves free, so a queue in a zeroed record needs no `wait_queue_init`, and every queue's lock is of one class for the lock checker, `wq_head->lock`, given at the first take to a queue that was never initialised. A wake tests that the sleeper is blocked and makes it ready under the run queues' lock (`sched_wake_blocked`), as Linux's `try_to_wake_up` tests the state under the task's `pi_lock` (kernel/sched/core.c:4191-4193), so of two wakers on two of a poller's queues, or a queue's and a signal's (`sched_wake_signal`) or the tick's for its deadline (`sched_wake_due`), one makes it ready. The interprocessor interrupt that has another processor select now is sent after the queue's lock is let go (`sched_kick_cpus`), so the queue's other users do not wait for it; a futex wake leaves its interrupts in the bucket and sends them after the bucket's lock (`futex_hb_unlock`), as Linux's `futex_wake` wakes its `wake_q` after that lock (kernel/futex/waitwake.c:198-199).

`wq_wait_event_killable` is the wait of a `vfork` parent and of `execve` for its other threads. Its caller supplies a condition that becomes true when SIGKILL is pending for the thread or its process; the queue code tests no signal itself and returns 0 when that condition is true. The caller then handles the pending SIGKILL, with `exec_one_thread` returning `EAGAIN`. Like Linux's TASK_KILLABLE, the sleep appears in /proc as D, but the hung-task detector skips it. Other signals may wake it to test the condition again and do not end the wait.

`wq_wait_event_sigflag` is the wait of a halted KVM vCPU and of a pipe's read, write, splice and FIFO open ([the IPC layer](../ipc/Readme.md)), which judge a signal themselves. It ends with `EINTR` when the thread's signal-work flag, `sig_woken`, is set, read with no lock and changing nothing, as Linux's `kvm_vcpu_check_block` reads TIF_SIGPENDING (virt/kvm/kvm_main.c:3738); a signal wakes it as it wakes `wq_wait_event`. The caller then returns to the system call's return, which takes the signal, or asks `signal_pending` under the big lock, which discards an ignored signal and clears its flag, and a pipe's wait sleeps again (`pipe_sleep`). Its counted form, `wq_wait_event_sigflag_counted`, reports whether the thread slept and counts the queue and deadline wakes that made it ready under the run queues' lock. KVM uses that form to account for halts.

### Processors and the big lock

The kernel runs on each enabled processor the firmware lists, up to `NR_CPUS`, 64 (`percpu.h`), or as many as `maxcpus=N` on the command line allows; [the PC platform](../arch/x86/Readme.md) finds and starts them. `smp_start` (`smp.c`) makes the boot processor's idle task, then for each other processor makes its idle task, has the platform start it, and waits up to 100 ms for it to come online. The boot and the processor each decide in one compare-and-exchange of the processor's `admit` word whether it is counted or refused, so a processor that comes as the wait ends is either counted or stopped, never running uncounted. The log says `smp: processors: N online of M`.

Each processor has a `struct percpu` in `cpu_table` (`percpu.h`): the thread it runs, its idle task, the page directory it translates through, its depth in the big lock, its tick counts, and the requests other processors leave it. `this_cpu()` is the running processor's entry, which `arch_cpu_id()` indexes, and `current_proc` is its `current`. A processor changes its own fields; another reads them while it has the big lock, or for a request under `ipi_lock`, and writes only the requests.

The big lock covers the kernel code that has no lock of its own. An entry to the kernel, a system call, a fault or an interrupt, takes it (`bkl_enter`), again when the processor has it already, unless the entry is marked to run without it, and its return gives back what the entry took (`bkl_exit`): each entry frame records in a bit of the thread's `bkl_frames` whether it took the lock (`bkl_frame_push`, `bkl_frame_pop`). A system call that runs without it shifts a clear bit in and does no other bookkeeping at its entry (`isr_syscall`); a hold it takes on the way is charged to the call its number names (`isr_call_entry`). A system call runs without it when its number is marked for its ABI (`syscall_unlock`), judged after the tracer's entry stop on the handler the call will run; the dispatcher takes it all the same for a traced thread, a thread with a seccomp filter, descriptor holds left to give back and USB work pending (`syscall_entry_locked`). `sched_yield` is marked, native and i386, and so is `getrusage`, which takes the lock itself for any target but the calling thread, whose own counters it reads under no lock, as Linux's getrusage does (kernel/sys.c:1825-1829), and `rt_sigprocmask`, native and i386, which changes the mask under the signal state's lock and takes the big lock only for a change that lock cannot make alone ([signals](signal.Readme.md)), and the identity calls, native and i386 with the 16-bit forms, `getpid`, `gettid`, `getppid`, `getpgrp`, `getpgid`, `getsid`, `getuid`, `geteuid`, `getgid`, `getegid`, `getresuid`, `getresgid` and `getgroups` (`syscall_ids_unlock`), which read the caller's own record and credentials, each word once, as Linux's read the task and its credentials under RCU: only the thread changes its own credentials, and a parent's PID or a group that another thread changes under the big lock reads as its old value or its new one, as on Linux; they take the big lock themselves to look another process up and in a user or PID namespace below the first, whose maps and lookups it covers (`ids_lock`), and there read the word under the same hold as its translation, so that a parent that exits and is reaped in between cannot leave a PID no namespace maps (`pid_seen_free`), and so are the clock calls, native and i386, `clock_gettime`, `clock_gettime64`, `gettimeofday` and `time` (`syscall_clock_unlock`), which read real time and the clocks since boot under those clocks' own spinlocks and the tick's sequence count (`rach2/sys/clock.c`), as Linux reads its timekeeper under a sequence count alone (kernel/time/timekeeping.c), and take the big lock only to resolve and read a CPU clock, whose process and threads it covers (`clock_get`), so that a reading that falls back from the vDSO to the HPET, an exit of some microseconds under a hypervisor, holds no other processor's call, and so are the calls that change the regions, `brk`, `mmap`, `munmap`, `mprotect`, `pkey_mprotect`, `mremap`, `madvise`, `mlock`, `mlock2`, `munlock`, `mlockall` and `munlockall`, which hold the regions' lock alone across a change and take the big lock only around its steps that reach what has no lock of its own ([memory's Readme](../mm/Readme.md)), the futex calls, `futex`, `futex_waitv`, `futex_wake`, `futex_wait`, `futex_requeue` and `set_robust_list`, with the i386 entry's `futex` of the other width of time, `futex_time64` on i686 and `futex` of 32-bit time on x86-64 (`syscall_futex_unlock`, [futexes](futex.Readme.md)), but not `get_robust_list`, which looks another thread up in the pid hash that the big lock covers, where Linux uses RCU alone (kernel/futex/syscalls.c:57-63), and the socket calls, whose Unix operations have their own locks and which take the big lock for another family alone (`syscall_socket_unlock`, `socket_call`), and the file calls read, write, pread64, pwrite64, ioctl, fstat, close, poll and ppoll, which take the lock for every step on a descriptor whose type does not declare that it runs without it and for the signal state when the thread's signal-work flag is set or the call changes its mask, a poll's step on a pipe, a unix socket, an eventfd or a timerfd among those that do (`FILE_OPS_POLL_UNLOCKED`), and epoll_wait, epoll_pwait, epoll_pwait2 and epoll_ctl, which hold the set's own locks and take the big lock only to poll a registration whose descriptor's poll needs it ([epoll](../io/Readme.md)), and getdents64, fstatat, newfstatat, open, openat, access, faccessat, faccessat2, readlink and readlinkat, which run without it on ext2's regular files, directories and links and take it for anything else, lseek and _llseek, which run without it on those files, a dma-buf and a descriptor they refuse unlooked, and fcntl, which takes it only for the seals, a pipe's resize, a duplicate of a socket or a KRFFS file and F_SETFL on a file whose attributes need it ([../fs/Readme.md](../fs/Readme.md)), splice between two pipes and tee, which take only the pipes' locks, splice taking the big lock for a pipe and anything else (`splice_file`), and flock, which, like close's drop of the table's record locks, takes the advisory locks' own lock and the big lock only for a file of KRFFS, FAT32 or exFAT, whose lock is keyed by its node ([advisory locks](../fs/lock.Readme.md)). A KVM vCPU's descriptor declares that it runs without it: KVM_RUN and the exits the kernel handles run without the big lock, as Linux's do, and take it only for the signal mask's swap, the check of a signal that woke the thread and Hyper-V's state; KVM_RUN lets go of a hold the dispatcher took for the reasons above and takes it back at the same depth before it returns, while the vCPU's other ioctls take it themselves under the vCPU's mutex ([kvm](../kvm/Readme.md#lock-order)). An interrupt's chain runs without it when every handler of the vector was registered with `ISR_UNLOCKED` (`isr_register_flags`), and an exception when its vector is marked (`exception_unlock`), which the page fault's is. An entry that ran without the lock takes it on its return to user mode only for the work `signal_return_work` names, signals, ended threads and a tracer's among it, for an rseq notice (`rseq_notify`), and for loopback datagrams to deliver (`WORK_LOOP`, `syscall_loop_drain`). Whoever makes work for a thread's entry or return sets its bit in the thread's work word (`work`, `proc_work_set`), as Linux sets a thread's `TIF_` flags: a signal or a restart, a reschedule, a tracer, a seccomp filter, an rseq notice, a datagram on the loopback backlog, a debug register to load and a wake time to record. The entry tests the word once for a tracer and a filter, and the return once for the rest (`isr_leave`), which takes the bits it finds, does their work and sets again those whose work remains; after the signal and rseq work, which runs with interrupts on, it repeats that work while a signal to act on (`sig_woken`), a tick's signal or an rseq notice came during it, then takes the bits again with interrupts off and goes round once more for a switch, a datagram or an rseq notice that came meanwhile (`isr_leave_work`, `arch/x86/leave.c`), as Linux's `exit_to_user_mode_loop` rereads its flags (kernel/entry/common.c:122-127). The depth is each thread's: a switch saves it in the outgoing record and the incoming thread takes the lock back at its own (Scheduling), and every sleep gives the lock up, since each goes through `schedule`. An idle wait lets it go whatever the depth (`bkl_drop`) and takes it again at the same depth (`bkl_take_as`). A copy to or from user memory and a prefault hold the address space's `mmap_lock` instead, the residency check needs the big lock held (`vm_resident`, `mm/paging.c`), and memory reclaim takes it when its caller runs without it (`mm/pressure.c`). Code that still needs it checks that it is held in the `rach2-lockdep` kernel (`bkl_assert_held`): the process list and the pid hash, signal posting and the network's receive path. The lock is a word set by an atomic exchange, and its holder is the processor whose depth is above 0. A free lock that no waiter has claimed and none has lent is taken by the exchange alone, with no wait to time for the wake latencies, as Linux's `queued_spin_lock` takes a free lock and leaves the rest to its slow path. A waiter past a fixed count of spins claims the lock (`bkl_claim`), and the others leave it to the claimant, since an exchange alone favours the holder's hyperthread and can pass over the others for seconds; a claimant that does not take a free lock is passed over, as under a hypervisor. A switch gives the lock up, and `sched_service_point` lets a claimant have it in a long call on a processor with no switch to make (`bkl_yield`), since the call would otherwise keep it for its whole length. A holder that cannot sleep or let the lock go, and waits for what a thread on another processor holds while an interrupt that thread took waits for the lock, lends the lock to that processor alone (`bkl_lend`): the word stays set, the borrower takes it by the loan (`bkl_lent`) and gives it back at its outermost exit or drop, and the lender, its depth unchanged, waits for it, so that no third processor has the lock between them and the borrower runs inside the lender's hold as an interrupt taken there would; the page-cache fault that waits for another caller's AHCI claim with interrupts off is that holder ([the block layer's Readme](../block/Readme.md)). A processor that waits for it answers the requests left for it meanwhile, since the holder may be waiting for that answer, and keeps the lockup detectors going: a wait for the big lock counts as the waiter's watchdog timer, so that the holder alone is reported ([the lockup detectors](../watchdog.Readme.md)). The interprocessor interrupt, the NMI, the machine check and the double fault are taken without it ([the architectures' Readme](../arch/Readme.md)), and so is the tick, whose handler takes it only for the part that still needs it, by a try (`timer_handler`, `rach2/kernel.c`), as Linux's tick takes no global lock (kernel/time/tick-sched.c:253-278, kernel/time/timer.c:2514-2529). Every tick runs its first part without the lock, each step under a spinlock of its own: the clock's pass, which advances the tick count and carries the vDSO's clock on, under `clock_pass`, one writer at a time, as Linux's `jiffies_lock` (kernel/time/tick-sched.c:91), made by the boot processor's tick or, when that one is late, by another's, and by none while another is in it; the accounting (Scheduling); on the tick that made the clock's pass, the timer pass that wakes the sleepers and the timerfds due; and on the boot processor the periodic services that take only locks of their own, the HDA tick under the stream lock, the lag device's answers and the block requests' deadlines under theirs, the end of a speaker's tone under the speaker's lock, the i915's release of forcewake under its register lock, and vkms's vblank timer under the device's locks (`timer_own_work`), as Linux runs a driver's timer under the driver's lock. Its second part takes the lock: on any processor to post the signals of the tick that wait (Scheduling), which another processor's tick tries only when some wait, and on the boot processor also to fold the load average and run the kernel's periodic services. A try that fails leaves that part to a later tick, so that a holder on another processor takes nothing from this processor's user code; the boot processor's tick waits for the lock at the fourth failed try in a row, so that its periodic work is at most that late. The parts of the kernel that every processor enters on its ticks, faults and allocations, the run queues, the wait queues, the frame allocator, the heap, the timers and the console, also have spinlocks of their own (`rach2/sys/lib/spinlock.h`). Each is taken after the big lock when both are held, and none is held while the big lock is waited for. Locking, below, gives the order of every lock.

A request is a word in the target's record and an interprocessor interrupt that has it look (`smp_service`):

* A shootdown (`smp_tlb_shootdown`): after the entries of a range of user pages change, each other processor that translates through that page directory drops the range's translations, or every user translation, on one request, and the sender waits until each has cleared its word. One sender at a time sends and waits, under `ipi_lock`, with interrupts off, and a processor that waits for that lock answers its own requests meanwhile. `/proc/stat` counts the shootdowns that interrupted a processor as `tlb_shootdowns`, and the interrupts they sent as `tlb_shootdown_ipis`. A processor whose thread has no address space, an idle task or a kernel thread that kept the directory loaded, is not interrupted; the directory is marked stale there and loaded again at the switch to one of its threads. The sender marks it stale, passes a full barrier and reads the processor's thread again, and interrupts it after all when a thread with an address space has come; the switch publishes its thread, passes the run queues' lock, whose release is a locked exchange, and reads the mark, so one of the two sees the other. The sender need not hold the big lock, as a fault's copy-on-write break does not, so the records of the other processors' threads it reads are kept by `ipi_lock` instead: `free_process` takes and lets go that lock once the record has left every processor (`smp_record_quiesce`), so a record a scan read stays until the scan ends, and a scan that begins later reads the processor's new thread.
* A release (`smp_space_release`): before a directory that no thread uses is freed, each processor that still translates through it loads the kernel's.
* A change of a kernel mapping is dropped on every other processor before the change returns, as Linux's `flush_tlb_kernel_range` does (`arch/x86/mm/tlb.c`): `smp_kernel_flush` sends the range, or all of it from `smp_kernel_mapping_changed`, and waits for each answer, under `ipi_lock`, from any context, with or without the big lock. The kernel maps nothing global, so a processor that drops all its translations drops the kernel's too.
* A barrier (`smp_barrier`), for `membarrier`: each processor named answers with a locked exchange, a full memory barrier, after an `iret` to the next instruction (`arch_sync_core`) for the sync-core barrier, and the sender waits for each answer. The sender holds the big lock, so the threads it found running stay there until the answers come. A thread that `MEMBARRIER_CMD_PRIVATE_EXPEDITED_RSEQ` reached has its rseq critical section aborted on the interrupt's return to user mode.
* A call (`smp_call`): a function runs on the processor named, with interrupts off there, and the sender waits until it has returned, as Linux's `smp_call_function_single` with `wait` does. The processor answers after a full barrier, so the sender sees what the function wrote; on the sender's own processor the function runs at once.
* A stop (`smp_stop_others`), for a panic and a power off, is final. The sender waits up to a second for each processor to take it, then sends each that has not an NMI, which stops it with its interrupts off, and waits 10 ms more, as Linux's x86 stop does.

### Locking

Each lock has a row in one order, outermost first, and a lock is taken only while every lock held is of an earlier row; two locks of one class nest only by a subclass that the lock-order checker is told, as a rename's directories and nodes are (`sleep_lock_subclass`). The `rach2-lockdep` kernel checks the order as it runs, and /proc/lockdep lists each class it has met with its orders ([the lock-order checker](../lib/lockdep.Readme.md)). Row 1 and rows 3 to 8 are sleeping locks, `struct mutex` and `struct rwsem` (`mutex.h`) and `struct sleep_lock` (`../fs/sleeplock.h`), and rows 9 to 14 spinlocks. No sleeping lock is taken under a spinlock, a sleeping lock's waiter gives up the big lock as every sleep does, and the big lock is never waited for under a spinlock. A kernel thread keeps the big lock from one sleep or service point to the next, since the tick does not switch it (Scheduling), so no processor that takes the lock at a switch sees what the thread changes under it half changed. A kernel thread whose work has locks of its own gives the lock up at its start instead and takes it only around the parts that still need it: `khda` ([audio](../audio/Readme.md)) and `kdrm`, which takes it for a driver's work, a hotplug event and a commit's tail on a device without `DRIVER_KMS_UNLOCKED` ([DRM](../drm/Readme.md)). debugfs's `bkl/calls` counts each kernel thread's own holds on a line of its own, by pid and name ([debugfs(5)](../../../man/man5/debugfs.5)). The one exception is kpsmoused inside a run of mouse commands: its waits for the mouse's bytes let the lock go to a processor that waits for it (`bkl_yield` in `wait_turn`, `rach2/sys/arch/x86/ps2mouse.c`), so that the keyboard's handler runs meanwhile; the run's own state is kept by `cmd_busy`, which makes every other run of commands wait, not by the big lock. A row whose Here is empty names the place of the lock Linux has there, which the kernel has not yet.

### Credentials

Each record has the real, effective and saved user and group ids and up to `NGROUPS_MAX`, 8, supplementary groups (`process.h`). The ids are the kernel's, those of the first user namespace; a process in another one sees and names them through its maps ([namespaces](ns.Readme.md)). The setters change the calling thread's ids, as Linux's do, under the saved-id rules of POSIX: a privileged caller sets any id its user namespace maps, and another moves its ids only among its real, effective and saved ones. A change of an effective id clears the address space's dumpable flag and the parent-death signal, as Linux's `commit_creds` does, and a change of the effective user id takes away the capabilities held in a user namespace (`cred_moved`).

Each record also has an identity of its credentials, `cred_id`, which stands for the pointer to Linux's `struct cred`: linkat's `AT_EMPTY_PATH` compares it with the identity a description recorded at its open, as Linux compares the file's `f_cred` with the caller's ([link(2)](../../../man/man2/link.2)). A record takes a new one from a 64-bit count at its making (`proc_cred_commit`), and at every point where Linux commits new credentials: an exec, each setter of the user or group ids past its early return for a call that changes nothing (`cred_moved`), a `setfsuid` or `setfsgid` that changes the id, `setgroups`, `capset`, `PR_CAP_AMBIENT`'s changes and `PR_CAPBSET_DROP`, and the making or joining of a user namespace (`ns_caps_fill`), which a refused `setns` of a pidfd puts back. A thread made with `CLONE_THREAD` shares its creator's, as Linux's `copy_creds` shares the record, and any other new process has its own.

A thread also has a file-system user id and group id, which every check of access to a file and the owner of a new file go by (`proc_fsuid`, `proc_fsgid`); `access(2)` alone judges by the real ids. Each is the effective id until `setfsuid` or `setfsgid` sets it apart (`fsuid`, `fsgid` and the bits of `fs_own`), so a record that never called them needs no second copy kept in step. Every setter of the user ids and every exec clears the bit, which makes the file-system id the effective one again as Linux's setters do (`fsuid_follow`, `exec_commit`); a fork copies it. `setfsuid` takes an id that is the caller's real, effective, saved or file-system one, or any mapped id from a privileged caller, returns the previous id whether or not it changed, and clears the dumpable flag and the parent-death signal when it did (`fsuid_set`). The eight capabilities of Linux's `CAP_FS_SET` are in the effective set by the file-system user id, as Linux's `cap_task_fix_setuid` leaves them: a thread whose file-system user id left 0 fails the file checks an ordinary user fails though its effective user id is 0 (`cap_eff_word` in `ns.c`, `proc_fs_privileged`). A call that sets user ids brings that id back to 0 without them, which the bit `PROC_FSCAPS_OFF` of `fs_own` records until `setfsuid` returns the id to 0, the effective user id comes to 0 from another (`cred_moved`) or an exec; [setfsuid(2)](../../../man/man2/setfsuid.2) has the rules.

A thread holds Linux's 41 capabilities, numbered 0 to 40, but those it gave up (`cap_lost`), while its ids give them: as effective user id 0, or in a user namespace as [namespaces](ns.Readme.md) says (`cap_ids` in `ns.c`); or while an exec gave it those of its ambient set (`amb_granted`, `cap_word`). The kernel keeps one set for the effective and permitted ones, and the inheritable and ambient sets (`cap_inh`, `cap_amb`) with Linux's rules. `capset` keeps the capabilities of the permitted set it is given (`cap_store`) and the inheritable set it is given, and narrows the ambient set to both. An exec of an image of root gives back those of the bounding set (`bset_lost`), from which `PR_CAPBSET_DROP` takes one for good, and of the inheritable set, except under `no_new_privs`, a tracer that is not privileged or directories another process shares, where the image holds no capability its caller lacked, a thread that holds only what an exec gave it from its ambient set as much as any (`exec_ids` in `syscall_proc.c`); a fork passes all four on. `PR_CAP_AMBIENT` raises a capability that is held and inheritable into the ambient set, which an exec keeps for an image without set-id bits and empties for any other, and which a change of the user ids away from root empties. An image whose ids give no capability then holds those of the ambient set and has lost the rest (`exec_ambient` in `syscall_proc.c`), as Linux gives them whatever the uid; bubblewrap's `--cap-add` keeps its capabilities this way, when root runs it and when an ordinary user does in a user namespace. What only a privileged thread may do needs `CAP_SYS_ADMIN`: `proc_privileged` (`process.h`) is true for a thread with effective user id 0 in the first user namespace that has not given it up (`nocaps`), and `PR_CAPBSET_DROP` also needs `CAP_SETPCAP`. `chroot` checks `CAP_SYS_CHROOT`, and KVM's KVM_CAP_VM_DISABLE_NX_HUGE_PAGES `CAP_SYS_BOOT` held in the first user namespace, as Linux's `capable`; the other capabilities guard nothing of their own ([capget.2](../../../man/man2/capget.2)).

`exec_ids` chooses the ids of a new image from the file's set-id bits and the caller's effective ids, and `exec_privileges` makes an image that runs with ids its caller lacks not dumpable and lowers its soft `RLIMIT_STACK`, when above 8 MiB, to 8 MiB; [execve(2)](../../../man/man2/execve.2) has the rules. For a caller that is not privileged, the bits do not apply when its thread has a tracer that is not privileged or shares its directories with a process outside its group, since either could change the image once it had the ids. While an exec that applies them runs, `CLONE_FS` fails in the threads that share its directories (`in_exec` in `struct fs_struct`), so that the choice stays true until the image is the process's.

### Resource limits

A record has nine limits, `RLIM_COUNT` in `process.h`, each a soft value that is enforced and a hard value the soft one may be raised to, `RLIM_INFINITY` for none. A limit is a `long`: 32 bits on i686, where a 64-bit value from `prlimit64` past them is kept as no limit, and 64 bits on x86-64. A fork copies the limits and an exec keeps them, but for the lowered stack limit above. `rlimit_set` (`rach2/sys/syscall_proc.c`) writes the limit into every thread of the process; it refuses a soft value above the hard one with `EINVAL`, a raised hard value from a caller that is not privileged with `EPERM`, and a hard `RLIMIT_NOFILE` above `fd_nr_open`, fs.nr_open, with `EPERM` even to root, as Linux does. A resource Linux has and this kernel does not keep reads as unlimited, and a set of one is accepted and changes nothing.

### seccomp

A thread has a chain of filters, newest first, each a classic BPF program, the instruction set of the BSD packet filter (`seccomp.c`). A filter runs over Linux's `struct seccomp_data`: the call's number, the architecture's audit number, `SC_AUDIT_ARCH` of the frame in its `cpu.h` (`0x40000003` on i686, `0xC000003E` on x86-64, and `0x40000003` there for an i386 call by `int 0x80`), the instruction pointer, and the six arguments, each widened to 64 bits. The check at the install, as Linux's `seccomp_check_filter`, takes at most 4096 instructions, loads inside the structure, sixteen scratch words, and jumps that go forward and stay inside the program, so every program ends at a return. A chain may have 32768 instructions, each filter counted with four more. A caller without `no_new_privs` must be privileged to install a filter, and `SECCOMP_FILTER_FLAG_TSYNC` gives the chain to every thread of the process.

The dispatcher (`_syscall_handler` in `rach2/sys/syscall.c`) runs the filters after a tracer's stop at the call's entry, on the call the tracer left, and before the handler. Every filter of the chain runs (`chain_action`), and the action of highest precedence is taken, the actions compared as signed numbers as Linux compares them (`precedence`); [seccomp(2)](../../../man/man2/seccomp.2) has what each action does. The strict mode's four calls are `SECCOMP_NR_` in each `cpu.h`, with `rt_sigreturn` in place of `sigreturn` on x86-64, and for an i386 call there the i386 numbers, `SECCOMP_NR32_` (`strict_allows`). A fork passes the mode and the chain on, a chain is shared and counted by the threads and children that have it, and an exec keeps both.

### Core files

A signal whose default action dumps core, a seccomp kill of the process, and a signal frame that cannot be built or read back end the process through `terminate_current_process` with a core asked for. `terminate_current_process` (`rach2/kernel.c`) writes the core when the process is dumpable ([prctl(2)](../../../man/man2/prctl.2)), its soft `RLIMIT_CORE` is at least a page, and no other thread has begun to end it ([core(5)](../../../man/man5/core.5)). It sets the group's `core_dumping`, sends the other threads `SIGKILL` (`proc_group_exit`), and calls `fs_core_file` (`rach2/sys/syscall_fs.c`) before this thread releases anything. Each other thread, ending by that `SIGKILL`, saves its floating-point state and parks before it releases anything (`core_park` in `coredump.c`), so that none runs in user mode on another processor while its registers are copied or the memory written.

`core_notes` waits until each other thread has parked or ended, as Linux's `coredump_wait` waits, or until an exec by one of them waits for the rest, and builds the `PT_NOTE` segment in the heap: the dumping thread's `elf_prstatus`, the process's `elf_prpsinfo` and auxiliary vector, the thread's floating-point notes (`arch_core_fp_notes`), then each other thread's `elf_prstatus` and floating-point notes. The registers are those `arch_regs_get` reads from the frame at the top of each kernel stack, as the ptrace requests read them ([ptrace](ptrace.Readme.md)). An i386 program's core on x86-64 is ELF32 for `EM_386`, its headers' sizes and offsets those of `core_ia32` where any other has `core_native`: its notes are the i386 structures, `core_prstatus32` with the registers of `ia32_regs_get` and `core_prpsinfo32`, the vector in 4-byte words through `AT_NULL`, and the floating-point and TLS notes of `ia32_core_fp_notes` (`arch/x86_64/ia32_core.c`).

`core_write` takes the regions once into a list, which the program headers and the pages follow, since another process that shares the address space, as a `vfork` child does, is not ended and may change the regions while the writer sleeps; each page is looked up again as it is read, and one unmapped meanwhile is a hole. Each page is read through `paging_access`, which brings in from the file a page of a mapped file the process never touched; a page of anonymous memory it never touched is a hole, which the writer may skip, and so are the vDSO's data page and KVM's clock page, [vvar], as on Linux (`vdso_is_data`). A process may have up to `VMA_LIMIT`, 65536, regions (`rach2/sys/mm/vm.h`), more than the ELF header's 16-bit count of program headers can record, so a file of 65535 headers or more uses ELF's extended numbering. `fs_core_file` writes the file `core` in the working directory: it unlinks whatever has the name, creates the file with `O_EXCL` and `O_NOFOLLOW`, and writes through a descriptor marked closing from the moment it is opened, so that a process sharing the descriptor table cannot use it. The parked threads go on to their end once the file is written or given up (`core_release`), and the wait status has `WCOREFLAG` only when the whole file was written. A `SIGKILL` sent to the process during the dump is the one signal that is not dropped then: it makes the process's status `SIGKILL`'s and sends every thread `SIGKILL` (`sig_complete`), and the writer stops before its next piece (`core_file_put`), as Linux's `dump_interrupted` stops it, and leaves `WCOREFLAG` out (`terminate_core`).

### Suspend to idle

A write of `freeze` or `mem` to `/sys/power/state` (`rach2/sys/fs/procfs.c`) calls `suspend_to_idle` (`suspend.c`), the sleep state Linux calls freeze. The writer sleeps on a wait queue, and until it wakes the scheduler runs no other process (`suspend_lets_run`), so each processor idles. Interrupts are taken and the clocks count, but no thread's wait on a run queue does. The freeze takes every ready ordinary thread but the writer off its fair queue onto a list of held threads, and finishes the dequeue of every delayed one, as Linux's frozen tasks sleep in a state that is never delayed; a thread running elsewhere joins the list at its switch away, and one woken meanwhile at its wake. Real-time threads stay on their lists, where selection passes over them. It adds each queued thread's wait so far to its `run_delay`, and the resume puts each held thread back as a wake does and starts every wait again (`sched_hold_waits`). The Atheros Wi-Fi station stops before the freeze and restarts after it if it was wanted and rfkill permits it; its association is cleared ([the driver](../network/driver/ath9k/Readme.md)). The clock's alarm interrupt (`rach2/sys/fs/devfs.c`) and a key event (`input_key_event` in `rach2/sys/input.c`) are the wake events (`suspend_wake`): the writer runs, its write returns, and the other processes run again. A signal ends the wait with `EINTR`, and a write while another suspend is in force fails with `EBUSY`.

A scheduler idle wait stops the local tick once the platform has an independent reference clock and a one-shot event timer ([the x86 timer](../arch/x86/Readme.md)). On wake, `sched_idle_account` charges the idle span at once, to the last scheduler edge before the wake and less the hypervisor's steal time, as Linux charges a stopped tick's idle span by the jiffies it crossed (`tick_nohz_account_idle_time`, kernel/time/tick-sched.c:1395-1415); the end of a halt under a running tick, whose ticks charged each edge it passed, charges nothing. The next busy tick charges the whole period it closes to the thread it finds, so the run of the last thread after its last tick, and a run shorter than a period that began at a wake, are charged as Linux's sampling tick charges them, not to idle (`sched_edge_ticks`). A reading of `sched_cpu_ticks` projects a stopped processor's idle and steal span to the same edge from its accounted time and its own hypervisor page, within the processor's sequence count, without changing its stored account. Each processor keeps an absolute watchdog sample armed while idle, including the buddy check for a processor stalled with interrupts off. A busy processor's tick asks one with a stopped tick to balance for the idle processors (`fair_nohz_kick`); KVM's SRCU waits on reader counts and needs no tick for a grace period.

An earlier CPU0 service target whose kick was absorbed by an awake or polling idle task is installed before that task returns to selection or starts its next wait (`timer_service_ipi`). The following final timer commitment includes it even when a short wait retains the tick.

## Limits

* Most kernel code still runs under the big lock, on one processor at a time, and a long system call delays every other processor's entry that takes it; the few calls that run without it are those Processors and the big lock lists, and its file calls take it for every descriptor type but ext2's regular files and directories, whose writes and changes of names and attributes take it still ([../fs/Readme.md](../fs/Readme.md)), and the few others that declare that they run without it, DRM's nodes and KVM's vCPUs among them. The timed-wake measurements under Results show the delay this causes under load. Console writes now offer the lock after each chunk; a single chunk and interrupt work still hold it.
* The fair class has no cgroup file system above it: autogroup's sessions are its only groups, so there is no `cpu.weight`, `cpu.max` or bandwidth control. It has no NUMA balancing and no core scheduling.
* No wake carries Linux's sync hint (`WF_SYNC`), with which a pipe's or a socket's waker that sleeps at once asks for the woken thread on its own processor, and an exec is not placed by load, as Linux's `sched_exec` places it; a wake and a fork are.
* `times`, `getrusage`, `wait4` and `/proc/PID/stat` give user and system time as the tick samples it, which switches shorter than a tick skew: of two threads that share a processor by weight, the one the tick finds more often is charged more than its share. Linux scales the samples to the run time the scheduler charged (`cputime_adjust`, kernel/sched/cputime.c:545-621).
* The load averages count no sleeper, uninterruptible or not.
* `SCHED_DEADLINE` is refused with `EBUSY` after its argument, privilege and affinity checks because the scheduler cannot provide deadline bandwidth. The utilization clamps are refused with `EOPNOTSUPP`, as by a Linux built without `CONFIG_UCLAMP_TASK`.
* The kernel runs on at most 64 processors, and an affinity mask has 64 bits.
* Privilege is `CAP_SYS_ADMIN` for every operation that asks for it, where Linux asks for the one capability each needs; the effective set is the permitted one. A thread whose ids are not root holds no capability but those an exec gave it from its ambient set.
* A thread has at most 8 supplementary groups, where Linux allows 65536.
* `clone` refuses `CLONE_SIGHAND` without `CLONE_THREAD`, an exit signal other than zero or `SIGCHLD` for a process, and the cgroup and time namespaces.
* `execve` follows one level of `#!`, and reads a first line of at most 128 bytes.
* Nine resource limits are kept; Linux's others read as unlimited.
* `getrusage` and `wait4` report CPU time, resident memory, page faults and voluntary and involuntary context switches; the other resource counters are zero. Context switches include ended threads and reaped descendants. The resident memory peak is sampled when asked and where an address space ends, not at every fault.
* `prctl` takes twelve options, the parent-death signal, the dumpable flag, the name, the child subreaper flag, `no_new_privs` and the seccomp mode, each set and read; any other is `EINVAL`.
* seccomp has no user notification: a filter cannot be installed with a listener, and `SECCOMP_RET_USER_NOTIF` fails the call with `ENOSYS`. `SECCOMP_RET_LOG` allows the call and logs nothing.
* `personality` takes only `PER_LINUX` and `PER_LINUX32`, and its flags change nothing; the kernel places no address at random.
* Suspend to idle stops the Atheros Wi-Fi station; other devices stay up. A write of `mem` to `/sys/power/state` suspends to idle as `freeze` does, and the kernel has no suspend to memory or to disk.

The same static program runs on Linux: on Debian 13's kernel, with the program in the root cgroup, which autogroup requires, every row but the suspend holds, and in QEMU that kernel does not wake from `freeze` at the clock's alarm.

* `tests/run memory` includes the overrun of a kernel stack ([the architectures' Readme](../arch/Readme.md)).
