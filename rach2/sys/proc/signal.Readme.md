# Signals

Rach2 keeps the signal dispositions, and the signals sent to a process as a whole with their `siginfo`, in the process's thread group (`tgroup.h`), and a blocked mask and the signals sent to one thread with theirs in each thread's record. It posts signals immediately but acts on them only when a thread returns to user mode. The Linux i386 signal numbers 1 through 31 have their usual names; the 64-bit masks also accept numbers 32 through 64. Each pending signal occupies one bit, so repeated instances coalesce, and the first instance's `siginfo` is the one delivered. Queued real-time signals are not implemented. Handlers receive Linux's i386 frames, built and restored by `sigframe.c`.

A user-mode CPU exception is forced as Linux forces it (`signal_force`): a page fault gives `SIGSEGV` with `SEGV_MAPERR` or `SEGV_ACCERR` and the address, a divide error, x87 error or SIMD error `SIGFPE` with its code, an invalid opcode `SIGILL`, a segment or alignment fault `SIGBUS`, `int3` and a single step `SIGTRAP`, and a protection fault `SIGSEGV` with `SI_KERNEL`. The signal goes to the faulting thread. A signal the thread blocks or the process ignores returns to its default disposition and is unblocked, so the process dies; a handler runs otherwise. When it returns without changing the saved context, a fault runs its instruction again, and a trap, `int3`, `into` or a single step, goes on after it, since the saved instruction pointer of a trap is the next instruction's; a handler that changes the context resumes where the context says. The breakpoint and overflow gates are DPL 3, so user mode reaches them. The trap number, error code and fault address go into the frame's `sigcontext`.

## Process and thread state

`struct tgroup` contains the dispositions, `action[1..64]`, which each thread's `sigacts` points at; the process's `pending` set and `info[1..64]`; and `stop`, the signal of a stop in effect. `process_t`, one record per thread, contains `sig_pending`, `sig_blocked` and `sig_info[1..64]`, the alternate stack (`altstack_sp`, `altstack_size`, `altstack_on`), the mask a wait replaced (`saved_sigmask`, `sigmask_saved`), the call a signal may restart (`restart_nr`), and the last exception's trap number, error code and address. A new process starts with default dispositions and empty masks. `fork` copies the dispositions, the blocked mask and the alternate stack but gives the child empty pending sets; a new thread shares the dispositions, has the creating thread's mask and no alternate stack. `execve` removes the alternate stack, preserves ignored dispositions, the blocked mask and the pending sets, and resets caught dispositions to default. The real-time interval timer is two more fields of the leader's record, the thread whose id is the process id: `alarm_tick`, the tick its next `SIGALRM` is due at, or zero when it is disarmed, and `alarm_interval`, the ticks between one `SIGALRM` and the next, or zero for a single one. `fork` gives the child no timer and `execve` keeps it, with a `SIGALRM` already pending.

`SIGKILL` and `SIGSTOP` cannot be caught or ignored, and every mask update removes their bits. Installing `SIG_IGN` for another signal also removes an instance already pending.

The main implementation is in `sys/syscall_proc.c`, which the system-call table in `sys/syscall.c` dispatches to; the interval timers' calls, `setitimer`, `getitimer` and `alarm`, are in `sys/syscall.c` itself. Signal numbers, action flags, and the kernel action layout are in `sys/lib/ksignal.h`; the PCB fields are in `sys/proc/process.h`; and both return epilogues in `sys/isr_handler.s` call `deliver_signals` before `iret`.

## Posting and permission

`signal_post` and `signal_post_info` send a signal to a process: they set the process's pending bit and make ready the thread `sig_taker` chooses, as Linux's `complete_signal` chooses: the thread named when it can take the signal, and otherwise the first that can, where a thread that can is one that has not ended, is not stopped, by job control or by its tracer, and does not block the signal. `signal_post_thread` sends one to a single thread, which alone may take it; `tkill`, `tgkill`, the faults, and the `SIGKILL` that `exit_group` and `execve` send the other threads use it. Posting has additional job-control effects:

* `SIGCONT` removes pending stop signals, the process's and each thread's, and resumes a stopped process, every thread of it. The parent receives `SIGCHLD` and a `wait4(WCONTINUED)` event.
* A stop signal removes a pending `SIGCONT`.
* `SIGKILL` makes a stopped thread ready so it can take the terminating action.
* Other signals remain pending while a process is stopped.

`kill` supports a positive PID, which may be the id of any thread of the process, PID zero for the caller's process group, and a PID below -1 for the named process group. PID -1 broadcast is not implemented and returns `-ESRCH`. Signal zero checks existence and permission without posting. `tkill` takes a positive thread ID; `tgkill` takes a positive process ID and a positive thread ID of that process.

`rt_sigqueueinfo` and `rt_tgsigqueueinfo`, which `sigqueue` calls, post a signal with the caller's siginfo, its code and the pid, uid and value words, under the same permission; a code of zero or above, or `SI_TKILL`, is the kernel's, and a caller gives one only to its own process. The kernel keeps one pending instance of each signal, its pending bit and one siginfo, so a real-time signal sent again while pending is merged with it, where Linux queues each. A POSIX timer posts its signal with `SI_TIMER` and its id, overrun and value in those three words, and adds later expirations to the pending signal's overrun (`io/timerfd.c`).

A signalfd (`signalfd` and `signalfd4`, in `syscall_proc.c`) reads the pending signals of its mask, which the caller blocks, as `rt_sigtimedwait` takes them (`sigwait_take`): a read with none pending waits with the mask unblocked, and `poll` reports it readable while one is pending for the poller, whom a signal post wakes as the thread `sig_taker` chooses.

Root, identified by effective uid zero, may signal any live process. Otherwise the sender's real or effective uid must match the target's real or saved uid. `SIGCONT` is also allowed between members of one session, but signal zero does not receive that exception. Terminal-generated signals are posted to the foreground process group without applying a process sender's credentials.

## Dispositions and masks

The signal syscalls are `kill`, `tkill`, `tgkill`, `rt_sigaction`, `rt_sigprocmask`, `pause`, `rt_sigsuspend`, `sigreturn`, and `rt_sigreturn`. The real-time action and mask calls require an 8-byte signal set.

The default actions are:

* Ignore `SIGCHLD`, `SIGURG`, `SIGWINCH`, and `SIGCONT`.
* Stop on `SIGSTOP`, `SIGTSTP`, `SIGTTIN`, and `SIGTTOU`.
* Terminate with a core file on `SIGQUIT`, `SIGILL`, `SIGTRAP`, `SIGABRT`, `SIGBUS`, `SIGFPE`, `SIGSEGV`, `SIGXCPU`, `SIGXFSZ`, and `SIGSYS`, as `core(5)` describes; `terminate_current_process` writes the file through `fs_core_file` in `syscall_fs.c` and `core_write` in `coredump.c`.
* Terminate on every other accepted signal number.

A stop stops the whole process: the thread that takes the stop signal records one status for `wait4(WUNTRACED)` and posts `SIGCHLD` to the parent, and every thread parks in `deliver_signals` as it next returns to user mode, unless a tracer has it, when it stops for the tracer instead, a thread a tracer attaches to while it is parked included. A terminating or core default ends every thread (`proc_group_exit`). A later continue records one `wait4(WCONTINUED)` status. The single status slot means that an unreaped stop or continue event can be replaced by the next transition. The booted `/sbin/init` cannot be stopped; this exception does not apply to the debug shell's transient test process.

An ignored signal, including one whose default action is ignore, does not interrupt a blocking wait. A caught, terminating, or stopping signal that is not blocked makes an interruptible wait leave its loop, and so does a stop a tracer asked for with `PTRACE_INTERRUPT` (`signal_pending`), which the return to user mode then takes. The syscall result is `-EINTR` unless the wait's own condition is already met when the signal is tested, for example a ready descriptor, data, space or end of file, a child's change of state, or a `nanosleep`'s deadline tick (a `poll` or `select` deadline is tested after the signal and does not count), or an operation that already transferred data returns its partial count; a default stop or termination can act before user code observes that result.

Every change of a thread's mask goes through `signal_set_blocked`: `rt_sigprocmask` and the old `sigprocmask`, a handler's mask and its return, and the masks `rt_sigsuspend`, `rt_sigtimedwait`, `ppoll`, `pselect6` and `epoll_pwait` install and put back. It removes the `SIGKILL` and `SIGSTOP` bits, and when the new mask blocks a signal pending for the process that the old one did not, it wakes another thread that can take it, as Linux's `retarget_shared_pending` does, since `sig_taker` may have woken this thread alone for that signal.

`rt_sigaction` stores all action flags. Delivery implements the installed mask, `SA_SIGINFO`, `SA_ONSTACK`, `SA_RESTART`, `SA_NODEFER` and `SA_RESETHAND`. The handler returns to the installed restorer with `SA_RESTORER` and to the frame's own `retcode` without it. musl and GNU libc both set `SA_RESTORER`, with a restorer that calls `sigreturn` for a plain handler and `rt_sigreturn` for `SA_SIGINFO`. `SA_NOCLDSTOP` and `SA_NOCLDWAIT` have no special behavior.

The dispatcher records a system call that returned `-EINTR` in `restart_nr` unless it is one Linux never restarts after a handler: `pause`, the sleeps, `poll`, `select`, the `epoll` waits and their signal-mask forms, `rt_sigtimedwait`, `rt_sigsuspend`, a `futex` wait with a timeout (`futex_restartable`), and the two returns from a handler. On that return `deliver_signals` restarts the call, by putting its number back in EAX and the instruction pointer back on `int $0x80`, when no handler runs, as after a stop and a continue, or when the handler that runs has `SA_RESTART`; otherwise the call keeps its `EINTR`.

`rt_sigsuspend` installs a temporary mask, waits for an acting signal, and returns `-EINTR`, keeping the old mask in `saved_sigmask`. The handler runs under the temporary mask, and its frame stores the old mask, which the handler's return restores; with no handler, the old mask comes back on the return from the call. `ppoll` and `pselect6` apply their mask the same way. `sigaltstack` sets the alternate stack, refusing a change while the process runs on it (`EPERM`) and a stack under 2048 bytes (`ENOMEM`); `rt_sigpending` reports the signals pending while blocked, and the old `sigprocmask`, 126, changes signals 1 through 32.

## Delivery and return

The interrupt and system-call epilogue and the hardware-IRQ epilogue call `deliver_signals` with interrupts disabled. A default that ends the process enables them for its teardown, as a system call runs, since the core file and the release of the files may sleep in a disk that answers only by interrupt (`terminate_current_process`), and disables them again once the end is published. It does nothing for a kernel-mode return. For a user-mode return it takes one pending, unblocked signal and clears its pending bit (`sig_dequeue`): the lowest-numbered of the thread's own, or, when the thread has none, the lowest-numbered of its process's, as Linux's `dequeue_signal` takes them.

A default disposition ignores, stops, or terminates as described above. A caught disposition builds a frame below the user stack pointer, or at the top of the alternate stack for `SA_ONSTACK` when one is set and not in use, redirects `EIP` to the handler, and blocks the action's mask plus the delivered signal unless `SA_NODEFER` is set. `SA_RESETHAND` resets the disposition for the next signal once the frame is built. Only one handler is entered at a time; remaining signals are reconsidered at a later return-to-user boundary.

The frames are Linux's (`arch/x86/include/asm/sigframe.h`). A plain handler's `struct sigframe` has the return address, the signal number, a `struct sigcontext`, an unused floating-point area kept where old programs found one, the upper word of the mask to restore and an 8-byte `retcode`. An `SA_SIGINFO` handler's `struct rt_sigframe` has the return address, the signal number, the `siginfo_t` and `ucontext_t` pointers, the 128-byte `siginfo_t`, the `ucontext_t` (flags, link, the alternate stack, the `sigcontext` and the 8-byte mask) and the `retcode`. The `sigcontext` has the interrupted segment and general registers, the trap number, error code and fault address, and the address of the floating-point state, a `struct _fpstate_32` placed above the frame at 64-byte alignment: `fpu_to_linux` writes the x87 environment and registers in the `fnsave` layout, then the `fxsave` image at byte 112, or under `rach2.nofxsr` the `fnsave` image alone with magic 0xFFFF. The frame is aligned so that the handler's stack pointer plus four is a multiple of 16. The handler starts with its signal number in EAX and, for an rt frame, the two pointers in EDX and ECX, with the direction and trap flags clear and the initial floating-point state.

When the handler returns, a plain restorer invokes `sigreturn(119)` after popping the signal argument, 8 bytes past the frame's start; an `SA_SIGINFO` restorer invokes `rt_sigreturn(173)` directly, 4 bytes past it. `sigframe_restore` then restores the general registers, instruction and stack pointers, the `EFLAGS` bits a program may change, the floating-point state through `fpu_from_linux`, which takes the x87 part from the environment a handler may have changed, and the saved mask; the rt form restores the alternate stack too. It forces the ring-3 code and stack selectors and keeps a data selector only when it is one this kernel has. An unreadable frame terminates the process with `SIGSEGV`, and so does a floating-point state with a reserved MXCSR bit set, which `fxrstor` would fault on in the kernel.

## Kernel signal sources

Process exit, stop, and continue post `SIGCHLD` to the parent, with `CLD_EXITED`, `CLD_KILLED` or `CLD_DUMPED`, `CLD_STOPPED` or `CLD_CONTINUED`, the child's pid and real uid, and its status (`proc_child_info`), and a process's exit posts to each living child the parent-death signal it set with `prctl(PR_SET_PDEATHSIG)`, after init, where there is one, has adopted the child (`reparent_children` in `sys/proc/process.c`). `kill` sends `SI_USER` and `tkill` and `tgkill` `SI_TKILL`, each with the sender's pid and real uid. A write to a pipe with no reader posts `SIGPIPE` with `SI_USER` from the writer. What else the kernel sends has `SI_KERNEL`. A pseudo-terminal resize posts `SIGWINCH`, and closing its master posts `SIGHUP` to the slave's foreground group. The real-time interval timer posts `SIGALRM`: `setitimer(ITIMER_REAL)`, `getitimer` and `alarm` set and read the two fields above, and the timer tick posts the signal to each process whose timer is due and arms the timer again for its interval, or leaves a single alarm disarmed (`proc_wake_sleepers` in `sys/proc/process.c`). A `nanosleep` ends with `-EINTR` when its process runs before its deadline with a `SIGALRM` pending that is neither blocked nor ignored; a `poll` or `select` that finds nothing ready ends with `-EINTR` whenever such a signal is pending, at its deadline too; `nanosleep(2)` and `poll(2)` give the rules. The virtual and profiling timers, `ITIMER_VIRTUAL` and `ITIMER_PROF`, count the process's processor time in two fields of its thread group: the tick that charges a thread a tick of user time, or of either for the second, counts it down, and posts `SIGVTALRM` or `SIGPROF` to the thread when it reaches zero, arming it again for its interval (`sched_account_tick` in `sys/proc/sched.c`); glibc's `profil`, which gprof's `-pg` programs use, samples with the second. `setitimer(2)` has the rest.

With terminal `ISIG` enabled, the line discipline maps `VINTR`, `VQUIT`, and `VSUSP` to `SIGINT`, `SIGQUIT`, and `SIGTSTP`. The defaults are Ctrl-C, Ctrl-Backslash, and Ctrl-Z. It discards the current edit line, committed unread input, and a pending EOF before signaling the foreground group. PS/2 keyboard and COM1 input both use this discipline while a user session owns the console.

A foreground read interrupted by a caught signal returns `-EINTR`, or is restarted when the handler has `SA_RESTART`; a default `SIGINT` terminates before user code observes the return. A background terminal read posts `SIGTTIN`, and a background write with `TOSTOP` posts `SIGTTOU`. If the applicable signal is blocked or ignored, the operation returns `-EIO` instead. The console and pseudo-terminal slave use the same rule.

## Verification

The default `make test` run includes these signal checks:

* `sigprobe` covers a caught signal, blocking and unblocking, `rt_sigreturn`, default termination, a one-shot handler, a sleep a signal ends, and the real-time interval timer.
* `ownprobe` covers uid permission, saved uid permission, the same-session `SIGCONT` exception, and the stricter signal-zero probe.
* `waitprobe` interrupts a blocked socket receive, `pipeprobe` catches `SIGPIPE`, and `jobprobe` covers group signals, stop, continue, kill, and background `SIGTTIN`.
* `musl/sigmusl` covers musl's plain and `SA_SIGINFO` handlers, both restorers, the mask, `raise`, and `abort`, and the Linux context of an `SA_SIGINFO` handler: the user code selector, a stack pointer and the floating-point state's address in `uc_mcontext`, the pre-handler mask, and a siginfo naming `tkill` and its sender. `tests/system/sigcontext_mutate.sh` proves it fails when `sigframe.c` stops filling `uc_mcontext`.
* `musl/sigframemusl` covers a fault handler that makes a page writable and returns to the faulting write, `SEGV_MAPERR` with its address, `SA_RESTART` and its absence on a blocked read, `SA_ONSTACK` on the alternate stack, `int3`, `rt_sigpending`, the old `sigprocmask`, `sigsuspend`'s mask, and `SIGCHLD`'s siginfo.
* `musl/pwauthmusl` installs handlers for signals above 34 and for fault-numbered signals, and confirms that musl reserves 32 through 34.

`tests/run host` checks the line discipline's `ISIG` recognition and input flush under AddressSanitizer and UndefinedBehaviorSanitizer. The test image also stages `musl/ctrlcmusl` for manual runs. It blocks in `read`; sending Ctrl-C must terminate it with `SIGINT`, and any return from `read` is failure. See the [guest test inventory](../../../tests/Readme.md) for the manual procedure.
