# Finish the normalization: the in-house non-kernel code, the missed docs, and the leftovers

## Status

Draft for review. This plan finishes what the text-standard refactor (dev-log/03-text-standard) started. That milestone brought the kernel (rach2/) and the high-traffic docs to the standard in CLAUDE.md and made the mechanical text checks a hard gate. It left the rest of the in-house tree (the tests, the krffs host tools, the utils, and the ish shell) with its original comment style, and a survey turned up a handful of consistency gaps in the work already done. This plan closes both.

## Purpose

Every file written for Rach2 should read as if one careful author wrote it, not just the kernel. The tests, the krffs host tools, the utils, and the ish shell were written for this kernel, so they get the same treatment the kernel got: real Doxygen headers, no restating or diary comments, terse prose, and docs that state the current contract. The phases here also fix the consistency gaps a read-only survey found in the already-normalized kernel and docs, so the whole tree is consistent, and they close the blind spots that let a stray non-ASCII byte and a couple of diary tags survive the gate.

## Scope

In scope (in-house, written for the kernel):

* `tests/` (the freestanding probes), `tests/musl/` (the musl-linked integration programs), and `tests/host/` (the native ASan/UBSan seam tests): comments, file headers, the two Readmes, the musl build script, and the .gitignore.
* `krffs/` host tools: the FUSE mount and the mkfs/fsck/defrag/edfs/fsviz/stagetree programs, the shared core (`krffs_file_system.c`, `krffs_node.c`, `krffs_allocator.c`, `krffs_utilities.c`) and their headers, and the ramdisk builder scripts.
* `utils/`: the musl-linked Unix utilities and the shared stub resolver (`resolv.c`, `netdb.h`).
* `ish/`: the shell C, the i386 syscall wrappers, `crt0.c`, and `ish/Readme.md` (the one in-house Readme never voice-normalized).
* Consistency fixes in the already-done work: the kernel files that kept plain `/*` headers or carry a surviving diary tag, the off-standard header banners, the one dev-log index that was missed, and a few stale doc facts.
* The leftovers a tree-wide sweep found: a non-ASCII byte the gate missed, diary tags in the run scripts, a prose em-dash inside a Makefile echo, capitalized script diagnostics, trailing whitespace, and the gate's own coverage gaps.

Out of scope (kept as-is, by policy or because it is not ours):

* The vendored trees: `libc/musl-1.2.5`, `busybox/busybox-1.36.1`, `dropbear/dropbear-2022.83`, `libc/install`, `krffs/vendor/` (termbox2), `krffs/vs-dokany/`, `rach2/vendor/multiboot.h`, and the whole `ports/doom/` port including its Readme.
* Behavior. This is a text-only refactor. Probe success tokens, the host seam-test exit-status contract, the `host-deps:` lines parsed by `tools/hosttest.sh`, every diagnostic message string and exit code in the utils and host tools, the inline-asm syscall numbers and ABI constants, the KRFFS on-disk format, and the build recipes all stay byte-for-byte.
* The kernel runtime boot log (`subsystem: event` strings), the verify-gate and `doctor` aligned-display layout, and the dev-log historical prompts and retired plans. These were settled in milestone 3.

## The standard

CLAUDE.md is normative. In short: the explanation lives in a Doxygen `/**` block before a non-trivial function (a one-line brief, then the contract and the non-obvious why, with `@param` and `@return` only where the meaning is not plain); trivial getters and thin wrappers stay bare. An in-body comment is allowed only for a one-line hardware or ABI fact or a deliberate hack, never restating the code or narrating a reasoning trace, and never a development-diary "Phase N" or "Part N" tag. Prose is ASCII, terse, in the Kernighan, Ritchie, and Stevens register, with no marketing. Docs are not column-wrapped, use `*` bullets, avoid bold, and use tables only for genuinely tabular aligned data. Messages from kernel and build tooling use the `component: detail` shape; user-facing program output (a utility's `Usage:` line, a probe's success token) is program behavior and is left exactly as it is.

## Method

The same discipline as milestone 3, and the same shape that suits ultracode: fan the work out one file or one small area per agent, with an independent adversarial-review pass over every result, then fix every finding.

* Each phase changes comments and docs only, never a code token. Prove it: a comment-stripped, string-aware token comparison of each edited `.c` and `.h` against HEAD must be identical (the throwaway `codeeq`-style script milestone 3 used; recreate it, it is a page of Python). A header banner, a `/**` header, a removed restating line, and a recast diary tag all leave the token stream unchanged.
* The kernel and the freestanding tests build under `-Werror`; the host tools and seam tests build with the host compiler; the utils and ish link against the ported musl. The relevant build must stay green, and `make verify-style` and `make verify-host` must stay green.
* A real boot, and the SSH capstone, are run where the touched code is on that path: the utils and the busybox and dropbear binaries are staged into the RAM disk and exercised by a boot, the krffs host tools build that RAM disk, and ish is staged as a guest program. The host seam tests and the freestanding probes are exercised by `make verify-host` and a boot that runs them.
* Each phase ends with a harsh independent Codex review with every finding fixed, then one scoped house-style commit with no attribution. Voice, which no checker can judge, is part of that review.

## The phases

Each phase is one logical unit and one commit. A large phase may split into two commits (noted) if that keeps each reviewable.

## What must not change (the contracts)

The review and the code-equal proof protect these; the plan names them so the work does not erode them.

* Every probe and musl-test success and failure token, verbatim, because the boot self-test and the harness read them as the contract: `VMPROBE OK`, `DEVPROBE OK`, `DIRPROBE OK`, `OFDPROBE OK`, `PIPEPROBE OK`, `POLLPROBE OK`, `PTYPROBE OK` and its parenthetical suffixes, `RNGPROBE OK (trusted)` and `(fail-closed)`, `SIGPROBE OK`, `TTYPROBE OK`, `WAITPROBE OK`, `COWPROBE OK`, `auxvprobe: ALL OK`, `MALLOC QSORT OK`, `CATFILE OK`, `PERMMUSL OK`, `MTTY OK`, and the rest, with their `FAIL` and count forms.
* The host seam-test contract: each `tests/host/*_hosttest.c` prints nothing and returns the failed-check count as its exit status; there is no `[PASS]`/`[FAIL]` token to add. The `host-deps:` line in each is a build contract that `tools/hosttest.sh` greps and feeds to cc; keep it literal.
* The inline-asm syscall numbers and the Linux i386 ABI in the freestanding tests, in `utils/resolv.c` and `utils/ping.c`, and in `ish/`: the `SYS_*` macros, the socketcall sub-call constants, `SC_PING = 0x1000`, the ioctl and termios constants, the register bindings, and the crt0 stack layout.
* The KRFFS v2 on-disk format: the magic `0x4B52`, the node-type order, the packed layout, `parent_id`, and the `krffs_mix_id` constant the host tools share with the kernel; and the dropbear staging contract in `stagetree.krffs.c` (`/etc/passwd`, `/etc/shells`).
* The freestanding and no-libc constraints (the `-nostdlib` links, the private statics in `resolv.c`, the `ISH_USE_STDLIB` toggle, the hand-rolled string and print helpers) and every build recipe and its flags.
* Every user-facing diagnostic string and exit code in the utils and the host tools, and the informal console output the legacy tests print and the Readme quotes.

## Verification gate, per phase

`make verify-style` and `make verify-host` green; the code-equal proof identical for every edited `.c` and `.h`; the touched component builds; a real boot and the SSH capstone where the touched code runs; and a harsh Codex review with every finding fixed before the commit.
