# Routine production and physical ownership

A selected routine site may need ordinary Linux production before native macOS or Windows preparation, or a physical Windows observer while WSL prepares and runs. `ETUDE_ROUTINE_ROUTE` identifies an installed descriptor for that route. The descriptor is stable across commits. Every invocation obtains the current clean commit from its checkout and transfers that exact commit; it does not install a candidate SHA in site configuration.

`etude run routine-sequence` constructs the fixed phase vectors for the existing native sequence owner. Case selection, scheduling and result judgement remain in the native collection and verdict readers. The native route client uses the existing `etude serve` framed command and file protocol. The remote C executor owns source staging and production and confirms cleanup. A successful SSH exit alone is insufficient. `etude prepare producer` invokes the ordinary public preparation and producer export, retaining its real admission result, artifact record and preparation receipt. Each invocation creates a new `RUN:producer` event; ordinary build caches may satisfy unchanged goals. An older producer receipt is never presented as new work.

The `macos-import` route produces and imports inside the normal admitted preparation interval. It retains its original producer cost and provenance. It uses ordinary Linux capacity admission and does not switch the physical PC's endpoint authority.

## Physical routes

The `windows-import` route has Linux production, native Windows preparation and native Windows collection. The `wsl-native` route has the original Linux preparation and collection only. It creates no second producer event. Both variants use one Windows native owner, one run and one physical grant through final cleanup.

Before a physical grant, the owner starts its sampler and waits for the first complete sample. The quiesce helper checks the configured Actions runners and their retained listener diagnostics. Every accepted job must have completed, apart from the exact coordinating workflow job. Missing diagnostics, an offline listener, ambiguous job identity or an unfinished job prevents the grant.

Each enrolled endpoint has an OS-native gate. Its normal launcher obtains that gate before reading the enabled policy and keeps it through its owned invocation. Direct admission and collection use the same gate through the actual shared ledger's filesystem identity. A stale site projection or ledger alias cannot bypass the installed authority. Unrelated private fixture ledgers remain independent.

The operator freezes each endpoint only while its gate is exclusive and its real ledger contains exactly the empty header. A durable blocked state is published before the endpoint is disabled. The owner then rechecks accepted jobs and both endpoints, publishes the shared physical block, and records the actual native grant reading. Windows and WSL do not share an assumed interoperable file lock. Their separate gates protect their own admissions; the fixed shared block prevents new normal claims during the final handover and restoration.

A phase capability has the exact run, commit, native owner PID and creation time, phase and private nonce. The original policy capacity remains the limit. The Linux producer's own admission ends and its cleanup is confirmed before Windows preparation starts. A direct WSL sequence retains its Linux clocks and identities, writes its preparation proof before collection, and waits for an acknowledgment carrying the physical owner's actual preparation-end reading. These clocks are never subtracted across operating systems.

The C owner enforces the purpose's existing work deadline from the physical grant. Caller loss, input-pipe loss, observer loss or an ownership error cancels the owned work. An uncertain cleanup leaves durable blocked state, disabled endpoint policies and the physical block. There is no unconditional restoration trap. Recovery requires independent native identity and ledger proof before the operator restores the exact retained policy bytes and access metadata.

After ordinary completion, both ledgers must be empty. The helper restores the original policy bytes while the physical block still prevents ordinary admission. The C owner finishes and reaps every owned Job, including the observer, then releases that block. Only afterward does it take the terminal reading and create `routine.completion.json`. This charge includes the observer cleanup. A separate in-owner sampler writes `physical-owner-load.jsonl`, starting before quiescence and the grant. It remains active through restoration, all child and observer Jobs, supervisor close and physical-block release. The owner joins its sampler, takes the actual terminal reading, and then takes synchronous native counters and writes the footer. Completion references this whole-owner trace. The earlier `observation_end` describes the unchanged child trace, whose context still owns its stop request. Missing terminal counters or incomplete coverage remains ineligible for comparison.

## First measurements of the routine route

The same installed route accepts `phase_first_run` only with the public allocator's preallocated `ETUDE_PHASE_SELECTION_EXPORT`. Its normalized selection bytes, hash and first-attempt set remain bound by the measurement context and native C collector. The physical owner reads that class's ceiling and cleanup reserve from the installed budget policy and cancels work at `ceiling_us - cleanup_reserve_us`. This bounds ownership; it does not change the existing validated first-run exempt verdict into a routine budget verdict. Preparation admission also retains the site's bound, capped at 86400 seconds. The ordinary `push`, `ci` and `release` classes refuse this exemption and keep their existing ceilings and cleanup reserves.

A comparison sample sets `ETUDE_PREPARATION_CLEAN=1`. The route passes that exact declaration to both fresh ordinary production and native preparation. Without it, a first diagnostic retains in-house products; this includes a focused seeded, repeated or loaded check. Release always requests clean preparation. Push and CI retain their existing behavior. Cleaning removes only the existing helper's declared in-house outputs under the preparation lock, retaining vendor builds, download caches and evidence.

Before fresh production or native compilation, the current native public allocator re-exports the same purpose's exact arguments and compares the complete export to the preallocation. A mismatch stops preparation. WSL retains the original Linux spelling and the verified Windows round-trip spelling of that same export, plus its SHA-256 and size, in `routine.request.json`. The native entry checks the run, commit, architectures, accelerator, selector and preparation declaration before returning the Linux spelling to the inner sequence. A changed request or selection is refused. This path introduces no alternate case selector.

Every imported comparison sample uses a new exclusive producer output and its own actual `RUN:producer` clean ordinary receipt. A retained producer is not made clean by cleaning the consumer. The importer still verifies the complete metadata, source, record, prepared inventory chains and every imported byte. The Mac observer charges its local interval, including remote production and transfer; the original producer's own receipt remains separate. The Windows physical lease spans producer, consumer and terminal cleanup on one native clock. No duration is subtracted across operating-system clocks, and one producer is not represented as five fresh workflows.

Five independent whole samples use five run IDs, the complete current both-architecture allocation and the same declared preparation/cache procedure. There is no extra whole run to establish a clean release cost. A successful first-measurement history can teach that cost only when the existing reader validates its exact clean receipt, producer provenance, node set and full observation. Failed or incomplete samples and all their outputs remain retained. This source support does not install a route, provide reference costs or establish a passing sample.

## Installed files

Installation is selected-site setup. No route is activated and no site value is chosen by the repository. The operator must provision protected parent directories and files writable only by the enrolled operator or the platform administrator. Both platforms' fixed bindings must exist before enabling this route:

* POSIX: `/etc/rach2/etude-authority`.
* Windows: `C:/ProgramData/rach2/etude-authority`.

A binding is strict LF-terminated text with its header and these nine unique fields:

    etude-authority 2
    ledger ABSOLUTE_REAL_LEDGER_DIRECTORY
    site ABSOLUTE_INSTALLED_VERSION_TWO_POLICY
    gate ABSOLUTE_NATIVE_GATE_FILE
    state ABSOLUTE_PRIVATE_STATE_FILE
    archive ABSOLUTE_PRIVATE_POLICY_ARCHIVE_DIRECTORY
    operator POSIX_UID_OR_WINDOWS_SID
    program ABSOLUTE_IMMUTABLE_ETUDE
    physical_block ABSOLUTE_SHARED_PHYSICAL_BLOCK
    route ABSOLUTE_PROTECTED_ROUTE_JSON

A binding of format 1, `etude-authority 1`, also has a tenth field, `launcher_body`, an absolute path that etude accepts and does not use. The gate is an existing protected regular file. The state and physical block must be absent when first provisioned. The archive is a private existing directory. The installed `tools/etude/launch.sh` is the enrolled wrapper: it runs `PROGRAM authority launch`, which takes the shared gate and runs `PROGRAM launch` under it. All normal installed shared-ledger entry paths must use the updated command and wrapper before enrollment. A partial deployment cannot establish physical exclusivity.

The POSIX policy publisher preserves owner, mode and extended access metadata before atomic publication. Windows preserves the original owner and DACL. An unsupported or inaccessible metadata operation fails before replacing the policy. The original bytes and policy snapshots remain evidence. Bindings, snapshots, route and the immutable command are checked for protected ownership and write permissions.

The descriptor is JSON with `format: "etude-routine-route"`, `schema_version: 1` and these required settings. All program and filesystem paths are absolute. No command fragments or arbitrary shell command strings occur in it.

* `mode`: `windows-import`, `wsl-native` or `macos-import`.
* `budget_policy`: the installed existing routine budget policy.
* `physical`: `etude`, `wsl`, `preparation_path`, `runtime_path`, and `linux_output_root`. The two PATH strings separate preparation tools from the declared runtime tools. Direct WSL OUT must be in the explicitly configured shared NTFS retention root, visible through its actual round-trip Windows path.
* `producer`: `transport` (`ssh`, POSIX `wsl-ssh`, or native Windows `wsl`), `host`, immutable Linux `etude`, fixed string `environment`, installed `site`, `policy` with actual `ledger`, `locks`, `capacity` and `seconds`, `account`, `preparation_resources`, existing Git `repository`, `tree_root`, `output_root` and `state_root`. Both WSL transports also have `distribution` and `user`. Windows import additionally has the verified `unc_tree_root` and `unc_output_root` corresponding to those Linux roots. The producer also has an `actor` descriptor with absolute local `path`, lowercase SHA-256 `sha256` and integer `size_bytes` for a retained immutable copy of that same installed Linux Etude. The descriptor and its bytes are required before route staging.
* `consumer`: actual native `env`, `account` and `preparation_resources`.
* `accepted_jobs`: actual Actions `repository` and a `listeners` object mapping every enrolled PC runner name to its retained diagnostic directory.

The fixed native route actions use this command:

    etude prepare route ACTION --config ROUTE --tree TREE --out OUT --run RUN --commit COMMIT --purpose PURPOSE --arches ARCHES --site SITE --etude ETUDE --accel ACCEL -- SELECTION...

ACTION is `quiesce`, `prepare`, `direct-setup`, `restore` or `ensure`. These operations retain the existing physical owner and observer. Consumer preparation is the existing native `prepare routine` invocation under its actual admission; the route does not implement another preparer.

The native remote wrapper retains the existing framed responder and sealed-program contract. The route checks the actor's complete bytes against its descriptor, stages them as `producer-etude` with mode 0755, and executes only `prepare producer operation.json` in the owned workspace. The installed `producer.etude` remains the responder and authority command. When the operation carries the actor descriptor, the producer compares its hash and size with that actual installed program. No script or arbitrary external program is substituted. Retain the original compiler and installation evidence with this ordinary external tool; changing the candidate does not relabel the tool's compilation.

For either physical route, native Windows preparation may select `producer.transport: "wsl"`. It starts the configured absolute `physical.wsl` executable with the existing distribution and user, then the same immutable Linux `etude serve --stdio` responder. This is a direct argument vector with retained stdin/stdout pipes; it starts no shell, SSH client or new owner. Mac, POSIX callers and nonphysical route modes refuse it. The SSH and POSIX `wsl-ssh` paths keep their existing framing and command construction.

Normal transport completion requires every framed attempt's successful result, complete streams and confirmed cleanup, the responder's `bye`, and the bridge's zero exit. On input loss the Linux C responder cancels and waits all active attempts before it returns. Closing a Windows client or seeing EOF is not independent cleanup proof. Failed framing, nonzero bridge status or unknown Linux identity/claim cleanup prevents a successful phase; the existing physical authority remains blocked when cleanup is uncertain. The existing separate endpoint/identity/ledger checks and exact restoration remain required. The bridge changes no installed account, authentication, policy or service.

The Windows importer remains the public `local` producer transport against the idle WSL UNC tree. It starts no unowned Linux copy process. It verifies the complete current producer metadata and record chain before copying portable files, then runs the actual native Make programs and inventories with bounded argument vectors. This route does not claim that the older cold Windows GNU tooling producer has passed.

## Retained result and acceptance

OUT is persistent and explicitly allocated by the retention policy. Direct WSL uses `linux.log` and `linux.sequence.receipt` for its inner sequence. The physical owner uses `log`, `sequence.receipt`, `physical-load.jsonl` and `physical-stop.request`. Native Windows uses its ordinary outer trace paths. Both physical modes additionally retain `physical-owner-load.jsonl` for the final native owner interval.

The immutable grant fixes the original native `routine.completion.json` pathname. `routine-completion.path` contains one caller-readable local absolute pathname, without rewriting the original locator in the JSON. The create-once completion binds the finalized `history/RUN.jsonl`, collector PID and creation time, phase results, ledger headers and complete observer proof. The normal collector's budget remains pending until this owner result exists.

After ownership ends, `etude prepare evidence pack OUT` copies the exact true proof closure by SHA and size into `routine-proofs`. It includes late finalized history, phase, ledger and observation proofs, follows recursive blob references and retains original locators. It does not copy compiler binaries or source files merely because provenance identifies their paths and hashes. Missing, ambiguous or changed proof bytes fail reporting. The routine verdict uses `--routine-completion` and `--routine-proofs`; it never executes a transported command.

Installation and first use remain acceptance work after a measured site is chosen. The mandatory selected-site push, CI report restoration and clean release must exercise the actual route, fresh current-commit production, confirmed phase transitions, purpose budget, retained proof closure and final empty ledgers. These are not replaced by a compiler result, a private imported run, or synthetic fixture measurements. Until enrollment and those ordinary entry runs pass, T95 remains unactivated. No installed policy, account, service or repository setting changes as part of the source implementation.

Mac import uses ordinary Mac admission, without a physical authority binding on the Mac. Its Linux producer must be enrolled. The Linux transport retains the enrolled authority boundary and starts the real admitted framed responder before uploading source. The responder forwards protocol input, preserves the original preparation grant, and releases its claim before the separate read-only cleanup check.

### Accepted jobs across listener restarts

The Linux producer records its actual kernel boot identifier and `/proc/stat` boot timestamp before and after each drain check. All retained listener files remain identified by path, size and SHA-256. Only events strictly before that boot are superseded; their original event lines remain in the proof. Current-boot events are replayed across all files, so a restart cannot discard an unfinished accepted job. Missing, malformed or future timestamps, missing current-boot log evidence, inconsistent completion and a changed boot prevent the grant.

GitHub runner online/busy state, every non-completed workflow status and the coordinating workflow's actual jobs remain required. Only its one exact in-progress coordinating job may be active. Both server snapshots must agree around log reconciliation; another accepted job or a changed server state prevents the grant. A new log filename or an idle server flag alone cannot clear an unfinished current-boot event. The existing endpoint gates and post-disable drain check still protect admission during handover.

The route client shares the ordinary C remote protocol implementation on POSIX and Windows. Its Windows transport starts through the existing Job supervisor, uses one borrowed input handle duplicated into the child, and retains its complete framed transcript. Standard output and error are verified separately while one complete operation log preserves their arrival order. A confirmed responder result and a zero-exit, fully reaped transport are both required; failed handshakes and abandoned connections cannot become successful phases. The native producer actor is a verified staged executable, subject to the responder's existing sealed-file checks.
