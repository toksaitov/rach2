# ext2 write batches across calls

This is the design required before implementation by [plan.md:237](plan.md#L237). No batch spanning calls is implemented here. Entry 49 measured six disk commands for a 4 KiB rewrite and twelve for an append. Removing the first of two inode stores reduced these to four and ten, and raised the measured rate from 494 to 911 KB/s. Those are the taken change's results, not a prediction for this design ([plan.md:86](plan.md#L86)).

The admission rule is fixed: admit only overwrites of allocated blocks and writes contiguous with EOF. Drain before a sparse write, a hole fill, or any namespace or attribute change. Bound the batch by bytes and pending inodes, with a separate metadata bound. Finish it at `fsync`, `sync`, close as defined below, and any bound. These rules apply to the whole mount ([plan.md:237](plan.md#L237)).

## Current contract

`ext2_write` opens the mount's batch, copies the range, calls `batch_end`, then updates size and times and stores the inode once. `batch_end` writes the recorded allocation metadata and syncs the cache. Thus the remaining inode store and cache writeback belong to each call ([ext2.c:2224-2272](../../rach2/sys/fs/ext2.c#L2224), [ext2.c:1127-1146](../../rach2/sys/fs/ext2.c#L1127)). The writeback contract allows repairable count, allocation and topology inconsistencies after interruption, but protects data outside the interrupted operation's range ([ext2.Readme.md:17-28](../../rach2/sys/fs/ext2.Readme.md#L17)). The batch must preserve that contract; it promises neither atomic overwrites nor an atomic commit of several files.

The cache's `first` and `after` marks order a bitmap before a pointer and no more. They do not order two `after` buffers, and direct `bcache_write` does not consult them. Sync writes the firsts before other buffers; a direct write checks the failure flag and calls `write_buffer` ([bcache.c:818-830](../../rach2/sys/fs/bcache.c#L818), [bcache.c:895-975](../../rach2/sys/fs/bcache.c#L895)). The marks cannot carry this design on their own.

There is no `bcache.Readme.md` in this tree. The cache contract is [vfs.Readme.md:59-71](../../rach2/sys/fs/vfs.Readme.md#L59). Its line 65 still describes new pointer-block zeros as `first`; the code writes those zeros through immediately, as the ext2 contract says ([ext2.c:1575-1599](../../rach2/sys/fs/ext2.c#L1575), [ext2.Readme.md:22](../../rach2/sys/fs/ext2.Readme.md#L22)). Use the code's order as the starting point.

## Ownership and admission

Decision: one batch belongs to a mount. Its states are empty, collecting, draining and failed. Give each batch a generation, a fixed pending-inode array, a data-block ledger, and private metadata images indexed by device block and role. A per-inode batch would still need coordination for shared bitmaps, descriptors and inode-table blocks. The current batch already belongs to `ext2_mount`, but records only sixteen allocation-metadata block numbers ([ext2.c:82-108](../../rach2/sys/fs/ext2.c#L82)).

On an inode's first admission, take one internal node reference and record its last committed size. Keep that reference until all of the batch's inode stores and final flush succeed, or until failed-device teardown discards the batch. It is independent of descriptor references and does not count as an external mount reference that would prevent unmount. Current lookup reuses the node on the mount's list; the last `put` frees it, including reclamation of an unlinked inode ([ext2.c:306-337](../../rach2/sys/fs/ext2.c#L306), [ext2.c:353-374](../../rach2/sys/fs/ext2.c#L353)). The new reference prevents close from destroying pending state and lets reopen find the same node.

The node's size, block map, block count and times are the visible state. Advance them only for bytes accepted into the batch. Reads, stat and subsequent appends use that state. Keep a separate committed size, advanced only after successful inode publication and its media flush. This is the last size known durable; an uncertain failed write may have persisted more. Today stat and read both use `n->size`, and indirect lookup reads pointer blocks through the cache ([ext2.c:589-620](../../rach2/sys/fs/ext2.c#L589), [ext2.c:643-663](../../rach2/sys/fs/ext2.c#L643), [ext2.c:384-438](../../rach2/sys/fs/ext2.c#L384)). Lookup and read must consult pending metadata and data images before the cache. Never serialize visible state merely to make it survive a lookup.

Admission is decided under the mount lock against visible EOF. An overwrite must end at or before EOF and every block it touches must be allocated in the visible map. An append must start exactly at EOF, including inside an allocated partial last block. If that partial block is a hole, treat the operation as a hole fill. A write starting before EOF and extending beyond it drains first and runs synchronously; this keeps the first admission predicate small. A file may contain older holes elsewhere. Writing into any of them drains first. Do not misclassify a missing indirect pointer as an allocated overwrite.

Sparse writes and hole fills use the same dependency rules in an immediately drained transaction; they never leave a batch open across calls. A hole below an already durable size needs data durable before its pointer is published, since size cannot protect it. The current allocator can dirty an indirect data pointer before `ext2_write` zeroes or copies that data, so the existing write path cannot simply be used unchanged as this fallback ([ext2.c:1634-1652](../../rach2/sys/fs/ext2.c#L1634), [ext2.c:2237-2249](../../rach2/sys/fs/ext2.c#L2237)).

## Serialization and bounds

Decision: hold the mount namespace lock through admission, copying and visible-state updates, and through the entire drain, including sleeps. Release it between collecting calls. A second writer joins the existing generation after taking that lock and rechecking the bounds and block map. A drain freezes the generation before its first I/O. Later writers wait and may start a new generation only after it completes. Recheck device and mount failure after every sleep and before accepting bytes; an eviction can fail during buffer acquisition ([bcache.c:639-656](../../rach2/sys/fs/bcache.c#L639)). The drain never acquires an open-description lock. Reads of pending maps and sizes must also use the mount lock so they cannot read a partly changed private image. The existing namespace lock is recursive for its owner and waits without interruption for another owner ([vfs.c:186-209](../../rach2/sys/fs/vfs.c#L186)).

Select an append's EOF under that same lock. Currently the syscall locks only its open description, reads EOF, then enters `ext2_write`, which takes the mount lock later. Independent descriptions can select the same offset ([syscall.c:696-714](../../rach2/sys/syscall.c#L696), [ext2.c:2193-2195](../../rach2/sys/fs/ext2.c#L2193)). Change every mounted descriptor path that can read pending state or mutate it to acquire the mount lock before the description lock, including read, write, seek and truncate. Audit every description-lock caller; changing write alone could leave an inverse lock order elsewhere. This agrees with the documented order ([vfs.Readme.md:41](../../rach2/sys/fs/vfs.Readme.md#L41)).

Decision: start with these hard limits, independent of cache capacity.

* 1 MiB of accepted user bytes per generation, counting repeated overwrites again, and at most 256 distinct 4 KiB data blocks. Retain each block's latest complete image, another limit of 1 MiB. The block limit also bounds many one-byte writes to different blocks. Eviction does not refund either charge.
* Sixteen pending inodes. Reopening or writing the same inode uses its existing slot. Failed records keep their slots; no new batch starts on a failed mount.
* Thirty-two distinct 4 KiB metadata images, at most 128 KiB, including allocation bitmaps, descriptor blocks, indirect blocks, inode-table blocks and a reserved superblock image. Shared blocks count once. Store the role and pointer depth with each image; inode records and the 256-entry data ledger are separate fixed arrays.

Reserve this workspace when a writable mount is constructed; allocation failure returns `ENOMEM` before publishing that mount. The image storage is 1152 KiB per writable mount, plus the fixed arrays and held nodes. Retained data images permit retry after a failed device flush even if cache buffers were cleaned and evicted; block numbers alone cannot do that. Do not allocate batch storage during a drain. The current constructor already returns `ENOMEM` for descriptor-table allocation failure ([ext2.c:3556-3562](../../rach2/sys/fs/ext2.c#L3556)). These initial limits bound copying, memory and inode lifetime without depending on cache size. No cache buffer is held between calls.

Use at most one data block as the admission piece. Plan its allocation and reserve all records before altering its data or visible map. A reserved pointer becomes part of the drain image only after its data block is fully initialized in a held cache buffer and copied to its retained image. Copy, dirty marking, installation of the reserved map and advancement of visible state must need no further allocation or I/O. On failure before that point, cancel the uninstalled reservation; never retry a pointer to uninitialized data. The allocator must see private bitmap changes, so two writers cannot reserve one block twice. Keep the existing whole-call space and reserved-block refusal before accepting bytes, using a bounded scan rather than a range-sized allocation; current checks occur before the batch starts ([ext2.c:2196-2227](../../rach2/sys/fs/ext2.c#L2196)). `ENOSPC`, `EFBIG` or a bookkeeping refusal before acceptance is a synchronous error, not a delayed writeback error.

If the next piece would exceed a limit, drain first and retry admission. Drain immediately upon reaching a limit. Split a larger call into pieces ending at block boundaries except the call's ends. If a piece cannot fit an empty batch, return `ENOMEM` before mutation; never overflow a ledger or write metadata through to evade its limit. The current sixteen-entry metadata list falls back to write-through when full; that fallback is explicitly replaced ([ext2.c:1084-1101](../../rach2/sys/fs/ext2.c#L1084)). If an I/O error follows acceptance of earlier pieces, return their byte count and latch the failure. With no accepted bytes, return the errno. This changes the current write path's error-only result on any failure ([ext2.c:2265-2272](../../rach2/sys/fs/ext2.c#L2265)).

## Drain protocol

Decision: keep changed allocation metadata and pointer blocks in private images; keep pending inode fields in held nodes. Leave their ordinary cache copies at the committed state while collecting. Update allocation counts in memory and consult the private bitmap images for further allocation. Data uses the ordinary cache and may be evicted early. Its new blocks were free before reservation and cannot be reused by another operation while this generation exists. Early data writes are safe because no new durable pointer names them.

Keep whole metadata images, preserving bytes outside changed fields. Reserve inode-table images but compose their pending inode fields only at publication. Today `inode_store` rewrites size, block count and every inode pointer even for an attribute change, and `bcache_write` writes the buffer's complete byte range ([ext2.c:1034-1068](../../rach2/sys/fs/ext2.c#L1034), [bcache.c:374-389](../../rach2/sys/fs/bcache.c#L374)). Private images prevent a direct write or eviction of another inode's table buffer from publishing those fields early.

Drain in this order. A completed stage means its writes and its media flush completed successfully, not merely that buffers became clean.

* Write allocation bitmaps and descriptor images. Complete their media flush. Allocation may become durable without a pointer, leaving a lost block after interruption.
* Write all remaining data and zeroing through cache sync, then flush the device. Initialize every new data block completely before making it dirty: preserve valid old bytes, copy accepted bytes, and zero the unwritten remainder of a fresh block. In an existing partial last block preserve the prefix and zero any newly exposed gap. Do not alter bytes outside the operation's range in an already allocated block.
* Write changed indirect blocks from leaves toward roots. Complete each depth's media flush before writing parents at the next depth. A new private pointer block starts entirely zeroed; its final initialized contents can be written once when all children are durable. This replaces the current immediate zero write without weakening its promise that a parent never exposes stale pointer contents ([ext2.c:1580-1599](../../rach2/sys/fs/ext2.c#L1580)).
* Persist any required superblock feature flag before the inodes needing it. Compose all pending inodes sharing an inode-table block into one image, preserving other inodes, and write each table block once. Flush before advancing committed sizes or dropping internal references. The current large-file flag likewise precedes the inode requiring it ([ext2.c:1059-1068](../../rach2/sys/fs/ext2.c#L1059)).

No stage places an ineligible image in the ordinary cache, even temporarily. An eligible image may be evicted or retried because all its dependencies are already durable. A cache run must contain only images eligible in the same stage. Require every metadata store, including error-state stores, to use this rule; assert that ordinary inode stores cannot run while collecting. Keep the complete private generation until the drain succeeds; cache residency and dirty bits are not its completion record.

`bcache_sync` issues writes, not a device flush. VFS adds `block_flush` after successful filesystem `fsync`, but that final flush is too late to order the drain's intermediate publications ([bcache.c:895-975](../../rach2/sys/fs/bcache.c#L895), [vfs.c:758-770](../../rach2/sys/fs/vfs.c#L758)). The drain must issue its own stage flushes. The drivers' write-through flush may not be removed for this speedup without a replacement keeping the same media promise. ATA waits for its flush; AHCI completes the request after its flush command ([ata.c:286-299](../../rach2/sys/block/ata.c#L286), [ahci.c:1133-1147](../../rach2/sys/block/ahci.c#L1133)).

## Close, errors and other entry points

Decision: close means final release of each open description, even if another independently opened description still exists. Closing one descriptor shared through `dup` or `fork` does not drain until that description's last descriptor reference goes. It is not the last inode reference. `dup` and `fork` increment the shared description's reference count; its last drop calls `vfs_desc_close`, which calls release and then puts the node ([syscall.c:3101-3109](../../rach2/sys/syscall.c#L3101), [syscall.c:6805-6818](../../rach2/sys/syscall.c#L6805), [fd.c:120-136](../../rach2/sys/fs/fd.c#L120), [vfs.c:673-684](../../rach2/sys/fs/vfs.c#L673)).

Make `ext2_release` drain the mount before dropping its handle reference. It currently only calls `ext2_put`; both release and the VFS close path return void, and `sys_close` has no filesystem error result ([ext2.c:638-641](../../rach2/sys/fs/ext2.c#L638), [vfs.c:673-684](../../rach2/sys/fs/vfs.c#L673), [syscall.c:2186-2194](../../rach2/sys/syscall.c#L2186)). Keep that interface. A failed release closes the description but keeps the batch reference and records the error. Last-node reclamation of an unlinked file must drain before freeing blocks, including when a temporary reference rather than a description was its final external owner.

Decision: store the first delayed errno, failing stage, block and generation in the mount, independently of nodes and descriptions. Any writeback or flush failure sets this record before making the mount read-only. Record device loss even when all data buffers are clean but metadata remains private. `fsync` on any inode of that mount returns the stored errno after attempting the frozen drain; a successful retry never clears the record. This conservative mount-wide report survives close, reopen and inode-number reuse without allocating an error history. Its lifetime ends at mount teardown, not at error observation. Persistence across reboot or a fresh mount is outside this in-memory error contract.

Today cache write failure keeps buffers dirty and makes the mount read-only, but the VFS notification retains no errno. `ext2_fsync` only syncs the cache, and `ext2_sync` returns success immediately on a read-only mount ([bcache.c:379-389](../../rach2/sys/fs/bcache.c#L379), [vfs.c:773-785](../../rach2/sys/fs/vfs.c#L773), [ext2.c:2164-2167](../../rach2/sys/fs/ext2.c#L2164), [ext2.c:762-776](../../rach2/sys/fs/ext2.c#L762)). Add persistent error recording to both cache-failure notification and VFS flush failures; do not let these early returns hide it.

On I/O failure after mutation starts, freeze all accepted state, retain private images and node references, and admit no later mutation. Cancel any uninstalled reservation by the admission rule. Retry the frozen generation from its earliest incomplete stage, rewriting that stage's images and completing its flush before advancing. Restore data from retained images, never by rereading an uncertain device. Bind the generation to the held device instance, not its registry slot, and forbid retry after `BLOCK_GONE`. Provide an internal cache write entry for this retry under the mount's drain ownership; it may bypass `BLOCK_WRITE_FAILED` only for the frozen generation. Ordinary `bcache_write` must retain its existing refusal ([bcache.c:824-830](../../rach2/sys/fs/bcache.c#L824)). Keep current drain status separate from the historical errno: completed retries allow teardown, but every later `fsync` still reports the first error.

The remaining entry points have one rule each.

* `fsync` and `sync` take the mount lock and drain the whole batch, including other pending inodes. `sync` then stores summary counts. Periodic sync uses this same path: `/bin/update` calls `sync` every thirty seconds, while VFS currently ignores individual sync results ([update.c:12-17](../../utils/update.c#L12), [vfs.c:805-823](../../rach2/sys/fs/vfs.c#L805)). Keep the syscall's result convention, but record errors before it discards them. A low-rate writer therefore drains periodically without a new kernel timer.
* Drain before changing any attribute or namespace state on the mount, including set-id clearing caused by a write, explicit timestamps, create, link, unlink, mkdir, rmdir, rename and truncate. If the drain fails, do not begin that change. Current `setattr` stores the entire inode; rename stores the source's raised link count; truncate stores a smaller size before removing pointers ([ext2.c:2069-2088](../../rach2/sys/fs/ext2.c#L2069), [ext2.c:2786-2793](../../rach2/sys/fs/ext2.c#L2786), [ext2.c:2123-2147](../../rach2/sys/fs/ext2.c#L2123)). A change to an unrelated inode drains too, since its metadata buffer may be shared. Never merge that change into a collecting generation.
* Before freeing blocks, finish all older writes aimed at them. Truncate and unlink use the drain before their existing pointer-removal order; last-reference reclamation does the same. The current removal writes a cleared pointer before freeing its block, and unlink may defer reclamation to the last holder ([ext2.c:1469-1484](../../rach2/sys/fs/ext2.c#L1469), [ext2.c:2353-2375](../../rach2/sys/fs/ext2.c#L2353)). Drain any tail zeroing before a later operation frees that block. A failed mount cannot free or reuse blocks.
* A timestamp that a read decides to store is an attribute change and drains first. Current ext2 reads do not store atime: the syscall advances its offset, the VFS wrapper delegates, and ext2 reads bytes without a timestamp update ([syscall.c:2757-2764](../../rach2/sys/syscall.c#L2757), [vfs.c:726-731](../../rach2/sys/fs/vfs.c#L726), [ext2.c:643-663](../../rach2/sys/fs/ext2.c#L643)). Do not add an atime policy as part of batching.
* Executable loading reads the visible pending map through the ordinary read path; its handle release drains by the close rule. There is no retained file-backed executable mapping to own a batch today: exec loads through `vfs_read` and releases the handle after `elf_load_image`, and file-backed `mmap2` returns `ENOSYS` ([syscall.c:5785-5803](../../rach2/sys/syscall.c#L5785), [syscall.c:6540-6552](../../rach2/sys/syscall.c#L6540), [syscall.c:12069-12070](../../rach2/sys/syscall.c#L12069)). Keep those semantics. A future file-backed mapping must hold its own inode reference and enter the same mutation and drain rules; this design grants no independent mapping writeback path.
* Drain the backing mount under its lock before publishing a loop attachment, then revalidate its size and busy state. Current attach opens and checks for an in-flight description but does not sync pending state ([loop.c:427-478](../../rach2/sys/block/loop.c#L427)). Keep each loop write followed by backing-file `fsync`, so an upper-volume stage cannot complete with bytes merely collected below ([loop.c:115-161](../../rach2/sys/block/loop.c#L115)). A loop-backed ext2 volume can collect its own calls. Drains proceed only down the backing chain, with no cache buffer retained across calls; cache acquisition already enforces that direction and a four-buffer hold limit ([bcache.c:284-315](../../rach2/sys/fs/bcache.c#L284)). Use per-mount or per-call drain workspace, including pointer traversal scratch, because lower ext2 operations may run inside an upper drain.
* Normal unmount drains before setting the valid bit. A current drain failure leaves the mount active and references intact for retry; historical error alone permits unmount after a successful retry but keeps the volume invalid. The unmount caller must use completion status separately from the sticky `fsync` result. Current VFS unmount waits for operations, checks external references, then syncs, prepares, flushes and invalidates ([vfs.c:1830-1878](../../rach2/sys/fs/vfs.c#L1830)). Preserve that ordering. On device loss, record the error before discarding private state, wait for in-flight cache users to finish, and allow teardown without writes. VFS already skips writes for a gone device, and the cache marks held buffers for discard ([vfs.c:1839-1874](../../rach2/sys/fs/vfs.c#L1839), [bcache.c:978-1000](../../rach2/sys/fs/bcache.c#L978)). Notify ext2 even if the cache finds no dirty buffer. Never replay the old generation onto a replacement device.

## Seven acceptance obligations

These are required tests for the implementation, not results of this record. Start with `order_row_under`, whose single call crosses logical blocks 1035 and 1036, and its `publication_ok` replay; it already runs with sixteen and sixty-four buffers ([ext2_hosttest.c:1996-2089](../../tests/host/ext2_hosttest.c#L1996)). Start interruption tests with `matrix_rows`, which stops each sequence and checks its disk image, allowed repairs and preserved contents ([ext2_hosttest.c:2886-2984](../../tests/host/ext2_hosttest.c#L2886)).

Run every new ordering sequence both with sixteen buffers and with at least 512 buffers, verifying that the latter retains the full 256-block data batch and metadata. Cover calls on both sides of direct-to-single and single-to-double transitions, and a new leaf within double indirection. Seed free blocks with nonzero junk. Include partial EOF, an existing hole, two independent writers, a shared description, and two pending inodes in one inode-table block. Observe visible state between calls and durable state at every permitted interruption, including before the first drain write. Add bound tests just below, at and above each byte, inode and metadata limit, plus allocation refusals with earlier calls pending. Do not judge only the final inode or final pointer write.

Keep handles open between collecting calls. The current `write_at` helper opens and releases its handle around every write, which would drain each call under this design ([ext2_hosttest.c:1132-1143](../../tests/host/ext2_hosttest.c#L1132)). Merely replacing its large write with many calls would prove no batch spanning calls.

* Data and zeroing are durable before a size exposes them. Extend the write at [ext2_hosttest.c:2032](../../tests/host/ext2_hosttest.c#L2032) into separate collecting calls, and extend [ext2_hosttest.c:2072](../../tests/host/ext2_hosttest.c#L2072) to replay durable inode sizes, block counts, data and zeros as well as pointers. Check a partial last block and all boundaries above. Add hole-fill interruption cases to [ext2_hosttest.c:2922](../../tests/host/ext2_hosttest.c#L2922), where an unchanged durable size makes pointer publication the exposure.
* No publication bypasses the drain through `setattr`, rename or truncate. Extend the same publication replay and interruption matrix with each operation between collecting calls, including read-derived timestamp requests and set-id clearing. Use two pending inodes sharing a table buffer, then mutate a third inode in that buffer. Verify that all dependencies precede the first changed attribute or directory record; an injected drain failure leaves that operation unstarted.
* No stale write reaches a reused block. Extend the interruption matrix with collecting writes followed by truncate or unlink, final reference release and immediate allocation of the freed blocks to another file. Include a dirty truncate tail, indirect-block reuse and both close orders. Run eviction and sync after reuse and compare the new owner's bytes. Extend the dirty-victim row at [bcache_hosttest.c:450-462](../../tests/host/bcache_hosttest.c#L450) to prove that neither an old buffer nor an old private image can later overwrite that owner.
* Dirty inode state survives close. Extend `order_row_under` and `matrix_rows` with open, several writes, release, reopen and `fsync`, both with success and a failure during release. Test `dup`, `fork`, independent descriptions and an unlinked inode with a final non-description reference. Assert the chosen close boundary, node identity, visible size, retained batch reference and eventual reference release. Exercise the real descriptor path or an equivalent linked host harness; calling `OPS->put` alone does not prove close semantics.
* Eviction, sync, unmount and device loss retain dependencies. Extend the `first`/`after` eviction and sync rows at [bcache_hosttest.c:464-521](../../tests/host/bcache_hosttest.c#L464) and the sleeping-sync row at [bcache_hosttest.c:893-910](../../tests/host/bcache_hosttest.c#L893). Pause every drain stage, attempt a second writer and a namespace change, then resume; neither may mutate the frozen generation. Add periodic sync, memory reclaim, unmount retry, loop recursion and device removal with clean data but private metadata pending. Check that held buffers are not reused and that teardown never marks an incomplete volume valid.
* Delayed errors remain observable at `fsync`. Extend the matrix and the failed-writeback row at [bcache_hosttest.c:524-534](../../tests/host/bcache_hosttest.c#L524). Fail each allocation-metadata write, data write, pointer depth, feature-flag write, inode-table write and each intervening or final flush. Include failures after some accepted pieces and after one of two inode-table blocks succeeds. Close, reopen, retry successfully, and call `fsync` twice; both calls must still report the original error. Test an empty cache and a read-only mount so dirty bits cannot supply the answer.
* Media order is preserved, not merely submission order. Extend the replay at [ext2_hosttest.c:2072](../../tests/host/ext2_hosttest.c#L2072) and the late-`first` row at [bcache_hosttest.c:893-910](../../tests/host/bcache_hosttest.c#L893) with separate submitted, completed and durable device images. Delay and reorder persistence until a flush completes; stop before and after each flush and replay each durable prefix. Test direct `bcache_write` and multi-block cache runs. Assert stage completion against durable contents. In the volatile-device model, removing a stage flush must fail that assertion; separately remove a write-through driver's flush and require its returned-write durability check to fail.

The present ext2 host device writes directly into the image file, its failure notification is a stub, and its namespace lock stub does not block a competing owner ([ext2_hosttest.c:115-137](../../tests/host/ext2_hosttest.c#L115), [ext2_hosttest.c:187-215](../../tests/host/ext2_hosttest.c#L187)). Replace those limitations in the new rows with controlled scheduling, real error recording and a volatile device model. Otherwise neither two-writer exclusion nor media order is proved.

Prove each new fault check by making it fail with the corresponding change removed and pass after restoration. Keep the taken single-inode-store change's command-count and interruption proof separate. The implementation must also pass `tests/run ext2` and `tests/run queue` unchanged, then measure command counts, flush counts and write rates on the machine, as [plan.md:237](plan.md#L237) requires. Rewrite the ext2 writeback contract when the implementation lands; this record does not change the running contract.
