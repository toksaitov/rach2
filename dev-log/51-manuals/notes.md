# Milestone 51: notes

## Where the work stands

In progress on 2026-09-19.

## Phase 1: the reader and the pipeline

* `mandoc` is on both hosts (1.14.6 on the testing host). Its ascii output marks bold and underline with backspace overstrikes; `man/render.sh` removes them with `sed` on a literal backspace, so the pages need no `col` on the host or the machine. The page's `.Os` is left empty and the renderer is given `-I os=Rach2`, so every page names the system once. `mandoc -T lint` reports its own STYLE notes on a legacy date form and an explicit `.Os`, so the pages use `.Dd Month day, year` and a bare `.Os`, and the lint runs at the warning level.
* BusyBox's `man` searches `/usr/man` and `/usr/share/man` without a `man.conf`, and looks for `catN/NAME.N` before `manN/NAME.N`; the images stage `build/man/catN` under `/usr/share/man/catN`. When its output is not a terminal it runs `col -b -p -x`, which the images provide as a script that copies its input.
* The proof, `tests/run man`, boots os-real, logs in, and reads `rach2(7)` through a pipe, compared with `cmp` against the staged page, and on the console under `less`, whose first line and, after `G`, last line are expected; 16 s on the Mac. The suite's expects are the page's own first and last lines, escaped for the harness's regular expressions.

## Phase 2: the pages a student meets first

* Seventeen sheets were written here from the source, then the pages by Codex in three write-enabled units of five or six pages each (a unit without `--write` writes nothing: its sandbox refuses the file, and the first round returned findings and no pages). Each unit answered with the sheet claims it could not place or found contradicted, with file and line, and every page was read here against its sheet and the rendered text.
* Codex's readings corrected the sheets in twenty places and the installer reference in four, among them: exFAT is read and written (`exfat.c` constructs a writable mount; the kernel Readme's "read" was stale and is corrected in the same commit); the recovery init is `init-recovery`, a shell on the console with no login and SSH only when a key was built in, checking `/dev/disk0p1` to `p4` under `rach2.fsck`; login closes descriptors 3 to 15 and takes an over-long name as a blank line; su reports an unknown user before asking a password; os-simple and test install ISH as `/bin/sh`; the loop file's unlink and rename refusal holds on the memory root only; growroot's repairing check accepts statuses 1 and 2 and a logical partition after the entry stops the growth; the installer's archive is removed before the new one is renamed, empty homes are made for uids of 1000 and over under `/home`, and `stop`, `STOP`, `Stop`, `quit` and `q` all stop the confirmation.
* os-real and the metal disk stage `cat1`, `cat7` and `cat8`; `tests/run man` reads all seventeen pages through the pipe on os-real, 18 s on the Mac.

## Phase 3: the kernel's interfaces

* The 54 section 2 sheets were generated here from the handler comments of `rach2/sys/syscall.c` (`sheets/syscalls.md`, 120 registered calls and 16 socket operations, grouped into families with an alias for every member), and the pages written by Codex in nine write-enabled units of six, each told to read the handler for what its comment does not say. Every unit answered with the sheet claims it found contradicted, with file and line; each was checked here against the code.
* Those answers found sixteen handler comments that described an older kernel, among them fchown as a no-op, execve copying into static buffers, fcntl's flags stored and not enforced, chdir limited to KRFFS, getpeername for streams only, a system call running with interrupts off, and unlink's bare refusal reaching userspace as EPERM. Each comment is corrected in the kernel and in the sheets that copied it, in commits of their own. The pages were written from the code, so none carried the stale claim.
* One kernel fault: a send on a stream this end had shut down failed with EPERM, since the dead-connection helper answered -1 when no reason was recorded, and a nonblocking read of the same socket did the same where the blocking read answered the end of input (entry 107). Fixed with a row in `tests/loopprobe.c`, proved by the old socket code failing it.
* The devices in section 4 (bootlog, console, disk, loop, null, random) and the formats in section 5 (passwd, proc, sshd.conf) came in the same round. `make mancheck` reads the table `syscall.c` registers and the `#define SC_` operations, and after the pages it reports no registered call without a page; a helper macro with the same prefix, `SC_BE16(p)` and its kind, had been taken for an operation until the extraction was narrowed to numbered defines.

## Phase 4: every program

* The rest of `utils/`, Doom, Dropbear and the twenty BusyBox families were written by Codex from sheets gathered here: the project programs from their sources and the utilities Readme, the families from each applet's `//usage:` text with a line of facts on this kernel. The units' answers corrected the sheets in some thirty places, recorded in the sheets themselves as what the writing found: `nice` never runs its command, `flock` has no call to issue, `klogd` has no syslog call to read, `lspci` reads a `/sys` that is not there, and the like; the pages say so.
* Two vestiges came up on the way. The recovery image wrote a marker of its fixed address that nothing had read since commit `99b740e2` removed the menu pair it chose between, with the lease script removing it, `bootctl` defining its path, a drill row proving the removal and the disk builder substituting a static token set no entry carried (entry 108); all of it is removed. And `rescue-static`, staged on the recovery image, had no sheet; it has one and a page.
* Aliases for the shared names (`busybox`, `cc`, `col`, `dropbearmulti`, `umount`, `shadow`, `group`, `mmap`), and every cross-reference checked against the pages and aliases. The os-real and metal-disk images stage every section; the recovery image stages the `man/recovery` list, now with `netup(8)`, `man(1)`, `e2fsck(8)` and `resize2fs(8)`, and `tests/run man` reads its pages through the pipe in a second boot.

## Phase 5: the close

* `mancheck` runs as step 18 of `tests/run style`, proved by four mutations run through the suite: a page removed (reflash.8), a registered call's page removed (getrandom.2), an alias pointing at no page, and a page without its NAME section, each refused by name, and the tree restored between them. The manual rule is in `CLAUDE.md`'s Documentation section.
* The first full set on the host found the self-build suite five times slower and two suites broken by the manual's staging (grub's manifest comparison and procfiles' image size). The slowness was the manual's nodes on the KRFFS disk root against a page cache of 1024 frames (entry 110): the alias files went first, replaced by a reader script and an alias table, then the page cache was doubled, and the suite runs in 156 s.
* Codex's review, three code units and twenty-one proofreading units of six pages each, two at a time. The code units found the socket fix incomplete (a never-connected stream now answers ENOTCONN, a shutdown one the end of input, blocking or not), the checker taking helper macros for socket operations and skipping list continuations and the bracket applets, the renderers publishing a failed render, and comments in six files describing the removed menu pair and recovery's old partition. The proofreading corrected some two hundred claims across the pages, most of them what an applet or a call cannot do on this kernel, and found the sealed root without its periodic sync (entry 109).
