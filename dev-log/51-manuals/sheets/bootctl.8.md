# bootctl(8)

NAME: bootctl - manage the boot partition of a machine nobody will open again. Source: utils/bootctl.c header, usage and messages; utils/bootverb.c; utils/Readme.md "Boot and recovery programs".

* SYNOPSIS, the exact forms: `bootctl status`, `bootctl kernel FILE`, `bootctl config FILE`, `bootctl grub FILE`, `bootctl commit`, `bootctl trial ENTRY`, `bootctl cancel`, `bootctl fallback`, `bootctl env KEY [VALUE]`, and `bootctl --target PARTITION COMMAND ...`, which acts on the named boot partition (a node such as `/dev/disk0p1`) instead of `/dev/bootpart`; `grub` and `commit` are refused with `--target`, since they act on the booted disk. A wrong operand count is a usage error.
* `status`: what is installed, committed and booting next: the four files' sector extents (`bootctl: NAME: first sector N, N sectors in N clusters, ...`), the environment block's keys (`saved_entry`, `next_entry`, each `VALUE`, `empty (a trial was consumed)`, `empty` or `absent`), and `booted: candidate | fallback | recovery, from the recovery partition and neither slot | not from a slot (no rach2.slot= on /proc/cmdline)`; `boot.cfg: absent` on a disk built before the menu slot existed. The extent lines' field order is a test contract.
* `kernel FILE`: validates the file and the fallback kernel, writes `saved_entry=fallback`, writes the candidate slot and reads it back byte for byte, sets `next_entry=candidate`: exactly one reboot tries the new kernel and a power cycle after a crash returns to the fallback; prints `installed: N bytes in the candidate slot; the next boot ...` and `run bootctl commit after the new kernel boots`. Refusals: a file that does not open or read, one larger than any slot, a boot not from a kernel slot.
* `commit`: makes the booted trial the saved default; only a machine running the candidate may commit (`only a machine running the candidate may ...`); prints `committed: the candidate is the saved default`.
* `trial ENTRY`: arms one boot of `candidate`, `fallback` or `recovery` (`not a menu entry this disk has` for any other name); `cancel` removes `next_entry` (`cancelled: the next boot takes the saved default`); `fallback` writes the committed candidate into the fallback slot and reads it back (`run bootctl trial fallback to boot it once`).
* `config FILE`: writes the boot menu GRUB reads after its stub entries, into the fixed menu slot, verified; the stub defines every entry the machine needs before the staged file is read, so a damaged menu leaves a bootable machine; refusals: empty, larger than the slot (`N bytes and the menu slot has N`), no menu slot.
* `grub FILE`: replaces the i386-pc GRUB core image through `/dev/grubcore`: 2 to 1024 sectors, written and verified in the inactive gap tail, then LBA 1 switched; never sector 0; `no boot loader window (no /dev/grubcore)` otherwise.
* `env KEY [VALUE]`: reads or sets `saved_entry` or `next_entry` only (`not a key this tool writes`); a value may not carry control characters; an empty value is the marker a trial boot leaves and is refused; only the three entries may be set.
* Requirements: `/proc/cmdline` with `rach2.slot=` before installing and `rach2.slot=candidate` before committing; `/dev/bootpart`, root only; a partition that is not a boot partition is refused with its name and the reason (a first sector that does not read; no FAT signature), and `--target` runs are told which partition is the machine's own.
* EXAMPLE: from the project Readme: `bootctl kernel /tmp/kernel`, reboot, `bootctl status && bootctl commit`. `tests/run install`, `menu`, `grub` and `bootpart` run every verb.
* SEE ALSO: recovery(7), disk(7), rach2-install(8).
