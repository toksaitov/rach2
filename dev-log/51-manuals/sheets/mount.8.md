# mount(8)

NAME: mount, umount - attach and detach a file system. BusyBox's applets over this kernel's `mount(2)`; sources: BusyBox util-linux/mount.c and umount.c usage; rach2/sys/fs/vfs.c vfs_do_mount; rach2/sys/block/Readme.md.

* BusyBox mount as built (rach2.config): `mount [OPTIONS] [-o OPT] DEVICE NODE`; `-a` mount all of `/etc/fstab`, `-f` dry run, `-v` verbose, `-r` read-only, `-t FSTYPE`, `-T FILE` a table other than fstab, `-O OPT` with `-a`; `-o` options: `[a]sync`, `[no]atime`, `[no]diratime`, `[no]relatime`, `[no]dev`, `[no]exec`, `[no]suid`, `ro`, `rw`, `remount`, `bind`, `move` and the rest of BusyBox's list; `LABEL=` and `UUID=` sources through blkid (`FEATURE_MOUNT_LABEL`); no `-o loop` (the loop feature is not built: attach the file with loopctl(8) first); no helpers, no mtab. `mount` with no arguments prints `/proc/mounts`.
* This kernel's mount(2): effective uid 0 required. Types: `vfat`, `exfat`, `ext2`, `krffs` (`devfs` and `proc` are the two synthetic mounts the kernel places itself). An unknown type: ENODEV. Flags honoured or recorded: ro, nosuid, nodev, noexec, noatime, nodiratime, relatime, silent; any other flag, `remount`, `bind` and `move` first among them: EINVAL. The target must be a directory (ENOTDIR), not the root of the root file system (EINVAL), not the root of a placed mount (EBUSY, it is a mount point already); a path of 256 or more bytes: ENAMETOOLONG. The source is a partition node `/dev/diskNpM`, a whole disk `/dev/diskN` (a stick with one volume and no table), a loop device `/dev/loopN`, or `/dev/bootpart`; the source's sector range is claimed for the mount's life, and a write-capable descriptor open on a window over it, or a mount already on the range, answers EBUSY. A device attached read-only (loopctl -r) mounts read-only whatever was asked. The kernel records the options it honoured in `/proc/mounts`, six fields in fstab's shape.
* umount: BusyBox `umount [OPTIONS] FILESYSTEM|DIRECTORY`; the kernel answers EBUSY while a file on the volume is open or a loop device stands on a file of it, and drains operations in progress before the mount goes. A stick pulled while mounted: the mount can be taken down, its unwritable buffers dropped.
* EXAMPLE: `mount -t vfat /dev/disk0p1 /mnt`, `mount -t ext2 /dev/loop0 /mnt` after loopctl, `umount /mnt`. `tests/run mount` and `tests/run fatwrite` run them.
