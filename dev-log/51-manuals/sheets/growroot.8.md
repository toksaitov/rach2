# growroot(8)

NAME: growroot - grow a root partition and its ext2 file system into the free space after it. Source: utils/growroot.c header and main; utils/Readme.md "Boot and recovery programs".

* SYNOPSIS: `growroot MBRID=ID,N [--measure]`. Anything else: `usage: growroot MBRID=ID,N [--measure]`, exit 2.
* The partition is named by identity, the disk's MBR signature (hexadecimal) and the entry number, as `rach2.root=` names one; the entry must be a primary one (`the entry is not a primary one; only entries 1 to 4 grow`); the signature must match exactly one disk (`ambiguous: more than one disk has that signature`; not found is reported too). The space it grows into is what lies between its end and the next entry's start, the disk's end, or the MBR's reach of 2^32 sectors, whichever comes first; a logical partition after the entry stops the growth altogether, since its records lie where the grown entry would write; a partition already at that size is left as it is; nothing is moved and nothing else is touched.
* Steps in order (utils/growroot.c, the grow function): the entry rewritten with the new count (requires the recovery kernel, the one that lets a whole-disk node take writes; the refusal is reported as what it is), the kernel asked to read the table again (`BLKRRPART`; refused while the disk is in use, reported; `the table read again does not show the new size` when it does not), `e2fsck -f -n` on the volume, a read-only check whose nonzero status stops the run (`e2fsck -fn status N; repair it first, since a repair ...`), then `e2fsck -f -p` (a status other than 0, 1 or 2: `e2fsck status N; the volume is not grown`), then `resize2fs` to the partition (`resize2fs status N`). Each step is announced: the table change as `growroot: entry: NODE from N to N sectors`, the checks as `growroot: check: ...`, the resize as `growroot: grow: ...`. A run stopped after the first step finds the entry at its size and does the rest; a volume left damaged is not repaired by this tool: the read-only check stops it and says to repair first.
* Memory: a machine with less than 7 MiB `MemTotal` is refused by name before anything is read, since e2fsck and resize2fs keep the bitmaps in memory (the figure measured at milestone 47).
* `--measure` records monotonic microseconds and `/proc/disk`'s command and flush counts around the table change and the resize, for the record.
* Every refusal is `growroot: WHAT: DETAIL` on stderr, exit 1.
* EXAMPLE: `growroot MBRID=1acef00d,3`, which the installer runs when asked to grow the root; `tests/run grow` runs it on the small rehearsal disk.
* SEE ALSO: rach2-install(8), disk(7), resize2fs(8), e2fsck(8).
