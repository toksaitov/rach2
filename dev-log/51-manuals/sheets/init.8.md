# init(8)

NAME: init - process 1: the reaper of orphans, the console session and the services. Source: utils/init.c header and the Readme section "Init and account programs"; utils/programs.mk (the four builds).
* One source, four builds, staged as `/sbin/init` by the image manifests: `init-shell` starts `/bin/sh` on the console (os-simple's test images), `init-login` starts only `/bin/login` and has no shell fallback compiled in, `init-metal` is the login plus a supervised Dropbear (init-metal also configures the network with netup(8)'s job on a `rach2.ip=none` boot), `init-recovery` is the metal build without the console login, a shell on the console instead, with the recovery duties (rach2.fsck: `e2fsck -p` first on each of `/dev/disk0p1` to `/dev/disk0p4` whose superblock has the ext2 magic, recorded as `init: e2fsck: /dev/disk0pN: status S`).
* What every build does: clears one level of `/var/run` at boot, reads `/etc/rach2/limits` and sets the limits on itself before any child (limits(7)), starts `/bin/update` and keeps it running, reaps orphans, continues stopped children, respawns the console session (with a pause so a failing login does not spin), and translates SIGUSR1, SIGUSR2 and SIGTERM into halt, poweroff and restart (BusyBox's mapping). The services get `/dev/null` on standard input and `/var/log/services` on standard output and error, a log that is emptied in place at 256 KiB with a line saying so, checked every minute, and unlinked at boot when it is already that large; a service gets `/dev/null` for its output where the log cannot be opened, never the console; the console belongs to the login from the start, and the kernel stops writing to the screen then (bootlog(4)). It never exits: the kernel panics if init dies. The SSH server is started without `-g` only when sshd.conf(5) says so.
* FILES: /etc/rach2/limits, /etc/rach2/sshd.conf, /var/log/services, /var/run.
* SEE ALSO: login(1), halt(8), update(8), limits(7), sshd.conf(5), recovery(7).
