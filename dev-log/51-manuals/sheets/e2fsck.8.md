# e2fsck(8)

NAME: e2fsck - check and repair an ext2 file system. Source: vendor/e2fsprogs/e2fsprogs-1.47.4/e2fsck/e2fsck.8.in (the upstream page, GPL-2.0, which the page adapts), vendor/e2fsprogs/build_e2fsprogs.sh, vendor/e2fsprogs/patches/, krffs/manifests/rach2-recovery.manifest, utils/growroot.c, utils/rach2-recover, utils/init.c.
* The program is e2fsprogs 1.47.4's e2fsck, built static against the ported musl and staged only on the recovery image as `/sbin/e2fsck`; os-real and the installed root do not carry it. mke2fs, debugfs and the rest of e2fsprogs are not built: nothing on the machine formats or edits a volume by hand. Configured without NLS, TLS, uuidd, fuse2fs, e2initrd-helper, e2image, e4defrag, debugfs, MMP, backtraces and tdb; with libuuid and libblkid.
* SYNOPSIS as upstream: `e2fsck [-pacnyrdfkvtDFV] [-b superblock] [-B blocksize] [-l|-L bad_blocks_file] [-C fd] [-E extended_options] [-z undo_file] device`. The device is a partition node, `/dev/disk0p3`; the volume must not be mounted, and the recovery system mounts nothing from the disk it repairs. There is no journal on this system's volumes (ext2 only), so the journal recovery upstream describes never runs here.
* Options, each as upstream describes it: `-p`/`-a` repair automatically what is safe, ask nothing, exit 4 when a person is needed; `-n` open read-only and answer no to every question, so nothing is written; `-y` answer yes; `-f` check even a clean volume; `-c` run badblocks, which is not built, so the option fails; `-b superblock` and `-B blocksize` a backup superblock; `-C fd` progress on a descriptor (`-C 0` on the terminal); `-d` debugging output; `-D` optimize directories; `-E` extended options (`ea_ver=`, `journal_only`, `fragcheck`, `discard`, `nodiscard`, `no_optimize_extents`, `optimize_extents`, `inode_count_fullmap`, `no_inode_count_fullmap`, `readahead_kb=`, `bmap2extent`, `fixes_only`, `check_encoding`, `unshare_blocks`); `-F` flush the device's buffer cache first; `-k` keep the existing bad blocks list with `-c`; `-l`/`-L file` add or replace the bad blocks list; `-r` nothing; `-t` timing, twice for per-pass; `-v` verbose; `-V` version; `-z undo_file` an undo file. Take the description of each from the upstream page, shortened; the page need not repeat upstream's discussion of `-b`'s superblock locations.
* `-p` and `-n`/`-y` may not be combined (upstream). Without `-p`, `-n` or `-y` and without a terminal, e2fsck refuses to run interactively.
* EXIT STATUS, the sum of: 0 no errors; 1 errors corrected; 2 errors corrected and the system should be rebooted; 4 errors left uncorrected; 8 operational error; 16 usage error; 32 cancelled by the user; 128 shared library error (never here: static).
* This system's uses, each a fact the page states: init runs `e2fsck -p` on each of `/dev/disk0p1` to `/dev/disk0p4` with the ext2 magic when the boot line has `rach2.fsck`, and records `init: e2fsck: /dev/disk0pN: status S` (recovery(7)); `rach2-recover` menu entry 2 runs `e2fsck -f -n DEVICE` and, on a nonzero status, names `e2fsck -f -p DEVICE` as the repair without running it; `growroot` runs `e2fsck -f -n` and stops on a nonzero status, then `e2fsck -f -p`, accepting 0, 1 and 2, before `resize2fs`.
* What differs from Linux: the kernel's partition nodes are raw sector windows, so the library reads and writes whole 512-byte sectors at sector-aligned offsets, through its bounce buffer where a request is not already aligned (patches `raw-device-io.patch` and `buffer-alignment.patch`) and sizes the device with `BLKGETSIZE64`; `/etc/mtab` on the recovery image is an empty file, which e2fsck reads to decide whether the device is mounted, so a mounted volume is not detected by that file: do not run e2fsck on a mounted volume. No badblocks program is built or staged, so `-c` fails to run it. No `/etc/e2fsck.conf` is staged.
* FILES: /sbin/e2fsck; /etc/mtab (empty); /etc/e2fsck.conf (absent).
* EXAMPLES: from the project Readme, over SSH to a machine in recovery: `e2fsck -fn /dev/disk0p3`; `tests/run grow` runs the read-only check and the repairing one through growroot.
