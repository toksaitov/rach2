# growset(8)

NAME: growset - the block ranges an ext2 grow writes. Source: utils/growset.c header, utils/Readme.md "Boot and recovery programs".
* `growset [--save] [--ranges] [--lba START] [--map JSON] VOLUME SECTORS`: VOLUME a file holding the volume (an image, or the partition copied out of a disk), SECTORS the partition's size after the grow. It reads the superblock and descriptors, computes the geometry the grown volume will have the way resize2fs does, and prints one `range START COUNT WHAT` line per run of sectors the grow writes, sorted and merged, relative to the volume's start, or to the disk's with `--lba`, when the disk's first page, where growroot rewrites the entry, is in the set too; then `total SECTORS` and the geometry. `--save` also includes the full seed overwrite and requires the file's length to equal the superblock's block count. `--ranges` prints only the sector pairs. `--map JSON` checks QEMU's written extents against the set. The host tool of the recovery plan includes this source, so the plan and recovery use one calculation; the machine helper compares its list with the supplied ranges before saving or writing.
* EXAMPLE: `growset --lba 266240 root.ext2 471040`; `tests/run grow` runs it.
* SEE ALSO: growroot(8), growboot(8), recovery(7).
