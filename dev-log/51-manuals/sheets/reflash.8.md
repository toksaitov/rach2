# reflash(8)

NAME: reflash - write a stream onto a raw device, or read a range back and hash it. Source: utils/reflash.c.

* SYNOPSIS: `reflash [-p] [--verify] DEVICE OFFSET BYTES`. Exactly three operands; more or fewer, or an operand that is not a number: `usage: reflash [-p] [--verify] DEVICE OFFSET BYTES`, `'X' is not an offset`, `'X' is not a length`, exit 2.
* The image arrives on standard input; `ssh` is the transport: `gzip -c root.img | ssh rach2 'gunzip | reflash /dev/disk0 68157440 524288000'`. The offset and the length in bytes come off the machine: `/proc/disk` reports disk 0's partitions as `partN TYPE START_LBA SECTORS` and every disk's as `part N M START COUNT ID LABEL`, times 512. The length is declared, not discovered, so where the write lands is settled before a byte is read; a length of zero (`a length of zero writes nothing`), an offset or a length that is not a whole number of sectors, and a range past the device's end are refused before anything is read (offset 0 is a whole-disk write and is allowed); the stream must be exactly the declared length (ends early, or data past it: a failure with `N of N bytes written at OFFSET`).
* Copies in batches of 2048 sectors gathered from the stream's pieces. `-p` prints `reflash: N of N bytes, P%` on standard error every sixteen mebibytes and at the end.
* `--verify` writes nothing: reads the same range back and prints `reflash: sha256 HEX of N bytes at OFFSET` on standard output; short positive reads are gathered, and a read that returns nothing or fails is the failure `DEVICE stopped answering after N of N bytes`; with `-p` it reports `read N of N bytes`.
* Only a kernel built for recovery may write a whole disk or a partition node; on any other the device refuses (EPERM) and this reports the refusal, not a partial write: `cannot open DEVICE: ERROR`, `cannot measure`, `cannot seek DEVICE to OFFSET`, `... (DEVICE has N bytes)` for a range past the device, `DEVICE did not close cleanly`.
* EXIT STATUS: 0; 1 for a refusal or a failed transfer; 2 for a usage error.
* EXAMPLE: the sealed layout the project Readme gives: a 64 MiB FAT boot partition at byte 1048576, the 64 MiB recovery partition at byte 68157440 (sector 133120), the ext2 root at byte 136314880 (1 GiB); the recovery partition rewritten from the disk's recovery entry: `dd if=build/images/rach2-sealed.disk of=recovery.img bs=512 skip=133120 count=131072` on the host, then `gzip -c recovery.img | ssh -i $KEY root@ADDRESS 'gunzip | reflash -p /dev/disk0 68157440 67108864'` and `reflash --verify /dev/disk0 68157440 67108864`. `tests/run installer` runs the write and the verify.
* SEE ALSO: rach2-install(8), recovery(7), disk(7).
