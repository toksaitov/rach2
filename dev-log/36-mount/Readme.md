# Milestone 36: mount

The kernel has a mount table, a resolver every path goes through, and a file-system interface that two kinds of file system answer besides KRFFS: the two synthetic namespaces and a read-only FAT32 reader. `mount(2)` and `umount2(2)` place a FAT32 partition of the boot disk on a directory and take it away again, BusyBox's `mount` and `umount` work as they do on Linux, and the block layer under it all has one entry that sleeps its caller when a device is slow, which is what a USB disk will need.

## What was built

`sys/fs/vfs.c` is the mount table and the resolver. A mount point is the covered directory's held node, `..` is physical, and every path-taking syscall walks one component at a time through one `lookup`, with search permission checked once in the common layer for every type. The three permanent mounts are the root, `/dev` and `/proc`; the synthetic two take the rest of a path in one call because their namespaces are flat tables. The interface is a table of operations with NULL for what a type does not do, and the common layer answers the standard error for a NULL, so a read-only type is a type with half its table empty.

`sys/fs/fat32.c` reads FAT32 as Linux recognises it, whatever the cluster count: long names with their checksums, the short alias beside each, the active FAT, a chain walk bounded by the cluster count so a looped directory ends in `EIO` and not in a hang, a node pool that gives the VFS something to hold, and inode numbers no two entries share.

`sys/block/request.c` is the one entry every transfer takes. A polled device is called and done; a device that sleeps its caller is handed a request from a pool of sixteen, each with its own page, so a completion that arrives after the caller gave up lands in memory nothing else owns. A request is owned by its generation, and a late answer to an abandoned one frees the slot and advances the generation. `sys/block/lag.c` is the test device: `rach2.blocklag=N` wraps the boot disk for the partition nodes and the mounts, delivers each completion N ticks later and then once more with an error, and scrubs a read's page until the completion is delivered, so a kernel that accepted a stale answer or copied out early fails a boot.

`sys/fs/bcache.c` is the buffer cache under the mounted types, with Lions' five operations, a hold limit of four, one device at a time, ascending blocks, and a buffer keyed and held before its fill. `sys/fs/devfs.c` gained the four partition nodes and a claim table beside the raw windows' single-writer rule: a mounted range refuses the raw writer and the raw writer refuses a mount, compared on the disk under every view, which is how `bootctl` and a mounted boot partition exclude each other.

## What running it found

A dozen defects in what this milestone built were found by its own rows before the review and are recorded in `notes.md` phase by phase; among them a lag device that transferred inside the timer handler and hung the machine, a cache that filled one block into two buffers when two processes missed at once, a `creat` that refused every device node, a `mkdir` of the root that broke `mkdir -p`, and a suite whose FAT volume was sized to the image rather than the partition.

## What the review found

Eight review units read the milestone and returned about a hundred findings; every one is fixed or recorded with its reason in `notes.md`. The structural ones: a request slot a timed-out caller could still touch after its late completion freed it; claims compared by device pointer, which under the lag device let a whole-disk writer past a mounted partition; a cache hold rule that allowed a two-device cycle and a sync that reported success over a failed write; a mount in transition that the resolver stepped over instead of answering `EBUSY`; every lock wait spinning on a pending signal on a kernel that does not preempt inside a syscall; the generic arms of the namespace, attribute and exec syscalls that skipped the permission policy the root type keeps; an `open` that created or truncated before it knew the descriptor table was full; and a set of test rows that passed for a weaker reason than their names claimed. The review also cut the owner's concurrency limit for delegated reviewers from five to two, after the first round's token use.

## Verification

`tests/run mount` is eight boots on a disk whose second partition is a FAT32 volume written by mtools: the partition nodes and a read sleeping through the lag while its sibling runs; a device that never answers in time, quarantined and freed late; the root on the real disk beside the lag, named by `/proc/mounts`; a write copied before the device sleeps; `mountprobe`, which is `mount(2)` and `umount2(2)` from a program with every flag, busy answer, claim and `/proc` file, and an awk over the unmount records; the mounted half of `lagprobe`, with a rmdir during a sleeping constructor, a counted busy-buffer wait, a shared description handing each sector to one of two readers, and the whole-disk writer refused over the mounted range; the boot partition refusing the raw writer; and BusyBox mounting, listing, reading and unmounting the volume with the listing compared against `mdir` and the bytes against `mcopy`. `vfsprobe` and `dirtyprobe` run in the default boot. `tests/run host` runs `bcache_hosttest` and `fat32_hosttest`, the second over volumes a separate builder writes and a boot sector the test patches field by field. Thirty-four mutations were proved across the phases and the review, each caught by the row named for it in `notes.md`. `make test` is 250 seconds against 172 at milestone 35: the mount suite is in the core tier because it is this milestone's proof, and its eight boots run one after another inside one script, so at 102 seconds it is the pool's longest member and sets the pool's length. `tests/run mount` alone is 90 seconds.

A passing run proves the interface and the block path under QEMU: that the resolver, the descriptions, the working directory and the mounts keep their reference counts across every path the probes take; that a sleeping device is waited for, given up on, and answered late without touching reused memory; that a FAT32 volume written by another implementation reads back exactly. The USB disk that the sleeping path exists for does not exist yet, so the lag device stands in for it, and its timing is emulated timing. Nothing in this milestone ran on the Lenovo: the machine milestone is 43, and the boot partition it will mount is the one `bootctl` already writes.

`syscall.c` is 11603 lines against 11034 at the close of milestone 35. The lexical `..` step, the per-syscall classification of synthetic paths and the KRFFS walk predicate are gone, and the generic arms now carry the permission policy the review required; the KRFFS fast paths beside them are the weight that remains, and folding them into the generic arms is milestone 37's work, where the first writable type makes the generic arms the ones every file system uses.
