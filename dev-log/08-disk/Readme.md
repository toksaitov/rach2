# Milestone 8: KRFFS on a disk-backed page cache

KRFFS previously occupied a RAM-disk module loaded in full by the bootloader. The file system could not exceed the 32 MB of physical memory managed by the kernel, and its contents did not survive a reboot. This milestone implemented Path B of the plan: KRFFS moved to an arbitrary-size ATA disk while retaining its contiguous virtual window and `krffs_node_t *` ring traversal. The window is now demand-paged from disk, and GRUB boots the system from that disk.

## The design

Independent Codex passes reviewed the plan. The page cache and fault path were designed around the two invariants below before implementation. Each phase used an in-guest probe that reports a checksum failure when the data changes.

* Fixed cache and demand-paged window: KRFFS is mounted at `PCWIN_BASE` (`0xC0000000`). The cache contains `PC_SLOTS` (256) page frames, or one mebibyte, regardless of disk size. A reference to an absent window page faults. The handler finds or evicts a frame, fills it from disk, and maps it. A clock sweep performs eviction and writes a dirty victim before reuse. An open-addressed hash with tombstones maps pages to slots. Only the working set remains resident, so the bounded cache can read a file system much larger than RAM.
* Synchronous polling in the fault path: the page-fault vector is an interrupt gate, so the handler runs with interrupts disabled. It cannot block on a disk IRQ and reschedule. The ATA driver therefore uses polled PIO, and a busy `insw`/`outsw` loop fills the page. The fault is the single cache entry path and completes synchronously.
* Supervisor-only window mapping before the first fork: `clone` copies page-directory entries by value, so a window mapping installed after a fork would not appear in the child. Before proc0 forks, the kernel allocates the window's page tables and links them into the kernel directory once. Every address space shares those tables, and any fault services the same cache.
* Write-back, fsync, dirty-mount flag, and offline fsck: a read maps a frame read-only. The first write faults again, changes the mapping to read-write, and marks the slot dirty. `pc_sync`, used by `sync` and `fsync`, writes only changed pages and makes them read-only again. The mount sets `KRFFS_MODE_DIRTY` (`0004000`) in the KRFFS root. This value lies outside both `mode & 0777` and the `0170000` type mask, so stat and the directory test do not expose it. A clean `halt` clears the bit. If a later mount finds it set, the previous boot did not shut down cleanly; the host `fsck` repairs the file system and clears the bit.
* Three mount modes with the RAM module as default: without a command-line option, the unchanged RAM module remains the default so existing images and the test harness boot byte-identically. `rach2.fswindow` accesses the module through the window and exercises the cache without a disk. `rach2.fsdisk` or `rach2.root=disk` mounts a disk partition. A small MBR parser reads the first sector of each non-empty entry and accepts the first partition containing a KRFFS root.

## CR0.WP defect

The page cache tracks dirty pages by mapping clean frames read-only and handling the first write fault. The first integrity probe, `blockprobe`, wrote eight 256 KB files, or two megabytes, through a one-megabyte cache to force eviction. Data returned corrupt with both disk and stub backing. The kernel ran with `CR0.WP` clear, so a ring-0 write to a read-only page did not fault. The dirty bit remained clear, and eviction discarded the changes. Setting `CR0.WP` with `CR0.PG` when paging is enabled fixed the defect. Checksums detect this corruption; a probe that checks only whether the kernel survived does not.

## MBR validation and GRUB embedding

* KRFFS ring signature: the first MBR probe rejected a valid partition because it required `previous_node_size == 0`. That condition is true for a fresh image but false for a ring, where the root's previous pointer names the trailing free node. The probe now validates the 16-bit magic, root node type, and a nonzero size that fits the partition.
* GRUB installation on Docker overlay storage: the bootable disk is assembled in a temporary container, but `grub-bios-setup` cannot canonicalize the disk file's host device on an overlay mount. `tools/grub_embed.py` performs the installation directly. It writes `boot.img` while preserving the partition table, writes a contiguous `core.img` in the post-MBR gap, patches the same two pointers as `grub-bios-setup`, and rejects a `core.img` that would extend into the first partition. This manual path is outside the automated checks. `make os-real-grub-disk` runs only on demand, requires Docker, and installs unpinned `grub-pc-bin`, `grub-common`, `parted`, `mtools`, and `python3` packages from `ubuntu:24.04`. An upstream package change can therefore break it without failing a probe. The patched offsets (`0x5c`, `0x64`, `0x1f4`, `0x1fc`) are stable GRUB i386-pc ABI constants, so embedding does not depend on the package versions.

## Verification

Each phase uses a freestanding probe staged on a disk and checks its serial token. `blockprobe` round-trips a pattern through forced eviction. `persistprobe` writes and `fsync`s a file during one boot and reads it during the next, demonstrating durability across a power cycle. `crash_test.sh` shows that a killed boot leaves the dirty flag set and that `fsck` clears it, while a clean `halt` does not leave it set. `stressprobe` writes and re-reads 33 MB of files through the 1 MB cache with every checksum intact. This exceeds the 32 MB physical limit while keeping the resident set bounded. The complete boot path is BIOS, MBR, GRUB, and the Multiboot kernel from a disk partition. The kernel mounts KRFFS from the second partition (`File system... OK (KRFFS, 23 files) (disk)`), runs `/sbin/init`, reaches BusyBox ash, and passes the end-to-end SSH test with public-key authentication. `make verify-style` passes 8/8, `make verify-host` includes a cache-bookkeeping host test under ASan/UBSan, the module path passes `make test` at 28/28, and the module boot and end-to-end SSH test remain unchanged.
