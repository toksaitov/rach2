# Milestone 11: the post-AHCI audit

The AHCI milestone added 927 lines across fifteen files: a 669-line SATA driver, the block-layer interface that lets two drivers publish `block0`, three `kernel.c` integration points, and the AHCI test and run support. This audit checked the new code, the unchanged code affected by its integration, and the agreement among comments, Readmes, support files, and the `CLAUDE.md` style contract. It is the post-AHCI counterpart of `dev-log/09-audit`. Every candidate finding was checked by a separate adversarial verifier, most candidates were refuted, and Codex independently repeated each phase.

## The method

The audit had eight phases ordered by risk. During each phase, parallel Workflow auditors read one group of concerns, a separate adversarial verifier tried to refute every candidate finding, and Codex then read the phase independently. The maintainer reviewed the result after its required checks. The opening and closing phases, baseline and retirement, ran the full check set. Each of the six middle phases used a named exit token. The plan in `plan.md` came from a six-dimension survey of the code.

The independent Codex checks changed the result twice. In the HBA phase, Codex restored a finding that the parallel audit had refuted: a low ABAR used the cacheable identity map. In the command-path phase, it found a second defect that the parallel audit had missed: the completion check ignored a device-fault status. A process that relied only on the parallel audit would have missed both defects.

## What it found

The eight phases found eleven defects. Codex found four of them, including two during its final review of the audit's own fixes. The most severe defects were in hardware error paths that QEMU cannot reach and the passing probes do not exercise.

* The command path returned false success for two hardware-only error conditions. The completion poll watched only the task-file error bit (`PxIS.TFES`), so a fatal host-bus or interface error could clear `PxCI` without setting the task-file error. The post-loop check would then report a corrupt transfer as successful. It also tested the task-file `ERR` bit but not `DF` (device fault), so a completion with only `DF` also appeared successful. Both cases silently corrupt data on hardware and do not occur on QEMU. The fix checks the full fatal `PxIS` set during the loop and again after it clears, and tests `ERR | DF`. The same phase added port recovery (AHCI 6.2.2): stop the engine, clear the latched errors, and restart it. A failed command therefore no longer leaves the port unusable until a new `ahci_init`.
* A low ABAR used the cacheable identity map. Initialization mapped the ABAR cache-disabled only when it was above the 32 MiB identity-map limit. A controller may legally place its ABAR below that limit, although QEMU does not. Polling its status registers through a cacheable mapping could read old values. ABAR mapping is now unconditional.
* The debug commands re-probed a live disk. Entering `disk`, `disk write`, or `ahci` in the rescue shell repeated the full initialization, which stops every port, even when KRFFS was mounted from the AHCI disk. The re-probe stopped the port used by the page cache, and a partial failure left the port stopped under a live mount. All three commands now refuse to run while a disk mount is active.
* The kernel command line could match a truncated token. A command line longer than the 256-byte capture buffer could end in the middle of a token, causing the partial token to match a flag. For example, `rach2.disk=ahcix` truncated to `rach2.disk=ahci` would select AHCI. The capture now discards a partial final token.
* The support scripts had two verification defects. The source-list check printed `OK` and returned zero when `mktemp` failed, allowing a constrained environment to pass without comparing the lists. It now reports failure. The ATA and AHCI disk tests also shared image filenames, so running an ATA target and its AHCI counterpart under `make -j` could make both use one file. The AHCI targets now use separate images.

The audit examined the partial initialization state left by a failed probe and found it benign. An idle started port performs no DMA without a queued command, and the HBA MMIO range does not overlap the legacy ATA ports. The state was documented rather than changed. Both the parallel auditors and Codex also confirmed the DMA-buffer trust boundary, bounds checks, `--ok` token check, and `!user_mode` window check.

The documentation and style phase corrected two comments that contradicted the code. The self-test no longer claims to perform an IDENTIFY command, and the command issuer no longer says it "sleeps". The phase converted every AHCI function header to the Doxygen `/**` form used by the ATA driver, updated the block Readme with the audited error model, removed bold text from the dev-log, documented the AHCI test variants, and removed an unused include and macro.

Codex's final review found three more defects, two in the audit's own fixes. The new error-recovery helper would have restarted a command engine that refused to stop; it now reports failure. The driver had not checked the device's logical sector size although its comment and Readme said that it did; it now rejects a sector size other than 512 bytes. The third defect was the crash test's shared disk image, which now has its own filename. Finding a defect in an audit fix justified the final independent review.

## Verification

The full checks passed after every phase and again at completion: `make verify-style` at 8/8, `make verify-host`, the module-path `make test` at 28/28, and `make check-sources`. The ATA disk probes (`test-disk`, `persist-test`, `stress-test`) and AHCI disk probes (`test-disk-ahci`, `persist-test-ahci`, `stress-test-ahci`) passed their tokens. SSH and Doom ran over the AHCI-backed disk. The default RAM-module boot and legacy `if=ide` ATA boot remained byte-identical. Every change either reports a failure where the old code continued or changes text only, and AHCI remains inactive unless `rach2.disk=ahci` selects it. Vendored trees remained outside the diff.
