# Milestone 10: AHCI, the modern SATA half of the disk layer

The disk milestone lifted KRFFS onto a real ATA disk through a polled page-cache window and deferred AHCI, the interface most real hardware actually speaks. This milestone delivers it. AHCI goes in behind the same `block0` the ATA driver publishes, so the page cache, the demand-paged window, the MBR root-probe, KRFFS, the dirty flag, and fsck are untouched: they call `block0->read`/`block0->write` and never learn which driver answered. It is the storage analog of the audio progression. The PC speaker and SB16 stand beside the HD Audio controller as the readable bring-up drivers; ATA PIO now stands beside AHCI the same way, behind one block interface.

## The design

The plan was written and reviewed with an independent Codex pass before any code, and every phase was gated by a concrete in-guest token so a regression bisects to one phase. The load-bearing decision was settled first, because it decides whether the fault path changes at all.

* **Polled completion, no interrupt.** The page-cache window fault is delivered through an interrupt gate and runs with interrupts off; it cannot sleep, so it cannot wait on a completion IRQ. AHCI is normally DMA plus a completion interrupt, so the driver keeps the DMA and drops the interrupt: mask `GHC.IE`/`PxIE`, set the slot bit in `PxCI`, and busy-poll it clear while watching `PxIS.TFES` and `PxTFD.STS.ERR`, bounded by the same iteration watchdog ATA uses. The HBA does the transfer; the CPU spins on a memory-mapped bit. So `ahci_read`/`ahci_write` satisfy the block contract verbatim and drop into the existing fault chain with no change to the fault model, the cache, or the mount flow. The polled-vs-IRQ-vs-async trade-off, and why IRQ and async are deferred rather than overlooked, is recorded in `sys/block/Readme.md` so a future contributor starts from the analysis.
* **A second producer of `block0`, selected at the seam.** `block0`'s definition moved from `ata.c` to `block.c`, which owns the contract, and a thin `block_probe` chooses the driver: `rach2.disk=ahci` brings up AHCI (falling back to ATA if no HBA answers), and without the flag it brings up ATA exactly as before, so every existing IDE image boots byte-for-byte unchanged. The flag is whole-token, so it never collides with `rach2.fsdisk`.
* **One slot, one PRDT, static DMA.** A single command list, received-FIS area, and command table, as `aligned` `.bss` arrays below the 32 MiB identity-mapped limit, so the virtual address is the physical DMA address. `READ`/`WRITE DMA EXT` carry a 48-bit LBA; a write is followed by `FLUSH CACHE EXT` for the durability the dirty flag and `pc_sync` rely on. The page cache issues one page (eight sectors) per call, which one PRDT entry covers; a larger request fails closed rather than truncating.

## The decisions the bring-up forced

* **Skip the HBA reset.** The plan's bring-up called for `GHC.HR`, the standard HBA-wide reset. In practice, on QEMU `ich9-ahci`, an HR without the deferred full per-port COMRESET handshake leaves the SATA link needing re-establishment and the device not ready: the port's `PxTFD` drops from `0x50` (ready) to `0x130`. Skipping HR and relying on the per-port stop-before-program keeps the device ready and the engine starts cleanly. The driver does this deliberately, with the reasoning at the point of use; a real-hardware bring-up would HR and then COMRESET each port.
* **Own the HBA before mastering the bus.** The first bring-up enabled bus mastering and started the selected port without first quieting the others. On firmware-initialized hardware a non-selected port can retain `PxIE`, stale DMA bases, or an outstanding command, and with bus mastering already on it could DMA a received FIS into a stale buffer, while a preserved `GHC.IE` with no registered handler invites an interrupt storm. The bring-up now clears `GHC.IE` first, masks and quiesces every implemented port, and enables bus mastering only after the selected port's DMA bases are programmed. This was an independent-review finding, fixed before the phase counted.
* **Guard the ABAR against a 64-bit BAR4 spill.** The ABAR is BAR5. A 64-bit BAR4 would put its high dword in BAR5's slot; mapping that as the ABAR would write into low memory. Discovery now rejects a 64-bit BAR4 or BAR5 before mapping. Also an independent-review finding.

## How it was built

Each phase was a multi-agent build that adversarially verified its own work before it counted: parallel reviewers under distinct lenses (FIS/PRDT layout, the IF=0 no-sleep contract, overflow and bounds, cache coherency, regression) tried to refute the change, and the two hard phases, the HBA/port bring-up and the block backend, took an additional independent Codex review. The bring-up review found the two dirty-state hazards above; the backend and transfer reviews confirmed, against the disassembled object, that the 64-bit LBA shifts compile inline with no libgcc dependency on this freestanding `-nodefaultlibs` build.

## Verification

The AHCI path runs the same probes the ATA path does, on an `ich9-ahci` HBA selected by `rach2.disk=ahci`: `make test-disk-ahci` round-trips a working set larger than the cache through forced eviction (`BLOCKPROBE OK`), `make persist-test-ahci` writes and fsyncs a file on one boot and reads it back on the next (`PERSISTPROBE OK`), and `make stress-test-ahci` writes and re-reads 33 MiB past the RAM cap (`STRESSPROBE OK`). The capstones run over a SATA root: `os-real` boots from the AHCI disk, the SSH login reaches an interactive busybox ash over a dropbear pty, and Doom reads `doom1.wad` off the AHCI-mounted file system and runs. The ABAR maps high (`0xfebf1000` on QEMU), clear of the window span `[0xC0000000, 0xD0000000)`, so the page-cache window is identical to the ATA boot. The global gate held throughout: `make verify-style` 8/8, `make verify-host`, the module-path `make test` at 28/28, and the legacy `if=ide` ATA `test-disk`/`persist-test`/`stress-test` byte-for-byte green. The default RAM-module boot is unchanged: AHCI is dormant unless the boot flag selects it.
