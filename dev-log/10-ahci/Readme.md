# Milestone 10: AHCI, the modern SATA half of the disk layer

The disk milestone moved KRFFS to an ATA disk through a polled page-cache window but deferred AHCI, the interface used by most current hardware. This milestone adds AHCI behind the same `block0` interface published by the ATA driver. The page cache, demand-paged window, MBR root probe, KRFFS, dirty flag, and fsck remain unchanged because they call `block0->read`/`block0->write` without depending on the driver. The arrangement follows the audio drivers: the PC speaker and SB16 remain readable bring-up drivers beside HD Audio, while ATA PIO remains beside AHCI behind one block interface.

## The design

An independent Codex pass reviewed the plan before implementation. Each phase had a specific in-guest token so a regression could be traced to one phase. The first decision determined whether the fault path would change.

* Completion is polled without interrupts. The page-cache window fault arrives through an interrupt gate and runs with interrupts disabled. It cannot sleep or wait for a completion IRQ. AHCI normally uses DMA and a completion interrupt; this driver retains DMA but masks `GHC.IE`/`PxIE`, sets the slot bit in `PxCI`, and polls until it clears while watching `PxIS.TFES` and `PxTFD.STS.ERR`. The same iteration watchdog used by ATA bounds the poll. The HBA transfers the data while the CPU polls a memory-mapped bit. `ahci_read`/`ahci_write` therefore satisfy the existing block contract without changing the fault model, cache, or mount flow. `sys/block/Readme.md` records why IRQ and asynchronous completion remain deferred.
* A driver-selection point chooses the producer of `block0`. `block0`'s definition moved from `ata.c` to `block.c`, which owns the contract, and a small `block_probe` selects the driver. `rach2.disk=ahci` tries AHCI and falls back to ATA if no HBA responds. Without the flag, the system initializes ATA as before, so existing IDE images boot byte-for-byte unchanged. Whole-token matching prevents the flag from colliding with `rach2.fsdisk`.
* One slot, one PRDT, static DMA. A single command list, received-FIS area, and command table use `aligned` `.bss` arrays below the 32 MiB identity-mapped limit, so the virtual address is the physical DMA address. `READ`/`WRITE DMA EXT` use a 48-bit LBA; a write is followed by `FLUSH CACHE EXT` for the durability required by the dirty flag and `pc_sync`. The page cache issues one page (eight sectors) per call, which one PRDT entry covers; a larger request fails closed rather than truncating.

## The decisions the bring-up forced

* Skip the HBA reset. The plan called for `GHC.HR`, the standard HBA-wide reset. On QEMU `ich9-ahci`, an HR without the deferred full per-port COMRESET handshake requires the SATA link to be re-established and leaves the device unready: the port's `PxTFD` changes from `0x50` (ready) to `0x130`. Omitting HR and stopping each port before programming it keeps the device ready and lets the engine start normally. The driver explains this choice at the point of use. Hardware initialization would issue HR and then COMRESET on each port.
* Take control of the HBA before enabling bus mastering. The first implementation enabled bus mastering and started the selected port before quiescing the others. On firmware-initialized hardware, an unselected port can retain `PxIE`, old DMA bases, or an outstanding command. Enabling bus mastering in that state could DMA a received FIS into an old buffer, while a preserved `GHC.IE` without a registered handler could cause an interrupt storm. The revised initialization clears `GHC.IE`, masks and quiesces every implemented port, programs the selected port's DMA bases, and then enables bus mastering. An independent review found this issue before the phase was accepted.
* Guard the ABAR against a 64-bit BAR4 spill. The ABAR is BAR5. A 64-bit BAR4 would put its high dword in BAR5's slot; mapping that as the ABAR would write into low memory. Discovery now rejects a 64-bit BAR4 or BAR5 before mapping. An independent review also found this issue.

## How it was built

Each phase used multiple agents and adversarial verification before acceptance. Parallel reviewers examined FIS/PRDT layout, the IF=0 no-sleep contract, overflow and bounds, cache coherency, and regression risk. The HBA/port initialization and block backend also received an independent Codex review. The initialization review found the two unsafe-state cases above. Reviews of the backend and transfer code checked the disassembled object and confirmed that the 64-bit LBA shifts compile inline without a libgcc dependency in the freestanding `-nodefaultlibs` build.

## Verification

The AHCI path runs the same probes as ATA on an `ich9-ahci` HBA selected by `rach2.disk=ahci`. `make test-disk-ahci` round-trips a working set larger than the cache through forced eviction (`BLOCKPROBE OK`). `make persist-test-ahci` writes and fsyncs a file on one boot and reads it on the next (`PERSISTPROBE OK`). `make stress-test-ahci` writes and rereads 33 MiB beyond the RAM cap (`STRESSPROBE OK`). The end-to-end tests use a SATA root: `os-real` boots from the AHCI disk, SSH reaches interactive BusyBox ash over a Dropbear pty, and Doom reads `doom1.wad` from the AHCI-mounted filesystem and runs. On QEMU, the ABAR maps at `0xfebf1000`, outside the window span `[0xC0000000, 0xD0000000)`, so the page-cache window matches the ATA boot. The following checks passed throughout: `make verify-style` at 8/8, `make verify-host`, module-path `make test` at 28/28, and the legacy `if=ide` ATA `test-disk`/`persist-test`/`stress-test` runs with byte-for-byte identical behavior. The default RAM-module boot is unchanged because AHCI remains inactive unless selected by the boot flag.
