# Milestone 5: three RAM disk images

Before this milestone, the build made one RAM disk in two overlapping ways. Both wrote `krffs/file_system.krffs`. A base image contained the ish shell and utilities; a larger image contained the syscall probes, BusyBox, and Dropbear. Nearly duplicate shell scripts mounted the image through FUSE, copied flat files into it, and ran a fixed-tree stager. This milestone replaced that design with three images under `build/images/`. Each has its own file and purpose:

* `test` contains only the freestanding syscall probes and musl integration programs. `make test` boots it headless and asserts that every probe exits 0.
* `os-simple` contains the in-house ish shell, booted as init, and the hand-written Unix utilities. Its small, readable programs show how the Unix tools are built.
* `os-real` provides a Unix-like environment. BusyBox supplies the shell and core utilities. Its standalone ash dispatches applets in-process because KRFFS has no symlinks. Dropbear supplies the SSH server and client, Doom is included, and `/etc` and `/root` contain the login and name-resolution configuration. The kernel boots `/bin/sh` as init, and the end-to-end SSH test uses this image.

The replacement is a manifest-driven builder. The old fixed-tree stager became `krffs/stageimage.krffs`. It reads a line-oriented manifest with `dir`, `file`, `optional-file`, `text`, and `exec-dir` directives, then writes directories and files directly as KRFFS v2 nodes. It does not use a FUSE mount, so it builds the same image on macOS and Linux. One builder and three checked-in manifests replaced the two nearly duplicate scripts. The kernel gained an init search that tries `/sbin/init`, then `/bin/sh`, then `ish`. BusyBox moved its exec path to `/bin/busybox`, Dropbear gained the dbclient client, and `make isos` produces a bootable ISO for each image for use on hardware.

Codex review covered the image set, manifest format, BusyBox handling without symlinks, and ISO design. The owner chose the names `test`, `os-simple`, and `os-real`, a kernel init, and a complete build. Each phase received Codex review and boot verification; `os-real` also passed the end-to-end SSH test. The commits added the builder with the `test` and `os-simple` images, then `make test`, then `os-real` with the kernel init, then the per-image ISOs, and finally this documentation.
