# 84-5255: Firefox's slow WebGL2 fill on the Lenovo's gate

Firefox's WebGL2 fill in the Lenovo's speed gate measured 73% of Linux's in the continued native run at 24dc2e113 (run 1115-114117), while Chromium's four measures and Firefox's other three passed. The cause is Rach2's scheduler: during the first seconds after the page loads, Firefox's own startup threads fill all four processors, and the threads that issue the WebGL draws wait far longer for a processor than Linux would let them. Every figure below was measured by the owner's loops and the manager on the Lenovo and on WSL, and posted on #5255; this record collects them.

## Design

`sched.c` keeps no virtual runtime. Selection alternates between the first thread a wake marked and the head of the queue (`_wake_turn`), whatever each has run, so a thread that needs 0.1 ms between sleeps waits behind threads that use whole slices. Linux's EEVDF picks the eligible thread with the earliest virtual deadline (`pick_eevdf`, kernel/sched/fair.c), and a thread that has run less than its share is both eligible and early, so it runs first. `rach2/sys/proc/Readme.md` gives the limit in its Limits with these measures.

The fix is a scheduler with a per-thread virtual runtime: EEVDF's pick, lag kept across sleeps for wake placement, and nice weights. It replaces the selection, the wake preemption test, stealing and balancing in `sched.c`. The owner set it as a milestone of its own, 87, the fair scheduler, after the display stack's release; until it lands, `webgl2-fill-firefox` stays `xfail` in the gate.

## Tests

`probe.sh -t`, or `LENOVO_THREADS=1` for `lenovo.sh gate probe`, snapshots every thread's `/proc/PID/task/TID/schedstat`, nice value and policy before and after each draw and prints the busiest threads of each window; the gate runs without it, since the snapshots move the draws against the startup work. `debian.sh probe OUT -b firefox -t` runs the same in the Debian guest, for comparison in the same QEMU profile. The same runs judge a fix: on the Lenovo, all four Firefox measures within 10% of Linux's in each run; in QEMU, Rach2's waits near Debian's.
