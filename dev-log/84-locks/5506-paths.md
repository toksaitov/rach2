# File permission and remount paths in task 5506

The tables use Linux 6.12. `fs/open.c` supplies the credentials for access and the attribute calls, `fs/namei.c` walks the path, and `fs/attr.c` applies the attribute checks. Rach2's cached access path handles only ordinary files with a complete cached walk and falls back for synthetic names.

## Inode operations

Each file system below takes chmod, chown and utimensat by name and by descriptor through the entry points above. Chown with both IDs omitted requests ctime. A supplied ID equal to the old ID still requires permission. Truncate checks the resolved inode for write access. Ftruncate requires a writable regular file description. Opening an existing regular file with O_TRUNC requests write permission even with O_RDONLY. A negative length, a directory, a read-only mount, a refused size or a seal cannot clear set-id bits. Ftruncate and O_TRUNC request both mtime and ctime. Pathname truncate supplies only the size and any required privilege removal.

The open host test checks an ordinary queue open and a proc descriptor reopen, empty-path operations through a covered working directory, and fstat after PID reuse. It checks write permission against superblock and mount-only read-only flags. The mqueue host test sends a message, polls and reads queue attributes, checks notification cleanup and checks mq_open errors on a read-only superblock. The procfs host test retains each kind of task directory and changes the task lifetime behind its PID.

The mqueue host test calls `sys_mq_open` and `sys_mq_unlink` with the namespace root at mode zero, searchable only, sticky and writable without sticky. The `mq-held-attrs` guest case calls fchmod, fchown and futimens on a queue descriptor across unlink and namespace changes. The tmpfs host test advances its clock, asks for one byte beyond the size limit and checks size, mtime and ctime after EFBIG. The `pid_ns` guest case inherits proc directories across PID namespaces and checks relative walks through an overmount, a changed root and openat2.

## Differences from Linux

* KRFFS has no Linux implementation. The format reserves part of the root header for the volume and fixes the root mode at 0755. A successful root attribute call can therefore leave the root unchanged. Regular files have a 32-bit size. Rach2 also refuses truncation of an attached loop backing file with EBUSY, including an equal-size request.
* For ordinary mounts Rach2 checks the caller's filesystem capabilities and mapped inode IDs. Rach2 has no idmapped mounts or debugfs lockdown mode. Rach2 derives permitted and effective capabilities from one mask with filesystem-ID adjustments, so it cannot represent every independent Linux capability set. For the proc ptrace check Rach2 keeps dumpability on the address space but consults the target process's user namespace. Linux also records the user namespace of the address space itself.
* Rach2 charges queues against the per-namespace count. Linux also charges the creator's user account against RLIMIT_MSGQUEUE. Rach2 supports signal notifications and SIGEV_NONE. SIGEV_THREAD requires a netlink socket type Rach2 lacks.
* Rach2 generates process status text and mount lists in the reader's namespaces. An inherited proc mount now uses its own PID namespace for directory lookup and enumeration, including fd and fdinfo. Linux uses the proc mount's PID namespace for process status fields and the target process's mount namespace for its mount list. Rach2 accepts fdinfo as a synthetic chroot target and substitutes an empty tmpfs directory for it. Other synthetic proc directories pass their search check before chroot refuses them with EINVAL. Linux retains that proc directory.
* Rach2 implements its proc data files as synthetic read interfaces. Pathname truncate returns EACCES there. Several synthetic proc, dev and sys nodes have fixed mode, owner or timestamps, and anonymous pipes and sockets keep fixed ownership. Rach2 also permits writes to certain sysfs attributes on a read-only mount. These interfaces do not have all the inode operations of their Linux counterparts.
* Rach2 accepts the ext2 errors policy and a common FAT permission mask. Linux has further ext2 and FAT options and separate file and directory masks. Rach2's devpts and proc instances expose fewer configurable mount options.

The capability checks follow [Linux file access](https://github.com/torvalds/linux/blob/v6.12/fs/namei.c), [inode ownership](https://github.com/torvalds/linux/blob/v6.12/fs/inode.c) and [ptrace capability checks](https://github.com/torvalds/linux/blob/v6.12/security/commoncap.c).

The file-system rules follow [ext2](https://github.com/torvalds/linux/blob/v6.12/fs/ext2/inode.c), [simple_setattr](https://github.com/torvalds/linux/blob/v6.12/fs/libfs.c), [debugfs](https://github.com/torvalds/linux/blob/v6.12/fs/debugfs/inode.c), [mqueue](https://github.com/torvalds/linux/blob/v6.12/ipc/mqueue.c) and [pstore](https://github.com/torvalds/linux/blob/v6.12/fs/pstore/inode.c).
