# 84-105: ext2 inode stores and size sequences

This is the data-safety fix of j59's two high findings in 84-85c and its stale locking comments. Both faults hold the release until the reviewed branch passes its proof.

An inode encoder now reports whether a field other than a time changed; it publishes no dirty mark. `ext2_inode_write` publishes `dirty_meta` under `em->share_lock` after the table-buffer store returns. A concurrent `fdatasync` may precede that store, but cannot consume its mark before the bytes are stored; a later call therefore writes the table block. An error also leaves a mark for a dirty buffer the failed store may have left. A batch drain keeps changed fields in `wb->inode_dirty`, one bit per held node, across a failed stage and a retry whose image already holds the changed fields. It publishes and clears each bit only after copying and dirtying that inode's table buffer.

The size writer saves and disables interrupts before making `size_seq` odd, and restores the entry flags after the size store and the even sequence. Thus a device interrupt waiting for the big lock cannot suspend the writer while another processor holding that lock waits for the sequence. The node lock still serializes writers.

The other sequence writers were read at their callers:

* `kernel_tick_seq` changes in the interrupt-disabled clock pass and under `rtc_realtime_lock` with irqsave in `rtc_seconds`.
* The vDSO page's sequence changes in the clock pass, under the interrupt-disabled `rtc_vclock_change` callback, or under `vclock_lock` with irqsave in `vclock_withdrawn` and `vclock_set_wall`.
* The per-processor `ticks_seq` and `bkl_ticks[].seq` writers run in the timer interrupt.
* Vblank's `store_vblank` runs under `vbl_lock` with interrupts disabled, either by its irqsave take or by the outer `event_lock` irqsave take.
* The name, mount, notification and KVM MMU sequences are change generations; their readers do not spin waiting for an odd generation to become even.

The old assertion that every cache store holds the big lock has been removed. The big lock keeps the node table during a file sync's neighbour walk. The batch lock keeps its images; a buffer hold keeps each store whole; the cache's write lock and buffer hold keep the dependency check and write together. A writer may run after `table_write_ready`'s last check. `bcache_sync_block` checks dependencies again and holds the table buffer until its write ends, so a store either precedes that check or waits for the buffer.

`ext2_reserve_hosttest.c` has two forced rows, with hooks in its model rather than the kernel. The first calls the real `ext2_fdatasync` at the second get of a table buffer, between a sparse growth's encode and store, and checks that the following call copies the grown size to a separate durable table image. The old early mark is consumed by the first call and fails the second call's durable-size check. The second intercepts the atomic exchange that makes the size sequence odd and attempts a device interrupt against the model's big lock held by a reader. It counts the blocked interrupt rather than spinning forever. With the guard the interrupt stays pending, the reader reads the even sequence and releases the lock, and the interrupt then acquires it. It covers entry with interrupts on and off; removing the guard leaves the on-entry interrupt blocked.

`make ARCH=i686 rach2` and `make ARCH=x86_64 rach2` both link. The latter reports ACPICA's existing missing `.note.GNU-stack` warning. No tests or standalone style checks ran, including the new rows, as this fix task requires. The commit hooks ran. No fault in upstream code was found.
