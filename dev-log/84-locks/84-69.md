# 84-69: an empty AHCI port skipped by its link status

Task 84-69 (#4748) ends the one-second wait the AHCI driver spent on each port with nothing on it, which 77-11b found to be about 5 s of every boot in QEMU. Linux references are to 6.12.115. No upstream fault was found.

The driver reset each implemented port in turn and polled SStatus.DET for up to a second, taking the port as soon as DET read 3. An empty port's DET stays 0, so each one cost the whole second. The driver now does what Linux's `ahci_hardreset` does through `sata_link_hardreset` (`drivers/ata/libahci.c:1641`, `libata-sata.c:624-700`): COMRESET held for at least a millisecond, released, 200 ms for the PHY (`sata_link_resume`, `libata-sata.c:323`), and then `sata_link_debounce` (`libata-sata.c:235-281`) with `sata_deb_timing_normal`, `{5, 100, 2000}` ms (`libata-sata.c:22`). DET is read every 5 ms and settles once it has held for 100 ms, except that a DET of 1, a device seen that has not negotiated, is waited on until the 2 s deadline. A port is taken when it settles at DET 3, as before; a link that is still changing after the deadline settles at its reading there, where Linux would try again at a lower speed.

The ports are reset and debounced together, as Linux scans an AHCI controller's ports in parallel when CAP.SSS is clear (`ATA_HOST_PARALLEL_SCAN`, `drivers/ata/ahci.c:2131`). On a controller with staggered spin-up Linux scans one port at a time, each port's device ready before the next is reset (`async_port_probe`, `libata-core.c:5974`), and so does the driver. Each port now has its own FIS area while it is reset, since several receive at once; they share the command list, which the HBA reads only with the engine running.

## Measurements

QEMU 10.2.1 on WSL, `-machine q35` with KVM, the x86-64 kernel, one 64 MiB disk on port 0 of the built-in `ich9-ahci` and ports 1 to 5 empty, `rach2.rescue`. Time from the serial line `block: started` to `nvme: none`, on the host's clock as the lines arrived; the kernel's own stamps agree within 5 ms.

| Kernel | AHCI time | Per empty port |
|---|---|---|
| milestone head, before | 5.709 s | 1.12 to 1.18 s |
| this task, ports together (QEMU has no CAP.SSS) | 0.348, 0.346, 0.350 s | 305 ms, all at once |
| this task, one port at a time, forced for this run | 1.922 s | 305 ms each |

In every run the disk on port 0 was found, identified and registered as `disk0` with its 131072 sectors. The ready wait, the signature check and everything after the link are unchanged.

## Build

Both kernels linked with `make -j8 ARCH=i686 rach2` and `make -j8 ARCH=x86_64 rach2`, and `check-kernel` passed each. The host test's model of the controller answers DET at once and its delay passes no time, so its rows settle each port after 21 polls and none counts delays across the scan.
