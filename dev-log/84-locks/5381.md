# 5381: ext2's ordered write-back of names

On a mount that writes back, an operation that adds a name no longer writes the device before it returns. Before, each create wrote the new inode's table block and then the directory block (`dir_commit`, `inode_commit`, both by `bcache_sync_block_ordered`), as Linux's ext2 does under `ext2_handle_dirsync`; a create waited for two disk requests and a mkdir for more. Linux's ext4 driver, with which Debian's kernel mounts ext2, waits for none: its journal commits later. Now the order is kept in the buffer cache instead.

## Design

* `bcache_order_after(dev, blk)` keeps a token in the process: every change it makes through `bcache_change` until `bcache_order_end` reaches the device after `blk` as it stands now. `bcache_change` turns the tokens into waits on the changed buffer, each the waited buffer and its count of marks, and records in the waited buffer the count it must reach (`need`). Every path that writes, a sync, a block's sync, an eviction, a shrink and a reserve, writes what a block waits for first (`order_before`, `way_to`).
* A change that carries waits and comes to bytes another wait needs first copies the bytes into an image of the block, which stands for it in those waits and is written before it, as soft updates roll a block back. So no change waits for what it is ordered after, and the graph of waits has no cycle: each wait points at bytes older than the change that made it. `way_to` logs a cycle and breaks it, should one appear.
* Only directory blocks (`bcache_dirty_entry`, outside the class rules) and the last class, the inode tables, carry waits, so no class rule and no order can point at each other.
* ext2: `dir_commit` takes DIR_BACK, DIR_ORDER or DIR_NOW. An added name is DIR_BACK when nothing after it depends on it and DIR_ORDER when a later step does, a rename's removal of the old name; a removed name stays DIR_NOW, written before the inode loses its count, since the free's bitmaps and the reuse of the inode are not blocks that carry orders. A new directory or symlink block under the direct pointers is DIR_ORDER; one under a pointer block is written at once, since the pointer rules do not wait for entries.
* An `fsync` of a new file writes, after its table block, the directory blocks that wait for it (`bcache_sync_waiting`, at most 64), so a new file keeps its name through an `fsync` of the file alone, as ext4's commit does.
* Each operation on names counts as a block written toward `ext2_em_balance`, so a program that makes names without end throttles as a writer does, which bounds the images.

## Measurement

The host rows (`ext2_hosttest --creates-only`), with the cache at 8192 buffers on a mount that writes back, 64 names of each kind in the root, which grows past its first block. The writes are the device's write requests during the 64 operations; the sources before are a630ec2b6's `rach2/sys/fs` and `process.h` built into the same test.

| Operation | Writes before | Writes after | Disk waits after (reads) |
|---|---|---|---|
| create | 256 | 0 | 5 |
| mkdir | 448 | 0 | 3 |
| fast symlink | 256 | 0 | 2 |
| slow symlink | 384 | 0 | 2 |
| mknod (FIFO) | 256 | 0 | 2 |
| link | 132 | 0 | 0 |

Each write before was a synchronous request the caller waited for, so a create waited for 4 requests and a mkdir for 7; now each waits for none, and the reads that remain are of blocks the cache lacked.

The create latency during Chromium's start-up was not measured. This worker's host has no GNU root, in its clone or in the host's cache, and its disk was 95% full, with 62 GiB free, where the GNU root's build takes some 35 GiB; a boot of the ext2 scenario by hand would be a run of a suite. The measurement is left to the checkpoint or the release, on the testing host's kept build copy.

## Proof

The new rows of `ext2_async_rows.h` pass: the create row, a rename's image in one directory block written between the table block and the block, a stop after which leaves both names in use, a new file's `fsync` that keeps its name, and the interruption matrix on a mount that writes back, synced and stopped after each of 683 writes, each stop judged by the matrix's judges. The default mount row and the symlink-kept row, changed for the new order, pass. Both kernels link.
