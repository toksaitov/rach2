# 5783: why WineD3D's d3d9:device fails 5 checks on Rach2 where Linux's reference has 2

The release's full run of milestone 84 at 19a1eb6354 failed `machine.d3d-wine.wined3d-d3d9-device` on x86_64: exit 5, the summary `[160671, 159, 0, 5, 9]` and 180 test lines, where `tests/graphics/d3d/ref/linux.json` kept exit 2, 2 failures, at least 60,590 checks and at most 10 skips. It is a test that differs from Linux's run. Wine's `test_occlusion_query` fails 2 or 5 checks by the clock, and the reference kept only the 2. The Debian reference guest today fails the same 5 checks as the release, in 6 runs of 6. Rach2's kernel has no fault here, and master's kernel gives the same 5.

## The test

`test_occlusion_query` (`dlls/d3d9/tests/device.c:6516-6793`, Wine 11.0) times 1000 query issues and skips its large query tests when they take more than 70 ms (`device.c:6686-6707`). Past that skip come 100,082 checks: 100,000 more issues, then 65 quads of 8192 by 8192 pixels drawn inside one occlusion query, after which `wait_query` (`tests/utils.h:24-37`) asks for the result 500 times, 10 ms apart. When llvmpipe has not finished the draws within those 5 s, three checks fail: `device.c:6775`, the wait, `6779`, the read of the result, and `6780`, the result itself, `0xffffffffffffffff` as the test's `memset` left it. So the unit ends in one of three ways:

| branch | failures | checks | skipped |
|---|---|---|---|
| the loop took more than 70 ms | 2 | 60,605 in the Debian run below | 10 |
| the draws finished inside 5 s | 2 | 160,671 | 9 |
| the draws had not finished after 5 s | 5 | 160,671 | 9 |

The other two failures are the same in every run: `device.c:14930`, a clip rectangle of (-64,0)-(704,480) where (0,0)-(640,480) is expected, and `device.c:15008`, a check inside a todo block that passed. The reference's 2 failures, 60,590 checks and 10 skips fit the first branch; its runs were not kept. That branch's count follows timing too: the TCG run below counted 175 checks marked todo, unexpected window messages among them, where every run under KVM counted 159, and 160,671 less the 100,082 skipped checks is 60,589.

## The runs

Each run is WineD3D's `d3d9:device` alone, the Debian runs by `tests/graphics/d3d/reference.sh -a lavapipe -p virtio-vga`, the Rach2 runs by `tests/run x86_64:d3d-wine` with `RACH2_QEMU_ACCEL=kvm` and the case alone, on 2026-11-24 between 11:41 and 12:12 UTC+6. Every Debian record has a host load of about 31 on its 32 threads. Each run's lines that count as failures are in [runs.txt](5783/runs.txt).

| machine | runs | 2 failures, 60,605 checks | 2 failures, 160,671 checks | 5 failures, 160,671 checks |
|---|---|---|---|---|
| Debian 13, 8 CPUs, KVM | 3 | 0 | 0 | 3 |
| Debian 13, 2 CPUs, KVM | 3 | 0 | 0 | 3 |
| Debian 13, 8 CPUs, TCG | 1 | 1 (the loop took 115 ms) | 0 | 0 |
| Rach2 at the milestone's c0d72028fb | 3 | 0 | 2 | 1 |
| Rach2 with master b167e6ac5c's kernel | 1 | 0 | 0 | 1 |

The milestone's head carries 19a1eb6354's kernel unchanged. The master run booted master's x86-64 kernel, built in a worktree, in place of the head's, with the head's GNU disk and Direct3D payload; between master and the head neither `vendor/gnu` nor the payload's sources differ. Every run that failed 5 checks failed them on the same five lines, Debian's and Rach2's alike.

## The change

`linux.json` now folds Linux's runs as `mkref.py` folds runs whose failure counts differ: no exit, the failure counts 2 and 5, and the five lines as `varying_lines`, so that each failure must be on one of them and the log must print as many as the summary counts. The fewest checks stays 60,590 and the most skips 10, so a run that stops early or skips more still fails. Each of the eleven logs above matches the new entry by `run.py`'s own code. With the change, the case passed alone on Rach2 at 12:15 UTC+6, failing 2 checks in 160,671.

The release's evidence kept the unit's summary and not its failures, since the case keeps the runner's output and the unit's log stays in the guest. `run.py` now prints each line of a Wine unit's log that counts as a failure, as `d3d: failure: LINE`.
