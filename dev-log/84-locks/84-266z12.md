# kms_content_protection and the cursor tests with the Lenovo's HDMI display

Task 5228 takes the 52 rows of the Lenovo's native `gpu/igt-kms.2` at 4add94748 that were not kms_color's: six `kms_content_protection` subtests incomplete where Linux's reference skipped them, and 46 `kms_cursor_crc` and `kms_cursor_edge_walk` rows not run here that passed in the reference. Both come from the HDMI display at 1920x1080 that is connected beside the 1366x768 panel; Linux's reference ran with the panel alone. Rach2's kernel answers as Linux's does in both. The run's 64 kms_color skips are task 5227's, whose CRTC colour properties came after 4add94748.

The evidence is igt_runner's own output of the run, which the owner copied to `build/tmp/lenovo-igt/212d9f986ab3a99d`. IGT's source was read from the pinned `intel-gpu-tools_2.0.orig.tar.xz`, whose SHA-256 matched `vendor/gnu/igt/sources.txt`, and Linux's from 6.12's `drivers/gpu/drm/i915/display`.

## Content protection

`igt@kms_content_protection@atomic` ends by SIGABRT on the assertion in `do_display_commit` (`lib/igt_kms.c:4631`), errno 34, with an empty dmesg. The commit is the first of `modeset_with_fb`, `tests/kms_content_protection.c:239`, which the stack trace shows inlined in `test_content_protection`. `create_fbs` makes the test's framebuffers 1920x1080, the largest connected mode. `modeset_with_fb` sets the eDP plane's source to 1366x768, but `igt_plane_set_fb` has set the plane's CRTC size to the framebuffer's 1920x1080, so the plane is scaled. Haswell's primary plane cannot scale: Linux 6.12's `i9xx_plane_check` passes `DRM_PLANE_NO_SCALING` both ways to `intel_atomic_plane_check_clipping`, whose `drm_rect_calc_hscale` gives -ERANGE, as Rach2's `intel_plane_check` does through `drm_atomic_helper_check_plane_state`. Linux with the same display would abort the same way. With the panel alone the framebuffers are 1366x768, nothing scales, and `output_hdcp_capable` finds no "Content Protection" property and skips. `legacy` skipped here as well, since a legacy commit of the primary plane sets the CRTC and does not scale it.

IGT's master sets the plane's size to the output's mode in `modeset_with_fb` and in the three functions that show a framebuffer after it. `vendor/gnu/igt/kms-content-protection-plane-size.patch` does the same to 2.0, and `build_igt.sh` applies it in the builder guest; the IGT step's inputs name it, so the step builds again. With one output the patch changes nothing, so the reference stays valid. The fault is in `upstream.md`.

## The cursor tests' pipe C

IGT's `__igt_pipe_populate_outputs` gives the panel pipe A and lets an external output take every other pipe, and the cursor tests run the first and the last pipe. With the panel alone they ran `pipe-a-edp-1` and `pipe-c-edp-1`; with the HDMI display, `pipe-a-edp-1` and `pipe-c-hdmi-a-1`, all 46 of which passed. `judge.py results` now judges a reference row `@pipe-P-OUTPUT` that the run lacks by the run's one row of the same subtest and pipe with another output, which the reference lacks, and prints it as `judge: output:`; a worse moved row is named by the run's name, which `lenovo.sh` reads IGT's output by. On the saved output of the four parts, igt-kms.1, .3 and .4 judge as before, 21, 36 and 1 worse, and igt-kms.2 goes from 116 worse to 70, the 64 kms_color rows and the six content-protection rows.

## Building

`make ARCH=x86_64 gnu-igt` built the patched IGT in the builder guest. No kernel source changed. No suite, host test, style check or boot ran outside the git hooks; the manager reruns igt-kms.2 on the Lenovo.
