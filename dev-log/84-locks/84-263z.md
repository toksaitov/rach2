# 84-263z: private regions merged by a one-bit mark instead of Linux's anon_vma and page offsets

Rach2 kept a private region's anonymous state as one bit, `anon`, set when `mm_note_anon` found a page of its own, and refused a merge only when both regions had the bit and mapped a file through separate records. Codex's reviews of the private-merge fix and of the guard-page change named four cases where its region counts differ from Linux's. Each is measured here against Linux 6.18.58, the WSL kernel of the testing PC, with vmamusl built natively and run there. Three were as the reviews said. The fourth was not: Linux 6.18 merges two private memfd pages that were guarded apart, and keeps two anonymous pages guarded apart from merging. Measuring further found two more differences in the same rule, page offsets of anonymous memory and the anon_vma of a fork's child.

## Linux 6.18's rule, as measured

Each case maps two pages between PROT_NONE pages, brings them next to each other, and counts the regions of the 6-page range, two of which are the guards on either side.

| Case | Linux | Rach2 before | Rach2 after |
| --- | --- | --- | --- |
| memfd pages of two calls, RW and RWX, both written, then one protection | 3 | 4 | 3 |
| memfd pages of one call, the second moved away before either was written, both written, the first moved beside it | 4 | 3 | 4 |
| memfd pages written apart, the file truncated to 0 and regrown, moved together | 4 | 3 | 4 |
| memfd pages guarded apart with MADV_GUARD_INSTALL, never written, moved together | 3 | 3 | 3 |
| anonymous pages guarded apart, moved together | 4 | 3 | 4 |
| anonymous pages of one call split by a move, both written apart | 4 | 3 | 4 |
| the same, only the page moved second written | 4 | 3 | 4 |
| the same, only the page moved first written | 3 | 3 | 3 |
| a fork's child joins pages split before the fork | 4 | 3 | 4 |
| a fork's child splits and joins written pages | 3 | 3 | 3 |
| a fork's child maps a page beside one written before the fork | 4 | 3 | 4 |
| [heap] regions after a fork's child grows a heap written before the fork | 2 | | 2 |

The "before" column is the milestone's head with the new rows, on both architectures; vmamusl stopped at its first failure, so a run with the rows printed one by one gave the rest. The "after" column is the task's kernel, on both architectures.

What the rows show of Linux:

* A region gets an anon_vma at its first private page and keeps it after truncation. A page written beside a neighbour that borders it, has the same file, policy and flags but for the access bits, continues its page offsets and has an anon_vma of its own reuses that one (`find_mergeable_anon_vma`); so the first row merges.
* An anonymous region's page offset is the page number of the address it was mapped at. A move keeps it once the region has an anon_vma; a region moved before its first write takes the offset of its new address (`copy_vma`). The row where only the page moved second was written stays apart for this reason alone, since the unwritten page moved first took its new address's offset.
* MADV_GUARD_INSTALL gives an anon_vma to anonymous memory and not to a private mapping of a file.
* A fork's child gets a new anon_vma for each region that had one, whose chain holds the parent's too. Such a region merges only with one of the same anon_vma, which a split in the child shares, and lends it to no neighbour. A brk in the child therefore makes a second heap region.

## The change

* `vma_t.anon` is an identity, a number of the address space's (`anon_last`), and `anon_forked` marks a fork's copy's. `vm_anon_prepare` gives one, reusing a compatible neighbour's, the one above first, as `find_mergeable_anon_vma`. `vm_merge` merges two regions only when at most one has an identity and neither side is a fork's copy, or both have the same one, as `is_mergeable_anon_vma`, and for anonymous memory too, where it ignored the bit before.
* An anonymous region's `pgoff` is the page number of its start, modulo 2^32; a split, a trim and a stack's growth follow it, `remap_move` keeps it for a region with an identity and gives the new address's otherwise, and `vm_merge` checks it for every region.
* `mm_note_anon` gives the identity in place of the bit, and now looks at anonymous neighbours too. It runs before a fork's copy, before brk and an anonymous mmap add a region, and before a truncation unmaps the private copies (`walk_space`), so the identity outlives them.
* MADV_GUARD_INSTALL gives an identity to each region with no file it meets.
* `vm_insert_like` and `vm_set_policy` merge with the lower neighbour first, as `vma_merge_new_range` does when both neighbours may not share the region.

## Proof

`tests/musl/vmamusl.c` has the twelve rows above, measured on Linux 6.18.58. On the milestone's head the first eleven ran, before the heap row was written, and eight failed on both architectures; on the task's kernel vmamusl passes on both, `RACH2_CASES=guest.default.vmamusl ARCH='i686 x86_64' tests/run default`, run on 2026-11-19. The host tests that compile `paging.c`, `mm.c` or `vm.c` were compiled and linked, not run.
