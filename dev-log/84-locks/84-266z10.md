## Indexed framebuffers

The four `kms_big_fb` 8-bit rows, linear and X-tiled at rotations 0 and 180, skipped with `unsupported configuration`. IGT 2.0's `tests/intel/kms_big_fb.c`, `test_pipe`, returns false before making the framebuffer when a C8 test has no CRTC GAMMA_LUT property. Rach2 advertised the C8 primary format but exposed no gamma property and refused C8 in the plane check. Linux passed these rows.

The change in 11d269df4 gives each Haswell CRTC GAMMA_LUT and GAMMA_LUT_SIZE, a 1024-entry precision table and the 256-entry legacy table, and the legacy gamma ioctls. C8 requires the legacy table, which IGT's `set_c8_lut` supplies as an RGB332 palette. The load follows Linux 6.12's `ilk_load_lut_8` and `ivb_load_lut_10`: explicit precision indices on Haswell, the index reset before another legacy palette write, channel values rounded and clamped, and the extended maximum set to 1.0. RGB planes take the pipe gamma stage only with a table and no visible C8 primary, as `ilk_gamma_enable`; a palette or format change updates the affected planes as well. The table loads before a pipe comes on or after its next vblank when already running.

## Panel downscales

Eight `kms_bw` rows passed on Linux and skipped on Rach2. They are the connected and ordinary one-display cases at 1920x1080, 2160x1440 and 2560x1440, and the ordinary two-display cases at 1920x1080 and 2160x1440. The last was absent from the task's original list but is present in its saved native JSON. Every skip reports `Unsupported mode` and errno 34 from the TEST_ONLY commit.

Both runs assign pipe A to eDP-1. The two-display rows also assign pipe B to HDMI-A-1, in both runs. This is no difference in connected outputs. The panel is 1366x768; these source modes need a downscale greater than 1.125. Rach2's `intel_pfit.c` imposed that ratio from Linux 6.18's fitter checks and returned ERANGE. The reference kernel's `pch_panel_fitting` has no such check and its recorded run passed the modes on this panel.

The change in aa116bf90 removes the ratio cap. The window and source-size checks remain, and a downscale's increased pixel rate must still fit the CD clock. The existing fitter assertions now cover the three reference source sizes with their expected panel windows; they are compiled only, not run for this release fix. The driver Readme and i915(4) describe the resulting contract.
