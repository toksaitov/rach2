# 84-265z: what webgl2-06's harness had when QEMU was lost after its 250 pages

Both failed runs of `machine.virgl.webgl-chromium-webgl2-06` on x86_64, the release's rerun at 04:09 and loop a's at 04:42 UTC+6 on 2026-11-15, had all 250 pages of the chunk's first pass recorded in the guest before QEMU was lost, but about 40 of them had been drawn on a GPU device that the host had already removed and fail where Debian's reference passes. The case cannot pass on those results, so it is not changed to collect them early. Debian's chunk 6 run did the same steps in the same order and collected nothing earlier; it ended clean because its engine reset came in its last browser.

## Where the results were

* `webgl.sh` runs the chunk in one Chromium, appends each page's line to `attempt` in its work directory, `mktemp -d /tmp/webgl.XXXXXX`, and only then prints "webgl: browser: done after 250 pages". `chunk` then starts a new Chromium for the pages that did not pass, and writes `chromium-2.0.1-06.pages` to the output directory only after that browser ends. The case's steps after `run`, `judge` and `collect`, read the output directory.
* When QEMU died, as the second Chromium made its GL context, the first pass's lines were in the guest's `/tmp`, which is on the ext2 root on the virtio overlay. The output directory had no pages file yet.
* Both kept overlays (`copies/gnu-disk` of the two workspaces) still hold the `attempt` lines and the server's events. 249 of the 250 lines of each come out whole with `grep -a`; page 1500's is split across a cluster. They are kept here as [first-pass-release-rerun.pages](84-265z/first-pass-release-rerun.pages) and [first-pass-loop-a.pages](84-265z/first-pass-loop-a.pages), in the pages file's form with each line's status as its first.

## What they show

* Pages 1501 to 1661 match the reference page by page in both runs: the same 18 pages fail, those that fail in Debian's reference, and every other page passes.
* From page 1663 in the release's rerun and page 1662 in loop a's, pages that pass in Debian fail: `shaderderivate_*`, `shaderloop_*`, `shaderprecision_*`, `shaderstruct`, `shaderswitch`, the `conformance2/attribs`, `buffers` and `glsl3/array-*` pages and others, with the same counts in both runs (page 1664, 6,409 subtests passed and 130 failed in each). Pages that read nothing back, such as `shaderstatequery.html` and `stringquery.html`, still pass.
* `judge.py webgl` with `webgl-virgl.flakes` on these first passes finds 39 pages worse than Debian's in the release's rerun and 40 in loop a's, besides page 1500, which it counts as not run because its line was not recovered.
* The server's event times place the onset. The last page ended at t = 643.4 s in the release's rerun and t = 706.3 s in loop a's; loop v's #5183 found the Windows engine reset 164 s and 166 s before QEMU's fault, and the second browser starts a few seconds after the last page. That puts the reset at about t = 480 s and 540 s, while pages 1659 to 1663 ran: `samplerobject.html` to `shadercommonfunction.html`. Which page hangs the engine is loop d's part, on #5178.

## What Debian's run did

`debian.sh webgl` runs the same `webgl.sh` to its end and packs `/tmp/out` only after it exits: the same first pass, the same second browser for the pages that did not pass, and no earlier collection. Its record (`tests/graphics/ref/virgl-wsl/webgl-chromium-2.0.1/record-06`) shows 26 pages run again, `shadercommonfunction.html` among them, and loop v found its engine reset at 04:02:02, 14 s before its counters were read: in the second browser, after which no new GL context was made. Its first pass had no reset, so its first results are good, and no browser started after the device was gone.

## Why the case is not changed

Copying the first pass out before the second browser starts would change the case's failure from "the machine or its transport was lost" to about 40 pages worse than Debian's; it would not make it pass, and those pages ran on a removed device. The case passes on this host only if the chunk runs without the engine reset, that is, without the page that causes it. `tests/graphics/runners/webgl-virgl.omit` is where such a page goes, as the RGB9_E5 uploads that remove the device went; that waits on loop d's finding.
