# 84-5782: top64 in machine.games-wine.maps

`machine.games-wine.maps` failed on x86_64 in the release's full run of 24 November: in the 64-bit hold program, the preloader's range top64, 7ffffe000000 plus 0x1ff0000, had 143360 bytes mapped against Linux's 33488896. Every other range of both programs matched.

## Cause

Wine's preloader leaves unreserved any range that holds the initial stack (`wld_start` in GE-Proton11-12's `wine64-preloader`), and the stack's top is drawn anywhere in the 16 GiB below the top of user space, on Linux (`STACK_RND_MASK`) as on Rach2 (`ASLR_STACK_PAGES`). top64 is the 32 MiB just below that top, so about one 64-bit start in 512 puts the stack there, on either system, and the range then maps the stack alone.

That this is what the failed start did is an inference from the counted size, since the full run kept no maps: 143360 bytes is 0x23000, one start's stack mapping of 0x22000 bytes with one more page of environment, and nothing else. Linux's reference starts had their stacks outside every range. Run alone on x86_64, master b167e6ac5c passed, and the head passed with all 33488896 bytes of top64 mapped.

## Change

The maps row (`tests/system/games/run.py`) sets aside a start whose `[stack]` overlaps a preloader range, keeps its maps and log, and starts the program again, up to three times; it judges a start whose stack lies outside the ranges against the same counts, and fails if all three land in one. A forced run that treated each first start as a hit passed.

The head's first lone run hung in `make_prefix`'s wineboot with the desktop session running, before any maps were read; that hang is task 5786.
