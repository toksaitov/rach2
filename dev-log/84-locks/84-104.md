# 84-104: the one-byte file calls against Linux's time

84-88 left Rach2's one-byte read and write of /dev/zero and /dev/null at 1.57 s for 400,000 of each against Linux's 0.39 to 0.43 s, and a one-byte pipe at 1.08 s against 0.91 s. This task took the four locks those calls still took, measured the calls against Linux's in one machine, and traced the time that is left to the code that spends it, beside the Linux code that does the same work.

## The setting

Both kernels ran in the same machine on this host, the Windows PC's WSL: QEMU 10.2.1's TCG, `-cpu max`, one processor. Rach2 ran as `run.sh` runs it, the x86-64 kernel with the os-real image in the debug shell. Linux was Debian's 6.12.107 cloud kernel, the testing host's pinned package, with an initramfs whose only program is Rach2's own static BusyBox. Each ran the same two commands three times, and the figures are BusyBox dd's own:

* `dd if=/dev/zero of=/dev/null bs=1 count=400000`, 400,000 reads and 400,000 writes of one byte;
* `dd bs=1 count=100000 </dev/zero | dd bs=1 >/dev/null`, a one-byte pipe, 100,000 bytes.

84-88 measured on the testing PC under etude, where both kernels ran faster than here, so its figures and these do not compare; the comparison is each kernel against Linux in one machine. Under TCG a run's time follows not only the instructions but also how often a translation block ends, and every POPF and every STI ends one. So each kernel also ran with `-icount shift=0,sleep=off`, where guest time is one nanosecond per instruction and dd's seconds count instructions; and a QEMU log of every block executed (`-d exec,nochain`, turned on for two seconds through the monitor) gave the instructions each function ran in each call.

## The changes

* fd88bed50: `fd_get` reads a table that only the calling thread has with no lock and no hold, as Linux's `__fget_light` reads a table whose count is 1 (fs/file.c:1114-1118). It relies on these rules. A table is shared only by a clone of one of its sharers (`fd_table_share`), so `refs` reads 1 only while no other thread can be in a call on it, and no other thread can join during the caller's call, since only the caller can clone. Every reservation, publication, close and growth of the table is a sharer's call, so it is the caller's own. Another process only reads the table (`fd_peek`) or changes a slot's node (`fd_table_repoint`). A sharer that left made its last change under the table's lock before it dropped `refs` there, and x86 does not move a load ahead of an earlier load, so the slot read after `refs` sees that change. The entry's lifetime is the call's: the table's chunks never move, and only the caller could close the slot. A shared table keeps the locked lookup and its holds.
* 39c0c3508: a rwsem's state is one atomic word, the readers' count with a writer bit and a waiting bit, so that `down_read`, `up_read`, `down_write` and `up_write` without contention are each one compare-and-exchange, as Linux's `rwsem_read_trylock` and `rwsem_write_trylock` are (kernel/locking/rwsem.c:248-272, 1336-1349). The spinlock now guards only the count of waiting writers and sets and clears the waiting bit, which stops new readers while a writer waits. It is a leaf lock and is dropped before a sleep. A writer's owner is set after its bit and cleared before the bit is cleared. The last reader's release and each writer's release wake the queue only with a sleeper on it. The release's exchange is a full barrier, and so is the unlock of the queue that a sleeper files itself on before it tests the state, so no wake is lost.
* 709d2ceda: `copy_from_user` and `copy_to_user` take no lock. They copy with `arch_user_copy`, a `rep movs` whose fault the page fault handler resolves as it would a fault of the program, taking `mmap_lock` for reading there, as Linux's copy faults in `do_user_addr_fault` (arch/x86/mm/fault.c:1329, 1361). A fault that nothing can serve moves the PC to the copy's fixup, which returns the bytes not copied, as Linux's exception table does (fault.c:721-728, arch/x86/lib/copy_user_64.S). A short read from user memory zeroes the rest of the kernel buffer, as include/linux/uaccess.h:180-184 does. The pages copied stay mapped only as long as the fault resolver keeps them, since nothing pins them between faults: a page that another thread unmaps during the copy faults again and is served or fails, as on Linux. The handler runs the fault with interrupts as the copy had them and may sleep, so a copy runs only where a sleep is allowed, which was already the rule for these two calls. CR0.WP is set on both architectures, so a kernel write to a copy-on-write page faults and is copied.
* 77355c4d3: the read and write of /dev/null, /dev/zero and /dev/full run without the big lock, opened by path or not, as Linux's drivers/char/mem.c takes no lock for them. Their tables declare `FILE_OPS_UNLOCKED`, and `file_rw_unlocked` admits them though a description opened by path carries its mount, because their calls never read it. Their ioctl answers ENOTTY with no lock, as mem.c:649-688 leaves them no ioctl. /dev/random keeps the lock, since krandom's generator has none of its own.
* 00f597bce: a read of /dev/zero clears only the bytes it copies, up to its 256-byte buffer, as Linux's `read_zero` clears only `count` (mem.c:495-518). A one-byte read cleared all 256 bytes, 90 instructions of the call's 1,600.
* 91d520298: a sleep lock's last give wakes its queue only with a waiter on it, as Linux's `__mutex_unlock_slowpath` wakes only a waiter it finds on the list (kernel/locking/mutex.c:937-956). The pipe takes its sleep lock in each transfer. The order is the same as the rwsem's: the give's unlock of the lock's spinlock is an exchange, and a waiter files itself on the queue and unlocks it before it tests its turn.

`bkl/calls` showed the big lock taken 6 times in the 400,000 reads and once in the 400,000 writes; before, it was taken for every one.

## Results

Seconds; under TCG the median of three runs, and in counted instructions one run, since Rach2's counted runs repeat to the microsecond (1.259335 and 1.259337 s). Linux's three counted runs of the first command gave 1.233, 0.693 and 0.566 s; the table takes the last, and the extra instructions of the first two, probably work left from its boot, were not traced.

| Measure | Rach2 before | Rach2 after | Linux |
|---|---|---|---|
| 400,000 one-byte reads and writes, TCG | 2.81 | 1.78 | 0.60 |
| the same, counted instructions | 1.776 | 1.259 | 0.566 |
| one-byte pipe, 100,000 bytes, TCG | 2.04 | 1.31 | 0.38 |
| the same, counted instructions | 1.039 | 0.752 | 0.367 |

Before is 9f94e5c5f, the milestone branch where this task began; Linux's pipe figure is the median of the six lines of its three runs. In counted instructions a call of the first command costs Rach2 1,574 against Linux's 708, of which dd's own code is some 130 in each. That leaves 1,444 in Rach2's kernel against some 580 in Linux's. A byte through the pipe costs 7,520 against 3,670. Under plain TCG the gap is wider than in instructions, three times against 2.2: a Rach2 write runs seven POPF, one in each `kirq_restore`, and each ends QEMU's translation block, where Linux's path turns interrupts on with one STI and off with a CLI and restores no flags.

## Where the rest goes

The block log of the final kernel, one write of /dev/null, 1,345 instructions in the kernel (a read of /dev/zero is 1,522):

| Part | Rach2 | Linux's counterpart |
|---|---|---|
| entry, to the table's function | 345 | entry_SYSCALL_64 to do_syscall_64's call (arch/x86/entry/entry_64.S:87-121, arch/x86/entry/common.c:76-90) |
| the call's choice of lock | 160 | none |
| the call | 426 | ksys_write and vfs_write (fs/read_write.c:663-743) |
| exit, to `sysretq` | 414 | syscall_exit_to_user_mode (kernel/entry/common.c:180-221, include/linux/entry-common.h:317-336) and the SYSRET test (common.c:91-129) |

The entry. `syscall_entry` builds an interrupt's frame and goes through `_isr_router`, which reads the TSC for the CPU time account (`arch_cycles`); `syscall_entry_locked`, which decides whether the call runs without the big lock; `bkl_frame_push` and `bkl_frame_top`, which record the frame on the big lock's stack, each with its interrupts saved and restored; `bkl_note_entry` and `bkl_entry_push`; and `_syscall_handler`, which marks `in_syscall`, turns interrupts on, asks `bkl_held` with interrupts saved and restored again, and tests the tracer's and seccomp's flags. Linux's entry saves the registers, turns interrupts on and tests one word of work flags (entry-common.h:190-202). The big lock's per-call frame bookkeeping and the cycle account have no counterpart in Linux, which keeps no big lock and charges time on the tick.

The choice of lock and the call. Rach2 decides at each call what Linux decided at open and keeps in `f_mode`. `fd_write_lock` looks the descriptor up and asks `file_vfs_unlocked`, `file_rw_unlocked` and `devfs_fd_moves_offset`; `write_fd` looks it up again and checks the end of the transfer against 2^63-1 (`rw_offset_end`), which for a device compares the device's operations with each table that has an offset: `devfs_fd_is_raw` twice, `devfs_fd_log_size`, `devfs_lseek_zero`, `procfs_is_mem` and `devfs_fd_is_mem`, 163 instructions; `ops_offset_held` asks `devfs_fd_moves_offset` again. Linux's `ksys_write` looks the descriptor up once (`fdget_pos`), takes the offset only when the file is not FMODE_STREAM (`file_ppos`, read_write.c:695-699), and `rw_verify_area` reads FMODE_UNSIGNED_OFFSET (read_write.c:448-469), all bits that open set. Linux's call has work Rach2's has not: `security_file_permission` and `fsnotify_modify`. Keeping these answers in the descriptor at open would leave one lookup and a few bit tests.

The exit. `_syscall_handler` translates a restart, tests the loopback ring (`ip_loop_pending`) and a switch it owes (`sched_take_preempt`); `isr_router_locked` pops the big lock's entry; `smp_call_end` reads the TSC again for the account; `isr_leave` pops the big lock's frame, runs `signal_return_work`, whose `sig_pending_now` saves and restores interrupts three times and asks `bkl_held` twice, then `debugreg_resume` and `waketime_return`; `syscall_entry` then makes the SYSRET test. Linux reads the work word once (common.c:180-200) and the thread flags once (entry-common.h:326-328), and a pending signal is a bit in those flags.

The pipe. A one-byte pipe write was 2,138 instructions before 91d520298, which took the wake of the pipe lock's empty queue out of it. Besides the parts above, `sleep_lock_take` stamps the start of each hold with `timer_now_us` for the record of holds that cross a disk wait (/proc/fs/lockwait): about 150 instructions in the clock's functions, with a spinlock and a save and restore of interrupts besides. Linux's `mutex_lock` without contention is one compare-and-exchange (kernel/locking/mutex.c:166-175) and times a hold only in lock_stat, a debugging option. The wake of the readers' queue at each byte is Linux's too, since `pipe_write` wakes the readers when the pipe was empty (fs/pipe.c:601-602), which in this test it nearly always is.

What is left is the entry and exit, 759 instructions, more than Linux's whole call of some 580, and the choice of lock and the per-call classification of the descriptor, some 370 (160, 163, and the second lookup's 51), where Linux tests a few bits of `f_mode`. The first is the big lock's frame bookkeeping, which every system call and interrupt shares and which goes only with the big lock itself; the second is the descriptor's types, which would gain a set of mode bits set at open.

## Other findings

`threadmusl`'s row `two-execs`, run by hand from the debug shell of the test image, fails with `two execs at once: errno 11` on the kernel before this task as on the one after, so the change did not cause it; the row was not traced further here.
