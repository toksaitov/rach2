# 84-61: Unix sockets without the big kernel lock

The Unix socket layer now keeps its state, receive queues, names and descriptors in flight under its own locks. Its file operations and the native and i386 socket entries run without the big kernel lock; the socket dispatcher takes it for another socket family alone. The [IPC Readme](../../rach2/sys/ipc/Readme.md#unix-sockets) gives the contracts and Linux 6.12.115's corresponding locks and lines. The [process Readme](../../rach2/sys/proc/Readme.md#locking) places them in the kernel's lock order.

## QEMU measurement

Measured on 2026-11-12, ending at 23:26 UTC+6. The committed [before](84-61/before.txt), [after](84-61/after.txt) and [lockdep](84-61/debug.txt) outputs retain every loop's counters and result. The complete serial logs, driver and QEMU commands are kept under `build/runs/4736-final/` in the Codex worktree.

The baseline kernel is the milestone branch at b3ef47abf. The converted kernel is task/4736 at b9a7c38cd, with the same milestone code. Both booted the same prepared GNU root on the testing host under KVM, four processors, 8 GiB, virtio-vga and llvmpipe (LLVM 19.1.7, 256 bits), with QEMU's `-snapshot`. The command was `trip.sh -u desktop -r llvmpipe -n 3 /tmp/trip-4736`. Each loop makes 1,000 GL round trips. Both kernels completed the three plain loops, the strace summary loop and the ioctl trace loop, returned status 0 and powered off. Every loop reported zero wrong pixels.

The same corrected trip.py collected both sides: each snapshot reads all syscall, vector, take and slept rows from debugfs's `bkl/calls`. `/proc/stat` contains only its top 16 cumulative held entries, whose absence cannot be treated as zero. A new row starts at zero only when both snapshots have the complete table. The disposable guest mounted debugfs with mode 0755 for the desktop user's snapshots, checked that the counter was readable, and restored mode 0700 before poweroff.

There were no resumed holds attributed to recvmsg, sendmsg or writev on either side's plain loops. The remaining seven recvmsg holds on each converted loop are counted across the whole system; the table does not identify their socket families. The conversion removes the sendmsg and writev entry holds in these windows and nearly all recvmsg entry holds. The varying timings and waits do not establish a speed gain. Most of the remaining resumed holds belong to clock_nanosleep, as 84-54 found.

The strace summary loop took 3153.0 ms before and 3037.7 ms after; the ioctl trace loop took 2805.2 and 2807.2 ms. Tracing forces the syscall entry to hold the big lock, which a Unix operation drops and restores, so these are separate modes, not plain-loop speed figures.

## Verification

The same converted head built as `rach2-lockdep` completed all five modes with zero wrong pixels and powered off. Its plain loops were 88.0, 79.5 and 75.9 ms, its strace summary loop 3460.5 ms and its ioctl trace loop 3386.5 ms. The checker remained on: 92 classes, 202 direct dependencies, 496 chains, zero reports and zero reports not made. The kernel is 3,602,592 bytes. No boot in this final comparison printed a user page-fault kill or panic.

Both kernels compile and link. The new focused rows cover whole-vector Unix writes, copying a descriptor while its source closes, signal handling during an interruptible mutex wait, and an unrelated wake during poll enrollment. The enrollment rows force a ROOM wake and a wake of no kind immediately after filing a poll record: the old ordering attempts to sleep with its record removed, and the fixed ordering preserves READY and retries. Only the new rows were run by their author; no suite or existing host-test row was run for this task. The manager's review and checkpoint remain the milestone's proof.

The poll correction publishes BLOCKED before enrollment, and never overwrites a concurrent READY afterward. Signal and rseq return copies run with interrupts enabled, with timer preemption deferred across that return work. The allocated descriptor-table and fs-state locks have classes, and nested unpublished ext2 and VFS child nodes have subclasses. These changes are carried by this task along with the socket conversion.
