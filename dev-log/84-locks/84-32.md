# 84-32: DRM entry without the big lock

The native and i386 ioctl paths now admit a table marked `FILE_OPS_UNLOCKED` by that flag alone (`file_ioctl_unlocked`). A held device descriptor keeps the device alive, and the ioctl touches neither its retained file-system inode nor its description offset. Its last release still uses `file_ops_unlocked` and takes the big lock for that inode. FIONBIO still takes the big lock to change the description, and FIOCLEX and FIONCLEX still change the slot under the descriptor-table lock.

## The row audit

Linux 6.12.115's [`drm_ioctl.c:728-746`](https://github.com/gregkh/linux/blob/v6.12.115/drivers/gpu/drm/drm_ioctl.c#L728) checks permission and calls the handler without a global lock; lines 762-857 do the copies around it. Its syncobj rows are lines 646-671, and its i915 rows are `drivers/gpu/drm/i915/i915_driver.c:1688-1747`. Rach2 retains `DRM_UNLOCKED` while converting the remaining drivers. No upstream fault was found.

* Every syncobj row is unlocked. The handle table's spinlock holds the reference lookup, as Linux's [`drm_syncobj.c:247-262`](https://github.com/gregkh/linux/blob/v6.12.115/drivers/gpu/drm/drm_syncobj.c#L247); each object's spinlock guards its fence and submission lists, as lines 266-289 and 371-396; references are atomic. Fences guard callbacks with their own locks, and a wait removes its callbacks before freeing its records, as Linux's array wait at lines 1118-1187. Different fences may call the same waiter's wake on different processors, so its shared event counter now increments with compare-and-exchange.
* VERSION and GET_CAP read immutable device identity and configuration; GET_STATS and the compatibility no-op and invalid-operation handlers have no mutable state. They are unlocked. Permission checks that read the master role still take the big lock. GET_UNIQUE, GET_MAGIC, GET_CLIENT, SET_CLIENT_CAP, SET_VERSION, AUTH_MAGIC, SET_MASTER and DROP_MASTER retain it for shared file and master state.
* Every KMS row with `DRM_MODESET_LOCK` is now conditionally unlocked, as WAIT_VBLANK already was: only a driver setting `DRIVER_KMS_UNLOCKED` omits the big lock. The mode mutex serializes its object and framebuffer lists, properties, probes and commits. i915 is the driver that opts in; its display hooks use the GEM mutex and event, vblank, backlight and hardware locks as well. A legacy driver's hooks keep their old guard. Dumb-buffer, core GEM and PRIME rows still hold the big lock because they can call legacy allocation, open, import or final-release hooks whose state has no lock of its own.
* Every i915 row is unlocked. Buffer wrappers hold the GEM mutex for pages, tiling, cache domains, mappings, placement and bindings, with waits dropping and retaking it; EXECBUFFER2 takes it between its copies. BUSY uses the handle and reservation locks, MADVISE the reservation and GEM locks. Contexts use the per-file mutex and GEM mutex, and THROTTLE holds a request reference obtained under the context and engine locks before waiting, as Linux's `gem/i915_gem_throttle.c:53-93`. REG_READ uses forcewake's uncore lock. The display lookup holds the mode mutex. GETPARAM and QUERY initialize topology under the GEM mutex, also used by context creation, before reading the immutable result. USERPTR registers its notifier under the address space's page-table lock; the legacy MMAP installs its mapping under the address space's write lock. Neither needs the big lock around the dispatcher.

The dispatcher still gives back an inherited big-lock depth for an unlocked row, across both copies and the handler, and restores it on every return. A tracer or a kernel caller can supply that depth. `drm_core_hosttest` retains the locked-row, inherited-depth and permission rows, counts one take for a locked handler and none for an unlocked render handler or SYNCOBJ_WAIT, and checks the real GETRESOURCES row with the driver opt-in off and on. `open_hosttest` checks that an unlocked device ioctl with a retained inode is admitted while its last release and an unmarked ioctl remain locked; `i915_gem_hosttest` checks the whole driver's table.

## The release measurement

The native cases `games/supertuxkart` and `games/0ad` use `tests/system/games/lenovo.sh` to save `bkl/calls`, `/proc/stat` and `/proc/uptime` on each side of the replay. They raise the GPU minimum to 1000 MHz and restore it on exit. They subtract the snapshots without resetting the counters, include kernel-thread entries, exclude the `take` rows from waits in entries, and exclude the duplicate ioctl rows from both sums, as 84-25's reading does. `/proc/stat` is in USER_HZ, 100 ticks a second. Each game prints held time as a share of wall time, waits in entries as a share of user plus system time, idle-take waits and system/user beside 84's bounds, then its existing frame figures. It also prints all six raw snapshots into the native case's retained output before its workspace is removed. Missing counters, read failures or an invalid window fail the case. The existing frame judgment stays; the lock figures and raw frame times supply 84-7's release reading.

## Build

Both kernels linked with `make -j8 ARCH=i686 rach2` and `make -j8 ARCH=x86_64 rach2`. The x86-64 kernel is 3,518,432 bytes against 4,194,304. The x86-64 link has the existing ACPICA missing `.note.GNU-stack` warning. No test or boot ran for this task; the new host rows and native measurement await review and the release.
