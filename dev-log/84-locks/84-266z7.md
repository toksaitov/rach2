# The Lenovo's piglit setup skips

The 1,035 skip-to-pass differences of `gpu/piglit-rest` reported in task 5223 come from the reference's setup. Both the reference and the root pin Mesa 25.0.7-2+deb13u1 (`tests/graphics/ref/lenovo/Readme.md` and `vendor/gnu/debian/mesa.list`); Mesa 26.1.6 is staged for Venus alone, not Crocus or hasvk.

## The compiler skips

Step 9's original `tests/graphics/ref/lenovo/piglit/results.json.bz2` has 1,032 `spec@ext_gpu_shader4@compiler@...` tests and `spec@ext_texture_shadow_lod@compiler@negative_compile.frag` with all these fields:

* `result`: `skip`.
* `out`: `Test requires extension GL_EXT_gpu_shader4 which is not available`.
* `returncode`: null.
* `pid`: an empty list.

These tests never started. Piglit 0.0~git20250409.af62c0dea-2's `framework/test/glsl_parser_test.py:115-136` selects the core profile for a desktop GLSL version without the word `compatibility`. `framework/test/opengl.py:72-92` checks the required extension in that profile through `framework/wflinfo.py:211-246`. EXT_gpu_shader4 is a compatibility extension; a core-profile extension query does not determine whether a GLSL 1.10 test can use it. The same original run passed the executed `spec@ext_gpu_shader4@bindfragdatalocation mixed-int-float-fbo` with `Testing GL_EXT_gpu_shader4.` in its output. Rach2's `piglit.sh` sets `PIGLIT_NO_FAST_SKIP=1`, so the compiler tests run and test their own requirements.

## The display skips

The original `spec@egl_ext_client_extensions@conformance test 3` skipped with `Failed to initialize default display`. `spec@egl_ext_surface_compression@create` skipped with `piglit: error: failed to connect to Wayland display` and `Can't connect to display` on stderr. `piglit.sh -p gbm` sets `EGL_PLATFORM=surfaceless`; step 9's original run did not. These skips say nothing about a new EGL extension.

## The expectations

`lenovo-expect.py` recognizes these skips by their original result fields and exact diagnostics, after applying the recorded reruns. Only rows still marked skip become `skip-or-pass`. `judge.py results` requires either skip or pass for that token; missing results, fail, crash and other outcomes remain failures. Every original pass and every other skip keeps its rule. The compressed expectations are generated again from the original JSON, which is unchanged. No suite, host test or style check was run for this release fix.

## The semaphore failure

The original Linux `spec@ext_external_objects@vk-ping-pong-multi-sem` failed with `Data mismatch!`; `piglit/rerun/results.json.bz2` passed it. `dev-log/76-graphics/research/run2/step9.md`, under piglit, records that it failed beside other work and passed alone. The manager moved that question to task 5224 while this task ran. A separate change on the milestone branch keeps the first run's failure because the native case also runs tests concurrently; this task preserves that change.
