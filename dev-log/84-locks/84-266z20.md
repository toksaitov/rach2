# Vgem at DRM startup

Task 5236 takes the vgem skips in the Lenovo's native `gpu/igt-kms.8` and `gpu/igt-gem.2` at f8104921a. The runs' own output is in the main clone's `build/tmp/lenovo-igt/5380f1ecd49300cf` and `build/tmp/lenovo-igt/a421e4f49d1db6a8`. The first run's record lists only `card0`, i915. `kms_prime@basic-crc-vgem` skips at `second_fd_vgem >= 0`; `gem_wait`'s `await`, `write-busy` and `write-wait` report no device for chipset flags `0x4 (vgem)`.

## The cause

The driver was already on the branch, added before the failed run in 3fa13a5c0a: dumb buffers mapped write-combined, PRIME export and import, and FENCE_ATTACH and FENCE_SIGNAL with a ten-second timeout. `drm_start` called `vgem_probe` after the display probes, but `vgem_probe` returned `ENODEV` without `rach2.vgem` on the boot line. The native run therefore had no vgem node to open. Linux's reference loads the vgem module on demand; the Rach2 driver is built into the kernel.

Linux 6.12.115's [vgem_drv.c](https://github.com/gregkh/linux/blob/v6.12.115/drivers/gpu/drm/vgem/vgem_drv.c) and [vgem_fence.c](https://github.com/gregkh/linux/blob/v6.12.115/drivers/gpu/drm/vgem/vgem_fence.c) were read for this task. Its module initialization registers a platform device and the DRM device, with no hardware probe. The existing Rach2 driver has the same identity and buffer and fence interfaces.

## The fix

Vgem now registers at DRM startup without a boot option, after the display devices, so their card indices stay the same. The old `rach2.vgem` word is harmless. Registration allocates the device and publishes its nodes; buffers and fences are made only by a caller. The driver has no modesetting feature, and `drm_client_dev_register` leaves such a device out of the console.

The 21 vgem expectations again require Linux's passes: the two `kms_prime@basic-crc-vgem` rows, `gem_busy@close-race` and the 18 `gem_wait` rows under `await`, `write-busy` and `write-wait`. The expectation generator no longer defers the PRIME rows. The hybrid rows keep Linux's skips: a software GEM provider does not supply a second display device.

## Building

Both kernels linked on the Mac with `make ARCH=i686 rach2` and `make -j6 ARCH=x86_64 rach2`. Their files are 3,287,520 and 3,793,440 bytes, respectively. `lockstressmusl`'s changed diagnostic compiled for both architectures against the main clone's installed musl. No test, suite or trial boot ran in this task; the task's instruction reserves the proof for the Lenovo rerun after the change lands.

The trial needs no new register sequence, interrupt handler, DMA path or hardware wait: it enables the existing software driver's registration. The existing host rows in `drm_prime_hosttest.c` cover its buffers, shared reservations, fence calls, timeout and close; they were not run here. The manager's go and the Lenovo's rerun remain due.
