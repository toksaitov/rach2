# 84-147: one 250 Hz tick

Both architectures use a 250 Hz scheduler tick on physical machines and in guests. `TICK_HZ` has one production default, with no CPUID choice of rate. The APIC, PIT, clock reference, NTP interval frequency and CPU accounting all use the same 4 ms unit. USER_HZ remains 100, as on Linux. This builds on 80-97's stopped idle tick and the merged 80-112 pipe changes.

## The conversion audit

[tick-uses.md](84-147/tick-uses.md) lists all 151 direct occurrences of TICK_HZ in 59 kernel files, with each line's disposition. The additional searches covered TICK_NS, TICK_US, kernel_ticks, rtc_ticks_now, millisecond divisors and numeric tick intervals. Linux 6.12.115 in `build/research/linux-6.12.115-full` supplied the reference: `kernel/time/time.c` for jiffies_to_clock_t and milliseconds, `include/linux/jiffies.h` for upward timeout conversion, and `kernel/time/itimer.c` for the real interval timer's independent hrtimer.

* `tick_clock` divides seconds and the remainder separately, scaling the remainder before division. Dividing by TICK_HZ / USER_HZ would truncate 2.5 to 2 and overstate CPU time by 25 percent. The quotient-first form also handles a full 64-bit tick count without an intermediate product overflowing.
* `tick_centisecs` multiplies the entire hundredths value before dividing and rounds up. It replaces the truncated factor in the lag device and both writeback intervals. A hundredth is alternately two or three ticks, not always two. Millisecond conversion also rounds up without overflowing a 32-bit product.
* DMA fence waits, sync-object waits, virtio GPU reply waits and i915 engine waits converted nanoseconds or microseconds to milliseconds and then used that number as ticks. They now convert directly to the actual tick unit. The DRM console and i915 debugfs wait use upward conversion too.
* IPv6 reachable, retransmit and MLD intervals round milliseconds up. The HDA jack interval rounds 250 ms up to 63 ticks. Audio diagnostics scale the sample count before division instead of truncating the sample rate divided by HZ.
* TSC synchronization retains its 100 ms rendezvous bound and 2 ms sampling windows. The APIC's early allowance stays 62.5 us and its long-gap threshold stays four seconds. Calibration counts and clock interpolation scale with the actual tick length.
* Second-based protocol lifetimes, block request deadlines, watchdog thresholds and iTCO countdowns scale by HZ. Tenths for VTIME and network maintenance, and fifths for the console backup, divide 250 exactly. Counter-to-time remainders use TICK_US or TICK_NS; KVM's TSC rate and PMU frequency use the calibrated counts per actual tick.

## Fine timing

| Mechanism | Behaviour at 250 Hz |
|---|---|
| Scheduler slice and wake preemption | A competing local thread arms a one-millisecond slice event. The existing 0.75 ms protection against an early device interrupt and the wake/priority reschedule requests remain. RR interval readback stays one millisecond. A single runnable thread arms no repeating slice event. |
| nanosleep, clock_nanosleep, futex, poll, select and epoll | Their absolute nanosecond deadlines and owner events remain; the whole-tick deadline is the fallback and never expires a fine wait early. |
| timerfd and POSIX timers | Nanosecond expiry, interval, phase and owner events remain. Signal posting retries in one millisecond if the big lock is busy. |
| Real itimer and alarm | Real timers now keep monotonic nanosecond deadlines and intervals instead of rounding to ticks. Getitimer reports microseconds. Posting stops the timer until its SIGALRM is taken, then rearming preserves the original nanosecond grid. Exec copies the unit flag with the timer. CPU-time itimers retain accounting ticks, now 4 ms, as HZ=250 CPU accounting does. |
| Boot processor polling | A one-tick service request gets an independent one-millisecond event. Longer requests retain their stable whole-tick conversion. USB and keyboard repeat read elapsed monotonic milliseconds, including calls between coarse ticks. Retry after a busy big lock remains one millisecond. |
| Watchdog | Absolute monotonic sample deadlines and elapsed sampling remain independent of HZ. CPU-frequency and seconds conversions use the actual rate. |
| KVM guest timers | APIC, PIT and Hyper-V guest expiries remain in nanoseconds. The unknown-TSC polling fallback remains one millisecond. The halted vCPU's coarse fallback uses the actual tick length. |
| i915 forcewake | The merged uncore still releases immediately and has no tick-rate dependency. The separate forcewake change and its idle-service integration are on 84-58 and 84-58a. The manager was told that their release must use nanoseconds or a millisecond event; one or two ticks now mean 4 to 8 ms. |

A machine with no local APIC event timer or no independent clock still uses the periodic fallback. Its resolution is now 4 ms, as its clock_getres reports. The documentation and manual pages state the new coarse unit and the independent real timer.

## The timing rows, read only

No existing suite or host row ran. The source reading covered `timeprobe.c`, `pollprobe.c`, `futex2probe.c` and `futexvprobe.c`, `tests/musl/cputimemusl.c`, `schedmusl.c`, `pollmusl.c`, `timerfdmusl.c`, the poll deadline model, the process timer model, the APIC calibration model, and the clock/NTP models.

The guest timeouts are expressed in seconds and nanoseconds or milliseconds and reach the fine deadline paths above. CPU-time rows compare USER_HZ from times with getrusage and wait4 timevals, so fractional conversion must precede truncation. Scheduler interval readback stays one millisecond. The CMOS and NTP literal-answer models deliberately keep their 1000 Hz fixture through an explicit compile flag; their hand-computed answers retain that meaning. A new NTP model exercises the production 250 Hz rate. APIC event rows now express their phase and count answers in the actual tick unit, with a separate physical/guest common-phase row. Input, USB and scheduler models supply the independent fine clock or timer interfaces, and the lag model converts complete hundredths values.

## Proof

Both kernels compile and link. Only this task's new checks ran:

* [tick250.c](84-147/tick250.c) checks fractional CPU-time conversion, upward hundredths and milliseconds, timespec boundaries and full-width inputs.
* `ntp250_hosttest` checks a 4 ms unit, ten seconds of raw time, a 100 ppm frequency slew and the first PLL correction. It passed.
* `process_timer_hosttest --fine-alarm` checks expiry without advancing a coarse tick, nanosecond readback, posting, phase after late signal consumption and units across exec. It passed; its existing rows did not run.
* [probe.c](84-147/probe.c) is a private freestanding PID 1. Its four-processor [i686](84-147/boot-i686.log) and [x86-64](84-147/boot-x86_64.log) TCG boots use the PM reference with HPET disabled. Both reported 4 ms coarse and CPU resolutions, matching one-second CPU-clock and USER_HZ readings, all 128 one-millisecond sleeps shorter than a full tick, a 700 us select, a 250 us periodic timerfd and a 500 us real interval timer. Both printed TICK250 OK and powered off.

The short-wait times are measurements, not a host-speed pass condition. The probe checks that sleeps do not return early, timerfd counts elapsed periods and the real timer posts its signal. No standalone style checks or CI ran; the git hooks ran normally.

## Failures in this work

These are this worker's failures, from its command output, shown in the session before this record was committed.

* The first probe compile omitted the freestanding flag, so GCC recognized a loop as strlen and the link lacked that symbol. Adding -ffreestanding fixed the command before either boot.
* I created the new host scratch directory as root; the unprivileged upload failed with permission denied. I corrected only that new directory's owner and repeated the upload.
* The first histogram used common_comm as a filter field. The kernel rejected it with Field not found. The source defines comm as the synthetic filter field; changing it fixed the setup. The failed VM was terminated and reaped and its admission claim was gone before the retry.
* I moved histogram creation to the owned instance but initially left removal pointing at the old global path. The first Linux setup then reported File exists. Creation and removal now use the same owned path; the stale owned histogram was removed before the retry. That VM was also terminated and reaped and its claim cleared.
* The first new NTP link supplied RACH2_HOST_CPU unnecessarily and lacked the host_cpu fixture. Removing that unused flag matched the existing NTP model's compilation and the new row passed. Its result initially named the wrong failure variable; a follow-up commit corrected it before that compile.
* Hooks rejected nesting in the enlarged timer pass and a long metadata comment. The alarm pass was split into a helper and the metadata wrapped. The later hooks passed.

No fault in another project's code was found.
