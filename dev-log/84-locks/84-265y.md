# 84-265y: Firefox's texture filtering page in machine.virgl.webgl-firefox-webgl2-04

The release's rerun failed `machine.virgl.webgl-firefox-webgl2-04` on x86_64 with one page worse than Debian's: `deqp/functional/gles3/texturefiltering/3d_combinations_10.html` passed 1,262,547 subtests where Firefox's reference, taken under NVIDIA's driver 621.01, passed 1,262,605. Two runs of the same chunk in the Debian guest under the present driver, 621.24, both give 1,262,547 on that page, so the count follows the driver as Chromium's chunk 4 does ([84-265t](84-265t.md)), and Rach2 behaves as Linux does. Firefox's chunk 4 reference is taken again from the first of them.

## The runs

Both ran `sh tests/graphics/runners/debian.sh webgl -p virgl -c 8 OUT -b firefox -v 2.0.1 -g -x /tmp/runners/webgl-virgl.omit 04`, the arguments of the reference's `record`, from the milestone branch at f01dc0273, with the reference's Mesa 25.0.7-2+deb13u1, Firefox 153.6.0esr and Weston 14.0.2, under the same QEMU, virglrenderer and host Mesa, on 621.24. The first ran from 00:54 to 01:30 UTC on 2026-11-15, the second from 01:31 to 02:03; each started when fewer than two other loop guests ran on WSL, and its `record` lists the claims that ran beside it. Each gives 130 pages passed and 120 failed, as the reference does, with 2,355 subtests failed against its 2,356.

`texturesize` passes one subtest more under 621.24 in both runs; every case it fails says "Got unexpected texture size". Chromium's reference under 621.01, Chromium's Debian run under 621.24 and both Rach2 Chromium runs of 84-265t pass 823 there, so the change is Firefox's under the new driver. The new reference holds 824: if Rach2's Firefox passes fewer, the judge reports it, as it should against Linux under the same driver.

The texture filtering pages move from run to run under one driver, as 84-265t found in Chromium's; `tests/graphics/runners/webgl-virgl.flakes` names the directory's "Image verification failed" from 84-265t on, which keeps those counts from failing the case.
