A comment-stripped token comparison proved the code equal to `HEAD`; `make verify-style`, `make verify-host`, the affected component's build, and a boot where applicable checked the result. ## Purpose

Every file written for Rach2 should read as if one careful author wrote it. The tests, KRFFS host tools, utilities, and ish shell receive the same treatment as the kernel: Doxygen headers, no restating or diary comments, terse prose, and documentation of the current contract. These phases also correct inconsistencies found in the previously revised kernel and documentation. They extend the checks that had missed a non-ASCII byte and two diary tags.

## The standard

`CLAUDE.md` is normative. A Doxygen `/**` block before a non-trivial function contains a one-line brief, the contract, and the non-obvious reason. Use `@param` and `@return` only when their meaning is not plain. Trivial getters and thin wrappers stay bare. An in-body comment is limited to a one-line hardware or ABI fact or a deliberate hack. It must not restate the code, narrate a reasoning trace, or contain a development-diary "Phase N" or "Part N" tag. Prose is ASCII and terse, in the register of Kernighan, Ritchie, and Stevens, without promotional language. Documentation is not column-wrapped, uses `*` bullets, avoids bold, and uses tables only for aligned tabular data. Messages from the kernel and build tools use the `component: detail` form. User-facing program output, such as a utility's `Usage:` line or a probe's success token, is program behavior and remains unchanged.

## Method

The method follows milestone 3. Ultracode assigns one file or small area to each agent. An independent adversarial-review pass follows each result, and every finding is fixed.

* Each phase changes comments and docs only, never a code token. Prove it: a comment-stripped, string-aware token comparison of each edited `.c` and `.h` against HEAD must be identical (the throwaway `codeeq`-style script milestone 3 used; recreate it, it is a page of Python). A header banner, a `/**` header, a removed restating line, and a recast diary tag all leave the token stream unchanged.
* The kernel and freestanding tests build under `-Werror`; the host tools and host tests build with the host compiler; the utilities and ish link against the ported musl. The relevant build, `make verify-style`, and `make verify-host` must pass.
* Run a boot and the end-to-end SSH test when the changed code lies on those paths. The utilities, BusyBox, and Dropbear binaries are staged in the RAM disk and exercised during a boot. The KRFFS host tools build that RAM disk, and ish is staged as a guest program. `make verify-host` exercises the host tests, while a boot exercises the freestanding probes.
* Each phase ends with an independent Codex review and one scoped house-style commit without attribution. Every review finding is fixed before the commit. The review also covers prose, which automated checks cannot judge.

## What must not change (the contracts)

The review and the code-equal proof protect these; the plan names them so the work does not erode them.

* Every probe and musl-test success and failure token, verbatim, because the boot self-test and the harness read them as the contract: `VMPROBE OK`, `DEVPROBE OK`, `DIRPROBE OK`, `OFDPROBE OK`, `PIPEPROBE OK`, `POLLPROBE OK`, `PTYPROBE OK` and its parenthetical suffixes, `RNGPROBE OK (trusted)` and `(fail-closed)`, `SIGPROBE OK`, `TTYPROBE OK`, `WAITPROBE OK`, `COWPROBE OK`, `auxvprobe: ALL OK`, `MALLOC QSORT OK`, `CATFILE OK`, `PERMMUSL OK`, `MTTY OK`, and the rest, with their `FAIL` and count forms.
* The host-test contract: each `tests/host/*_hosttest.c` prints nothing and returns the failed-check count as its exit status; there is no `[PASS]`/`[FAIL]` token to add. The `host-deps:` line in each is a build contract that `tools/hosttest.sh` greps and feeds to cc; keep it literal.
* The inline-asm syscall numbers and the Linux i386 ABI in the freestanding tests, in `utils/resolv.c` and `utils/ping.c`, and in `ish/`: the `SYS_*` macros, the socketcall sub-call constants, `SC_PING = 0x1000`, the ioctl and termios constants, the register bindings, and the crt0 stack layout.
* The KRFFS v2 on-disk format: the magic `0x4B52`, the node-type order, the packed layout, `parent_id`, and the `krffs_mix_id` constant the host tools share with the kernel; and the dropbear staging contract in `stagetree.krffs.c` (`/etc/passwd`, `/etc/shells`).
* The freestanding and no-libc constraints (the `-nostdlib` links, the private statics in `resolv.c`, the `ISH_USE_STDLIB` toggle, the hand-rolled string and print helpers) and every build recipe and its flags.
* Every user-facing diagnostic string and exit code in the utils and the host tools, and the informal console output the legacy tests print and the Readme quotes.
