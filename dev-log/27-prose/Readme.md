# Milestone 27: reading every file

This milestone read every project-owned document and comment and compared each current claim with the code it described. `plan.md` defines the method; `worklist.md` records the order and status. This record lists false claims, comments that described development reasoning instead of the code, and code defects deferred to milestone 28.

The record was updated during the work so that an interruption would preserve the completed findings.

## Cross-checks to settle against code later in set one

These numeric and path claims required source files scheduled later in set one. Each document was revisited when its source was read.

* `Readme.md`, `tools/Readme.md`, `tests/Readme.md`: "eighteen smoke checks" remained to be compared with `tools/selfbuild_test.sh` during set two. The separate "29 utilities" claim was correct: `utils/Makefile` builds 19 `UTILITIES` and 10 `SBIN_PROGS`, totaling 29 programs.
* `rach2/Readme.md`: "over 100 syscalls" was correct. `syscall.h` defines about 111 `SYS_*` numbers, and `syscall.c`'s `init_syscall` dispatch table installs well over 100 handlers. The `cr3` field's "offset 52" was also correct: `process.h` places pid at 0-3, state at 4-7, eleven uint32 registers at 8-51, and cr3 at 52-55. "make subset-test boots six lines" was correct as well. The recipe at `Makefile:1018` loops over "", noaudio, nomouse, nonet, nodisk, and all four together, for six cases.
* `rach2/sys/network/Readme.md`: "all 61 probes" remained to be compared with `tools/runtests.py`.
* `rach2/Readme.md`: `gdt.h` sets `GDT_ENTRY_COUNT` to 7: null, kernel code and data, user code and data, TSS, and TLS. TLS occupies index 6, so the GDT has 7 descriptors. The Readme said "The GDT contains 6 segment descriptors", and its foundation table listed indices 0-5. It became "The foundation GDT has 6 segment descriptors (the TLS subsystem adds a 7th at index 6...)", with a reference to tls.Readme, so the foundation count no longer described the complete GDT.
* `krffs/Readme.md`: `make images` builds test, os-simple, and os-real at `Makefile:213`. Its "all three" statement was correct; the metal image is a separate target.
* `rach2/sys/block/Readme.md`: the predecessor of `DISKINFO_WINDOW_MAX_SECTORS` in `diskinfo.h` described 8388607 as "the last sector /dev/disk0 can reach". The value 8388607 is the last reachable sector index because its final byte is 8388607*512+511 = 4294967295 = 2^32-1, the largest value a 32-bit offset can name. block/Readme incorrectly treated 8388607 as a count in "the first 8388607 sectors"; that became "the first 4 GiB, through sector 8388607". Both block/Readme and `diskinfo.h` also said "the byte just past that sector is the largest one such an offset can name". The byte just past is 2^32, the first unnameable byte, so both became "that sector's last byte is the largest one such an offset can name".

## Noticed in the code, left for milestone 28

* `rach2/.gdbinit`: line 1 is `file kernel`, which loads `./kernel`, but build-directory unification described in milestone 22 moved the kernel to `build/rach2/kernel`. Because 0x1F is rarely sent to the console and the correction changes code, it was deferred to milestone 28.

The paths remain unique and the probe remains valid, but `snprintf("/bp%u", n)` would produce expected decimal names. This milestone corrected the stale "N < 10" comment and deferred the code concern to milestone 28.
