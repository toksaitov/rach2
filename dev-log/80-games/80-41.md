# 80-41: the games' kernel time, work per call against waits on the big lock

80-7b's runs on the Lenovo with the GPU's clock pinned at 1000 MHz (`80-7.md`, the first run of 11-11) spend twice as much system time as user time, wait 112 s on the big lock in 90 s of SuperTuxKart and 195 s in 150 s of 0 A.D., and hold it in DRM ioctls for 32 to 65 s a run. This task splits that time: what each hot call costs on Rach2 against Linux on the same machine, which is work to fix in this stack, and what is waiting on the lock while another processor holds it, which goes to the manager for the owner's decision on the lock. No lock change is made here.

## What 80-7b's build counts, and what it lacks

The trial build 1d49ce855 counts, since boot, each entry's holds of the lock and their time (`bkl_hold_entry` in `/proc/stat`, the 16 longest), the sum and the longest of the waits, and the oldest hold an interrupt has found with its stack. It does not count:

* the waits by the entry that waited, only their sum;
* the calls of each system call and their time from entry to return;
* the ioctls by request: every DRM call is one entry, system call 16;
* where the kernel spends its time under the lock: there is no profile.

Commit 1a5825c41 adds them in debugfs, `bkl/calls` and `bkl/profile` ([debugfs(5)](../../man/man5/debugfs.5), [the process subsystem](../../rach2/sys/proc/Readme.md)). Its changes are counters under the lock and a sample taken by the tick: no register of any device, no wait and no mapping. It picks clean onto 1d49ce855 and onto 261ab3ae5, 80-40's rerun build; on 1d49ce855 the kernel is 4,103,248 bytes, 91,056 under the slot. One boot in QEMU on the Mac (TCG, four processors, the os-real image, `ls -lR /` on each) filled both files: 26 system calls, the page fault and tick vectors and two ioctl requests counted, 17,763 samples and none lost, the hottest `krffs_memory_read` under `krffs_brief`; the times read 0 there, since TCG gives no invariant TSC, and are measured on the Lenovo.

The first takes the screen and plays SuperTuxKart's sound at volume 1; the second takes the screen, with no sound driver. Comment the notice on #3540 ten minutes before the first reboot:

### Reading

For each game, from Rach2's `calls` and Linux's `calls.txt`, both over the game's whole run:

* the time per call of each system call and ioctl request that holds the lock for more than 1% of the run: Rach2's `held_us / holds` and `wall_us / calls` against Linux's `@ns / @calls` and `@ins / @icalls`;
* the share of the run spent waiting: the sum of `wait_us` over the game's run against its length times the processors it kept busy, and `/proc/stat`'s `bkl_wait_us` between `stat-before` and `stat-after`;
* the user and system time: `/proc/stat`'s `cpu` line on Rach2, the game's `utime` and `stime` (fields 14 and 15, in clock ticks) between `pid-before` and `pid-last` on Linux, each over the frames of the run.

Rach2's profile by function, against the kernel the step booted:

```
K=$T/build/x86_64/rach2/kernel.debug
p=$R/out/supertuxkart/profile
awk 'NR > 2 { print $1, $3 }' $p > $R/pcs
x86_64-elf-addr2line -f -e $K $(cut -d' ' -f1 $R/pcs) | paste - - | cut -f1 | paste - $R/pcs |
  awk '{ s[$1] += $3 } END { for (f in s) print s[f], f }' | sort -rn | head -n 40
```
