# 80-117: histogram cleanup and nested EOI attribution

Review j121 found two faults. `kvmstat.py` now blocks SIGINT, SIGTERM and SIGHUP while it installs a histogram trigger and records the event for cleanup, then restores the previous signal mask. A pending cancellation runs only after the event is registered. Each interrupt router now keeps the initial paravirtual EOI word reading on its stack and passes it, with its frame's vector, to `lapic_eoi`. A nested interrupt or a handler's sleep therefore cannot overwrite either part of the attribution. The four existing local-APIC host rows use the new interface; no row was run.

## The compiled return

Subtask 80-117a closes j121's open question about 84-143 moving `isr_leave_work` into `leave.c`. Both kernels were linked at 84-129's last commit, `a0818d8d2`, and at this task's `325d89059`, which includes the two fixes and the milestone's intervening changes. Both cross compilers are GCC 16.2.0, using the kernel Makefile's ordinary `-O2` flags. No test or boot ran. The x86-64 link gave the existing ACPICA `utxfmutex.o` warning about its missing `.note.GNU-stack`, on both versions.

The counted path has a current thread, returns to user mode from an unlocked call, has no `WORK_EXIT` bits or dead threads, and has cycle accounting off. The assembly frame is unchanged, so x86-64 takes `sysretq`. Every instruction on that path is counted once, including calls, returns and the final `iret` or `sysretq`; padding and untaken branches' bodies are left out. `isr_leave_work`, now in `leave.c`, is never called on this path.

[The disassembly](80-117/return-disassembly.txt) keeps the instructions in execution order and each debug binary's SHA-256. It comes from each architecture's `objdump -d --no-show-raw-insn --disassemble=SYMBOL` on `kernel.debug`. The only difference in instruction count is x86-64's processor-table stride: the old `lea (%rax,%rax,8),%rax` and `shl $0x5,%rax` multiply by 288; the new `imul $0x128,%rax,%rax` multiplies by 296 in one instruction. The i686 register allocation and structure offsets changed without changing the count. Moving the helper added no instruction to this path and needs no performance fix.

The earlier figure is [84-115's author's traced 237.3 instructions per call for entry and exit together](../84-locks/84-115.md#where-the-instructions-went), from the one-byte read/write workload. The static counts here cover only the return from the assembly's call of `isr_leave` through the return to user mode; they exclude system call entry and dispatch. They establish that moving the helper preserved the no-work return, without claiming a new measurement of the whole entry-and-exit figure.
