# 80-97: the idle tick

The scheduler idle task stops its processor's tick and leaves the local APIC timer armed for the next event. A busy processor keeps the 1000 Hz tick. The event uses TSC-deadline mode where available and a measured APIC count elsewhere. A stale tick pending at entry to idle is acknowledged without running the scheduler tick. Wake-up advances the tick's phase past the idle span and accounts that span as idle and steal time before the next thread runs.

The boot processor's periodic services report their deadlines through `idle_timer.h`. Its idle entry programs the earliest service, sleep or timer; its wake catches the global clock up and runs the services. Busy application processors check for an earlier service on their tick, and once more before entering idle, and kick the boot processor when needed. Services which currently poll retain their polling interval as a one-shot service event. A second bounds reference-counter maintenance and NTP; the load average keeps its existing sample phase. Whole-tick sleeps and real alarms also arm events, and an event makes the clock's pass before expiring them. A deferred signal retries after one tick if its try for the big lock fails. There is no tick-dependent RCU grace period: KVM's SRCU waits on reader counts.

The new `timercal_hosttest --idle` rows passed: a stopped timer without work, a stale pending tick, a long one-shot event, a whole-tick deadline, restart at the next phase, and TSC-deadline programming and cancellation. The new `sched_hosttest --idle-only` rows passed: a remote idle and steal reading, catch-up once on wake, the first busy tick, and the load sample's phase. No existing test rows or suites were run.

[nohzprobe.c](80-97/nohzprobe.c) is the task's unattended boot check. It pins itself to CPU0, sleeps with every user thread blocked, checks the interrupt count and clock, then checks poll, futex, timerfd and a blocked real alarm and powers the guest off. Both kernel links passed. The task's QEMU boots and the Crysis load measurement are recorded below once complete.
