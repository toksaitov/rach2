# The file page cache on the Lenovo

Task 80-13 kept the pages a read brings in from ext2 in the file page cache, as Linux's page cache keeps them, and tried the change on the Lenovo on 2026-11-11 from 06:07 to 07:07 UTC+6. A second read of Objects.pak and Music.pak read nothing from the disk, where before the change Objects.pak read some 1,600 MiB each time and pushed Music.pak out. Of Crysis's two flybys with no reboot between, the second read 2 MiB during its level load against the first one's 762 MiB, but the load took 52.21 s against 51.69 s, so the load time did not improve. The readings are on the task's issue, #3446.

## The trial root

The Crysis launches ran on 76-17b's GNU trial root on the data partition, since 80-6's root was deleted with its task. That root carries GE's original `dinput8.dll` (`e2bce11b`), not 80-6's fixed one (`0bec4391`, from `vendor/gnu/proton/dinput-shutdown.patch`, commit 22052fe15), which, by the manager's reading of the two runs, is why both launches hung at their exit. A later Crysis step must not reuse that root as it is: it uses a root built after 22052fe15, or 80-12's.
