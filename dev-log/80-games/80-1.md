# The Proton game launcher

The launcher and its Direct3D 9 proof were completed on 2026-11-10, at 08:50 UTC+6. The implementation is `05d901db9`; the retained logs are under [80-1/](80-1/).

## Errors in the proof setup

Two errors were mine. The first QEMU command attached the read-only payload as an ATA disk, which QEMU refused before boot with `Block node is read-only`; the command was corrected to put a disposable snapshot over that payload too. In the boot that followed, the probe drew correctly and exited 0, but my log check's expression `d3d9.*native` matched the probe executable `d3d9.exe`, not a DXVK DLL. I corrected it to `d3d9\.dll.*native` and judged the retained log, without running the guest again. The outer command's result is therefore `exited 1`, from that assertion; it is not the probe's exit. Both errors and their corrections were reported in the worker's transcript before this record was committed.

## Configuration

The testing host ran QEMU 10.2.1 (Debian `1:10.2.1+ds-1ubuntu3.3`) under KVM, with `host,invtsc=on`, four processors, 8192 MiB, virtio-vga, no host display, and AHCI. The root was a private qcow2 overlay of the existing `gnu-test.disk`; the Direct3D payload was a snapshot of `build/tests/graphics/d3d/data.ext2`, mounted read-only in the guest. No system image was rebuilt for this shell change. The candidate launcher was copied to `/usr/bin/rach2-game` in that overlay with mode 0755. The kernel's SHA-256 was `dfaf0fd35676f4f04830432da3154b0bd8ba0cbc478a4a3324a469d2e9e2ff13`; the compiled probe archive's was `e91486ea8628f75f8c22d40872522d4a88ffc09a6a5c246b8bff60abc11ab42a`.

The guest used GE-Proton11-12, Xvfb from the Direct3D payload with `-noreset -screen 0 1280x800x24 -nolisten tcp`, and llvmpipe (LLVM 19.1.7, 256 bits). The ordinary account `test` ran both commands below, with a new compatibility directory. `GALLIUM_DRIVER=llvmpipe`, `LIBGL_ALWAYS_SOFTWARE=1`, `LP_NUM_THREADS=4`, a new private shader cache, `PROTON_USE_XALIA=0`, and `WINEDEBUG=+timestamp,+pid,+tid,+loaddll,+wined3d` were set for the proof. The Steam client directory and log directory were private directories of the run. Other work ran on the host; this measured no performance gate.
