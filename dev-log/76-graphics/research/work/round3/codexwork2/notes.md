Guest Linux server has PCI ivshmem device; Rach2 host has shared object+eventfds, NOT a PCI device or hardware interrupt from its guest. Build bounded Rach2 userspace ivshmem protocol peer and local ioctl binding fd refs into host virtio transport. Host queue submit signals guest peer's eventfd; QEMU injects MSI-X; guest driver handles MSI-X and wakes server. Guest completion writes doorbell BAR0+12 `(host_peer_id<<16)|vector`; QEMU signals host peer eventfd; host eventfd wait/callback completes queue. ioeventfd/irqfd are QEMU optimizations, not protocol custom PIO port.
