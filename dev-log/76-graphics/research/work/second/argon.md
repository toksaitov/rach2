* Task 74-9 flips only `DSPSURF` on the inherited GOP mode ([plan-v2.md:201](file:///Users/toksaitov/Desktop/rach2/build/flow/coordinator/graphics-research/plan-v2.md#L201)), which rejects or scrambles Crocus scanout BOs. Crocus allocates `PIPE_BIND_SCANOUT` BOs as `ISL_TILING_X` whenever `has_tiling_uapi` is true and reports `I915_FORMAT_MOD_X_TILED` ([crocus_resource.c:193-195](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/gallium/drivers/crocus/crocus_resource.c#L193-L195), [crocus_resource.c:941-942](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/gallium/drivers/crocus/crocus_resource.c#L941-L942)). ### 2. Aliasing PPGTT and Linux's command parser on Haswell

* The plan is right that Haswell needs both for safe multi-user rendering, and it misses a hardware ordering dependency between 74-5 and 74-7: on Gen7, the command parser's GGTT shadow copy is also what grants privilege for the register writes Crocus emits when `I915_PARAM_CMD_PARSER_VERSION` is nonzero.
* When `RING_MODE_GEN7` sets `GFX_PPGTT_ENABLE` ([intel_ring_submission.c:168-172](file:///Users/toksaitov/Desktop/rach2/build/research/src/linux/drivers/gpu/drm/i915/gt/intel_ring_submission.c#L168-L172)), 3D state and `PIPE_CONTROL` (`DestinationAddressType = DAT_PPGTT` on Gen7+, [crocus_state.c:8901-8903](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/gallium/drivers/crocus/crocus_state.c#L8901-L8903), [gen75.xml:2741-2744](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/intel/genxml/gen75.xml#L2741-L2744)) use PPGTT, while `ggtt_bo` in `crocus_store_register_mem32` and `crocus_emit_pipe_control_write` sets `EXEC_OBJECT_NEEDS_GTT` on the relocation without setting `UseGlobalGTT` in the instruction ([crocus_genx_macros.h:167-170](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/gallium/drivers/crocus/crocus_genx_macros.h#L167-L170), [crocus_state.c:497](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/gallium/drivers/crocus/crocus_state.c#L497)). Every VMA must therefore occupy the same offset in GGTT and aliasing PPGTT ([intel_ggtt.c:916-947](file:///Users/toksaitov/Desktop/rach2/build/research/src/linux/drivers/gpu/drm/i915/gt/intel_ggtt.c#L916-L947), [i915_gem_execbuffer.c:616-620](file:///Users/toksaitov/Desktop/rach2/build/research/src/linux/drivers/gpu/drm/i915/gem/i915_gem_execbuffer.c#L616-L620)).
* Haswell hardware ignores `MI_LOAD_REGISTER_*` to `OACONTROL`, `HSW_SCRATCH1`, `HSW_ROW_CHICKEN3`, `MI_PREDICATE_*` and `CS_GPR` (emitted by Crocus when `cmd_parser_version >= 2..7`, [crocus_screen.c:132-160](file:///Users/toksaitov/Desktop/rach2/build/research/src/mesa/src/gallium/drivers/crocus/crocus_screen.c#L132-L160)) when a batch starts with `MI_BATCH_NON_SECURE_HSW | MI_BATCH_PPGTT_HSW`. In Linux, `CMDPARSER_USES_GGTT` is true on Gen7 ([i915_drv.h:653](file:///Users/toksaitov/Desktop/rach2/build/research/src/linux/drivers/gpu/drm/i915/i915_drv.h#L653)): `eb_parse` copies the validated batch to a kernel GGTT BO and sets `I915_DISPATCH_SECURE` ([i915_gem_execbuffer.c:2345](file:///Users/toksaitov/Desktop/rach2/build/research/src/linux/drivers/gpu/drm/i915/gem/i915_gem_execbuffer.c#L2345)), causing `hsw_emit_bb_start` to dispatch with `security = 0` in GGTT ([gen6_engine_cs.c:258-266](file:///Users/toksaitov/Desktop/rach2/build/research/src/linux/drivers/gpu/drm/i915/gt/gen6_engine_cs.c#L258-L266)).
* Task 74-5 must report `I915_PARAM_CMD_PARSER_VERSION = 0` until 74-7 copies validated batches into GGTT and dispatches them with `security = 0` ([plan-v2.md:166-184](file:///Users/toksaitov/Desktop/rach2/build/flow/coordinator/graphics-research/plan-v2.md#L166-L184)).
