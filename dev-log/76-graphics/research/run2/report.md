# The second graphics discovery run

The second graphics discovery run measured, in eleven steps, what draft 5 of the graphics plan had left open: which engine the agents' graphics work should run on, what Linux's software and GPU paths give a guest in QEMU, what the test suites cost, what today's Rach2 lacks to run Debian's graphics stack, and the Lenovo's HD 4400 as the reference, alone, behind Venus in a VM and assigned to a VM through VT-d. Steps 1 to 8 ran on the testing PC, in WSL under KVM and TCG and on Windows under WHPX and TCG; steps 9 to 11, and 9b, a retake of step 9 with the IOMMU's DMA translation off, ran on the Lenovo under Debian 13.7, installed for the run on its p5. The owner ordered the run on 2026-11-08 at 20:05 UTC+6, and it ran to 08:46 on 2026-11-09, one agent per step. Rach2 itself was measured in steps 1, 7, 8 and 11: its boots and suites under each engine, Debian's graphics programs on its kernel, and its boot partition restored from the running system at the end. The run decided that the agents' graphics work stays in WSL under KVM while Rach2's suites stay on TCG, that the suites' Dones take the sizes and admission limit of steps 3 and 4, that decision A gains a fourth option (udmabuf as a module in WSL's own kernel), that decisions B and C keep option 1, that Crysis's speed (risk 1) is cleared under Linux at 44 to 46 FPS, and that assigning the GPU to a VM is a go. It also found that Linux's GPU numbers on the Lenovo change with VT-d's translation, glmark2 scoring 15 to 16 percent more with it off, so Rach2's native gates, Rach2 having no IOMMU driver, compare with the translation-off figures.
