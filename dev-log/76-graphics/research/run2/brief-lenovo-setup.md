# The Lenovo's setup: Debian 13 on the trial partition

The run's plan gives the Lenovo Debian on its trial partition for steps 9 to 11. Your task is to install it, boot it once from Rach2, and leave it running and ready for step 9, whose agent follows you in the same boot. Read `tonight/lenovo.md`'s "How it ran", `dev-log/70-wifi-chip/` on how Linux was booted there, the `machine` skill (`.agents/skills/machine/SKILL.md`) and `bootctl(8)` and `recovery(7)` under `man/`.

* The chat holds the Lenovo's lock, `build/flow/lenovo/issue` reading `run2`; leave it in place.
* The disk under Rach2: `/dev/disk0p1` the boot partition (vfat, 55 MiB free), p2 recovery, p3 Rach2's root (ext4, mounted at `/`; Crysis in `/opt/crysis/game`), p4 BIOS boot, p5 "Rach2 trial root" (32 GiB, unmounted), which is Debian's. Save p1's image to the Mac before any change, with its SHA-256; Rach2's own boot files must come back exactly when the Lenovo track ends, so write in the report how to restore p1 and how the last agent proves it.
* Debian 13 (trixie), amd64, Debian's own kernel and Mesa: choose the fastest sound way. Either Debian's generic cloud image (not `genericcloud`, which lacks hardware drivers), its root partition written to p5 with `dd` over SSH from the Mac and grown with `resize2fs`, configured by a NoCloud seed placed in the root; or debootstrap as root in WSL, niced (`nice -n 19 ionice -c3`), in `/home/testing/rach2/build/run2/lenovo-setup/`, since step 1's timings run on the same PC. Either way: the kernel and an initrd small enough for p1 on p1, root on p5 by its PARTUUID, the wired port by DHCP, `modprobe.blacklist=ath9k,snd_hda_intel` and no sound server, SSH for root by the development key's public half `krffs/rach2_demo_ed25519.pub` only, the backlight low, the clock synced, and the IOMMU left at its default (step 11 boots again with it on).
* Install what step 9 and step 10 need from Debian: Mesa's drivers and utilities, vulkan-tools, the glmark2 variants, weston, cage, seatd, chromium, firefox-esr, Google Chrome stable from dl.google.com, VA-API drivers and vainfo, ffmpeg, intel-gpu-tools, piglit if Debian has it, qemu-system-x86, virglrenderer and its test server, python3-websocket, curl, fio. Write the installed versions to the report.
* Boot it by the milestone 70 method: GRUB's `linux.mod` and a `boot.cfg` block keyed on `next_entry` that clears the key before booting Linux, armed with `bootctl trial`. The machine comes back to Rach2 only by `rtcwake -m off -s 120` from Linux, never by a warm reboot. A boot that does not answer SSH within five minutes: wait for the firmware's next try, then read why from the Mac; if the machine is left off, say so at once in your reply.
* Once Debian answers: record the machine as the first run did (kernel, Mesa, `eglinfo`, `vulkaninfo --summary`, `drm_info`, `vainfo`, `lspci -nnk`, `dmesg` for i915 and the NIC, `dmesg` for DMAR), and check that p3 mounts read-only. Leave Debian running, with nothing of yours running in it.
* Report as `run2/lenovo-setup.md`, ending with what step 9's agent needs: the address and SSH command, the users, where things are, how to leave Linux and how to restore p1.
