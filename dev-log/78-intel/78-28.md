# 78-28: netconsole's start, a held target and a panic in a send

Round 79z's review of 78-20 found six faults in netconsole. The fixes follow Linux 6.12, fetched from kernel.org at tag v6.12 for the line numbers cited here and in the code; the review's numbers were a few lines off that tag.

## The start

* Each sender, the frames and each target, begins with a start (`struct nc_start`), as `netpoll_setup` waits for carrier (net/core/netpoll.c:694-716): until the card's link is up, for at most `carrier_timeout` seconds, 4 by default (netpoll.c:61-62). The boot option is `netpoll.carrier_timeout=`, the name Linux's built-in module parameter takes. After the timeout the start is over, as Linux's "timeout waiting for carrier" is.
* The two-second settle of 78-20 now covers only a link seen up during the start with records held: the replay of the ring. A link seen up with nothing held ends the start at once. After the start a record is sent when written, whenever the link is up; a link that comes back after a flap is not held again, since Linux's live path asks only `netif_running` (drivers/net/netconsole.c:1214; netpoll.c:332).
* Records written during the settle wait behind the replay, so that the order is kept; they go out with it at most two seconds later.
* The boot processor's tick tries a drain every 10 ms while a sender is in its start (`netconsole_tick`), so the held records go out when the start ends, and not with a later record. `kernel_shutdown` calls `netconsole_shutdown` after the goodbye record and before it stops the cards, which ends every start and sends what is held, as a panic does.

## A held sender and the full ring

* When the ring is full, each sender furthest behind that is held loses its oldest record (`nc_make_room`), so that a target with no link or no address no longer stops the frames and the other targets. This is Linux's behaviour for a console behind the log buffer (`console_emit_next_record`, kernel/printk/printk.c:3049). Before any sender exists, and while a drain runs, the newest are dropped as before, which keeps the boot log.
* A record lost to a target is counted against it: the skipped records, and the runs of records the full ring dropped for all, which `nc_gaps` keeps with the place of the record after each. The extended form's `seq` adds the count, so it numbers the records written since the target began, as Linux's numbers each record (`info_print_ext_header`, printk.c:662-680), and a loss is a gap. The plain form gets `** N printk messages dropped **` before its next record, as `console_prepend_dropped` writes it (printk.c:2904-2906), in a datagram of its own.

## A panic in a send

* `k_panic` calls `netconsole_panic`, which clears `nc_sending` as `klog_deliver_directly` clears klog's guard. The frame or datagram the stopped send held is sent again, since its sender's place moves only after the card takes it.

## Documents

* `nc_source` said that Linux's `netpoll_take_ipv6` passes over a tentative address; Linux 6.12 has no such function, and `netpoll_setup` takes the first IPv6 address whose link-local scope matches (netpoll.c:719-756). Passing over a tentative or failed address is Rach2's own, and the comment and the network Readme say so.
* netconsole.h, netconsole(4), cmdline.md and the network Readme describe the start, the carrier timeout, the held sender's loss and the dropped line. The host test's tick stubs have doc blocks of their own above `net_lock`'s.

## Measured

* Compiled: the i686 and x86-64 kernels, and the netconsole and panic host tests with the host tests' flags. As the task orders, nothing else was run; the proof is the review and the end's runs.
* 78-28.7's carrier rows, run alone from a scratch driver that includes the host test, passed: the tick sends the held boot log when the carrier comes back, and at the settle's end, with no later record. Before the tick drove the start, nothing would have sent it.
* The host test's start rows replace the settle rows: the tick sends the held records at the settle's end, a flap after the start is not held, the carrier timeout ends a start, and a panic, shutdown and a panic in a send each send what is held. Its target rows give `eth0` an address, drive a target held for want of one beside the frames, and check the dropped line, the extended `seq` gap, and a gap from before setup.
