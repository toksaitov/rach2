# 78-26: kernel slots of 16 MiB

The manager's report of 11 November, 17:45: the x86-64 kernel at 997183044 was 3,969,496 bytes, 224,808 under the 4 MiB kernel slot of a boot partition, and had lost some 65 KB of headroom in an hour. A kernel over the slot fails its link. Linux has no fixed kernel size, since its kernel is a file on the boot partition written whole on each install; Rach2's slots are fixed-size files that `bootctl` rewrites in place, so the fix is slots large enough that the kernel's growth does not reach them for years.

## The size

* `BOOTSLOT_SLOT_BYTES` in `utils/bootslot.h` is 16777216, the one place the size is set. The kernel's link (`rach2/Makefile`) and `tools/image/mkdisk_grub.sh` read it from the header's define line, `BOOTSLOT_MAX_FILE_CLUSTERS` is derived from it (32768 clusters at 512 bytes), and `bootctl status` prints it as `bootctl: slot size: 16777216 bytes`, which `rach2-install` reads, since the installer runs on the recovery system with no source tree.
* 16 MiB is four times the x86-64 kernel of today and 5.2 times the i686 kernel, 3,246,932 bytes. Two slots, the 8 KiB menu, the environment block and GRUB's 802,816-byte EFI image fit a FAT32 volume of 40 MiB, which `mkdisk_grub.sh` now makes by default on either table and refuses to go below; the installed disks' 64 MiB boot partition has room besides for a grown slot's copy while `rach2-install --slots` moves an older disk. Larger slots would not fit that move: the fallback's step holds two new slots and the old fallback.
* The recovery kernel and its RAM image are on partition 2, not the boot partition, so the slot size does not bound them.
* The walk's directory chains, one per depth of the scan, moved from the recursion's stack to static storage, since each is now 128 KiB; `bootctl`'s kernel buffer takes a slot, and its menu buffers stay at 4 MiB.

## Older disks

* An installed disk has 4 MiB slots. `bootctl kernel` and `bootctl fallback` refuse a disk whose slots are smaller than `BOOTSLOT_SLOT_BYTES` (`bootslot_layout_current`) and name `rach2-install --slots DISK`.
* `rach2-install --slots DISK`, from the recovery system, refuses an armed trial, saves the machine to recovery, grows the candidate slot and then the fallback, and puts the saved default back. Each slot is copied beside itself as `kernel.new` or `fallback.new`, padded and compared with the slot and its padding; then the slot is removed and the copy renamed. The rename is not done over the slot: the FAT driver's rename onto an existing name frees the destination and the source's entries before it writes the new ones, so a stop between leaves a chain no name reaches (`rach2/sys/fs/fat32.Readme.md`). Renamed with the name free, in one directory, the copy's entries are rewritten in place. A stop thus leaves the slot or a whole copy, the recovery system starts, and the command run again finishes the rename or removes an unfinished copy.
* `rach2-install --update` grows the slots the same way, inside the window in which the update has saved the machine to recovery.

## Measured

* Compiled: `bootctl` and `growboot` for both architectures, the two host tests, and both kernels, whose link read 16777216 from the header and passed.
* The Lenovo's move and boots are 78-26.4, below.
