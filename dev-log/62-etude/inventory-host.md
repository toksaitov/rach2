# Inventory of the host tests, fuzz harnesses, style checks and proofs

This part of [the inventory of assertions](inventory.md) covers what `tests/run host` and `tests/run style` run, the fuzz harnesses, and every script that compiles a deliberate fault and requires a test to catch it. The scripts under `tests/system/` that `tests/run host` also runs are in [the suites' part](inventory-suites.md).

The host suite's limit of 60 seconds per test (`tests/system/suites/host.sh`, `WATCHDOG_SECS`, or a `host-seconds:` line) is a completion bound that only ends a hung test, and is not counted as a dependence on speed. A host test's "model clock" is a variable the test advances, not the host's clock.

## The host tests

`tests/system/suites/host.sh` step 1 compiles each `tests/host/*_hosttest.c` with its `host-deps:` sources under AddressSanitizer and UndefinedBehaviorSanitizer, every report fatal, and runs it; the test passes when it exits 0. Every bullet below is run so, by `tests/run host` on the host that runs it, once and not per guest architecture.

* `tests/host/accounttools_hosttest.c` (host suite): includes `utils/login.c`, `su.c` and `sudo.c` with identity calls and descriptors modelled. Sudo's policy file: a line that is exactly a user id is taken; a uid after a long comment, an overlong line, a suffix, a sign, an embedded NUL and a missing file are refused. Login's name read: partial and exact-capacity end of file end the name, an overlong line and a one-byte buffer discard the rest, an empty read and a read error are refused. Descriptors: `login` closes 3 to 1023, `su` and `sudo` close them before they change identity. Timing: none. Fate: kept, T23.

## The proofs

A proof puts a deliberate fault into a source, requires a named test to fail with that row's words, and requires the test to pass again once the source is restored. Every script below but the metal suite has a `--texts` mode that checks each fault's text against the tree's source and builds nothing; `tools/verify/faulttexts.sh` runs it in `tests/run style`. Nothing else runs a proof unless the bullet says so: a person runs it by hand, and a test it proves runs in its own suite.

Unless a bullet says otherwise, a host proof (`tests/host/*_mutate.sh`) holds the tree's run lock, copies the sources it changes into a directory made by `mktemp` under `build/tests`, compiles the test as the host suite does, under ASan and UBSan, and runs three phases: the copy as it is must pass, the copy with each fault must fail the row named for the fault, and the copy restored, touched and rebuilt must pass and compare equal (`cmp`) to the saved source. Each phase runs under a completion bound set with `perl -e 'alarm N'`. Its trap restores the copy and removes the directory on success or a signal, and keeps it after a failure, printing its path. Unless a bullet says otherwise, a system proof (`tests/system/*_mutate.sh`) holds the tree through `tests/system/runlock.sh`, puts the fault into the tree's own source, rebuilds through the suite's own target, requires the row to fail with its words, restores and touches the source, and requires the rebuilt kernel to equal the first build byte for byte; its trap stops the row's processes, restores the source and rebuilds when a run is stopped. A proof runs on the architecture `ARCH` names unless the bullet says otherwise.

The fates follow the plan: T26 moves the proofs of processes, system calls, protocols, the network, terminals, the agents and the tools to the proof driver of T25, and T27 the proofs of storage, file systems, block devices, disks and images.

## The probe fault catalogue

`tests/system/probe_faults.txt` lists 502 faults, each a block that names the fault, the probe, the file, the words the probe prints only when its row fails, and the old and new text. The comment before each group names the part of the system its faults are in; most faults take back a fix of milestone 54's review, or bring back the defect their row is about. * `tests/system/probe_faults.sh` (by hand; `--check` by `tests/run style`): puts each fault of the list alone into the tree under the run lock, has `make run-default` rebuild what it changed and boot the suite, and counts the fault caught when the suite fails, the runner does not pass the probe and the boot's log has the probe's words; a fault that hangs its probe is caught the same way, its words printed before the runner's deadline ends the boot. The file is restored and touched after each fault, and the kernel and programs rebuilt at the end must equal the first build byte for byte; the script does not run the rows on the unmodified tree, and leaves that to the next full set. NAME arguments run faults alone, and `-s K/N` runs one share of the list so that N copies of the tree can divide it; every fault runs even after one was not caught. `--check` checks each fault's text once in its file and builds nothing. Timing: none; a hang is ended by the runner's completion bound.
