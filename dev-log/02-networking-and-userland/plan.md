# Port musl libc to Rach2 and build its kernel dependencies

Status: final candidate. This plan ports musl, BusyBox, and Dropbear so that Rach2 provides a small Unix-like system with SSH access. It also builds their kernel dependencies: the process ABI, TLS, virtual memory, a hierarchical file system, signals, terminals, and ptys. KRFFS gains directories in Phase 6 rather than flat-namespace workarounds. Threads, dynamic linking, and a memory-architecture rewrite are not required.

## What this is, and why

Today every Rach2 user program is freestanding: it writes its own `int 0x80` stubs, `strlen`, and typedefs, then links with `-nostdlib`. This provides no `printf`, `malloc`, `FILE`, or `errno`, and every utility repeats the same support code. The next step is to port musl and link the utilities statically against it.

Running musl also requires the kernel services that a libc expects:

* a process and binary ABI: argc, argv, env, and an auxiliary vector on an aligned stack, as required by SysV/i386;
* thread-local storage: a `%gs`-based thread pointer via a GDT TLS descriptor, exactly as Linux manages i386 TLS;
* a virtual-memory subsystem: per-process virtual memory areas (VMAs) with demand paging, stack growth on fault, regions registered by `mmap` and `brk`, region-based fault dispatch, and copy-on-write fork;
* the `-errno` syscall contract: negative errno from the kernel, exactly the Linux i386 ABI a libc expects;
* signals: disposition, masking, delivery on return to user mode, and a `sigreturn` trampoline.

The goal is to implement these subsystems in readable code. Running musl tests that they work together. The VMA, demand-paging, TLS, and signal code should show how a kernel supports a libc.

### Why musl

musl is small, supports static linking, and generally keeps one concept in each short source file. Its requirements map directly to kernel subsystems without glibc's breadth. It uses the Linux i386 ABI already used by Rach2 (`int 0x80`; number in EAX; arguments in EBX, ECX, EDX, ESI, and EDI; result in EAX). The entry mechanism is compatible; the missing services are not.

### Scope: the end goal in view

The endpoint is an interactive BusyBox shell reached over SSH through Dropbear. The work has three parts:

* Part I, musl and core kernel subsystems (Phases 0-11, done): a frame allocator over detected RAM, VMAs and demand paging with copy-on-write fork, Linux-style `%gs` TLS, the `-errno` contract, a hierarchical KRFFS, a CSPRNG, signals, the TCP `send` and `recv` path, and refcounted open-file descriptions.
* Part II-A, the BusyBox shell (Phases 12-18): blocking and dispatch support, pipes, poll and select, `/dev`, a minimal `/proc`, `termios`, a line discipline, sessions, job control, and the BusyBox port.
* Part II-B, Dropbear remote login (Phases 19-23): pseudo-terminals, fail-closed `/dev/urandom` seeded by RDSEED or RDRAND with optional virtio-rng, the remaining socket calls, authentication and key staging, and the Dropbear port.

BusyBox and Dropbear are both static, fork-based, and designed for small systems. The target therefore needs no threads, dynamic linker, or memory-architecture rewrite. Parts I and II are specified below to the same depth.

The plan rejects eager mapping, a large static stack, and partial errno because those choices would omit the VM and ABI mechanisms being taught.

## Verification procedure

The DNS port established the procedure: verify each subsystem in the guest with a handwritten freestanding probe before musl depends on it. This gives each phase a deterministic offline check. A 40-line program that grows its stack on a fault also demonstrates demand paging directly. Each subsystem phase has:

* Probe (hermetic): a freestanding `tests/*probe.c` exercising the new facility via raw `int 0x80`, asserting, printing `All ... checks passed!`, exit 0. No musl, no network, deterministic.
* Integration: once the probes pass, run a musl binary that depends on the facility in the guest.
* Codex review: after the probe and integration checks, run the `codex:codex-rescue` subagent over the phase diff for an independent GPT-5.5 review. Ask it to challenge the design and find bugs. Address every finding before completing the phase.

Harness: `mk_image.sh <bins...>` builds a KRFFS image. `drive.py` boots `qemu-system-i386 -kernel ... -serial stdio -display none`, waits for the shell-ready marker, drives `exec <prog>` (resending after the known debug-shell input drop), and captures serial output. The caller checks the pass markers and `Process exited with status 0`. The debug shell becomes unreliable after about four sequential `exec` commands in one boot, so run each probe as the first or second command.

## Static analysis, formatting, and harness checks

Phase 0 creates `tools/check.sh` and the `make verify-style` target. Each later phase runs it with the probes and Codex review, and Phase 9 runs the complete set. The checks cover in-house code only; they exclude `ports/doom`, `vendor/`, and the imported musl, BusyBox, and Dropbear trees. Because the run does not use git, it records each phase's files in `/tmp/rach2_verify/phase-files.txt`. The Codex review uses `diff -ruN` against a snapshot made at the start of the phase rather than `git diff`.

The checks:
* Build the kernel with `-Werror`, enforcing the existing `-ansi -Wall -Wextra` policy in the compiler.
* Run `clang-format --dry-run -Werror` only on files changed by the phase. The `.clang-format` file uses an LLVM base, four-space indentation, Allman braces for functions, K&R braces for control statements, no include sorting, right-bound pointer stars, and a 100-column limit.
* Run `cppcheck --std=c89 --platform=unix32 --enable=warning,style` on the kernel and new `*probe` sources with `tools/cppcheck.suppress`. Exclude the existing `utils/` and `ish/` sources because they are not built with `-ansi` and a C89 check reports false positives there. This replaces the proposed `clang-tidy` check: its 64-bit target analysis reports false positives on the freestanding i686 kernel. The phase review checks function size and complexity instead of adding `lizard`.
* `shellcheck -e SC2086` on the in-house shell scripts (the QEMU option-splitting is intentional).
* Keep the convention grep (ASCII-only, no `//`, `_NAME_H_` guards): it catches what the tools cannot.
* Use `readelf` to require produced musl and probe binaries to be static ELF32 i386 `EXEC` files without `PT_INTERP` and with an entry point in the expected range.

Harness changes:
* Add QEMU's `isa-debug-exit` device. The kernel exit path writes it in harness builds because a ring-3 probe cannot use `out`. `sys_exit(status)` encodes the status on that port, and the harness reads it under a wall-clock timeout. A hang or triple fault therefore fails independently of serial markers.
* Compile pure logic such as the DNS parser, VMA operations, path resolution, dirent parsing, and the CSPRNG core both into the freestanding kernel and a native test binary. Run the host build with `-fsanitize=address,undefined` beside the guest probe. This catches boundary, overflow, and lifetime errors that are hard to diagnose in the guest. The DNS parser already uses this arrangement.
* When a Phase 2 TLS, Phase 3 usercopy, or Phase 4 paging probe triple faults or hangs, rerun QEMU with `-d int,cpu_reset -D qemu-trace.log -no-reboot -no-shutdown` and attach gdb with `-s -S`; `debug.sh` already configures the gdbstub. This diagnostic mode is manual and is not part of the pass criteria.
* Do not weaken a probe or test to complete a phase during an autonomous `/goal` run. A failing probe requires a code fix.

The plan does not add kernel-wide sanitizers, blanket kernel UBSan handlers, a CI service, `libFuzzer` or other fuzzing, formal methods, CodeChecker, Coverity, Infer, `lizard`, `jscpd`, a documentation generator, pre-commit frameworks, or multi-agent orchestration. The host ASan and UBSan tests provide the inexpensive 90% coverage intended here for pure logic. `clang-tidy` is addressed above; Phase 3 uses `sparse` for the user-pointer check that it can decide.

## Target end-state architecture

```
toolchain (host):  the stock i686-elf-gcc builds musl itself (no cross-toolchain;
                   spiked and confirmed; see Phase 0).
libc/              pinned musl source (pinned tarball, no git submodule), build step, the
  Readme.md        link recipe, and how utils select musl vs. freestanding.
rach2/sys/
  mm/frame.{c,h}   NEW: real frame allocator sized from the multiboot memory map
  mm/vm.{c,h}      NEW: per-process VMAs + demand-paging fault dispatch + brk/mmap
  mm/paging.c      EDITED: user fault handler routes to vm.c (was a panic)
  proc/tls.{c,h}   NEW: GDT TLS descriptor + set_thread_area (Linux-style)
  proc/fork (cow)  EDITED: copy-on-write via frame refcounts + write-fault
  signal/signal.*  NEW: minimal real signal subsystem
  lib/krandom.*    NEW: a small real-shaped entropy/CSPRNG source
  errno.h          NEW: Linux i386 errno values for the -errno ABI
  fs/krffs.{c,h}   EDITED: simple hierarchical directories + path resolution
  proc/elf.c, syscall.c, isr_handler.s, switch.s, tables/gdt.* : EDITED
tests/*probe.c     NEW: one hermetic probe per subsystem
utils/             EDITED: link against musl, drop the freestanding stubs
  (Part II adds: fs/devfs, tty/termios, pty, and the poll/pipe syscalls.)
```

Decisions:

| Decision | Choice | Reason |
|---|---|---|
| Linking | static, non-PIE first | supported by musl; dynamic linking is deferred and the loader remains ready for it |
| Syscalls | `int 0x80` | the canonical, always-present i386 mechanism; vDSO is an optimization (deferred) |
| Error ABI | `-errno` everywhere + `errno.h` | matches the Linux kernel/libc contract; partial errno was rejected |
| Memory | VMAs + demand paging | the address-space model every kernel uses; eager mapping was rejected |
| Frame pool | allocator from the multiboot map | uses detected RAM; the 32 MB constant was a placeholder |
| TLS | GDT TLS descriptor, rewrite-on-switch | precisely how Linux manages i386 TLS |
| Stack | grows on fault (a VMA) | demonstrates demand-paged stack growth |
| fork | copy-on-write (frame refcounts) | the canonical fork optimization taught in every OS course |
| Entropy | CSPRNG/`getrandom` | gives `AT_RANDOM` and `getrandom` generated bytes instead of a fixed constant |
| Signals | disposition + mask + delivery + sigreturn | standard signal behavior; real-time signals are deferred |
| Filesystem | simple hierarchical KRFFS (directories) | path resolution and the directory tree; limits retained at perms/size, not structure |

### [x] Phase 1: Process image and the initial stack (argv, env, auxv, alignment)
Goal: hand a process a correct SysV/i386 stack: `argc`, `argv[]`, `envp[]`, a complete auxv, 16-byte aligned. Concept taught: the process/binary ABI: where the kernel and the C runtime meet on the stack; what the auxv is for. Design:
* Unify the two divergent stack builders (`sys_execve`, `exec_program`) into one documented helper (they disagree today on alignment and string placement).
* Build, low->high: `argc`, `argv` ptrs, `NULL`, `envp` ptrs, `NULL`, auxv pairs terminated by `AT_NULL`, then the string/aux-data area; 16-byte align the entry `esp`.
* Populate auxv from kernel facts: `AT_PAGESZ`=4096, `AT_CLKTCK`=100, `AT_PHDR/PHENT/PHNUM/ENTRY` (record in `elf_load`), `AT_SECURE`=0, and `AT_RANDOM` (16 bytes from `lib/krandom`). Entropy tiering (important, resolves a cross-phase tension): Part I `krandom`/`AT_RANDOM`/`getrandom` is best-effort, non-security randomness (`RDTSC`/timer/RTC mixing): fine for a stack canary, not for keys; the crypto-grade, fail-closed `/dev/urandom` + trusted `getrandom` (seeded by virtio-rng) arrives only in Part II-B, before dropbear.
* Add `envp` support to `execve` (today ignored); the boot-shell `exec` passes a small default environment.
* Give the process a modest initial stack of a few eagerly mapped pages and record its bounds, with the ELF segment bounds, in the PCB. Phase 4 turns that metadata into a stack VMA that grows on fault. Phase 1 records the bounds but does not build a VMA, so it must not allocate a large eager stack.
* Replace the whole-file ELF loader. Both exec paths slurp the entire ELF into a 512 KB static buffer and reject anything larger (`syscall.c`, `kernel.c`): static busybox/dropbear exceed that. Move to a segment loader: read the ELF header + program headers, then load each `PT_LOAD` range from KRFFS into its eagerly-mapped pages (this also produces the `AT_PHDR`/`AT_PHNUM`/`AT_ENTRY` metadata for the auxv). An optional improvement makes exec failure atomic by building the new address space and committing only on success, rather than freeing the old image first. Build: the unified stack builder; the segment loader; `lib/krandom.{c,h}`; `elf_load` records program headers; `auxv.h`. Verify (probe `tests/auxvprobe.c`, hermetic): walk the stack from `_start`, print `argc`, each `argv`/`envp`, and every auxv `{type,value}`; assert the expected entries/values, env round-trips, vector is `AT_NULL`-terminated, `AT_RANDOM` is non-constant across two runs. Done when: the probe shows a correct, terminated auxv with env and non-constant `AT_RANDOM`, the stack is aligned, one builder serves both paths.

### [x] Phase 2: Thread-local storage (Linux-style GDT TLS and `%gs` preservation)
Goal: a `%gs`-based per-process thread pointer that survives context switches, IRQs, and syscalls: musl puts `errno`, the stack canary, and (later) `pthread_self` behind `%gs`. Concept taught: TLS segmentation on 32-bit x86: TLS via a GDT descriptor, mirroring Linux's i386 `set_thread_area` GDT-entry mechanism, and why entry/exit paths must preserve segment state. Design (from the investigation):
* GDT. Enlarge `GDT_ENTRY_COUNT` (today exactly full at 6/6); add a TLS data descriptor slot + a runtime `gdt_set_tls(base, limit)` (the current setter is file-static). This is the Linux layout (a dedicated TLS GDT entry).
* `set_thread_area`(243). Read the user `struct user_desc`, program the TLS descriptor (base=TCB, 4 GB limit, DPL 3, data R/W), return the entry number, write it back: the same syscall and `user_desc` ABI musl calls from `__init_tls`.
* PCB + switch. Store the per-process TLS base in `struct process`; in `switch.s`, which today touches no segment register, rewrite the shared TLS GDT descriptor from the incoming process and reload `%gs`: exactly how Linux reloads TLS entries on `__switch_to`. Do the descriptor rewrite + `%gs` reload with interrupts disabled (the switch can be entered from syscall context where IF=1), so a nested IRQ cannot observe a half-updated TLS descriptor.
* The critical fix is at interrupt and syscall entry. `isr_params_t` saves only `%ds` and the exit path copies it across `%es/%fs/%gs`; the first timer tick after musl sets its thread pointer would destroy it. Extend the saved frame to include `%gs` (and `%fs/%es`) and save and restore each individually on both stubs, including the nested-IRQ window (the syscall stub runs with interrupts enabled). The saved-frame layout must be exact. Two more pieces the review flagged: (a) close the `sti` windows: the syscall stub does `sti` before `in_syscall` is set and again just before `iret`; set `in_syscall` before enabling interrupts and let `iret` restore IF (drop the pre-`iret` `sti`), so a timer IRQ cannot preempt a half-built or half-restored frame; (b) update every consumer of the frame layout: the new `gs/fs/es` fields shift offsets, so `sys_fork`'s hand-spliced child frame and `isr_return` must match. Since `switch.s` hard-codes `struct process` offsets, append new PCB fields (TLS base here, VMAs in Phase 4, signal state in Phase 8) and re-check the asm offsets in the same patch; never insert them in the middle. Build: `proc/tls.{c,h}`; PCB field; `switch.s`/`isr_handler.s` edits; a `proc/tls` Readme citing the Linux analogue. Verify (probe `tests/tlsprobe.c`, hermetic: tests the TLS path early): call `set_thread_area`, point `%gs` at a known TCB, write sentinels at `%gs:0`/offsets, then spin thousands of `int 0x80` + busy-wait through many timer IRQs, re-read each time, assert intact; a concurrent second process with a different TCB proves per-process isolation across switches. Prints `All TLS checks passed!`. Done when: the probe proves `%gs` TLS survives IRQs/syscalls/switches with per-process isolation, without musl.

### [x] Phase 3: The syscall contract (`-errno`) + MVP calls + first musl binary
Goal: make the kernel speak the Linux `-errno` ABI, add the calls musl needs to reach `main`, and run a static musl `hello` in the guest. Concept taught: the kernel/libc error contract: negative errno from the kernel, `errno` set by the libc. Design:
* `-errno` everywhere. Add `errno.h` with the Linux i386 errno values. Dispatcher returns `-ENOSYS` for an empty/out-of-range slot (not `-1`). Sweep all existing handlers to return `-errno` on failure (a bare `-1` becomes `EPERM` and defeats musl's `ENOSYS` fallbacks). This is comprehensive, not "most-used": the contract must be uniform to be consistent. Update the existing freestanding utils/tests/stubs that compare exactly to `-1` (e.g. `cat`/`ls` treat any non-`-1` fd as valid) to test `< 0` first, in the same change; otherwise, a `-ENOENT` reads back as a valid fd and they regress.
* A user-copy / fault contract (prerequisite for Phase 4 demand paging). Today syscalls dereference user pointers directly (`sys_write` reads `buf[i]`, `sys_execve` walks user strings) behind only an `access_ok` range check. Once user memory is demand-paged, a kernel access to a not-yet-present user page faults while the kernel is running. The handler must fault the page in or return `-EFAULT`, never panic. Add `copy_from_user`/`copy_to_user`/`strncpy_from_user`/iovec helpers and route every pointer syscall through them. Then annotate user pointers `__user` (a no-op macro in normal builds) and run `sparse` once over the syscall/usercopy sources. A raw dereference of a `__user` pointer becomes a sparse error, making the routing requirement checkable. This is where the conversation's `sparse`/`__user` trigger applies to a Rach2 bug class (`sys_write`/`sys_execve` dereference user memory directly today). Run it once in Phase 3 rather than as a standing check.
* MVP syscalls: `writev`(146) (stdio/`printf`), `exit_group`(252) (musl's `exit` uses it), `set_tid_address`(258) (record+return tid), `ioctl(TCGETS/TIOCGWINSZ)`->`-ENOTTY` (so `isatty` picks buffering), `getpid`(20), `uname`(122).
* musl link integration: wire `libc/` so a program links `crt1/crti` + static `libc.a` + `crtn` via the cross compiler. Verify:
* Probe `tests/errnoprobe.c`: an unimplemented number returns `-ENOSYS`; a deliberately failing call returns the right `-errno`.
* Integration milestone: a static musl `hello.c` runs in the guest, prints `hello`, and the kernel reports `Process exited with status 0`. This proves that musl reaches `main`, performs buffered stdio, and exits cleanly. Done when: the errno probe passes and musl `hello` runs in Rach2.

### [x] Phase 4: Virtual memory: the address-space model (VMAs + demand paging)
Goal: the VM subsystem: a per-process map of memory regions, frames allocated lazily on fault, stacks that grow, `brk` and `mmap` as region operations, and a fault that kills a process rather than the machine. Concept taught: the VMA address-space model and demand paging. Design:
* Frame allocator first (`mm/frame.{c,h}`). Size the frame pool from the multiboot memory map (`mem_upper`/the mmap), replacing the `HARD_MEMORY_LIMIT` placeholder (the kernel's own `ToDo`). Document the remaining cap: the kernel can only directly access identity-mapped low RAM, so total resident memory is bounded until a high-memory kernel split lands (a documented future effort in the resolved blockers below). Within that limit, use a bitmap or stack allocator over actual RAM. Allocate only frames the kernel can access. The ELF loader and fork write user frames through their identity (physical) address, so cap the allocatable pool to the direct-mapped window. Do not allocate high multiboot RAM until a `kmap` or high-memory split exists.
* VMAs (`mm/vm.{c,h}`). Per-process small fixed array of `{start, end, prot, type(code/data/heap/stack/anon)}` (simpler to teach than a list, and `MAX_PROCS` is 16): the structure Linux/BSD use. `exec` sets up code/data/heap/stack VMAs; `mmap`/`munmap` insert/split; `brk` extends the heap VMA. Map pages with PTE permissions from the VMA `prot` / ELF `p_flags` (text read+execute, data read+write): `alloc_user_page` maps everything writable today and `elf_load` ignores `p_flags`, and COW (Phase 5) needs that fixed to tell a write-fault from a protection fault.
* Demand-paging fault dispatcher. Replace the panic-on-fault with: read CR2 + the error code; find the VMA containing CR2; not-present in a valid VMA -> allocate a frame and map it (demand paging); fault just below the stack VMA, within the growth limit -> extend the VMA and map (stack growth); no VMA, or a protection violation -> deliver a segfault (kill the process; wired to `SIGSEGV` in Phase 8); a kernel fault outside the user range still panics. A kernel access to a user address can fault while copying the user stack on the process's behalf, so distinguish that case by checking CR2 against the user range rather than checking CS.
* `brk`(45), `mmap2`(192), `munmap`(91) implemented as VMA operations over the demand-paged backing. Anonymous `MAP_PRIVATE|MAP_ANONYMOUS` first; file-backed mmap is a documented follow-on. Build: `mm/frame.{c,h}`, `mm/vm.{c,h}`, the fault dispatcher in `paging.c`, PCB VMA-list head, the syscalls; an `mm/vm` Readme explaining VMAs and demand paging with the Linux analogue. Verify (probe `tests/vmprobe.c`, hermetic): `brk`-grow and r/w the heap; `mmap` anon, write a pattern, read back, `munmap`; recurse to force stack growth and confirm it succeeds; (separate boot) deref a wild pointer and confirm the process dies but the kernel survives and the shell returns; confirm a lazily-faulted page reads back zero. Integration: a malloc/`qsort`-heavy musl program runs and exits 0. Done when: VMAs + demand paging + stack growth work under the probe, faults are per-process, and a malloc-using musl program runs.

### [x] Phase 5: Copy-on-write fork
Goal: make `fork` copy-on-write instead of deep-copying, and add `wait4` to complete the process model. Copy-on-write matters because the shell and sshd repeatedly fork and then exec; a deep copy duplicates pages that exec immediately discards. Concept taught: copy-on-write, frame reference counting, and the write fault. Design: upgrade the frame allocator from a used bit to a reference count (per the investigation, `_frames[]` is a bitmap today). `fork` copies the VMA list and marks both parent's and child's pages read-only, incrementing each frame's reference count. A write fault on a shared page copies it if the reference count is greater than one, remaps it writable, and decrements the old frame's reference count; otherwise it restores write permission. Frees decrement reference counts. Reserve a software PTE bit for COW, rely on the Phase-4 write-protect so a write fault can be distinguished from a protection fault, and flush the parent's TLB after write-protecting its pages. Wire this into the Phase 4 fault dispatcher. Add `wait4`(114), which musl's `wait`/`waitpid` and the shell/sshd reaper use, beside `waitpid`(7). Fix the wait-status encoding: `waitpid` writes the raw child exit code today, but musl/BusyBox expect the Linux encoding (`WIFEXITED`/`WEXITSTATUS`, signal deaths). ### [x] Phase 6: Files and directories (a hierarchical KRFFS + the `*at` API)
Goal: give KRFFS simple directories and add the file-API syscalls musl's `fopen`/`stat`/`opendir`/`mkdir` need, so file utilities and a navigable tree work, and the existing `mkdir`/`rm -r` utils finally operate on directories. Concept taught: the filesystem tree: directory entries and path resolution, and the `*at` file API a libc builds `FILE*`/`DIR*` on. Design:
* Simple hierarchical KRFFS (extend it in place, not a new FS). A directory node type whose entries map `name -> node`; path resolution that splits a path on `/` and walks components from the root; `mkdir`(39)/`rmdir`(40). Route `open`/`stat`/`unlink`/`rename`/`chdir`/`getdents64` through the walk (today they flat-match a single name). Now `/etc`, `/tmp`, `/home`, `/bin` are directories. This is a KRFFS v2 on-disk format (node headers gain a `parent_id`, or a directory node carries dirents), and the same format must be taught to the host tools (`mkfs.krffs`, the FUSE mount that today rejects directories, `fsck`/`defrag`, and the `build_*.sh` stagers) so images can actually contain `/etc`, `/bin`, `/dev`. Kernel-side path-splitting alone cannot stage a tree.
* Split the fd layer (needed for `O_CLOEXEC`/`fcntl`, and by pipes/ptys later). Today `fd_entry_t` is the open object; `dup2` copies it by value and `fork` copies the whole table, so they don't share file offsets the Unix way and there is nowhere to hang per-descriptor `FD_CLOEXEC`. Introduce the two-level model: a descriptor table (per-descriptor flags incl. close-on-exec) pointing at refcounted open-file descriptions (shared offset + status flags); `dup`/`fork` share the description, `execve` closes `FD_CLOEXEC` descriptors. This is the foundation pipes, ptys, and sockets build on in Part II.
* Documented simplifications: no users, permissions, or ownership (`chmod` and `chown` are no-ops); small fixed limits; linear directory scans without hashing or B-trees; no hard links or symlink chains; and no journaling. These limits retain the directory tree and path-resolution mechanisms.
* The `*at` file API: `openat`(295) (resolve relative to `AT_FDCWD`/a dirfd), `fstat64`(197) + `fstatat64`(300), `fcntl64`(221) (`F_GETFL/SETFL/SETFD/DUPFD(_CLOEXEC)`), `_llseek`(140) (64-bit); working `O_CLOEXEC`/`O_NONBLOCK`. Build: `fs/krffs.{c,h}` directory support + path resolution; the new syscalls; an updated `fs` Readme on the tree, path resolution, and the simplifications. Verify (probe `tests/fileprobe.c`, hermetic): `mkdir` nested directories, `openat`/`fstat`/`read` a file inside one, `chdir` into a subdir + `getcwd`, `getdents` lists a subdir, `fcntl` round-trips, `_llseek` seeks, `rmdir` removes an empty dir. Integration: musl `cat <dir>/<file>`, `ls <dir>`, `mkdir`/`stat`, and the existing `mkdir`/`rm -r` utils work on nested directories. Done when: the probe passes, directories work, and musl file utils navigate the tree in-guest.

### [x] Phase 10: Finish the socket path: `send`/`recv` on connected TCP
Goal: make musl's `send()`/`recv()` work on a connected TCP socket so the musl `httpd` actually serves requests: the regression the Phase 9 port introduced and the head-to-head check missed. Concept taught: the Linux socketcall multiplexer, and the ABI subtlety that `send`/`recv` are not their own syscalls: musl compiles them to `sendto`/ `recvfrom` with a NULL address. A from-scratch stack that routes by sub-call number instead of socket type silently pushes stream traffic down the datagram path. The musl port exposes it; the freestanding `httpd` dodged it by calling `SC_SEND`/`SC_RECV` directly, and `nc` by using `read`/`write`, which is why only the ported `httpd` broke. Design: in `rach2/sys/syscall.c`, `do_send`(SC_SEND=9)/`do_recv`(SC_RECV=10) route to `tcp_send`/`socket_tcp_recv`, but `do_sendto`(11)/`do_recvfrom`(12) route to the UDP path (`udp_tx`/`socket_recv`). When the fd is a connected `SOCK_STREAM` socket, route `sendto`/`recvfrom` to the TCP path exactly like `send`/`recv` (POSIX: a null destination on a connected socket means `send`/`recv`). Leave the `SOCK_DGRAM` path untouched; for stream `recvfrom` accept a NULL `sockaddr` (no `-EFAULT`) and skip the source-address writeback. Verify (probe `tests/musl/tcpsendrecv.c` + live `httpd`): a new musl program connects out through the SLIRP gateway `10.0.2.2` to a host echo server and round-trips a line using `send()`/`recv()` (not `read`/`write`), printing a marker; and the musl `httpd`, run under QEMU `hostfwd`, serves a host `curl`: HTTP 200, non-empty body, a `"GET / HTTP/1.1" 200` access-log line (the freestanding `httpd` already proves the kernel TCP works, so this isolates the send/recv routing). `ping`/`nc`/`dnstest` unchanged; `make verify-style`/ `verify-host`. Then an independent Codex review of exactly the `do_sendto`/`do_recvfrom` change: it touches the untrusted socket path, so scrutinize the NULL-`sockaddr` handling, the buffer/length bounds, and that the `SOCK_DGRAM` path is byte-for-byte unchanged, and fix every finding. Done when: musl `send()`/`recv()` round-trip over TCP, the musl `httpd` serves `curl`, the rest of the suite is unchanged, and Codex's findings are addressed.

### [x] Phase 11: Refcounted open-file descriptions (`dup`/`fork` share the offset)
Goal: give file descriptors POSIX semantics: a `dup`'d or `fork`'d fd shares one open-file description (and its seek offset): closing the Phase 6 deferral. Concept taught: the three-layer fd model every Unix has: the per-process fd table -> a shared, refcounted open-file description (offset + status flags) -> the underlying file/inode/socket. Today Rach2 collapses the first two, so `dup2(fd,1)` then `printf` and the original `fd` disagree about the offset, and `lseek` on one does not move the other. This is the structure that makes shell redirection, pipes, and `fork`+`exec` behave; Linux calls it `struct file`. Design: add a refcounted `struct open_file` (the OFD) from a fixed static pool: `{ refcount; offset; status_flags (O_APPEND / access mode); backing (KRFFS node id / socket* / device kind) }`. The fd-table entry becomes `{ fd_flags (FD_CLOEXEC: per-fd, not per-OFD); struct open_file *ofd }`. `open`/`creat`/`openat` allocate an OFD (refcount 1); `dup`/`dup2` copy the pointer + `ref++` and clear the new fd's `FD_CLOEXEC`; `fork` copies each entry's pointer + `ref++` (parent and child share the offset); `close` does `ref--` and frees at zero (releasing the backing socket via its own unref); `read`/`write`/`lseek`/`getdents` use the OFD's shared offset and honor `O_APPEND`; `execve` closes the `FD_CLOEXEC` fds; `fd_init_stdio` builds the stdin/stdout/stderr OFDs. Refactor `fs/fd.{c,h}` (`fd_get`/`fd_alloc`/`fd_table_init`); `alloc_process` `k_memset`s the fd table so OFD pointers start NULL. Verify (probe `tests/ofdprobe.c`, hermetic + a musl check): prove (a) `dup`/ `dup2` share the offset: read N bytes via one fd, then read via the dup and confirm it continues from N (not 0); (b) `fork` shares the offset: the child advances it and exits, the parent `waitpid`s and its next read sees the advance; (c) closing one fd leaves the dup working, and many open/close cycles leak no OFDs; (d) `execve` still closes `O_CLOEXEC` fds. Plus a musl integration check: `dup2` a file over `stdout`, `printf`, confirm the shared offset advanced. The whole suite + utilities stay from a clean `make clean && make` (zero warnings, one combined boot). Update `fs/Readme.md` to document the OFD layer and drop the Part-II deferral note. `make verify-style`/`verify-host`. Then an independent Codex review of the fd-layer refactor: scrutinize the refcount lifecycle (no leak, no double-free, the socket-unref-on-last-close interplay), the `fork`/`execve`/`dup2` paths, and the PCB layout, and fix every finding. Done when: `dup`/`dup2`/`fork` share the seek offset, the OFD pool is leak-free, the whole suite passes from a clean build, the OFD layer is documented, and Codex's findings are addressed.

## Part II: busybox and dropbear: a Unix-like system you can log into

Part I provides musl and the kernel foundation. Part II adds an interactive BusyBox shell reached over SSH through Dropbear, the combination used by Alpine Linux. Phases 12 through 23 continue the earlier numbering and follow the same ground rules, checks, and review procedure. Part II-A, Phases 12 through 18, creates the interactive console shell. Part II-B, Phases 19 through 23, adds SSH access. `wait4`(114) and refcounted open-file descriptions were completed in Phases 5 and 11, so they are prerequisites rather than phases here.

An independent Codex review of the repository source and vendored musl headers found six blocking defects in the first Part II draft. The revised phases incorporate these corrections:

* Take ABI numbers and structures from the vendored `libc/musl-1.2.5` headers. Part I's `httpd` regression showed the cost of assuming a call number: musl compiled `send` and `recv` into `sendto` and `recvfrom`, while Rach2 dispatched by sub-call number. The headers establish that `getpgid` is 132, not 155; musl i386 uses `select`(82), `_newselect`(142), `pselect6`(308), `poll`(168), and `ppoll`(309); socketcall sub-call 15 is Linux `getsockopt` but conflicts with Rach2's private `SC_PING`; the userspace `struct termios` has `NCCS=32` and speed fields while the kernel `TCGETS` structure is its layout-compatible 19-`c_cc` prefix; and the pty ioctls are `TIOCGPTN=0x80045430` and `TIOCSPTLCK=0x40045431`. The 64-bit `time_t` transition on i386 means musl 1.2 tries the `*_time64` calls `clock_gettime64`(403), `clock_nanosleep_time64`(407), `pselect6_time64`(413), and `ppoll_time64`(414) first, then falls back to time32 numbers 265, 267, 308, and 309 on `-ENOSYS`. Part I already relies on that fallback for `clock_gettime`(265) and `nanosleep`(162). Each ABI phase therefore adds a by-number or by-offset probe and checks the built binary.
* Phase 12 adds backing dispatch and a multi-waiter wait queue before pipes, poll, ttys, ptys, or signal-interruptible sockets. Part I's `struct open_file` contains only `{refcount, offset}`, fd dispatch remains an `enum` switch, and a blocking socket parks one `waiting_proc` with `sti; hlt`.
* Each pipe, tty, pty, and accepted socket becomes a backing kind on a refcounted `struct open_file`. Existing `fork`, `dup`, and `close` refcounting then serves the new objects. `O_NONBLOCK` becomes an enforced OFD status flag, and `close(0/1/2)` becomes legal so a shell or daemon can replace standard descriptors.
* New PCB fields are append-only (`switch.s` hard-codes offsets: the Phase-2 lesson): pgid/sid/ctty and the new `PROC_STOPPED` state (Phase 17) append and re-check the asm offsets in the same patch.
* RDSEED or RDRAND is the required fail-closed entropy path. Virtio-rng is an optional Phase 20-opt extension because a new virtio-pci driver is not otherwise required by BusyBox or Dropbear. The kernel already checks RDSEED and RDRAND with CPUID. Each new PCI interrupt handler must check its device because PCI devices may share an IRQ through the chained dispatcher.
* Compile pure logic such as the pipe ring, N_TTY state machine, `fd_set` to `pollfd` translation, and virtqueue index arithmetic into both the kernel and native ASan and UBSan tests.
* Keep the interactive and SSH drivers under `tools/`. The existing `tools/harness.py` appends a newline and ignores a failed `expect=`, so it cannot check control characters, raw mode, backspace echo, an SSH password prompt, or a pty session. Part II adds a raw-byte expect driver that does not append input and fails on a missing expectation, plus a host SSH driver using `hostfwd`.
* Run `make clean` after every header edit because this version of the build lacks header dependencies. Check the fixed process, descriptor, and socket limits of 16 first by accounting, then with a live probe after Phase 19. Raise a limit before the Dropbear port if one session does not fit, append PCB fields, and recheck assembly offsets.

### [x] Phase 12: Blocking & dispatch substrate (wait queues + the file-backing layer)

No new userspace feature; the foundation pipes/poll/tty/pty/sockets all require. Done when: multi-waiter wake + `EINTR` + enforced `O_NONBLOCK` + closable stdio all pass, sockets ride the new wait queue with no net regression, and Codex is addressed.

### [x] Phase 13: Pipes (`pipe`/`pipe2`)

Implement the pipe's `poll` op (consumed by 14) and `FIONREAD`. The ring-buffer logic is also compiled for host tests. Host test: the ring buffer under ASan. Integration: a musl `pipe`+`fork` round-trip. Then an independent Codex review of the lifecycle (no pool leak, last-close ordering, the SIGPIPE/EOF edges). Done when: the probe shows blocking + EOF + `SIGPIPE` + non-blocking, a musl fork+pipe round-trips, the pool is leak-free, and Codex is addressed.

### [x] Phase 14: I/O multiplexing (the `select`/`poll` family)
Goal: wait on many descriptors with a timeout: the call BusyBox's `ash` loop and most applets depend on. Concept taught: readiness-based multiplexing. Each pollable object reports which of `{readable, writable, error/hup}` applies now and provides a wait queue (12). The syscall scans the objects and, if nothing is ready, blocks on all of them until a wakeup or timeout. ABI (Part-I lesson applied: confirmed from the vendored musl headers): i386 musl defines the whole family: `select(82)`, `_newselect(142)`, `poll(168)`, `pselect6(308)`, `ppoll(309)`, plus the `time64` variants `pselect6_time64(413)`/ `ppoll_time64(414)` musl tries first. Implement them all through one core, with the `time64` calls either down-converting the `timespec` or relying on musl's `-ENOSYS` fallback to the time32 number. Let the BusyBox binary select the call rather than assuming one, as the first draft did with `pselect6`. musl's `fd_set` has an `FD_SETSIZE` of 1024 while `MAX_FDS` is 16, so the translation scans only the first `MAX_FDS` bits. A large `nfds` with no bit set past `MAX_FDS` is valid because no descriptors exist there. A bit set for an fd >= `MAX_FDS` is invalid and returns `-EBADF`, as required by the select and poll contract, rather than being silently truncated. Design: a per-backing `poll(events) -> revents` + register-on-wait-queue operation for pipes (13), tty (16), sockets (now on the wait queue, 12), regular files (always ready), and devfs character devices (15). The poll core scans first. If nothing is ready, it sleeps on every referenced wait queue until a wakeup or timeout, then rescans without losing wakeups (12). `_newselect`, `select`, and `pselect6` translate `fd_set`<->pollfd; the `p*` variants perform the specified atomic signal-mask swap. Document the 10 ms tick resolution. The `fd_set`<->pollfd translation is also compiled for host tests. Build: `sys/io/poll.{c,h}`, the per-backing poll operations + a number-by-number ABI probe; a Readme on readiness + wait queues. Verify (probe `tests/pollprobe.c`, hermetic): two pipes (13); poll with nothing ready -> `0` after about the requested timeout; write one -> `POLLIN`; close a write end -> `POLLHUP`; the same via `select`/`_newselect` `fd_set`; a large `nfds` with only in-range bits works, while a bit set for an fd >= `MAX_FDS` returns `-EBADF` (no silent truncation). Host test: the set<->pollfd translation under ASan. Integration: a musl program polling `stdin` + a pipe; an ABI-by-number probe logs which select/poll number the built binary emits. Then an independent Codex review of the wait/rescan race and the signal-mask handling. Done when: the probe passes (timeout, readable, `POLLHUP`, the select family), a musl poll/select program works, the lost-wakeup race is closed, and Codex is addressed.

### [x] Phase 15: Synthetic filesystems: a `/dev` devfs and a minimal `/proc`

Concept taught: the synthetic filesystem: names backed by in-kernel drivers, not storage: a char device dispatches `open` to a `struct device_ops`, and `/proc` exposes kernel/process state as files. The boundary between the namespace and driver code. ## Part III: Simplify and unify the build

Parts I and II produced a Unix-like system with SSH access. Part III changes only the build system; kernel objects and binaries remain byte-identical wherever their command lines do not change. It adds header dependencies so a `.h` edit no longer requires `make clean`, replaces three dependency schemes and four copies of cross-compiler detection, removes duplicate component builds, runs the three vendored builds through Make, and adds kernel language-server support.

Part III follows the same procedure in dependency-ordered Phases 24 through 30. Each phase builds the change, demonstrates it directly, runs `make verify-style` and `make verify-host`, boots the guest through `tools/harness.py`, and repeats the Dropbear end-to-end SSH test. An independent Codex review covers that phase's build files. Address its findings, update the owning `Readme.md`, and make one house-style commit without attribution.

Claude and Codex designed and reviewed Part III. Codex found ten issues in the first draft, including an overbroad Phase 26, incomplete stamp prerequisites, and checks that did not mechanically preserve build, boot, and SSH behavior. The revised phases incorporate those findings. The build remains visible so a student can read and modify it. These decisions are fixed for the run:

* Keep GNU Make. CMake, Meson, and Bazel would hide the freestanding compile and custom `ld` link steps that this project intends to show. Make covers the kernel, assembly, FUSE host tools, QEMU scripts, and vendored autotools or kbuild projects. Keep commands visible; do not add quiet or color wrappers around commands such as `i686-elf-gcc [arguments] -T link.ld`. A `V=` switch may be added later but is not a primary goal.
* Keep the explicit kernel source list. `find sys -name '*.c'` could include scratch files and make link order depend on directory contents. Phase 29 adds `make check-sources`, which fails when a kernel `.c` file is absent from the list and reports but permits extra Doom or vendor sources.
* Generate `compile_commands.json` from Make's source lists. The checked `i686-elf-gcc` 16.1 rejects the Clang-only `-MJ` option.
* Keep plain `make` as the base build. BusyBox, Dropbear, and Doom remain under `make full`. The default build includes libc because the utilities require `libc.a`.
* Run the end-to-end SSH test with `krffs/build_test_ramdisk.sh`, which stages `/busybox`, `/sh`, `/dropbearmulti`, `/etc`, and the demo key. Do not use the base `build_ramdisk.sh`. `make full` must produce the tested image.
* Hybrid build dir: final artifacts stay where the run scripts expect (`rach2/kernel`, `krffs/file_system.krffs`); only intermediates move out of tree (Phase 30, last and deferrable).
* Do not add `make run`. The existing `run*.sh` scripts already express the disk or ISO, audio device, `NET`, `NET_HOSTFWD`, CPU, and future SSH options. `make help` points to those scripts.

Goal: kernel, tests, ish, utils, the Doom port, and the krffs host tools share one visible build procedure. ## Part II execution risk (live)

* Codex identified job control (Phase 17), rather than Dropbear, as the phase with the greatest risk. The kernel today classifies stop signals but ignores them, has no `PROC_STOPPED`, and `wait4` only reaps zombies. The phase is therefore split into five probe-verified steps. Signal routing is the difficult part; `jobprobe` drives Ctrl-C/Ctrl-Z over the raw-byte serial driver and asserts the recipient.
* ABI fidelity recurs throughout Part I. Values are pinned from the vendored headers: the select family (not `pselect6` alone), `getpgid`=132, the `SC_PING`=15 collision, the `NCCS=32` termios prefix, and the exact pty ioctl bit patterns. Each gets a by-number or by-offset probe and is also tested by the built BusyBox and Dropbear binaries.
* The blocking and dispatch substrate (Phase 12) is required by every later phase. A lost wakeup in the wait queue or a socket regression in the `file_ops` refactor would break later work, so its probe first exercises multi-waiter wake + `EINTR` repeatedly.
* Phase 20 requires RDSEED or RDRAND and leaves virtio-rng as the optional Phase 20 extension. If a probe hangs, use the Phase 0 diagnostic mode (`-d int,cpu_reset` and the gdbstub).
* The one-session fixed-limit budget is settled by a live probe after Phase 19 (ptys exist), raising `MAX_PROCS`/`MAX_FDS`/the socket pool (append-only PCB, re-check asm offsets) before dropbear if needed.

## Deferred features not required by BusyBox or Dropbear

The end goal does not require the following large deferred features:

* Threads / `clone` / futex / `pthread`: not needed. busybox and dropbear are fork-based and static; musl `fork` uses `SYS_fork`(2), which exists. The whole end goal needs no threading. (Threads stay a clean future lesson; Phases 2/4/5 lay the foundation.)
* Dynamic linking: not needed. Both build fully static (the Alpine pattern). The loader stays dynamic-ready for a future lesson.
* High-memory kernel split / >32 MB resident: not required. Dropbear and BusyBox are built for low-memory embedded systems (a Dropbear session runs in a few MB); the 32 MB resident pool comfortably holds one SSH session + shell. The limit caps concurrent sessions rather than preventing a single login. The end goal therefore does not require a memory-architecture change, and the high-memory work remains deferred.
* vDSO/`sysenter`, real-time signals, file-backed executable paging: extras, not on the path.

Every remaining step toward an SSH BusyBox shell belongs to a specified subsystem: poll, pipes, termios, ptys, devfs, a CSPRNG, and the remaining socket operations. Part I already completed the hierarchical file system. None of the three deferred architectural changes is required.

## Part I execution risk (still live)

* `%gs` preservation under the syscall `sti` window (Phase 2) has a specified implementation but requires exact frame handling. The TLS probe repeatedly exercises nested IRQs during syscalls. The toolchain question is resolved: build musl with the stock `i686-elf-gcc`, as confirmed by the experiment.

## Questions resolved in the owning phase

All Part I questions were resolved when their subsystems shipped: the musl auxv set (Phase 1), the KRFFS v2 directory format threaded through the host tools (Phase 6), musl's `send`/`recv` -> `sendto`/`recvfrom` routing found after Part I (Phase 10), and IRQ 11 sharing between HDA and RTL8139 (the chained-IRQ dispatcher).

Part II had open questions, each assigned to a phase:
* Backing dispatch and wait-queue design: the `file_ops` table and the multi-waiter `wait_queue` that replace the fd `enum` switch and the single-`waiting_proc` park (Phase 12). Later subsystems register with these interfaces.
* `/dev` devfs and `/proc` design: a device-node kind in KRFFS carrying `{major,minor}` vs. a mounted devfs, and the minimal `/proc/self/fd` + `/proc/PID/stat` slice `ttyname_r` and `ps` need: pick the simpler one (Phase 15).
* N_TTY scope: how much line discipline now (ERASE/KILL/ECHO/ISIG/OPOST + VMIN/VTIME) vs. deferred (IXON flow control, full `c_cc`): settle in Phase 16 and reuse for ptys.
* ABI layouts pinned against the vendored `libc/musl-1.2.5`: the select family (`select`/`_newselect`/`poll`/`pselect6`/`ppoll`, implement all routed to one core: Phase 14), the `TCGETS` 19-`c_cc` termios prefix under musl's `NCCS=32` struct (Phase 16), the exact pty ioctl bit patterns (Phase 19), and the `SC_PING`=15 renumber before the socketcall fill-out (Phase 21).
* Entropy: RDSEED/RDRAND fail-closed is the required source (Phase 20); virtio-pci + virtqueue is the optional paravirt upgrade, off the critical path (Phase 20-opt).
* Fixed-limit budget for one SSH session: static accounting first, then a live probe after ptys exist (Phase 19) confirms that `MAX_PROCS`, `MAX_FDS`, and the socket pool (16 each) can hold the listening and accepted sockets, pty, child, and standard descriptors. Raise them before Dropbear if necessary, append fields only to the PCB, and recheck the assembly offsets.
* Dropbear crypto and entropy fit: choose a KEX/cipher set for Rach2's CSPRNG and entropy support, and choose the authentication policy between a fixed password and `authorized_keys` (Phases 22/23).

Settled earlier by the Codex review: directories extend KRFFS in place; VMA = small fixed array; entropy = virtio-rng, fail-closed; job control is Part II-A; `getpid` lives only in Phase 3.

## Definition of done (the full plan)

* Part I: a pinned static musl runs Rach2's utilities (`printf`/`malloc`/ `FILE*`/`errno`/`abort`) atop probe-verified kernel subsystems: SysV stack + auxv (env, generated `AT_RANDOM`), Linux-style `%gs` TLS, a frame allocator + VMAs + demand paging, copy-on-write fork, a simple hierarchical filesystem (directories), the `-errno` contract, and a signal subsystem.
* Part II-A: a static musl busybox runs as an interactive shell: pipes, job control, termios, and `/dev`, navigating the Part-I directory tree.
* Part II-B: dropbear accepts an SSH connection and runs that shell over a pty with crypto-grade entropy: you can `ssh` into Rach2.
* Part III: every component uses one visible GNU Make procedure with automatic header dependencies, so routine builds need no `make clean`. `make doctor` and `make help` describe the environment; `make` and `make full` build the OS, including the end-to-end SSH test, from a clean clone without manual `build_*.sh` runs. The build also supports clangd and leaves the kernel and all binaries unchanged.
* Every subsystem ships a `Readme.md` (with its Linux or BSD analogue) and a passing `tests/*probe`; the existing syscall + network suites never regress; the whole project builds clean under our conventions. All commits are the user's; this plan and the harness never touched git.
