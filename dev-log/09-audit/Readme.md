# Milestone 9: the post-disk audit

The disk milestone and its four follow-up fixes landed about 3700 lines across fifty files. This milestone audited the whole tree afterward, across four dimensions (code correctness, comments, documentation, support files), to prove the new code correct, prove the unchanged code unbroken by the ripple, and bring every comment and Readme back into agreement with the code. It ran as ten phases, risk-ordered, each a multi-agent fan-out that surfaced candidate findings and then adversarially verified every one before it counted, in the milestone-6 discipline where most candidates are refuted. The hard phases were re-verified independently by Codex, and the highest-risk finding was reproduced on real hardware emulation before it was fixed.

## What the audit found

The audit cleared the new code: the page cache, the MM-VM and user/window boundary, the block and ATA driver, the KRFFS disk modes, the three recent fixes, and the whole broader-kernel ripple sweep all came back refuted, with the verifiers walking the callers, the invariants, and the host tests to kill each candidate. Across all those phases it found exactly one real defect, plus a documentation debt the milestone had accumulated.

* **The one real defect (Phase 1): a user-triggerable kernel panic.** The page-fault handler's window branch matched on the faulting address alone, not the CPU mode. The user segments are flat, so any user program could form an address in the page-cache window (`[0xC0000000, 0xC0000000 + window)`) and fault there; the branch ran ahead of the segfault arm, and on the default RAM boot, where no disk backing is set, `pc_fault` returned 0 and the handler panicked. So a user program that merely read `0xC0000000` halted the whole kernel; with a disk backing it would have looped on the supervisor-only page the fill installs. Reproduced with a freestanding probe (the unfixed kernel wedges; the serial shows the touch and then nothing), then fixed by gating the window branch on `!user_mode` so a ring-3 in-window fault falls through to the clean segfault, leaving the file system's supervisor-mode window access untouched. A by-hand fault probe, `winprobe`, is the regression: a user read of the window must be killed, never honored.

* **The documentation and comment debt.** The KRFFS dirty-mount comments overstated the contract (only the debug-shell `halt`, or offline `fsck.krffs`, clears the bit; a normal boot has no clean-unmount path, which is intended for an OS with no userland reboot). The CR0.WP comment understated the copy-on-write self-heal. Six in-code comments and the `pagecache.h`/`fsync`/`init_krffs` headers had gone stale against the window, the mount modes, and the GP-register reset. The Readmes still described a RAM-only file system: the mm Readme's fault handler had no window branch and no page-cache section, and the kernel Readme's limitations, memory map, source tree, and debug-shell table all predated the disk. `make help` did not list the disk-integrity targets. The audit corrected each, surgically, in the phase that owned it. One host-tool invariant was hardened in passing: the KRFFS root node's `parent_id` is now stamped to the reserved root id rather than relying on zeroed backing, so a forced re-mkfs over a non-zeroed file cannot break root `..` resolution.

## Verification

The global gate held green throughout and at the end: `make verify-style` 8/8, `make verify-host` (twelve host seam tests), and the module-path `make test` at 28 of 28. The whole-system manual pass exercised every mode on emulation: the default RAM boot, a `rach2.fswindow` and a `rach2.fsdisk` boot that mount and read KRFFS off the window, the SSH capstone (pubkey login to busybox ash over a dropbear pty, proving musl fork and execve startup survive the exec GP-reset), Doom run from `/` with sound and the framebuffer up, the `os-real-grub-disk` BIOS-to-GRUB-to-kernel boot off a real disk, and `winprobe` confirming the window panic is now a clean segfault the kernel survives. The vendored trees stayed untouched, and the default boot stayed byte-identical.

The fixes landed as scoped commits: the window-branch segfault and its probe, the KRFFS dirty-bit comments and the `parent_id` stamp, the recent-fix comment alignment, the stale-comment corrections, the Readme and `make help` updates, and the support-file coupling made explicit. The plan and its per-phase concerns are in `plan.md`.
