# Milestone 29 notes

This is the persistent record for information needed after a compaction or between documentation files. It is not evidence for a factual claim. Recheck every item against the repository before using it in an edit.

## Cross-document contradictions

* `CLAUDE.md` and `Readme.md` described all build output as living under `build/`. The root Makefile and `mk/build.mk` make that true for in-house components; vendored projects also build extracted trees and musl's install under `vendor/`. `CLAUDE.md` is corrected. Recheck the root Readme in its own pass.
* `CLAUDE.md` and `Readme.md` said the build does not run QEMU without distinguishing image builds from test targets. Image build targets do not boot QEMU. The run scripts and the test harnesses do. `CLAUDE.md` is corrected. Recheck the root Readme in its own pass.
* Both root-document contradictions above are corrected in `Readme.md`.
* The root `Readme.md` says the IPC subsystem provides atomic writes. The pipe implementation does not provide the POSIX `PIPE_BUF` guarantee: a write of 4096 bytes or less can use partial free space, block, and interleave with another writer. Revisit the root row during the file-system and I/O subsystem pass.

## Non-document defects

* The comment at the top of `rach2/guest.mk` says the response file avoids putting 87 objects on one command line. `OBJS` now has 88 entries, confirmed by `tools/check_guest.py`. This milestone does not edit source comments.
* `mk/build.mk` says a Docker `grub-mkrescue` call in `rach2/Makefile` uses `$(abspath ...)`. No `abspath` call remains in the in-house Makefiles or tools. This milestone does not edit Makefile comments.
* The `.clangd` comment says the host KRFFS tools receive host-compiler flags from the compilation database. `tools/gen_compile_commands.sh` excludes `krffs/`, so that database supplies no such flags. This milestone does not edit configuration comments.
* `make compile-commands` exits successfully but produces invalid JSON with the current Homebrew i686 toolchain. A wrapped recipe continuation matches the `i686-elf-*gcc` filter through its libgcc path, and `json_escape` does not escape the leading tab. The target's kernel coverage check does not parse the completed JSON. `mk/Readme.md` states the limitation; the generator needs separate code work.
* `tools/textcheck.sh` does not include `ports/doom/` among its roots, so it does not check the project-owned `ports/doom/Readme.md`. This milestone checks that file explicitly and does not edit the script.
* The default scope of `tools/prose_check.py --banned` excludes `vendor/`, so it does not check the six project-owned vendor integration Readmes or `vendor/busybox/patches/Readme.md`. This milestone checks those files explicitly and does not edit the script.
* A comment in `tools/mkdisk_grub.sh` calls `UBUNTU_IMAGE` a floating tag. The value is a digest read from `tools/ubuntu-image.txt`. This milestone does not edit script comments.
* The header comment in `tools/hosttest.sh` says the native tests run in milliseconds and implies that every exercised source also links into the kernel. `pwauth_hosttest.c` deliberately takes tens of seconds, and the suite also exercises utility sources and test-only hardware models. This milestone does not edit script comments.
* Comments in the root `Makefile` and `krffs/manifests/test.manifest` say `make test` checks every probe's success token. `tools/runtests.py` instead runs its explicit 63-program list, scores each program's debug-shell return status, and checks the guest clock separately. The image stages 105 guest programs, including helpers and programs reserved for dedicated or manual runs. This milestone does not edit Makefile or manifest comments.
* The header of `rach2/run.sh` says omitting the image boots the kernel into its debug shell. `k_main` refuses an unmounted root unless rescue mode was requested, so the working kernel-only command is `RESCUE=1 ./run.sh`. A direct harness boot confirmed both paths. This milestone does not edit script comments.
* `rach2/qemu_devices.sh` says `NET=off` disables networking, but it emits no QEMU network option in that mode. QEMU 11.1.0 creates its default e1000 device and SLIRP backend. The kernel does not support e1000, so guest networking is unavailable, but the virtual NIC is not removed. This milestone does not edit the script.
* The `mmap2` comments in `rach2/sys/syscall.c` say the syscall supports only anonymous private mappings. The implementation requires `MAP_ANONYMOUS` and rejects `MAP_FIXED`, but it neither requires `MAP_PRIVATE` nor rejects `MAP_SHARED` or unknown flags. Every accepted mapping receives private COW fork behavior. This milestone does not edit source comments or code.
* Comments in `rach2/sys/mm/vm.h` and `tests/musl/vmamusl.c` say four VMAs exist before a program runs. `elf_setup_vmas` inserts the loadable segments and one stack VMA; it records the empty heap only in `heap_start` and `brk`. The first non-empty `brk` growth inserts the heap VMA. This milestone does not edit source or test comments.
* The header comment in `rach2/sys/lib/ksignal.h` calls 1 through 64 standard signals. It defines the named Linux i386 signals only through 31; the implementation accepts numeric signals through 64, and musl reserves 32 through 34 before its real-time range. This milestone does not edit source comments.
* The `SA_*` comment in `rach2/sys/lib/ksignal.h` says the kernel honors `SA_RESTORER`. `signal_setup_frame` always uses the action's `restorer` field and never tests the `SA_RESTORER` bit. This milestone does not edit source comments or code.
* A keyboard-path comment in `rach2/kernel.c` says Ctrl-C is intercepted earlier. That is true only for the kernel debug shell. While a user session owns the console, the code converts the key to byte 3 and sends it through the line discipline so it can flush input and signal the foreground group. This milestone does not edit source comments.
* The contract comment above `tls_resolve_base` in `rach2/sys/proc/tls.c` says the function rejects anything the fixed TLS descriptor cannot represent. The function does not examine `limit`, `UD_LIMIT_IN_PAGES`, `UD_USEABLE`, or higher flag bits, although those fields do not change the descriptor. This milestone does not edit source comments or code.
* `sys_set_thread_area` installs the requested base in the GDT and process control block before copying entry number 6 back to the user descriptor. A descriptor on a readable, non-writable page therefore returns `-EFAULT` after changing the TLS base. This milestone does not edit code.
* Comments in `tests/tlsprobe.c` say the isolation phase switches between parent and child hundreds of times. The probe runs 3,000 iterations with user-mode delays in each process but does not count context switches. The TLS Readme states only the measured iteration counts. This milestone does not edit test comments.
* `rach2/sys/lib/krandom.h` says the best-effort fallback feeds ASLR. User programs are fixed-address i386 `ET_EXEC` images; the loader performs no address-space randomization. This milestone does not edit source comments.
* The header comment in `tests/auxvprobe.c` says a harness compares its `AT_RANDOM` bytes across two boots. No Make target or harness invokes the probe twice or parses that line. The default suite runs it once and checks only its exit status. This milestone does not edit test comments.
* `krandom_reseed` changes the generator key without changing `cc_src`. Current kernel code calls it only for the jitter fallback inside `krandom_seed`, which sets `cc_src` immediately afterward; the other callers are host tests. A later runtime caller could replace a trusted key while leaving `krandom_is_trusted()` true. This milestone does not edit code.
* Comments in `rach2/sys/fs/krffs.h` and `rach2/sys/fs/krffs.c` call directory IDs unique and parent references unambiguous. The IDs are 64-bit hashes, and the implementation does not detect collisions. This milestone does not edit source comments.
* The comment above `krffs_mix_id` in `krffs/stageimage.krffs.c` says a host-staged node and the same node created in the guest receive the same ID. The stager uses the parent-aware mix for every node, while guest-created and guest-renamed regular files use the basename DJB hash. This milestone does not edit source comments.
* The kernel reports `relatime` for every KRFFS root in `/proc/mounts`, although KRFFS reads never update atime. This milestone does not edit kernel output.
* The `fcntl64` contract comment in `rach2/sys/syscall.c` says `O_APPEND` and `O_NONBLOCK` are stored but not enforced. The read, write, socket, pipe, terminal, and device paths enforce them. This milestone does not edit source comments.
* The header of `tests/lstest.c` says KRFFS is flat and every file appears in the root. KRFFS is hierarchical, and the probe lists only the root. This milestone does not edit test comments.
* `tests/host/synthfs_hosttest.c` does not cover classifier branches added for `/dev/pts`, `/proc/disk`, the system proc files, or `/proc/net`; its header still describes the classifier generally. This milestone does not edit tests or source comments.
* `procfs_readlink_fd` renders fd links for `/proc/cmdline`, `/proc/disk`, and the four network snapshots, but omits `/proc/uptime`, `/proc/stat`, `/proc/meminfo`, and `/proc/mounts`. An fd link for one of those four falls through to `/proc/0/stat`. This milestone does not edit code.
* `/proc/disk` is always classified, listed, stattable, and openable by root. Before `diskinfo_probe` it reports `state not-asked`. Comments in `rach2/kernel.c` and `rach2/sys/block/diskinfo.h` say `rach2.diskdiag` publishes the proc file and that it does not exist without the option. This milestone does not edit source comments.
* `rach2/sys/fs/procfs.h` describes only the older per-process and cmdline subset and omits the current system and network files. This milestone does not edit source comments.
* The registry comment in `rach2/sys/fs/devfs.c` says only two raw disk windows are root-only, but the table contains `bootpart`, `disk0`, and `grubcore`. This milestone does not edit source comments.
* The root `Makefile` describes `make bootpart-test` as three boots, and `tests/bootprobe.c` says two boots share the probe. The target has four boot modes. This milestone does not edit Makefile or test comments.
* The comment above `discover_boot_devices` says a partition in the GRUB gap withholds both boot devices. The implementation withholds `/dev/grubcore` but continues to judge and may publish `/dev/bootpart`. This milestone does not edit source comments.
* `/dev/pts` is a resolvable synthetic directory but `getdents` on `/dev` does not list `pts`; it lists only the device registry. This milestone does not edit code.
* `procfs_gen_stat` maps `PROC_STOPPED` through its default branch to `R`, so a job-control-stopped process is reported as running rather than `T`. This milestone does not edit code.
* `pipe_read` removes each chunk from the ring before `copy_to_user` validates and copies the destination. If that copy fails, as many as 512 removed bytes are lost and are not included in the return count. This milestone does not edit code.
* `tests/host/pipe_ring_hosttest.c` checks the physical ring boundary but never places the monotonic counters near 32-bit rollover, although `pipe_available` relies on unsigned subtraction across that rollover. This milestone does not edit tests.
* `tests/musl/pipemusl.c` prints a failure when the child receives wrong data but still returns status 0. It is staged for manual use and is absent from the default runner. This milestone does not edit tests.
* The fallback in `fd_poll` reports mouse descriptors readable without consulting the mouse packet ring or supplying a wait queue. A poller cannot wait for a mouse packet and can repeatedly receive readiness followed by a zero-byte read. This milestone does not edit code.
* The header of `tests/musl/pollmusl.c` says a one-second `select` calls `pselect6_time64(413)` and falls back to `_newselect(142)`. The musl source and the built program show that a timeout whose seconds fit in 32 bits calls 142 directly; only an out-of-range timeout tries 413. This milestone does not edit test comments.
* A comment in `sys_pselect6` says the sixth syscall argument is passed on the stack. The i386 syscall wrapper loads that argument into `%ebp`, which the interrupt frame saves as `params->ebp`; the implementation ignores it either way. This milestone does not edit source comments.
* `raw_window_read` and `dev_disk0_read` return `-EIO` for a zero-length aligned read before EOF. They return zero only when the offset is at or past EOF. This milestone does not edit code.
* The debug-shell `ahci` command withdraws all three raw disk devices before re-probing. It republishes `/dev/disk0` only when `rach2.diskdiag` is present and does not test `recovery_publishes_disk()`, so a recovery boot without that option loses `/dev/disk0` after the command. This milestone does not edit code.
* Comments in `rach2/sys/block/recovery.h` and `rach2/kernel.c` say every image may write `/dev/bootpart` and `/dev/grubcore`. The metal build's `RACH2_DISK_READONLY` driver policy refuses their write commands. This milestone does not edit source comments.
* Comments in `rach2/sys/block/diskinfo.h` and `rach2/sys/fs/devfs.h` call `/dev/disk0` read-only without qualifying the recovery build, whose handler permits effective uid 0 to write. This milestone does not edit source comments.

## Facts for subsystem passes

* `block_probe` tries ATA by default. With `rach2.disk=ahci`, it tries AHCI first and falls back to ATA. Disk-root discovery scans the four MBR entries and mounts the first entry whose first sector is a valid KRFFS root; it does not depend on a host device path.
* The current vendor patch count is one for musl, two for BusyBox, none for Dropbear, one for TinyCC, and one for pdpmake. Each build script verifies its pinned tarball by SHA-256.
* `tools/check_guest.py` reports 88 kernel sources, 29 utility programs, five ish objects, and three staged `/src` trees. `tools/selfbuild_test.sh` checks 18 userland smoke tokens.
* `make test` checks each probe's declared outcome; it is not accurate to say that every special probe simply exits zero.
* `make os-real-disk` creates a partitioned disk-image file. `rach2/run.sh` can attach that image through ATA or AHCI and mount it as the persistent root.
* The fresh-Mac manifest uses the Homebrew cask `fuse-t` and the `coreutils` formula, which provides `gtimeout`. The direct commands are `brew install --cask fuse-t` and `brew install coreutils`.
* `tools/Readme.md` names every tracked file under `tools/`. Its checker descriptions were verified with the self-tests for comments, prose, the dev-log, kernel ELF, user ELF, set-id, embedded GRUB, sealed networking, and probe scoring. `sh tools/bootstrap_mac.sh --dry-run` and `make doctor` also passed.
* `tests/host/Readme.md` names all 36 discovered host tests, the three compatibility headers, and the FAT32 fixture builder. `make verify-host` passed all 36 tests with the documented compiler, dependency, logging, and watchdog contract.
* `tests/Readme.md` accounts for all 70 root test programs and all 35 musl programs. The default `make test` list has 47 root programs and 16 musl programs; a fresh run passed all 63 status checks and the host-clock comparison.
* `rach2/Readme.md` now owns only the kernel-level build, boot, option, run-script, source-map, debug-shell, hardware, and limit contracts. `make check-sources`, `tools/check_guest.py`, and `tools/check_kernel.py` passed; direct QEMU harness runs confirmed rescue mode and the no-root refusal.
* `rach2/sys/mm/Readme.md` now describes the implemented physical-frame, page-table, VMA, demand-paging, COW, usercopy, and page-cache contracts. It includes the AHCI backing path, module-layout check, fixed limits, allocation-failure behavior, and the actual default and host tests. `make verify-host` passed all 36 tests.
* `rach2/sys/proc/signal.Readme.md` now distinguishes the named signals 1 through 31 from the numeric range through 64 and describes pending-bit coalescing, fork and exec inheritance, permission, job control, supported action flags, the `SA_RESTART` and `rt_sigsuspend` limitations, signal frames, terminal delivery, and the actual default and manual tests. The default `make test` suite includes `sigprobe`, `ownprobe`, `waitprobe`, `pipeprobe`, `jobprobe`, and the high-signal cases in `musl/pwauthmusl`; `make verify-host` covers the line discipline's `ISIG` behavior.

The default `make test` run also exercises the real musl startup path before each musl program's `main`.

## Decisions and deferred questions

* The block pass corrected the old claim that `rach2.diskdiag` publishes `/proc/disk` and `/dev/disk0` together. It also distinguishes mode 0400 from the ordinary kernel's write refusal because effective uid 0 bypasses the mode check.
