## Phase 7, the kernel comments the milestone-53 round did not reach

Six units read `sys/proc`, `sys/mm`, `sys/tty`, `sys/ipc`, `sys/io` and
`sys/input.c` against the code. What they found and what was done with it:

* `elf_check` bounded the program header table with a sum that wraps, and
  never required this kernel's entry size, so the debug shell's `elf` command
  read a table outside the buffer it had loaded. Entry 139 of the shortcomings
  list; fixed and proved by mutation.
* `premap_kernel_window` and `map_mmio` each carried a range check that wraps.
  Entry 140; fixed, unreachable from this tree's callers, and the row is owed
  because nothing host-compiles `mm/paging.c`.
* The idle marker was reported as leaking from a halted process to whoever the
  timer switches to. Rejected. A process becomes runnable only from a state
  that parks it in `idle_wait_irq_off` or `idle_wait_irq_on`, and both clear
  the marker as the process resumes; a process that never halted cannot be
  runnable while another is halted, since the halt happens only when the
  scheduler finds nobody. A row was written and a mutation compiled with the
  reported fix removed: `procprobe` passed on both kernels, which is the same
  answer. The row and the fix were taken out again rather than kept unproved.

The rest of what those six units reported is comment work: headers whose
claims the code no longer keeps, in-body explanations that belong in a header,
and contracts a caller needs that no header states. That is Codex's to write
and is not yet applied.

* Phase 16, Doom and the audio matrix: `doom` and `audio`, the second of which

* Phase 17, the network path and the concurrency stress: `ping`, `packet`,

## What this run did, and where it ends

Phases 1 to 6 ran first and their findings are entries 116 to 136 of the
shortcomings list. Phases 7 and 8, the comment rounds, ran as twenty-four
units over the kernel and userland sources milestone 53 had not reached; they
found the faults recorded as entries 139 to 155, among them a `sudo` that
authorised a uid written inside a comment, an `rm -r` that emptied a symbolic
link's target, a program header table the debug shell read outside its buffer,
a pipe span held across a copy that can sleep, a page written back with
nothing holding its slot, and a second reader that slept through a hangup.
Phase 9 read the documents that round had not rewritten and produced entries
of its own. Phases 10 and 11 were superseded by milestone 53. Phases 12 to 19
are the suites listed above.

The tree at the end of this run passes all 89 suites on the testing host, and
the shortcomings list has no open entry: what remains in it is what only the
Lenovo can answer, written into the entries that name it.


## The sitting of 2026-09-21

The kernel of `b984b33c` was installed on the Lenovo through `bootctl kernel`
over SSH, tried once, and committed. What the first attempt installed was
`build/rach2-metal/kernel`, the live stick's build, which is compiled with
`-DRACH2_DISK_READONLY` and refuses every write command: it booted, found the
controller, the disk and the partition, and was then refused at the mount's
first write, so the machine halted with nothing mounted and fell back by
itself. That is entry 158, and `bootslot_validate_kernel` now refuses a kernel
that names the read-only policy.

Two readings were taken on the machine with the right kernel running. Its
codec is `0x14F1510F`; `/proc/audio` gives `pcm 0x000A0560`, which advertises
44.1, 48, 96 and 192 kHz at 16 and 24 bits, and `audiotest` left `requested
48000 programmed 48000 format 0x0011`. Its two pins read `raw 0x10 0x11`,
expand to `16 17`, and both select dac 16. Entries 126 and 127 record both.
The owner was at the machine and heard that tone from its speakers, so the
path from the encoder to the codec's output is confirmed on the hardware. A
tone is played loudly and without warning, which is worth saying before the
next one is started on a machine somebody is sitting at.

The size rehearsal was run once more at `b984b33c`, since entry 49 had
rewritten the ext2 write path after the last one: `RACH2_REHEARSE_LENOVO=1
tests/run installer-rehearse` passed in 1456 s over a disk of the machine's
488397168 sectors, so the install, the grow to 232 GiB and the boot of that
grown root hold with the batched writer.
