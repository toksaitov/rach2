# The Codex review of 2026-09-26

The fixes of the closing review's fifteen findings and of entries 199 to 223 had been read only by reviewers of the session. On 2026-09-26 the owner had them reviewed by Codex, at most three Astra units at the same time, together with the close's prose, which the session had written. The first round had five units over what changed after the closing review: the kernel and userland sources (unit A), the host tests (B), the system tests, probes, runner and tools (C), the manual pages and Readmes (D), and the close's records (E). Every later round was one unit over the diff of the round before's fixes, and the review ended when a round found nothing to change. The rounds found 48, 12, 7, 4 and no faults. Each finding was read against the code before it was acted on; the session fixed some itself and gave the rest to Opus agents, one group of files each, whose changes it read in turn.

A fix to a host test or its mutation script was run on the Mac as it was made; everything was run once more on the testing host at the end, with the build from clean, the full set and every changed mutation script, as `results-2026-09-20.md` records.

## Round 1

The installer and `dhcpc` (unit A):

* `utils/rach2-install` copied a recovery key to `/tmp/rach2-install-key.PID`, a name another process could make first as a symbolic link to a file root owns, which the copy then overwrote. The copy is made in a directory `mktemp -d` creates for the run, mode 0700, which the run removes as it ends (entry 224).
* The installer judged a key file's size before it added a newline to the last line, so a key of 16384 bytes with no final newline was accepted and written as 16385, which init refuses. The copy's last line is ended before the copy is judged, and the copy is what is written (entry 224).
* `dhcpc` wrote a claim that had gone again with the address it holds even when that address was one the interface already had, so a later `dhcpc -k` could take off an address it had not put on. It now writes the claim as the other claim writers do; `tests/host/dhcpc_hosttest.c` has a row for both cases and `tests/host/netutil_mutate.sh` a fault, `claim-rewrite`, that fails it (entry 225).

The host tests (unit B):

* `tests/host/fat_barriers_mutate.sh` took any nonzero exit of a mutated run as a proved barrier, a timeout or a fixture failure among them, and never ran the restored driver. A site is now proved only by an exit of 1 at a failed row that judges the medium; any other end stops the proof. Each restore is compared byte for byte with the saved source, and each driver's restored source is rebuilt and run once, after its last site, since a run after every site would add about an hour for the same bytes (entry 226).
* `tests/host/tcp_reset_hosttest.c` could not tell the reset's ACK-flag test from its number test, since its reset without the flag also had a wrong number. A row sends a reset without the flag but with the number that acknowledges the SYN, and `tcp_reset_mutate.sh` has a fault for each test (entry 226).
* `tests/host/packet_hosttest.c` did not check that a full loopback ring keeps the datagrams it took: every payload was the same. Each datagram now has its own number, a row requires the ring to deliver the ones it took in order and none it refused, and `ip_mutate.sh`'s fault `overwrite` fails it (entry 226).
* `tests/host/exfat_hosttest.c` did not require the file its synced unlink removed to be gone, nor the file an earlier sequence unlinks while it is held open. Two rows require both names gone, and `exfat_scan_mutate.sh`'s fault `unlink` must fail both (entry 226).
* `tests/host/bcache_cost_hosttest.c` bounded its counts only from above, so a counter that answered 0 passed. Three rows require the reads each measured operation must make, and `bcache_mutate.sh`'s fault `uncounted` fails all three (entry 226).

The system tests, the runner and the tools (unit C):

* `tests/system/host_tools_mutate.sh` stopped only its `deadline` wrapper when it was interrupted, so a compiler or test the wrapper had started went on reading a source the script was putting back. Each job now leads a process group of its own and the whole group is stopped, and waited for, before a source is restored (entry 226).
* `tests/system/runner/deadline.c` passed no signal on to the group it runs, so a `deadline` stopped by hand left its command running; it now passes on `SIGTERM`, `SIGINT` and `SIGHUP` (entry 226).
* `tools/dev/poll_kernels.sh` could not finish its first build, since the private tree it builds in had no rule for the ELF checker the kernel's link asks for. It gets the same one-line makefile the GPT and USB proofs use, and it built both orders on the Mac (entry 226).
* Row 6b of `tests/system/suites/installer.sh` tried its key login once after the console's first prompt, which init forks before it starts the SSH server; it now waits for the server's banner first. Row 6c took any error from ssh but a refused key as proof that no server answered, and probed without waiting for init's test for a key. Row 6 called `fail`, which is a variable in that suite, and had 6b's race. Rounds 2 to 4 changed row 6c again; its final form is below (entry 226).
* `tests/system/rows_mutate.sh` took any failure of a probe as proof of the row it names, and its `devprobe` fault also let each open of a device table entry write a word of kernel memory. Each probe phase now requires the failure line of its own row, the `devprobe` fault is in `entry_index` alone, and the `arping` phase reads the harness's trace for the status step's own failure (entry 226).

The pages and Readmes (unit D) and the records (unit E):

* Fourteen passages of the pages and Readmes the close changed said more than the code does, or said it unclearly: `ifconfig -a` with an interface named works; a timeout never expires early, where the wait may still end early; a sleep keeps its first deadline only with a nonzero remainder; the time limits are applied to the seconds first; a class's netmask was not defined; a failed netmask request unconfigures the interface only for `EINVAL`; the KRFFS write rule, the stager's identifier check, the recovery key reader and the `disk write` command were each described wrongly in part; and three sentences gave code intentions. Each passage was rewritten against its source (entry 219).
* Nineteen errors of the records, among them that the metal kernel issues no write command at all, where USB storage can still write; that no image has a demonstration key; the count of the closing proofs' failures; and figurative sentences. Each was corrected in place; the account of why these fixes had no Codex review was rewritten when this review ran.

Found while fixing round 1: `rach2/sys/block/Readme.md` left `READ DMA` out of the metal kernel's read commands; a comment of `ip.c` named a /0 card that the loop skips; and `rach2-install`'s `find_recovery` ran in a command substitution, so its `die` ended only the subshell, and a recovery partition mounted elsewhere was taken for none, after which an update wrote the root with no archive of the machine's configuration (entry 224). Each is fixed.

## Round 2

* `deadline` could lose a signal that came as its command ended, and killed the group at once after passing a signal on, with no time for cleanup. Fixed in rounds 2 to 4, below.
* `host_tools_mutate.sh`'s cleanup waited without end on a process of the group that was stopped. `CONT` now follows `TERM`, and whatever is left after five seconds gets `KILL`.
* Row 6c could still probe before init's second test for a key, since init forks a session before that turn's test. Final form below.
* `ip_mutate.sh`'s fault `limited-scan` matched the comment of `ip.c` that round 1 had corrected, so it could not have run; it now matches the code.
* The harness took a read error of a `sendfile=` step's file for the file's end, and the step passed. `send_file` fails on the error, a selftest row requires a step whose file cannot be read to fail, and `harness_input_mutate.sh`'s fault `unread` fails that row (entry 226).
* Six sentences of the pages, Readmes and records were narrowed or corrected.

## Rounds 3 and 4

* Row 6c's count of `dropbearmulti` processes missed a server init had forked and not yet run. Init now prints `init: sshd: started as pid N` in the turn it forks the server, before it forks another session, and row 6c requires no such line in the log up to a token typed at the third console session, which init forks only after the turn that forked the second has tested root's keys; a log that cannot be read fails the row. `recovery_disk_key_mutate.sh` has two faults for the row, the server started with no key and the server started one turn late, and the installer fault it had follows the new copy of the key (entry 226). `init(8)` and `recovery(7)` give the new line.
* `deadline` blocks the signals it catches, and takes one already pending as caught, while it decides whether to return its command's status; watches the group after a signal it passed on or after its limit, kills what is left two seconds after the signal and returns when the group is gone or five seconds after the kill. A signal that comes after it has decided to return the command's status is not passed on, as one sent after it has ended is not; `deadline.c`'s header says so, since no further test closes that window. A signal ignored when `deadline` started stays ignored.
* `host_tools_mutate.sh`'s timer left a `sleep` holding the script's output; the timer is one process now.
* A sentence of `busybox-networking(1)` was narrowed to the failure it describes, and a function placed between another function and its header comment was moved above that comment.

The fifth round read the fourth's fixes to `deadline.c` and row 6c and found nothing to change, and the review ended there.
