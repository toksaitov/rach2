# Milestone 53: notes

## Where the work stands

In progress on 2026-09-19, after milestone 51 was accepted at `1ad9d0cc`.

## Phase 1: the build

* The product rules left `tests/system/suites.mk` for `mk/images.mk`, and step 7 of `tests/run style` refuses a rule under `tests/` whose target is an image, a disk, an ISO or a stick. The root Makefile lost its duplicate credentials block and its stale disk comments, and `mk/host.mk` compiles every host program with one link line under `-Werror`.
* The fingerprint became an explicit `fingerprint` step, an order-only prerequisite of every object, so a dry run removes nothing (eleven files under `build/ish` before and after `make -n` with a changed flag). The first form of that change put the prerequisite line before a component's `all`, which made the first object the default goal: `make -C ish` compiled one file, and `make -Bn -C tests` printed only the step. The line now follows `all`, and the fragment restores the goal it found.
* `-Werror` had been proved with the Mac's clang only. The testing host's gcc 15.2 rejected 25 sites in six programs, format truncation, a cut `strncpy` and a header read before it was set, which the style run had not seen because `make` kept the binaries compiled before the flag. The fixes are in the code: the two fixture checkers size their message buffers to the longest name they format, `wavcheck` zeroes the header before reading it, the harness copies a socket path whole or refuses it, and `guestcheck` and `prosecheck` join a path whole or stop. The same move had linked `growset` from two sources, its own and the `utils/growset.c` it includes; the rule links one again.
* Five tools the scripts compiled by hand with a bare `cc` (`asciiscan`, `fatchains`, `grubembed`, `hostcheck`, `machine_net`) have make rules, `make` builds every host tool through `host-tools`, and the three disk tools are prerequisites of every rule that runs `mkdisk_grub.sh`, so parallel suites never compile them inside the script.
* `tools/dev/gen_compile_commands.sh` writes twelve databases under `build/compile_commands/`, one per unit: the four kernel variants, the tests, the shell, the utilities, Doom, the musl programs (the build script prints its commands under `MUSL_PRINT_COMMANDS`), KRFFS with its mount tool, the host tools from a dry run of `print-host-tools`, and the host tests (`host.sh` under `HOST_PRINT_COMMANDS`). `tools/verify/dbcheck.sh` requires every in-house source to be in one, or to be a fragment another source includes, or a fixture under `tests/system/fixtures` that a test script compiles; 437 sources pass. It runs in step 7, and one entry removed from the tools database is refused by name.
* The proofs on the testing host on 2026-09-19: a flag change rebuilt `ish` in under a second; `make -j32` from the in-house directories removed compiled 316 files in 4 s and left nothing to do; a touched `vfs.h` recompiled 13 objects and a touched manifest remade 3 images; two concurrent component makes and two concurrent whole-tree makes ended without an error and with nothing left to do.

## Phase 2: the judges

* The judges are the testing host's: gcc 15.2.0 as `cc` and, behind the `i686-elf-gcc` wrapper, the same compiler for i686-linux-gnu with the distribution's defaults switched off; clang and clang-format 21.1.8; cppcheck 2.19.0; shellcheck 0.11.0; sparse 0.6.4; pmccabe 2.8; QEMU 10.2.1. `tools/setup/judges` records each tool's version line, and `doctor.sh` prints the version it finds beside it: on the Mac every judge but shellcheck is another version (Apple clang 21, clang-format 23.1.1, cppcheck 2.21.0, QEMU 11.1.1, a Homebrew cross GCC 16.2.0), reported and not counted missing, since a check whose verdict depends on the version is judged by the record. Two faults in `doctor.sh` came up on the way: `bzip2 --version` compresses its standard input after printing, so the report waited on the input it inherited, and `mandoc` has no version option, so the report had counted it missing since milestone 51.
* The full set's time on the testing host, measured on 2026-09-19 with 64 workers at milestone 51's acceptance: 22 min 23 s under KVM (timeout factor 4, the longest suites sealed 989 s, diskrate 396 s, grow 322 s) and 17 min 33 s under TCG (factor 1, sealed 705 s, diskrate 384 s, selfbuild 339 s). The allowance is that time plus a quarter: 28 minutes under KVM.
* `tools/`, `tests/system/` and `krffs/` are under cppcheck, at c99 on a 64-bit platform since that is how they are compiled, and `tools/` joined the in-house list the convention greps read. The day's run found 64 things: 12 in the vendored terminal library fsviz includes, 25 members of the on-disk layouts and the fixture's copy of the kernel's VFS structures, and 27 in the code. The 27 are fixed, each in its own commit: a `realloc` that lost its block on failure and a `calloc` used unchecked in pcapcheck, three leaks of the console name in runutil, a logical partition table read before it was filled in mkmbr, two lookups in setidcheck that dereferenced a pointer the search could leave null, a bound the tag parser had already checked, a block-size test growset had decided before it, a shadowed buffer and an unread advance in the harness, an unused member, an uninitialised fixture and a shadowed sample in prosecheck, three places guestcheck's normaliser and include scanner confused the analyser, the Windows file time composed by union halves in the KRFFS platform layer, and an argc test the five KRFFS tools cannot fail. The vendored library, the layout structs and one array parameter C cannot make const are the exceptions, written in `cppcheck.suppress` with their reasons.
* The six programs that decide verdicts (elfcheck, cfgcheck, setidcheck, prosecheck, runtests, harness) are compiled again under ASan and UBSan by the host tier and their selftests run there. The first run found setidcheck handing qsort an empty list's null array, which glibc declares never null, and, on Linux where the sanitizer counts leaks, the allow list and two selftest tables never freed; the list sort skips an empty list, `main` frees the allow list through a `run` function, and the selftest releases its tables. The style suite's checker selftests now build elfcheck and cfgcheck through make, under the host flags, instead of a bare `cc -O2`.
* The proof of the sanitized selftests: elfcheck's user checker made to read two program headers past its table (`i < e_phnum + 2`), driven by a script that restores the source in a trap. The plain `-O2` build's selftest still reported every case in order, since the bytes past a stack fixture read as anything; the sanitized build stopped on a stack-buffer-overflow at the first case. Restored, both pass.
