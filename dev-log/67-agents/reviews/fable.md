**Review of the fixup 67 draft triage, against `origin/milestone/66-terminal` (364913c48).**

**1. Name lookup speed.** Real; two causes, both in the code. (a) `bcache.c:118` indexes the cache with `BHASH 4096` buckets while the cap allows some 262k 4 KiB buffers at 1 GiB, so every hit walks a chain that grows to ~64 as the cache fills; a miss at the cap scans the LRU list for a victim (`bcache.c:711`). That is the uptime degradation. (b) No name cache: `vfs.c:1316` calls `ops->lookup` per component; `ext2_lookup` (`ext2.c:799`) scans directory blocks (no `dir_index`: `mkext2.sh:167` turns it off) and `node_for` (`ext2.c:~1185`) walks the mount's linear node list, then `inode_load` reads through bcache. `ext2_getattr` (`ext2.c:875`) already answers from the in-memory node, so "keep cached stat off bcache" is misstated: the cost is in lookup. Size: bucket count from the limit, 1 subtask; ext2 node list to a hash, 1; a VFS name cache with negative entries, invalidated at the `vfs.c` mutators that already emit inotify, 3-4. Files `bcache.c`, `vfs.c`, new `fs/dcache.c`, `ext2.c` (node_for only). QEMU for correctness, Lenovo for the numbers. Keep; the bucket fix first.

**2. Lock scaling.** Real as measured, but the cause is the one big kernel lock (`proc/Readme.md:3`, `vfs.Readme.md:105`) plus ext2's `ns_serialised` namespace lock (`vfs.c:622`). Not a fixup. Cut; item 1 lowers the per-call time the thread test measures. Record it under Limits.

**3. Timestamps.** Real. `inode_load` reads `raw[128]` and `le32` times (`ext2.c:405,428-430`); `inode_encode` writes 128 bytes (`ext2.c:1677`); `ext2.Readme.md:99` states seconds and the 2038 clamp. `vfs_stat` already has nsec fields (`vfs.h:104-109`), and the mount check admits 256-byte inodes (`ext2.c:5502`). The triage's "5489 assumes 128 for rev 0" is correct behaviour, not the bug; the gap is bytes 128-255 (`i_extra_isize`, the `*_extra` fields with their epoch bits). `mkext2.sh:167-170` makes `-I 128 ... ^extra_isize`; `E2FSPROGS_FAKE_TIME=1` at line 170 is Muse 2.3's 1970 stamp: set it to the commit's date. 4-5 subtasks; `ext2.c`, `mkext2.sh`, `tests/host/ext2_hosttest.c`, Readme, man. Image re-run, no GNU rebuild. Keep.

**4. Threads.** Real, two separate causes. (a) Every per-record operation walks `proc_list`: pid allocation (`proc/Readme.md:75`), `proc_wake_sleepers` on every tick (`process.c:242`), `get_process` (:304), `fork_nproc` (`syscall_proc.c:2122`), `rlimit_set` (:5389), scheduler pick (`sched.c:117-127`) and steal (:147-152), since "the run queues are the process list" (`sched.c:24-26`). Fix: pid table, per-user count, real per-CPU ready lists, a sleepers list. 4-5 subtasks in `process.c/.h`, `sched.c`, `syscall_proc.c`; the riskiest kernel task; QEMU `-smp 4` and Lenovo. (b) `futex_wake` marks n waiters then `wq_wake_all(&_queues[bucket])` (`futex.c:281`); all waiters of one word share a bucket, so each wake-one wakes all 500, which re-check and sleep: that is the superlinear curve, cubed by (a). Fix: a wait queue per `futex_q`. 1-2 subtasks, `futex.c` alone. Keep both, as two tasks.

**5. Time.** vDSO: real (`arch/Readme.md:183`), and the largest item: a user ELF from the cross toolchain, a vvar page with TSC mult/shift (the clock is tick-based, `clock.c:73`, with HPET sub-ticks user space cannot read), auxv at `syscall_proc.c:1605`, maps, gdb. 6-8 subtasks, x86-64 first. Keep only if a loop frees. Finer tick: `TICK_HZ 100` (`platform.c:58`) is also hard-coded as 100 in `timerfd.c:45`, `clock.c:73`, `syscall.c:2346`, and `times()` returns ticks as `CLK_TCK` (`syscall.c:2277-2299`), so 1000 Hz needs a kernel `TICK_HZ` and conversion to USER_HZ where a program sees `clock_t`: 4-5 subtasks across those files and `futex.c` (deadlines in ticks, `futex.Readme.md:35`, which makes Python's 5 ms GIL interval a 10-20 ms wait). `clock_getres` 1 us (`syscall.c:537`): one line, little effect. `times()` `(int32_t)kernel_ticks` (`syscall.c:2299`): real; at 1000 Hz it goes negative in 25 days; fix with the tick. Keep tick, getres, times; vDSO optional.

**6. Limits.** Real: `FD_TABLE_LIMIT 1024` (`fd.h:24`), `rlimit_set` refuses root above it (`syscall_proc.c:5385`). Raising it touches the shared table that grows to all entries so no entry moves (`fd.c:347`: needs chunks at 65536), `fd_held[FD_TABLE_LIMIT/32]` per thread (`process.h:354`), `poll.c:36`, `syscall_fs.c:3627`, `utils/su.c:53`, `sudo.c:32`, limits(7). 4-6 subtasks; QEMU with `tests/limitprobe.c`. R2-028's 256/512 is not the kernel (`PROC_COUNT_POLICY 4096`, `process.h:20`) but `/etc/rach2/limits` in `os-real-gnu.manifest:150`: one line. Keep.

**7. inotify and sysctl.** inotify: `vfs_setattr` emits only `inotify_file` (`vfs.c:1807`), never to the parent: real. chown gives IN_ATTRIB on the file watch by `setattr_events` (`vfs.c:1769`), so "chown emits nothing" needs a QEMU check before anyone chases it. Fix at `sys_fchmodat` (:8039), `sys_fchownat` (:8197), `sys_utimensat` (:11632): resolve parent and name as unlink does; 2 subtasks. sysctl: a static text table (`synthfs.c:195-231`), three writable entries (:238). Add writable `fs.inotify.*` (`inotify.c:30` constant to variable), `fs.file-max`, `fs.nr_open`, `vm.max_map_count`, `net.core.somaxconn`, `kernel.random.boot_id/uuid` (`krandom_bytes`, `krandom.h:47`), and `kernel.overflowuid/overflowgid` = 65534: **bubblewrap reads `/proc/sys/kernel/overflowuid` before parsing arguments and exits 1 without it, which is Muse 1.1's "`--help` ... exit status 1"**. 4-5 subtasks. Keep.

**8. procfs.** All real: `Cpus_allowed` text at `procfs.c:1561`; snapshot at open with no regeneration (`procfs.c:1-10`, `procfs_read` :4597); `/proc/PID/ns` resolves (`synthfs.c:338`) but its readdir gives nothing; maps `" 00:00 0 "` (:1245) though the vma keeps its file (`vm.h:103`); cpuinfo siblings = cores = `smp_cpu_count` (`cpuinfo.c:310-312`), no sysfs topology. Muse 2.5 is readlink showing the `ls` process's own descriptors (`vfs.Readme.md:69`); `open` is right; cut. 7-8 subtasks: split into 8a (status, snapshot, ns, maps, pid stubs: `procfs.c`, `synthfs.c`) and 8b (topology: `cpuinfo.c`, sysfs).

**9. Syscall gaps.** All real against `x86_64/systab.c` (no `COPY_FILE_RANGE`, `FACCESSAT2`, `OPENAT2`, `PIDFD_*`, `MEMBARRIER`, `EXECVEAT`, `PIVOT_ROOT`); `no_copy` returns EINVAL by design (`syscall_fs.c:9683`); `clone3` refuses bit 32, so `CLONE_CLEAR_SIGHAND` (`syscall_proc.c:2550`); `prctl` default EINVAL (:7305); `lseek` handles whence 0-2 (:4262); no `O_TMPFILE`; `getrusage` has no fault fields (:3187); `MAP_POPULATE` ignored; `ptm_read` returns 0 at `slave_opens == 0` (`pty.c:~212`). About 17 subtasks: split into 9a fs (`syscall_fs.c`, `vfs.c` resolve flags, `pty.c`, `ext2.c` for O_TMPFILE) and 9b proc (`syscall_proc.c`, `mm/`, a pidfd anon type). Keep.

**10. Sandboxes.** The kernel gaps are larger than stated: `pivot_root` absent; `umount2` has no `MNT_DETACH` (`syscall_fs.c:3342`), which bwrap uses to drop the old root; type `proc` mounts only over `/proc` (`vfs.Readme.md:144`), which bwrap's `--proc` needs elsewhere; plus the ns readdir (8a) and overflowuid (7). Binds, `MS_REC` and read-only remounts exist (`syscall_fs.c:3245-3300`). 3-4 kernel subtasks (`syscall_fs.c` mount section, `vfs.c`, `ns.c`), two ports (bubblewrap 0.8.0, the last with autotools, since the tooling machine has no meson; socat), install, and the config flips: Claude's managed settings `sandbox.enabled=false` and Codex's `sandbox_mode = "danger-full-access"` (`codex.sh:74`). Landlock: cut. The pinned Codex runs its bundled bwrap (`codex.sh:6`, `codex.1:149`); R2-025's Landlock claim is stale. Proof: real bwrap in QEMU, then the agents on the Lenovo. Keep as the agents' headline.

**11. Tools.** Real and cheap. Node, rg, fd, shellcheck, ninja, git-lfs: one recipe each beside `vendor/gnu/agents/packages/` (the layer is x86-64 only; naming them under `GNU_AGENTS` is a taste call). pip: `python.sh:24` `--with-ensurepip=no`; one port rebuild (minutes). `/usr/local`: a mkdir in `install_root.sh`. Chromium: Debian's `/usr/bin` script is copied as is (`install_root.sh:213-220`); make it a symlink. 6-7 subtasks, image re-run. Keep.

**12. init.** Real: `waitpid(WNOHANG)` then `sleep(1)` (`init.c:2554-2557`). A SIGCHLD handler without `SA_RESTART` ends the sleep. 1 subtask; fold into 6.

**13. ASLR.** Real (`mm/Readme.md:220`): `ELF_ET_DYN_BASE` (`syscall_proc.c:1563`), interpreter (:1519), stack (:1584), `vm_find_free` from a constant. Needs a per-mm mmap base and random offsets; `krandom_u32` exists. 4-5 subtasks; x86-64 first, i686 has no room below `0xB0000000`. QEMU. Keep.

**14. IPv6 loopback.** Real (`syscall_net.c:387`). v4-mapped sockets, `sockaddr_in6` in eight calls, `IPV6_V6ONLY`, `if_inet6`, `tcp6`, netlink v6 addrs (`netlink.c:1533` branches already). 6-7 subtasks in `syscall_net.c`, `socket.c`, `netlink.c`, `procfs.c`. A non-loopback v6 connect must fail fast or Happy Eyeballs stalls. Keep only if a loop frees.

**15. TCP.** Partly real. LAST_ACK leaves only on `ack == snd_nxt` (`tcp.c:2503-2514`); the FIN retransmits with `TCP_RTO_MIN` 1 s (`tcp.h:70`; Linux 200 ms) doubling to 60 s for 7 tries (`tcp.h:74`), so a peer that never ACKs holds a socketless block for minutes with a log line each. Likely fixes: RTO_MIN 200 ms, an orphan timeout, quieter logs. 2-3 subtasks after one capture in QEMU. Keep, small.

**16. sock_diag and orphans.** Two unrelated things. The remnant: unix diag messages are built in 512 bytes and never split (`netlink.c:400,1433`), so 44 bytes = header + `unix_diag_msg` + RQLEN attr of a nameless, peerless socket; check `msg_attr` alignment (:364) and the NAME length with NUL (:1452). 1 subtask. The orphans: `unix_release` hangs up and wakes the peer (`unix.c:696-725`); the code shows no cause; one bounded strace on the Lenovo, then stop. Keep, small.

**17. Logins.** `rach2-install --update` keeps `/home` (`rach2-install:991-1133`); `/root` is kept by neither path. Cheaper than staging tokens into images: teach the installer to keep `/root`'s dotfiles as it keeps `/home` (1 subtask), plus `tools/dev/machine_logins.sh pull|push` over the five paths `agents_accept.sh:58-60` lists (1-2 subtasks). Owner-only proof.
