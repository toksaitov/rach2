1. The IPv6 waits are incomplete. 18a's `ping -6` requires 18c, since `syscall_net.c:386` rejects AF_INET6; reaching another host also requires 18b's neighbour discovery. Move those checks to integration. 18c must wait on 18b for routing, neighbour resolution and multicast membership. 18d must wait on 18c for widened socket snapshots and `ss -6`: `network/socket/netlink.c:1533` currently returns an empty IPv6 diagnostic dump. No objection to 18b's SLAAC and inbound echo proof after 18a.

2. Give 18a ownership of the actual interface records and shared APIs. Addresses live in `network/driver/netdev.h:150`, not `netif.c`; `netdev_ops` at line 125 has no multicast operation. e1000 clears its multicast table (`driver/e1000.c:586`), whereas both Realtek drivers already accept all groups (`rtl8139.c:161`, `rtl8168.c:733`). Define group membership, interface scope and receive-interface propagation first. Update Ethernet's transmit-down check as well as dispatch (`ethernet/ethernet.c:49,86`). Preserve IPv4 routing callers in `ip/ip.c:351,404` and `socket/netlink.c:694`; TCP and getsockname also depend on `ip_source` (`tcp/tcp.c:1501`, `syscall_net.c:1458`).

3. Specify the boundary between ND and ARP. ARP directly releases IPv4's pending packets (`network/arp/arp.c:214`); flushing it discards that queue (`:120`). The queue has a 32-bit next hop and always emits IPv4 (`ip/ip.c:175,226`). Give ND a separate bounded queue/cache, or explicitly assign a shared replacement. Include interface/address removal, expiry and failed-resolution notification: `netconf.c:504` currently flushes ARP and aborts affected TCP connections, while `netif.c:299` merely changes the up flag. These hooks cross 18a, 18b and 18c.

4. 18c is too large for one loop. Split transport conversion from the socket ABI after agreeing the address representation. TCP endpoints are 32-bit (`network/tcp/tcp.h:116`); UDP matches the socket's 32-bit addresses (`udp/udp.c:184`); queued sender addresses are also 32-bit (`socket/socket.h:138`). Include scope IDs, mapped-address binding conflicts, family-aware snapshots and ancillary data. `recvmsg` clears control data (`syscall_net.c:1890`) and rejects raw sockets (`:1824`). UDP currently sends checksum zero and never verifies it (`udp/udp.c:248,158`); IPv6 needs both directions checked. TCP's PMTU calculation subtracts IPv4's 40 bytes (`tcp/tcp.c:842`).

5. 18b/18d need explicit ownership of the remaining contracts. Assign RFC 7217's persistent secret, MLD query/leave handling, RDNSS publication to the resolver, and enforcement of `disable_ipv6`, forwarding and temporary-address settings. Listing sysctls alone does not implement them. 18d also needs `fs/synthfs.c:240` for proc entries, beyond `procfs.c`, and BusyBox configuration plus a DHCPv6 lease script: `vendor/busybox/rach2.config:1016` disables `udhcpc6`. Rewrite "unreachable fails at once" as "no usable route fails at once"; route lookup can establish that condition (`network/ip/ip.c:404`), but cannot immediately detect a remote black hole.

6. QEMU user networking can prove basic SLAAC and outbound IPv6 TCP to an IPv6 host listener, without Internet IPv6. SLIRP advertises an autonomous prefix, and QEMU provides `ipv6-host`. [SLIRP source](https://android.googlesource.com/platform/external/qemu/+/emu-master-dev/slirp/ip6_icmp.c), [QEMU documentation](https://www.qemu.org/docs/master/system/qemu-manpage.html). The present launcher uses user networking (`rach2/qemu_devices.sh:116`), but its default port forwarding proves IPv4. Add a tap or two guests sharing Ethernet for controlled DAD conflicts, RA expiry, multicast, fragments and PMTU. Do not count ordinary SLIRP connectivity as those proofs.
