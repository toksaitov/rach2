# Milestone 17: closing the deferrals

Milestone 15 implemented privilege and recorded its deferrals. Milestone 16 audited the implementation. This milestone resolves the list: each deferral either ends with a probe that can fail or remains a policy decision whose reason is recorded here.

The plan (`plan.md`) preceded the implementation and received a Codex review. Implementation then required two recorded corrections. In phase 10, a review found that the planned lock ordering held a lock across a terminal read. In phase 11, the same rework removed the contention case described by the plan. The plan was updated to describe the resulting implementation.

The milestone used seventeen phases and one commit per phase. Each phase ran the complete verification set and received an independent Codex review. Every finding was checked against the code before its commit.

## What was closed

Descriptor lifetime came first because three later phases depend on it. An open descriptor now identifies the same file across `unlink`, `rename`, and file-system relocation of a growing node. The fd layer holds a reference. Unlinking an open node removes its directory entry but frees the node only after the last descriptor closes. Previously, rename could leave a descriptor writing to a reused node.

The remaining work uses the credential library in `utils/pwauth.c`. It defines one comparison, salt alphabet, replacement procedure, and lock. The lock is a file created with `O_CREAT|O_EXCL` that contains the writer's pid, and the library never breaks it. An age limit cannot distinguish a stopped writer from a dead writer. Once another process breaks the lock, the operation cannot be made safe because there is no `funlink`. Refusal affects only another writer because readers do not take the lock. Replacement writes a temporary file named with the writer's pid, applies the original owner and then its mode, flushes it, checks the lock again, renames the file, and flushes again through the descriptor that remains open on the file. The second flush is required to report a writeback error. The three results, published, unflushed, and unchanged, determine the caller's exit status because an active but unflushed change is not a successful completion. This phase took twenty-one review rounds; several late rounds found defects introduced by the preceding fix.

`passwd` is the first program that writes a credential file. It is setuid root, chooses the account from the real uid, prompts before starting the transaction, and holds the transaction only across the re-read and publication. The phase 10 review required this ordering. Taking the lock early kept the account, hash, and file consistent by construction, but held the lock across two terminal reads and allowed a user at the prompt to block every other writer. Taking it late instead detects an intervening change. If the record changes while the password is being typed, the program reports the conflict and changes nothing.

`adduser` is restricted to root and writes three databases plus a home directory under one transaction. A lock cannot make four changes atomic, so the publication order preserves a readable state after every prefix: shadow with a locked field, group, home directory, then passwd. The documentation states what each prefix leaves and how root removes it. Failure injection checks the order. A second build of the same source terminates immediately after a named publication, and one probe round at each point checks the resulting paths, the byte-identical files, and the diagnostic from the refused re-run.

The console now requires login. `utils/login.c` authenticates, then calls `setgroups`, `setgid`, and `setuid` in that order. Init is no longer one program with a fallback list. Two builds produce separate artifacts, and the strict artifact contains neither a code path nor a string that names a shell. The split occurs at compile time so an omitted runtime marker cannot restore an unauthenticated root shell. `make login-test` boots two images that differ only in the init artifact declared by the manifest. The strict image must refuse repeatedly, while the permissive image must reach `uid=0`; the permissive result establishes that silence from the strict image represents refusal.

Staging `/bin/ping` exposed a denial of service available to any SSH user. Its wait loop executed `sti; hlt` inside a syscall, where the timer skips `schedule()`, so each unanswered attempt prevented every other task from running for four seconds. The wait now sleeps with two bounds: an armed `wakeup_tick` lets the timer make it runnable, and the same deadline in the wait predicate prevents a woken task from re-enqueueing after disarming its timer. The single in-flight slot records its owner, so a second caller receives `-EBUSY` instead of replacing the first request.

Attaching a disk now mounts it. After `make os-real-disk`, one command starts a persistent Rach2 system in which created accounts and changed passwords survive power loss.

The milestone closes two network omissions. An empty UDP datagram is now delivered. A separate flag records receive-slot occupancy, so a zero-length payload is no longer constructed, sent, accepted, and then discarded because its length also denoted an empty slot. A stream socket also keeps its bound local port through `connect`. One listener excludes a second listener on the same port. The check occurs when the listener is published because `bind` and `listen` are separate syscalls; checking only `bind` can be bypassed by binding both sockets before either listens. Simultaneous open also works, which loopback makes reachable.

## What the reviews caught

The reviews found two console denial-of-service defects outside the planned probes. Pressing `^Z` at the login prompt stopped a process that had no parent shell to continue it. Running `stty -icanon min 0` before `exit` made every later login read zero bytes immediately. Init now continues stopped children because only the parent can undo a stop and `SIGSTOP` cannot be caught. Login now resets the terminal line before prompting, as a getty does.

Three findings involved programs accepting records that musl's parser skips and then reporting success. `passwd` treated `x:1000junk` as uid 1000, while `getpwnam` rejects it. Under the lock, it rechecked a shadow record's hash but not the record shape, so it republished an aging field that became invalid while the prompt was active. `adduser` counted uids with `strtoul`, which saturates where musl's parser wraps. All three paths now accept exactly the records accepted by musl.

Another defect was in a test. A boot test searched for a token that appeared in the console's echo of the command intended to print it, so the test passed with a deliberately broken kernel. Mutating the code and requiring the test to fail exposed three separate vacuous tests during this milestone. Reading the tests alone had not exposed them.

## What stays deferred, and why

`SO_REUSEADDR` remains a no-op, so the listener check considers only live listeners rather than every block in the connection table. Counting an accepted connection or a `TIME_WAIT` remnant would prevent a server from restarting after a session, and `setsockopt` provides no override. The probe checks that restart succeeds.

Ping retains one request slot for the whole machine. A request queue would need a second wait queue and a fairness rule for a shell command with no visible queue. The single slot reflects the raw-socket non-goal; with a complete `SOCK_RAW` implementation, each caller would own a socket. The Readme records the resulting four seconds of refusals for each dead address.

The two possible credential-lock residues are accepted policy. A writer killed by `SIGKILL` leaves the lock and may leave its `<path>.tmp.<pid>` file. Root must remove both because the lock is never broken automatically. A release that has just read its own pid can unlink a successor's lock during a window one scheduling boundary wide, but only after an operator has already broken the rule manually. Closing that window requires unlink and rename operations that identify a descriptor rather than a path.

`adduser` neither resumes nor rolls back a partial account. Resumption would require distinguishing residue from an operator's deliberate changes. Rollback would require another series of replacements, each subject to the same failures as the original series.

The ping deadline's wrap check is justified by analysis rather than a probe. The tick counter wraps about every 497 days at 100 Hz, and no test in this milestone can set it.

Two parts of the simultaneous-open fix also rely on analysis. An active open that reaches SYN_RCVD must wake as its own completed `connect` rather than enter a queue for a nonexistent listener. A reset must not remove its reference because a descriptor owns the socket. Review found both defects in the first version. A probe cannot exercise either path because the timer drains the loopback ring while the caller remains inside its own `connect`. The crossing therefore completes before the wait predicate is first evaluated, so no wake is needed, and a reset arriving in that interval has no sender. The probe checks that the crossing establishes and transfers data. It uses bounded retries because a timer tick between the two connect calls resets the first; this loses one round but does not indicate a defect. A blocking connect was tested as a fifth assertion and removed because the same race can hang until the runner's step timeout.

Every ordinary disk boot leaves the dirty-mount flag set. Userland has no `reboot(2)`, and only the debug shell's `halt` clears the flag. This item was closed in `dev-log/18-shutdown/`.

Four items from milestone 15 remain deferred by policy. There is no complete loopback interface with routes and an `lo` device. The `127/8` alias is the entire feature; a separate interface requires a routing table that the stack lacks, and no program in the image requires one. Quotas, access control lists, and capabilities each add policy above the credential model and file system. Each requires its own milestone, none is needed by a program in the image, and adding one would obscure the nine-bit permission check without explaining those bits further.

SSH continues to refuse root's password, the first item on the original list. `vendor/dropbear/Readme.md` explains both effects of `-g`. It removes root's password from the authentication exchange that an attacker can retry without an account, but it does not keep the password off the link because the end-to-end test pipes it to `su` through the session channel. The Readme names the single flag a student removes to change this policy. It also explains why root's shadow field contains a hash rather than a lock: `su` rejects a hash that does not begin with `$`, so a locked field would prevent the intended privilege transition.

## Verification

Every phase ran `make verify-style`, `make verify-host`, and `make test`. A phase also ran the disk probes on both buses and the SSH end-to-end test when it changed a path they exercise. `make test` grew from 44 probes to 51. Three targets joined the verification set: `make test-noentropy`, run once for the library and once for `passwd`; `make login-test`; and `make ping-test`.

Every end-to-end case was run on the live system. Cases that depend on refusal first ran against a deliberately broken build. They covered console login and its refusals; `passwd` over SSH, followed by acceptance of the new password and refusal of the old one; `adduser` at the os-real prompt, followed by an SSH login as the new account that can read but not write `/etc/motd` and cannot read `/etc/shadow`; `ping 127.0.0.1` and `ping localhost`, while a second session remains responsive during a ping to a dead address; and a password change that survives a power cycle of the disk image.
