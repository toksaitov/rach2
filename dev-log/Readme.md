# dev-log

The record of how each Rach2 milestone was planned and built, one subdirectory per milestone. Milestone 1 keeps the prompts that drove it; later milestones keep the plan they were built from.

* `01-foundation`: the boot, paging, system calls, shell, audio, and Doom of the first OS.
* `02-networking-and-userland`: the TCP/IP stack, the ported musl libc, BusyBox, the Dropbear SSH server, and the build modernization.
* `03-text-standard`: the text and documentation standard, the refactor that reached it, and the gate that keeps it.
* `04-normalization`: carrying that standard into the rest of the in-house tree (the tests, the krffs host tools, the utils, and the ish shell) and widening the gate to match.
* `05-images`: replacing the one overloaded RAM disk with three purpose-built images (a test image, our simple-tools image, and a real busybox/dropbear/Doom environment), built by a manifest-driven stager, plus a `make test` boot check and a bootable ISO per image.
* `06-review`: a full code, comment, documentation, support-file, and manual-test audit of the whole system, every finding refuted before it counted, the safe ones fixed in scoped commits, and the gate, boots, and capstone re-verified against a recorded baseline.
* `07-init`: a persistent userland init (`/sbin/init`) that reaps orphans and respawns the login shell, the kernel orphan-reparenting that fix needs, and a `rach2.rescue` boot flag that turns the kernel debug shell into a deliberate rescue mode instead of the default home.
* `08-disk`: Path B, lifting KRFFS off the RAM-disk module onto a real ATA disk through a kernel page cache and a demand-paged kernel-virtual window (the fault polls the sectors in rather than sleeping, since it runs with interrupts off), with write-back, a real fsync, a dirty-mount flag, and a GRUB boot from the disk.
* `09-audit`: a full four-dimension audit (code, comments, documentation, support files) of the whole tree after the disk milestone, run as ten risk-ordered multi-agent phases that adversarially verified every candidate finding; it found and fixed one real defect (a user read of the page-cache window panicked the kernel, now a clean segfault) and brought the comments and Readmes back into agreement with the disk-backed system.
* `10-ahci`: the modern SATA half of the disk layer, an AHCI driver published behind the same `block0` the ATA driver fills, driven by polled `PxCI` completion so it stays callable from the interrupt-off page-cache fault, selected by a `rach2.disk=ahci` probe seam that leaves the legacy IDE boot byte-for-byte unchanged; the disk probes and the SSH and Doom capstones all run over a SATA disk.
* `11-audit`: the post-AHCI audit, eight risk-ordered multi-agent phases that adversarially verified every candidate finding and had Codex independently re-verify each phase; it found and fixed eleven real defects, the highest hiding on the error paths QEMU never exercises (the command completion reported two hardware-only fatal-error conditions as success, now detected, with the port recovered in place), and brought the comments, Readmes, and support scripts back into agreement with the audited code.
* `12-review`: the whole-system production-readiness review, thirty risk-ordered multi-agent phases over the entire OS (boot, memory, the page cache, KRFFS, the syscall ABI, processes and signals, the fd layer, the TTY and pty, poll and pipes, the whole network stack, audio, the peripherals, the freestanding library, the userland, the host tooling, and the trust boundary); it confirmed and fixed about fifty defects, the heaviest in the TCP closing states and send-side backpressure, and cleared the two negatives (no hostile-frame out-of-bounds at any layer, no ring-3 escape). Codex's independent re-verify carried real weight: it overturned the fan-out's refutation of the keyboard early-unmask bug and caught two regressions in the review's own TCP fix. Verified live, network and capstones included.
* `13-post-review`: the small follow-ups made after the milestone-12 review, on `master` rather than as a new milestone: the full BusyBox applet set (`defconfig` minus the Linux-only tools), a VT100/ANSI interpreter on the VGA console so line editing and `vi` render in the QEMU window, and a `run_from_disk.sh` SSH-forward fix.
* `14-multiuser`: the classic Unix multi-user model, in five reviewed phases: per-process credentials (V7 with POSIX saved IDs), file ownership stamped at creation with real `chmod`/`chown`, the nine-bit permission check enforced at every path that opens/creates/execs, and an unprivileged `test` account the SSH capstone logs into beside root, the kernel keeping the two apart in both directions.
* `15-privilege`: the other half of the model, privilege regained, in six reviewed phases: a real `/etc/shadow` of `$6$` hashes minted at build time by a host tool from the vendored musl crypt, IP loopback (a `127/8` alias delivered through a timer-drained ring), SSH password login for the test account with root kept pubkey-only, the setuid and setgid bits on exec with `AT_SECURE` told true, and a small setuid-root `su` (with a reference `sudo` shipped only as coursework) as the one way privilege climbs, busybox left unprivileged after a setuid-busybox attempt surfaced a latent busybox use-after-free the kernel's strict `munmap` faults.
* `16-review`: the audit of the privilege milestone, six risk-ordered phases with the trust boundary and the network independently re-verified by Codex; it confirmed no privilege escalation (every candidate refuted with a trace) and fixed four defects: `su` inheriting the caller's environment (a `PS1` command-substitution vector), a missing martian-source filter that let a spoofed self-address reach the loopback path, two privilege probes that could false-pass on a crash (`WEXITSTATUS` without `WIFEXITED`), and the generator's un-ignored transients.
* `17-completion`: closing milestone 15's deferrals, in seventeen reviewed phases, under one rule: every deferral ends with a probe that can fail or as declared policy with its reason. A descriptor now names one file across `unlink`, `rename` and relocation; one credential library carries a never-broken lock, a durable replacement and a prompt that survives signals; `passwd` and `adduser` write through it, the second publishing four things in an order whose every prefix is a system a reader can make sense of, proved by a crash build that dies at each point; the console is behind a `login` that cannot fall back to an unauthenticated shell, because init builds twice and the strict artifact holds no string that names one; the ping wait sleeps instead of freezing every process on the machine for four seconds an unprivileged user could ask for; an attached disk is a mounted disk, so os-real is the writable Rach2; and an empty datagram, a bound client port, one listener per port and simultaneous open close the network gaps. `make test` grew from 44 probes to 51, and `make login-test` and `make ping-test` joined the gate.
* `18-shutdown`: the clean shutdown, closing milestone 15's last deferral, in nine reviewed phases: the machine can now be stopped from userland, because `reboot(2)` exists at syscall 88 and because `/sbin/init` is pid 1 in fact rather than only in the prose, which is what a bare `halt`, `poweroff` or `reboot` signals; the kernel gained one place that knows how it stops, parking the CPU in a loop rather than a single `cli; hlt`, deriving the PIIX4's power-management base out of PCI configuration space rather than trusting a port, and reporting what it asked for and what it got; and the clean unmount now flushes before it clears the dirty-mount flag, which is a defect the planning found in shipped code, since a write-back fails whole after writing part of the cache and clearing first could leave an image reading clean with data missing. The flag therefore means something again: it fires on a boot that was killed rather than on every boot. `make test` grew to 52 probes and `make shutdown-test` joined the gate with eight boots.
* `19-busybox-first`: where each implementation belongs, under one instruction: take as much from busybox as it can give. os-real's account tools are now busybox's, including the three that need the set-id bit, which come from a SECOND build of the same source holding `login`, `passwd` and `su` and nothing else, because busybox's own `Config.in` says to build twice and put the bit on the one that needs it. os-simple, which had been a shell and a heap of utilities at the file system root, becomes a small Unix built out of this project's own code with a login in front of it, so the programs the privilege milestones produced are still what a reader runs; reading one image against the other is the point of having two, and nothing was deleted. The work found the kernel had no `readv`, which is what musl's buffered stdio issues whenever it wants more than a byte, so every program reading through `fgets` or `fread` had been failing silently and three in-house programs carried comments calling that a property of the system; it also found that a process left its process group when it exited rather than when it was reaped, which refused a shell the terminal for a pipeline whose first command had already finished, and that a write pre-fault reported a copy-on-write page backed, promising the kernel a page the next store faulted on. The guards grew with the images: the applet tables and the configs `oldconfig` resolved are read as staged beside the binaries they describe, and an unprivileged program root runs is now checked for its mode, its owner and its source, because `/bin/login` staged 0777 needs no set-id bit to be a hole. `make test` grew to 54 probes and `make account-test` runs both images.
* `20-compiler`: a compiler on the machine, so a student can build a program ON it and not only FOR it. tinycc is vendored and cross-built the way musl, busybox and dropbear are, and staged into os-real with the sysroot it was configured to look in (musl's headers and `libc.a`, the startup objects, tcc's own runtime) and the source of this project's tools at `/src/utils`. tcc is compiler, assembler and linker in one binary, which is the whole argument for it: gcc and clang are only the first of the three and hand their output to tools this image would have to port next, and then to a `make` it does not have. What this machine cannot run, the compiler refuses by name and with its reason, enforced by a pinned patch rather than left to intention: `-run`, which compiles into memory and jumps and so wants an `mprotect` this kernel does not have; a shared library; an executable link without `-static`, since the loader maps `PT_LOAD` and never looks at `PT_INTERP`; and a raw image, the output format being a different field from the output type. Staging a sysroot took a manifest directive that stages a directory tree, because 218 headers cannot be named a line at a time, and it took the kernel to hold more than twelve mappings at once, which is what `memory full (malloc)` means on a machine with memory to spare. The gate grew the capstone it had always described in prose: `make ssh-test` logs in by key and by password without a person at the keyboard, and proves HOW each session was let in rather than that one happened, with three attempts that must be refused. `make test` grew to 55 probes, `make tcc-test` compiles a program and one of this project's own tools on the machine as an unprivileged user, and every boot harness now ends its machine on every way out.
* `21-time-and-make`: a make on the machine, and the clock it turned out to need first. A make decides what to rebuild by comparing modification times, and this kernel reported zero for every file and stamped none on write, so a build would have looked like it worked and done nothing; pdpmake is blunter than that and reads a zero time as a file that does not exist, so nothing would have built at all. So the machine reads its CMOS clock once at boot and anchors an epoch to it (a pair, the second the clock reported and the uptime second at which it was read, carried on uptime seconds rather than ticks because a 32-bit tick counter wraps after 497 days), refuses a clock whose own hardware says its contents are not to be trusted rather than believing a dead battery, and keeps `CLOCK_MONOTONIC` meaning what it always meant. Every path that fills a `stat` now reports the times the file system stores, one helper stamps them where POSIX says to, and a read never does, this file system being a write-back page cache. Two builds of one tree now produce one image byte for byte, which staging a node's times made necessary. `execve` grew from 15 arguments and 512 bytes of strings to 63 entries per vector and a 3072-byte budget shared by both, derived from the one page the initial stack lives in and checked at copy-in, before the old image is torn down and a refusal would become a kill. `system(3)` and `popen(3)` work, which they never had: the planned `clone` shim was refused in review as a kernel answering a question it had not been asked, and the vendored musl is patched to fork its `posix_spawn` instead, syscall 120 still saying `ENOSYS`. pdpmake 2.0.4 is vendored and staged as `/bin/make`, with tcc staged again as `/bin/cc`, and `make make-test` proves a build is a build across a reboot. `make test` grew to 61 probes.
* `22-selfbuild`: the machine builds itself. The kernel, the 24 utilities and the ish shell all compile and link on Rach2, with the staged tcc driven by pdpmake over POSIX `guest.mk` files staged beside the sources at `/src`, and the proof reads the result back out: the kernel is built twice from clean workspaces and must hash equal, the exact bytes are extracted from the disk image, checked on the host by a new structural checker for kernels, and booted through all 61 probes. Getting there took one source tree that both toolchains accept (the 49 interrupt stubs written out because tcc has no `.macro`, three instructions emitted as bytes because its table lacks their names, the standard memory routines defined because both compilers emit calls to them, the entry renamed `_start` and the image end read from `_end`, and tcc's native two-segment link at a computed text address in place of the linker script it cannot read), and the machine then measured its own limits: the 1 MiB page cache slowed a compile to more than a minute per file and is 4 MiB now, adapted down on small machines; the 64-entry VMA table ran out linking `login` and is 128, with the probe guarding the boundary; and accelerated busybox SHA faulted on the kernel's missing SIMD state, which is recorded as a deferred contract. `make selfbuild-test` runs the whole loop in about seven minutes.
* `23-install`: the machine installs the kernel it built, and the next boot runs it. On the GRUB disk the boot partition became the install surface: the candidate slot install-kernel rewrites in place, the untouched fallback kernel, and GRUB's environment block deciding between them by exact menu ids, every install a one-boot trial a power cycle revokes until root commits the booted kernel. Getting there took a permission model for /dev (the first restrictive device, the root-only raw boot-partition window, every transfer bounced through a kernel buffer), /proc/cmdline so a program can read which entry booted, a pure MBR parser, and a host-tested FAT core that validates the volume, the chains and both kernels to the loader surface before writing a sector, in an interruption order that leaves a bootable machine after a power cut at any point. The design was settled by experiment before code: GRUB ignores slot padding, rewrites its environment block in place, consumes next_entry only when the config scripts it, and resolves the fallback variable by entry number. `make install-test` proves the loop twice on the booted disk, marker-identified kernels, fallback and in-place repair included; `make bootpart-test` proves the device seams. The in-repo anchor for the current state of the tree.
