# Milestone 42: ext2

The os-real system exists as an ext2 volume built on the host and checked clean by `e2fsck`, and the kernel boots it as its root: reads it, writes it in the order the format allows without a journal, checks it at mount when it was not unmounted, and hands what the check cannot mend to `e2fsck`, which is ported and runs from the recovery system's `init` before anything else. Symbolic links resolve through the walker milestone 36 prepared for them, on every type. The sealed disk carries both roots, the ext2 one on a fourth partition that the candidate entries boot and the KRFFS one that the fallback entries keep, so a candidate root that does not come up falls back through the trial to a system that does. The Lenovo's move to that root is milestone 43's, with the procedure written in `hardware.md` and rehearsed by `tests/run sealed`; nothing here touched the Lenovo.

## What was built

The host side first. e2fsprogs is a required host tool, `mke2fs`, `debugfs` and `e2fsck`, found by one script that puts the first installation with all three at the front of the path. `stageimage.krffs --tree` materialises a manifest into a host directory and names every node with its mode and owner, the implicit parents included; `tools/image/mkext2.sh` hands that directory to `mke2fs` on one fixed profile, revision 1, 4 KiB blocks, 128-byte inodes, `sparse_super`, `large_file` and `filetype` with every other feature named and off, reads the superblock back and refuses anything else, sets each node's owner, mode, set-id bits and change time with `debugfs`, requires `e2fsck -fn` clean and the set-id policy kept, and renames the image into place from a directory of its own; with the times, the identifier and the directory hash seed fixed, two builds of one manifest are one image. `setidcheck --ext2` reads such an image with a reader that shares nothing with the kernel's driver, refuses anything off the profile and any block or entry out of place, lists the root and every node reached from it, and holds a declared set-id entry to be a regular file. `make os-real-ext2` builds `build/images/os-real.ext2`, and every image now depends on the programs its manifest stages.

The port: e2fsprogs 1.47.4, pinned and verified, built against the ported musl behind a stamp, `e2fsck` alone, 673864 bytes against a limit of 737280, staged into the recovery image. One patch, under a `__rach2__` the wrapper defines because `i686-elf-gcc` defines no operating system: the size requests `BLKGETSIZE` and `BLKGETSIZE64`, and the 512-byte alignment `unix_io.c` applies for Cygwin, since the kernel's partition nodes take whole sectors and nothing else.

The driver, `rach2/sys/fs/ext2.c`. The reader takes revisions 0 and 1, blocks of 1, 2 and 4 KiB, inodes of 128 and 256 bytes, judges the three feature words, and checks every structural block against the descriptors before it is read; a file past 4 GiB less one is `EOVERFLOW`. The walker follows symbolic links on every type with the rules `open`, `stat`, `unlink` and the rest keep on Linux, forty along a path, and `symlink`, `symlinkat`, `readlinkat`, `link` and `linkat` are real syscalls. The writer keeps one order: an inode's bit before its body and its body before its name, a block's bit and its group's count before the pointer that names it, a pointer block zeroed before the pointer to it, a fresh block zeroed before a partial write, the data synced before the size, a new entry in the slack behind an old one before the old one is shortened, an entry removed before its inode's count, a held inode kept with its blocks until its last put; `rename` is a link followed by an unlink and a directory's move rewrites its `..` between its two names. The promise is what the format allows without a journal: at every stop, no data lost or shared outside what the operation itself was changing, and `e2fsck` repairs the rest without discarding a reachable file.

The check runs before a writable mount of a volume whose valid bit is clear or error bit set, under the walk lock and the bitmap the FAT drivers share, raised to 2^22 bits: the structural blocks seeded, the tree walked with a reached set, every block every inode names marked through every pointer level, the orphans scanned with their blocks marked, the bitmaps compared and the free counts recounted. It repairs nothing. Lost blocks and orphans are kept, held out of the allocator by their bits, and the error bit is set so that nothing marks the volume clean before `e2fsck` has; a fault mounts the volume read-only with the fault named. `rach2.root=ext2` mounts the first ext2 partition as the root through a new install of entry zero, before the USB stack starts, and an orderly stop unmounts it with its valid bit set; `init`, `login` and every program, scripts included, run from it through the read path `execve` has for a mount of another type. The recovery build's partition nodes are writable, the one build where they are, and its `init` runs `e2fsck -p` on each of the four with the ext2 magic and records the status.

The disk: `mkdisk_grub.sh` takes a fourth partition from an ext2 image at 630 MiB, where the installed machine's fourth partition already begins, and gives the candidate entries `rach2.root=ext2` while the fallback entries keep `rach2.root=disk`. The sealed disk has the metal-disk manifest there as 1 GiB.

## What running it found

The first ext2 root boot reached a login and its shell died at its first command: `_llseek`, which is musl's `lseek` on i386, answered `EBADF` for any file of another type, a fault FAT mounts had carried unnoticed since nothing had seeked a file on one from a shell. `execve` refused a script on a mount of another type by design; it takes its reader now. The kernel's start of `init` and the boot's refusal of an unmounted root asked KRFFS by name. `e2fsck` on the machine sized the partition at zero blocks and then could not write the superblock's changed bytes, the two halves of the port's patch. The recovery image did not rebuild when `init` did, which is the dependency rule every image has now. The host test's fourth judge, which mounts every crash stop with the check, decided that a deleted inode is what `e2fsck` says it is and that a count behind its pointers or its entry is a fault the writer's order leaves and the check must name. A candidate's root that halts is recovered only by the trial, and the sealed suite rehearses exactly that: missing, faulty and dirty in turn, each boot after falling back to KRFFS with nothing armed.

## What the review found

Three Codex units after phase 3, four after phase 5 and four at the close, fifty-nine findings in all, every one fixed or recorded with its reason. After phase 5: the check's unit found the root inode outside the reached set on a volume whose first inode is 2, the fault path writing half-recounted free counts, and a deleted inode counted against its comment's word; the port's unit found `init` naming four nodes where the prose said every partition, a fork failure that skipped a partition, and a status read before it was set; the tools' unit found ten, among them a heap write on a one-block volume, an entry header read past its block, a set-gid root the policy could not see, a set-id link passing as a program, and two reasons one manifest did not make one image. At the close: the root commit's unit found nine gaps the ext2 root made root-wide, a write or truncation that kept a file's set-id bits, `fchmod` and `fchown` that changed nothing on such a descriptor, `umask` ignored, the working directory recorded as typed and never held, `stat("/")` answered for KRFFS, the root read through the test lag wrapper, the recovery partition writers outside the single-writer rule, and a staging buffer kept after a failed write; the driver's unit found seventeen, among them the node pool taken outside any lock while a load slept, a failed store reported as a count, a rename and a `mkdir` that left a count raised after `ENOSPC`, a directory's growth that allocated before it knew, a new inode keeping its slot's old words, faults met while reading that were forgotten at unmount, and a pointer block past the size the check accepted; the tests' unit found eleven, among them rows that matched the terminal's echo, judges that allowed a link-count repair at every stop, a created name that could vanish, and a junk volume nobody looked at; the documents' unit found eight claims the code did not keep, among them an update command that would commit a read-only root. `notes.md` has each with what changed.

## Verification

`tests/run host` runs `ext2_hosttest`: the reader against the tree and the guard's reader, the refusals by name, thirteen write sequences under three judges, the interruption matrix at 439 stops with a fourth judge running the check on each, and the dirty-volume rows. `tests/run ext2` boots the fixture's link rows and then the os-real root through kill, check, fault, recovery and the clean boot. `install-ext2`, `drill-ext2` and `selfbuild-ext2` are the install, the drill and the self-build on the ext2 root, and `sealed` both roots of the sealed disk. Every check added here was proved by a mutation that makes it fail, twenty-six in all, with two recorded as not separable by any judge.

The full set on the closing tree ran 69 suites and passed 65; of the four, `scratch` was milestone 37's rehearsal of a FAT32 fourth partition and is retired, since the fourth partition is the ext2 root and the sealed suite rehearses it, `subset` named the boot's skips in the old order with USB before the disk, `sealed`'s new phase died under `set -e` at `e2fsck -p`'s repaired status, and the runner's self-test had failed silently since phase 1, when `tests/run` began sourcing the e2fsprogs path script that the self-test's tree does not have; each fixed and rerun alone. `make test` runs the core tier in 8 minutes 26 seconds against milestone 41's 8 minutes 12 seconds, the ext2 suite's 46 seconds being the tier's addition, with `mount`'s lag-sleep boot failing in the pool and passing alone, the flake milestone 40 recorded. The tree is clean and nothing was pushed.
